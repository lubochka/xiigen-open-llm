# Репозиторные DPO-наборы

Этот каталог — канонический дом учебных пар предпочтений. Если пара должна
использоваться повторно, она хранится здесь как обычный файл репозитория, а не
как кэш, временный вывод теста, карантин, соседняя рабочая копия, другой диск
или другая ветка.

```text
training-data/dpo/<domain>/<design-pattern>/<version>/manifest.json
training-data/dpo/<domain>/<design-pattern>/<version>/pairs/<pair-id>.dpo-pair.json
```

Человеческий договор простой:

- набор принадлежит конкретной задаче, домену, шаблону и версии;
- манифест хранит паспорт набора: какие строки и ответы легли в запрос, какой
  учитель имел право писать пары и какие файлы должны лежать рядом;
- перед обучением или продолжением код открывает набор с диска и сверяет этот
  паспорт;
- повторный идентичный запрос переиспользует уже сохранённые пары и не вызывает
  учителя заново;
- платный эталон может быть ориентиром качества и источником контрольной суммы,
  но не становится ни выбранной, ни отклонённой обучающей стороной;
- если файлы повреждены, неполные или относятся к другой задаче, система
  сообщает ошибку до обучения, до вызова учителя и до замены старых данных.

При повторном запросе система сначала проверяет паспорт сохранённого набора: к
какой задаче он относится и не изменились ли файлы. Если набор подходит, она
читает прежние пары и не обращается к китайской модели. Если набора ещё нет,
китайская модель создаёт обе стороны новой пары. Ответ платной модели служит
ориентиром, но не попадает ни в одну учебную сторону. Новая пара сохраняется до
обучения. Если файлы повреждены или относятся к другой задаче, система сообщает
об ошибке и не заменяет их новыми данными.

## Граф бизнес-потока CrossStack

Канонический адрес:

```text
training-data/dpo/cross-stack-business-flow-graph/ilearning-unit/<version>/
```

Для CrossStack обучающая часть и отложенная проверочная часть должны быть двумя
разными сохранёнными наборами. У них разные адреса или версии, разные сведения о
разрезе и разные контрольные суммы запроса. Они не могут ссылаться на один и тот
же манифест или на один и тот же отпечаток строки, иначе проверка качества
получила бы подсказку из учебных данных.

Если подходящий набор уже есть, код открывает `manifest.json` и все файлы
`pairs/*.dpo-pair.json` с диска и отдаёт дальше только заново прочитанные
данные. Если набора действительно нет и каталог чистый, запускается только
переданный в этот режим создатель пар. После создания пары сразу запечатываются
манифестом, открываются обратно и только затем становятся входом для проверки,
метрик или обучения.

Старый детерминированный генератор CrossStack остаётся исходной проверкой формы
матрицы. Он не превращается в реальный корпус учителя. Этот адрес нужен как
будущий шов для настоящих строк, где обе обучающие стороны созданы допущенным
открытым учителем. В текущем срезе здесь не запускается Qwen/Ollama, не
создаются реальные строки учителя, не обучается модель и не публикуются веса.

## Перевод

Для Translation репозиторный путь сначала ищет уже сохранённый набор и сверяет
паспорт запроса. Если паспорт совпал, используются пары этого сохранённого
набора; новый клиент учителя не создаётся. Старые вне-репозиторные артефакты
для этого не нужны. Только при настоящем отсутствии манифеста команда может
подключить допущенный локальный Qwen/Ollama-контекст создания.

При создании новых Translation-пар запускающий код читает проверенные платные
эталоны, кладёт их точные контрольные суммы в паспорт запроса и просит
локальный Qwen один раз на пару написать обе обучающие стороны: `chosen` и
`rejected`. Платный ответ направляет качество задания, но не копируется в
сохранённую сторону. Пока пары создаются, репозиторная бронь удерживает место
записи; после записи код открывает те же файлы заново. Повторный идентичный
запуск начинает с этих файлов, а не с фабрики учителя.

## Оркестрация программистской задачи

Канонический адрес:

```text
training-data/dpo/programming-task-orchestration/ilearning-orchestrator/<version>/
```

Продолжение оркестрации программистской задачи тоже начинается с диска. Готовый
набор открывается с диска; при его чистом отсутствии допустимо создание через
разрешённого учителя с обязательным сохранением и повторным открытием. Если
файлы повреждены или паспорт относится к другому запросу, команда сообщает
ошибку без замены данных и до записи новой контрольной точки.

При продолжении команда берёт обучаемый текст только из файлов DPO-пар:
`chosen` и `rejected`. Исходный корпус платных эталонов нужен для проверки
паспорта и безопасной связи с задачей: номер строки, исходный `PairId`, хэш
платного плана, идентификатор запроса и адрес набора. В
`OrchestrationPlanMachine` сохраняются проверенные маршрутные метки и память
ближайших примеров. Экзаменационные строки, уже применённые пары и лимит циклов
влияют только на выбор допустимых новых пар.

Если пара дублируется, переставлена, не привязана к исходной строке, потеряла
файл, относится к изменённому корпусу или пытается подставить платный ответ как
учебную сторону, команда останавливается до изменения контрольной точки. Новая
пара должна быть сохранена и открыта обратно до применения. Этот путь сейчас
обновляет память выбора маршрута; это не градиентное DPO-обучение общей
нейросетевой модели и не доказательство запуска настоящего Qwen.

Старые сохранённые пары важны для будущего учителя как история,
воспроизводимость и хорошие/плохие примеры формы ответа. Они не означают
автоматический повтор всех прошлых изменений весов. Учитель может получить
платный эталон отдельной учебной задачи как ориентир, но этот эталон не
становится стороной DPO. Закрытые экзаменационные задания и привязанные к ним
отложенные эталоны учителю не даются. Целевой, ещё не готовый, цикл качества
должен после новой пары сравнить пробную версию с исходной оценкой и либо
принять улучшение, либо вернуть полный снимок состояния до этой пары.

## Документация кода

Канонические адреса:

- `training-data/dpo/csharp-code-documentation/ilearning-unit/<version>/`;
- `training-data/dpo/angular-code-documentation/ilearning-unit/<version>/`;
- `training-data/dpo/sql-code-documentation/ilearning-unit/<version>/`.

Эти домены используют платную или справочную документацию только как цель
качества и как часть паспорта запроса. Сохранённые DPO-стороны должны быть
написаны допущенным локальным Qwen/Ollama-учителем, затем сохранены и открыты с
диска до обучения. Повторный идентичный запрос должен читать тот же манифест и
те же файлы пар без нового подключения клиента учителя.

Для совместимости старые `RoutingDpoPair[] DpoPairs` остаются оценочным
артефактом. В репозиторном режиме будущий источник обучения — отдельно
названные `RepositoryOwnedDpoPairs`, открытые с диска, и receipt с источником,
хэшем манифеста, путём манифеста, хэшем паспорта запроса и хэшами файлов пар.

Этот README существует, чтобы свежий clone сразу содержал видимый канонический
дом DPO-наборов даже до публикации первого реального доменного набора.

## Техническая справка

| Точный адрес или класс | Что он делает человечески |
|---|---|
| `RepositoryOwnedDpoDatasetResolver.OpenExistingOrCreateAndSealAsync` | Сначала пытается открыть подходящий сохранённый набор. Только при чистом отсутствии берёт бронь и разрешает один вызов создателя пар. |
| `RepositoryOwnedDpoDatasetManifestSealer` | Записывает пары и манифест, затем открывает эти же файлы обратно и сверяет контрольные суммы. |
| `RepositoryOwnedTrainingArtifactLayout.CreateDpoDatasetAddress` | Строит безопасный путь `training-data/dpo/<domain>/<design-pattern>/<version>/`. |
| `TranslationRepositoryOwnedTrainingRunContextFactory` | Для Translation выбирает путь “сначала диск”: повторно открыть набор или подготовить допущенный локальный Qwen/Ollama-контекст при чистом отсутствии. |
| `TranslationDpoTrainEvaluateRunner` и `TranslationDpoTrainingHandoffBuilder.BuildRepositoryOwnedDpoTrainHandoff` | Передают Translation-пары из сохранённого набора в DPO-тренировочный маршрут. |
| `OrchestrationRepositoryOwnedDpoDatasetAuthoring.BuildTeacherPrompt` | Формирует запрос будущему оркестрационному учителю; платный эталон остаётся ориентиром, а не обучающей стороной. |
| `MaterializeRepositoryOwnedOrchestrationDpoPairsForContinuation` | Для текущего продолжения оркестрации выбирает новые, привязанные к корпусу пары и не повторяет уже применённые. |
| `CrossStackBusinessFlowGraphRepositoryOwnedDpoDatasetAuthoring` | Хранит типизированный переносчик данных, чтобы восстановить CrossStack-пару после открытия с диска. |
| `CrossStackBusinessFlowGraphDpoGenerator` | Остаётся детерминированным исходным ориентиром для проверки формы, а не настоящим автором учебного корпуса. |
| `CodeDocumentationTrainingRunner` и `CodeDocumentationBatchFileRunner` | Имеют отдельный repository-owned вход для будущих DPO-пар документации. |

| Технический термин в коде | Человеческий смысл |
|---|---|
| `request identity` | Паспорт запроса: контрольные суммы задания, эталонов, учителя, политики генерации и настроек создателя. |
| `paid-reference` | Платный эталон качества: его можно хэшировать и использовать как ориентир, но нельзя сохранять как `chosen` или `rejected`. |
| `mismatch` | Файлы или паспорт относятся не к тому запросу, который сейчас хочет выполнить команда. |
| `partial dataset` | Видна только часть набора: например, есть папка пар без корректного манифеста. |
| `malformed pair file` | Файл пары нельзя безопасно прочитать как ожидаемую DPO-пару. |
| `sealed dataset` | Набор сохранён с манифестом, контрольными суммами и успешным повторным открытием с диска. |
