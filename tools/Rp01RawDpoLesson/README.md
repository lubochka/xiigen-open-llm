# Один raw C# TRAIN-урок для существующего DPO-пути

`Rp01RawDpoLesson` принимает уже выбранный платформенным агентом исходник и отдельную точную инструкцию оператора о его использовании. Он не выбирает урок и не судит пару. `train-and-hold` передаёт строго открытый набор существующему ModelServer trainer после независимого J и допуска оператора и удерживает Trial до отдельного научного вердикта. Источник — оригинальный синтетический C#12 TRAIN specimen; чужие репозиторные примеры, paid answers, DEV, SEALED, gold и rubric этим входом не допускаются.

Первый научный маршрут требует отдельных startup selectors ModelServer. Старый `train-existing` для raw входа теперь отказывает до подготовки модели: native quality PASS сам по себе не разрешает adoption. Legacy routing с отсутствующим marker сохраняет прежний bounded timeout.

| Selector | Значение |
|---|---|
| `XIIGEN_CODE_DOCUMENTATION_SCIENTIFIC_MODE` | `FIRST_RP01_SCIENTIFIC_HOLD` |
| `XIIGEN_CODE_DOCUMENTATION_SCIENTIFIC_POLICY_SHA256` | Точный SHA256 заранее созданного server-owned `config/code-documentation/first-rp01-scientific-policy-v1.json`. |
| `XIIGEN_CODE_DOCUMENTATION_SCIENTIFIC_HELD_SHA256` | Для publish-only: точный SHA256 возвращённого `held-trial.json`. |
| `XIIGEN_CODE_DOCUMENTATION_SCIENTIFIC_VERDICT_SHA256` | Для publish-only: точный SHA256 настоящего независимого `scientific-verdict.json` в том же private run subtree. |

Host захватывает значения один раз. По умолчанию путь выключен. Оператор после независимой проверки перезапускает host с тем же policy hash и новыми held/verdict hashes; старый first-root optimizer grant остаётся отдельным и не разрешает будущий reset. HTTP request не содержит policy, verdict, output path или принятие. Это явное доверие оператору и настоящему независимому экзаменатору, а не криптографическая аттестация его роли.

Private policy использует строгий camelCase JSON, без неизвестных или повторных полей. Поля: `schema=first-rp01-scientific-policy-v1`, `trainingRunId`, `parentManifestSha256`, `datasetManifestSha256`, `pairId`, `examinerAuthority`, `familyCount=12`, `repeatCount=5`, `minimumCorrectFamilyGain=2`, `maximumTrialCritical=0`, `maximumNewCritical=0`, `protocol`, `commitment`, `evaluationRetentionGrant`, `scorerBinding`, `cases`. Каждый source содержит `relativePath`, `sha256`, `private`; retention/scorer обязательно private. Двенадцать `cases` содержат `caseId`, отдельный `familySha256`, точный `ownerInputSha256`. Policy и private inputs должны иметь owner-only custody; public protocol/commitment могут иметь `private=false`. Пути относительны trusted root, без drive, traversal и reparse. Сервер сверяет preregistration SHA `bbbcfd4f00d749306024b231d23d5e490a0a9beb58f48a2869d89558898429c8`, commitment `c4680151e6a93fb6276ac3e701c36f5f5643c4657a540778ff0b147434c79fac`, EVALUATION_ONLY grant `fe3b5eb01ae013bd2750a826c7dc23670a185e5c057b8d8c19bbd02de0d8345f`. Здесь не создаётся реальный policy, scientific capsule или вердикт.

`train-and-hold` использует endpoint `/code-documentation/repository-owned-dpo/scientific/train-and-hold`. Durable `intent.json` сохраняется **до C0 и optimizer** в `training-artifacts/private-evaluation/<domain>/<pattern>/<model>/<version>/<SHA256(run-id)>/`, вне canonical checkpoint discovery. Полные точные decoded UTF8 всех 12×5×2 ответов сохраняются отдельно с case/input/repeat/settings/model/source/corpus bindings и char count; newline, control, Unicode и строки длиннее preview не переписываются. Default assessment сохраняет прежний preview/wire без новых writes. Private artifacts служат только EVALUATION_ONLY retention, не TRAIN и не public stdout. Complete `held-trial.json` содержит исходную baseline graph, Trial graph, native disposition и точный saved weights hash. Ответ `HELD_FOR_SCIENCE` не содержит publication receipt. Native negative тоже сохраняется, но не публикуется. Cancel/partial hold не очищается автоматически; ordinary/direct resume того же run ID отказывает даже при неполном intent.

Независимый экзаменатор позже записывает owner-only `scientific-verdict.json` в этот private run subtree. Строгая схема: `schema=first-rp01-independent-scientific-verdict-v1`, `graderRole=INDEPENDENT_BLIND_EXAMINER`, `examinerAuthority`, `policySha256`, `protocolSha256`, `trainingRunId`, `heldBundleSha256`, `sourceBindingSha256`, `parentManifestSha256`, `trialWeightsSha256`, `families`. У каждой из 12 families: `caseId`, `familySha256`, binary `baselineCorrect`/`trialCorrect`, `trialCriticalErrors`, `newCriticalErrors`, ordered `baselineRawAnswerSha256`/`trialRawAnswerSha256` по пять реальных повторов. Сервер проверяет все bindings и фактические raw hashes, целый прирост correct count ≥2 и оба critical count=0; пять повторов не считаются независимыми семьями. Пример 11−9=2 допускается точно, без double-rounding/epsilon. Нужен также положительный прежний native gate.

`resume-baseline-and-hold` вызывает `/code-documentation/repository-owned-dpo/scientific/resume-baseline-and-hold` с **теми же** intake, run ID, B0, парой и frozen policy. Оператор выбирает эту команду только для оборванного C0 до canonical attempt; это явное восстановление, без скрытого retry. Сервер повторно допускает source/legal/parent, держит отдельный custody-protected run lock для всех трёх scientific операций и кратко проверяет отсутствие canonical attempt под существующим pair lock. Pair lock освобождается до calibration и обычного executor. Любой canonical claim/journal/Trial, post-update/held state, конфликтующий sibling, неизвестное или нечитаемое состояние отказывает. Историческое число optimizer calls этим структурным допуском не измеряется.

Сервер сверяет исходный intent byte-for-byte с полным текущим source binding и проверяет **все 60 исходных C0 слотов до новых вызовов**. Сохранённые raw переоткрываются по original assessment run/case, exact input/settings/corpus/model bindings, строгому UTF8, SHA, byte length и char count. Orphan, лишний case/arm/repeat, неизвестный формат, изменённые raw/metadata или settings отказывают. Сохранённый raw не генерируется повторно и не переписывается. Генерируются только действительно отсутствующие слоты. Если durable verdict отсутствует, evaluator получает те же точные raw bytes с текущим one-call permit; genuine полный результат/profile/provenance сохраняется create-only до следующего case. Cached результат проходит те же profile/authority/parser/request-ID проверки, но не получает фиктивного CallIssued.

120 — число **логических результатов**, а не утверждение о lifetime physical calls. Для исходных пяти raw без durable verdict требуются 55 новых baseline и 60 Trial generations и 120 новых evaluator calls, если новых interruptions нет; число предыдущих evaluator calls остаётся UNKNOWN. Каждый новый dispatch intent сохраняется отдельно до внешнего вызова; intent без durable result означает UNKNOWN external effect, не zero calls. Provider exactly-once через окно crash не обещается; frozen MaxTeacherCalls/criteria/settings не увеличиваются. После complete C0 существующий executor выполняет единственное прежнее обновление, затем собирает те же 60 Trial результатов и возвращает HELD_FOR_SCIENCE даже при native negative. Повторный recovery при существующем canonical attempt отказывает; publish остаётся отдельным этапом после независимого T2.

```powershell
dotnet run --no-build --project tools/Rp01RawDpoLesson -- resume-baseline-and-hold <same-repo-root> <same-intake.json> <same-intake-sha256> <same-loopback-uri> <same-training-run-id>
```

`publish-held` вызывает `/code-documentation/repository-owned-dpo/scientific/publish-held`. Он переоткрывает существующие baseline/optimizer/RNG/Trial через прежние owners и сравнивает полные сохранённые quality graphs чистой функцией прежнего gate. Никакого нового optimizer, calibration, Qwen, Student generation или pair replay нет. Missing/negative/drifted review, policy, raw evidence или parent оставляют Trial удержанным. Только существующий canonical publisher публикует те же Trial weights; затем обычный latest consumer может принять новый checkpoint.

Все три scientific HTTP метода явно используют caller lifetime: Ctrl+C/разрыв запроса и host stopping token, без `CancelAfter` или HTTP deadline. URI/JSON/body-size safety остаётся прежней; injected HttpClient с конечным timeout для этого пути отказывает. Старые transport API сохраняют максимум 24 часа и запрет Infinite. После отказа или cancel нельзя утверждать нулевой optimizer effect; сначала читается server journal. Реальные T1, независимая научная оценка и cold adoption этим кодовым срезом не запускались.

Вызов после сборки:

```powershell
dotnet run --no-build --project tools/Rp01RawDpoLesson -- inspect C:/Projects/llm_mvp_core <absolute-intake.json> <intake-sha256>
dotnet run --no-build --project tools/Rp01RawDpoLesson -- author C:/Projects/llm_mvp_core <absolute-intake.json> <intake-sha256>
dotnet run --no-build --project tools/Rp01RawDpoLesson -- reopen C:/Projects/llm_mvp_core <absolute-intake.json> <intake-sha256>
dotnet run --no-build --project tools/Rp01RawDpoLesson -- train-and-hold C:/Projects/llm_mvp_core <absolute-intake.json> <intake-sha256> <loopback-modelserver-base-uri> <stable-training-run-id>
dotnet run --no-build --project tools/Rp01RawDpoLesson -- publish-held C:/Projects/llm_mvp_core <same-intake.json> <same-intake-sha256> <loopback-modelserver-base-uri> <same-training-run-id>
```

Корень репозитория и SHA256 intake передаёт оператор вне входного файла. `inspect` не открывает teacher factory. `author` сначала использует существующий repository resolver; только чистое отсутствие набора допускает один вызов существующего локального Qwen клиента. `reopen` использует строгий reader без factory. В WSL передайте `/mnt/c/Projects/llm_mvp_core`; абсолютные Windows-пути внутри закреплённых хешем входов читаются с соответствующего `/mnt/<drive>/` mount, их JSON и исходные байты не переписываются. Доступ WSL к тому же loopback Ollama должен подтвердить будущий author; Windows localhost не считается автоматически доступным из WSL. Endpoint не меняется на LAN-адрес.

Все JSON используют точные camelCase имена свойств из трёх публичных records в `CodeDocumentationRawDpoLessonSource.cs`; неизвестные и повторные свойства отклоняются. Обязательные поля:

| Файл | Поля |
|---|---|
| intake | `schema=raw-code-documentation-lesson-intake-v1`, `selectionHandoffPath`, `selectionHandoffSha256`, `authorizationPath`, `authorizationSha256`, `configurationPath`, `configurationSha256`, `datasetVersion` |
| authorization | `schema=raw-code-documentation-source-authorization-v1`, `authorityKind=CURRENT_HUMAN_PROJECT_INSTRUCTION`, `authorizedBy`, `authorizationText`, `purpose=LOCAL_CHINESE_BOTH_DPO_AUTHORING_AND_ONE_STUDENT_STEP`, `selectedHandoffSha256`, `ownerInputSha256`, `recipient=LOCAL_OLLAMA_LOOPBACK`, `retention=REPOSITORY_LOCAL_CANDIDATE_PAIR_THEN_DISTINCT_JUDGE_BEFORE_TRAINING` |
| configuration | `schema=raw-code-documentation-local-authoring-configuration-v1`, `modelId`, `manifestSha256`, `modelLayerSha256`, `outputLicensePath`, `outputLicenseSha256`, `authoringProfileId`, `authoringProfileSha256`, `evaluationProfileId`, `evaluationProfileSha256`, `maximumAuthorCalls=1`, `maximumDpoSteps=1` |

Пути intake/authorization/configuration/handoff и трёх выбранных copies должны оставаться внутри trusted root; локальный файл лицензии модели может лежать вне него. Reparse points отклоняются. SHA256 каждого файла и его полное содержимое проверяются до authoring; изменение уже захваченного файла запрещает даже factory. Это граница доверенного оператора с закреплёнными байтами, не криптографическая аттестация человека или платформенного агента. Поля `authorityKind` и origin сами по себе не доказывают согласие: оператор обязан передать настоящую текущую инструкцию и её точный digest. Test fixture не заменяет этот вход реального запуска.

Отображение настоящего S handoff: `identity.selectionOrigin/platformAgentId`, `lesson.caseId/familyId/partition/language/declaredLanguageVersion`, `lesson.frozenInput/source/question` (`path/rawSha256/byteLength`), `sourceUse.sourceKind/paidReferenceClaimed/realRepositorySampleClaimed`, `prospectiveTeacher.modelId/modelVersion/expectedModelLayerDigest`. Принимается схема `rp01-actual-astra-selected-raw-train-lesson-handoff-v1`; читаются только соседние `owner-input.txt`, `specimen.cs`, `question.txt`. Оригинальный exam manifest и его содержимое не нужны. Платформенный выбор не превращается в Native Codex receipt.

Конфигурация обязана выбрать действительные `ManualCpuAuthoring` и `ManualEvaluation` ID/SHA из `LocalQwenOllamaInferenceProfileAuthority`. License bytes читаются и хешируются, а manifest/layer/native-vocabulary и полный rendered input проверяет существующий production client при будущем вызове. CPU: 2048 context, 512 output reserve, максимум 1536 входных native tokens; без truncation/shift, 2 threads, batch 16, GPU 0, keep_alive 0. Отмена — caller/client lifetime, без добавленного таймера. Model pins — bare 64 hex, legal refs — `sha256:` плюс 64 hex. Assessment-only retention нельзя использовать как authoring permission.

Учитель получает JSON wrapper с отдельным полным `raw_task`. Он должен вернуть только `chosen` и `rejected`, соблюдая язык ответа и требования задания. Китайская модель как автор подтверждается существующим provenance, а не наличием CJK-символов в ответе. `Pair.Prompt` равен точному raw owner input, decoded стороны сохраняются без Trim, Unicode/newline rewrite и `[WRONG:]` append. Механическая проверка требует строгий bounded UTF8, непустые и не whitespace-only строки, различающиеся по точному Ordinal-сравнению. Пунктуация, регистр и Unicode form не удаляются даже для сравнения: `x?.Length` и `x.Length` имеют разные C# законы. Корректность, смысловой контраст, косметику и TIE обязан оценить отдельный J.

Новый request schema `repository-owned-dpo-dataset-request-identity-raw-v2` хранит полный source/selection preimage и не имеет `paidReferenceAnswers`. Старый v1 writer и его хеш не меняются. Rich pair v5, exact-byte content binding, resolver/sealer, objective/masks/LoRA/checkpoint и обычный Student generation остаются существующими. Команды author/reopen печатают точные pair paths/hashes для отдельного J и `NOT_PERFORMED`; они не выдают judge acceptance, training lease, B0, T1 или adoption. Любая неясность прав, TIE/BOTH_BAD/UNJUDGEABLE или невалидная пара означает отсутствие допуска к T1.

`train-and-hold` — команда с реальным эффектом обучения. Оператор обязан заранее проверить положительный независимый J для точного PairId/SHA и запустить существующий ModelServer с допущенным current manifest, совместимым сохранённым B0, одношаговым TRAIN plan и отдельно предоставленным научным startup capsule/policy. CLI не создаёт этот capsule, не читает Gold/rubric и не превращает вывод J в фиктивный Native receipt. `CodeDocumentationRawDpoTrainingComposition.CreateRequest` вызывает строгий `Reopen` без factory, копирует реальный manifest receipt и точные пары, ставит `routingDisposition=NOT_PERFORMED` на запросе. Нулевые routing fields означают отсутствие наблюдений. Неизвестный marker, ненулевые routing counts/metrics/resources, cases/routing pairs и конфликт pair/source отклоняются клиентом и сервером; сервер дополнительно требует реальный raw-v2 identity на диске. При legacy `null` marker поле отсутствует в JSON и прежние positional constructors сохраняются.

Далее используется общий core существующего координатора: его C0 calibration выполняется до optimizer, затем durable Trial и единственная серия Trial quality; science route останавливается перед canonical publication. Дополнительные baseline calls не добавляются. Все startup/current-manifest/lease/правовые/masks/LoRA/journal checks сохраняются. Новые команды используют явный caller lifetime без внешнего deadline; старый bounded API сохраняет 24 часа. При refusal/cancel CLI сообщает неизвестный optimizer effect: перед повтором оператор обязан сверить server attempt/journal, сохранив тот же run ID. HELD не означает scientific PASS или adoption. Этот code slice не запускал реальное обучение.

Для первого обновления от уже сохранённого B0 сервер при создании host отдельно захватывает `XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_MODE=ROOT_B0_FIRST_UPDATE`, `XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_REASON=<настоящая текущая причина первого optimizer update, 1–512 символов без CR/LF>` и `XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_PARENT_SHA256=<canonical manifest SHA256 точного B0>`. По умолчанию выбор выключен; raw marker, client JSON и прежняя причина создания B0 не дают optimizer grant. Неверный/отсутствующий выбор отказывает до C0. Этот путь требует уже проверенной `generation-v1` конфигурации обычного сервера (`XIIGEN_CODE_DOCUMENTATION_GENERATION_ENABLED=true`, её точный `XIIGEN_CODE_DOCUMENTATION_GENERATION_CONFIG_SHA256`) и согласованного ContinuousLearning startup. Модель, tokenizer, LoRA и seed/streams берутся у существующего generation configuration owner, а не из CLI или нового parser. Для данного B0 это rank8/alpha16/q_proj+v_proj/dropout0/root seed20261014; общий training default 0.05 не меняется. Нулевой dropout сохраняет прежний контракт без RNG restore/cold-start grant; adapter seed authority остаётся точной. Строгий loader проверяет exact latest-compatible Step1 `InitialBaselineNoUpdate` и canonical B0 hash до baseline/model creation. Trained descendant, mismatch или отсутствие parent не переходят в fresh optimizer; continuation этим первым маршрутом не реализована. Existing optimizer authorization с точной причиной передаётся endpoint → coordinator → executor, их guards не меняются.
