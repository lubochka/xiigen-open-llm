`activeAfterRootExit` — диагностический снимок Job сразу после завершения root. Дочерний процесс может ещё работать в этом снимке: owner затем закрывает весь Job и дренирует оба raw streams. Успех возвращается только при точном exit0, отсутствии timeout, `activeAfterCleanup=0` и пустом `closureError`. Регрессия отдельно создаёт дочерний процесс с подтверждёнными PID/birth, удерживает его после root exit и проверяет его отсутствие после возврата, точные streams и terminal0. Старое требование transient0 воспроизводится на этом же receipt как ошибочный отказ; controlled terminal1 и closureError должны отвергаться и тестовым helper, и настоящим production terminal guard. Эти проверки не исполняют native Facts.

ZIP extraction180 s, resource hashes300 s, build binding300 s, fixture inventory180 s, source-after180 s, cleanup300 s, final validation300 s также работают в owned subprocess через `Invoke-NativeEvidenceOperation.ps1`. Synchronous CopyTo, Flush(true), hashing, PE/PDB/binlog reading, physical deletion и evidence validation можно остановить вместе с точным Job. Они не оставляют отдельный Task.Run/thread. Небольшие JSON control writes (до16 MiB) передаются через private named pipe в собственный Job writer30 s с тем же kill/accounting; блокирующий disk flush находится в child. State/requests/results не являются runtime TRX.

Controller сохраняет synchronous reads/JSON parsing только для явно ограниченных request/result control files до16 MiB, helper/source/control identity checks и открытия stream log files. Размер проверяется до чтения и при открытии; выросший файл отвергается. До adoption и после operation closure проверяется deadline. Эти небольшие controller операции не имеют отдельного hard kill boundary: зависание ОС в таком I/O может потребовать внешнего job cancellation, поэтому README не утверждает устранение вообще всех synchronous I/O. Missing/overdue terminal evidence при таком исходе не даёт PASS. Bulk resource I/O выполняется в child; наружу публикуется только compact receipt до64 KiB с hash/length и candidate/helper/request/operation/deadline binding.

Перед импортом результата controller сверяет request physical identity/content hash, helper hash, candidate, operation и deadline. Existing owner identity/creationTicks/flags неизменны; seal и promotion разрешают только свои точные переходы. Новые resource leaves ограничены предварительно заданными путями, новые directories — отсутствующими предками этих путей. Missing/stale/foreign receipt не импортируется. Ownership journal без terminal receipt служит диагностикой; unknownEffects сохраняет отрицательный исход и запрещает completed cleanup/acceptance. Cleanup удаляет только точного физического владельца с полным текущим hash/length; foreign/changed content сохраняется. При interrupted writer новая неизвестная custody не превращается в authority на удаление.

`absentAfter=true` становится монотонным только после принятого terminal Cleanup-Owned: exact owner получает `deletedByCleanup=true` лишь после успешного физического Remove-Item. Уже принятый absent owner допускается при позднем noncleanup readback с прежними path/identity/creationTicks/flags и leaf hash/length; это повторное чтение, не новая deletion authority. Missing/duplicate prior owner, новая неподтверждённая пропажа, false absence/witness, foreign/reparse или resurrection отказывают; ошибки указывают path/identity. Каталоги имеют те же owned/absentBefore/reparse/absence/witness controls. Closure больше не пытается автоматически запечатать interrupted/unsealed partial: он сохраняется present, с null seal, без права удаления. Такой результат оставляет cleanup=false и весь run failure; bounded repair не превращает его в native PASS.

`evidence.json` запечатывает завершённые prepare-through-closure phases перед bounded validator process. `timing.json` и `commands.json` продолжают фиксировать validator closure; `validation-report.json` содержит validator interval. Failure checkpoint и компактные operation receipts входят в явный artifact allowlist. Request/result state snapshots остаются локальными control files; resource binaries не публикуются. Missing/overdue timing, unknown outcomes, shortened native allowance, отсутствие sealing receipt и stream-only timing отвергаются.
