# Закрытый native reference: сохранение и повторное открытие

Команда предназначена для научного владельца уже полученного capture. Она не вызывает модель, не создаёт учебную пару, не меняет веса и не выдаёт прав. Из явно переданного закрытого intake она строит отдельный вариант provenance, сохраняет корпус через существующий `RepositoryOwnedReferenceCorpusManifestSealer` и действительно открывает его заново. В консоль выходят только purpose, идентификаторы, hashes и количества.

Отсутствующие в возвращённом native stream provider/backend model/version/server request ID записываются как `null`. Запрошенный alias, reasoning effort, версия CLI и local thread ID имеют отдельные поля. Hash полного capture связывает операторские утверждения с байтами, но не подтверждает их истинность, backend identity, лицензию, admission или grant.

```powershell
dotnet build tools/Rp01NativeReferenceCorpus/Rp01NativeReferenceCorpus.csproj -m:1 /nr:false
dotnet tools/Rp01NativeReferenceCorpus/bin/Debug/net9.0/Rp01NativeReferenceCorpus.dll seal <trusted-repository-root> <private-intake-path> <raw-intake-sha256>
dotnet tools/Rp01NativeReferenceCorpus/bin/Debug/net9.0/Rp01NativeReferenceCorpus.dll reopen <trusted-repository-root> <subject> <version> <corpus-sha256-ref> <payload-sha256> <manifest-self-sha256>
```

`seal` принимает ровно четыре аргумента вместе с именем команды. `reopen` — семь. Успех возвращает exit 0, отказ — exit 1. Для `seal` SHA256 — bare lowercase 64 hex из фактических bytes intake. При `reopen` corpus hash имеет префикс `sha256:`, payload и manifest self hash — bare lowercase 64 hex. Полученные pins не являются разрешением на следующий model call. Ответ команды не содержит raw task, Gold, текста native ответа, полного capture metadata или абсолютных private paths.

Trusted root задаётся в точной нативной absolute форме без aliases: на Windows — backslash path. Existing typed layout отказывается, если supplied root не совпадает с `Path.GetFullPath`. Subject/version — lowercase repository slugs длиной до 96 символов (`a-z`, `0-9`, `-`, первый символ — буква/цифра); они не принимают dot/underscore/colon.

Private intake должен лежать строго внутри явно переданного доверенного root, иметь owner-only custody у файла и непосредственного родителя и не проходить через reparse point. Команда не исправляет ACL входных файлов. На Windows используется существующий `SecureLocalFileBoundary.OpenCustodyOwnerOnlyFile`; на Linux — существующие owner-only modes. Два полных чтения одного handle, проверка его пути до/после, ограничение 32 MiB и точный SHA предшествуют JSON parser. Для native origin sealer создаёт только новый защищённый leaf-каталог и staging files через existing custody helpers; небезопасный существующий native leaf отказывается, его ACL не исправляется. На reopen native manifest и payload читаются через фактические custody-verified handles. Native seal не вызывает общую clone-custody preparation. Generic `OpenSealed` сначала читает bounded strict manifest/self hash; native tuple и address проверяются до любой общей preparation, затем core повторно сверяет exact manifest-file pin и приватные handles. Небезопасные существующие native modes отказываются без исправления; другие DPO/model/reference roots не обходятся. Valid legacy v1/v2 сохраняет прежнюю preparation. Missing/malformed manifest теперь отказывается до неё, в том числе у legacy: это намеренное изменение порядка отказа. Общие ancestor и legacy ACL native-операция не меняет. Output остаётся в каноническом `training-data/reference-corpora/<domain>/<subject>/<version>/`; прежний sealer обеспечивает no-overwrite, custody preparation и payload-before-manifest publication. Native intake после seal и CLI `reopen` вызывают `OpenSealedNativeCapture(address, expectedCorpusSha256, expectedPayloadSha256, expectedManifestSha256)`: bounded strict discovery проверяет полный native tuple/address и все ожидаемые seal pins до core readback, без вызова generic legacy preparation. Valid legacy header, включая замену прежнего native header, unknown origin или mismatch любого pin отказываются без обхода других roots и без исправления modes. Exact discovered raw manifest-file hash передаётся в core отдельно от manifest self hash и сверяется повторно. После успеха отдельный `reopen` можно выполнить в новом процессе.

Публичная [схема private intake](native-reference-intake.schema.json) содержит только поля и типы. Реальные вопросы, эталоны и capture остаются у научного владельца. Все перечисленные JSON members обязательны; неизвестные, повторные и пропущенные members запрещены. UTC использует точный .NET round-trip формат `yyyy-MM-ddTHH:mm:ss.fffffff+00:00`. Все `*Sha256` внутри intake имеют формат `sha256:<lowercase64hex>`. Материал остаётся исходным строгим UTF-8: CRLF и decomposed Unicode не нормализуются.

Исходный owner различает `train` и `held-out`; этот ABI не добавляет новую роль DEV. Владелец отдельно формирует корпус SEALED для оценки, например 12 `held-out` записей, а TRAIN и DEV сохраняет по отдельным purpose/address. DEV нельзя молча включить в SEALED. Hash полного private batch capture может сопровождать split-specific reference; полный batch, его private path и read handle не передаются кодовому worker, selector или Teacher. Служба не открывает capture по hash: научный оператор сам делает разрешённое сопоставление capture→case и подаёт нужный split.

Замороженный корпус и все entries получают отдельные native schemas. Каждый entry имеет `nativeCaptureProvenance`, без `paidReferenceProvenance`. Его metadata, nullable counters, exact answer hash и factory-owned closed/never-train/never-DPO-side restrictions входят в length-framed SHA256 preimage. Reader восстанавливает provenance и entry, сравнивает полные canonical representations и hashes, затем весь corpus и manifest. Смешение native с known-model v1/raw-v2 отказывается. Legacy factories и emitted owner JSON сохраняют свой прежний контракт.

Открытый native корпус подходит существующим закрытым assessment inputs, corpus selection, `PlanCalibration` и `PlanQualityGate`; checker prompt сохраняет точные исходные строки. Текущая canonical noise policy при 12 held-out требует 5 повторов: 60 baseline + 60 trial, всего 120 evaluation calls. Этот расчёт не является выполненными вызовами. Права проверяющего, модельный паспорт, состояние Student и последующая scientific protocol binding остаются отдельными условиями. Legacy teaching/selection и generic normalized pair matcher требуют known-model provenance и дают отказ для native origin; этот срез не расширяет их disclosure права.

Ближайшая проверка — один `NativeCapturedReferenceCorpusTests.NativeCapture_PrivateOwnerSealAndReopenPreserveRawAssessmentInputsAndRejectOriginTampering` на синтетическом 12-case корпусе. Она проверяет raw bytes, private intake hash, fresh selection/assessment prompt, реальную arithmetic plan и refusal после подмены каждого capture member при пересчитанных внешних seal hashes. В ней переиспользуется прежняя v1/raw-v2 owner проверка. Это инженерная проверка, не scientific corpus execution, native backend attestation, Student learning или независимый обзор кода. Настоящий capture seal/reopen выполняет научный владелец после отдельного review.
