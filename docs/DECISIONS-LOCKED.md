# DECISIONS-LOCKED.md — Locked architectural decisions

These decisions are final. Do not reopen without explicit approval from Luba.

| Decision | What | Rationale |
|---|---|---|
| D-01 | OperationResult<T> — no exceptions | Consistent error handling, testable |
| D-02 | Fabric First — interfaces not concrete | Swap providers without code changes |
| D-03 | 5-level semantic compression (E01→E17) | 20× compression validated across tiers |
| D-04 | Domain split: CODE_Q / BUG / PLAN / ARCH / REFACTOR | E18 95% accuracy; these are the canonical names |
| D-05 | LoRA (Low-Rank Adaptation) adapters per project (2 MB each) | Base model shared, specialization cheap |
| D-06 | 70/30 Replay Buffer | E43: prevents catastrophic forgetting |
| D-07 | StackDetector before normalization | E20: C#/TS/PY markers destroyed by E15 if run after |
| D-08 | StratifiedSplit for all experiments | E40: seed-42 distribution collapse with naive split |
| D-09 | max_weight = total / (classes × rare) | E44: constant ×10 caused catastrophic forgetting |
| D-10 | BM25 (Best Match 25) + K-NN (K-Nearest Neighbours) fusion | E34V2: hybrid beats either alone at +8% hit@1 |
| D-11 | No external ML frameworks | TensorCore (project 00) is the only tensor primitive |
| D-12 | Domain labels: short form in code, long form in comments | CODE_Q not CodeQuestion in enum; D-04 is the only source of truth |
| D-13 | Tier promotion requires coverage verification, not only metric passage | E51A Tier 1 passed metrics while still exposing thin neighborhoods; promotion must check subject density, distinct predicate profiles, and named edge risks before scaling |
| D-14 | Internal LLM always first; external AI requires explicit single-use approval with a named missing-competence statement; all results examined by the internal model before return; all examined results stored as training signals; training runs at idle time only under IdleDetector gate; a new adapter installs only if after-accuracy exceeds before-accuracy | E51A/E51B calibrated the 0.50 confidence boundary; CH-01 defines the external-help package shape, CH-02 keeps arbiter authority above external answers, and the idle-learning queue prevents external AI from becoming a permanent dependency |
| D-15 | Priority decides what to attempt; KNN uses arbiter history as memory; arbiters decide what is accepted; no priority score, KNN score, budget pressure, style preference, or external AI answer can override an arbiter rejection | This locks the authority separation proven by E51B CH-02 and needed before domain-scoped KNN and arbiter-aware retrieval are transferred into projects 21-23 |
| D-16 | PromptFlowGroundingModel (in 42.ProjectWikiDomain) is the only permitted production flow grounding path. FlowReferenceDetector is build-time corpus/audit only — it must never be reachable from GeneratePlanAsync, runtime route classifiers, or any production code path. Removed contracts that must not be re-added: PromptFlowIndex, GenerationRouteMode.KnownFlowRetrieval, RetrievalSource, _flowIndex. See D-17 for the leakage gate requirement. (Phase 37, 2026-06) | Prevents deterministic flow lookup from masquerading as trained flow grounding; enforces the trainable-model-only production path |
| D-17 | exactPromptLeakageRate must be 0.0 in all OrchestrationPlanMachine evaluation gates. Any evaluation prompt that exactly matches a training prompt causes PassesGate=false. Exclusion-without-failure (e.g., skipping exact-match prompts from scoring) is forbidden. Applies to every OrchestrationPlanMachine evaluation runner. (Phase 37, 2026-06) | Prevents contaminated accuracy claims from train/eval prompt overlap |
| A-LM-01 | `ILearningMachine<TDomain>` sits above `ILogicalOrchestrator` in the abstraction hierarchy — it wraps an orchestrator and adds the training loop; the orchestrator does not know about training | Ensures clean separation: inference path (orchestrator) is independent of training path (learning machine); an orchestrator can be used without a learning machine |
| A-LM-02 | `Train*` methods (`TrainBatchAsync`, `EvaluateAsync`) live **only** on `ILearningMachine` — never on `ILogicalUnit`, `ILogicalFlow`, or `ILogicalOrchestrator` | Prevents training logic from leaking into inference contracts; `ILogicalUnit` is a pure executable cell |
| A-LM-03 | Bootstrap `ILogicalUnit` implementations keep the exact static logic from the original classes — no behaviour change; they are the starting point for DPO (Direct Preference Optimization) training, not a replacement | Guarantees zero regression during TD1 transition; trained units can replace Bootstrap defaults after a runner publishes validated weights |
| A-LM-04 | `27.TranslationDomain` is a separate subproject implementing `ILearningMachine<TranslationDomain>` with four direction adapters: RU_EN, EN_RU, HE_EN, EN_HE; batch discipline is 50 new training pairs + 50 held-out evaluation rows per batch | Keeps domain concerns isolated; translation pairs already exist in the external corpus under `C:\Users\lubao\Documents\xiigen\llm mvp\language translate learning\` |
| A-LM-05 | `30.DesignConversionDomain` is the design-to-code domain subproject number — not 29, which is occupied by `29.SemanticCompiler` | Prevents subproject number collision |
| A-LM-06 | BOOTSTRAP_FALLBACK path in `ProjectWikiPluginOrchestrationAdapter` is logged as a warning and will remain until a trained unit replaces the Bootstrap default; it must never silently replace orchestrated behaviour | Keeps the fallback observable; a warning in the log is the signal to complete TD2 training |
| A-LM-07 | The affiliate global server is `25.ModelServer` plus a new endpoint in `15.OrchestratorModel` — no new top-level server project is needed | Reuses the existing model server rather than introducing a new network boundary |
| A-LM-08 | `SyncPersonalToGlobalAsync` sends only anonymised learning signals — never raw prompts, user IDs, or repository paths | Privacy constraint: the global model must not be trainable on identifiable personal data |
| A-LM-09 | `IMachineTraining<TDomain>` extends `ILearningMachine<TDomain>` and adds `TrainMachineBatchAsync`. It is implemented by `SkillSelectionMachine` (43.SmartSkillsDomain). All 11 semantic units in 43.SmartSkillsDomain must use trainable inference as their final semantic authority (DeterministicFinalAuthority = false for all units per SmartSkillsSemanticUnitCatalog). Deterministic algorithms (BM25 (Okapi Best Match 25), regex, if-else) may serve as bootstrap candidate generators only — never as the final production decision. (Phase 39, 2026-06) | Locks IMachineTraining as the product-facing training adapter for SkillSelectionDomain; prevents regression to deterministic-only skill selection |
| A-LM-10 | Adaptive user state for 43.SmartSkillsDomain lives in `<project root>\.xiigen\smart-skills\`. It is never silently overwritten by server skill library upgrades. Ambiguous migrations (conflicting server vs user state) produce a patch proposal or DPO (Direct Preference Optimization) row for the next training cycle, not a silent overwrite. Common assets (skill library baseline) live in the llm_mvp_core models/ and training-data/ directories. (Phase 39, 2026-06) | Protects per-project user adaptation state from being clobbered by global library upgrades |
| A-LM-11 | claude-xiigen-smart-skills, codex-xiigen-smart-skills, cursor-xiigen-smart-skills are thin API/check-set clients of llm_mvp_core. They must not contain: training logic, private corpus, canonical skill library source, project-local user state, or semantic ranking/selection/completion code. All trainable logic stays in 43.SmartSkillsDomain. The boundary is enforced at XiigenExtensionRequest / XiigenExtensionResponse. Violation of this boundary is a core/host split violation. (Phase 40, 2026-06) | Enforces the host-extension boundary: host repos are thin wrappers, not intelligence owners |
| A-LM-12 | Allowed trainable architecture patterns are only `ILearningMachine<TDomain>`, `ILogicalOrchestrator`, `ILogicalFlow<TInput>`, `ILogicalUnit<TInput,TOutput>`, and `ILearningMachinePair<TPersonal,TGlobal>` for common/user two-leg machines. Scorers, selectors, classifiers, routers, retrievers, detectors, KNN/Jaccard/BM25 stores, dictionary/counter state, regex/keyword matchers, pattern matchers, and private method families such as `TryDecide*`, `ChooseBestPattern`, `SelectBestPattern`, and `CountMatchingSignals` are implementation details only, not new architecture patterns. | Prevents pseudo-trainable pattern drift. A helper may be used only inside an allowed level and must be labelled honestly as internal detail or baseline unless lifecycle evidence proves a stronger semantic claim. |
| A-LM-13 | If code or documentation names "semantic units" that are implemented only as checkpoint sections, dictionaries, counters, or scoring methods, the plan/review must classify each item as actual `ILogicalUnit`, internal checkpoint section, baseline implementation detail, forbidden runtime shortcut, or report claim too strong. | Stops JSON/checkpoint section names from being accepted as real trainable units. Forces code review to compare the human-readable claim with the actual mechanism. |
