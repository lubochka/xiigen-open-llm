`next` → прочитать возвращённые coordination-файлы → создать реальные пары/семейства → `progress` → `finish` → `next`. `next` не вызывает модель; `finish` не проводит предметную приёмку и не обучает. Одновременно разрешено несколько агентов, но **не более одного владельца на домен**, один активный request на agent ID и один создатель ещё не записанной общей семьи. Общая файловая система обязательна. Отдельные checkout с отдельными data root не координируются.

Выданные `paths.*` и `commands.*` — текущая исполнительная поверхность. `request.json`, первоначальные prompt/commands и созданные строки не переписываются ради новой claim. Производные coordination-файлы обновляются при законном resume. Для domain-campaign request, созданного до владельцев, первый token выдаёт explicit resume того же пути в прежнем окне; точные три случая продолжения — в [runbook](18-BATCH-RUNBOOK.md#продолжение-next-и-занятость). Просроченное время или отсутствие coordination-файла не означают разрешение на takeover; token нельзя угадывать или копировать в другую сессию.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Рабочие действия определяют этот контракт, входной MASTER и текущие coordination-команды. `subject.instructions` сохраняет предметные ограничения, но исторические ссылки на полные skills, шаблон 08, будущий review или обучение не расширяют CREATE_ONLY. Применяется [краткая выжимка skills](campaign/EXECUTOR-SKILLS-RU.md), а не повторная загрузка всего пакета. Старый prompt сохраняется как история; обновление документа не означает, что текущая Kiro-сессия уже прочитала уточнение. Отдельно назначенный пользователем аудит разрешён своей задачей и не становится обязательной остановкой генератора после каждой партии.

## Учебное содержание

Строка `xiigen.dpo.v1` содержит полные `prompt/chosen/rejected`, точные domain/topic/profile/objective/pair/family IDs, `source_refs`, `origin_family_id`, `leakage_group_ids`, фактическое происхождение и `split=train`. В видимом prompt есть все решающие факты. Rationale, правильный canonical-ответ и метки предпочтения не раскрываются ученику.

Одна пара — один проверяемый содержательный контраст. Два допустимых перевода, две корректные реализации и ошибка только в пояснении автора не образуют полезную DPO-пару. Документация объясняет показанный код, code реализует требование, orchestration выбирает действие/план. D22 размечает части исходного prompt, D23 формулирует задачу своего домена, D24 восстанавливает текст на исходном языке. Контракты и примеры находятся в [дополнительных доменах](29-ADDITIONAL-DOMAINS-AND-LEARNING.md).

Сначала создаётся реальный материал семьи: сценарий и смысловые факты; для связанных переводов — согласованные EN/RU/HE canonical-тексты. Следующие направления используют тот же сохранённый сюжет. Номер F сам по себе родство не доказывает. `family_id` связывает сценарий, `lexical_family_ids` — лексему и значение. Разные слова не объединяются из-за похожего написания. Одно повреждение/раскладка той же лексемы сохраняет родство. Весь reference-пайплайн одного исходного запроса имеет общий origin и не делится между TRAIN и закрытым EXAM.

Публичные образцы не входят в квоты и не переименовываются в независимый EXAM. Здесь создаётся только кандидатный TRAIN. Качество старых коммитов оценивается отдельно как уже порученная ретроспектива; эта оценка не добавляет новый review-гейт каждому генератору.

## Значение статусов

| Поле / состояние | Что оно означает |
|---|---|
| `owner_id`, `active_request`, `work_status=in_progress` | Домен занят конкретной сессией |
| `authoring_rows_saved` | Полные реальные строки текущей незавершённой партии; не зачтены в квоту |
| `draft_created_pairs` | Строки завершённых структурно допустимых партий |
| `DRAFT_CREATED` | Одна партия создана; квота домена могла ещё не завершиться |
| `domain_complete` | 1000 созданных кандидатов конкретного домена |
| `POOL_DRAFTS_CREATED` | Все домены пула достигли своих квот, другие пулы могут работать |
| `CAMPAIGN_DRAFTS_CREATED` | Все 24 домена достигли 1000; не semantic acceptance и не обучение |
| `quality_status=needs_rework` | Есть предметная ошибка с указанным доказательством и областью |
| `quality_status=needs_assessment` | Есть конкретная непроверенная область; ошибка не объявляется доказанной |
| `quality_status=not_established` | Качество не установлено; отсутствие открытого флага не доказывает качество |

`state.json` авторитетен, `status.json` — его производная общая матрица. Флаги качества сохраняются после нового `finish`; счётчик не закрывает предметное замечание автоматически. [JSON-шаблон](campaign/status.template.json) помечен как **INITIAL_TEMPLATE_NOT_RUNTIME_SNAPSHOT** и не заменяет рабочий state/status.

Сохранённые строки, зачтённые кандидаты и смысловая приёмка — разные показатели. Сумму строк разных кампаний, core/library-копий, retry, accepted и export той же пары нельзя выдавать за новые уникальные пары или прибавлять к квоте D1000 автоматически. Структурная проверка дублей не доказывает смысловую независимость семей. Это уточнение отчёта, без дополнительного checksum/review-гейта генератору.

## Язык и граница создания

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

Старый `xiigen.batch-request.v1` остаётся вне claims нового координатора и продолжается отдельно последовательно. Существующий явно выбранный request сохраняет свой путь и не переносится самовольно. Старые результаты не зачитываются в новую квоту автоматически.
