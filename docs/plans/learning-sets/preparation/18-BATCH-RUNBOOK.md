# Исполнение партии и продолжение кампании

## Первый запуск в трёх окнах

Выбери ровно один готовый промпт на окно: [переводы](prompts/PARALLEL-TRANSLATIONS-RU.md), [оркестрация](prompts/PARALLEL-ORCHESTRATION-RU.md), [код/документация](prompts/PARALLEL-SOFTWARE-RU.md). Его стартовая команда создаёт уникальный agent ID один раз. Не повторяй генерацию нового ID после каждой партии.

Пример для окна переводов:

```powershell
$DpoAgentId = 'translations-' + [Guid]::NewGuid().ToString('N')
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action next -WorkRoot "C:/Projects/llm_mvp_core/learning-sets" -AgentId $DpoAgentId -Pool translations
```

Первый вызов использует фиксированный launcher `py -3`. Если известный Python установлен иначе, передай его точный абсолютный путь параметром `-PythonExecutable`. Инструмент не ищет соседний checkout. Следующие выданные команды содержат фактический `sys.executable` и работают из любой cwd.

## Один рабочий цикл

1. Дождись завершения `next`. Прочитай ответ и `paths.prompt`, `paths.material_required`, `paths.commands`, `paths.request`. Для текущего владельца первые три пути указывают на `coordination-*` файлы.
2. Прочитай одну назначенную микротему, два исходных и доступные точно соответствующие дополнительные примеры. Не загружай все уроки, skills и аудиты в контекст.
3. Создай только недостающий материал `missing_family_ids`; существующие факты не изменяй. Заполни точные `row_slots`, назначенные классы и `count`. Последняя партия может быть короче обычной десятки.
4. Сохраняй завершённые JSONL-строки в `paths.draft`. Выполни выданную команду `progress` после сохранённой порции; она считает реальные назначенные строки, а не оценочный процент.
5. Вызови выданный `finish`. При структурной ошибке дополни текущую партию, сохранив уже правильные строки и IDs. При `DRAFT_CREATED` выполни выданный `next` в этой же работе.

Самопроверка зависит от урока: точная буква/порядок/регистр/полное предложение; владелец и отрицание в переводе; видимое состояние и разрешённое действие в оркестрации; конкретная ветка `null`, SQL-строка или событие в коде. Не заменяй её JSON-валидностью.

## Продолжение, NEXT и занятость

Продолжение зависит от формата уже назначенного request и наличия владельца. Это три разных случая:

| Сохранённая попытка | Действие в её прежнем окне |
|---|---|
| `xiigen.domain-campaign-request.v1`, есть текущая claim | Точный resume из `coordination-commands.md` с прежними agent ID и token. Отсутствие файла само по себе не разрешает создать новую claim |
| Тот же domain-campaign request, созданный до координатора, текущей claim ещё нет | Однократный explicit resume **этого пути** с ID прежнего окна; первоначальный token выдаст координатор |
| `xiigen.batch-request.v1` | Отдельный последовательный legacy-resume, `LEGACY_NOT_COORDINATED`; без переноса в D1000 |

Для второго случая не ищи несуществующий token и не начинай новый `next`. Сначала дождись terminal текущего инструмента в том же окне; другую копию автора этой попытки не запускай. В `$DpoRequest` уже должен быть точный путь текущего задания из его последнего результата или выбранной записи `pending_requests`; не выбирай первый pending, если их несколько. Сохрани прежний `$DpoAgentId`; если у старого окна ID ещё никогда не было, создай его один раз:

```powershell
# Только для прежнего окна с явно выбранным, ещё не claimed domain-campaign request.
# $DpoRequest — его уже известный полный путь request.json.
if (-not $DpoAgentId) { $DpoAgentId = 'resume-' + [Guid]::NewGuid().ToString('N') }
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action resume -Request $DpoRequest -AgentId $DpoAgentId
```

Здесь не передаются `-WorkRoot`, `-Allocation` и выдуманный token. Runner читает корень из сохранённого request. Если claim уже существует, он требует её правильный token; отказ не обходят новым agent ID, удалением state или копированием задания. После успешного ответа прочитай возвращённые coordination-файлы и используй только их следующие команды. Уже сохранённые draft, request, IDs и завершённые партии не создаются заново. Основание: `campaign.py:261–271,1139–1185`, `create_campaign.ps1:35–58`; это статическое чтение кода, не выполненная миграция.

После потери контекста прочитай [промпт восстановления](prompts/DPO-TASK-RESET-RU.md). Повторный `next` тем же владельцем продолжает его назначение. Завершённый request возвращает актуальные `next/status`, не повторное создание. Отсутствующий `status.json` при старом state сам по себе не доказывает сбой: производная матрица записывается координатором. Команда `status` тоже сохраняет состояние/матрицу; аудитор READ_ONLY читает существующие файлы и не запускает её ради осмотра.

Если пользователь прямо назвал A-ID, выполни `next` с тем же `-AgentId`, своим `-Pool` и `-Allocation` из [очереди](EXECUTION-QUEUE.md). Координатор сохраняет прошлый незавершённый request, освобождает его claim и переводит курсор вперёд. Он не возвращается к пропущенной старой работе самовольно. Для её продолжения нужен явный выбор. ID вне твоего пула — конкретное несоответствие назначения, а не разрешение копировать работу другого окна.

`WAITING_FOR_OWNERS` — занятость, не падение. Не бери чужой token, не редактируй state. Если у тебя есть реальный handle владельца, ожидай его документированным способом; иначе выполняй доступную независимую работу и повторяй `next` после подтверждённого завершения/освобождения, без цикла частого опроса. `FORWARD_QUEUE_COMPLETE_WITH_PRESERVED_EARLIER_WORK` означает остаток перед явным NEXT, а не полный DONE.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

## Границы

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

Legacy `xiigen.batch-request.v1` распознаётся `resume` и возвращает команду старого `batches.py`; это **LEGACY_NOT_COORDINATED**, без общей claim. Продолжай такую явно выбранную попытку отдельно последовательно. Не объявляй защиту старого runner от параллельных дублей. Файлы и прежние пути сохраняются.
