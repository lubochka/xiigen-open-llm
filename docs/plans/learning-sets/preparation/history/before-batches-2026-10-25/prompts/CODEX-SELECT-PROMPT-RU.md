# CODEX: выбрать материал для одной партии

Ты выполняешь роль выбора, которую в проекте вместо человека выполняет CODEX. Требуемый профиль — `astra 6 ultracode`. Не выдавай текущее имя модели за этот профиль без наблюдаемой конфигурации. Промпт предназначен CODEX, не внешнему китайскому генератору.

Пиши по-русски. Прочитай `10-CODEX-AND-CHINESE-ROLES.md`, назначенный request, карточку, `02-DATA-CONTRACT.md`, `04-QUALITY-AND-SPLITS.md` и перечисленные source slices. Источники материала — только `lubochka/xiigen-planning`, ветки `main` и `llm_plan3`, по закреплённым ссылкам. Проектные skills задают правила работы.

Выбери ровно тему и профиль request. Проверь: что обучается; какой ответ требуется; достаточно ли видимых фактов; какой один дефект различает стороны; какие версии/SQL-диалект заданы. Симуляция прямо разрешена текущим поручением; её условие задаёт локальную истину задачи, а не факт о действующем production.

`family_id`/`origin_family_id` связывают производные одного сценария и запрещают утечку между split. `lexical_family_id` связывает слово с опечатками/раскладками; одинаковое слово в двух независимых задачах не делает их одним сценарием. Значение слова определяется контекстом/sense_id. Открытые reference-примеры нельзя переименовать в закрытый EXAM.

При достаточном пакете сохрани `selection.json` рядом с request, заполнив шаблон реальными полями модели, профиля, evidence_ref и `decision=SELECTED`. Хеш должен соответствовать выбранному request. В `selection.notes.md` коротко запиши выбранные факты, допустимые вариации и неразрешённые вопросы. Не создавай вместо китайской модели полный DPO-корпус.

Исправление задания — новая версия с новым выбором, прежние файлы сохраняются. При неизвестном профиле оставь pending-статус, не фабрикуй квитанцию. NEXT/ID означает переход к указанному заданию без продолжения прошлого; STOP — немедленное прекращение новых действий. Следующий шаг: `prompt.md` для внешней китайской модели в Kiro.
