# Исправить один дефект учебного пакета

Входы: исходный draft.jsonl, неизменяемый request.json, validation.json, review.jsonl и карточка с тем же ID. Исправь только указанную категорию ошибки. Сохрани все исходные файлы; создай **полный** draft.v2.jsonl с тем же числом строк и всеми назначенными family_id. Неизменённые строки перенеси без изменений, включая их pair_id. Только исправленные строки получают новый pair_id и metadata.derived_from со ссылкой на исходный pair_id. Сохрани split, family_id, origin_family_id и leakage_group_ids; не меняй их для прохождения проверки. Условия и предпочтение должны оставаться проверяемыми. Не добавляй новые домены, модели и production-правки.

Сначала кратко объясни причину отклонения и выбранное исправление. Для label leakage перенеси [WRONG]/объяснение в rationale, но не считай удаление ярлыка достаточным: rejected должен стать настоящим альтернативным ответом. Для tie создай содержательный контраст. Для неверного chosen исправь по видимому источнику; не переворачивай метки без повторной проверки. Для недостатка контекста добавь необходимые факты в prompt. Если исправление не обосновано, сохрани нерешённую строку и отказ в отчёте; полный пакет пока не принят. Не удаляй строку и не передавай подмножество под исходным request: validate проверяет его полные count и family coverage. Новый состав требует отдельного явно назначенного request, а не редактирования старого. Не скачивай внешние источники.

В том же каталоге run проверь полный draft.v2.jsonl с исходным request.json. Затем создай **новый blind/review всего draft.v2.jsonl**, включая неизменённые строки: blind.v2.jsonl, blind.v2.key.json и review.v2.jsonl. Новый ключ связан с хешем всего input, а review обязан покрывать все его pair_id; review только исправленных строк не поддерживается этим путём. Языковые/oracle-доказательства также должны быть связаны с новым blind_sha256; старый положительный статус не копируется как новая проверка. Точные команды на примере сохранённого run есть в разделе ремонта [03-GENERATION-AND-KIRO.md](../03-GENERATION-AND-KIRO.md). Проверяющий CODEX действует по 10-CODEX-AND-CHINESE-ROLES.md и создаёт новую review.v2.receipt.json. Исходный selection.json используется только для того же неизменного request. Итоговый validate использует draft.v2.jsonl, исходный request.json, blind.v2.jsonl, review.v2.jsonl, blind.v2.key.json, selection.json и review.v2.receipt.json; его файл — draft.v2.validation.json. Исходные draft, blind, key, review и validation остаются на месте.

Отчёт на русском, с хешами старой/новой версии. До/после относится к качеству записи, не к качеству обучения модели. Любое учебное улучшение требует отдельного реального урока. После NEXT переходи к назначенному ID, не завершая этот ремонт за спиной пользователя; при STOP прекрати новые действия.
