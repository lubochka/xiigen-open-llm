# Приоритеты, конфликты и требования

> Актуальная дорожка новых партий — [17: контракт](17-CURRENT-PREPARATION-CONTRACT.md) и [18: команды](18-BATCH-RUNBOOK.md), `tools/batches.py`, встроенный rag/. Обязательные hashes/profile receipts из прежних описаний не применяются к подготовке; содержательное качество и native-контракт не ослабляются. Ниже сохранена предметная методика и история.

## Дополнительные решения 25.10.2026

1. Broad topic и узкий objective различаются: objective-партии используют узкую карточку, а общий topic остаётся доменным контейнером. Реальный следующий поток обоих видов — execution-queue.json; curriculum/index.json и pilot-queue задают содержание и локальные связи микронабора. Старый номер или каталоговый next_id не подставляется в NEXT.
2. Conditional clarification имеет оба класса в одном objective. Запрет смешения тем не превращается в запрет положительных и отрицательных контролей одной темы.
3. Голые שלום и book не задавали однозначного предпочтения в старых TR08 опорах. Новые версии имеют видимый контекст и derived_from; старые сохранены в quarantine. Mobile routing теперь прямо задаёт мобильное приложение. Составной запрос → clarify указан в самом input роутера.
4. Смысл code literal может зависеть от пробелов и Unicode. Удаление пробелов не используется как доказательство равенства ответов; duplicate JSON keys не выбирают последнее значение молча.
5. Отсутствие needs_* и шаблон NOT_RUN не означают завершённый review. Нужны связанный артефакт, фактический статус, хеши и проверяемая причина.
6. Публичные reference и их известные семейства не становятся закрытыми DEV/EXAM. Нет автоматического доказательства семантической независимости просто по новому family ID.
7. Китайская модель через Kiro не получает выдуманный native author enum. Специальный simulation runner не переименован в общий trainer. Подготовка продолжается; native adapter является отдельной явно ограниченной следующей работой по [нативной границе](10-NATIVE-CONTRACT-BOUNDARY.md).

Текущие изменения исправляют только подготовку материалов и её инструменты. Статические проверки входа не регистрируются как успешные learning experiments, новые production-fixes планы без измерений не создаются.

Текущее поручение — подготовить учебный материал, симуляции, подробные промпты и библиотеку навигации. Ранее процитированные STOP и NEXT описывают поведение прошлой сессии; они не отменяют нынешнее поручение. Их правила включены в каждый новый work order. Старые эксперименты не удаляются и не запускаются заново.

## Приоритет исполнения

Сначала данные и ограничения, без которых невозможно обучение: реальный контраст, правильный input получателя, достаточный старт и восстановление. Затем конфликты схемы/карточек и источников. Затем расширение тем и объёма. Статические инструменты допускаются здесь, потому что они готовят фактический вход урока; их работа не объявляется учебным экспериментом.

`execution-queue.json` — единственный полный машинный порядок запуска; EXECUTION-QUEUE.md строится из него. `index.json` — каталог родительских тем. Карточку выбирать по ID, не старому порядковому номеру. Конкретный NEXT-ID пользователя имеет приоритет над очередью; независимые темы не надо искусственно блокировать одна другой.

| Документация C#/.NET, SQL, Angular | [Каталог документации](domains/documentation/topic-index.json): 15 родительских тем; микроцели перечислены отдельно в curriculum/index.json | Версия, диалект, call transit, конкретные пары |
| Написание кода | [Каталог кода](domains/coding/topic-index.json): 12 родительских тем; микроцели перечислены отдельно в curriculum/index.json | Выполняемый контракт и adversarial fixtures |
| Много качественных узких промптов | Каждая карточка + MASTER | Одно содержательное различие; отработанные примеры |
| Не выдумывать место/модель/команды | 03, sets.py, request.json | prepare создаёт точный путь и immutable request |
| Не заканчивать вместо ожидания | 03, MASTER и все карточки | Один handle, native wait, terminal evidence |
| Не продолжать предыдущий опыт после NEXT/STOP | 03 и все карточки | Literal instruction с ID; старые артефакты неизменны |
| Не удалять прошлые опыты | append-only runs, 03 | CreateNew, SHA records, отказ overwrite |
| Реальное обучение, не 0→0 | 04, 05, report template | Ненулевой учебный результат и before/after raw outputs |
| Любая полезная метрика = успех | 04, 05, все карточки | Таблица всех дельт, включая ухудшения |
| Повторно использовать обученный старт | 05 | bundle lineage, hashes, fresh load; no hidden bootstrap |
| Только измеренные улучшения в fixes | report candidate, 05 | Новый fixes-план не создаётся до фактических улучшений |

Проектные навыки применены к классу текущего задания — документам и подготовке данных. Общие требования навыков о production-коде, десятках проверок расширений или изменениях core не создают дополнительного поручения. Никаких вымышленных N review passes и заявлений полной готовности production в этой поставке нет.


## Исправления активного пакета от 25.10.2026

| Конфликт | Действующее решение | Где обеспечено |
|---|---|---|
| Старый review назначал текущую модель Kiro | Материал выбирает и пары оценивает CODEX с `astra 6 ultracode`; китайская модель только генерирует кандидатов | 10, prompts/CODEX-SELECT, REVIEW, MASTER; tools/sets.py |
| Любой положительный review принимался без роли/профиля | Приёмка v2 требует отдельные selection/review receipts и связи по хешам | validate → merge → compose → export |
| Положительный review мог не соответствовать видимому A/B | Проверяется точное соответствие blind/key/draft и хеш blind в квитанции | tools/sets.py::blind/validate |
| Лексическая семья могла ошибочно объединить все независимые предложения | lexical_family_id отдельно от family_id сценария; смысл задаётся контекстом/sense_id | 02, 04, translation addendum |
| Новые темы могли перезаписать прежние | Новые ID дополняют реестр; исправленные версии сохраняют derived_from, прежние примеры остаются в истории/карантине, а не исчезают | index.json, curriculum/index.json, предметные индексы и quarantine |

Текущий запрос — подготовка наборов, источников и промптов. Не подменять его новым большим аудитом possibleDifs, изменением навыков, production-реализацией или запуском всех старых экспериментов. Успешные учебные кандидаты оформляются только по измеренным данным отдельного опыта.

## Решения при объединении параллельных дополнений

- Topic и objective сохраняют разные ID. Одна карточка objective ссылается на родительский topic; duplicate order numbers из старых отчётов не определяют следующий запуск.
- CODEX selection/review receipts дополняют входящие language/oracle evidence, а не заменяют их. Китайский генератор не заполняет доказательство независимого CODEX-вызова за проверяющего.
- Для code.* обязателен execution evidence обоих кандидатов. Для docs.* evidence обязателен всегда; source_grounded допустим только для неисполняемого факта источника и не заменяет runtime/API/SQL/Angular проверку.
- Старые проверки и их числа сохраняются с собственными версиями. Проверка объединённого инструмента требует нового отчёта, связанного с его SHA; отсутствие такого отчёта не подменяется прежним PASS.
