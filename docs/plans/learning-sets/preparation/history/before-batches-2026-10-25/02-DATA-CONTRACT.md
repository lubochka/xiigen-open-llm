# Формат одной учебной записи

> Актуальная дорожка новых партий — [17: контракт](17-CURRENT-PREPARATION-CONTRACT.md) и [18: команды](18-BATCH-RUNBOOK.md), `tools/batches.py`, встроенный rag/. Обязательные hashes/profile receipts из прежних описаний не применяются к подготовке; содержательное качество и native-контракт не ослабляются. Ниже сохранена предметная методика и история.

## Дополнение v2: один навык и точный текст

В request с `objective_id` каждая строка обязана иметь `metadata.learning_objective_id` с тем же ID. `merge`/`compose` не смешивают разные микроцели или размеченные и старые неразмеченные строки. Родительский topic/domain/profile сохраняется. Примерные строки нового слоя лежат в `curriculum/reference-examples.jsonl` и имеют только `split=reference`.

JSON с повторным ключом на любом уровне, NaN, Infinity либо переполнением вроде `1e999` отклоняется. Строки сравниваются без удаления пробелов, смены регистра и Unicode-нормализации: `"a  b"` и `"a b"` могут означать разное поведение кода. Семантическую эквивалентность проверяет reviewer. Это проверка сохранности фактического материала, не механизм принятия runtime-решения.

В TR10-CONDITIONAL две строки одного семейства имеют `metadata.clarification_class=ambiguous|resolved` и общий family/origin/split. Число строк чётное; каждый family получает ровно одну строку каждого класса. Класс служит контролем состава и не добавляется в student prompt. Для OR-ROUTE-INTENT проверяется баланс 20 routes и clarify по chosen-JSON; это контроль данных, не правило роутинга в runtime.

Известные публичные reference families, declared origin/leakage groups и точные публичные prompts запрещены в DEV/EXAM даже под другим ID пары. Проверка охватывает старые и новые reference-файлы и сохранённый карантин. Она не распознаёт все скрытые перефразирования: семантическое происхождение остаётся обязательным предметом review. Все изменения ID сохраняют derived_from.

Структурная проверка и содержательный допуск различаются. Отсутствующие `needs_oracle`/`needs_language_review` не считаются false. Для перевода нужен завершённый связанный language_review; для code.* и docs.* — предметный evidence.oracle по [REVIEW-PROMPT-RU](prompts/REVIEW-PROMPT-RU.md). Для code.* это всегда реальное изолированное исполнение; для docs.* только неисполняемый факт контракта может иметь режим source_grounded с проверенными ссылками. Предпочтение по поведению/API/SQL/Angular требует execution. Экспорт принимает только проверенный вид/статус release; формат остаётся interchange-only. Актуальная native карта — [10](10-NATIVE-CONTRACT-BOUNDARY.md).

У пары одно условие. Правильный и ошибочный ответы удовлетворяют одному формату и отличаются проверяемым смыслом. Объяснение дефекта хранится рядом, но не попадает в текст ответа. Это предотвращает обучение на метках вроде `[WRONG]` вместо содержания.

## Основная запись JSONL

Одна UTF-8 строка — один JSON-объект; переводы строк внутри текста экранируются. Никаких Markdown-ограждений вокруг JSONL.

```json
{
  "schema_version": "xiigen.dpo.v1",
  "pair_id": "DOC-CS-01.base.F0001.P01",
  "domain_id": "docs.csharp",
  "topic_id": "DOC-CS-01",
  "profile_id": "base",
  "family_id": "synthetic.guard.not-null.0001",
  "split": "reference",
  "prompt": "Симуляция. C# 10, .NET 6. bool IsPresent(string? s) => s is not null; Опиши возвращаемое значение; не приписывай проверку пустой строки.",
  "chosen": "Возвращает true для любого значения, кроме null, включая пустую строку.",
  "rejected": "Возвращает true для любого значения, кроме null и пустой строки.",
  "error_tag": "null_empty_confusion",
  "rationale": "Код сравнивает только с null; дополнительная проверка пустой строки отсутствует.",
  "source_refs": ["RAG-027", "RAG-028"],
  "provenance": {"kind": "synthetic_from_repo", "generator_model": "reference_authoring_not_a_kiro_run"},
  "metadata": {"stack": "C# 10 / .NET 6", "response_language": "ru", "source_role": "methodology", "simulation": true}
}
```

Эта запись — пример формата, не исторический фрагмент исходников. Источники поддерживают метод составления пары; поведение конкретного вымышленного метода задано в условии.

## Обязательные поля и правила

| Поля | Контракт |
|---|---|
| `schema_version`, `pair_id` | Версия формата; ID уникален глобально, не переиспользовать для изменённого содержания |
| `domain_id`, `topic_id`, `profile_id` | Должны существовать в `index.json`; один пакет содержит одну комбинацию |
| `family_id` | Общий ID смыслового/исходного семейства, включая производные перефразирования, опечатки, варианты раскладки и обратные переводы |
| `split` | `train`, `dev`, `exam`, `reference`; reference не попадает в экспорт обучения |
| `prompt` | Полное условие, видимый код/схема/контекст/версии и договор об ответе; не ID вместо содержания |
| `chosen`, `rejected` | Полные ответы в одинаковом формате. Они различаются по одной основной проверяемой ошибке; два допустимых синонима не образуют предпочтение |
| `error_tag`, `rationale` | Тип и объяснение отличия, только метаданные |
| `source_refs` | Непустой список проверенных RAG-ID либо immutable URL разрешённого репозитория; ссылка на внешний сайт внутри старого документа не разрешает его скачивание |
| `provenance` | `kind`, фактическая модель/селектор Kiro; для реального материала также commit/blob/line span, origin и parent revision |
| `metadata` | Язык ответа, стек/диалект/версия, допустимые варианты ответа, ограничения, семейства источника и lexical_family_ids при их наличии |

Статические примеры допускают `reference_authoring_not_a_kiro_run`. Новая генерация записывает фактический идентификатор модели, если среда его показывает. Если показывает только текущий селектор, записать этот селектор и `model_identity_observed=false`, не выдумывать точную версию. Один генератор может создать кандидаты обеих сторон; их достоверность определяется проверкой, а не числом разных моделей. Указания старого навыка о двух разных моделях не запрещают текущую запрошенную симуляционную генерацию.

## Семейство не равно строке

У предложения, его обратного перевода, опечатки и преобразования клавиатуры общий `family_id`. Для отдельных слов добавить `lexical_family_ids`: предполагаемый язык + каноническая лексема + проверенное значение. Совпадение букв между языками не объединяет лексемы. Общий исходный код, его пересказ и вариант с переименованием относятся к одной source-family. Типовые неизменяемые инструкции генератора сами по себе не делают весь корпус одним семейством; содержательные исходные задачи делают.

Новые семейства распределяются до генерации ответов. Один и тот же family не может быть и TRAIN, и EXAM даже в разных доменах. Межкарточные семьи опечаток/раскладки и одних исходников сверяются дополнительно: один лишь автоматически выделенный номер не доказывает независимость.

## Как передать материал обучению

Храним две формы: полную запись с происхождением и строгую проекцию `prompt/chosen/rejected`. `tools/sets.py export` создаёт `dpo.train.jsonl`, `dpo.dev.jsonl`, `dpo.exam.jsonl` и `provenance.jsonl`. Экспорт — обменный формат, **не обещание совместимости с нативным загрузчиком**. Перед запуском проверяется реальный потребитель и adapter mapping. Поле `error_tag`, rationale, источник, split и ID никогда не добавляются к ответу ради удобства loader.

| Вид обучения | Какой вход действительно нужен |
|---|---|
| Student DPO/LoRA | Точные одинаковые prompt/chat template, полный контраст ответов, маска loss на ответе и EOS, совместимые tokenizer/reference policy |
| Unit с обучаемой памятью/kNN | Реальный вход Unit, представление и цель; сохраняется связь с исходной парой; полный prompt не заменять тегом ошибки |
| Маршрутизатор | Пользовательское намерение и список допустимых целей; правильный route, отказ/уточнение и ложный route |
| Splitter/planner после роутера | Фактический типизированный выход предыдущего узла; не притворяться, что Unit всегда принимает сырой пользовательский prompt |

Экспериментальная привязка содержит `recipient`, `training_entrypoint`, `inference_entrypoint`, `state_artifacts`, `tokenizer_hash`, `template_hash`, `dataset_hash`, `source_to_unit_fields`. Если связывание отсутствует, данные остаются `CANDIDATE_VALIDATED`, а не `TRAIN_READY`. Исполнитель подготовки не изменяет production-импорт ради прохождения своей проверки.

Не обрезать пары фиксированным числом символов. После токенизации проверить, что различающий смысл ответов и EOS помещаются в контекст. Если не помещаются — создать отдельную более короткую смыслово полноценную задачу с новым ID и связью `derived_from`; старую сохранить. Статический подсчёт длины Python не заменяет реальный tokenizer.


## Уточнение 25.10.2026: роли и два уровня семейств

Выбор материала и качество пар подтверждает CODEX с `astra 6 ultracode` по [10](10-CODEX-AND-CHINESE-ROLES.md). Внешняя китайская модель в Kiro создаёт кандидатов. `provenance.generator_model` не является полем оценщика; роль/профиль CODEX и реальные хеши находятся в отдельных selection/review receipts. Старые reference записи не переписываются в результаты Chinese-генерации.

`family_id` и `origin_family_id` описывают происхождение сценария. `metadata.lexical_family_id` связывает каноническое слово с ошибками ввода; `sense_id` и контекст различают его значения. Совпадение слова в двух независимых сценариях само по себе не создаёт общий split-group. Все производные одного сценария, включая его переводы/опечатки/раскладки, остаются в одном split. Специальный экзамен на невиданные лексемы требует отдельно назначенного лексического split.

## Явное исключение строки

`metadata.training_allowed=false` у non-reference строки запрещает её допуск. Изменение split или ID не отменяет явный запрет. Reference проверяется только как публичный материал через `--allow-reference` и не экспортируется в обучение. Новая разрешённая симуляция остаётся допустимой после фактической генерации, CODEX-review и сохранения её настоящего происхождения; старый пример не переименовывается в якобы выполненный прогон.
