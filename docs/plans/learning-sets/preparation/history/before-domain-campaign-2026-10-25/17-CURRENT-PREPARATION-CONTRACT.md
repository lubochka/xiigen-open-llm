Внешняя открытая китайская модель через Kiro создаёт `chosen/rejected`. Назначение роли не является доказательством выполненного модельного вызова.

**Цель этого этапа — получить реальные обучающие тройки для моделей/Unit XIIGEN.** В каждой строке prompt задаёт предметную задачу ученику, chosen содержит полный желаемый ответ, rejected — полный правдоподобный ответ с назначенной ошибкой. Кандидатный статус означает стадию приёмки. Он не заменяет учебное содержание служебным каркасом. CREATE_ONLY запрещает запуск обучения сейчас, но требует создать именно данные для него.

Дата: 25.10.2026. Этап — **только создание учебного материала и кандидатных DPO-пар (`CREATE_ONLY`)**. Этот документ применяет прямые условия нынешнего поручения к уже существующей библиотеке. Он выше исторических процедур, сохранённых в старых примерах команд, навыках и RAG. Предметные требования карточек — смысл, язык, версия, состав партии — сохраняются. Прямое поручение «just creation no review» означает, что предметное review, blind, accept, export, native import и обучение не входят в текущую очередь; они запускаются только отдельным последующим заданием.

## Какие требования сняты для этой подготовки

| Прежнее препятствие | Действующее правило |
|---|---|
| Обязательная сверка checksum каждого фрагмента перед составлением prompt | Не требуется. Исторические hashes остаются справочными полями происхождения. Нужны читаемый назначенный источник и понятный локатор. |
| Подтверждение профиля CODEX как барьер для создания | Не требуется для CREATE_ONLY. При этом обе роли выбора и оценки закреплены за CODEX с `astra 6 ultracode`; китайский генератор остаётся в своей выбранной модели. Не выдумывать исполнение/identity. |
| Подписанные/связанные по хешам selection и review receipts до генерации | Не требуются. Нужна одна содержательная тема; независимое review относится к отдельно поручаемому этапу и не блокирует создание. |
| Два разных генератора для каждой симуляционной пары | Не требуется. Текущая китайская модель может создать обе альтернативы; её самооценка остаётся черновой. |
| Полная production build/test/CI цепочка для новой партии | Не требуется. Сейчас выполняется только минимальная проверка создаваемого JSON/контракта/количества. Предметный runtime oracle запускается позже, если будет поручена оценка данных. |
| Обязательное независимое review, blind/accept/export перед следующим набором | Не требуется и не выполняется в CREATE_ONLY. После DRAFT_CREATED сразу следующий stream. |
| Обязательное обучение перед созданием кандидатного файла | Не требуется. Draft можно подготовить сейчас; полезность для Student проверяется отдельным учебным пилотом. |
| Автоматическая интеграция удачного наблюдения | Не разрешена. Измеренный результат становится кандидатом; перенос выбирает Люба. |

`tools/sets.py` и его прежний формат приёмки сохранены как история и возможность отдельно порученного продолжения старого процесса. Наличие старого draft/review не включает этот процесс автоматически; в нынешней сессии действует CREATE_ONLY. Старый runner не является обязательной предварительной ступенью для `tools/batches.py`. Не создавать фиктивные квитанции ради старого гейта. Старые артефакты и эксперименты не удалять.

Снятие служебного гейта не изменяет native-контракт core. Если реальный потребитель требует конкретный формат, состояние или права, их устанавливают по коду; подготовочный JSONL нельзя самовольно объявлять нативным DPO. [Граница импорта](10-NATIVE-CONTRACT-BOUNDARY.md) остаётся явной.

## Что требуется по существу

Один shard содержит одну тему, одну микроцель, один профиль и один split. Полный prompt задаёт факты, по которым предпочтение можно обосновать без скрытого знания автора. Chosen и rejected решают одинаковую задачу в сопоставимом формате. В rejected одна существенная правдоподобная ошибка; другой верный синоним, стратегия или разрешённое состояние означает tie, а не плохой ответ.

Метки, rationale, правильный маршрут, `canonical_source`, оценка и ответы экзамена не попадают в learner-visible input, если сама учебная задача прямо не требует их как вход. Пол и синтаксическая роль остаются раздельными признаками. Поле metadata само по себе не доказывает, что kNN, токенизатор или LoRA его читает. В учебном пилоте нужен указанный потребитель и фактический вход.

Для переводов сохраняются исходный текст, направление, смысл, морфология и семейства. Опечатка и неверная раскладка связаны с исходной лексемой при подтверждённом смысле. Один и тот же текст может быть обычным словом или буквальным идентификатором — роль фрагмента задаётся в prompt. Раскладку проверяют по объявленной таблице; нельзя угадывать её по первому алфавиту.

Для оркестрации классы «разрешить/отклонить», «ждать/завершить» и отрицательные контроли относятся к одной теме решения. Переводческий запрос в наборе маршрутизатора не делает этот набор уроком перевода. Для документации описывают фактическое поведение показанного кода; для написания кода реализуют видимое требование. Точный язык, framework version, SQL dialect, входные данные и ожидаемое поведение задаются до генерации.

## Последующий отдельный этап: независимая проверка и свидетельства

**Этот раздел не выполняется в CREATE_ONLY.** Он сохраняет требования к будущему прямому заданию на приёмку данных. Генератор не создаёт blind/review, не вызывает reviewer и не ждёт его перед следующим набором.

CODEX с Astra 6 ultracode в отдельном контексте решает запрос по A/B без исходных меток и rationale. Он записывает фактическую среду и наблюдаемую модель; если модель неизвестна, это так и указывается, без заявления о подтверждённом соответствии назначенному профилю. Произвольный reviewer или человек не назначаются вместо CODEX этим пакетом. Имя роли не доказывает независимость: важен отдельный контекст, в который не попали ключ и первоначальное предпочтение.

Для перевода нужна двуязычная смысловая проверка. Для оркестрации — пошаговое разрешение сценария по видимым условиям. Для исполняемого кода — локальный oracle на одинаковых входах для обеих альтернатив; проверяется именно различающий результат. Для документации, зависящей от runtime, oracle выполняет исходную мини-программу и сопоставляет оба описания с результатом. Нельзя исполнять текст объяснения вместо описанного кода. Неисполняемый факт может быть подтверждён назначенным источником с конкретной ссылкой.

Синтаксический `check` не принимает смысл. `accept` проверяет связность записанных результатов review и соответствие исходному blind-пакету; он не аутентифицирует провайдера и не доказывает истинность человеческого или модельного утверждения. Выполненный oracle подтверждают сырые результаты, а не `PASS`, вписанный генератором. Ничьи и неполные случаи сохраняются для новой версии. Экспорт имеет статус **INTERCHANGE_FORMAT_ONLY**, пока не установлен нативный потребитель.

## Семейства и независимый экзамен

План семей задаётся до ответов. Переводы, обратные переводы, раскладки, опечатки, переименование сущностей и DOC/CODE-описания одного исходника сохраняют общий origin и один split. Новый случай не становится независимым только от нового ID. Считаются отдельно строки, исходные ситуации и лексические семейства.

Публичные reference-примеры и их потомки не включаются в закрытый EXAM. Для нескольких потоков одного исходника использовать общий `--family-plan`. Для последовательной партии использовать `--previous` или `request.next_start`; нельзя вычислять start по числу строк, особенно когда на семью приходятся две строки. В отдельно порученной проверке между партиями передавать их через `--against`; непереданные корпуса инструмент не проверяет. Это не требование запускать review в сессии создания. При создании сохранять известные origin/family/split из request без самостоятельного смешения тем.

Разные цели могут делить один родительский пул в 1000 TRAIN-пар. Эти квоты не складываются повторно. Пилотные TRAIN-пары входят в большой корпус; DEV/EXAM назначаются отдельно. Большая плановая цель — 129000 TRAIN-пар — не является выполненной генерацией, расходом бюджета или принятым набором.

## Поведение исполнителя, обязательное для каждой карточки

1. При прямом «следующий» или новом ID немедленно перейти к указанному заданию. **Запрещено продолжать прошлую задачу, дописывать её отчёт или повторять её запуск.** Текущие файлы сохраняются; они не дают разрешения продолжать старую работу. При STOP прекратить действия сразу.
2. При реально живом процессе сохранить один handle и пользоваться документированным wait/resume этой среды до terminal. Yield, таймаут транспорта и отсутствие stdout не доказывают сбой процесса. Не запускать второй процесс или монитор и не заканчивать ход словами «жду» вместо ожидания. Использовать интервалы ожидания инструмента, не самодельный цикл частого status-polling.
3. Если процесса нет, не придумывать ожидание. Если состояние запуска неизвестно, сначала восстановить его handle или подтверждённый terminal-статус. Каталог с частичным результатом не удалять для повторного старта; новая попытка получает новый run ID.
4. После структурного `finish` переходить к следующему stream; не делать blind/review/accept/export и не ждать отдельного reviewer. Отчёт — по-русски, ответы пар — по предметному контракту. Путь вывода, файлы, роль модели, команды и источник заданы request и карточкой. Обучение Student, генерация Teacher, проверка данных и production-интеграция имеют отдельные статусы.

5. Не создавать фиктивный RAG, пустой manifest или текст под ожидаемый hash. Источник читается по `request.paths.sources` из настоящего локального RAG. Если указанный файл отсутствует, назвать точный ID/path и свериться с manifest/картой переноса; выдуманный источник не является восстановлением.
6. Текущие instructions о mode и paths действуют после compaction и во всех дочерних заданиях. Запрещены поиск той же схемы в чужом проекте, самостоятельная смена корня и новая генерация вместо продолжения существующего request.

Исторические цитаты STOP в исходном поручении являются примерами нарушения; текущую задачу они не отменяют.

## Когда будет поручен учебный пилот

Восстановить совместимое обученное состояние B1 из назначенного каталога. Проверить фактический тип/версию модели, токенизатор, адаптеры, параметры продолжения и вход набора. Если B1 отсутствует, явно выполнить отдельную подготовку базового состояния, обучить на минимально достаточном TRAIN, сохранить один раз и затем переиспользовать. Путь будущего B1 не является доказательством существования весов.

Оба плеча сравнения начинают из одного состояния и получают сопоставимый бюджет. Сначала измеряется предметная Unit при правильном маршруте, затем отдельно prompt → обучаемый router → домен → Unit → ответ. Ошибки маршрута показываются отдельно от качества предметного обучения. EXAM не используется для выбора checkpoint, а после сохранения проверяются свежая загрузка и продолжение обучения.

Сравниваются правильные ответы/токены по явной рубрике, критические ошибки, время достижения полезного результата, обновления/примеры до него, CPU/GPU-время и память — только фактически измеренные показатели. **Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности не обязателен.** Все остальные дельты и ухудшения публикуются рядом. Время Teacher/проверки/компиляции не переименовывается во время обучения Student.

**0 правильных до и 0 после — невалидное доказательство обучения.** Малые сдвиги loss/margin не исправляют отсутствие учебного результата. Бюджет должен позволять получить минимальный содержательный результат; его нельзя заведомо ограничить несколькими почти нулевыми обновлениями. Допустимое сравнение скорости требует одинакового ненулевого уровня качества. Реальные улучшения документируются кандидатом; неудачные и незавершённые попытки сохраняются.

## Граница этой поставки

Подготовка prompt, создание draft текущей моделью Kiro и локальное структурное завершение составляют текущую рабочую дорожку. Доступность инструментов не означает, что конкретный draft уже создан: это подтверждает только фактический файл и состояние. Китайская модель, native oracle новых примеров и Student в этой документной поставке не запускались. Готовых больших принятых корпусов, готовых B1 и измеренного прироста обучения здесь не заявлено.
