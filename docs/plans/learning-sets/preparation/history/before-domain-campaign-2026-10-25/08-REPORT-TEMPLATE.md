# Отчёт создания кандидатной партии

**Текущий режим — CREATE_ONLY.** После записи реального draft выполнить один структурный `finish`. Он сохраняет `report.creation.md` в каталоге попытки, сохраняя имеющийся отчёт версией; затем исполнитель переходит к следующему stream. Независимый reviewer, oracle, приёмка, export и обучение не входят в нынешнее задание. Полный договор — [20](20-CREATE-ONLY-AND-PATHS.md), команды — [18](18-BATCH-RUNBOOK.md).

## Текущий короткий шаблон: report.creation.md

Писать по-русски, только факты текущего создания. Значения `unknown`, `NOT_ESTABLISHED`, `NOT_RUN`, `NOT_MEASURED` допустимы; чужие свидетельства и вымышленные числа — нет. Отчёт не превращается в самостоятельный длительный этап.

```text
Тема и задача: <чему посвящены пары; какая одна ошибка отличает rejected>.
Партия: <stream_id, run, profile, split>.
Создано: <фактическое число> из <count> кандидатных строк;
семей: <число по request и фактическим строкам>.
Модель: <фактически наблюдаемая модель/selector либо unknown>.
Файлы: <абсолютные пути request, draft, state и отчёта>.
Источники: <назначенные RAG ID; без выдуманных дополнительных материалов>.
Структура: <finish завершён / конкретная ошибка / неполный результат>.
Состояние: <DRAFT_CREATED только после успешного finish; иначе фактическое>.
Смысловая приёмка: не проводилась; review_status=not_requested,
semantic_quality=NOT_ESTABLISHED.
Обучение Student: NOT_RUN; учебные метрики: NOT_MEASURED.
Следующий stream: <точный ID из актуального registry либо указанный Любой>.
```

Например: «Создано 10 из 10 кандидатных пар о null-only fallback в C#. Структурный finish завершён, файлы сохранены по request. Модель не раскрыта: unknown. Предметное review и обучение не проводились. Перехожу к следующему stream из registry». Это пример формы, а не сообщение о выполненной сейчас генерации.

Если известны время/токены/стоимость генерации, их можно добавить одной строкой как наблюдавшиеся затраты Teacher. Не требовать эти значения, если инструмент их не сообщает; символы не переводить в токены по догадке. Стоимость **принятой** пары и число принятых здесь не вычисляются: приёмка не выполнялась.

Количество и имена файлов не доказывают смысловую корректность, независимость семейств или обучение. Не заменять отсутствие данных отметкой PASS. Ошибки структуры и неполный count указываются прямо; старые версии сохраняются. PREPARED без draft не является завершённым созданием.

Если процесс ещё жив, сначала дождаться terminal по его штатному handle/wait; отчёт не заменяет ожидание. При прямом NEXT/новом ID немедленно перейти и не дописывать прежний отчёт. При STOP прекратить действия. После успешного создания — следующий stream, без blind/review/accept/export.

## Сохранённый полный шаблон для отдельного будущего поручения

**Следующие разделы сейчас не заполнять и не выполнять ради их заполнения review, oracle, приёмку или обучение.** Полный шаблон предназначен только для будущего прямого задания на эти этапы. Он сохраняется в `report.md` отдельно от нынешнего `report.creation.md`; существующие отчёты не перезаписываются.

Заполнять только действительно порученные и выполненные части. Если заказано review без обучения, учебные поля остаются NOT_RUN/NOT_MEASURED. Для каждой проверенной версии сохранять ссылки на реальные данные и сырые результаты; имя роли и флаг PASS не заменяют свидетельства.

### 1. Что выполнено

- Stream ID / topic / objective / domain / profile / split / run.
- Задание и одна учебная граница обычными словами.
- Каталог результата и фактическое состояние: подготовлено / сгенерировано / проверено / принято / требует исправления.
- Генератор: реально наблюдаемая модель Kiro, либо unknown. Проверяющий: отдельный контекст/человек, наблюдаемая модель либо unknown, видел ли ключ.
- Источники: назначенные RAG ID и конкретный фрагмент, факты симуляции.

### 2. Материал и его проверка

| Показатель | Фактическое значение |
|---|---|
| Запрошенные / полученные / структурно полные строки | |
| Независимые исходные ситуации / лексические семьи | |
| Состав классов и контрфактуальных пар | |
| Проверенные / принятые / tie / отклонённые | |
| Проверенные другие корпуса через --against | |
| Смысловые ошибки и конкретные pair_id | |
| Oracle/языковая проверка: что действительно выполнено | |
| Файлы review и сырые результаты предметных проверок | |
| Сохранённые старые версии / исправленные pair_id и derived_from | |

Показать минимум одну реальную принятую пару и каждый существенный тип отказа; при отсутствии принятых так и написать. Не называть parse или checksum смысловой приёмкой.

### 3. Затраты подготовки

Время и токены генерации, review и исправления показываются отдельно. Если стоимость не наблюдается, оставить unknown; символы не считать токенами. Стоимость принятой пары считать по реально принятым строкам и явно названным затратам. При нуле принятых деление не выполнять.

### 4. Обучение — только если оно действительно поручено и выполнено

Если поручено только review данных, а обучения не было: **Student NOT_RUN; метрики NOT_MEASURED**. Смысловое review не доказывает обучение.

Для последующего пилота указать native потребителя, реальные файлы/методы входа, идентификатор и путь восстановленного B1, train/dev/exam datasets, усвоенный навык, число/бюджет обновлений, контрольное и изменённое плечо. Сравнить:

| Полезный показатель | До | После | Дельта | Домен/профиль и граница вывода |
|---|---:|---:|---:|---|
| Правильные ответы / полный знаменатель | | | | |
| Критические ошибки | | | | |
| Секунды / обновления до одного ненулевого качества | | | | |
| CPU/GPU-время и RAM/VRAM | | | | |
| Правильный маршрут / ответ при правильном маршруте | | | | |
| Результат после fresh load / продолжение обучения | | | | |

Любое измеренное полезное улучшение — успех по этому показателю и домену; рост точности не обязателен. Все ухудшения показать рядом. 0→0 не даёт учебного результата; loss/margin отдельно и не подменяют усвоение. Время подготовки не переименовывать во время обучения.

### 5. Решение и продолжение

Что исправить в данных/промпте новой версией; какой конкретный вывод поддерживают факты; какие вопросы ещё не проверены. Измеренный выигрыш — кандидат для Любы, без автоматического изменения production. Для подготовки не создавать successful-fix из проверки JSON.

Следующий ID брать из execution-queue.json; прямое указание Любы выше очереди. При NEXT запрещено продолжать предыдущую задачу и её отчёт; при STOP прекратить действия. Если реальный запуск ещё жив, не завершать отчёт вместо штатного ожидания terminal.
