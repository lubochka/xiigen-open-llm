# Требования, приоритеты и разрешение конфликтов

> **Текущее поручение — CREATE_ONLY.** Смысловые требования к содержимому и семействам используются при авторинге. Процедуры отдельного review/oracle/приёмки/обучения ниже сейчас не запускаются и не блокируют создание. После записи реального draft выполнить один структурный finish; он создаёт report.creation.md, затем следующий ID. Полный договор: [20](20-CREATE-ONLY-AND-PATHS.md); схема строки: [dpo-candidate.schema.json](schemas/dpo-candidate.schema.json).

Текущее поручение — подготовить материал, подробные симуляции, промпты и навигацию, затем создавать кандидатные DPO-наборы без отдельного review. [Контракт 17](17-CURRENT-PREPARATION-CONTRACT.md) и [runbook 18](18-BATCH-RUNBOOK.md) определяют действующую процедуру. Исторические эксперименты, результаты и документы сохраняются; новое обучение и production-интеграция этой поставкой не объявляются.

## Порядок

Сначала устраняются дефекты реального учебного входа и препятствия подготовки. Затем согласуются карточки, индексы, роли и пути. После этого добавляются предметные темы и планируется увеличение объёма. Проверки, не связанные с подготовкой, загрузкой или оценкой обучения, не включаются в учебные эксперименты.

`execution-queue.json` — полный порядок фактически исполняемых потоков; карточка выбирается по ID. Пользовательский ID выше очереди. При NEXT/новом ID запрещено продолжать прошлую задачу, её отчёт или повторный запуск. STOP прекращает действия немедленно. Цитаты прошлых STOP в исходном поручении — описание нарушения, а не отмена текущего задания.

## Разрешённые расхождения

| Историческое правило или дефект | Действующее решение |
|---|---|
| Обязательный профиль `astra 6 ultracode`, selection/review receipts и checksums | Для новой подготовки не требуются. Записывается фактически выбранная модель либо unknown; reviewer сейчас не назначен и не ожидается; `tools/batches.py` не зависит от старой приёмки `sets.py` |
| Review/blind/accept/export задерживают следующий набор | Не входят в CREATE_ONLY. Один структурный finish записывает создание; затем следующий stream без reviewer |
| Старый короткий output root или поиск в llm_mvp_core | Результаты под `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets`; инструменты и sources из соседнего preparation, абсолютные paths находятся в request |
| Полный main checkout в отдельном `xp-rag` | Встроенный `rag/` содержит 58 выдержок и 28 выбранных originals |
| Родитель и его objectives исполнялись как независимые корпуса | 89 покрытых parent/profile исключены; их `command=null`, названы заменяющие потоки. Общая квота распределяется один раз |
| Старые номера и NEXT расходятся | Индексы, очередь и хвосты карточек обновляет `tools/refresh_indexes.py`; источником порядка является refresh-config |
| RAG-023/027 запрещают близкие пары; RAG-029 использует `[WRONG: …]` | Близкие ответы допустимы при реальном отличии смысла; объяснение ошибки остаётся в rationale, без метки в rejected |
| Исторический `train_ready` или `PASS` | Не наследуется. Сейчас сохраняется DRAFT_CREATED без смысловой приёмки; независимое review видимого условия возможно только в отдельно порученном будущем этапе |
| Два допустимых ответа ошибочно образуют preferred/rejected | Tie сохраняется как неоднозначность; не создаётся фиктивный учебный сигнал. Примеры проблемы: RAG-TR-001 и RAG-DATA-001 |
| Запрет синтетики или два разных генератора в старом навыке | Текущая задача разрешает обе альтернативы выбранной китайской моделью; происхождение обозначается честно. Их создание не выдаётся за независимое review и не требует второго генератора |
| Карта раскладки была только в metadata | В 12 исправленных reference-строках таблица находится в prompt. Metadata не передаётся Student вместо входа |
| Всегда исправлять слово, похожее на wrong-layout | Один сырой фрагмент имеет restore/preserve-контроли по видимой роли; буквальный идентификатор может требовать сохранения |
| Документация runtime принималась как source_grounded | При отдельно порученной будущей приёмке `executable_oracle` требует реальный предметный запуск; сейчас его не выполняют. В CREATE_ONLY назначенный код/сценарий остаётся полным содержанием prompt |
| Оптимистичная трактовка yield/нет stdout | Сохраняется один handle; штатное ожидание до terminal. Без дублей, частого polling и окончания хода вместо ожидания |
| Подготовочный export назван нативным DPO | Статус `INTERCHANGE_FORMAT_ONLY`; реальные native admission/author/format требования проверяются отдельно |

Предметные выводы старых источников применимы только в их области. Например, порядок слов и морфология важны для перевода; синтаксическое дерево — для соответствующих кодовых задач. Наличие поля family/AST в JSON само по себе не означает, что tokenizer, kNN либо LoRA использует его.

В [19](19-CURRENT-DELIVERY.md) разделены нынешнее изменение CREATE_ONLY и сохранённые результаты проверок прежней версии. Для генератора они являются сведениями о подготовке, а не обязанностью повторять технический аудит или позднее review. Они участвуют в формировании будущего учебного входа, но не записываются как успешные эксперименты обучения. [Предыдущая версия страницы](history/before-batches-2026-10-25/07-CONFLICTS-AND-REQUIREMENTS.md) сохраняет старые процедуры и историю решений.
