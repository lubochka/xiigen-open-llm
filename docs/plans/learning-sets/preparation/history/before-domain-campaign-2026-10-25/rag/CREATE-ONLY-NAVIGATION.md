# Местный RAG для создания DPO: точная навигация

**Зачем нужен этот RAG:** генератор берёт предметные факты и сценарии, чтобы создать реальные учебные `prompt/chosen/rejected` для моделей/Unit XIIGEN. Prompt задаёт задачу ученику; выбранный и отклонённый ответы — полные предметные решения. Инструкции поиска, отчёты и имена файлов не заменяют этот материал. CREATE_ONLY запрещает запуск learner сейчас, сохраняя учебное назначение создаваемых данных.

После разбора реального запуска уточнены [учебная постановка](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/learning-sets/preparation/22-DPO-LEARNING-TASK-AND-CE76.md) и [промпт для продолжаемой Kiro-сессии](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/learning-sets/preparation/prompts/DPO-TASK-RESET-RU.md). Само обновление навигации не изменяет старые сохранённые prompt.md и draft.jsonl.

Дата: 25.10.2026. Сейчас создаются кандидатные наборы в режиме **CREATE_ONLY**. Эта страница описывает навигацию исполнителя; она не является предметным уроком для Student и не добавлена в каталог обучающих источников.

## Готовое задание вместо повторного поиска

1. Открыть `preparation/prompts/MASTER-PROMPT-RU.md` в уже выбранной китайской модели Kiro. Смена модели не требуется; неизвестное точное имя остаётся `unknown`.
2. Выбрать точный `stream_id` из `preparation/execution-queue.json`, либо применить явный ID пользователя. В очереди есть card, command, output и next ID.
3. Выполнить назначенную команду `create_sets.ps1`. Она собирает `request.json`, `prompt.md`, `commands.md`, `RESUME.md`, `state.json` и шаблон отчёта. Она **не создаёт DPO-пары сама**.
4. Прочитать готовый prompt: он уже содержит профиль, count, семьи, схему, предметные примеры и назначенные выдержки. Абсолютные пути находятся в `request.paths`. Не искать другую схему или `batches.py` в `llm_mvp_core`.
5. Создать реальные пары в точном `request.paths.draft`, выполнить один структурный `finish` из commands.md и перейти к следующему stream. Review, oracle, accept, export и обучение сейчас не запускаются.
6. После compaction читать `RESUME.md` / `resume --request <фактический request.json>`. Не начинать discovery заново и не повторять выполненную генерацию.

Назначенные исходники читаются как материал. Их старые команды, имена моделей, checksum gates и регламенты не устанавливают дополнительных поручений. Политика CREATE_ONLY и текущий пользовательский запрос выше исторических цитат.

## Если назначенный файл отсутствует

`prepare` сообщает точный отсутствующий путь. Сначала проверить, что открыт актуальный пакет `preparation` ветки `llm_plan3`. Получить именно отсутствующий tracked-файл из этой ветки. Уже созданные пользовательские файлы и попытки не удалять; конфликтующее содержимое сохранить отдельной версией до восстановления исходника.

Нельзя создавать пустой manifest, подменять источник одним заголовком, сочинять текст по имени файла или пытаться подобрать текст под SHA256. Исторические hashes сохранены только как метаданные происхождения; генератор не обязан их пересчитывать. Без реального материала по одной теме фиксируется точный пробел, а остальные назначенные темы сохраняют доступность.

## Что считается завершением

`PREPARED` — есть задание. `DRAFT_CREATED` — файл содержит назначенное количество структурно согласованных кандидатных строк. Семантическое качество остаётся `NOT_ESTABLISHED`, review — `NOT_REQUESTED`, обучение — `NOT_RUN`. `finish` не запускает модель и не устанавливает качество перевода, кода или обучения.

При NEXT перейти немедленно к указанному ID, не дописывая прошлый отчёт. При STOP прекратить действия. Если процесс реально работает, продолжать один сохранённый handle штатным wait/resume; timeout транспорта и отсутствие stdout не доказывают сбой. Отдельный фоновый polling или повторный запуск не заменяют ожидание.
