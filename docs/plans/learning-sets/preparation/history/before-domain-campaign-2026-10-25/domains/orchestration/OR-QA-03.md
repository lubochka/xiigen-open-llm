## Обязательные правила этой карточки

Используется текущая выбранная китайская модель Kiro без override; неизвестный model ID не выдумывается. CODEX выбирает и оценивает материал по [контракту ролей](../../10-CODEX-AND-CHINESE-ROLES.md). Навыки архитектуры, планирования, ревью плана/кода, авторинга и коммуникации читаются по [06](../../06-SOURCES-AND-SKILLS.md). Общая тема и один profile не смешиваются с предметными уроками переводов/SQL; эти слова в сценарии описывают проверяемый риск.

**NEXT/новый ID: немедленно перейти, не доделывать прежний опыт/отчёт/исправления. STOP: немедленно прекратить новые действия.** Старые файлы и опыты сохраняются. Живой запуск продолжается по одному handle с документированным wait/resume до terminal в текущем раунде; нельзя объявлять отказ по пустому stdout, запускать дубль или заменять ожидание фоновым polling.

Будущее обучение использует восстановленный квалифицированный B1 из микроцели; создание нового B1 — отдельный однократный producer, а не повтор перед каждой проверкой. Должен существовать ненулевой полезный baseline; 0→0 не принимается. Данные, ответы и полное используемое состояние получают hashes. Любое измеренное улучшение полезного показателя — успех по метрике и домену с остальными дельтами и ухудшениями рядом. Результат — кандидат для решения Любы; сейчас обучение и production-изменения не выполняются.
