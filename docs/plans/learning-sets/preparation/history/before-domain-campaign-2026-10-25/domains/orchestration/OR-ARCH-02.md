## 5. Будущая проверка обучения

Изменяемый механизм: обучаемое состояние получателя этой микротемы; inference должен читать именно обновлённую версию. До запуска в experiment host фиксируются recipient, training_entrypoint, inference_entrypoint, source_to_unit_fields, hash tokenizer/template/dataset и parent checkpoint. Без фактического связывания это подготовленные данные, а не TRAIN_READY.

Восстановить один совместимый обученный parent в оба плеча. Если такого состояния нет, общий базовый набор обучить один раз до ненулевого полезного усвоения, сохранить и затем переиспользовать его; не начинать с нуля при каждом опыте. Контроль без нового урока отделяет влияние повторного inference. Будущий бюджет должен покрывать минимальное усвоение; правильные ответы 0→0 не считаются учебным результатом.

Полезный показатель: Доля handoff без потери поля/единицы/кардинальности; отдельно ненужные поля, уточнения, размер и время ответа.

Любое измеренное улучшение полезного показателя считается успехом **по этому показателю и этому поддомену**, даже при неизменной точности. Рядом показываются все остальные дельты, включая ухудшения. Вывод не даёт автоматического разрешения на production перенос; измеренный результат оформляется кандидатом для решения пользователя.

Для долгого задания найти поддерживаемый tool/handle и ждать его штатным механизмом в текущем раунде. Пустой/задержанный вывод не означает падение. Не перезапускать существующий job, не делать частый пустой polling и не заканчивать раунд обещанием ждать. ## 6. Разобранные reference-пары

### 1. `unit_changed`

**Prompt:** Симуляция. Узел A отдаёт duration_ms=250. Узел B принимает duration_ms как целое число миллисекунд. Между ними преобразования единиц нет. Сформулируй handoff.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "duration_ms: integer, значение 250 миллисекунд.",
  "next_step": "Передать duration_ms=250 в B."
}
```

**Rejected**

```json
{
  "input_contract": "duration_ms: integer, значение 250 секунд.",
  "next_step": "Передать duration_ms=250 в B."
}
```

**Почему различаются:** Одинаковое имя поля не спасает контракт, если изменена единица.

Семья: `simulation.handoff.duration`; pair_id: `OR-ARCH-02.base.REF2.F001.P01`.

### 2. `null_replaced`

**Prompt:** Симуляция. A отдаёт phone=null, потому что телефон необязателен. B принимает phone: string|null и сохраняет null без подстановки. Составь передачу.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "phone: string|null; null допустим.",
  "next_step": "Передать phone=null в B."
}
```

**Rejected**

```json
{
  "input_contract": "phone: string|null; null допустим.",
  "next_step": "Передать phone=\"\" в B."
}
```

**Почему различаются:** Пустая строка и null по заданному контракту не взаимозаменяемы.

Семья: `simulation.handoff.nullable`; pair_id: `OR-ARCH-02.base.REF2.F002.P01`.

### 3. `missing_collapsed_to_null`

**Prompt:** Симуляция. В PATCH отсутствие поля nickname означает «не менять», а nickname=null означает «очистить». Запрос не содержит nickname. Опиши передачу из A в B.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "nickname может отсутствовать; null означает очистку.",
  "next_step": "Передать PATCH без поля nickname."
}
```

**Rejected**

```json
{
  "input_contract": "nickname может отсутствовать; null означает очистку.",
  "next_step": "Добавить nickname=null при передаче PATCH."
}
```

**Почему различаются:** Подстановка null превращает отсутствие изменения в удаление значения.

Семья: `simulation.handoff.missing`; pair_id: `OR-ARCH-02.base.REF2.F003.P01`.

### 4. `handoff_drops_packet`

**Prompt:** Симуляция. A произвёл два DomainPacket: billing и delivery. B принимает массив всех выбранных пакетов и планирует зависимости. Ни один пакет не помечен исключённым. Составь handoff.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "DomainPacket[] со всеми выбранными пакетами.",
  "next_step": "Передать [billing, delivery] в B."
}
```

**Rejected**

```json
{
  "input_contract": "DomainPacket[] со всеми выбранными пакетами.",
  "next_step": "Передать [billing] в B."
}
```

**Почему различаются:** Передача одного пакета теряет явно выбранную ветку. Это учебная тема handoff, а не обучение billing и delivery.

Семья: `simulation.handoff.batch`; pair_id: `OR-ARCH-02.base.REF2.F004.P01`.

### 5. `cancelled_as_failure`

**Prompt:** Симуляция. A возвращает status=cancelled. B по контракту обрабатывает success, failed и cancelled отдельно; отменённая задача не должна автоматически повторяться. Сформулируй передачу.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "status ∈ {success, failed, cancelled}.",
  "next_step": "Передать status=cancelled в B."
}
```

**Rejected**

```json
{
  "input_contract": "status ∈ {success, failed, cancelled}.",
  "next_step": "Передать status=failed в B."
}
```

**Почему различаются:** Смена статуса может запустить ошибочный retry вместо отмены.

Семья: `simulation.handoff.cancellation`; pair_id: `OR-ARCH-02.base.REF2.F005.P01`.

### 6. `revision_defaulted`

**Prompt:** Симуляция. A вернул document_id=D7 и revision=12. B обновляет только при expected_revision=revision из A. Других чтений между узлами не было. Составь handoff.
Формат ответа: JSON: input_contract (string), next_step (string). Контракт и действие описываются без кода реализации.

**Chosen**

```json
{
  "input_contract": "document_id и expected_revision из результата A обязательны.",
  "next_step": "Передать document_id=D7, expected_revision=12."
}
```

**Rejected**

```json
{
  "input_contract": "document_id и expected_revision из результата A обязательны.",
  "next_step": "Передать document_id=D7, expected_revision=0."
}
```

**Почему различаются:** Значение по умолчанию теряет фактическую версию, требуемую для согласованного обновления.

Семья: `simulation.handoff.version`; pair_id: `OR-ARCH-02.base.REF2.F006.P01`.
