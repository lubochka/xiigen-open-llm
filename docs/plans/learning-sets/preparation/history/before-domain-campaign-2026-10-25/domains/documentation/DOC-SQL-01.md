## Примеры для составления контрастов

### Пример 1

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. T(v) содержит 7, NULL, 7. SELECT COUNT(*) AS a, COUNT(v) AS b FROM T; Укажи a,b.

**Chosen:**

```text
a=3, b=2.
```

**Rejected:**

```text
a=3, b=3.
```

**Почему отличается:** COUNT(v) не считает NULL. Тип: `count_null`. Объяснение не включается в ответ.

### Пример 2

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. T(v) содержит 1, NULL, 2. SELECT v FROM T WHERE v IS NULL; Опиши выбранные строки.

**Chosen:**

```text
Выбирается строка с NULL.
```

**Rejected:**

```text
Выбираются строки со значениями 1 и 2.
```

**Почему отличается:** IS NULL проверяет именно отсутствие значения. Тип: `null_predicate`. Объяснение не включается в ответ.

### Пример 3

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. T(v) пустая. SELECT COUNT(*) AS n FROM T; Что возвращается?

**Chosen:**

```text
Одна строка с n=0.
```

**Rejected:**

```text
Ноль строк.
```

**Почему отличается:** Агрегат без GROUP BY выдаёт одну строку. Тип: `empty_aggregate`. Объяснение не включается в ответ.

### Пример 4

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. T(v) содержит 3,3,5. SELECT COUNT(DISTINCT v) AS n FROM T; Что означает n?

**Chosen:**

```text
n=2: количество различных значений, не равных NULL; числовой 0 не исключался бы.
```

**Rejected:**

```text
n=3: количество всех строк.
```

**Почему отличается:** DISTINCT устраняет повтор значения 3. Тип: `distinct_ignored`. Объяснение не включается в ответ.

## Невалидные пары и граничные случаи

Не принимать два эквивалентных ответа, отвергать только стиль или недостаточную длину, ссылаться на невидимую зависимость, придумывать версии и использовать ошибочную старую заготовку как истину. Не считать compilation PASS доказательством исполнения контракта. SQL без ORDER BY не требует конкретного порядка строк; NULL и дубликаты обязательны. RxJS teardown не доказывает физический rollback сервера. Для документации callee summaries должны присутствовать, если вывод от них зависит.

Матрица генерации: 40% обычные случаи, 30% границы, 20% правдоподобные почти правильные ответы, 10% недостаток сведений с явным корректным ограничением вывода. Проценты — первоначальная квота после проверки на этой теме; не размешивать разные предметные темы. Семейства отделить до ответа модели; DEV и EXAM не показывать TRAIN-генератору. Публичные reference примеры не являются закрытым EXAM.
