## Примеры для составления контрастов

### Пример 1

**Условие:** Авторская симуляция. Среда: C# 10 / .NET 6. Все необходимые факты указаны ниже. Task<int> Load(CancellationToken ct) => repo.Load(ct); Договор repo.Load: асинхронно читает хранилище, принимает ct; ошибок не подавляет. Опиши wrapper.

**Chosen:**

```text
Передаёт ct в repo.Load и возвращает его Task; собственного чтения или перехвата ошибки нет.
```

**Rejected:**

```text
Возвращает Task от repo.Load, но не передаёт ему ct.
```

**Почему отличается:** Вызов содержит ct. Тип: `lost_cancellation`. Объяснение не включается в ответ.

### Пример 2

**Условие:** Авторская симуляция. Среда: C# 10 / .NET 6. Все необходимые факты указаны ниже. async Task<int> Twice() { var x = await Read(); return 2*x; } Read завершает Task<int> значением 3. Назови результат.

**Chosen:**

```text
После завершения Read возвращает 6.
```

**Rejected:**

```text
Возвращает 3 после завершения Read.
```

**Почему отличается:** Результат умножается на два после await. Тип: `lost_transform`. Объяснение не включается в ответ.

### Пример 3

**Условие:** Авторская симуляция. Среда: C# 10 / .NET 6. Все необходимые факты указаны ниже. async Task Save() { await repo.Store(); audit.Add("done"); } repo.Store завершается исключением, catch нет. Будет ли добавлена запись done?

**Chosen:**

```text
Нет: исключение прерывает выполнение до audit.Add.
```

**Rejected:**

```text
Да: audit.Add выполняется после неуспешного repo.Store.
```

**Почему отличается:** Без catch/finally следующая строка не выполняется. Тип: `wrong_error_path`. Объяснение не включается в ответ.

### Пример 4

**Условие:** Авторская симуляция. Среда: C# 10 / .NET 6. Все необходимые факты указаны ниже. Task Ping() { calls++; return Task.CompletedTask; } calls — поле. Опиши изменение calls.

**Chosen:**

```text
calls увеличивается при вызове Ping; возвращается уже завершённый Task.
```

**Rejected:**

```text
calls увеличивается только после того, как вызывающий код выполнит await.
```

**Почему отличается:** Инкремент расположен до возврата Task. Тип: `invented_await_effect`. Объяснение не включается в ответ.

## Невалидные пары и граничные случаи

Не принимать два эквивалентных ответа, отвергать только стиль или недостаточную длину, ссылаться на невидимую зависимость, придумывать версии и использовать ошибочную старую заготовку как истину. Не считать compilation PASS доказательством исполнения контракта. SQL без ORDER BY не требует конкретного порядка строк; NULL и дубликаты обязательны. RxJS teardown не доказывает физический rollback сервера. Для документации callee summaries должны присутствовать, если вывод от них зависит.

Матрица генерации: 40% обычные случаи, 30% границы, 20% правдоподобные почти правильные ответы, 10% недостаток сведений с явным корректным ограничением вывода. Проценты — первоначальная квота после проверки на этой теме; не размешивать разные предметные темы. Семейства отделить до ответа модели; DEV и EXAM не показывать TRAIN-генератору. Публичные reference примеры не являются закрытым EXAM.
