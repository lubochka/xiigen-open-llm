## Примеры для составления контрастов

### Пример 1

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. Customers(id): 1,2. Orders(customer_id): 1,1. SELECT c.id FROM Customers c LEFT JOIN Orders o ON o.customer_id=c.id; Укажи мультимножество результата.

**Chosen:**

```text
1, 1, 2; порядок строк не задан.
```

**Rejected:**

```text
1, 2; порядок строк не задан.
```

**Почему отличается:** Два заказа порождают две строки для customer 1. Тип: `join_multiplicity`. Объяснение не включается в ответ.

### Пример 2

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. Customers(id) содержит 1,2. Orders(customer_id) содержит 1,1. SELECT c.id FROM Customers c INNER JOIN Orders o ON o.customer_id=c.id; Укажи результат.

**Chosen:**

```text
Две строки с id=1; id=2 отсутствует.
```

**Rejected:**

```text
Две строки с id=1 и одна строка id=2.
```

**Почему отличается:** INNER JOIN не сохраняет отсутствие совпадения. Тип: `inner_vs_left`. Объяснение не включается в ответ.

### Пример 3

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. Customers 1,2; Orders(customer_id,status): (1,'paid'). LEFT JOIN по customer_id, затем WHERE o.status = 'paid'. Останется ли customer 2?

**Chosen:**

```text
Нет: после JOIN его NULL-строка не проходит WHERE.
```

**Rejected:**

```text
Да: LEFT JOIN гарантирует сохранение customer 2 после любого WHERE.
```

**Почему отличается:** WHERE применяется к результату соединения. Тип: `where_null_filter`. Объяснение не включается в ответ.

### Пример 4

**Условие:** Авторская симуляция. Среда: T-SQL / SQL Server 2019; ANSI_NULLS ON. Все необходимые факты указаны ниже. SELECT c.id FROM Customers c WHERE EXISTS (SELECT 1 FROM Orders o WHERE o.customer_id=c.id); У customer 1 три заказа. Сколько строк customer 1 выдаст запрос при одной строке Customers?

**Chosen:**

```text
Одну строку.
```

**Rejected:**

```text
Три строки.
```

**Почему отличается:** EXISTS проверяет существование, не размножает исходную строку. Тип: `exists_vs_join`. Объяснение не включается в ответ.

## Невалидные пары и граничные случаи

Не принимать два эквивалентных ответа, отвергать только стиль или недостаточную длину, ссылаться на невидимую зависимость, придумывать версии и использовать ошибочную старую заготовку как истину. Не считать compilation PASS доказательством исполнения контракта. SQL без ORDER BY не требует конкретного порядка строк; NULL и дубликаты обязательны. RxJS teardown не доказывает физический rollback сервера. Для документации callee summaries должны присутствовать, если вывод от них зависит.

Матрица генерации: 40% обычные случаи, 30% границы, 20% правдоподобные почти правильные ответы, 10% недостаток сведений с явным корректным ограничением вывода. Проценты — первоначальная квота после проверки на этой теме; не размешивать разные предметные темы. Семейства отделить до ответа модели; DEV и EXAM не показывать TRAIN-генератору. Публичные reference примеры не являются закрытым EXAM.
