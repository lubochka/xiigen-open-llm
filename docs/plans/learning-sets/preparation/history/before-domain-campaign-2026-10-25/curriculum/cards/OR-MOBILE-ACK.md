## 5. Оси генерации и содержательная проверка

- **ack_state:** none; queued; applied; rejected.
- **identity:** matching_operation; other_operation; different_payload.
- **local_state:** pending; retained_error; closed.

В первой партии должны присутствовать все релевантные состояния из этих осей и близкие контроли с противоположным действием. Не требуется механическое равенство всех комбинаций; фактическое распределение классов записать в отчёте. Если целый класс отсутствует, не объявлять pilot содержательно полным.

- ACK относится к точным операции и содержанию; локальное сохранение не выдаётся за применение на сервере.
- Включены корректное закрытие после applied и сохранение ошибки после terminal_rejected.
- Идентификатор в target совпадает с ожидаемой операцией, не с чужим ACK.
- Один решающий дефект; выбранный ответ следует из видимого prompt, а не из скрытых метаданных.
- Есть близкий контроль с обратным решением; нельзя выигрывать постоянным ожиданием, отказом или одним классом.
- Контрпример не выдан за новую измеренную строку и остаётся в семье исходного сценария.
- Набор не подменяет обучение роутингу предметным ответом и наоборот.

Не смешивать:

- Не обучать API мобильной платформы, полному алгоритму merge или дизайну интерфейса.
- Не смешивать один mobile shard с серверным outbox только потому, что в обоих встречается ACK.

Невалидны два одинаково допустимых ответа, потеря решающего контекста, альтернативы с разными заданиями и отрицательный ответ с несколькими независимыми дефектами. Сохранить причину карантина; новая версия получает новый ID и `derived_from`.

## 6. Шесть полных reference-примеров

Ответы ученика не содержат рационализацию выбора. Объяснение и контрпример ниже предназначены автору и проверяющему. Контрпример принадлежит тому же открытому семейству и не может стать независимым EXAM.

### Пример 1: OR-MOBILE-ACK-REF-01

Семейство: `v3-ref.or-mobile-ack.f01`.

**Вход:**

```text
Симуляция мобильной синхронизации. Операция Q записана в локальную очередь, сеть offline, сервер Q не видел. Правило: удалять Q можно только по связанному ACK applied; retain_pending оставляет Q и локальные данные, close_pending удаляет Q как синхронизированную. Верни JSON next_action, operation_id=Q.
```

**Предпочтительный ответ:**

```json
{
  "next_action": "retain_pending",
  "operation_id": "Q"
}
```

**Правдоподобный ошибочный ответ:**

```json
{
  "next_action": "close_pending",
  "operation_id": "Q"
}
```

**Различающий факт:** Локальная сохранность не является серверным подтверждением применения.

**Контрпример / граница:** После проверенного ACK applied для Q и его содержания close_pending становится допустимым.

**Происхождение:** развитие прежней reference-пары `OR-MOBILE-01-REF-001`; исходная семья `OR-MOBILE-01-REF-F001`. Новый ID не делает этот материал независимым экзаменом.
