## Предметный промпт

```text
Создавай малые ситуации о готовности одной задачи к передаче следующему исполнителю. Всегда покажи утверждённый исходный контракт и фактический prompt. Контраст — ровно одна утрата/искажение поля либо отсутствие утраты. Не задавай скрытую проверку неизвестного файла. Работай только с этим objective_id и его темой. Ситуации синтетические; полные условия помещай в prompt. Изменяй причинные условия, а не только названия объектов. Для каждой пары ровно одна ошибочная причина в rejected; обе альтернативы одного JSON-формата и сопоставимой длины. Не добавляй пояснения или метки правильности в chosen/rejected. Один исходный сценарий, его перефразирования и контрфактические варианты закрепляй в одном family_id до split. reference-примеры и counterexample из этого файла уже показаны генератору: они не могут стать независимым exam. Следуй полям request.json, ID семей и лимиту count; не копируй эталоны в новый train. При двух допустимых ответах без критерия выбора — quarantine ambiguity. ## Формат ответа
```

JSON {"next_step": одно из действий prompt}; один следующий шаг, без кода и списка дополнительных задач.

## Оси новых сценариев

- **delivery_state:** полный фактический prompt; только ссылка на недоступный файл; утрачено одно поле
- **evidence:** точные bytes prompt; только наличие файла

### OR-CODE-PROMPT-CONTEXT-REF-01 / base

Семейство: `OR-CODE-PROMPT-CONTEXT-RF01`.

**Условие:**

```text
Нужно передать worker задачу сохранить черновик формы при HTTP 409. Контракт уже утверждён: draft_retention="keep". Worker видит только фактический prompt: «Обработай HTTP 409 в форме». Он не имеет доступа к файлам. Допустимые next_step: add_draft_retention, dispatch_worker. Что сделать следующим?
```

**Предпочтительный ответ:**

```text
{"next_step":"add_draft_retention"}
```

**Правдоподобный ошибочный ответ:**

```text
{"next_step":"dispatch_worker"}
```

**Доказательство различия:** У worker отсутствует решающее условие о сохранении черновика; handoff ещё не готов.

**Контрпример / граница:** Если фактический prompt уже содержит draft_retention="keep" и остальные требования, следующий шаг dispatch_worker.

### OR-CODE-PROMPT-CONTEXT-REF-02 / base

Семейство: `OR-CODE-PROMPT-CONTEXT-RF02`.

**Условие:**

```text
Worker должен вызвать SaveAsync. Утверждённая сигнатура: SaveAsync(string id, CancellationToken ct). Фактический prompt содержит эту сигнатуру полностью, id="A7", ct=providedToken, ожидаемый вызов и все критерии. Worker подтвердил получение этих байтов. Допустимые next_step: dispatch_worker, repackage_same_signature. Выбери один.
```

**Предпочтительный ответ:**

```text
{"next_step":"dispatch_worker"}
```

**Правдоподобный ошибочный ответ:**

```text
{"next_step":"repackage_same_signature"}
```

**Доказательство различия:** Все зависимости этой ограниченной задачи переданы; повторная упаковка не закрывает отсутствующий контекст и задерживает следующий шаг.

**Контрпример / граница:** Если из фактического prompt пропал CancellationToken при том же исходном контракте, нужно сначала восстановить подпись, а не dispatch_worker.

Разные SQL-диалекты дают разные конструкции. Допустимые next_step: add_dialect_to_prompt, dispatch_worker. Верни один next_step.

**Правдоподобный ошибочный ответ:**

**Контрпример / граница:** Если prompt уже явно задаёт SQL Server 2022 и полный вход, корректен dispatch_worker.
