## Учебная граница

Создавать ровно заданный контракт фиксированного состава/значений либо живого readonly view без лишнего копирования или скрытой ленивости.

Родительская карточка остаётся источником остальных случаев. Эта микроцель добавляет контрбаланс и явные поздние изменения; количество файлов не считается улучшением обучения. CODE реализует явно заданный договор. Две формы одного исходника имеют общее семейство до назначения split, даже если обучаются разные получатели.

```text

Дано: sealed class Item { public int Value; }  Реализуй static Item[] Capture(List<Item> source): вернуть новый массив с текущим составом source, сохранив именно исходные ссылки Item; не клонировать Item и не менять source. После Capture источник может добавить элемент, а исходный Item — изменить поле. Длина массива должна остаться прежней, изменение поля исходного объекта должно быть видно. ```

**Предпочтительный ответ:**

```text
static Item[] Capture(List<Item> source) => source.ToArray();
```

**Правдоподобный ошибочный ответ:**

```text
static Item[] Capture(List<Item> source) => source.Select(x => new Item { Value = x.Value }).ToArray();
```

**Почему различаются:** Новый массив не клонирует Item: членство фиксировано, поле доступно через общую ссылку.

**Различающий случай:** После изменения first.Value результат имеет длину 1 и значение 8; добавление в source не меняет длину copy.

**Почему различаются:** Условие требует отдельный Detail; rejected копирует только внешний Item и делит вложенную ссылку.

**Различающий случай:** source=[original], original.Detail.Value=4; после Freeze установить original.Detail.Value=8. Результат должен сохранить Value=4, а обе ссылки Item и Detail отличаются от исходных.
