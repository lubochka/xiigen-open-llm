## Полные публичные примеры

Это исходные опоры для понимания правила, не независимо сгенерированные TRAIN/EXAM. Контрпример — часть той же публичной семьи. Для каждого направления брать соответствующий профиль; не смешивать строки разных профилей в учебном пакете.

### OR-DESIGN-ROLE-PANEL-REF-01 / base

Семейство: `OR-DESIGN-ROLE-PANEL-RF01`.

**Условие:**

```text
Пользователь U8 — owner документа D8 в tenant A. Политика экрана: owner своего документа видит edit_panel; viewer видит read_panel. Иных ограничений нет. Выбери panel для U8 на D8.
```

**Предпочтительный ответ:**

```text
{"panel":"edit_panel"}
```

**Правдоподобный ошибочный ответ:**

```text
{"panel":"read_panel"}
```

**Доказательство различия:** Указанное владение даёт ровно edit_panel для своего документа.

**Контрпример / граница:** Если owner документа D8 — U9, а U8 имеет только viewer, правильной станет read_panel.

### OR-DESIGN-ROLE-PANEL-REF-02 / base

Семейство: `OR-DESIGN-ROLE-PANEL-RF02`.

**Условие:**

```text
U10 — tenant_admin только tenant A. Открыт документ tenant B. Политика не допускает межтенантного чтения и предписывает access_denied_panel; admin_panel показан администратору своего tenant. Выбери panel.
```

**Предпочтительный ответ:**

```text
{"panel":"access_denied_panel"}
```

**Правдоподобный ошибочный ответ:**

```text
{"panel":"admin_panel"}
```

**Доказательство различия:** Имя tenant_admin не переносит область прав с A на B.

**Контрпример / граница:** Если документ принадлежит A и прочих запретов нет, admin_panel станет правильным.

### OR-DESIGN-ROLE-PANEL-REF-03 / base

Семейство: `OR-DESIGN-ROLE-PANEL-RF03`.

**Условие:**

```text
U11 получил делегирование только на просмотр отчёта R11 до 18:00; сейчас 17:00, tenant совпадает. Политика: действующее view-only делегирование даёт report_read_panel, редактирование требует edit grant и report_edit_panel. Edit grant отсутствует. Выбери panel.
```

**Предпочтительный ответ:**

```text
{"panel":"report_read_panel"}
```

**Правдоподобный ошибочный ответ:**

```text
{"panel":"report_edit_panel"}
```

**Доказательство различия:** Делегирование активно, но его операция только view; нельзя расширять её до edit.

**Контрпример / граница:** Если в том же делегировании явно разрешён edit и срок не истёк, report_edit_panel допустима.

### OR-DESIGN-ROLE-PANEL-REF-04 / base

Семейство: `OR-DESIGN-ROLE-PANEL-RF04`.

**Условие:**

```text
Для владельца заказа U12 разрешён order_panel. Платформенный диагностический trace_panel доступен лишь platform_support; U12 этой роли не имеет. Заказ завершён с ошибкой, пользователь должен видеть свой заказ и понятное сообщение. Выбери panel: order_panel или trace_panel.
```

**Предпочтительный ответ:**

```text
{"panel":"order_panel"}
```

**Правдоподобный ошибочный ответ:**

```text
{"panel":"trace_panel"}
```

**Доказательство различия:** Ошибка заказа не наделяет владельца ролью support и не меняет аудиторию диагностической панели.

**Контрпример / граница:** Если пользователь явно platform_support и запросил диагностический просмотр с данным правом, trace_panel будет правильной поверхностью.
