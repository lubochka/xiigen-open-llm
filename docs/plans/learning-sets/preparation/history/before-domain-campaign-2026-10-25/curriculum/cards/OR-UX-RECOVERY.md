## Формат ответа

JSON {"message": краткая русская фраза, "action": enum из prompt}; два поля вместе описывают одно восстановление.

## Оси новых сценариев

- **cause:** validation; expired_session; transport_unknown; access_denied
- **draft:** сохранён локально; не нужен
- **retry_contract:** безопасное status/resume; повтор запрещён без проверки

## Что не смешивать

- Не учить реализации network-кода, UI-цветам или обходу доступа.
- Не менять одновременно причину ошибки и независимое действие: rejected ошибается в одной связке причина→восстановление.

## Будущий этап: содержательная проверка (сейчас не запускать)

Метод: `rubric`.

- Сообщение не утверждает failure, когда известна только потеря транспорта.
- Действие соответствует данному пользователю и контракту.
- Не предлагается терять черновик или бессмысленно повторять неизменённый ошибочный ввод.
- Решающие факты доступны в prompt; источник не требуется угадывать по имени файла.
- У chosen и rejected одна задача, один формат и ровно один причинный дефект.
- Контрпример меняет решающий факт и объясняет, когда прежний chosen уже неверен.
- Никакие численные результаты в сценарии не представлены как реальные измерения этого пакета.

## Полные публичные примеры

Это исходные опоры для понимания правила, не независимо сгенерированные TRAIN/EXAM. Контрпример — часть той же публичной семьи. Для каждого направления брать соответствующий профиль; не смешивать строки разных профилей в учебном пакете.

### OR-UX-RECOVERY-REF-01 / base

Семейство: `OR-UX-RECOVERY-RF01`.

**Условие:**

```text
Сервер вернул VALIDATION: поле age должно быть целым от 1 до 120; введено 150. Черновик сохранён локально. Доступные action: edit_age, retry_unchanged. Составь одно сообщение и действие.
```

**Предпочтительный ответ:**

```text
{"message":"Возраст должен быть от 1 до 120. Черновик сохранён.","action":"edit_age"}
```

**Правдоподобный ошибочный ответ:**

```text
{"message":"Возраст должен быть от 1 до 120. Черновик сохранён.","action":"retry_unchanged"}
```

**Доказательство различия:** При неизменённом 150 повтор даст ту же ошибку; сообщение сохранено одинаковым, дефект ровно в действии.

**Контрпример / граница:** Если сервер сообщил временный сбой, а введённое значение валидно и повтор безопасен по контракту, retry_unchanged может стать корректным.

### OR-UX-RECOVERY-REF-02 / base

Семейство: `OR-UX-RECOVERY-RF02`.

**Условие:**

```text
Сессия пользователя истекла до отправки формы; сервер подтвердил NOT_SUBMITTED. Черновик D21 сохранён локально и после входа должен быть продолжен. Action: sign_in_resume_draft, sign_in_blank_form. Составь JSON.
```

**Предпочтительный ответ:**

```text
{"message":"Сессия истекла. Войдите, чтобы продолжить заполнение.","action":"sign_in_resume_draft"}
```

**Правдоподобный ошибочный ответ:**

```text
{"message":"Сессия истекла. Войдите, чтобы продолжить заполнение.","action":"sign_in_blank_form"}
```

**Доказательство различия:** Обе ветви восстанавливают вход, но только одна сохраняет уже сделанную пользователем работу по контракту.

**Контрпример / граница:** Если пользователь явно удалил черновик и запросил новую пустую форму, sign_in_blank_form становится правильным.

### OR-UX-RECOVERY-REF-03 / base

Семейство: `OR-UX-RECOVERY-RF03`.

**Условие:**

```text
После отправки заявки связь прервалась. Серверный итог неизвестен; доступен check_status по request_id. Повтор до проверки может создать вторую заявку. Допустимый action=check_status в обоих ответах. Напиши сообщение без утверждения неизвестного результата.
```

**Предпочтительный ответ:**

```text
{"message":"Ответ пока не получен. Проверим состояние заявки.","action":"check_status"}
```

**Правдоподобный ошибочный ответ:**

```text
{"message":"Заявка не создана. Проверим состояние заявки.","action":"check_status"}
```

**Доказательство различия:** Действие одинаковое, дефект только в неподтверждённом утверждении, что заявка не создана.

**Контрпример / граница:** Если check_status достоверно вернул not_created, фраза «Заявка не создана» больше не ложна.

### OR-UX-RECOVERY-REF-04 / base

Семейство: `OR-UX-RECOVERY-RF04`.

**Условие:**

```text
Для просмотра документа нужна роль reviewer. Сервер вернул ACCESS_DENIED, пользователь роль не имеет. Политика предусматривает request_access у владельца; retry_same_role не меняет права. Выбери сообщение и одно действие.
```

**Предпочтительный ответ:**

```text
{"message":"Для этого документа нужен доступ reviewer.","action":"request_access"}
```

**Правдоподобный ошибочный ответ:**

```text
{"message":"Для этого документа нужен доступ reviewer.","action":"retry_same_role"}
```

**Доказательство различия:** Повтор с неизменными правами не устраняет подтверждённую причину; запросить предусмотренный доступ — подходящее действие.

**Контрпример / граница:** Если доступ уже выдан, а ответ был временно устаревшим и контракт разрешает обновление, retry_same_role может быть корректным.
