## Оси новых сценариев

- **parent_restore:** полный совместимый снимок; только веса; новая инициализация; снимок с другим tokenizer
- **changed_factor:** способ выбора negatives; один update DPO; одна kNN-функция
- **stochastic_state:** ГСЧ сохранён и восстановлен; другая случайная последовательность

## Что не смешивать

- В этой партии только выбор общего совместимого parent для A/B; split leakage, скорость и критерии успеха вынести в свои objective.
- Не включать ответы предметного переводчика или кода; learner учится выбирать протокол восстановления.
- Не использовать 0→0 или выдуманный runtime как свидетельство результатов.

### OR-QA-CAUSAL-REF-01 / base

Семейство: `OR-QA-CAUSAL-RF01`.

**Условие:**

```text
Сравниваются два способа выбора negatives. Совместимый обученный snapshot S даёт 6/10 правильных ответов на калибровке. Требуется изолировать только выбор negatives. A: оба плеча клонируют полный S. B: первое плечо клонирует S, второе заново инициализируется. Данные, EXAM и бюджет одинаковы. Выбери protocol A или B.
```

**Предпочтительный ответ:**

```text
{"protocol":"A"}
```

**Правдоподобный ошибочный ответ:**

```text
{"protocol":"B"}
```

**Доказательство различия:** B одновременно меняет negatives и начальное состояние; один фактор нельзя отделить от другого. Числа условные.

**Контрпример / граница:** Если изучается именно сравнение способов инициализации, различные начальные состояния допустимы, но это другой заранее заданный objective.

### OR-QA-CAUSAL-REF-02 / base

Семейство: `OR-QA-CAUSAL-RF02`.

**Условие:**

```text
Обучающий consumer использует weights и optimizer moments; momentum ненулевой и влияет на следующий update. Snapshot S сохраняет оба. A: второе плечо восстанавливает только weights и обнуляет moments. B: оба плеча восстанавливают weights+moments из S. Исследуемый фактор — состав одной DPO-пары; данные/EXAM/бюджет совпадают. Выбери protocol.
```

**Предпочтительный ответ:**

```text
{"protocol":"B"}
```

**Правдоподобный ошибочный ответ:**

```text
{"protocol":"A"}
```

**Доказательство различия:** Обнуление реально используемых moments меняет следующий учебный шаг независимо от пары; B сохраняет общий parent.

**Контрпример / граница:** Если optimizer прямо задан stateless и moments не читаются, их отсутствие не является дефектом и требовать фиктивные moments нельзя.

### OR-QA-CAUSAL-REF-03 / base

Семейство: `OR-QA-CAUSAL-RF03`.

**Условие:**

```text
Исследуется один новый вариант kNN update. Consumer читает обученную память M и случайно выбирает tie-break через RNG. S сохраняет M и RNG; усвоение уже ненулевое. A: оба плеча восстанавливают M+RNG из S. B: память совпадает, но второе плечо берёт новый RNG seed. Прочие условия равны. Выбери protocol.
```

**Предпочтительный ответ:**

```text
{"protocol":"A"}
```

**Правдоподобный ошибочный ответ:**

```text
{"protocol":"B"}
```

**Доказательство различия:** Другой RNG может изменить выбор при равенстве независимо от исследуемого kNN update; A изолирует фактор.

**Контрпример / граница:** Если consumer детерминирован и RNG вообще не используется, отличие нечитанного RNG не влияет на parent и не должно блокировать протокол.

### OR-QA-CAUSAL-REF-04 / base

Семейство: `OR-QA-CAUSAL-RF04`.

**Условие:**

```text
Snapshot S обучен с tokenizer T1, vocab_sha=v1 и adapter A1; он имеет ненулевые ответы. Consumer интерпретирует weights через token IDs. A: оба плеча загружают weights S, но второе использует T2 с иными token IDs. B: оба восстанавливают S+T1+A1 и проверяют v1. Исследуемый фактор — новый DPO update, не tokenizer. Выбери protocol.
```

**Предпочтительный ответ:**

```text
{"protocol":"B"}
```

**Правдоподобный ошибочный ответ:**

```text
{"protocol":"A"}
```

**Доказательство различия:** Одинаковые числовые weights с другой интерпретацией token IDs не являются тем же обученным parent.

**Контрпример / граница:** Если T2 доказанно побитово эквивалентен T1 по mapping и конфигурации, смена имени файла не меняет parent; сравнивать нужно содержимое.
