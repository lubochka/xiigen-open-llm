## Формат ответа

JSON {"action": enum из prompt, "run_id": исходный ID}; никаких новых run_id без явного разрешённого retry-контракта.

## Оси новых сценариев

- **state:** running; transport_unknown; terminal_success; terminal_failure
- **artifact:** нет; частичный; terminal связанный с run
- **wait_response:** ещё running; terminal; transport timeout

## Полные публичные примеры

Это исходные опоры для понимания правила, не независимо сгенерированные TRAIN/EXAM. Контрпример — часть той же публичной семьи. Для каждого направления брать соответствующий профиль; не смешивать строки разных профилей в учебном пакете.

### OR-AUTO-TERMINAL-REF-01 / base

Семейство: `OR-AUTO-TERMINAL-RF01`.

**Условие:**

```text
Обучающий run L41 имеет handle h41. Последнее подтверждённое состояние сервера running. progress.json содержит steps=8, но terminal.json ещё нет. API wait(h41) штатно ждёт до следующего состояния. Допустимые action: wait, read_final. Верни JSON action, run_id=L41.
```

**Предпочтительный ответ:**

```text
{"action":"wait","run_id":"L41"}
```

**Правдоподобный ошибочный ответ:**

```text
{"action":"read_final","run_id":"L41"}
```

**Доказательство различия:** Промежуточные шаги не являются terminal-результатом; продолжение того же handle сохраняет один процесс.

**Контрпример / граница:** Если сервер сообщил terminal_success для L41 и terminal.json с этим run_id полностью записан, действие read_final становится правильным.

### OR-AUTO-TERMINAL-REF-02 / base

Семейство: `OR-AUTO-TERMINAL-RF02`.

**Условие:**

```text
Run L42 уже запущен. Документированный wait(h42) вернул transport_timeout через 30 секунд; последняя heartbeat сервера говорит state=running, heartbeat_age=2s. Контракт разрешает повторно ждать тот же handle; start_new разрешён только после terminal_failure. Допустимые action: wait, start_new. Верни JSON action и run_id=L42.
```

**Предпочтительный ответ:**

```text
{"action":"wait","run_id":"L42"}
```

**Правдоподобный ошибочный ответ:**

```text
{"action":"start_new","run_id":"L42"}
```

**Доказательство различия:** Причина возврата wait относится к транспорту; подтверждённый процесс ещё работает, поэтому разрешения на retry нет.

**Контрпример / граница:** Если вместо heartbeat running получен terminal_failure и контракт retry остаётся разрешённым, следующий run можно создать действием start_new с явной привязкой к прежней попытке.

### OR-AUTO-TERMINAL-REF-03 / base

Семейство: `OR-AUTO-TERMINAL-RF03`.

**Условие:**

```text
Run L43 завершился terminal_failure до первого учебного шага: build_exit=1. failure.json полностью записан и содержит run_id=L43. Доступные action: read_failure, wait. Пользователь не отменял задачу; нужен достоверный статус этой попытки. Верни JSON action, run_id.
```

**Предпочтительный ответ:**

```text
{"action":"read_failure","run_id":"L43"}
```

**Правдоподобный ошибочный ответ:**

```text
{"action":"wait","run_id":"L43"}
```

**Доказательство различия:** Состояние terminal_failure известно, поэтому ожидание уже не может довести этот run до обучения; нужно прочитать фактический отказ, не придумывая учебных метрик.

**Контрпример / граница:** Если build ещё идёт и state=running без terminal_failure, следует wait, а не читать незавершённый failure.json.

### OR-AUTO-TERMINAL-REF-04 / base

Семейство: `OR-AUTO-TERMINAL-RF04`.

**Условие:**

```text
Отправлен запуск L44 с идемпотентным request_id=q44. Транспорт оборвался без ответа; успех или отказ процесса неизвестен. API resume(q44) возвращает handle и фактическое состояние; повторный start без этого API может создать второе обучение. Допустимые action: resume, start_new. Верни JSON action, run_id=L44.
```

**Предпочтительный ответ:**

```text
{"action":"resume","run_id":"L44"}
```

**Правдоподобный ошибочный ответ:**

```text
{"action":"start_new","run_id":"L44"}
```

**Доказательство различия:** Отсутствие ответа не доказывает, что запуск не создан; resume разрешает неопределённость без дубля.

**Контрпример / граница:** Если resume вернул not_created и контракт прямо разрешил повторный start с тем же request_id, следующим действием может быть start_new.
