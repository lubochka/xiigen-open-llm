## Узкая задача

Переводить однозначное слово после одного случайного повторения буквы; связывать чистую, ошибочную и layout-формы одной лексемы, сохраняя исходную строку.

Родитель: `TR07`. Предметные домены: `tr.en`, `tr.ru`, `tr.he`. Профили: `ru-en`, `he-en`, `en-ru`, `he-ru`, `en-he`, `ru-he`. Один request содержит только назначенный профиль и эту микроцель.

Статус: авторский материал подготовки. Публичные пары ниже — reference; их нельзя копировать в новый корпус или выдавать за скрытый экзамен. Китайская генерация, оценка Astra и Student для нового материала не выполнялись; ожидаемые результаты не являются измерениями.

## Подробный промпт исполнителю

Сначала составь грамматически правильную исходную фразу и выбери ровно одно обычное слово в той форме, которая реально стоит в предложении. Выбери индекс i одного Unicode code point и повтори этот же символ сразу после него: raw = canonical[:i+1] + canonical[i] + canonical[i+1:]. Длина raw на один code point больше canonical. При удалении вставленного символа по i+1 должно получиться исходное слово побуквенно, включая регистр. Запиши canonical_token, raw_token, mutation.kind=repeat_one_codepoint, mutation.index=i, inserted_index=i+1 и character. Индексы нулевые, не UTF-8 bytes и не model tokens. Строка source_raw и learner prompt содержат raw, а canonical_source хранится только в metadata. Не «упрощай» законные двойные буквы: book→boook — одна вставка; book→bok — уже удаление.
Chosen переводит восстановленное слово; rejected подменяет только этот предмет другой естественной лексемой, сохраняя действие, место, участников и остальные факты. Не используй бессмысленную строку как rejected и не выдавай правильный синоним за ошибку. Для Hebrew возьми простые слова без niqqud и без преобразования final forms; вставленный code point буквальный. Не добавляй опечатку в другое слово. В каждом request 10 новых семей назначенной темы: пять случаев повторения внутри слова, три у начала и два у конца, если назначенный материал позволяет; это распределение позиции, а не дополнительные темы. Каждый пример получает ровно одну фактическую вставку. Уже назначенное содержательное распределение request имеет приоритет перед этими примерами позиционного разнообразия.
Простая самопроверка до записи: выпиши длины n→n+1, убери только inserted_index, сравни весь результат с canonical_token; затем назови один предмет, который неверно переведён в rejected. Эти действия помогают авторингу, отдельный review/отчёт об этом не создаётся. Лексическая семья canonical/raw/layout остаётся той же при подтверждённом смысле; молоко и сок в одну lexical family не сливаются. Если вывод о семейном происхождении не следует из назначенного общего сюжета, не выдумывай его.

### 1. TR07-REPEAT.ru-en.REF01 — ru-en

**Задача ученику:**

~~~~text
Переведи с языка «русский» на язык «английский». Выдай только перевод. В одном обычном слове случайно повторена ровно одна соседняя буква. Восстанови это слово и переведи предложение, сохранив остальные факты.
Исходный текст: Моолоко на столе.
~~~~

**Chosen — полный правильный ответ:**

~~~~text
The milk is on the table.
~~~~

**Rejected — правдоподобная содержательная ошибка:**

~~~~text
The juice is on the table.
~~~~

**Почему есть предпочтение:** Удаление ровно добавленной повторной буквы возвращает исходную лексему. Rejected подменяет предмет другим; место и остальные факты не меняются.

Различающий дефект: `single_repeated_character_wrong_lexeme`. Семья: `v3-ref.translation.repeat.milk-table`.
