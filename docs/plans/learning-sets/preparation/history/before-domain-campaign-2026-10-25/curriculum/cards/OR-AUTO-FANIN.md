## 1. Что усваивается

Выбирать следующий шаг fan-in по состоянию каждой обязательной попытки и явной политике частичного результата.

Один набор учит одному решению. Несколько классов и отрицательные контроли принадлежат этому же решению. Разные поддомены оркестрации в одну партию не объединять. JSON с решением — учебная цель; это не заявление о наличии одноимённого метода или класса в production.

## 5. Оси генерации и содержательная проверка

- **children:** success+running; success+success; failure+running; success+failure.
- **policy:** all_required; allow_partial; all_or_nothing.
- **artifact_identity:** current_attempt; stale_attempt.

В первой партии должны присутствовать все релевантные состояния из этих осей и близкие контроли с противоположным действием. Не требуется механическое равенство всех комбинаций; фактическое распределение классов записать в отчёте. Если целый класс отсутствует, не объявлять pilot содержательно полным.

- Все обязательные attempts и terminal-политика перечислены во входе.
- Есть wait и aggregate на почти одинаковых условиях, а также противоположные исходы для partial/all-or-nothing.
- Артефакт принадлежит нужному group/run/attempt; файл на диске сам по себе недостаточен.
- Один решающий дефект; выбранный ответ следует из видимого prompt, а не из скрытых метаданных.
- Есть близкий контроль с обратным решением; нельзя выигрывать постоянным ожиданием, отказом или одним классом.
- Контрпример не выдан за новую измеренную строку и остаётся в семье исходного сценария.
- Набор не подменяет обучение роутингу предметным ответом и наоборот.

Не смешивать:

- Не смешивать с предметным содержанием ответов ветвей, SQL либо точностью learner.
- Не включать в одну пару одновременно изменение политики и ошибку ID: один основной дефект.

Невалидны два одинаково допустимых ответа, потеря решающего контекста, альтернативы с разными заданиями и отрицательный ответ с несколькими независимыми дефектами. Сохранить причину карантина; новая версия получает новый ID и `derived_from`.

## 6. Шесть полных reference-примеров

Ответы ученика не содержат рационализацию выбора. Объяснение и контрпример ниже предназначены автору и проверяющему. Контрпример принадлежит тому же открытому семейству и не может стать независимым EXAM.

### Пример 1: OR-AUTO-FANIN-REF-01

Семейство: `v3-ref.or-auto-fanin.f01`.

**Вход:**

```text
Симуляция автоматизации. Группа G1 содержит обязательные текущие попытки A1 и B1. A1 terminal_success; B1 running. Политика all_required, fail_fast=false: агрегация только после terminal всех обязательных попыток. wait_group ждёт тот же group handle; aggregate читает результаты сейчас. JSON next_action, group_id=G1.
```

**Предпочтительный ответ:**

```json
{
  "next_action": "wait_group",
  "group_id": "G1"
}
```

**Правдоподобный ошибочный ответ:**

```json
{
  "next_action": "aggregate",
  "group_id": "G1"
}
```

**Различающий факт:** Завершилась одна ветвь, а не вся группа; условия сборки ещё нет.

**Контрпример / граница:** Если B1 тоже terminal_success и оба артефакта связаны с текущими попытками, aggregate становится правильным.
