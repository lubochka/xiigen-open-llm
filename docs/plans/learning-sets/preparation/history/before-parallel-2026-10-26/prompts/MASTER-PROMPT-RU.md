# Промпт для Kiro: создание DPO до заданной квоты

Ты создаёшь обучающие предпочтения для моделей/Unit XIIGEN. Используй текущую выбранную китайскую модель Kiro; помощник, если доступен, наследует эту же модель. Не подменяй её и не выдумывай model_id: неизвестное имя запиши `unknown`.

**Reason internally in English. Do not output private reasoning or a chain-of-thought transcript.** Короткий прогресс и итог — по-русски. Язык `prompt/chosen/rejected` задаёт текущий профиль.

Режим **CREATE_ONLY: только создание, без review**. Цель новой кампании — 1000 кандидатных пар на каждый из 21 домена, всего 21 000. Микротема, профиль и партия делят эту квоту. Старый план 132 000 не является текущим поручением.

Инструкции: `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation`. **Писать наборы только в `C:/Projects/llm_mvp_core/learning-sets`**. Не искать preparation в core и не писать новые наборы рядом с planning-инструкциями.

Если пользователь назначил конкретный существующий request, продолжи его по сохранённому пути через resume. Не переносить и не удалять старые попытки. Для новой кампании выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action next -WorkRoot "C:/Projects/llm_mvp_core/learning-sets"
```

Прочитай возвращённые `prompt.md`, `request.json`, `material.required.json`, `commands.md`. Этого достаточно для текущей партии: примеры и выдержки включены. Не открывай всю библиотеку и полные skills по кругу. Дополнительное чтение — только точный source path при конкретном пробеле.

Создай **реальные полные** пары: вход ученика содержит предметную задачу, chosen — правильное решение, rejected — правдоподобное решение с одной заданной ошибкой. Генерационный план или фраза «создай DPO» не заменяют эту тройку. Разные допустимые синонимы не дают предпочтение. Источник, rationale, целевой перевод и скрытое восстановление не должны подсказывать ответ ученику.

Request назначает ровно count строк, IDs, классы и семейства. Для новых семей сначала задай конкретный сценарий и факты; переводческие семьи содержат канонические EN/RU/HE тексты. Остальные направления используют сохранённый материал, а не новую историю под старым F-номером. Самопроверка выполняется при составлении: например, удаление сокращает слово на одну букву и обратная вставка восстанавливает весь исходник; `письмо→пильмо` не удаление. VALIDWORD сохраняет правильное слово и не разрешает придумать смесь 5+5.

Запиши назначенные файлы и выполни готовый `finish`. После DRAFT_CREATED **сразу исполни commands.next и продолжай в той же задаче**. Не спрашивай «продолжать?» после десяти строк и не заканчивай работу, пока квоты не достигнуты. Реальный внешний блок сообщай точно; не выдавай его за завершение.

Повторное завершение использует тот же сохранённый draft и его размер/время изменения. `BLOCKED` после изменения или исчезновения файла не устраняют сбросом state; [точное правило](../20-CREATE-ONLY-AND-PATHS.md#состояние).

**Прямое NEXT/новый ID немедленно меняет задачу:** запрещено дописывать предыдущий отчёт, чинить прошлый опыт или повторять его запуск. **STOP прекращает действия немедленно.** Эти указания выше автоматической очереди.

Живой процесс ожидай через документированный механизм реально доступного инструмента и тот же handle до terminal. Не читай результат до завершения зависимой записи. Не заменяй ожидание повторным стартом, быстрым polling, пустыми вызовами или финальным сообщением «жду». Если поток стал бессвязным, сохрани trace как инцидент, не принимай его за DPO и продолжи от сохранённого request в чистом коротком контексте; не перегенерируй готовые партии. Нечитаемый вывод не даёт права перекодировать здоровые исходные файлы.

Не запускай независимое review/blind, acceptance, export/import, обучение, production CI и checksum-гейты. `finish` проверяет структуру и назначение, не качество обучения. Отчёт: домен, поток, созданные строки, остаток до 1000, путь, следующий ID; качество `NOT_ESTABLISHED`, обучение `NOT_RUN`.

**Параллельное поручение по 192 потокам:** [контракт другой кампании](../27-CAMPAIGN-CONTINUATION-CONTRACT.md) сохранён отдельно. Его 192000/192008 не меняют квоту D1000. Если пользователь назначил именно старую кампанию или существующий request, продолжать их; новая кампания не заменяет их автоматически.
