# Продолжить текущую DPO-задачу после потери контекста

Учебный результат текущего задания — реальные кандидатные prompt/chosen/rejected для XIIGEN. Это не обучение самой Kiro-модели и не отчёт о том, как когда-нибудь создать данные.

**Данные:** `C:/Projects/llm_mvp_core/learning-sets`. **Инструкции:** `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation`. Reason internally in English; do not output private reasoning. Отчёт по-русски. Текущая китайская модель Kiro без override. Режим CREATE_ONLY, без review.

1. Возьми exact request/state/commands текущего запуска. Не угадывай путь по cwd, соседней ветке или историческому журналу.
2. Если пользователь прямо назначил NEXT/новый ID, немедленно переключись. Запрещено продолжать прошлый отчёт, ремонт или запуск. STOP прекращает действия.
3. Возобнови выбранный request через его resume. Сохрани существующие строки и семьи. Отсутствующий готовый prompt можно восстановить штатным resume, но готовый draft не удаляется и не перегенерируется.
4. Прочитай одну назначенную микротему и встроенные примеры. Создай недостающие реальные пары/материал семей; не перечитывай все skills и исторические аудиты.
5. Выполни finish и готовый next. Первая партия не равна1000; продолжай до доменной квоты без вопроса о продолжении. Полный текущий бюджет21000 определяется [реестром](../campaign/registry.json).

При нечитаемом выводе прочитай исходный файл корректным UTF-8; не перекодируй здоровые документы. При бессвязных повторах сохрани trace как неуспешный ответ, не переноси повторяющийся хвост в новый контекст. Причина модель/сервер/UI по такой копии не доказана. Возобновление не требует повторной генерации уже сохранённых партий.

Живой handle ожидается документированным wait/resume до terminal. Пустой stdout, раннее отсутствие файла и timeout транспорта не означают падение. Не запускай дубль и не заканчивай раунд вместо доступного ожидания.
