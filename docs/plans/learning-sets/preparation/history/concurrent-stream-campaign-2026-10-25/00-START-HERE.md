**Прямое поручение: 192 потока, цель 192 000 пар, без вопросов и остановок после очередной партии.** [Контракт продолжения и языка](27-CAMPAIGN-CONTINUATION-CONTRACT.md) · [готовый reset для начатой Kiro-сессии](prompts/DPO-TASK-RESET-RU.md). После END очередь обходится снова до выполнения цели; размер партии берётся из назначения. Видимые служебные пояснения остаются на английском, отчёты для Любы — на русском. Новые правила уже встроены в BATCH/MASTER/reset; старые prompt.md автоматически не переписываются.

**Актуальное дополнение:** [26-DOMAIN-GENERATION-DELIVERY.md](26-DOMAIN-GENERATION-DELIVERY.md). Для предметного обзора — [навигатор](prompts/LIBRARY-NAVIGATOR-RU.md); при уже назначенном stream сразу открыть готовый prompt/request.

[Последующий аудит новых партий](25-GENERATOR-FOLLOWUP-AUDIT-2026-10-25.md) дополняет [первый срез](24-GENERATOR-OUTPUT-AUDIT-2026-10-25.md) и исправляет пропуск в проверке цели VALIDWORD. Для авторинга — [хорошие/плохие примеры и простая самопроверка](prompts/TYPO-AUTHORING-EXAMPLES-RU.md), включая сохранение владельца, остальных фактов и полного предложения; они помогают создавать текущие пары без нового review-гейта. Уже сохранённые prompt.md не обновились автоматически; начатой сессии подсказка передаётся через reset ниже.

Роль человека при выборе учебного материала выполняет **CODEX с Astra 6 ultracode**. Оценку качества DPO также выполняет **CODEX с Astra 6 ultracode**. Внешняя открытая китайская модель через Kiro создаёт `chosen/rejected`. Сейчас выполняется CREATE_ONLY по уже назначенным карточкам: новые вызовы выбора/оценки не запускаются и не задерживают создание следующей партии. Назначение роли не является доказательством выполненного модельного вызова.

**Результат работы — сами учебные DPO-тройки для моделей XIIGEN.** Генератор пишет предметный prompt и два полных ответа на него: желаемый chosen и содержательно ошибочный rejected. Учебный набор не заменяется планом, описанием формата или отчётом о намерении его создать. «Не запускать обучение сейчас» относится к действиям исполнителя, а создаваемые данные предназначены именно для обучения.

Если сессия уже работала по старому prompt, сначала передайте ей [reset-промпт](prompts/DPO-TASK-RESET-RU.md). Он объясняет различие между автором данных и учеником и сохраняет границу CREATE_ONLY; [основание по реальному коммиту](22-DPO-LEARNING-TASK-AND-CE76.md).

**Сейчас требуется только создание (`CREATE_ONLY`).** Для каждой партии сохраните реальные кандидатные пары, выполните минимальную проверку JSON/контракта/количества и переходите к следующему потоку. Предметное review, blind, accept, export, native import и обучение выполняются только по отдельному последующему заданию. Наличие их описания в библиотеке не делает их обязанностями этой сессии.

## Первая партия

1. Прочитайте [общий промпт](prompts/MASTER-PROMPT-RU.md) и [контракт](17-CURRENT-PREPARATION-CONTRACT.md).
2. Возьмите точный `stream_id` из [единой очереди](EXECUTION-QUEUE.md). ID, который указала Люба, имеет приоритет. Исторические номера и summary не заменяют действующий registry.
3. Выполните точную команду выбранного stream из очереди. Команда ниже — пример первого потока исходной кампании; она не отменяет уже назначенный ID и не перезапускает завершённую попытку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Stream TR07-OMISSION/ru-en -Run M001 -Count 10
```

Обёртка находит доступный Python 3 через `py -3` либо `python`. В `request.paths.python_executable` сохраняется фактический интерпретатор; команды `commands.md` уже содержат его абсолютный путь. Вручную подбирать команду Python не нужно.

4. Откройте `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/prompt.md` и соседний `request.json`. Там находятся назначенные семьи, count, split, источники, контракт записи и точные выходные пути. В этой же текущей Kiro-сессии создайте `draft.jsonl`; не считайте результат `prepare` готовым набором.
5. Завершите создание командой `finish` из `commands.md`. Пример, если интерфейс не раскрывает модель:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Action finish -Request "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/request.json" -InputPath "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/draft.jsonl" -Model unknown
```

`finish` проверяет только структурные условия создания и записывает состояние/отчёт. При успешном результате `DRAFT_CREATED` означает «кандидатный файл создан»; смысловая приёмка и обучение не выполнены. Исправляйте только найденные ошибки текущего создаваемого файла, сохраняя прежние версии. После успешного `finish` переходите к следующему stream, не запускайте review.

## Если попытка уже существует или контекст был сокращён

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Action resume -Request "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/request.json"
```

Команда показывает сохранённые пути, статус и следующий ID; она не генерирует, не проверяет смысл и не обучает. Если draft ещё не дописан, продолжите эту попытку по её request. Если `DRAFT_CREATED` уже получен, берите следующий stream. Если существует draft без завершённого состояния, выполните `finish`, а не повторную генерацию. Для новой партии **того же** потока нужны новый run ID и `-Previous` с прежним request; курсор берётся из `next_start`, не из количества строк.

После compaction или при делегировании передайте абсолютные пути к request/prompt/draft, режим `CREATE_ONLY`, текущий stream и следующий ID. Допускается один помощник одновременно, с текущей моделью. Он получает готовый пакет, а не задачу снова исследовать репозитории.

## Обязательное поведение

Checksum, фиксированное имя модели, подписанные receipts, независимый reviewer и product CI не являются условиями создания. Нужны настоящие источники и содержательные пары по назначенному контракту. При отсутствии конкретного источника нельзя создавать пустой manifest, выдумывать текст или подбирать его под hash; используйте указанный файл в локальном `rag/` и сохранённую карту происхождения.

При NEXT/новом ID запрещено продолжать предыдущую задачу, её отчёт или запуск. При STOP действия прекращаются немедленно. Живой процесс ожидается штатным handle/wait до terminal; ранний возврат инструмента не является доказательством сбоя. Не создавайте дубли, циклы частого опроса и новые мониторы вместо ожидания. Старые карточки, наборы и попытки сохраняются.

Отчёт — по-русски: сколько пар реально создано, какая тема, где сохранено, какой следующий ID. Для Student пишется `NOT_RUN`, для учебных метрик — `NOT_MEASURED`. План большого корпуса не является завершённой генерацией.


## Общие сценарии новой переводческой волны

Для TR07-REPEAT, TR06-NUMBER-UNIT и TR03-EVENT-ORDER `prepare` автоматически включает один назначенный TRAIN-план во все шесть направлений. В request есть сам сюжет и все языковые версии; ученик видит только source-язык. После первых 10 сцен требуется следующий новый scenario chunk; старые сцены не повторяют под другими ID. Для DEV/EXAM этих трёх целей пока нет назначенных команд: соответствующие поля очереди null, нужны отдельные непересекающиеся планы. [Точные правила и команды](26-DOMAIN-GENERATION-DELIVERY.md).
