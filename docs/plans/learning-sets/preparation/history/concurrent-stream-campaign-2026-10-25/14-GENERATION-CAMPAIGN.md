# Создание большого корпуса DPO небольшими партиями

**Назначение корпуса — обучение предметным задачам моделей/Unit XIIGEN.** Для каждой строки автор создаёт задачу ученику и два полных ответа на один вход с заданным предпочтением. CREATE_ONLY означает, что нынешняя сессия производит данные и не запускает learner.

**Прямое поручение Любы: 192 потока и цель 192 000 реально созданных кандидатных пар.** Ограничение одной партии (например, 10 строк), готовая волна M008 и один проход очереди не завершают кампанию. После finish немедленно продолжать; после END — следующий обход недовыполненных потоков. Вопросы «продолжать?», «коммитить?», «10 или 25–50?» не блокируют работу: решения уже заданы [контрактом продолжения](27-CAMPAIGN-CONTINUATION-CONTRACT.md). Явные NEXT/STOP пользователя имеют приоритет; старая попытка не пересоздаётся ради нового отчёта.

[Объяснение на материале ce76](22-DPO-LEARNING-TASK-AND-CE76.md) показывает, какие выводы допустимы по маленькой партии, её отчёту и указателю Git LFS.

Текущий режим — **CREATE_ONLY**: китайская модель в уже выбранной Kiro-сессии создаёт кандидатные пары. После записи `draft.jsonl` выполняется один структурный `finish`, затем следующий поток. Независимое ревью, oracle, приёмка, экспорт и обучение относятся к отдельному будущему поручению.

Старт: [MASTER](prompts/MASTER-PROMPT-RU.md). Порядок: [EXECUTION-QUEUE](EXECUTION-QUEUE.md), машинные команды: [execution-queue.json](execution-queue.json). Точный договор: [20](20-CREATE-ONLY-AND-PATHS.md). Все карточки и назначенный RAG находятся в `llm_plan3`; отдельный checkout `main` не требуется.

## Одна готовая команда, правильный каталог

Подготовка первой партии из любого текущего каталога PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Stream "TR07-OMISSION/ru-en" -Run "M001" -Count 10
```

Результат подготовки: `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/prompt.md`. Этот prompt уже включает семейства, предметные примеры, источники, схему и абсолютные пути. Прочитай его и создай реальные строки в `draft.jsonl` той же папки. Статус PREPARED означает только подготовленное задание, не созданный набор.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Action finish -Request "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/request.json" -Model "unknown"
```

`unknown` заменить только действительно наблюдаемой моделью/selector. После DRAFT_CREATED следующий поток — `DOC-CS-NULL/base`. Не ждать reviewer. Если M001 уже существует, не удалять его и не вызывать генерацию повторно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Action resume -Request "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/request.json"
```

## Очередь и объём

Единая очередь содержит **192 потока: 165 узких целей и 27 непокрытых родительских профилей**. В текущей библиотеке 148 карточек и 934 публичных reference-строки. Потоки переводов разделены по направлению; предметная тема — перевод. Профили `tr.en`, `tr.ru`, `tr.he` задают язык назначения; другие темы в ту же партию не добавляются.

Новая цель **создания кандидатов** — минимум 1000 уникальных пар на каждый из 192 потоков. Для router полная группа 21 округляет его цель до 1008; минимальная сумма с целыми группами — **192 008**, что покрывает порог 192 000. Первые партии включаются в этот счёт; копии и переименованные версии не считаются заново. DEV/EXAM не создаются попутно.

[scale-plan](curriculum/scale-plan.json) пока описывает другой показатель — старое распределение будущих **accepted TRAIN** по родительским пулам: 132 000, из них распределено 131 987 и резерв 13. Его target_accepted_train_pairs и соответствующие квоты в старых карточках не являются новым пределом создания кандидатов. Они не позволяют остановиться раньше 192 000 и не доказывают приёмку созданного корпуса. JSON не пересчитан этой Markdown-правкой; явный приоритет и различие показателей зафиксированы в [27](27-CAMPAIGN-CONTINUATION-CONTRACT.md).

Первая партия обычно 10–42 строки по точной команде очереди; максимум одной операции — 50. Для routing должны присутствовать все заданные классы, для paired objectives — полный набор классов каждой семьи. Не уменьшать число до неполной группы, чтобы ускорить видимость результата.

После одной готовой партии переходить по точному next_stream_id; завершив обход, возвращаться к первому потоку ниже цели. **Расширение всех 192 потоков уже назначено текущим поручением** и не требует вопроса после каждой волны. Новая партия того же потока в пределах прежнего плана использует новый run и прежний request как источник next_start. Новый реально подготовленный scenario chunk использует `-FamilyPlan` и `-Start 0` без `-Previous`; исчерпание первого chunk не разрешает повторить его под новыми ID. [Правило и фактическая ёмкость 18 потоков](27-CAMPAIGN-CONTINUATION-CONTRACT.md). Не выводить следующий cursor из количества строк:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Stream "TR07-OMISSION/ru-en" -Run "M001B002" -Count 10 -Previous "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001/request.json"
```

Цель кампании не подтверждает покупку модельных токенов или запуск обучения. Точное время, модельные токены и стоимость записываются только если они наблюдаются. При фактическом лимите сервиса сохранить текущую попытку, её строки и handle; не начинать заново и не переключать модель самостоятельно. Само предположение «это займёт много сессий» не является причиной добровольно остановить доступную работу.

## Состояние определяет действие

| Фактически есть | Следующее действие |
|---|---|
| Только request/prompt | Создать назначенные строки, затем finish. |
| Живой process/task handle | Продолжать штатный wait/resume до terminal; не запускать дубль и не заменять ожидание частым polling. |
| Частичный draft | Сохранить строки, дополнить только отсутствующие назначенные family IDs; не переименовывать публичные примеры в новые семьи. |
| Полный draft, finish ещё не выполнен | Один структурный finish, без review. |
| DRAFT_CREATED | Следующий недовыполненный stream ID; на END — новый обход до цели кампании, без вопроса о продолжении. |
| Существуют старые review/oracle файлы | Сохранить их; они не назначают продолжение прежнего ревью. |
| NEXT/новый ID от Любы | Перейти немедленно; не дописывать предыдущий отчёт или прежний эксперимент. |
| STOP | Немедленно прекратить действия. |

## Содержание пары и разнообразие

Каждая партия учит одной узкой границе. В prompt полностью заданы исходные данные и решающее условие; chosen/rejected решают одинаковую задачу и различаются одной правдоподобной существенной ошибкой. Синоним или альтернативная допустимая стратегия не являются rejected без видимого критерия предпочтения. Не увеличивать корпус простой заменой имён и чисел.

Варианты исходного сценария, его переводы, обратные переводы, опечатки, раскладки и DOC/CODE-представления остаются в одной группе происхождения и одном split. Лексическая семья, смысл, род/число и синтаксическая роль хранятся раздельно; они не доказывают, что текущий learner их потребляет. Общие исходники разных потоков получают один заранее заданный [family-plan](schemas/family-plan.example.json). Публичные reference и их производные не становятся закрытым EXAM.

Для DEV/EXAM требуется отдельно назначенная сессия без TRAIN-ответов. Автоматически выделенный ID не доказывает смысловую независимость: будущая содержательная оценка остаётся NOT_ESTABLISHED. Это ограничение вывода, а не поручение запускать review сейчас.

## Последующее измерение обучения — только отдельным поручением

Сохранённые требования [05](05-LEARNING-AND-CHECKPOINTS.md) и [нативная граница](10-NATIVE-CONTRACT-BOUNDARY.md) остаются для будущего этапа. Сначала восстановить совместимый обученный B1, если он существует; при его отсутствии отдельно создать минимально достаточный обученный старт и сохранять его для повторного использования. Не называть запланированный каталог существующими весами.

Сравнение проверяет предметную Unit при правильном маршруте, затем отдельно путь prompt → обучаемый router → домен → Unit → ответ. Изменение только JSON, oracle или времени Teacher не является измерением обучения Student. 0→0 правильных ответов не доказывает обучение. Любое измеренное улучшение полезного показателя в валидном опыте признаётся успехом по этому показателю и домену с публикацией остальных изменений. Успех документируется кандидатом; перенос в production решает Люба.

## Файлы текущей партии

Сохраняются request.json, prompt.md, исходный вывод при наличии, draft.jsonl и его версии, state.json, RESUME.md, commands.md и краткий report.creation.md. finish не меняет тексты пар, не добавляет результатов oracle и не запускает модели. Предыдущие state/report сохраняются при новом завершении. Старые эксперименты и данные не удаляются.
