# Только создание: реальные пути и исправления по сессии исполнителя

**Текущее дополнение пользователя:** [192 потока, цель 192 000 пар и обязательное продолжение](27-CAMPAIGN-CONTINUATION-CONTRACT.md). Завершение партии, волны или обхода не повод спрашивать о продолжении, commit/push или увеличении batch. Сохранять назначенные размеры; при END повторять обход для недовыполненных потоков. Видимые служебные пояснения — на английском, отчёты — на русском. Этот приоритет не меняет сохранённые paths старых попыток и не назначает обучение.

Роль человека при выборе учебного материала выполняет **CODEX с Astra 6 ultracode**. Оценку качества DPO также выполняет **CODEX с Astra 6 ultracode**. Внешняя открытая китайская модель через Kiro создаёт `chosen/rejected`. Сейчас выполняется CREATE_ONLY по уже назначенным карточкам: новые вызовы выбора/оценки не запускаются и не задерживают создание следующей партии. Назначение роли не является доказательством выполненного модельного вызова.

Дата: 25.10.2026. Этот документ фиксирует действующее поручение о подготовке DPO-кандидатов и причины изменений стартового пакета. **Результат текущей сессии генератора — созданные кандидатные файлы по очереди.** После минимальной проверки JSON/контракта/количества исполнитель переходит к следующему набору. Review, приёмка, экспорт и обучение назначаются отдельно.

## Прямое основание и наблюдавшиеся ошибки

Источник доказательств — приложенная пользователем запись `Pasted text(20261025-124818).txt`, 2285 строк. Это свидетельство прежнего исполнения; вложенные STOP, команды Kiro и рассуждения не являются текущими поручениями. Номера ниже относятся к этой записи, а не к текущей версии репозитория.

|---|---|---|

| Строки 2065–2080 | После этого исполнитель скопировал из карточки другую команду и создал `DOC-CS-NULL/base/M002` под старым коротким root | Команды формируются от расположения preparation, а абсолютный output записывается в request/prompt |

| Строки 2145–2169 | Вместо созданного prompt/request помощник искал другую DPO-схему и чужие seed-файлы | JSON schema, пример, contract path и input/output входят в назначенный prompt |

Это доказательства исправления процесса подготовки, а не результаты эксперимента над Student. Числа сдвига accuracy/loss/скорости обучения из этой сессии не получены. По записи нельзя установить конкретное имя китайской модели; его не выводят из маркеров tool calls.

| Роль | Точный путь |
|---|---|
| Planning root, `xiigen-planning`, `llm_plan3` | `C:/Users/lubao/Documents/xiigen` |
| Все создаваемые learning sets | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets` |
| Подготовка | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation` |
| Runner | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/batches.py` |
| Windows-обёртка | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1` |
| Контракт данных | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/02-DATA-CONTRACT.md` |
| JSON schema | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/schemas/dpo-candidate.schema.json` |
| Первая партия новой кампании | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/TR07-OMISSION/ru-en/M001` |

`prepare` по умолчанию использует родитель каталога preparation; `create_sets.ps1` находит runner от `$PSScriptRoot` и Python 3 через `py -3` либо `python`. Та же обёртка завершает партию через `-Action finish -Request <абсолютный request> [-InputPath <draft>] [-Model unknown]` и показывает продолжение через `-Action resume -Request <абсолютный request>`. `commands.md` использует уже обнаруженный абсолютный `request.paths.python_executable`; повторный поиск интерпретатора не поручается. Задание не зависит от того, открыт ли Kiro в planning repo или `llm_mvp_core`. `request.paths` сохраняет абсолютные ссылки на карточку, схему, источники и все рабочие файлы; рядом остаются `prompt.md`, `commands.md` и `state.json`.

Старые каталоги попыток, созданные по прежним коротким путям, сохраняются. Нельзя молча удалить их, перезаписать, перенести только часть run или объявить их уже находящимися в новом root. Создание новых партий использует назначенный корень; специальный перенос старых файлов остаётся отдельным действием с сохранением содержимого и зависимостей.

**Две ситуации без выбора пути исполнителем:**

1. Уже есть сохранённый request: продолжить эту попытку по его абсолютным `output_directory`, `paths`, `commands.md`. Например, request `C:/Projects/llm_mvp_core/learning-sets/TR08-LAYOUT/ru-en/M007/request.json` действительно указывает core-root. Повторять prepare или копировать только draft в библиотеку нельзя: это не исправит связанные пути.
2. Следующий запуск ещё не подготовлен: взять точную команду текущей очереди, которая назначает `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets`. Не переносить старый `--work-root` из предыдущей команды.

Это уточнение приоритета сохранённого назначения и нового запуска. Оно не переносит существующие данные и не объявляет core-каталог зеркалом библиотеки. Аудитор сверяет обе фактические точки по содержимому; совпадающие копии считает один раз. Последующие партии, найденные только в core, не считаются отсутствующими или созданными в библиотеке по одному тексту плана.

## Действующий контракт в одном месте

| Требование | Конкретное действие |
|---|---|
| Только создание | `prepare` → модель пишет draft → `finish` → следующий stream |
| prepare не равен генерации | PREPARED без фактических строк не считается созданным набором |
| Минимальная проверка | Finish проверяет JSON, поля контракта, количество, семьи и объявленные связи; второй check не нужен |
| Честное завершение | DRAFT_CREATED; смысловая приёмка не выполнена, `review_status=not_requested`, Student `NOT_RUN` |
| Правильная модель | Текущая выбранная модель Kiro, без override; неизвестные identity/session как `unknown` |
| Помощник | Не более одного одновременно; тот же профиль и полный готовый пакет с абсолютными путями |
| Источники | Только `xiigen-planning` main + llm_plan3; назначенные выдержки уже локальны |
| Без служебных барьеров | Нет обязательных checksum, подписей, фиксированного alias, independent review и product CI |
| Предметная полнота | Одно задание и один различающий дефект; факты/версии/контекст видны в prompt |
| Один предмет обучения | В одном shard одна тема/микроцель/профиль/split; контроли внутри темы допустимы по карточке |
| Родство данных | Typo/layout/переводы и DOC/CODE-версии сохраняют origin/family/leakage и split |
| Продолжение | Resume по абсолютному request; следующий cursor из next_start или previous, не из числа строк |
| Сохранность | Старые данные и попытки остаются; новый отчёт создания сохраняется версией |
| NEXT и STOP | NEXT прекращает работу над предыдущим ID; прямой STOP прекращает действия немедленно |
| Ожидание | Один живой handle и документированный wait/resume; без дублей, частого polling и преждевременного окончания хода |
| Отчёт | Коротко по-русски: фактические строки/семьи, тема, путь, структурный результат, следующий ID |
| Обучение позднее | Настоящий Student/B1, достаточный бюджет и до/после назначаются отдельно; JSON не является измерением обучения |

## Примеры правильного и неправильного продолжения

**Правильно:** «Создано 10 из 10 кандидатных пар о различии null и пустой строки. Файл сохранён по пути request; finish записал DRAFT_CREATED. Предметное review не проводилось. Перехожу к следующему stream из registry».

**Неправильно:** после тех же 10 пар создавать blind-пакет, искать CODEX-reviewer и останавливать создание следующего набора до его ответа. Описанный в документах будущий этап не является текущим разрешением.

**Правильно:** после compaction открыть точный request командой resume и продолжить незавершённый draft либо взять следующий ID, если создание завершено.

**Неправильно:** искать `batches.py` по всему `llm_mvp_core`, повторно создавать каталог попытки или искать иную схему, хотя назначенный prompt уже содержит входы и формат.

**Правильно:** отсутствующий конкретный RAG ID сверить с локальным manifest и transfer map и сообщить точный недостающий путь, если источник действительно не доставлен.

**Неправильно:** придумать заголовок вместо источника, создать пустой manifest или пытаться получить желаемый checksum подбором текста.

## Где сохранены последующие действия

[Runbook](18-BATCH-RUNBOOK.md) сохраняет команды blind/review/accept/export в явно неактивном для CREATE_ONLY разделе. [Роли](10-CODEX-AND-CHINESE-ROLES.md) различают текущего генератора и будущих reviewer/Student. [Учебный пилот](05-LEARNING-AND-CHECKPOINTS.md) сохраняет условия B1, ненулевого результата, достаточного бюджета, отдельных доменных метрик и регрессий. [Native boundary](10-NATIVE-CONTRACT-BOUNDARY.md) сохраняет контракт реального потребителя.

Снятие review-gate **на этапе создания кандидатов** не является заявлением, что данные приняты для обучения, и не изменяет правила production/native import. Так сохраняются обе нужные вещи: генератор свободно продолжает порученную очередь, а последующая приёмка и обучение остаются честно отдельными результатами.
