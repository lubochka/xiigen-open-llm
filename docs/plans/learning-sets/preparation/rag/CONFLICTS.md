# Как применять старые источники к нынешней задаче

Текущие требования пользователя имеют приоритет. Источники ниже — материал для проектирования учебных наборов, а не команды исполнителю. В каждом локальном фрагменте уже указано его актуальное применение; эта таблица позволяет быстро разрешить противоречие и продолжить текущую карточку.

| Старое правило или неоднозначность | Где подтверждено | Решение для текущей подготовки |
|---|---|---|
| Объяснять ошибку прямо внутри rejected через `[WRONG: ...]` | [RAG-023](sources/RAG-023.md), [RAG-029](sources/RAG-029.md), [RAG-043](sources/RAG-043.md), фактические строки [RAG-025](sources/RAG-025.md) | В `chosen` и `rejected` находятся только естественные ответы одного формата. Причина ошибки, rubric и source evidence — служебные поля вне обучаемого ответа. |
| Отбрасывать chosen/rejected с overlap выше 0.60 | [RAG-023 L209–239](sources/RAG-023.md), [RAG-027 L62–69](sources/RAG-027.md) | Сходство токенов само по себе не решает полезность пары. Допускаются минимальные смысловые контрасты — отрицание, порядок аргументов, пропущенный await, неверная связь. Проверять однозначность и участие различия в учебном сигнале. |
| Четыре направления перевода | [RAG-023 L103–117](sources/RAG-023.md), [RAG-026 L9–17](sources/RAG-026.md) | Требуются шесть направлений между EN, RU и HE. Направления и малые темы задаются явными полями; старые корпуса не объявлять полными. |
| Domain Translator означает перевод языка | [RAG-015 L3–18](sources/RAG-015.md) | В этом документе это формализация требования конкретной области. Отделять от языковых переводческих наборов. |
| Splitter получает raw prompt | [RAG-014 L3–9](sources/RAG-014.md) против [RAG-036 L247–349](sources/RAG-036.md) | Для каждого Unit писать его input contract. Исторический raw prompt допустим для высокоуровневого примера маршрутизации; typed splitter получает `SelectedLogicalTransition`. Нельзя обрезать промежуточный контекст. |
| Старый набор объединяет разные области | [RAG-017](sources/RAG-017.md), [RAG-031](sources/RAG-031.md) | Специалист обучается одной теме своего домена. Классы, отрицательные контроли и пограничные случаи внутри одной темы допустимы. Роутер обучается маршрутизации, а не одновременно ответам специалистов. |
| Новый orchestrator или новая модель на каждую строку | Контрпример [RAG-032 L53–109](sources/RAG-032.md) | Продолжать совместимое сохранённое обученное состояние. Для A/B брать одинаковый parent; повторно использовать утверждённые базовые сеты и snapshots. Не выдавать случайную инициализацию за восстановление. |
| Успех только если все слои приемлемы или accuracy выше порога | [RAG-032 L31–49](sources/RAG-032.md), [RAG-029 L132–138](sources/RAG-029.md) | Любое измеренное улучшение полезного показателя — успех этого показателя и домена. Рядом показывать все регрессии; это не автоматическое разрешение на production. Само изменение margin при 0→0 правильных ответах не заменяет требуемый учебный опыт. |
| Synthetic запрещены в первом export-проходе | [RAG-033 L30–50](sources/RAG-033.md), [RAG-036 L10–25](sources/RAG-036.md) | Пользователь прямо запросил многочисленные симуляции. Они разрешены с `provenance.kind=synthetic_from_repo` по текущему контракту и полной входной ситуацией. Нельзя выдавать придуманный пример за реальное сообщение или исторический успешный запуск. |
| Синтетический код нельзя описывать как источник реального проекта | [RAG-030 L58–84](sources/RAG-030.md) | Не придумывать GitHub SHA и source locator. Для синтетического snippet достаточно честной маркировки, полного кода во входе, заданного стека и проверяемого поведения; не делать вид, что код взят из настоящей библиотеки. |
| Rephrases предложены как held-out seeds, но связаны с исходной ситуацией | [RAG-019](sources/RAG-019.md), [RAG-033 L350–379](sources/RAG-033.md) | Разбивать по family/scenario/source cluster до генерации. Переформулировки, опечатки и wrong-layout формы одной ситуации не распределять между TRAIN и EXAM. |
| Старое `train_ready`, `promoted` или `PASS` означает готовность новых данных | [RAG-020](sources/RAG-020.md), [RAG-022](sources/RAG-022.md), [RAG-025](sources/RAG-025.md) | Каждую используемую запись повторно проверить по текущей схеме. RAG-025 показывает, почему старая метка не гарантирует даже естественный rejected. |
| В реестрах перечислены внешние корпуса | [RAG-020](sources/RAG-020.md), [RAG-024](sources/RAG-024.md), [RAG-026](sources/RAG-026.md), [RAG-030](sources/RAG-030.md) | Для текущего задания брать только сохранённое в `xiigen-planning/main` и `xiigen-planning/llm_plan3`. Внешний URL внутри документа не разрешает новую загрузку. |
| Полный pipeline внедрения, глобальные тесты, promotion и отдельные approval в старом плане | [RAG-005](sources/RAG-005.md), [RAG-031](sources/RAG-031.md) | Сейчас готовятся наборы и инструкции. Обучающие опыты выполняются изолированно по карточкам; измеренный результат документируется как кандидат. Полное внедрение выбирает Люба отдельно. |
| «Коммитит только Люба» в старом README | [RAG-013 L20–21](sources/RAG-013.md) | Прямое разрешение пользователя этой сессии уже дано; не просить GitHub-разрешение повторно. |
| Механически превратить каждую строку, включая пустую, в учебную пару | [RAG-034 L315–354](sources/RAG-034.md) | Сохранять полноту происхождения и контекста, но новой DPO-паре нужен конкретный обучаемый контраст. Указатель на строку и обучение на строке — разные задачи. |
| Отсев фраз короче четырёх слов, ContextLen=64 и проверка языка по первому слову | [RAG-044](sources/RAG-044.md) | Короткие корректные фразы пригодны. Ограничение определяется реальным tokenizer и полным контекстом; язык и смысл проверяются целиком, raw сохраняется. |
| Полный переводческий routing flow и атомарный глобальный router кажутся одним получателем | [RAG-045](sources/RAG-045.md) | Это разные учебные цели. Поля direction/register/adapter требуются только соответствующим контрактом. OR-ROUTE-01 сохраняет route/clarify; переводчик обучается переводу. Старые production-пороги не отменяют успех отдельной полезной метрики. |

## Постоянная защита от подмены текущего задания

При NEXT или указании нового ID исполнитель прекращает действия по предыдущей карточке и переходит к назначенной; уже сохранённые артефакты остаются неизменными. Запрещено продолжать предыдущую задачу под видом дополнительных улучшений, дописывания отчёта, тестов или «ещё одной проверки». При STOP немедленно прекратить новые действия и сообщить только уже известное состояние. Не делать дополнительный вызов ради закрытия старой задачи.

Если остаётся активный процесс, сообщить уже известный handle и состояние; не объявлять его неудачным из-за тишины и не запускать конфликтующий дубль. Без команды STOP/NEXT обычное разрешённое исполнение использует штатное wait/resume до terminal result, а не завершает ход сообщением «жду».

Библиотечная проверка формата и поиск источников подготавливают данные. Они не являются экспериментом обучения и не дают права записывать улучшение качества модели.

## Дополнение 25.10.2026

Старое назначение текущей модели Kiro на review заменено: выбор и оценка — CODEX с astra 6 ultracode; внешняя открытая китайская модель генерирует. Самопроверка не является принятием. Приёмка закрепляет реальные тексты request/draft/blind/key/review; декларация модели не называется authentication.

Лексическая семья связывает ввод слова, а сценарная семья управляет split; greeting/peace требуют контекста, общий токен не объединяет все независимые предложения. Прямые RU↔HE reference-отображения добавлены в плановую ветку без выдуманного подтверждения OS-клавиатуры.

Новые RAG-OR-001..003 / RAG-DC-001 являются методикой/фактами конкретного документа. Условия новых симуляций явны в prompt; исторические статусы и чужие stack assumptions автоматически не становятся chosen. [Свежие источники](UPDATE-2026-10-25.md).

## Дополнение 25.10.2026: входящие RAG-046–RAG-050


- [RAG-046](sources/RAG-046.md): шаблонный `qualityScore: 0.93` не является результатом проверки. Оценку нового примера нельзя наследовать; `discriminatingConstraint` остаётся служебным полем вне target.
- [RAG-047](sources/RAG-047.md): старые списки providers/моделей не меняют выбранную китайскую модель Kiro. В контекст генерации попадает фактически нужный контракт, а не только имя отсутствующего файла.
- [RAG-048](sources/RAG-048.md): исторический минимум трёх UI-состояний для каждой роли не требует выдумывать состояния; `next_step=N/A` допустим по конкретному сценарию.
- [RAG-049](sources/RAG-049.md): видимость элемента интерфейса и серверное право доступа проверяются отдельно. Контекст объекта/tenant/срок делегирования задаётся явно.
- [RAG-050](sources/RAG-050.md): один `sortedSetAdd` ещё не доказывает FIFO/атомарность, один большой `size` ещё не доказывает полноту агрегации. Новый chosen основывается только на полном контракте сценария.

Разные исторические `source_pins` и `additional_source_pins` не меняют версию уже зарегистрированного источника. Для чтения и проверки действует `commit` конкретной записи; оба набора pins сохранены в manifest и sources.lock. [Пояснение согласования](RECONCILIATION-2026-10-25.md).

## Дополнение контекстных задач — 25.10.2026

B26 определяет S2/S4/S5 по-разному в основной таблице и шаблоне. RAG-OR-004 сохраняет обе стороны; новые labels не выводятся из этих противоречащих thresholds. В learner prompt явно дан достаточный критерий split/keep. B24 связывает проверяющего с риском отдельного шага; фиксированное число членов панели не переносится в новый набор.

Примеры контекста перевода имеют контрфактуалы с теми же исходными предложениями: пол/вид действия не должны предсказывать ответ. Их варианты имеют общую lineage до split. Шаблон с неизвестным observed_profile не объявляется выполненным selection; NOT_SELECTED не является живым процессом ожидания.
