# Дополнение: существующие Angular и SQL примеры

## Что найдено

В разрешённых ветках есть конкретные фрагменты, которые можно использовать при подготовке небольших тем. Добавлены шесть источников RAG-037–042. Это дополнение закрывает пробел первой выборки RAG: она содержала преимущественно методику документации legacy .NET.

| Источники | Содержательный материал | Что пока не доказано |
|---|---|---|
| [RAG-037](sources/RAG-037.md) | TypeScript interface runtime config, initializer, AuthSessionService, refresh single-flight, lazy route array | Это проектный ADR, а не скомпилированный текущий модуль. |
| [RAG-038](sources/RAG-038.md) | `provideTransloco` configuration, bundles/tenant overlay, `html.lang` и `html.dir` | Совместимость с произвольной текущей версией библиотеки. |
| [RAG-039](sources/RAG-039.md) | Standalone bootstrap, route arrays, functional guards, граница `loadChildren`/`loadComponent` | Старый условный выбор Angular21/22 не устанавливает актуальную версию проекта. |
| [RAG-040](sources/RAG-040.md) | Существующие вопросы про SQL window vs GROUP BY и Angular change detection; контраст «объяснить» vs «исправить» | Метка `sql-docs` или `angular-docs` без точного upstream locator не является первичной документацией API. |
| [RAG-041](sources/RAG-041.md) | SQL `SELECT ... INNER JOIN ... LIMIT` и `ALTER TABLE ... NULL`, условия success/failure/wait | Исторические утверждения о блокировках и времени не подтверждены новым исполнением. |
| [RAG-042](sources/RAG-042.md) | Транзакция заказа/остатка, rollback и обнаруженное различие `>0` / `>=requested_quantity` | Нет готового проверенного полного C#/SQL implementation fixture. |

## Три пригодные малые темы

**Angular — окончание загрузки конфигурации.** Взять типы и требование из RAG-037. Полностью показать в input короткий loader и начальные состояния. Chosen описывает, когда promise разрешается и когда можно читать config; rejected преждевременно объявляет `ready`. Использовать выбранную версию и реальные типы fixture. Факт существования ADR не заменяет компиляцию нового кода.

**SQL — условие доступного количества.** RAG-042 содержит полезный конфликт в двух формулировках одной задачи: в первой достаточно `StockAvailable > 0`, во второй — `StockAvailable >= requested_quantity`. Для контролируемой симуляции явно задать остаток 2 и запрос 3. Тогда различие наблюдаемо по отрицательному остатку и сохранению заказа. Указать одну таблицу, один ID товара, одну транзакцию, начальное состояние и ожидаемые итоговые строки. Проверять один и тот же набор на chosen/rejected, а не ссылаться на название источника.

**SQL — строки после JOIN и GROUP BY/window.** RAG-040 даёт готовую тему вопроса, RAG-041 — реальный помещённый в проект JOIN-пример. Для новой пары предоставить маленькие таблицы, дубликаты, NULL и точный запрос. Выбрать один диалект, сортировку и правила сравнения результата. Не соединять `LIMIT` из одного сценария с T-SQL DDL из другого в якобы одном исполнимом примере.

## Исправления при переносе источника в учебный материал

- В RAG-041 не переносить абсолютные обещания отсутствия блокировок при nullable ADD или обязательной перезаписи всех строк при DEFAULT. Состояние блокировок относится к конкретной СУБД, версии, операции и нагрузке. Новый набор может учить читать конкретный план/trace, когда он предоставлен, либо описывать только логическое изменение таблицы.
- В RAG-042 не превращать описание границы данного сценария в универсальный запрет любой межбазовой локальной транзакции. Новая ситуация уже задаёт одну базу; этого достаточно для проверяемого локального примера.
- В RAG-037 перечисление guards в массиве само по себе не служит доказательством последовательного ожидания всех асинхронных действий. Если обучение проверяет зависимость config→auth, дать реализацию с явным ожиданием и проверить её.
- Повторные вопросы RAG-040 относятся к одним semantic families. Их нельзя использовать как независимые train и exam строки.
- Времена и статусы из старых текстов остаются текстом источника. Доказательство улучшения обучения появляется только после отдельного валидного учебного запуска.

Внешние сайты не использовались. Полные source locators закреплены в manifest; сохранены только отмеченные прочитанные фрагменты разрешённого репозитория.
