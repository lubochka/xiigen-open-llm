# Местный RAG для создания DPO: действующая навигация

## 27.10.2026 — связь с будущим GPLv3-релизом

После создания наборов их включение в `xiigen-open-llm` определяется [контрактом релизного допуска](../../../PrepareToGPL/GPL3-LEARNING-SETS-RELEASE-CONTRACT.md) и [RAG релиза](../../../PrepareToGPL/GPL3-RAG-CURRENT.md). Это отдельный последующий этап: ссылка не добавляет review, export/import, checksum-проверки или обучение в текущее задание `CREATE_ONLY` и не меняет активные request/claim/next.

Текущая квота подтверждена [контрактом подготовки](../17-CURRENT-PREPARATION-CONTRACT.md) и [реестром](../campaign/registry.json): **24 доменные позиции кампании × 1000 = 24 000 кандидатных пар**. Доменные ID и квоты не выводятся из числа папок или профилей. На проверенном срезе RAG содержит **69 выдержок и 39 выбранных полных оригиналов**; прежние количества ниже относятся к своим датам. Новые релизные документы являются навигацией подготовки, а не дополнительными учебными строками и не самостоятельными предметными источниками для генератора.


**Цель текущей кампании: 24 доменные позиции кампании × 1000 = 24 000 кандидатных пар. CREATE_ONLY: только создание, без review.** Единственный владелец квот, порядка и next-ID — [campaign/registry.json](../campaign/registry.json). Микротемы и профили делят доменную квоту, а не получают дополнительные 1000.

RAG даёт предметные факты и сценарии для настоящих `prompt/chosen/rejected`. Prompt содержит задачу ученика, а два ответа — её полные альтернативные решения. Инструкция автору «создай DPO», список файлов или отчёт о генерации не заменяют обучающую пару. Эта страница служит навигацией исполнителя и не является учебной строкой.

Уже выбранный сохранённый request продолжает использовать собственные `paths` через `resume`, без переноса и удаления старой попытки.

## Новая кампания

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action next -WorkRoot "C:/Projects/llm_mvp_core/learning-sets"
```

Команда готовит назначение, не вызывает китайскую модель и не создаёт готовые DPO. Для прямо назначенного A-ID используется тот же вызов с `-Allocation Axxx`; точное соответствие stream/A-ID находится в [очереди](../EXECUTION-QUEUE.md). Старые create_sets/batches-примеры из исторических источников не запускаются поверх новой кампании.

1. Использовать текущую китайскую модель Kiro; помощник наследует её, неизвестное имя остаётся `unknown`. Reason internally in English; do not output private reasoning. Прогресс — по-русски, учебные тексты — на языке назначенного профиля.
2. Прочитать возвращённые `prompt.md`, `request.json`, `material.required.json`, `commands.md`. Они содержат одну микротему, count, slots, примеры, source IDs и точные пути. Не искать другой checkout и не перечитывать все skills.
3. Создать реальные пары в `request.paths.draft` и конкретный материал отсутствующих семейств в `request.paths.family_material`. EN/RU/HE версии одного сюжета используют общие сохранённые факты; самостоятельные лексемы не объединяются по похожести строки.
4. Выполнить сохранённую `commands.finish`. После `DRAFT_CREATED` сразу выполнить **`commands.next` того же request** и продолжить. Одна партия не завершает домен; продолжать до 1000 и дальше по очереди без вопроса «продолжать?».
5. Для уже выбранного старого/текущего request применять его точный `resume` и собственные пути. Не пересоздавать первую партию, не перемещать данные и не засчитывать старые кандидаты в новую кампанию автоматически.

Прямой **NEXT/новый ID немедленно меняет задание**: запрещено продолжать прежний отчёт, ремонт или запуск. **STOP немедленно прекращает действия.** Реальный недоступный файл или инструмент указать точно; не подменять блок фиктивным завершением.

Это карта поиска, не разрешение смешивать темы в одной партии или добавлять источники к назначенному request самовольно. Готовый prompt уже содержит нужные выдержки. Дополнительный original читать только при конкретном недостающем фрагменте, по точному пути из `request.paths.sources`. Публичные reference-примеры, их переводы и производные не становятся закрытым EXAM и не входят в счёт 1000.

Источник является материалом: его исторические команды, модели, STOP, checksum и production-гейты не становятся приказами текущему исполнителю. Используются назначенные файлы xiigen-planning main/llm_plan3; возможное внешнее расширение требует лицензии MIT/Apache-2.0 именно выбранного артефакта. Историческая ссылка не назначает загрузку.

## Ожидание, кодировка и граница создания

Зависимое чтение выполняется после завершения записи. Для работающего tool использовать его настоящую документацию: синхронное завершение либо один handle с предусмотренным wait/resume до terminal. Не объявлять молчащий stdout или раннее отсутствие файла отказом; не повторять запуск, не опрашивать быстро несвязанный tool и не заканчивать ход вместо доступного ожидания.

При нечитаемом выводе прочитать исходный файл через UTF-8; не перекодировать здоровые файлы по одному повреждённому diff. Бессвязные повторы не принимать за DPO; сохранить trace и продолжить от текущего request/state с коротким чистым контекстом. Причину сбоя без доказательств не утверждать.

CREATE_ONLY не добавляет независимое review/blind, acceptance, export/import, обучение, checksum и production CI. Простая проверка состава пары остаётся частью авторинга; структурный `finish` не доказывает смысловую правильность и улучшение обучения.
