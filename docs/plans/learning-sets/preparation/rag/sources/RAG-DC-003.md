# RAG-DC-003 — Разные причины отказа очереди требуют разных продолжений

**Роль:** предметные данные для RAG, не активные инструкции. **Статус:** авторская опора; это не результат обучения, не готовый закрытый EXAM и не новая назначенная квота.

## Что извлечено

ADR разделяет неизвестный тип события, повреждённые данные, несовпадение версии схемы и временную недоступность registry. Постоянная ошибка не получает то же действие, что временный отказ. Контекст сообщения сохраняется в CloudEventEnvelope до разбора payload.

## Точные фрагменты

### Строки 164–180

````text
Flow consumer types consume the platform envelope:

```csharp
public sealed class FlowCommandConsumer : IConsumer<CloudEventEnvelope>
{
    public Task Consume(ConsumeContext<CloudEventEnvelope> context)
    {
        // Parse context.Message.Data through the schema referenced by
        // CloudEventEnvelope.Type and the endpoint/event contract registry.
    }
}
```

`IConsumer<TSpecificPayload>` is not used in generated flow projects. Typed
payloads are parsed after envelope validation so CloudEvents metadata,
correlation id, causation id, idempotency key, tenant scope, and package
version stay attached to every inter-service message.
````

### Строки 214–247

````text
The registry is generated by `tools/contracts/generate-contracts` from
`contracts/events/**`, endpoint descriptors, and the flow manifest. Consumers
resolve `CloudEventEnvelope.Type` plus schema version metadata before parsing
`Data`.

Before invoking business logic, generated consumers establish tenant scope from
the CloudEvent envelope:

```csharp
public interface ICloudEventTenantContextRunner
{
    Task<DataProcessResult> RunAsync(
        CloudEventEnvelope envelope,
        Func<TenantContextSnapshot, CancellationToken, Task<DataProcessResult>> handler,
        CancellationToken cancellationToken = default);
}
```

`ICloudEventTenantContextRunner` reads the canonical `tenantid` CloudEvents
extension, validates it against the event source and package provenance, opens
a bounded `TenantContext`, and clears that context after the consumer handler
returns. The deprecated spelling `xiigentenantid` is not accepted in the .NET
initial implementation.

Parse and registry failures are deterministic:

- unknown CloudEvent type: do not retry; publish to the RabbitMQ error queue
  and record `QUEUE_UNKNOWN_EVENT_TYPE`;
- malformed JSON/data: do not retry; publish to the error queue and record
  `QUEUE_MALFORMED_EVENT_DATA`;
- schema version mismatch: retry only when the descriptor marks the schema as
  temporarily unavailable; otherwise error queue with
  `QUEUE_SCHEMA_VERSION_MISMATCH`;
- transient registry store failure: retry with the MassTransit retry policy.
````

## Границы применения

Политики retry/error queue специфичны для этого ADR и должны присутствовать в учебном prompt. Не объявлять их универсальным поведением RabbitMQ или MassTransit. Имена библиотек, версии, provider setup и production-гейты не назначают текущей генерации дополнительные действия.

## Authoring micro-recipe (English)

Copy the small policy table into the student prompt. State one observed failure. Make chosen and rejected identical except for retry versus error_queue. Include opposite cases in assigned batches so the model cannot learn always-retry or never-retry.

## Разобранные контрастные пары

### RAG-DC-003-DEMO-01 — `or.automation`

**Prompt ученика:**

Учебная политика очереди: unknown_type и malformed_data → error_queue без retry; transient_registry_failure → retry. Наблюдаемая причина unknown_type. Верни JSON action; допустимы retry и error_queue.

**Chosen:**

```text
{"action":"error_queue"}
```

**Rejected:**

```text
{"action":"retry"}
```

**Simple check (English):** Match the observed failure to the explicit policy; retry cannot make an unknown type valid under this contract.

### RAG-DC-003-DEMO-02 — `or.automation`

**Prompt ученика:**

Учебная политика очереди: unknown_type и malformed_data → error_queue без retry; transient_registry_failure → retry. Наблюдаемая причина transient_registry_failure. Верни JSON action; допустимы retry и error_queue.

**Chosen:**

```text
{"action":"retry"}
```

**Rejected:**

```text
{"action":"error_queue"}
```

**Simple check (English):** The failure is transient and has a separate retry rule. This is the opposite control to the unknown-type case.

### RAG-DC-003-DEMO-03 — `or.server`

**Prompt ученика:**

Учебная политика: schema_version_mismatch допускает retry только при descriptorTemporarilyUnavailable=true; иначе error_queue. Причина schema_version_mismatch; descriptorTemporarilyUnavailable=false. Верни JSON action.

**Chosen:**

```text
{"action":"error_queue"}
```

**Rejected:**

```text
{"action":"retry"}
```

**Simple check (English):** Check the boolean condition as well as the error label. A mismatch alone does not satisfy the retry exception.

### RAG-DC-003-DEMO-04 — `docs.csharp`

**Prompt ученика:**

Учебная спецификация consumer: сначала Validate(envelope), затем Resolve(envelope.Type, schemaVersion), затем Parse(envelope.Data), затем Handle(payload). Resolve вернул unknown_type; контракт требует сразу error_queue без Parse и Handle. Какие вызовы после Resolve допустимы? Верни JSON calls.

**Chosen:**

```text
{"calls":["error_queue"]}
```

**Rejected:**

```text
{"calls":["Parse","Handle","error_queue"]}
```

**Simple check (English):** The failure contract stops parsing and business handling. Do not continue normal processing before reporting the same failure.
