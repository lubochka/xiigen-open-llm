Это закреплённая по источникам библиотека для подготовки больших учебных наборов Xiigen: полезные фрагменты старых наборов, форм симуляций, способов передачи контекста, ошибок данных и методов измерения обучения.

Здесь сохранены **57 записей и 57 различных путей исходных файлов** из веток main и llm_plan3: 27 записей из main, 30 из llm_plan3. Все прежние 55 фрагментов сохранены побайтно. Объединены RAG-046–RAG-050, RAG-OR-001–RAG-OR-003 и RAG-DC-001; ни один источник не удалён и не переназначен. Каждый источник привязан к commit/blob SHA и строкам; индекс задаёт назначение и ограничения, поиск работает локально без модели.

Планы, микротемы, потоки подготовки, авторские опорные пары и общий промпт находятся в [плановой ветке llm_plan3](https://github.com/lubochka/xiigen-planning/tree/llm_plan3/llm%20mvp/learning-sets/preparation). [Главный промпт генератора](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/learning-sets/preparation/prompts/MASTER-PROMPT-RU.md). Актуальные количества учебных тем и потоков определяет реестр этой ветки.

Кандидаты создаёт текущая выбранная китайская модель Kiro без override. Фактический selector записывается в отчёт; точное имя, версия или открытость модели не выводятся из названия интерфейса. Проверка материала получает отдельную рубрику и не считается независимой лишь из-за другого названия роли. Retrieval, reference-пример и статическая проверка не являются выполненным обучением.

## Порядок использования

1. Прочитать [разрешение расхождений со старыми документами](rag/CONFLICTS.md). Исторический источник не отменяет текущие требования Любы.
2. Выбрать текущий ID карточки в реестре плана. Открыть назначенные ею источники и связанные фрагменты.
3. При необходимости найти дополнительный контекст через [поиск](rag/RETRIEVAL.md); источник указывается как ID + commit + path + строки.
4. Генерировать один предметный набор по одной небольшой теме. Симуляции обозначать как симуляции; старые `train_ready`, `PASS` и шаблонный `qualityScore` не наследовать.
5. Добавлять новые записи и найденные источники с сохранением старых опытов, результатов и версий.

RAG-046–RAG-050 добавляют контраст одного ограничения, сохранение фактического prompt-контекста, состояния интерфейса, отношения ролей и ограничения FIFO/агрегации. RAG-OR/RAG-DC добавляют инварианты, UX, контракт клиентского экрана и историческую карту маршрутов. Жёсткие квоты старых руководств, шаблонные оценки и упрощённый псевдокод не становятся универсальными правилами новых наборов.

Исходные `source_pins` main@3d1fa938… и llm_plan3@b242c6f9… сохранены. Восемь новых main-источников закреплены на main@8d3b4c60…; RAG-DC-001 использует прежний main pin. Новые RAG-OR-004 и RAG-OR-005 закреплены на main@f16e68bc662bc629bc45bd0e6a46011c12865199. Полный commit каждого текста записан в manifest. Значение `llm_plan3_baseline` относится к исходному состоянию плана и не перепривязывает исторические source records.

Для всех входящих записей сохранены ранее зафиксированные сверки Git blob и SHA256 оригинального текста. В предыдущем согласовании проверены 55 фрагментов. Нынешняя проверка включает все 57 локальных SHA256 и соответствие source lock; прежние 55 фрагментов сохранены побайтно. Это проверка происхождения и целостности, а не истинности каждого исторического утверждения.

Внешние URL внутри исходных документов не расширяют разрешённые источники. Полнота всего репозитория не заявлена; raw EXAM будущего обучения не помещается в общий RAG для TRAIN-генератора. Результатов нового обучения в этой библиотеке нет.

Новый [RAG-TR-001](rag/sources/RAG-TR-001.md) фиксирует ложные отрицательные переводческие пары из `curated_ru.py` в llm_plan3: допустимый синоним и неоднозначное значение нельзя делать rejected без решающего видимого контекста. Это материал аудита разметки, а не автоматически принятый TRAIN. Четыре ранее существовавших ID RAG-OR/RAG-DC теперь также включены в source lock плановой ветки.
