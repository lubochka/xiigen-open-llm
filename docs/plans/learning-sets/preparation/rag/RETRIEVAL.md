# Поиск и расширение местного RAG

## Что уже доступно локально

`sources/` содержит 58 адресных выдержок: RAG-001…RAG-050, RAG-OR-001…RAG-OR-005, RAG-DC-001, RAG-TR-001 и RAG-DATA-001. В `originals/` уже сохранены 28 выбранных полных исходников из main. `manifest.json` сохраняет происхождение и исторические SHA256; пересчёт checksum не является условием генерации. Поиск работает по пути, тегам, русскому пояснению и сохранённому тексту. Это простой поиск контекста; он не является kNN-компонентом обучаемой модели и не изменяет её данные или веса.

## Команды из известного каталога подготовки в llm_plan3

Требуется Python 3 из текущей среды. Сторонние пакеты и сеть не нужны.


Для адресного поиска используйте тот же обнаруженный интерпретатор из `request.paths.python_executable` (в PowerShell: `& $pythonPath ...`). Примеры с `python` ниже применяются только если эта команда есть; для обычной генерации поиск не нужен — все назначенные источники уже встроены в prompt.

```powershell
python "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/rag/search.py" --query "automation ожидание" --limit 3
python "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/rag/search.py" --query "translation rejected" --limit 3 --show
```

Это абсолютные PowerShell-пути пользователя; в другой среде путь берётся из расположения существующего preparation. Отдельный checkout main не нужен. `--verify` сохранён только для обслуживания RAG, не для генератора.  В PowerShell можно использовать `py -3` вместо `python`, если именно эта команда настроена в окружении. Не вызывать другую AI-модель, чтобы просто найти файл.

Для структурированного результата добавить `--json`. Ограничить область — `--tag documentation` или `--tag orchestration`. Если совпадений нет, открыть [INDEX.md](INDEX.md) и [coverage.json](coverage.json): отсутствие в этой ограниченной выборке не означает отсутствие во всём репозитории.

## Пакет контекста для одной карточки

В CREATE_ONLY назначенный `batches.py prepare` уже включает источники в prompt и сообщает абсолютные `request.paths.sources`. Генератор читает этот готовый пакет, не начинает повторный поиск после compaction. [Короткая навигация](CREATE-ONLY-NAVIGATION.md).

1. Прочитать карточку по её стабильному ID и текущий реестр плана.
2. Взять назначенные `RAG-*` и прочитать их фрагменты вместе с разделом «Как использовать сейчас».
3. При необходимости открыть оригинал по закреплённой ссылке; не подменять его текущим head другой ветки.
4. Записать использованные source IDs и конкретные spans в provenance партии.
5. Отделить извлечённый факт, синтетическое условие, выбранный ответ и объяснение rejected.

В генератор не нужно передавать всю библиотеку. Начальный пакет — карточка, общий промпт, схема DPO и 2–5 назначенных фрагментов. При нехватке точного контекста добавить связанный источник, а не придумывать факт.

## Как открыть полный исходник

Если нужный закреплённый commit доступен в локальном клоне, например:

```powershell
git show "3d1fa938d4b50df5d430283983f45b2c0d2c4e5c:Flow files generator/GUIDE-B11-FLOW-UI-AUTOMATION-JSON.md"
git show "b242c6f9efc2e3a0a01301c2875751cfd57ef83b:llm mvp/documentation learning/CODE-DOC-STACK-VERSION-AND-CALL-TRANSIT-GATE-v1.md"
```

Сначала проверить `local_original_path` в manifest: 28 нужных main-файлов уже перенесены в пакет. Если нужного исходника нет, получить только конкретный файл через GitHub connector по `repository_full_name`, `path` и `ref` из manifest. Не скачивать всю ветку main. Не угадывать содержимое по названию и не переходить по внешним ссылкам за новыми источниками.

## Добавление ресурса без потери старого

1. Найти файл только в разрешённых ветках `main` или `llm_plan3` этого репозитория; зафиксировать commit, path и blob SHA.
2. Прочитать полезный фрагмент и указать реально прочитанные строки. Нельзя объявлять прочитанным весь файл по его заголовку.
3. Проверить занятость ID в manifest и выдать следующий свободный: `RAG-051` и далее использовать только после проверки реального manifest; имена `RAG-OR-001`…`RAG-OR-005`, `RAG-DC-001`, `RAG-TR-001` и `RAG-DATA-001` заняты и сохраняются. Старые IDs не переназначать и файлы не удалять.
4. Создать `sources/<ID>.md` только из прочитанного реального файла: источник, строки, содержание, применение к малой теме, ограничения и точная цитируемая выборка. Заголовок без материала, пустой manifest и попытки подобрать текст под SHA недопустимы.
5. Добавить запись в `manifest.json` и индекс; вычислить SHA256 нового локального файла. Для другой версии того же источника добавить отдельный ID и связь `supersedes`; сохранить старую запись.
6. Согласованно обновить `sources.lock.json` плановой ветки: каждый ID, commit, path, blob SHA и SHA256 фрагмента должен совпадать с manifest. При отдельном обслуживании индекса можно выполнить `--verify` и сверить количество записей; текущую генерацию эта служебная операция не блокирует. Обновить связи карточек и реестра по ID, затем зафиксировать оба согласованных изменения.

Числа исторических запусков остаются историческими утверждениями, пока не прочитаны их первичные артефакты. Нет результатов — нет нового измеренного улучшения.

Сохранённые исторические pins не обновляются до текущего HEAD автоматически. Поле `commit` записи задаёт источник текста; aliases дополнительных pins объяснены в [записке согласования](RECONCILIATION-2026-10-25.md).
