### eng 01: `BootstrapCycleRouter` — archetype override before structural boundary

**Missing:** The `route()` method hardcodes `score < 0.50 → STOP_STRUCTURAL` before
querying the graph. No archetype-specific override can intercept a score-0 result.

**Breaks:** a task type (CheckInValidator / ATTENDANCE archetype) scores 0.0 on cycle 1 from
a config.get() used where a literal constant is required. The correct routing is
`CYCLE_WITH_PATCH` (the MACHINE_CONSTANT_INVERSION override edge is seeded in Phase A
at confidence 0.80). Instead, the flow terminates at STOP_STRUCTURAL — no PromptPatch,
no the preference learning signal triple for a task type, no learning signal.

**Failure class:** D (Generation) — BREAKS

**Fix** — add before line 42 of `bootstrap-cycle-router.ts`:
```typescript
if (params.score < 0.50) {
  const inversionOverride = await this.graphRag.query({
    fromEntity:   `${params.archetype}:SCORE_BRACKET:MACHINE_CONSTANT_INVERSION`,
    relationship: 'ROUTES_TO',
    minConfidence: 0.0,
  });
  if (inversionOverride.edges.length > 0) {
    return {
      action:      inversionOverride.edges[0].toEntity as CycleAction,
      note:        `MACHINE_CONSTANT_INVERSION override: ${inversionOverride.edges[0].reasoning}`,
      decidingEdge: { ...inversionOverride.edges[0], confidence: inversionOverride.edges[0].confidence },
    };
  }
  return { action: 'STOP_STRUCTURAL', note: 'Score below STRUCTURAL threshold — no archetype override found' };
}
```

**Scope:** EXTENSION — ~15 lines in one TypeScript file. No new service needed.

### eng 02: `IScopedMemoryService` — sorted set operations for FIFO queue patterns

**Missing:** The interface has 5 methods: `increment`, `setIfAbsent`, `get`, `set`,
`delete`. No sorted set operations exist. a task type (CheckInQueueManager) requires FIFO-ordered
concurrent check-in processing via a sorted set keyed by timestamp.

**Breaks:** a task type cannot implement FIFO ordering. Without sorted sets:
- Generated code uses `setIfAbsent()` as a mutex — provides mutual exclusion but NOT FIFO order
- `fifo_sorted_set_pattern` named check fires in the quality judge station — score drops
- Alternatively: the atomic first-writer-wins lock/Redis used directly — DNA fabric-first violation
- At capacity-constrained events: attendees processed in non-deterministic order
  (Class G SILENT_FAILURE — no error, wrong admission decisions)

**Failure class:** B (Interface missing) — BREAKS for the event attendance flow; Class G SILENT_FAILURE in production

**Fix** — add to `scoped-memory.interface.ts`:
```typescript
/**
 * Add member to sorted set with given score (used for FIFO timestamp-ordered queues).
 * Members are unique — duplicate member updates score, not count.
 */
sortedSetAdd(key: string, score: number, member: string): Promise<void>;

/**
 * Return members with score between min and max, in ascending order.
 * opts.limit: maximum members to return.
 */
sortedSetRangeByScore(
  key: string,
  min: number,
  max: number,
  opts?: { limit?: number },
): Promise<string[]>;

/** Remove a specific member from sorted set. No-op if member doesn't exist. */
sortedSetRemove(key: string, member: string): Promise<void>;
```

Implement in `in-memory.provider.ts` (Map + Array.sort) and `redis.provider.stub.ts`
(ZADD / ZRANGEBYSCORE / ZREM).

**Scope:** INTERFACE — ~60 lines across 3 files (interface + 2 providers).

### eng 03: Phase F orchestrator — write `planningLayerLearning` to LEARNING_HANDOFF

**Missing:** `AiDrivenRetrospectiveService.runR1()` returns a result object containing
`calibration` (per-archetype budget accuracy), `promotionResults` (arbiter promotions),
and can be extended to include all `planningLayerLearning` metrics. No caller currently
writes this to a persistent LEARNING_HANDOFF document.

**Breaks:** Planning layer learning is invisible. After 12 flows, there is no way to
assess whether the graph is learning at the expected rate, whether promotions are
happening, or whether calibration accuracy is improving. M8 (ENGINE PROGRESS) requires
learning metrics to be visible every phase.

**Failure class:** H (Visibility) — PARTIAL. Data is computed but not stored.

**Fix** — in the Phase F flow controller (or wherever `runR1()` is called):
```typescript
const retrospective = await this.retrospective.runR1(flowId);
await this.db.storeDocument('xiigen-flow-lifecycle', {
  documentId:  `${flowId}-LEARNING-HANDOFF`,
  flowId,
  type:        'LEARNING_HANDOFF',
  planningLayerLearning: {
    graphEdgesUpdated:    retrospective.calibration,
    promotionEvents:      retrospective.promotionResults,
    calibrationAccuracy:  this.computeCalibrationAccuracy(retrospective.calibration),
    generatedAt:          new Date().toISOString(),
  },
});
```

**Scope:** EXTENSION — ~20 lines in the Phase F controller.

## LAYER 3 — NAMED CHECK CATALOG

These are named checks that validate.handler must know about for the event attendance flow archetypes
to score correctly. Without them in the catalog, the scored code can silently pass.

---

### chk 01: `dual_entry_routing_pattern` — ATTENDANCE archetype

**Missing from catalog:** A check that verifies generated a task type code handles both
`entryType === 'PHYSICAL'` (badge → IScopedMemoryService lookup) and
`entryType === 'QR'` (token → validate and extract) paths and rejects any other value.

**Breaks:** If the check isn't in the catalog, the quality judge station scores a task type with QR-only code
as passing. Physical NFC check-ins fail silently at runtime.

**Failure class:** D (Generation) — SILENT_FAILURE (if check absent from catalog)

**What it detects:**
```
WRONG:  if (input.entryType === 'QR') { ... }  // only QR handled
CORRECT: if (input.entryType === 'PHYSICAL') { ... }
         else if (input.entryType === 'QR') { ... }
         else { throw new AttendanceError('UNKNOWN_ENTRY_TYPE'); }
```

---

### chk 02: `fifo_sorted_set_pattern` — ATTENDANCE archetype

**Missing from catalog:** A check that verifies a task type uses sorted set operations
for FIFO-ordered concurrent access, not a simple mutex (`setIfAbsent`) or direct
the atomic first-writer-wins lock.

**Breaks:** Code using `setIfAbsent()` as a mutex passes the quality judge station if this check is absent.
At capacity-constrained events, non-FIFO ordering produces wrong admission outcomes.

**What it detects:**
```
WRONG:  await this.memoryService.setIfAbsent(`lock:${attendeeId}`, '1', 30);
        // provides mutual exclusion but not FIFO order

CORRECT: await this.memoryService.sortedSetAdd(QUEUE_KEY, timestamp, attendeeId);
```

Note: chk 02 can only be enforced after eng 02 (sorted set interface) is in place.

---

### chk 03: `time_window_bounded_aggregation` — AGGREGATION archetype

**Missing from catalog:** A check that verifies a task type queries include a timestamp range
filter bounded to `input.date` AND an explicit `size` parameter from FREEDOM config.

**Breaks:** Unbounded queries appear correct at day 1. At scale (day 365), the search index default
size truncates the result. The summary contains fewer records than exist. No error thrown.

**What it detects:**
```
WRONG:  query: { term: { eventId: input.eventId } }
        // no timestamp range — returns ALL records ever

CORRECT: query: { bool: { must: [
           { term: { eventId: input.eventId } },
           { range: { timestamp: { gte: startOfDay, lte: endOfDay } } }
         ]}},
         size: freedomConfig.get('attendance.maxDailyRecords') ?? 10000
```

### seeding section 05: Infrastructure gate — the search index term-query round-trip verification

**Missing from the user registration flow-INFRASTRUCTURE-GATE.md:**

A CHECK 18 that seeds a test edge, queries it back, and confirms the search index `term` query
returns the correct result. Without this, the gate verifies the index exists but not
that documents are retrievable — a mapping mismatch would go undetected until Phase B
produces zero graph matches.

**Fix** — add to the user registration flow-INFRASTRUCTURE-GATE.md after CHECK 17:
```bash
# CHECK 18: the search index term-query round-trip (verifies fromEntity field is keyword-mapped)
TEST_ID="GATE-check 18-$(date +%s)"
curl -sf -X PUT "localhost:9200/xiigen-decision-graph/_doc/${TEST_ID}" \
  -H "Content-Type: application/json" \
  -d '{"fromEntity":"GATE:CHECK:18","relationship":"TEST","toEntity":"PASS","confidence":1.0}'

FOUND=$(curl -sf "localhost:9200/xiigen-decision-graph/_search" \
  -H "Content-Type: application/json" \
  -d '{"query":{"term":{"fromEntity":"GATE:CHECK:18"}}}' | jq '.hits.total.value')

[ "$FOUND" -ge "1" ] \
  && echo "✅ CHECK 18 PASS: term queries work — fromEntity is keyword-mapped" \
  || echo "❌ CHECK 18 FAIL: term query returned 0 hits — the search index mapping may be text not keyword"

curl -sf -X DELETE "localhost:9200/xiigen-decision-graph/_doc/${TEST_ID}" > /dev/null
```
