## 1. Какой запрос решается (The Core Problem)

### Исходный запрос из `basic_prompt.txt`

Пользователь хочет **AI-платформу оркестрации потоков** (аналог n8n, но для сложных AI-пайплайнов), которая решает 10+ реальных бизнес-сценариев:

**Базовый сценарий (MVP):**
- Пользователь отдаёт дерево нод Figma (raw CSS/HTML).
- Система прогоняет его через **несколько AI-моделей** (Claude, GPT, Gemini, DeepSeek...).
- Учитывает предыдущие positive/negative feedback.
- Делает финальный review другой моделью.
- Возвращает результат клиенту.
- На каждом шаге сохраняет **промежуточные результаты + промпты** в Elasticsearch.
- Пользователь может поставить лайк/дизлайк + текст — это сразу попадает в RAG и улучшает будущие запуски.

**10 расширенных сценариев использования (из basic_prompt):**

1. **Figma → Полноценная система**  
   Пользователь выбирает технологии (клиент/сервер/БД). Система:
   - Анализирует все экраны и компоненты
   - Понимает архитектуру продукта
   - Генерирует архитектуру как набор flows внутри XIIGen
   - Для каждого экрана создаёт техдизайн взаимодействия с flows + собирает feedback

2. **Интеграция Figma в существующую систему**  
   Автоматическая генерация документации, skillset'ов, применение дизайн-системы, стилизация.

3. **Генерация системы с нуля по тексту**  
   Пользователь описывает идею → дизайн-тема → архитектура → skills → план реализации → генерация кода + возможность деплоя и отладки на платформе.

4. **Персональный AI-агент (WhatsApp Diet / Health)**  
   Регистрация → генерация плана питания несколькими AI-раундами → ежедневный сбор данных через WhatsApp → пересчёт калорий/нутриентов → корректировки + уведомления (push + WhatsApp).

5. **Полноценный Content Pipeline**  
   Голос/текст → STT → улучшение текста → план изображений/видео (3 сек) → генерация изображений + промптов → видео + музыка + аватар → субтитры → описание под платформы → автопостинг по расписанию.

6. **Библиотека Design Patterns**  
   Для каждого паттерна: когда использовать, как, примеры на 5 языках, распространённые комбинации.

7-10. Поддержка сложных UML (possible umls.drawio.xml), генерация систем по примерам типа "Small Business Networking App", динамический код из Genie skill library, поддержка любых GraphRAG-стратегий.

**Ключевые технические требования из запроса:**
- Generic интерфейсы (DB, Queue, AI, RAG, Secrets) — легко менять реализации.
- Динамические документы (никаких жёстких схем).
- Полноценный RAG + Graph на каждом шаге AI (AI сам планирует, что искать, и куда сохранять после feedback).
- Multi-language skills (основной .NET 9 + альтернативы: Node, Python, Rust, Java, PHP + клиенты React Native / Vue / Angular).
- Продвинутые "skills": MCP, тестирование всех уровней, DevOps (K8s), документация, безопасность, оптимизация.
- Полная наблюдаемость: визуализация flow, отладка каждой ноды (вход/промпт/выход), история.

## 2. Постепенное описание функционала (Progressive Functionality)

### Уровень 0 — Базовый AI Flow Engine (n8n для AI)
- Визуальный редактор DAG (React Flow).
- Запуск по traceId + input.
- Топологическая сортировка + последовательное/параллельное выполнение.
- Хранение состояния и результатов в Elasticsearch.
- Feedback loop (положительный/нейтральный/негативный + текст) → сразу влияет на следующие запуски через RAG.

### Уровень 1 — Специализированные Worker'ы (Step Executors)
- Figma Parser (разбор нод + сырой код).
- AI Transform (несколько моделей + арбитраж).
- AI Review (отдельная модель).
- Code Generator, Documentation Generator, Design System Applier.
- Content Pipeline (аудио→видео→соцсети).
- WhatsApp Diet Orchestrator.
- Notification Service (push + WhatsApp + email).

### Уровень 2 — Память и Интеллект (RAG + Graph)
- IRagContextPlanner — перед каждым вызовом AI делает **план ретривала** (какие запросы, какие источники).
- После выполнения и feedback — **план сохранения** (куда и как положить результат + контекст).
- Поддержка 7+ стратегий (Neo4j, LightRAG, nano-graphrag, LlamaIndex, Hybrid и т.д.).
- Индексы: `flows-definitions`, `flows-state`, `flows-results`, `feedback`, `rag-{collection}`, `chat-sessions` и др.

### Уровень 3 — Полноценная Платформа (Back Office + Self-Hosting)
- Auth + Permissions + Multi-tenant.
- Chat (внутренний + с пользователями).
- Code Generator + возможность поднять сгенерированный микросервис.
- MCP Server (16+ инструментов) — AI-агенты (Claude Code, Cursor, Copilot) могут напрямую работать с платформой: запускать flows, читать логи, править код, дебажить.
- Мониторинг, логирование, метрики.
- Генерация и применение дизайн-систем.
- Calculator / Moderation / Content skills.

### Уровень 4 (будущее) — Meta-Orchestration
- XIIGen может сам себя улучшать (self-awareness flows).
- Генерация новых skills по draw.io / тексту.
- Полноценный "Freedom Machine" — бизнес-пользователь меняет поведение системы через конфиги в Elasticsearch, без кода.

## 3. Ключевые решения технического дизайна (Technical Design Solutions)

### 3.1. Genie DNA + Freedom Machine (главная философия)

**Правило №1:**
> Если бизнес-пользователь может захотеть это поменять — это FREEDOM (динамический JSON-документ).  
> Только то, что даёт эту свободу — MACHINE (статичный generic код).

**5 основных DNA-паттернов:**
1. **Dynamic Documents** — ObjectProcessor + `BuildSearchFilter` (пропускает пустые поля). Никогда не используем фиксированные классы моделей для бизнес-данных.
2. **Strategy + Factory по строке из конфига** (никаких switch по типу сущности).
3. **Generic Fabrics** — 6+ интерфейсов (Database, Queue, AI, RAG, Flow, Secrets). Код никогда не знает, какая реализация стоит за интерфейсом.
4. **CloudEvents + полная трассировка** на каждом шаге.
5. **Zero Schema** — Elasticsearch хранит что угодно. Новые поля появляются автоматически.

### 3.2. Универсальный контракт — `DataProcessResult<T>`

**Никогда не бросаем исключения.** Все сервисы возвращают:
```csharp
public class DataProcessResult<T>
{
    public DataProcessStatus Status { get; init; } // Success, NotFound, Error, RateLimited...
    public T? Data { get; init; }
    public string Message { get; init; }
    public string? ErrorCode { get; init; }
    // + Metadata, Timestamp
}
```

Это позволяет:
- Единообразно обрабатывать ошибки на всех уровнях (включая фронт).
- Легко логировать и мониторить.
- Делать ретраи и DLQ на уровне очередей.

### 3.3. Flow Orchestration (Skill 09)

```csharp
IFlowOrchestrator.TriggerFlowAsync(flowId, input) → traceId
// Внутри:
1. Загрузить FlowDefinition (шаги + edges)
2. Топологическая сортировка (DAG)
3. Для каждого шага:
   a. IRagContextPlanner.PlanRetrievalAsync(...) → реальные поиски
   b. IStepExecutor.ExecuteAsync(step, inputsWithRag)
   c. IRagContextPlanner.PlanStorageAsync(result, feedback)
4. Сохранение StepState (вход, промпт, выход, retry, время) в Elasticsearch
5. Финальный результат
```

Поддержка resume/cancel/pause по traceId.

### 3.4. Per-Step RAG Planner (Skill 00b)

Перед каждым вызовом AI:
- AI (или эвристика) генерирует `RagRetrievalPlan` (список запросов + источники).
- Выполняется hybrid/vector/graph поиск.
- Контекст инжектится в промпт.

После шага + feedback:
- Генерируется `RagStoragePlan`.
- Результаты, метаданные, связи сохраняются в graph + vector хранилища.

### 3.5. Skill как единица поставки

Каждый Skill — это **самодостаточный артефакт**:
- `SKILL.md` (6KB+, YAML frontmatter, полное описание, DNA-совместимость, альтернативы)
- Реализация на .NET (10KB+)
- 5 языковых альтернатив (Python, TS/Node, Rust, Java, PHP)
- `prompts/implement.md` — промпты для других AI, чтобы они могли воспроизвести skill
- Тесты (unit + integration)
- Примеры использования

Это позволяет:
- Claude/Cursor/Copilot instantly понимать и использовать skill.
- Поставлять incrementally (один skill = одна полезная возможность).
- Легко мультиплицировать на другие стеки.

### 3.6. Другие важные решения

- **Очереди** — Redis Streams (основной) + SQS/Rabbit/Kafka как альтернативы. Consumer groups + DLQ.
- **Кэш** — Redis + in-memory.
- **Мультиязычность** — основной стек .NET 9 + React Native, но каждый skill имеет папки с альтернативами.
- **MCP Server** — даёт AI-агентам прямой доступ к 16+ инструментам платформы.
- **Тестирование** — 3 уровня (unit, e2e flows, UI) + InMemory-реализации всех fabrics для тестов.
- **Observability** — структурированные логи + traceId через все слои.

1. Расширенный `SKILL.md` с YAML, DNA-оценкой, примерами.

3. 5 языковых портов (хотя бы скелеты + ключевые классы).
4. Промпты для воспроизведения другими AI.
5. Тесты (минимум 80%+ coverage для критичных частей).
6. Документация по использованию в flows.

### Дальнейшие фазы (ориентировочно)

- **P6**: Полноценный MCP + Self-Modification flows (платформа улучшает себя).
- **P7**: Visual Designer + Deployment Orchestrator (one-click деплой сгенерированных систем).
- **P8**: Enterprise (SSO, audit, compliance, multi-region).

## 5. Как устроена сама оркестрация процесса разработки

Это не обычный agile. Это **AI-оркестрируемая поставка**:

1. **Многосессионный Planning** — сотни claude-sessions, grok-сессий, извлечение знаний.
2. **Extraction & Merging** — специальные flows (FLOW-33, FLOW-34, FLOW-37...) собирают разрозненные знания в canonical merged документы (business flows/, Architecture plan/).
3. **DNA Audit** — регулярные аудиты (DNA_AUDIT_REPORT.md) показывают, где "разбавляется" философия Freedom Machine.
4. **Phased Skill Delivery** — один skill или небольшая группа за итерацию. Каждый skill самодокументирован так, чтобы другой AI мог его понять и использовать.
5. **Verification** — тесты + InMemory fabrics + реальные запуски flows.
6. **ZIP Checkpoint** — после каждой большой фазы — полный архив + чёткая инструкция для следующей сессии.
7. **Continuous Self-Improvement** — чем больше flows и feedback накапливается в RAG, тем умнее становится генерация следующих skills и flows.

**Ключевой инструмент оркестрации** — сами flows XIIGen (когда платформа будет готова, она будет использоваться для собственной разработки).
