Planning и output — два разных корня, заданных пользователем. Нельзя вычислять output как родителя `preparation`. `paths.json` и [реестр](campaign/registry.json) задают одинаковые корни. На другой платформе нужен явный временный `--work-root`; строка `C:/...` не должна становиться относительным Linux-каталогом.

## Новая сессия

Три самостоятельные команды находятся в [стартовых промптах](00-START-HERE.md). Пример:

```powershell
$DpoAgentId = 'software-' + [Guid]::NewGuid().ToString('N')
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action next -WorkRoot "C:/Projects/llm_mvp_core/learning-sets" -AgentId $DpoAgentId -Pool software
```

Сохрани `$DpoAgentId` как ID этой сессии. Для продолжения копируй готовые команды из `paths.commands`, включая owner/token. При новом окне создавай другой ID; нельзя запускать два процесса с одной сохранённой ролью владельца. Все окна указывают **один и тот же реальный data root**. Локальные копии на разных компьютерах требуют отдельного координационного решения и этим пакетом не синхронизируются.

## Что возвращает координатор

`paths.prompt` → актуальный `coordination-prompt.md`; `paths.material_required` → `coordination-material.required.json`; `paths.commands` → `coordination-commands.md`. Эти производные файлы обновляются при разрешённом resume. Исходные `request.json`, `prompt.md`, `commands.md`, ID и уже сохранённые пары остаются историей первоначального назначения. Не выполняй неполную команду из старого request вместо текущей команды владельца.

Скрипт разрешает preparation относительно собственного пути, использует UTF-8 и фиксированный launcher `py -3`, если не передан известный `-PythonExecutable`. Последующие команды содержат фактический исполняемый Python. При отсутствии назначенного файла или runtime сообщается его точный путь; поиском по случайным каталогам и выдуманными путями это не заменяется.

## Уже сохранённая попытка

Используй точный абсолютный request и его сохранённый resume. Не переноси output задним числом. Четыре читаемых исторических request указывают прежний Documents-root; это [наблюдаемое расхождение](verification/COMMITTED-CORPUS-ASSESSMENT-2026-10-26.md), а не доказательство отсутствия файлов на компьютере пользователя. Новые задания пишутся только в заданный Projects-root.

Legacy `xiigen.batch-request.v1` остаётся отдельной последовательной попыткой вне claims нового координатора. Новая кампания не принимает старые строки в квоту автоматически и не запускает вместо явно назначенного старого request другую работу.

`finish` сохраняет размер и `mtime_ns` завершённого draft. Повторный `finish/resume` сверяет их с фактическим файлом. Это лёгкая проверка сохранности без checksum, а не смысловой review и не криптографическая гарантия. Изменённый/исчезнувший завершённый файл не выдаётся за прежний успешный результат; state не обнуляется.

## Состояние и ожидание

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action status -WorkRoot "C:/Projects/llm_mvp_core/learning-sets"
```

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

При нечитаемом выводе прочитай исходный файл как UTF-8; не перекодируй здоровый документ по одному повреждённому UI-следу. При бессвязном повторе сохрани фактический trace и продолжи тот же request с коротким входом. По одной копии UI нельзя установить причину модель/сервер/интерфейс.

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Граница подтверждения: Windows-корни назначены пользователем; облачная сессия не открывала его диск C:. Linux-проверки используют временные явные roots. Фактическая ветка Windows `msvcrt`, PowerShell и запуск выбранной китайской модели требуют выполнения в среде пользователя; их успешный прогон здесь не заявляется.
