## Переводы: шесть направлений и один понятный дефект

Каждая новая переводная цель имеет 12 полных контрастов: два исходных сюжета и шесть направлений между английским, русским и ивритом. По действующему реестру предметный домен задаётся языком назначения: tr.en, tr.ru или tr.he; направление задаётся profile. Это пользовательское разделение учебных наборов, не доказательство необходимости отдельной физической модели на каждую комбинацию.

Пример цели «область отрицания»:

> Вход: «Она не сказала, что письмо отправлено».
>
> Предпочтительный перевод: “She did not say that the letter had been sent.”
>
> Ошибочный перевод: “She said that the letter had not been sent.”

Оба ответа грамматически правдоподобны, но отрицание относится к разным действиям. Этот контраст учит конкретной смысловой границе. Аналогично в примере «Анну похвалил Борис» порядок слов не должен превращать Анну в действующее лицо.

В карточке явного рода информация о референте местоимения находится в самом запросе. Английское слово engineer само по себе не означает мужчину или женщину. Если данных недостаточно, нельзя создавать ложный отрицательный ответ; используется существующая цель условного уточнения, где есть оба класса — необходимость вопроса и достаточный контекст без вопроса.

Опечатки и неверная раскладка продолжают использовать существующие карточки TR07/TR08 и проверенный layout fixture. Полная строка сохраняется вместе с канонической лексемой, языком и значением. Нельзя объединять разные корректные слова только из-за edit distance. Морфология, роль и порядок могут быть полезны конкретному domain-aware kNN, но их хранение в metadata ещё не доказывает, что потребитель их читает. Такая привязка отдельно проверяется на реальном учебном входе.

## Оркестрация: учить выбору по состоянию

Новые симуляции полностью задают наблюдаемое состояние и разрешённые действия. Например, для повторного запроса с тем же ключом и подтверждённым результатом правильное действие — вернуть существующий результат; создание новой операции нарушает заданную идемпотентность. Для первого запроса без владельца сценарий отдельно задаёт атомарные свойства claim. Имя операции само по себе гарантией не считается.

В outbox-сценариях различены несохранённая транзакция, подтверждённое сохранение, ожидание ACK, повторная доставка и обработанный дубликат. Историческое указание «сначала store, потом enqueue» не объявляется доказательством exactly-once. Нужные гарантии и ограничения указаны в learner prompt.

Мобильные примеры различают локальную очередь, принятие сервером и подтверждённое применение конкретной операции. ACK другой операции или другого payload не завершает текущую. Автоматизация группы ветвей учитывает ожидаемый состав и политику all/any; частичная готовность не выдаётся за полный результат. Противоположные действия в таких сценариях являются классами одной темы, а не смешением предметных уроков.

## Документация и код: общий исходник, разные задачи

Каждая пара целей документации/кода имеет явный стек: C# 10/.NET 6, T-SQL/SQL Server 2019, Angular 16/RxJS 7.8. Профили сохранены из предыдущего пакета. Нельзя проверять T-SQL в SQLite и приписывать результат SQL Server, либо подставлять latest-версию зависимости без нового профиля.

Для документации выполняется один показанный исходник, а два описания сравниваются с его результатом. Для написания кода выполняются обе реализации на одинаковых входах. Карточки задают каталоги oracle, состав fixtures, команды, ожидаемые наблюдения и места отчёта. Они прямо указывают, что будущий oracle harness должен быть создан в конкретном run и ещё не выполнен.

Пример защищённого изменения остатка: при запасе 2 и запросе 3 условие `Available > 0` пропускает недопустимое списание; `Available >= @qty` его блокирует. Отдельные случаи проверяют равенство остатка запросу, отрицательное количество без внешней валидации и отсутствующий ID. Это разные граничные классы одного predicate, без скрытого перехода к проектированию всей транзакции.

C#-примеры не приравнивают передачу CancellationToken к физической остановке внешнего хранилища. Для await явно заданы обычные исключения и отдельный статус отмены; не обещается сохранение любого fault-статуса при произвольном типе исключения. RxJS-сценарии задают виртуальное время, успешный запрос после ошибки и проверки подписок. Цель с явно названным switchMap учит составлению этого выражения; самостоятельный выбор оператора этим не доказан.

Для подмножества микроцелей первые партии назначают **1041 строку**, пилот TRAIN/DEV/EXAM — **10 326 / 2 082 / 2 082**. ## Какие выводы разрешены после следующего этапа

Улучшение времени, потребления памяти, точности или другого полезного показателя на валидном учебном опыте фиксируется по этому показателю и домену. Другие изменения, включая ухудшения, показываются рядом. Рост accuracy для успеха по времени не обязателен. Успешный опыт становится документированным кандидатом для решения Любы, без автоматического изменения production.

В этой поставке выполнены подготовка, содержательное чтение примеров, согласование источников/индексов и проверки сборки заданий. **Вызовов китайской модели, native oracle и обучения Student здесь нет.** Принимаемые датасеты и измерения появляются только после выполнения заданий в Kiro, предметного допуска и отдельного учебного запуска с реальным binding.
