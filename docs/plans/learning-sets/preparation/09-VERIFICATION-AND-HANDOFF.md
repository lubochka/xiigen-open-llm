## Что проверено фактически

1. Все 45 RAG-фрагментов сверены по SHA-256; Git blob SHA источников сверен с исходными байтами. Команда `python rag/search.py --verify` в RAG checkout возвращает PASS, 45, без ошибок.
2. Все 185 reference JSONL записей прочитаны и прошли структурную проверку с разрешённым статусом reference. Сверены domain/topic/profile, источники, уникальность и границы семей. Это не приёмка готового учебного корпуса.
3. Независимый проход по 60 документационным и кодовым парам обнаружил и помог исправить зависимость SQL-строки от предыдущей строки, путаницу NULL и числа 0, скрытое требование передачи CancellationToken и отсутствующие версии внутри prompt. Все 60 пар в JSONL совпадают с карточками. Runtime snippets в этом сеансе не исполнялись.
4. Выполнены 17 небольших проверок утилиты подготовки: сборка реального контекста, запрет перезаписи, продолжение через next_start, разделение структурной и смысловой приёмки, слепой пакет, привязка review/request к хешам, общий аудит семей, отклонение вымышленных источников, неизменяемые части и накопительная сборка без повторов. Результат — [data-utility-checks.json](verification/data-utility-checks.json).
5. Проверены существование карточек и локальных ссылок, единый порядок/next_id общего и предметных индексов, JSON и происхождение используемых RAG-ID. Сводка — [package-checks.json](verification/package-checks.json).

В проверках утилиты использованы явно обозначенные mock-review fixtures. Они проверяют механику подготовки и не подменяют языковую экспертизу, исполняемый oracle или обучение. **Вызовов китайской модели: 0; новых учебных экспериментов: 0; измеренного эффекта обучения: нет.** Эти проверки касаются загрузки, разделения и сохранения будущих учебных данных; не регистрировать их как успешные learning experiments или кандидаты production-исправлений.

## Исправленные противоречия источников и порядка

В [07](07-CONFLICTS-AND-REQUIREMENTS.md) и [RAG/CONFLICTS](https://github.com/lubochka/xiigen-planning/blob/main/llm%20mvp/learning-sets/preparation/rag/CONFLICTS.md) зафиксированы решения: старый запрет overlap>0.60 не исключает сильную минимальную пару; `[WRONG]` не попадает в ответ; критика плохого перевода не заменяет rejected-перевод; старый ContextLen=64 не становится универсальным лимитом; текущая симуляционная задача имеет приоритет над историческими запретами synthetic exports. Domain Translator старого плана не переименован в переводчик естественных языков.

Порядок одинаков в index.json, предметных topic-index.json и карточках. Первая последовательность: TR01 → DOC-CS-01 → CODE-CS-01 → OR-ROUTE-01. Прямой ID пользователя имеет приоритет; при NEXT/STOP предыдущая задача не продолжается ради дописывания результата. Накопление корпуса разделено на непересекающиеся принятые части и версии набора; новый snapshot не регистрирует прежние строки повторно.

## Следующее действие, назначенное в историческом пакете

Открыть [03](03-GENERATION-AND-KIRO.md) и выполнить первый `prepare` для TR01/ru-en/R001 в назначенных коротких папках. Использовать выбранную пользователем модель текущей Kiro-сессии, её фактическое имя записать в provenance. `prompt.md` содержит выбранные RAG-фрагменты и полный предметный контракт. Затем отдельный слепой review, исправление конкретных дефектов, глобальный audit, immutable shard, compose и export. Пример для увеличения 50→100→1000 уже дан с точными командами.

Код генератора/обучения в production не менялся. Совместимость обменного JSONL с нативным loader, реальный runner нового домена, достаточный B1 и исполняемый oracle — следующий этап по [05](05-LEARNING-AND-CHECKPOINTS.md). Новые состояния не объявлены существующими. 0→0 правильных результатов не подтверждает обучение; любой полезный выигрыш на валидном уроке фиксируется по своему домену и метрике вместе с регрессиями.
