**65 RAG-источников, 35 выборочно перенесённых originals из main.** Владелец списка — [rag/manifest.json](rag/manifest.json), карта переноса — [rag/transfer-map.json](rag/transfer-map.json). Все назначенные генератору excerpts находятся в llm_plan3. Полный main не скачивается.

## Источники

Текущий пакет использует материалы самого `lubochka/xiigen-planning` из main и llm_plan3. Разрешение пользователя также допускает внешние MIT/Apache-2.0 материалы. Для такого будущего добавления фиксируется лицензия конкретного артефакта и источник, а не лицензия похожей программы. Ссылка из исторического документа не разрешает автоматическую загрузку любого сайта.

Пять новых источников: B13 session simulation; B45 visibility; ADR tenant-context snapshot; ADR queue/cache fabrics; ADR idempotency/outbox. Их [полные пути, выдержки и20DPO-контрастов](rag/domain-source-additions-2026-10-25.json) сохранены отдельно. Спорные исторические обобщения (например, exactly-once из lease или универсальное поведение AsyncLocal) не используются как доказанный факт; в симуляции задаётся точный контракт.

Commit/blob refs служат происхождением сохранённого источника. Генератор не вычисляет checksum, не восстанавливает отсутствующий материал подбором hash и не останавливает создание ради квитанции.

## Навыки автора пакета и короткое применение у генератора

Применимые секции актуальных проектных навыков прочитаны из [core/docs/skills](https://github.com/lubochka/llm_mvp_core/tree/codex/dpo-implementation/docs/skills). Для длинных навыков использованы конкретные относящиеся к задаче разделы; полный production-аудит не заявляется.

| Навык | Что применено здесь |
|---|---|
| architect-behavior-classifier | Текущий запрос отделён от цитат старых сессий; источник и наблюдение отделены от гипотезы |
| phase-planning | Каждому требованию назначен конкретный файл/выход; текущая стадия — создание |
| plan-review | Согласованы квоты, карта доменов, карточки, next-ID и два разных root |
| generated-code-review | Проверено фактическое поведение preparation utility; JSON не объявлен обучением |
| prompt-patch-authoring | Даны буквальные WRONG/CORRECT контрасты и конструктивная простая самопроверка |
| planning-dpo-authoring | Один смысловой выбор, достоверный контекст, близкий rejected, происхождение |
| human-communication-GLOSSARY | Домен, направление, микротема, механизм и модель не смешиваются |
| session-scope-resolution | Генератор не превращается в reviewer, разработчика production или trainer |
| temporal-behavior | Явные состояния и границы переходов; документация реального wait-tool читается отдельно |

Их минимальное действующее применение включено в [английский протокол](campaign/AUTHORING-PROTOCOL-EN.md) и prompt каждой партии. **Генератор не перечитывает сотни килобайт skills перед каждыми десятью строками.** Имена и параметры Kiro wait не выдумываются: temporal-behavior не является описанием API Kiro.

Прямое поручение пользователя задаёт CREATE_ONLY. Требования production-тестов, двух разных моделей для chosen/rejected, обязательных checksums, отдельного reviewer и готового native admission к этому этапу не применяются. Содержательная корректность строк остаётся задачей автора; независимая приёмка пока не назначена.
