## Текущий путь и сохранённая последующая приёмка

`tools/batches.py`: prepare → генерация draft → finish → следующий stream. Сам prepare не является генерацией. Цепочка blind → независимое предметное review → accept → export сохранена **только для отдельно порученного последующего этапа**. [Runbook](18-BATCH-RUNBOOK.md) содержит точные команды, пути, форматы и продолжение. Prepare собирает карточку, назначенные источники и примеры выбранного профиля; не требует checksum, фиксированного профиля модели, provider receipt или full CI. Старый `sets.py` сохранён для прежних запусков.

В сохранённом последующем этапе reviewer получает A/B без ключа, rationale и меток генератора; текущая сессия его не запускает. Приёмка проверяет завершённость review и его соответствие фактическим текстам. Поля не аутентифицируют провайдера и не доказывают правдивость заявленного выполнения. Для исполнения нужны реальные сырые артефакты. В независимом просмотре найден и закрыт обход обязательного `executable_oracle` через `source_grounded`: назначение objective теперь обязательно. [Отчёт](verification/BATCHES-INDEPENDENT-REVIEW-2026-10-25.md).

Точные пути разных objectives больше не сталкиваются в общей parent-папке. `--previous` переносит семейный cursor, а не число строк. `--against` проверяет известное объявленное родство переданных корпусов; не объявляется доказательством независимости всего неизвестного материала. Целый run можно переносить вместе с его относительными связями.

## Следующее фактическое действие

Открыть [MASTER](prompts/MASTER-PROMPT-RU.md), выбрать первый незавершённый stream либо точный ID Любы и выполнить команду из очереди. Генератор сохраняет первую назначенную партию, выполняет `finish` и переходит к следующему stream. Предметное review сейчас не поручено; структурно завершённый draft не становится принятым корпусом. Для нового learning-пилота нужны явное задание, нативный потребитель и совместимый обученный B1 по [05](05-LEARNING-AND-CHECKPOINTS.md). Скорость Teacher, parse либо размер файла не заменяют измерение Student. `0→0` не является доказательством обучения; любое действительное полезное улучшение фиксируется вместе с регрессиями как кандидат, без автоматического изменения production.
