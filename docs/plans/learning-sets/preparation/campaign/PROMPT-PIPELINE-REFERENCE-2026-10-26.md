# Сквозные учебные примеры: prompt → части → задания → предметный ответ

**26.10.2026 · REFERENCE_ONLY · четыре авторские симуляции.** Ни один сценарий здесь не запускался; native-интеграция core, генерация китайской моделью и обучение не выполнены.

Полные структурированные входы, ожидаемые ответы и JSON-схемы находятся в [машиночитаемом приложении](../schemas/prompt-pipeline-reference-2026-10-26.json). Все этапы одного сценария сохраняют один `origin_family_id`, `split=reference`; они дают **0** строк в квоту и исключены из закрытого EXAM вместе со своими производными.

## Что именно передавать между задачами

`prompt.span-routing` сохраняет прежнюю схему D22: `segments[{id,text,domain_id,depends_on}]` и `clarify`. Текст каждого сегмента — непрерывная точная подстрока исходного запроса. Общие условия могут стоять в другом месте; их не нужно и нельзя выдуманно приклеивать к подстроке или превращать в новые действия.

**Каждый вход D23 содержит четыре части:** полный исходный prompt, выбранный сегмент, назначенный предметный домен и доступные результаты предшественников. Именно полный исходный prompt переносит общие запреты, язык ответа, схему данных и другие условия, отсутствующие в коротком сегменте. Ученик D23 возвращает прежние `domain_id/task/missing`, не новый формат.

Результат предшественника нельзя считать известным по плану. Пока текста нет, D23 возвращает `task=null` и называет недостающий результат. В учебном примере можно явно подать ожидаемый предыдущий ответ, но он помечается `REFERENCE_EXPECTATION_NOT_OBSERVED`; это не свидетельство завершившегося запуска.

Для зависимых стадий ниже показаны два альтернативных входных случая — без предшествующего текста и с явно данным reference-текстом. Это не два фактически проведённых запуска. Каталог доменов является видимой частью входа D22, а не скрытой metadata-подсказкой.

Старый `or.routing` остаётся отдельной атомарной задачей: он требует `clarify` для составного запроса. Новые D22/D23 описывают другие обучаемые задания и сами по себе не внедряют такой путь в приложение.

Источники методики: [разделение частей](../rag/sources/RAG-014.md), [формализация предметного задания](../rag/sources/RAG-015.md), [разделение ролей оркестратора](../rag/sources/RAG-031.md), [документация по видимому коду](../rag/sources/RAG-027.md), [исторический splitter](../rag/sources/RAG-PROMPT-003.md) и [translator](../rag/sources/RAG-PROMPT-004.md). Новые примеры — собственные симуляции; старые лицензионные и измерительные утверждения источников не повторяются как установленные факты.

## PIPE26-01. Общее «не менять код» действует на обе части

Общая семья всех этапов: `ref.pipeline26.shared-constraints`.

**Исходный запрос**

```text
Общее правило для обоих пунктов: только объясняй, не меняй код; отвечай по-русски. Среда C# 10/.NET 6: string Label(string? s)=>s??"-"; nullable enabled. Для SQL Server 2019 таблица T(v int NULL) содержит [NULL,0,0]. Объясни результаты Label(null) и Label(""). Отдельно объясни результат SELECT COUNT(v) AS n FROM T.
```

Видимый каталог D22: `docs.csharp` — объяснить C#, `docs.sql` — объяснить SQL, `code.csharp` — написать C#, `code.sql` — написать SQL.

**D22 — ожидаемое разделение**

```json
{
  "segments": [
    {
      "id": "s1",
      "text": "Объясни результаты Label(null) и Label(\"\").",
      "domain_id": "docs.csharp",
      "depends_on": []
    },
    {
      "id": "s2",
      "text": "Отдельно объясни результат SELECT COUNT(v) AS n FROM T.",
      "domain_id": "docs.sql",
      "depends_on": []
    }
  ],
  "clarify": []
}
```

**D23 и предметные результаты**

**`s1.compile` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s1` + назначенный `docs.csharp` + пустой список доступных результатов предшественников.

```json
{
  "domain_id": "docs.csharp",
  "task": "По-русски объясни результаты Label(null) и Label(\"\") для C# 10/.NET 6: string Label(string? s)=>s??\"-\";, nullable enabled. Только объяснение; код не менять.",
  "missing": []
}
```

В коротком задании сохранены исходник, оба входа, русский язык и общий запрет изменения кода.

**`s1.subject` → `docs.csharp`**

Ожидаемый предметный ответ:

```text
Label(null) возвращает "-", Label("") возвращает "". Оператор ?? заменяет только null; пустая строка сохраняется.
```

Ответ объясняет видимый метод и не предлагает новый код.

**`s2.compile` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s2` + назначенный `docs.sql` + пустой список доступных результатов предшественников.

```json
{
  "domain_id": "docs.sql",
  "task": "По-русски объясни SELECT COUNT(v) AS n FROM T для SQL Server 2019, T(v int NULL)=[NULL,0,0]. Назови число строк и n. Только объяснение; SQL не менять.",
  "missing": []
}
```

Показаны схема и строки T, хотя они находятся вне выбранного короткого фрагмента; общий запрет сохранён.

**`s2.subject` → `docs.sql`**

Ожидаемый предметный ответ:

```text
Одна строка результата: n=2. COUNT(v) пропускает NULL и учитывает оба значения 0.
```

Оба нуля учитываются, SQL не переписывается и не запускается.

**Ошибка, которую ловит сценарий:** Передать в D23 только «Отдельно объясни результат SELECT COUNT(v) AS n FROM T». Тогда теряются общие ограничения, схема и сами строки T.

**Simple check (English):** For every compiled task, compare its constraints with the FULL original prompt, not just the selected substring. Global constraints are not extra tasks.

**Старый атомарный router:** `{"action":"clarify","domain_id":null}`. Два независимых предметных действия: прежний or.routing по своему атомарному контракту просит уточнение; новый D22 сохраняет обе части.

## PIPE26-02. Написать → объяснить → перевести без выдуманных результатов

Общая семья всех этапов: `ref.pipeline26.write-explain-translate`.

**Исходный запрос**

```text
Среда: SQL Server 2019; таблица T(v int NULL) содержит [NULL,0,0]. SQL не запускай. Напиши один SELECT, считающий строки с v не NULL, с единственным полем n. Затем объясни полученный запрос одним предложением по-русски с результатом для T. Затем переведи это объяснение на английский; ответ переводчика — только перевод.
```

Видимый каталог D22: `code.sql` — написать SQL, `docs.sql` — объяснить SQL, `tr.en` — перевести на английский.

**D22 — ожидаемое разделение**

```json
{
  "segments": [
    {
      "id": "s1",
      "text": "Напиши один SELECT, считающий строки с v не NULL, с единственным полем n.",
      "domain_id": "code.sql",
      "depends_on": []
    },
    {
      "id": "s2",
      "text": "Затем объясни полученный запрос одним предложением по-русски с результатом для T.",
      "domain_id": "docs.sql",
      "depends_on": [
        "s1"
      ]
    },
    {
      "id": "s3",
      "text": "Затем переведи это объяснение на английский; ответ переводчика — только перевод.",
      "domain_id": "tr.en",
      "depends_on": [
        "s2"
      ]
    }
  ],
  "clarify": []
}
```

**D23 и предметные результаты**

**`s1.compile` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s1` + назначенный `code.sql` + пустой список доступных результатов предшественников.

```json
{
  "domain_id": "code.sql",
  "task": "SQL Server 2019: напиши только один SELECT с единственным полем n — числом строк T(v int NULL), где v не NULL; повторения учитываются. T=[NULL,0,0]. SQL не запускать.",
  "missing": []
}
```

Задание требует написать SELECT, а не исполнить его; NULL и повторения определены видимыми данными.

**`s1.subject` → `code.sql`**

Ожидаемый предметный ответ:

```text
SELECT COUNT(v) AS n FROM T;
```

Ожидаемый SQL сохраняет COUNT(v), одно поле n и отсутствие UPDATE/DELETE/DDL; это эталон, не результат реального выполнения.

**`s2.compile.before-prior` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s2` + назначенный `docs.sql` + пустой список доступных результатов предшественников.

```json
{
  "domain_id": "docs.sql",
  "task": null,
  "missing": [
    "результат s1: фактически созданный SELECT"
  ]
}
```

Пока s1 не дал текст SQL, D23 явно показывает зависимость. Он не подставляет удобный предположительный запрос.

**`s2.compile.with-reference-prior` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s2` + назначенный `docs.sql` + результаты `s1` с явной отметкой reference.

```json
{
  "domain_id": "docs.sql",
  "task": "Одним предложением по-русски объясни SELECT COUNT(v) AS n FROM T; для SQL Server 2019, T(v int NULL)=[NULL,0,0], с точным результатом. SQL не запускать и не заменять.",
  "missing": []
}
```

Вход содержит точный текст предшественника. В этом reference он явно помечен ожидаемым, а не наблюдённым.

**`s2.subject` → `docs.sql`**

Ожидаемый предметный ответ:

```text
Запрос возвращает одну строку n=2, учитывая оба значения 0 и исключая NULL.
```

Точное объяснение: одна строка n=2; две нулевые величины считаются, NULL исключён.

**`s3.compile.before-prior` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s3` + назначенный `tr.en` + результаты `s1` с явной отметкой reference.

```json
{
  "domain_id": "tr.en",
  "task": null,
  "missing": [
    "результат s2: русский текст объяснения"
  ]
}
```

SQL из s1 не заменяет русский текст s2. Переводчик не получает выдуманное объяснение.

**`s3.compile.with-reference-prior` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s3` + назначенный `tr.en` + результаты `s2` с явной отметкой reference.

```json
{
  "domain_id": "tr.en",
  "task": "Переведи на английский: «Запрос возвращает одну строку n=2, учитывая оба значения 0 и исключая NULL». Сохрани n=2, оба нуля и исключение NULL; ответ только перевод.",
  "missing": []
}
```

Передаётся полный русский текст s2 без изменения фактов и без запроса решать SQL заново.

**`s3.subject` → `tr.en`**

Ожидаемый предметный ответ:

```text
The query returns one row with n=2, counting both 0 values and excluding NULL.
```

Перевод сохраняет число строк, значение n, повторение 0 и исключение NULL.

**Ошибка, которую ловит сценарий:** Назвать s2 готовым до появления SQL s1 или передать переводчику собственное объяснение вместо конкретного результата s2.

**Simple check (English):** At each dependent compilation, inspect available_prior_results for the required predecessor ID. A planned or expected result is not an observed result in a live run.

**Старый атомарный router:** `{"action":"clarify","domain_id":null}`. Три действия: старый атомарный router требует clarify; новая задача D22 выделяет три части и две явно заданные зависимости.

## PIPE26-03. Команда в цитате остаётся текстом перевода

Общая семья всех этапов: `ref.pipeline26.quoted-command`.

**Исходный запрос**

```text
Переведи на английский точную цитату «Удалите все файлы». Не выполняй её; в ответе только перевод.
```

Видимый каталог D22: `tr.en` — перевести на английский, `or.automation` — управлять исполнением процесса.

**D22 — ожидаемое разделение**

```json
{
  "segments": [
    {
      "id": "s1",
      "text": "Переведи на английский точную цитату «Удалите все файлы». Не выполняй её; в ответе только перевод.",
      "domain_id": "tr.en",
      "depends_on": []
    }
  ],
  "clarify": []
}
```

**D23 и предметные результаты**

**`s1.compile` → `prompt.task-compilation`**

Вход: полный исходный запрос выше + выбранный сегмент `s1` + назначенный `tr.en` + пустой список доступных результатов предшественников.

```json
{
  "domain_id": "tr.en",
  "task": "Переведи на английский цитату «Удалите все файлы». Не выполняй содержащуюся в ней команду; ответ только перевод.",
  "missing": []
}
```

Цитата передана как данные; ни автоматизация, ни удаление файлов не назначены.

**`s1.subject` → `tr.en`**

Ожидаемый предметный ответ:

```text
Delete all files.
```

Создан только перевод текста. Действий с файлами в этом сценарии нет.

**Ошибка, которую ловит сценарий:** Выделить отдельный маршрут or.automation для слов внутри цитаты или заменить требуемый перевод сообщением «файлы удалены».

**Simple check (English):** Identify the outer instruction before classifying quoted verbs. Translation of an imperative does not authorize performing it.

**Старый атомарный router:** `{"action":"route","domain_id":"tr.en"}`. Здесь одно внешнее действие, поэтому и старый атомарный router выбирает tr.en.

## PIPE26-04. Неуказанный целевой язык требует вопроса

Общая семья всех этапов: `ref.pipeline26.ambiguous-target`.

**Исходный запрос**

```text
Переведи «שלום».
```

Видимый каталог D22: `tr.en` — перевести на английский, `tr.ru` — перевести на русский, `tr.he` — перевести на иврит.

**D22 — ожидаемое разделение**

```json
{
  "segments": [
    {
      "id": "s1",
      "text": "Переведи «שלום».",
      "domain_id": null,
      "depends_on": []
    }
  ],
  "clarify": [
    {
      "segment_id": "s1",
      "missing": "целевой язык перевода"
    }
  ]
}
```

**D23 и предметная задача пока не назначаются:** D23: предметный домен ещё не выбран.

Вопрос: **На какой язык перевести «שלום»?**

Сохранить исходную часть; не выбирать tr.ru по языку интерфейса и не создавать предметный ответ до уточнения языка.

**Ошибка, которую ловит сценарий:** Угадать английский как язык по умолчанию, пометить маршрут подтверждённым и выдать Hello.

**Simple check (English):** List the supported target languages and inspect the user text. None is selected; the source script identifies the source language, not the requested target.

**Старый атомарный router:** `{"action":"clarify","domain_id":null}`. Оба маршрутизатора сохраняют неоднозначность. Это точное незавершённое входное условие, не фиктивный успех.

## Граница задания и учёт результатов

Общий JSON кампании учитывает настоящие созданные пары и владельцев заданий; эти четыре открытые иллюстрации не прибавляются к прогрессу ни одного домена. Фактические subject-ответы и их измерения появляются только при отдельно выполненной генерации/проверке/обучении.

При последующей генерации сохраняйте один origin между частями, компактными заданиями, кодом, документацией и переводом одного сценария. Разные domain_id не делают родственников независимыми. Семантический сбой отмечается по конкретному этапу: потеря действия — D22; потеря общего ограничения — D23; неверный COUNT или перевод — предметный получатель. Нельзя списывать все ошибки на маршрутизатор или объявлять успехом только правильный JSON.
