## Конкретные уточнения при авторской проверке

1. В первоначальном черновике CODE-CS часть поздних мутаций была описана словами без полного исходного fixture. До передачи на интеграцию в каждый prompt добавлен полный сценарий внутри Main: создание исходника, вызов реализуемого метода, мутация и чтение результата. Значения ожидаемого вывода оставлены отдельно от результата реально выполненного oracle.
2. Единственный фиксированный Angular fixture допускал слишком слабую проверку константного ответа. В каждый CODE-NG prompt добавлен повторный вызов после точного `setValue` при прежнем enabled/disabled-state; второе ожидаемое значение записано в `metadata.oracle.follow_up`. C# контракт уточнён для любого конечного не-null списка, включая пустой, а не только для приведённых чисел.
3. `AsReadOnly`, `ToArray`, `value` и `getRawValue` встречаются в разных контрактах с противоположной оценкой. Это исключает правило авторинга «одно имя API всегда правильное» и делает предметной причиной именно условие пользователя.
4. Nullable, начальные значения, enabled/disabled каждого контейнера, runtime-ключи и сигнатуры функций находятся в learner-visible prompt. Для документации выбран ответ о фактическом коде; для написания кода — реализация заданного договора. Ожидание правильного поведения не подменяет объяснение фактического ошибочного кода.
