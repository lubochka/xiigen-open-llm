## Конкретные findings и readback

### DC-XR-01 — один исходный Angular fixture имел разные family_id: RESOLVED

Пары:

- `DOC-NG-04.base.REF2.F0001.P01`, JSONL строка 25;
- `CODE-NG-04.base.REF2.F0001.P01`, JSONL строка 67.

Обе задают один `FormGroup`: `name="Ada"`, `code="X7"`, code disabled, группа enabled. Первая объясняет `value/getRawValue`; вторая создаёт request по тому же исходнику. Изначально family были `sim2.doc-ng-04.f0001` и `sim2.code-ng-04.f0001`. Карточки прямо требуют сохранять общий source-family для исходника и документации/кода к нему. Разные ID могли бы позволить развести потомков одного fixture по TRAIN/EXAM. На стадии reference фактическая утечка ещё не возникла.

Readback: обе строки теперь используют **`sim2.angular.forms.disabled-child`**. Семантика пары сохранена. Это закрывает наблюдавшийся конфликт идентичности; будущий split должен применяться к общему family, а не к `(topic_id,family_id)` отдельно.

### DC-XR-02 — `loadComponent` без явного standalone-контракта: RESOLVED

Пара `DOC-NG-05.base.REF2.F0003.P01`, JSONL строка 33; карточка `DOC-NG-05.md`, пример 3.

Исходный prompt сообщал только, что модуль экспортирует `DetailsComponent`. Ответ говорил, что загружается leaf-компонент. Для исполнимого сценария Angular 16 следует явно определить standalone-компонент, иначе экспорт сам по себе не устанавливает совместимость с `loadComponent`. Если проверяется только значение callback, вопрос можно было бы сузить до этого чтения; исходная формулировка была шире.

Readback: prompt теперь задаёт файл `./details`, класс `DetailsComponent` с `@Component({standalone:true,template:"Details"})` и импорт `Component` из `@angular/core`. Смысловой контраст component/route array остался одним фактором. Это уточнение условий, не выполненная проверка приложения.

### DC-XR-03 — в rejected пропущен второй требуемый результат: RESOLVED

Пара `DOC-NG-04.base.REF2.F0004.P01`, JSONL строка 28; карточка `DOC-NG-04.md`, пример 4.

Prompt требует назвать и `c.value`, и `log` после `setValue("B",{emitEvent:false})`. Chosen даёт оба: `B`, пустой log. Rejected: `c.value равно A; emitEvent:false отменяет присваивание.` Пустой log не назван. Причинная ошибка про обновление значения уже различается, но пропуск второго ответа добавляет различие полноты.

Минимальный ремонт rejected с сохранением одного ошибочного механизма:

> c.value равно A; log пуст, поскольку emitEvent:false отменяет присваивание.

Теперь обе стороны называют оба запрошенных результата; спорным остаётся только трактовка `emitEvent:false` как отмены присваивания. Повторное чтение подтверждает эту формулировку в JSONL и карточке `DOC-NG-04.md`, строка 134. Пример не имел перевёрнутого предпочтения даже до ремонта; исправление улучшает изоляцию фактора.

## Условия для расширения, не новые результаты

1. C# документационные snippets местами показывают helper class и исполняемые statements в одной строке. Перед реальной oracle-компиляцией scaffold должен явно разделять declarations и тело Main, задавать `using System`, `System.Collections.Generic`, `System.Linq` там, где требуется. Ни .NET 6, ни C# 10 сами по себе не гарантируют включённые implicit usings. Это ограничение воспроизводимости фрагментов, а не доказанная семантическая ошибка chosen.
2. Для будущих decimal-семейств явно ограничить диапазон/длину сумм либо задать ожидаемую overflow-политику. Reference F0003 использует малые значения и различается честно; из него нельзя вывести поведение произвольной суммы на границе decimal.
3. Новые SQL оконные пары с ROWS должны задавать полный order при различимых строках. При исследовании RANGE/ROWS нужны равные ключи и явная рамка: текущие reference не доказывают покрытие этого дополнительного случая. Не выдавать новые независимые темы за уже пройденные.
4. Angular 16.2.0, TypeScript 5.1.6, RxJS 7.8.1 в prompt — выбранная симуляционная среда. Исторический ADR с иной major-версией поддерживает проектный стиль, а не фактическую проверку этой версии API. Перед допуском generated-кандидатов нужен предусмотренный oracle именно заданного стека.

Обучение **NOT_RUN**. Измерений скорости, качества обучения и официальных quality_pass нет. Для последующей генерации сохраняются границы `docs.*` (объяснить показанный исходник) и `code.*` (создать реализацию по договору); общий source-family не требует смешивать их учебные темы.
