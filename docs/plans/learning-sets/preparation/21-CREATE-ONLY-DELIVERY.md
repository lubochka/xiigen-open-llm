# Поставка: создание DPO с точными путями и без перехода в review

Дата: 25.10.2026. Изменён существующий пакет подготовки. Основание — текущее поручение пользователя и приложенная сессия исполнителя; [разбор причин](20-CREATE-ONLY-AND-PATHS.md) содержит конкретные строки свидетельств. Базовая версия плановой ветки: `97d61ed38a20fe0a6128ca5648b97fb9520dc17a`.

## Результат

У исполнителя одна дорожка: `prepare → реальная запись draft.jsonl → finish → DRAFT_CREATED → следующий stream`. После создания кандидатов не требуются независимый reviewer, blind-пакет, oracle, accept/export, checksum receipts или запуск Student. Старые будущие процедуры сохранены с явной границей этапа. Набор кандидатов не назван принятым или нативно готовым к обучению.

Во всех 124 карточках и производных индексах согласованы режим, точные Windows-команды, output root и следующий stream ID. Порядок 169 потоков сохранён; старые эксперименты, reference-файлы и примеры не удалялись. Новые данные от китайской модели в этой документной сессии не генерировались.

## Где изменено поведение

| Требование | Реализующее место | Наблюдаемый результат проверки |
|---|---|---|
| Не искать каталоги в чужом workspace | `tools/batches.py::prepare`, `paths.json` | Output по умолчанию — родитель реального preparation, независимо от cwd; проверено в копии с пробелами в пути |
| Не возвращать короткий ошибочный root из карточки | `tools/refresh_indexes.py::command/build` | Все 169 текущих команд берут известный root; все 124 карточки получают тот же режим и очередь |
| Не требовать python, если доступен только py launcher | `tools/create_sets.ps1`, `batches.py::cli` | Обёртка выбирает py -3/python; generated команды используют фактический `sys.executable` и `request.paths.python_executable` |
| Не принимать prepare за генерацию | `prepare`, `finish` | PREPARED не создаёт draft; DRAFT_CREATED требует фактические строки и соответствие request |
| Не уходить в review после записи | `commands_for`, `finish`, MASTER/BATCH prompts | Автоматических команд blind/accept/export в commands.md нет; finish пишет только состояние/отчёт создания |
| Не терять точное задание после compaction | `RESUME.md`, `resume`, `request.paths` | Возвращаются фактические пути, число строк, действие и следующий ID; новый процесс не запускается |
| Не завершать незавершённый процесс по наличию файла | `resume`, `finish` | Сохранённый нетерминальный handle имеет приоритет; finish требует сначала установить terminal |
| Не читать старый run после копирования | `resume` | Draft выбирается только внутри каталога текущего request |
| Не подменять RAG заголовком | `prepare` | Назначенный файл должен содержать реальную сохранённую выдержку; ошибка указывает конкретный путь без требования вычислять checksum |
| Согласовать схему и структурное завершение | `schemas/dpo-candidate.schema.json`, `structural` | Некорректные типы provenance/metadata и ложный measured_training_result не дают DRAFT_CREATED |
| Не продолжать предыдущую задачу при NEXT | Общий промпт, каждая карточка, generated commands | Явный ID пользователя выше очереди; запрет дописывать старый отчёт сохранён в каждом запуске |

Эти функции служат подготовке данных. Они не являются обучаемым router, kNN, LoRA, токенизатором или измерителем Student. Поле metadata не доказывает, что будущий learner его использует.

## Запуск

Исполнителю передать [MASTER-PROMPT-RU.md](prompts/MASTER-PROMPT-RU.md). Первый новый stream готовится так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_sets.ps1" -Stream "TR07-OMISSION/ru-en" -Run "M001" -Count 10
```

Если фактическая попытка уже существует, использовать resume по её request, не удалять данные и не запускать генерацию повторно. Подробные действия по каждому состоянию находятся в [18-BATCH-RUNBOOK.md](18-BATCH-RUNBOOK.md).
