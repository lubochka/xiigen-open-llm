Все исходные draft пока TRAIN; не объявлять их независимым экзаменом или готовым native-входом. Это дополнение не запускает review/training и не меняет обычную квоту CREATE_ONLY.

При назначенной проекции в продукт дополнительно прочитай в31 «До импорта: сохранить смысл фактического входа». Не теряй контекст prompt при заполнении ASide и не передавай canonical_source как уже исправленный вход. Указывай реального получателя и точный вход отдельно от эталона; при неподдержанном контексте не объявляй исходную задачу проверенной. Обычная генерация кандидатов не является такой проекцией и не получает от этого нового задания.

Ты создаёшь учебные кандидаты для XIIGEN через текущую выбранную китайскую модель Kiro. Выполни назначенную группу до её квоты. Всего [24 домена × 1000](../campaign/registry.json), 217 назначений; не по 1000 на каждую микротему.

В каждом окне используй один промпт и уникальный agent ID. Если пользователь уже указал pool, domain, A-ID или request, это назначение выше общего порядка. Не запускай все три пула внутри одной сессии и не копируй ID владельца в другую. Существующий request продолжается по [трём случаям resume](../18-BATCH-RUNBOOK.md#продолжение-next-и-занятость): текущая claim, прежний domain-campaign без claim, отдельный legacy batch. Token, которого ещё не было, выдаёт только explicit resume прежней попытки.

Пути данных: `C:/Projects/llm_mvp_core/learning-sets`. Planning: `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation`. Общая матрица: `C:/Projects/llm_mvp_core/learning-sets/campaigns/D1000-20261025/status.json`; авторитет: `C:/Projects/llm_mvp_core/learning-sets/campaigns/D1000-20261025/state.json`. Все окна используют одну реальную общую папку. `next` назначает свободную работу и возвращает текущие paths/commands. Читай `coordination-prompt.md`, `coordination-material.required.json`, `coordination-commands.md` **по возвращённым путям**, а не устаревшую исполнительную копию из request.

Создай конкретные полные DPO-тройки и отсутствующий материал семей. После сохранения порции выполни выданный `progress`, после полной партии — `finish`, затем — `next`. Не редактируй shared JSON вручную. Матрица содержит `quality_flags` по доменам/темам/профилям; [правила их использования](../28-PARALLEL-GENERATION-AND-QUALITY.md) отделяют доказанную ошибку от ещё не оценённого содержания. Флаг не является новым gate review для генератора.

Не заменяй учебные данные планом их написания. В prompt ученика — задача и видимые решающие факты; в chosen/rejected — два полных ответа с одной содержательной причиной предпочтения. Для удаления одной буквы сравни длину, порядок и всё предложение; для кода — различающий вход; для оркестрации — видимое состояние и допустимое действие. Нужные хорошие/плохие примеры включены прямо в назначенное задание. Полные packs и [навигатор](LIBRARY-NAVIGATOR-RU.md) нужны только при конкретном пробеле.

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

**Если встроенный урок ссылается на старый порядок работы:** `subject.instructions` задаёт предметную задачу, формат ответа, классы и факты. Фразы «Прочитай 06-SOURCES-AND-SKILLS», «отчёт по 08-REPORT-TEMPLATE», восстановление B1, будущий review или пилот не добавляют действий к CREATE_ONLY. Например, для `OR-FUNC-ACCEPTANCE` составь один критерий по видимым условиям, сравни given/when/then, сохрани назначенные строки и выполни текущие coordination-команды; не начинай загрузку полного набора skills ради этой вставки. Это разрешение конкретного конфликта инструкций, а не отмена смысловых требований урока. Применяй краткую выжимку skills ниже. Сохранённые request/prompt и их count/IDs не переписывай.

Это хорошие/плохие примеры и короткая проверка во время авторства, без отдельного reviewer или запуска обучения. У TR02 фраза «начал раньше» не доказывает нужного референта: видимые факты должны исключать второго участника.

Разные допустимые синонимы не дают предпочтение. Rationale, целевой перевод и скрытое восстановление не должны подсказывать ответ ученику. Полные пары и видимые условия обязательны, как указано выше.

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

Применяй [краткую выжимку проектных skills](../campaign/EXECUTOR-SKILLS-RU.md). Источники — назначенные проектные файлы; внешние только с artifact-specific MIT/Apache-2.0. Прежние опыты/строки/IDs не удаляй. Legacy requests не входят в защиту нового координатора и не зачитываются автоматически.
