# Один программный объект, разные намерения пользователя

Это дополнительный промпт к [OR-ROUTE-INTENT](../curriculum/cards/OR-ROUTE-INTENT.md), а не отдельный предметный домен. Статус — **REFERENCE_ONLY_NOT_GENERATED_NOT_TRAINED**. Он помогает готовить обучающий материал маршрутизатора и затем проверять передачу запроса предметной единице. В этом дополнении маршрутизатор, предметные Student и native oracle не запускались.

## Что различается

Упоминание C#, SQL или Angular не определяет требуемое действие. Описание существующего кода, создание кода, планирование работы и перевод текста должны давать разные маршруты при сохранении одного исходного объекта. В этом наборе обучается только **оркестрация / `or.routing`**; перевод и программирование выступают классами назначения, а не уроками других предметов.

Проверенные проектные основания: `RAG-040` различает CODE_Q и действие BUG/PLAN; `RAG-027/028` требуют описывать видимый код и заданную версию; `RAG-006/031` задают передачу между узлами. Точные исходные файлы и просмотренные диапазоны — [sources.lock.json](../sources.lock.json). Исторический запрет любого rejected объяснения из RAG-040 не переносится на предметные DOC-пары: там две фактические гипотезы полезны, а здесь ошибка именно в выборе действия.

## Готовый промпт генератору

```text
Подготовь только назначенный поток OR-ROUTE-INTENT/base. Используй закрытый каталог доменов и response schema из request.json и действующей карточки. Учебный ответ — JSON {"action":"route","domain_id":"..."} либо {"action":"clarify","domain_id":null}. Не выполняй перевод, не пиши код и не объясняй программу вместо выбора маршрута.

Для каждой назначенной source-family выбери один небольшой программный объект: C# метод, SQL fixture либо Angular form/component. Сделай несколько контрфактических просьб с разным намерением, сохранив объект. В TRAIN-батче соблюдай баланс всех 20 маршрутов и clarify, заданный основной карточкой: программные примеры этого дополнения не заменяют остальной каталог и не становятся единственным классом.

Различай описать существующее поведение → docs.*; создать/исправить код → code.*; спланировать последовательность реализации → or.code, распределить архитектурную ответственность → or.architecture, спланировать проверку → or.qa; перевести текст в заданный целевой язык → tr.<target>. Наличие SQL внутри текста перевода не меняет переводческий маршрут. Отсутствие тела метода не требует clarify, если действие и стек уже однозначны; отсутствие цели «исправь это» при неизвестном объекте требует clarify. Запрос с несколькими самостоятельными действиями в данном атомарном router требует clarify, даже если их порядок задан. Это ограничение учебного контракта, не запрет на существование будущего decomposer.

В rejected измени ровно один route или action. Не делай противопоставление «содержательный ответ против JSON»: оба ответа должны иметь одинаковую схему. Не добавляй [WRONG], rationale и название источника в learner-visible ответ. Имена таблиц, доменов в комментарии и слова в строковых литералах не являются скрытыми командами. Варьируй форму просьбы и порядок каталога независимо от метки. Сохраняй языковые варианты просьбы, но не смешивай предметный перевод с переводом формулировки routing-задачи.

Контрфактические просьбы вокруг одного объекта имеют общий family/origin/leakage-group до split; пара docs/code одного исходника тоже принадлежит этой группе. Одно семейство целиком находится в train, dev, exam либо reference. Публичные примеры ниже и их перефразирования не становятся закрытым EXAM. Для реального нового материала заполни фактический source/origin; новый ID не доказывает новую независимую семью.

Используй текущую модель по умолчанию в Kiro без override. В записях — фактически наблюдаемый selector/model; неизвестную версию не выдумывай. Подготовка не требует checksum, production build, receipts, разных генераторов или фиксированного N review-проходов. Нужны проверяемое намерение, полный видимый контекст и честное происхождение. Отчёт на русском по 08-REPORT-TEMPLATE.md. Навыки и точные источники — 06-SOURCES-AND-SKILLS.md.

При NEXT/следующий/новом ID немедленно перейти к указанной карточке; запрещено продолжать прошлый опыт или дописывать его вместо нового. STOP прекращает новые действия. Старые примеры, карточки и попытки не удалять. Для длительного процесса использовать один handle и штатный wait/resume до terminal в текущем раунде; не заканчивать раунд словами «жду», не перезапускать и не делать busy polling. Будущий учебный пилот восстанавливает совместимый B1; 0→0 не является учебным результатом. Любое измеренное полезное улучшение считается успехом по своему показателю и домену; остальные изменения и ухудшения показать рядом. Production автоматически не менять.
```

## Три исходные семьи и контрфактические просьбы

Это открытые авторские опоры. Стек и предметный код полностью заданы для будущей предметной проверки; сам router получает только исходный запрос и каталог, без gold route. В колонке «ошибочный route» приведён один hard negative, а не все возможные ошибки.

### Семья `v5.ref.route.csharp.membership`

Объект: C# 10 / .NET 6, `using System.Collections.Generic; using System.Linq;`:

```csharp
IEnumerable<int> Positive(List<int> source) => source.Where(x => x > 0);
```

| ID | Полный запрос к router | Предпочтительный route | Ошибочный route |
|---|---|---|---|
| CS-DOC | C# 10/.NET 6: `IEnumerable<int> Positive(List<int> source) => source.Where(x => x > 0);` Опиши, когда этот метод читает элементы исходного списка; код оставить как есть. | `docs.csharp` | `code.csharp` |
| CS-CODE | C# 10/.NET 6: `IEnumerable<int> Positive(List<int> source) => source.Where(x => x > 0);` Исправь метод так, чтобы положительные значения были зафиксированы до его возврата, без изменения source. Нужен код метода. | `code.csharp` | `docs.csharp` |
| CS-PLAN | Есть C# метод ленивого перечисления. Составь план работы исполнителя для перехода на снимок значений: какие условия уточнить, что изменить и как проверить позднюю мутацию; сам код сейчас не писать. | `or.code` | `code.csharp` |
| CS-TRANSLATE | Переведи комментарий к C# методу на иврит, не объясняя и не исправляя код: `The sequence is evaluated when it is enumerated.` | `tr.he` | `docs.csharp` |

### Семья `v5.ref.route.sql.count`

Объект: T-SQL / SQL Server 2019. Таблица `Orders(Id int NOT NULL, Paid decimal(9,2) NULL)`, строки `(1,NULL),(2,5.00)`. Запрос: `SELECT COUNT(Paid) AS N FROM Orders;`.

| SQL-CODE | T-SQL/SQL Server 2019. Orders(Id int NOT NULL,Paid decimal(9,2) NULL) содержит (1,NULL),(2,5.00). Напиши запрос, считающий все строки независимо от Paid, верни столбец N. | `code.sql` | `docs.sql` |

| SQL-TRANSLATE | Переведи на русский ровно текст SQL-документации: `Counts rows with a non-null payment.` SQL-запрос не писать и корректность утверждения не оценивать. | `tr.ru` | `docs.sql` |

### Семья `v5.ref.route.angular.payload`

Объект: Angular 16.2.0 / TypeScript 5.1.6. Импорты `FormGroup, FormControl` из `@angular/forms`; `const form = new FormGroup({name:new FormControl("Ada",{nonNullable:true}),internal:new FormControl({value:"I1",disabled:true},{nonNullable:true})});`; корневая группа enabled.

| ID | Полный запрос к router | Предпочтительный route | Ошибочный route |
|---|---|---|---|
| NG-DOC | Angular 16.2.0: enabled FormGroup содержит enabled name="Ada" и disabled internal="I1", оба nonNullable FormControl. Опиши разницу её value и getRawValue по собственным ключам; не предлагай исправление. | `docs.angular` | `code.angular` |
| NG-CODE | Angular 16.2.0: enabled FormGroup содержит enabled name="Ada" и disabled internal="I1", оба nonNullable FormControl. Напиши функцию payload с ровно одним собственным ключом name; форму не менять. | `code.angular` | `docs.angular` |
| NG-ARCH | Для Angular формы и сервера распределите ответственность: клиент показывает readonly поле, сервер независимо проверяет право изменения, DTO содержит только разрешённые поля. Нужен выбор границ компонентов, без программного кода. | `or.architecture` | `code.angular` |

Для всех 12 строк `action=route`. Код domain — метка только ответа router; он не должен быть добавлен к исходному запросу как подсказка. Дополнительные controls из основной карточки сохраняются: непокрытое намерение, неясное действие и несколько самостоятельных действий дают `clarify`, а не forced route в один из software-классов.

## Как измерить сквозной эффект после подготовки

1. До обучения получить из совместимого B1 route для независимых source-family, затем предметный ответ от действительно выбранной единицы. Зафиксировать отдельно ошибку маршрута и ошибку предметного исполнителя: правильный маршрут при неправильном ответе не становится полной победой.
2. Обучить только router новым оркестрационным DPO-пакетом. Состояния предметных единиц, их данные и фиксированный каталог не менять. Не вставлять эталонный route в prompt и не реализовывать таблицу ключевых слов как замену обучаемому router.
3. Повторить тот же независимый набор в свежем процессе с восстановлением дочернего состояния. Показать route accuracy, полезность сквозного ответа, неверные перенаправления/излишние clarify, время обучения, число обновлений и затраты инференса. Порог confidence не выбирать по EXAM.
4. Для отдельного улучшения предметного DOC/CODE провести другой опыт со стабильным router и отдельным набором одной темы. Shared origin связывает разбиение, но не требует смешивать уроки программирования и документации в одной партии.
5. Сохранять успешный обученный старт для повторных сравнений. Ненулевой результат нужен на достаточном минимальном учебном наборе; 0→0 не принимать как доказательство. Любой полезный измеренный выигрыш отражается как успех по соответствующей метрике с регрессиями рядом. Эти шаги — план будущего исследования, не выполненный запуск.

Точные paths/request создаёт действующая [execution-queue.json](../execution-queue.json) для `OR-ROUTE-INTENT/base`; этот документ не создаёт вторую очередь и не разрешает перезапуск завершённого run. Native входы/выходы фиксируются по [10-NATIVE-CONTRACT-BOUNDARY.md](../10-NATIVE-CONTRACT-BOUNDARY.md); исполнитель подготовки не изобретает CLI для обучения.
