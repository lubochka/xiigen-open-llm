# Восстановить текущую сессию DPO после потери контекста

Цель — реальные кандидатные prompt/chosen/rejected в назначенном пуле. [24 домена, 24 000 всего](../campaign/registry.json); сохраняй прежний выбор пользователя и его границы. Planning: `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation`. Output: `C:/Projects/llm_mvp_core/learning-sets`.

1. Возьми точный существующий request и **текущие coordination-commands** этой сессии. Сохрани её agent ID, pool и claim token. Не создавай новый ID для дублирования прежнего задания.
2. Прямой NEXT/новый ID немедленно заменяет старое назначение; STOP прекращает действия. Не возвращайся к предыдущему отчёту или ремонту после переключения.
3. Выполни exact resume владельца. Прочитай возвращённые `paths.prompt`, `paths.material_required`, `paths.commands`. Первоначальный request и уже записанные строки сохраняются; производные coordination-файлы получают актуальные подсказки и owner-команды.
4. Посмотри общую матрицу `C:/Projects/llm_mvp_core/learning-sets/campaigns/D1000-20261025/status.json`: текущий owner/request, `authoring_rows_saved`, `draft_created_pairs`, remaining и `quality_flags`. Не редактируй state/status вручную и не снимай чужую claim по возрасту.
5. Прочитай одну назначенную микротему и включённые примеры. Допиши недостающие реальные строки/семьи, выполни `progress`, затем `finish` и выданный `next`. Существующий draft не удаляй и не перегенерируй целиком.

Если request уже завершён, используй возвращённые `next/status`; не выполняй повторную генерацию. Legacy `xiigen.batch-request.v1` обозначен `LEGACY_NOT_COORDINATED` и возобновляется отдельно последовательно своим runner. Его пути не переносятся задним числом, строки не зачитываются автоматически в D1000.

Нечитаемый UI-вывод проверь чтением исходного UTF-8, не перекодировкой здоровых файлов. Бессвязный повтор не копируй в новый prompt; сохрани фактический trace. Причина модель/сервер/UI по одному trace не доказана.

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.
