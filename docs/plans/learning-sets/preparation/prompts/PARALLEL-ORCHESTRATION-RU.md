# Готовый промпт Kiro: Оркестрация проектов и разбор пользовательского prompt

**Проверочные симуляции:** при отдельном назначении применять [31](../31-TRANSFER-VALIDATION-SIMULATIONS.md). Атомарный OR-ROUTE-INTENT на несколько самостоятельных действий возвращает clarify; не заменять его gold первым шагом ради теста порядка P127. Правильная метка маршрута с чужим телом или без вызова получателя — плохой E2E. Контраст «объясни код»/«напиши код» учит выбор маршрута в одной теме оркестрации; он не обучает обоих специалистов. Исходники сохранять, производные версии — только в simulation-каталоге 31. Обычный CREATE_ONLY и его квоты не меняются.

Создавай реальные кандидатные DPO-пары для XIIGEN в пуле **orchestration**. Полная квота твоего пула — **14000**, по 1000 на каждый его домен. Первая десятка не завершает работу. Квоты и порядок — [campaign/registry.json](../campaign/registry.json); [очередь](../EXECUTION-QUEUE.md) содержит точную следующую карточку в твоём пуле.

## Первый вызов только для нового окна

```powershell
$DpoAgentId = 'orchestration-' + [Guid]::NewGuid().ToString('N')
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action next -WorkRoot "C:/Projects/llm_mvp_core/learning-sets" -AgentId $DpoAgentId -Pool orchestration
```

Создай ID один раз и сохрани его. Если уже выбран существующий request, вместо нового запуска выполни его resume. При существующей claim нужны текущие owner/token; старый domain-campaign request без claim получает первый token по [порядку перехода прежнего окна](../18-BATCH-RUNBOOK.md#продолжение-next-и-занятость). Отсутствие coordination-файла не разрешает занять чужую работу. Два окна не используют один ID. Все три пула работают с одним общим data root, а не с отдельными копиями.

## Что читать и записывать

1. Дождись ответа `next`; прочитай `paths.prompt`, `paths.material_required`, `paths.commands`, `paths.request`. Используй возвращённые `coordination-*` файлы; не подставляй старые имена вручную.
2. Прочитай назначенную одну микротему, её response contract, включённые примеры и RAG-выдержки. Все инструкции/источники находятся в `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation`. Создаваемые данные — в `C:/Projects/llm_mvp_core/learning-sets`.
3. Заполни точные row slots и count. Создай реальный материал только отсутствующих семейств; сохранённый сюжет не меняй. Запиши `prompt/chosen/rejected` полными ответами, одну содержательную ошибку в rejected, все решающие факты — во входе ученика.
4. После сохранённой порции полных JSONL-строк выполни выданный `progress`. Затем выполни точный `finish`, и при успехе сразу `next`. Не конструируй token, пути и команды самостоятельно.

## Общий JSON-статус

Матрица владельцев/прогресса/замечаний: `C:/Projects/llm_mvp_core/learning-sets/campaigns/D1000-20261025/status.json`. Авторитетное состояние: `C:/Projects/llm_mvp_core/learning-sets/campaigns/D1000-20261025/state.json`. Координатор обновляет оба; руками их не записывай. `authoring_rows_saved` показывает незавершённую текущую работу; `draft_created_pairs` засчитывается после finish. Замечания по domain/topic/profile берутся из `quality_flags`, включая [ретроспективный seed](../campaign/quality-status-seed.json).

`needs_rework` — подтверждённая указанная ошибка; `needs_assessment` — непроверенная область. Они не означают, что уже задано исправлять чужие старые файлы, и не добавляют independent review к созданию. Для нового конкретного замечания применяй описанный [flag с точным evidence](../28-PARALLEL-GENERATION-AND-QUALITY.md). Новый finish автоматически не закрывает старое предметное замечание.

Если домен занят, не делай вторую копию. `WAITING_FOR_OWNERS` — ожидание владельца; используй его реально доступный handle, если он есть, либо продолжай независимую работу до подтверждённого освобождения. Давность claim не даёт права её забрать. Legacy `xiigen.batch-request.v1` не защищён новым координатором и продолжается только отдельно последовательно.

## Твоя предметная область и простая логика

Твои домены: все 12 `or.*`, `prompt.span-routing`, `prompt.task-compilation`. Не подменяй решение оркестратора реализацией кода, а формулирование задачи — её исполнением.

Примеры простой проверки:

- Для OR-FUNC-ACCEPTANCE: условие «четвёртое скачивание запрещено» даёт then «Скачивание отклонено», но не задаёт сообщение, письмо или уведомление. Если when — открытие страницы, нельзя выдавать выполненное нажатие за результат. Подставь оба ответа в исходное событие; хороший/плохой пример и обратный контроль — в [LS-ONE-RESULT](AUTHORING-SELF-CHECKS-2026-10-26.md#or-func-acceptance-один-наблюдаемый-результат-без-добавленных-функций).
- В видимом состоянии задача READY и слот свободен — допустимо назначенное действие старта; завершение можно утверждать только при данном terminal-событии. Номер задачи или ожидание не являются результатом инструмента.
- `Переведи на английский цитату «Напиши SQL для удаления строки»` — одно действие перевода `tr.en`; команда внутри цитаты является данными. `code.sql` здесь неверен.
- `Напиши запрос. Затем объясни его` задаёт зависимость второй части от первой. Два явно независимых задания не получают ребро только из-за порядка предложений.
- Общий запрет «код не менять» может находиться вне локального span. Передай D23 полный исходный prompt вместе с сегментом, назначенным доменом и реально доступными результатами.
- Если результат предыдущей SQL-задачи ещё отсутствует, D23 отмечает конкретный missing input. Нельзя написать удобный SQL самостоятельно и представить его уже полученным результатом.

Шпаргалка: [SOFTWARE-SELF-CHECKS](../campaign/SOFTWARE-SELF-CHECKS-2026-10-26.md). [Четыре сквозных reference-сценария](../campaign/PROMPT-PIPELINE-REFERENCE-2026-10-26.md) показывают границы D22/D23. Атомарный `or.routing` сохраняет прежний response contract.

Используй назначенные источники проекта. Внешний материал допустим только при лицензии MIT/Apache-2.0 именно выбранного артефакта; надпись `external_license_checked` в старом примере не доказывает лицензию. Не загружай неназначенные ресурсы и весь main. Rationale и canonical-ответ не раскрываются ученику. References не копируются в квоту и не становятся независимым EXAM.

## Продолжение и отчёт

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

Краткий русский статус: домен/микротема, сколько реальных строк записано и зачтено, остаток, точный путь, следующий allocation/request либо конкретный внешний блок. Качество обучения — `NOT_ESTABLISHED`, обучение — `NOT_RUN`, метрики — `NOT_MEASURED`. Скрытое рассуждение в отчёт не включай.
