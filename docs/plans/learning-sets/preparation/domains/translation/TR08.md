## Что именно учим

При явно заданном intended-language восстановить текст по проверяемому соответствию клавиш и перевести его.

Домены текущего задания: `tr.en`, `tr.ru`, `tr.he` — язык назначения. Профили: `ru-en`, `he-en`, `en-ru`, `he-ru`, `en-he`, `ru-he`. **Один файл, один topic, один профиль.** Источники и механизмы не становятся дополнительными доменами. Отдельный TRAIN для направления не запрещает общую lineage-разметку его обратных переводов.

Для первого пакета intended-language обязателен; source_raw, layout_from, layout_to, map_id и canonical_source сохраняются. Использовать только поддержанные unshifted-клавиши fixture. Составление всех букв одного алфавита по памяти недопустимо: карта лежит рядом. Прямой RU↔HE перевод поддерживается; восстановление RU-клавиатуры в HE и наоборот пока не покрыто fixture и не утверждается выполненным.

## Шесть конкретных контрастов

| Профиль | Исходный текст | Chosen | Rejected | Почему предпочтение имеет смысл |
|---|---|---|---|---|
| `ru-en` | ghbdtn | Hello. | Thank you. | QWERTY-ввод ghbdtn соответствует привет; intended ru. |
| `he-en` | akuo; контекст: дружеское приветствие при встрече в начале разговора | Hello. | Goodbye. | QWERTY-ввод akuo соответствует שלום; видимый контекст выбирает приветствие, а не прощание. |
| `en-ru` | руддщ | Привет. | Спасибо. | РУ-ввод руддщ соответствует hello; intended en. |
| `he-ru` | ,usv | Спасибо. | Привет. | QWERTY-ввод ,usv соответствует תודה; intended he. |
| `en-he` | נםםל; контекст: книга для чтения, существительное | ספר | מחברת | HE-ввод נםםל соответствует book; видимый контекст исключает значение глагола бронирования. |
| `ru-he` | cgfcb,j | תודה. | שלום. | QWERTY-ввод cgfcb,j соответствует спасибо; intended ru. |

### Невалидный пример, который нельзя размножать

Для raw «to» без intended-language нельзя автоматически выбрать смысл. На EN это самостоятельное слово, в RU-раскладке эти клавиши дадут «ещ». Наличие преобразования не доказывает намерение пользователя.

Та же проблема возникает после корректного восстановления: `שלום` без ситуации может служить приветствием или прощанием, а `book` бывает существительным и глаголом. В активном JSONL эти опоры имеют новые ID `TR08-REF-02-v3` и `TR08-REF-05-v3`, видимый контекст и `derived_from`. Исходные версии полностью сохранены с причиной в [quarantine/translation-legacy-v1.jsonl](../../quarantine/translation-legacy-v1.jsonl). Их нельзя возвращать в обучение как однозначные пары. Это исправление авторских примеров, не измеренный результат обучения.

## Матрица генерации внутри маленькой темы

Направление восстановления раскладки задаёт исходный язык профиля; оно не совпадает автоматически с направлением перевода.

| Source-язык | Профили перевода | Допустимое восстановление по fixture |
|---|---|---|
| RU | `ru-en`, `ru-he` | фактическая `en-qwerty` → предполагаемая `ru-ycuken` |
| HE | `he-en`, `he-ru` | фактическая `en-qwerty` → предполагаемая `he-fixture` |
| EN | `en-ru`, `en-he` | фактическая `ru-ycuken` или `he-fixture` → предполагаемая `en-qwerty` |

Для узкого задания используйте objective `TR08-LAYOUT` из [curriculum/translation.json](../../curriculum/translation.json): один source-профиль, известная карта и контекст значения. Чистая форма проверяется отдельным контролем с честным prompt без утверждения о наличии ошибки. Неоднозначный ввод без достаточных оснований отделяется в TR10; он не попадает в квоту однозначного восстановления.

Первый pilot — 50 принятых пар **на один профиль**: две генерации по 25. Для source RU и HE все 50 используют единственную разрешённую здесь карту. Для source EN назначаются 25 на фактическую RU-карту и 25 на фактическую HE-карту; это два значения одного фактора известной раскладки в пределах одного source-профиля. После проверки семантики и утечки собрать достаточный учебный pilot по общему плану. При дальнейшем выпуске 1 000 пар сохранить соответствующие доли: RU/HE — 1 000 по своей карте; EN — 500 + 500 по двум разрешённым картам. Не включать строку чужого source-языка ради квоты. Если request фиксирует один разрешённый map, все строки относятся к нему, что явно отражается в отчёте. Расширение до 5 000 требует полезного измеренного результата соответствующего учебного pilot; это план, не уже созданные строки.

Один stem-сценарий, его переводы, парафразы, чистый и испорченный ввод имеют один family/lineage и один split. Не объявляй 1 000 перефразировок одной фразы 1 000 независимыми примерами. Журнал содержит число строк, семей и независимых сценариев отдельно.

### Межкарточная связь семьи

`metadata.lexical_family_ids` связывает правильное написание, опечатку и клавиатурный вариант одной исходной лексемы в TR07 и TR08. Значение задаётся sense/context. `metadata.leakage_group_ids` связывает исходный сценарий и его производные через `source:<origin_family_id>`; общесловарный lexical ID сам по себе не переносится туда для всех независимых предложений. Если эксперимент проверяет перенос на новые лексемы, отдельное заранее назначенное lexical-heldout разбиение указывается явно. Чистая/испорченная формы и все языковые производные одного сценария в любом случае остаются в одном split. Сначала сверить общий lineage-реестр, затем генерировать. Автоматический номер `v1/tr/TR07/F…` или `v1/tr/TR08/F…` сам по себе не доказывает различие/независимость смысла. Если request предписал split, несовместимый с уже закреплённой семьёй, эту семью не использовать в данном пакете и не менять её split задним числом. Связанные материалы проходят глобальную проверку вместе с другими профилями и карточками, а не только локальный merge одного файла.

### Управление работой — обязательно

- Текущая фаза — подготовка материала. Сначала создай заданный пакет и отчёт; не запускай обучение, исправление production-кода или всей цепочки тестов по собственной инициативе.
- При прямом «следующий» переходи к указанному ID; запрещено продолжать предыдущую задачу, дописывать её план или повторять её запуски. При «стоп» немедленно прекрати действия. Номер строки реестра не заменяет ID карточки.
- Если обучение позже явно запущено по этой карточке, используй существующий handle процесса и штатное ожидание из [инструкции Kiro](../../03-GENERATION-AND-KIRO.md). Не заканчивай раунд словами «жду», не запускай копию и не заменяй ожидание частым опросом одного тула. Записывай terminal-state и exit code; отсутствие свежего файла не означает отказ процесса.
- Любое измеренное улучшение полезной метрики — успех по этой метрике, профилю и домену; рядом покажи остальные изменения, включая ухудшения. Результаты после реального обучения не подменяются schema-pass, margin, красотой файлов или скоростью скрипта подготовки.
- При нуле правильных предметных ответов до и после учебного эффекта не показано. Восстанови проверенный обученный parent либо в отдельном ограниченном pilot обучи и сохрани базовую компетенцию по [правилам checkpoint](../../05-LEARNING-AND-CHECKPOINTS.md); не расширяй бюджет молча и не начинай с нуля при существующем совместимом состоянии.
- Сохраняй прежние примеры, эксперименты и отчёты. Новый материал — новый run/revision; конфликт существующей папки решается новым RUN_ID, а не удалением. Успешный опыт — кандидат на исправление; решение о переносе в исходный код принимает Люба.
