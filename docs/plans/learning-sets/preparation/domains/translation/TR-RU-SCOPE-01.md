### Пример 1: `en-ru` — not_all_vs_none

**Prompt:** Симуляция перевода. Переведи с языка «английский» на язык «русский». Ответ — только перевод; не добавляй объяснение, служебную разметку или новый факт.
Исходный текст: Not all guests arrived.

**Chosen:** Не все гости пришли.

**Rejected:** Ни один гость не пришёл.

**Почему:** Отрицание всеобщности превращено в отсутствие любого пришедшего. Исходник допускает, что часть гостей пришла.

**Проверка смысла:** Из трёх гостей пришли двое: chosen истинно, rejected ложно.

Семья: `sim:translation:logic-v2:not-all-guests-arrived`.

## Что варьировать и что оставить постоянным

Варьировать имена, бытовые предметы, число участников, порядок придаточного и главного предложения, естественные синонимы. Сохранять одну указанную смысловую ошибку; не ухудшать rejected одновременно грамматикой, чужим языком, стилем и лишней болтовнёй.

Квоты после успешных пилотов — 1 000 **принятых** TRAIN-пар на каждый профиль отдельно; это цель, не имеющееся количество:

- «Не все» против «ни один»: 200 из 1000.
- «Не оба» против «ни один из двух»: 150 из 1000.
- «Только» при субъекте и при объекте: 150 из 1000.
- По одному объекту каждому против одного общего объекта: 150 из 1000.
- Нижняя/верхняя граница количества: 200 из 1000.
- «Только подписанные» против «все подписанные»: 150 из 1000; менять предметные существительные.

Не учить скрытые пресуппозиции, иронию и литературное отрицание. Не отмечать стилистически разные эквивалентные кванторы как ошибку. Изолированное «каждый ... один» без уточнения не использовать для жёсткой оценки общего/разного объекта.

## Какой учебный механизм материал должен проверить позже

Предполагаемый получатель — переводческая Unit/адаптер домена `tr.ru` для данного профиля. DPO должен менять вероятность полноценного перевода относительно ошибочного на одном и том же входе; при отдельной проверке обучаемой kNN-памяти должна реально изменяться её запись/представление, участвующее в переводе. Наличие family metadata само по себе не доказывает обучение токенизатора или kNN.

До запуска привязать карточку к проверенному native training_entrypoint, inference_entrypoint, полям состояния и сохранённому parent из 05-LEARNING-AND-CHECKPOINTS.md. Эта карточка не придумывает существующий класс/runner и не разрешает production-правку. Проверка JSON или перевод детерминистическим словарём не заменяет учебный опыт.

Для A/B восстановить один и тот же проверенный parent в раздельные run-папки, сохранить tokenizer/template/reference-policy/dataset hashes, бюджет и порядок. Достаточность стартовой компетенции доказать предметными ответами; не обучать с нуля при существующем совместимом состоянии. 0 правильных ответов до и после не является валидным опытом. Если parent отсутствует, отдельный ограниченный bootstrap-план должен создать и сохранить общий parent один раз; не прятать этот этап внутри сравнения.

Показатели по этому профилю:

- сохранение области отрицания.
- сохранение субъекта/объекта оператора «только».
- сохранение числовой границы.
- ложное усиление либо ослабление утверждения.
- Время реального train/update/load→train, peak RAM/VRAM, число обработанных токенов и сохранность компетенции после fresh load.

Любое измеренное улучшение полезного показателя — успех по этому показателю и домену; обязательный рост общей точности не требуется. Рядом показать все остальные дельты, включая ухудшения и разброс повторов. При ненулевой базовой компетенции ресурсный выигрыш измеряется в реально выполняемом обучении. Margin без усвоенного предметного поведения не выдаётся за учебный результат. Результат успешного опыта документируется кандидатом; интеграцию решает пользователь.
