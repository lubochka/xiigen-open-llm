# Начать параллельное создание DPO

Если задача — **улучшить наборы для проверки переноса**, сначала открыть [31 — отдельные симуляции](31-TRANSFER-VALIDATION-SIMULATIONS.md) и назначенный профиль 158. Нижние команды относятся к обычной кампании CREATE_ONLY; не запускать её заново вместо проверки уже существующих партий.

**24 домена × 1000 = 24 000 кандидатных TRAIN-пар.** Квоты принадлежат [campaign/registry.json](campaign/registry.json); 217 назначений делят этот объём. Это цель, а не число уже созданных или проверенных пар.

Открой три независимых окна Kiro и в каждое вставь соответствующий готовый промпт. Каждый промпт содержит свою команду и создаёт уникальный ID сессии.

| Независимое окно Kiro | Пул | Домены | Квота |
|---|---|---|---:|
| [Переводы и опечатки](prompts/PARALLEL-TRANSLATIONS-RU.md) | `translations` | `tr.en`, `tr.ru`, `tr.he`, `text.typo-normalization` | 4000 |
| [Оркестрация и части prompt](prompts/PARALLEL-ORCHESTRATION-RU.md) | `orchestration` | 12 `or.*` + `prompt.span-routing`, `prompt.task-compilation` | 14000 |
| [Код и документация](prompts/PARALLEL-SOFTWARE-RU.md) | `software` | 3 `docs.*` + 3 `code.*` | 6000 |

1. Если уже явно выбран сохранённый request, продолжай именно его. Для текущей claim используй сохранённые owner/token и resume. Старый domain-campaign request без claim получает первый token через [explicit resume прежнего окна](18-BATCH-RUNBOOK.md#продолжение-next-и-занятость); искать token в старом prompt или запускать замену через next не нужно. Не создавай второй экземпляр работы.
2. При новом запуске один раз выполни стартовую команду своего промпта. В следующих партиях исполняй **точные команды, возвращённые координатором**; они уже содержат agent ID, pool, token и пути.
3. Прочитай файлы по возвращённым ключам `paths.prompt`, `paths.material_required`, `paths.commands`, а также исходный `request.json`. Для согласованной параллельной работы это `coordination-prompt.md`, `coordination-material.required.json`, `coordination-commands.md`. Старый `prompt.md` сохранён как история назначения и не задаёт текущего владельца.
4. Создай назначенное количество реальных `prompt/chosen/rejected` и отсутствующий материал семейств. Записывай полностью сформированные JSONL-строки. После сохранённой порции выполни возвращённый `progress`; незавершённые строки не засчитываются в доменную квоту.
5. Выполни точный `finish`, затем `next`. Общая матрица обновляется координатором. Не редактируй `state.json` и `status.json` вручную.

Встроенный `subject.instructions` сохраняет предметные ограничения, но старые указания прочитать `06-SOURCES-AND-SKILLS.md`, оформить отчёт по `08-REPORT-TEMPLATE.md` или запустить будущий pilot не добавляют действий к CREATE_ONLY. Рабочий порядок задают текущие coordination-файлы и этот входной документ. Применяй [краткую выжимку skills](campaign/EXECUTOR-SKILLS-RU.md); полные packs и исторические аудиты не перечитываются для каждой партии.

Для назначенной микротемы используй её раздел [примеров самопроверки по аудиту](prompts/AUTHORING-SELF-CHECKS-2026-10-26.md), если он есть, вместе с включёнными в задание примерами. Это проверка при авторстве, не отдельный review-шаг. Один формат двух ответов, одна содержательная ошибка rejected и общий сохранённый сюжет EN/RU/HE остаются обязательными; обновление памятки не переписывает готовый request или draft.

|---|---|
| Создаваемые наборы | `C:/Projects/llm_mvp_core/learning-sets` |
| Инструкции и назначенные источники | `C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation` |

Одинаковый data root на **одной общей файловой системе** обязателен для всех окон. Разные копии каталогов и разные компьютеры не образуют общий координатор. Занятость защищает домен и ещё не сохранённые общие семейства. Давность записи не даёт права захватить работу другого агента.

**Показать общую матрицу:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/tools/create_campaign.ps1" -Action status -WorkRoot "C:/Projects/llm_mvp_core/learning-sets"
```

Reason internally in English. Do not output private reasoning or a chain-of-thought transcript. Краткие статусы и итог — по-русски; учебный текст — на языке назначенного профиля. Используй текущую выбранную китайскую модель Kiro без override. Не угадывай имя или версию модели; неизвестное происхождение обозначай `unknown`.

CREATE_ONLY: реальные кандидатные DPO-пары и материал семейств. Самопроверка смысла каждой составляемой строки входит в создание. Отдельный reviewer, checksum-гейты, acceptance, export/import, обучение и production CI в эту сессию не входят. `finish` проверяет структуру и назначенный объём, но не доказывает смысловую правильность или обучение.

После успешного `finish` сразу выполни выданный `next` и продолжай до квоты своего пула, без вопроса «продолжать?». Прямой NEXT/новый ID немедленно заменяет прежнее задание: не доделывай старый отчёт, ремонт или запуск. STOP прекращает действия, включая вызов release; сохранённая claim остаётся для явно разрешённого последующего resume/release. Реальный внешний блок сообщай точно, не выдавай его за DONE.

Если инструмент реально выполняется и вернул handle, прочитай документацию доступного инструмента и используй его штатный wait/resume до terminal. Зависимое чтение выполняй после завершения записи. Пустой stdout, раннее отсутствие файла и timeout транспорта не доказывают падение. Не запускай дубликат, не создавай цикл частого опроса, не придумывай API ожидания и не заканчивай работу вместо доступного ожидания.

Старый `xiigen.batch-request.v1` продолжает работать через отдельный последовательный legacy runner; общими claims он не защищён. Не запускай его копию параллельно. Старыми строками новая квота автоматически не пополняется.
