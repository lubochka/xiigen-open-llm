## 5. Оси генерации и содержательная проверка

- **key_state:** absent; owned_by_self; owned_by_other; done; expired.
- **payload:** same; different.
- **guarantee:** atomic_unique; non_atomic_check_then_write; explicit_cas.

В первой партии должны присутствовать все релевантные состояния из этих осей и близкие контроли с противоположным действием. Не требуется механическое равенство всех комбинаций; фактическое распределение классов записать в отчёте. Если целый класс отсутствует, не объявлять pilot содержательно полным.

- Условие явно задаёт атомарность, единственного владельца и предел действия lease.
- Есть положительный контроль apply_once после полученного владения и reuse_result после done.
- Истечение lease не представлено новым правом без атомарного захвата.
- Один решающий дефект; выбранный ответ следует из видимого prompt, а не из скрытых метаданных.
- Есть близкий контроль с обратным решением; нельзя выигрывать постоянным ожиданием, отказом или одним классом.
- Контрпример не выдан за новую измеренную строку и остаётся в семье исходного сценария.
- Набор не подменяет обучение роутингу предметным ответом и наоборот.

### Пример 1: OR-DB-ATOMIC-CLAIM-REF-01

Семейство: `v3-ref.or-db-atomic-claim.f01`.

**Вход:**

```text
Симуляция БД. Два worker одновременно обрабатывают ключ K. Гарантия: бизнес-запись разрешена только единственному владельцу K. В таблице ключ отсутствует. claim_unique делает атомарный INSERT с уникальностью K и возвращает выигрыш только одному; read_then_insert — раздельные чтение и запись без ограничения уникальности. Выбери следующий шаг JSON next_action из claim_unique, read_then_insert.
```

**Предпочтительный ответ:**

```json
{
  "next_action": "claim_unique"
}
```

**Правдоподобный ошибочный ответ:**

```json
{
  "next_action": "read_then_insert"
}
```

**Различающий факт:** Только claim_unique по явно заданному контракту выдаёт единственное владение при гонке.

**Контрпример / граница:** Если read_then_insert выполняется в одной корректно сериализованной транзакции с эквивалентной гарантией единственного владельца, предпочтение между этими способами без другого критерия исчезает; пару надо исключить.
