# E02 — Энтропия Шеннона и сжатие токенного потока
## Zstandard-сжатие vs plain uint16 shards
**Проект:** llm-mvp-core · **Этот документ не касается XIIGen.**

---

## Гипотеза
Sstandard сжимает хорошо то что предсказуемо.
Предсказуемость = низкая энтропия Шеннона: H = -Σ p_i × log2(p_i).

Гипотеза: замена BPE токенов кластерными id снижает энтропию на 30–50%
потому что ~40 вариантов равномернее распределены чем 2000.
Более низкая энтропия → лучшее сжатие → меньше диска.

Это единственный эксперимент без Марковской матрицы: достаточно посчитать энтропию.

## Что меняется

**Baseline (оригинал):** uint16 токены (BPE). Энтропия потока ~10–11 бит на токен. Сжатие Zstandard без словаря.

**Enhanced (улучшение):** Cluster id (0–49). Энтропия ~5–6 бит на токен. Sstandard со словарём обученным на проекте.

**Использует подпроекты:** 01.Tokenizer, 24.Compression (Zstandard), 14.MachineLearning (K-Means)

## Марковская реализация (Scale 0–2)

```csharp
// E02: нет Маркова — только энтропия Шеннона
static double ShannonEntropy(IReadOnlyList<int> tokens)
{
    var counts = new Dictionary<int,int>();
    foreach (var t in tokens) counts[t] = counts.GetValueOrDefault(t,0) + 1;
    double n = tokens.Count, h = 0;
    foreach (var c in counts.Values)
    { double p = c/n; h -= p * Math.Log2(p); }
    return h;  // бит на токен
}

// baseline:  ShannonEntropy(BpeTokenizer.EncodeToInts(text))
// enhanced:  ShannonEntropy(TokensToClusterIds(BpeTokenizer.EncodeToInts(text), clusters))
// затем: сжать оба потока Zstandard → сравнить размер файла
```

## Примечания по каждому уровню

**Scale 0:** BpeTokenizer.cs: подсчёт энтропии < 1 мс. Сжать оба потока → сравнить размер.

**Scale 1:** 01.Tokenizer: тот же подсчёт, больше данных. Проверяем стабильность.

**Scale 2:** 5 подпроектов: тренировать Zstandard-словарь на тренировочной части, сжимать тестовую.

**Scale 3:** Зонд: N/A — сжатие не зависит от нейросети. Переходим к Scale 4 напрямую.

**Scale 4:** Полный проект: измерить итоговый размер на диске. Это финальный тест для E02.

**Scale 5:** WikiText-103 C# подмножество: подтверждение на внешних данных.

## Альтернативный подход

Вместо K-Means кластеров использовать Huffman кодирование (подпроект 25): частые токены получают короткие коды — то же самое по сути но другой алгоритм.
