# E01 — AST узлы Roslyn вместо BPE токенов
## Отдельный план эксперимента · LlmFromScratch.sln

**ID:** E01-AST-TOKENIZER  
**Подпроект-источник:** 33.CodeCompletion (Уровень 1 — статический анализ)  
**Альтернативный подход учтён:** MICRO-EXPERIMENT-FRAMEWORK-v1 + RESEARCH-04 (унификация через перплексию)

---

## Гипотеза

Представление C# кода как последовательности типов AST-узлов (SyntaxKind, ~200 уникальных значений) вместо BPE токенов (подстрок кода, 500–2000 уникальных значений) делает задачу предсказания следующего токена проще: меньше вариантов выбора → выше точность при той же N-граммной модели.

Ключевое следствие из RESEARCH-04: если AST-словарь насыщается (перестаёт расти) быстрее чем BPE-словарь — это означает что модель тратит меньше ёмкости на «открытие» структуры кода.

---

## Что меняется

| Параметр | Baseline | Enhanced |
|---|---|---|
| Токенизатор | `BpeTokenizer` из подпроекта 01 | `CSharpSyntaxTree.ParseText` → `DescendantNodes()` → `node.Kind().ToString()` |
| Единица токена | Подстрока кода: `"public"`, `" bool"`, `"Validate"` | Тип узла: `"MethodDeclaration"`, `"PredefinedType"`, `"IdentifierName"` |
| Размер словаря | 500–2000 на типичном C# проекте | ~150–200 (все SyntaxKind значения C#) |
| Модель предсказания | 3-граммная модель на BPE токенах | 3-граммная модель на AST типах |

Измерение точности без нейросети (из MICRO-EXPERIMENT-FRAMEWORK):
```
1. Взять 100 случайных позиций в коде
2. Для каждой: взять 3 предыдущих токена (триграмм)
3. Найти все вхождения этого же триграмма в остальном коде
4. Предсказать следующий как самый частый после этого триграмма
5. Ошибка = доля позиций где предсказание не совпало с реальным
```

---

## Уникальная ось масштабирования: насыщение словаря

**Центральный вопрос этого эксперимента при росте датасета:** в какой момент AST-словарь перестаёт расти (насыщается), а BPE-словарь продолжает расти?

Если AST насыщается на Tier 2, а BPE насыщается только на Tier 4 — это означает, что AST-представление гораздо более компактное и обобщающее.

```
Метрика насыщения = (новые_уникальные_токены_на_этом_тире) / (все_уникальные_токены_до_этого_тира)

Значение 0.05 = 5% новых = близко к насыщению
Значение 0.50 = 50% новых = словарь ещё растёт быстро
```

## Лестница тиров

### Tier 1 — micro (< 5 секунд, < 60 МБ RAM)

**Датасет:** `01.Tokenizer` — 3 файла, ~197 строк, ~2 000 токенов BPE  
**Что проверяем:** работает ли принцип вообще?  
**Фокус:** разница в размере словаря (BPE vs AST)

Ожидаемый словарь BPE: 300–400 токенов  
Ожидаемый словарь AST: 50–80 типов узлов  
Ожидаемое улучшение точности 3-грамм: +15–25%  

Шаг перехода: prediction_error улучшился ≥5% → запускаем Tier 2

---

### Tier 2 — small (< 30 секунд, < 150 МБ RAM)

**Датасет:** 6 малых подпроектов — `01, 02, 05, 07, 09, 10` — ~47 файлов, ~9 100 токенов  
**Что проверяем:** насытился ли AST-словарь уже здесь?  
**Фокус:** метрика насыщения для обоих словарей

BPE словарь должен вырасти примерно пропорционально (×6 файлов → ~×3–4 новых токенов)  
AST словарь должен вырасти меньше (большинство типов узлов уже встретились на Tier 1)

Шаг перехода: метрика насыщения AST < 0.15 (словарь почти не растёт) → Tier 3

---

### Tier 3 — medium (< 2 минуты, < 300 МБ RAM)

**Датасет:** все 24 подпроекта — ~195 файлов, ~141 000 токенов  
**Что проверяем:** стабильно ли преимущество на полном проекте?  
**Фокус:** абсолютная точность предсказания + насыщение

Ожидаем: AST-словарь насытился (насыщение < 0.05), BPE ещё растёт  
Перплексия AST-модели должна оставаться ниже BPE-модели

Шаг перехода: улучшение accuracy стабильно ≥5% → Tier 4

---

### Tier 4 — external project (< 10 минут)

**Датасет:** внешний C# репозиторий (например, `dotnet/runtime` — выборка 500 файлов)  
**Что проверяем:** работает ли на незнакомом коде?  
**Фокус:** переносимость — насколько AST-словарь одного проекта помогает на другом

Ожидаем: AST-словарь полностью стабилен (те же ~150–200 типов, они определены грамматикой C#)  
BPE-словарь для нового проекта будет существенно отличаться

---

### Tier 5 — CodeSearchNet C# (часы, одноразово)

**Датасет:** CodeSearchNet C# subset — ~500 000 функций  
**Что проверяем:** финальное подтверждение  
**Фокус:** перплексия по всему корпусу (метрика из RESEARCH-04)

Ожидаем: AST-перплексия стабильно ниже BPE-перплексии
