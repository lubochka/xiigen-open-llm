# E05 — Иерархическое предсказание vs плоский softmax
## Двухуровневый Марков: сначала кластер, потом токен внутри
**Проект:** llm-mvp-core · **Этот документ не касается XIIGen.**

---

## Гипотеза
Предсказывать «1 из 2000» дорого. Но если разбить на два шага:
  Шаг 1: предсказать кластер (1 из 50) — дёшево, матрица 50×50
  Шаг 2: предсказать токен внутри кластера (1 из ~40) — дёшево, 50 матриц по 40×40

Суммарно: 2500 + 80000 = 82500 ячеек против 4000000 у плоского.
В 48 раз меньше памяти. Небольшая потеря точности (ошибка на Шаге 1 не исправляется).

Это Марковский аналог hierarchical softmax (используется в Word2Vec и языковых моделях).

---

## Нарастающие уровни нагрузки (Scale Ladder)

Каждый эксперимент проходит три уровня. Переход разрешён только если предыдущий дал ≥5% улучшения.

| Уровень | Название | Датасет | Время прогона | Инструмент |
|---|---|---|---|---|
| Scale 0 | Markov-micro | 1 файл (~1 000 токенов) | < 10 мс | Марковская цепь |
| Scale 1 | Markov-small | 1 подпроект (~9 000 токенов) | < 100 мс | Марковская цепь |
| Scale 2 | Markov-medium | 5 подпроектов (~45 000 токенов) | < 500 мс | Марковская цепь |
| Scale 3 | Probe-net | 1 подпроект + зонд-сеть 2L×64d | < 3 мин | Зонд-нейросеть |
| Scale 4 | Probe-medium | 5 подпроектов + зонд-сеть | < 15 мин | Зонд-нейросеть |
| Scale 5 | Full | Весь проект + трансформер | часы | Подпроекты 03+04 |

**Правило остановки:** если Scale N дал < 5% по всем метрикам — эксперимент помечается ABANDON.
Не запускаем следующий уровень зря.


---

## Что меняется

**Baseline (оригинал):** Одноуровневый Марков: одна матрица V×V. Нейросеть: полный softmax на всём словаре.

**Enhanced (улучшение):** Двухуровневый: matrix[cluster_prev → cluster_next] + matrix_within[cluster][token_prev → token_next].

**Использует подпроекты:** 01.Tokenizer, 14.MachineLearning (K-Means для кластеров)

---

## Марковская реализация (Scale 0–2)

```csharp
// E05: двухуровневое предсказание
// Уровень 1: предсказать кластер следующего токена
int clusterPrev = tokenToCluster[currentToken];
int predictedCluster = FindArgmax(clusterTransitionMatrix, clusterPrev, nClusters);

// Уровень 2: предсказать токен внутри предсказанного кластера
int predictedToken = FindArgmax(
    withinClusterMatrix[predictedCluster],
    currentToken,                         // или clusterPrev — зависит от реализации
    clusterMembers[predictedCluster].Count);

// Метрика: точность предсказания кластера (должна быть очень высокой)
//        + точность предсказания токена внутри кластера
//        × итоговая точность = произведение
```

## Примечания по каждому уровню

**Scale 0:** BpeTokenizer.cs: матрица кластеров 50×50 + 50 матриц по 40×40. Память: 82500 float vs 22500 float у baseline.

**Scale 1:** 01.Tokenizer: тест на 9100 токенах. Словарь ~400 → кластеры 50. Матрица 160000 vs 82500.

**Scale 2:** 5 подпроектов: словарь ~800. Матрица 640000 vs 82500. Экономия растёт с размером.

**Scale 3:** Зонд: hierarchical softmax в нейросети. Точность немного хуже, но в разы быстрее.

**Scale 4:** Зонд на 5 подпроектах: проверяем что потеря точности < 5%.

**Scale 5:** Полный трансформер: иерархический softmax на всём проекте.

## Альтернативный подход

PROGRESSIVE CURRICULUM: использовать иерархию динамически — на ранних шагах обучения предсказывать только кластеры, потом добавить второй уровень.

---

## Условие остановки (ABANDON)

Если потеря точности > 10% — кластеры слишком крупные (токены слишком разные внутри). Попробовать K=100 или K=200.
