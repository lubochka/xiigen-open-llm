## Основная гипотеза

Современные трансформеры работают на одном временно́м масштабе: каждый шаг обновляет веса на основе одного батча. Нет механизма который накапливает знание о состоянии системы через тысячи шагов и использует его для структурной перестройки.

Астроцитарная сеть в мозге делает именно это: работает на медленном таймскейле (секунды-минуты vs миллисекунды у нейронов) и управляет не информацией, а условиями её обработки — топологией, ресурсами, температурой.

Гипотеза: добавление медленного асинхронного слоя поверх трансформера, который наблюдает паттерны активации и обновляет топологию связей каждые K шагов, должно улучшить:
- Скорость сходимости (быстрее достигать целевой перплексии)
- Устойчивость при сдвиге распределения входных данных
- Сопротивление катастрофическому забыванию

## Что уже есть в проекте — пять частичных аналогов

Из анализа существующих компонентов:

| Компонент | Какую функцию астроцитов выполняет | Чего не хватает |
|---|---|---|
| Graph RAG (подпроект 08) | Соединяет семантически несвязанные регионы | Статичен, не обновляется во время инференса |
| PageRank (подпроект 07) | Глобальный сигнал важности узла | Статичен, не реагирует на текущую активность |
| Семантические объекты (кирпич A) | Структурное знание заложено заранее | Предзагружен, не адаптируется |
| Разреженная маска внимания (кирпич D) | Топология как параметр, а не веса | Фиксирована после обучения |
| K-Means семьи + иерархический softmax (кирпич F) | Маршрутизация вычислительных ресурсов | Нет медленного слоя наблюдателя |

**Общий вывод из предыдущего анализа:** ни один из этих компонентов не является настоящим астроцитарным слоем, потому что все они или статичны, или работают на том же временном масштабе что и основная сеть.

## Архитектура двух слоёв

```
┌──────────────────────────────────────────────────────┐
│  МЕДЛЕННЫЙ СЛОЙ (астроцитарный аналог)               │
│                                                       │
│  ActivationStatisticsMonitor                         │
│  ├── собирает статистику каждый шаг (cheaply)        │
│  ├── агрегирует по скользящим окнам 100/1000/10000   │
│  └── детектирует перегруженные и простаивающие головы│
│                                                       │
│  TopologyOptimizer                                   │
│  ├── каждые K шагов читает статистику                │
│  ├── обновляет граф связей (кто с кем говорит)       │
│  └── записывает новую CSR маску внимания             │
│                                                       │
│  DeprivationDetector                                 │
│  ├── отслеживает распределение концептуальных семей  │
│  └── перераспределяет ёмкость при отсутствии типа    │
└──────────────────┬───────────────────────────────────┘
                   │ topology mask (CSR) ↓
                   │ activation stats ↑
┌──────────────────▼───────────────────────────────────┐
│  БЫСТРЫЙ СЛОЙ (стандартный трансформер)              │
│                                                       │
│  Каждый токен, каждый шаг:                           │
│  ├── применяет маску внимания от медленного слоя     │
│  ├── forward pass → logits                           │
│  └── loss → backward → optimizer step               │
└──────────────────────────────────────────────────────┘
```

Ключевые принципы разделения:
- Медленный слой не видит токены — он видит паттерны активации (какие головы активны, какие нет)
- Быстрый слой не решает кто с кем говорит — эту структуру ему даёт медленный слой
- Обновление топологии происходит каждые K шагов, не каждый шаг (K = 100–1000)

### Фаза 2 — Динамическая маска внимания (первый настоящий шаг)

Самое важное изменение: маска внимания перестаёт быть фиксированной. Каждые K шагов `ActivationStatisticsMonitor` собирает статистику и `DynamicGraphMaskUpdater` перезаписывает CSR маску.

**Новые компоненты:**

```csharp
// ActivationStatisticsMonitor собирает lightweight статистику
// после каждого forward pass без существенного замедления обучения.
// Хранит скользящее среднее активности каждой головы внимания.
public class ActivationStatisticsMonitor : BaseService
{
    // Статистика для каждой головы: [layer_index, head_index] → среднее значение активации
    private readonly Dictionary<(int layer, int head), RunningAverage> headActivations = new();

    // Вызывается после каждого forward pass — дешёвая операция O(heads × seq)
    // attentionWeights — тензор весов внимания из последнего прогона [heads, seq, seq]
    // layerIndex — какой трансформерный блок только что отработал
    public OperationResult<bool> RecordStep(float[,,] attentionWeights, int layerIndex)
    {
        // Для каждой головы считаем среднее значение активации по всей матрице внимания
        // Голова с низким средним значением — простаивает и расходует вычисления впустую
        int headCount = attentionWeights.GetLength(0);
        for (int headIndex = 0; headIndex < headCount; headIndex++)
        {
            double meanActivation = ComputeMeanActivation(attentionWeights, headIndex);

            // Обновляем скользящее среднее для этой головы
            var key = (layerIndex, headIndex);
            if (!headActivations.ContainsKey(key))
                headActivations[key] = new RunningAverage(windowSize: 1000);

            headActivations[key].Update(meanActivation);
        }

        return OperationResult<bool>.Ok(true);
    }

    // Возвращает список голов которые были практически неактивны за последние N шагов
    // Эти головы — кандидаты на "отключение" или перенаправление в медленном слое
    public OperationResult<List<(int layer, int head)>> GetIdleHeads(
        double idleThreshold = 0.01)
    {
        var idleHeads = headActivations
            .Where(kv => kv.Value.CurrentAverage < idleThreshold)
            .Select(kv => kv.Key)
            .ToList();

        return OperationResult<List<(int layer, int head)>>.Ok(idleHeads);
    }
}
```

```csharp
// DynamicGraphMaskUpdater перезаписывает CSR маску внимания каждые K шагов
// на основе статистики активаций и текущего графа связей.
//
// Логика обновления:
//   1. Получить список простаивающих голов от ActivationStatisticsMonitor
//   2. Для каждой простаивающей головы — расширить её зону видимости
//      (разреженная голова которая мало что видит → дать ей видеть больше случайных позиций)
//   3. Для каждой перегруженной головы (высокая дисперсия активаций) — сузить зону
//      (она пытается охватить слишком много → сфокусировать на ближайших соседях)
//   4. Записать новую CSR маску и передать в трансформер
public class DynamicGraphMaskUpdater : BaseService
{
    private readonly ActivationStatisticsMonitor monitor;
    private readonly IGraphStorage graphStorage;          // граф из подпроекта 07

    // Обновить маску внимания на основе текущей статистики активаций
    // updateInterval — каждые сколько шагов вызывать эту функцию
    //   рекомендуемое значение: 100–500 шагов (1–5% от эпохи)
    public async Task<OperationResult<CsrSparseMatrix>> UpdateMaskAsync(
        int currentStep,
        int updateInterval,
        int sequenceLength)
    {
        // Проверяем наступил ли момент обновления
        if (currentStep % updateInterval != 0)
        {
            // Ещё не время обновлять — возвращаем null как сигнал "использовать текущую маску"
            return OperationResult<CsrSparseMatrix>.Ok(null!);
        }

        // Получаем список голов которые не работают и голов которые перегружены
        var idleHeads = (await monitor.GetIdleHeads(idleThreshold: 0.01)).Value!;
        var overloadedHeads = (await monitor.GetOverloadedHeads(varianceThreshold: 0.1)).Value!;

        // Строим новую маску: комбинируем локальное окно + граф соседей + случайные позиции
        // Простаивающие головы получают больше случайных позиций — "исследование"
        // Перегруженные головы получают только локальное окно — "фокус"
        var newMask = BuildAdaptiveMask(
            sequenceLength,
            idleHeads,
            overloadedHeads);

        return OperationResult<CsrSparseMatrix>.Ok(newMask);
    }
}
```

### Фаза 3 — Полный астроцитарный слой (медленный асинхронный оптимизатор)

Переход от "обновляем маску каждые K шагов" к "отдельный слой на другом временном масштабе".

Ключевое отличие от фазы 2: медленный слой запускается в отдельном потоке и не блокирует основной цикл обучения. Пока трансформер делает шаги 1–100, медленный слой анализирует накопленную статистику. На шаге 100 новая маска записывается атомарно.

**Новый компонент:**

```csharp
// AstrocyteLayer запускается асинхронно от основного цикла обучения.
// Основная задача: наблюдать, накапливать, обновлять топологию.
//
// Аналогия: нейроны обрабатывают сигнал (токены).
//           Астроциты управляют условиями существования сигнала (кто с кем говорит).
public class AstrocyteLayer : BaseService
{
    // Монитор который собирает статистику от каждого шага быстрого слоя
    private readonly ActivationStatisticsMonitor activationMonitor;

    // Обновлятель маски — решает как перестроить топологию
    private readonly DynamicGraphMaskUpdater maskUpdater;

    // Три скользящих окна разного масштаба:
    //   - Короткое (100 шагов): реагирует на последние изменения
    //   - Среднее (1000 шагов): выявляет устойчивые паттерны
    //   - Длинное (10000 шагов): хранит "долгосрочную память" системы
    private readonly TimeWindowAggregator shortWindow  = new(windowSize: 100);
    private readonly TimeWindowAggregator mediumWindow = new(windowSize: 1000);
    private readonly TimeWindowAggregator longWindow   = new(windowSize: 10000);

    // Запустить медленный слой в фоновом потоке
    // cancellationToken — останавливает когда обучение заканчивается
    public async Task RunAsync(
        Channel<ActivationSnapshot> snapshotChannel,
        Channel<CsrSparseMatrix> maskUpdateChannel,
        CancellationToken cancellationToken)
    {
        // Читаем снэпшоты активаций от быстрого слоя
        await foreach (var snapshot in snapshotChannel.Reader.ReadAllAsync(cancellationToken))
        {
            // Обновляем все три временны́х окна
            shortWindow.Update(snapshot);
            mediumWindow.Update(snapshot);
            longWindow.Update(snapshot);

            // Если достигли порога обновления топологии — вычислить новую маску
            if (ShouldUpdateTopology(snapshot.StepNumber))
            {
                var newMask = await ComputeNewTopology();

                // Атомарно записать новую маску в канал
                // Быстрый слой считает её на следующем шаге
                await maskUpdateChannel.Writer.WriteAsync(newMask, cancellationToken);
            }
        }
    }

    // Решить нужно ли обновлять топологию сейчас
    // Топология обновляется когда произошло значимое изменение в паттернах активации
    private bool ShouldUpdateTopology(int stepNumber)
    {
        // Минимальный интервал: каждые 100 шагов
        if (stepNumber % 100 != 0) return false;

        // Дополнительное условие: короткое окно отклонилось от длинного более чем на порог
        // Это означает что система сейчас в принципиально другом режиме чем раньше
        double divergence = ComputeWindowDivergence(shortWindow, longWindow);
        return divergence > 0.15;  // 15% расхождение считается значимым
    }
}
```

**Эксперимент 3A — Асинхронный слой vs синхронный:**

Сравниваем три конфигурации:
1. Маска фиксирована
2. Маска обновляется синхронно каждые K шагов (фаза 2)
3. Маска обновляется асинхронным слоем при обнаружении значимого изменения

Метрика: гибкость адаптации — насколько быстро перплексия восстанавливается после намеренного изменения распределения датасета на шаге 5000.

### Фаза 4 — Реакция на депривацию (самая новая часть)

Самый интересный эксперимент. Воспроизводит эксперимент с мышами: когда убирали входные данные определённого типа, астроцитарная сеть перестраивалась.

**Протокол депривации:**

Модифицировать WikiText-103 так чтобы определённые тематические кластеры (например: статьи о математике, или о спорте) отсутствовали в батчах с шага 5000 по шаг 15000. Потом вернуть их. Измерить:
- Как меняется маска внимания во время депривации?
- Восстанавливается ли качество быстро после возврата данных?

**Новый компонент:**

```csharp
// DeprivationDetector отслеживает распределение концептуальных семей во входных данных.
// Когда семья не появляется N шагов — это депривация.
// Реакция: перераспределить вычислительную ёмкость с депривированных голов на активные.
//
// Аналогия с экспериментом: подрезали усы мышам (депривация тактильного входа) →
//   астроциты перераспределили ресурсы от соматосенсорной зоны к другим зонам.
public class DeprivationDetector : BaseService
{
    // Для каждой концептуальной семьи — сколько шагов прошло с последнего появления
    private readonly Dictionary<string, int> stepsSinceLastSeen = new();

    // Порог: сколько шагов без семьи считается депривацией
    private const int DeprivationThresholdSteps = 500;

    // Записать появление концептуальных семей в текущем батче
    // conceptFamilies — список семей (из семантических объектов кирпича A)
    // currentStep — номер текущего обучающего шага
    public void RecordBatch(List<string> conceptFamilies, int currentStep)
    {
        // Для каждой появившейся семьи — обнулить счётчик
        foreach (var family in conceptFamilies)
        {
            stepsSinceLastSeen[family] = 0;
        }

        // Для всех остальных семей — увеличить счётчик отсутствия
        foreach (var family in stepsSinceLastSeen.Keys.ToList())
        {
            if (!conceptFamilies.Contains(family))
            {
                stepsSinceLastSeen[family]++;
            }
        }
    }

    // Вернуть список семей которые сейчас в состоянии депривации
    public OperationResult<List<string>> GetDeprivedFamilies()
    {
        var deprived = stepsSinceLastSeen
            .Where(kv => kv.Value > DeprivationThresholdSteps)
            .Select(kv => kv.Key)
            .ToList();

        return OperationResult<List<string>>.Ok(deprived);
    }
}
```

**Эксперимент 4A — Устойчивость к сдвигу распределения:**

Конфигурация:
- Датасет: WikiText-103, разбитый на тематические кластеры через K-Means (подпроект 14)
- Шаги 0–5000: обучение на полном датасете
- Шаги 5000–15000: депривация — убрать математический и компьютерный кластеры
- Шаги 15000–20000: вернуть все кластеры

Измерения в трёх конфигурациях:
1. Без астроцитарного слоя (базовая линия)
2. С астроцитарным слоем (динамическая маска, без депривации-реакции)
3. С полным астроцитарным слоем включая DeprivationDetector

| Метрика | Что показывает |
|---|---|
| Перплексия на деприванных кластерах в период депривации | Насколько модель "забывает" |
| Перплексия после возврата данных (шаги 15000–16000) | Насколько быстро восстанавливается |
| Активность голов в период депривации | Перераспределились ли ресурсы |

**Эксперимент 4B — Катастрофическое забывание:**

Стандартный тест: обучить на теме A, потом на теме B, проверить тему A.

Ожидание: с астроцитарным слоем деградация на теме A должна быть меньше, потому что:
- Медленный слой помнит паттерны темы A через длинное временно́е окно
- При обучении на теме B — головы отвечающие за тему A не полностью перезаписываются

```
ExperimentRunner/
└── AstrocytePipeline/
    ├── Monitoring/
    │   ├── ActivationStatisticsMonitor.cs  — сбор статистики каждый шаг
    │   ├── TimeWindowAggregator.cs         — три скользящих окна (100/1000/10000)
    │   ├── ActivationSnapshot.cs           — снэпшот одного шага для передачи в медленный слой
    │   └── RunningAverage.cs               — скользящее среднее для каждой головы
    ├── Topology/
    │   ├── DynamicGraphMaskUpdater.cs      — перезаписывает CSR маску на основе статистики
    │   ├── TopologyUpdateScheduler.cs      — решает когда обновлять (интервал vs расхождение)
    │   └── AdaptiveMaskBuilder.cs          — строит новую маску с разными радиусами для голов
    ├── SlowLayer/
    │   ├── AstrocyteLayer.cs               — асинхронный медленный слой
    │   ├── WindowDivergenceComputer.cs     — измеряет расхождение между временными окнами
    │   └── TopologyOptimizer.cs            — принимает решение о перестройке топологии
    ├── Deprivation/
    │   ├── DeprivationDetector.cs          — обнаруживает отсутствие концептуальных семей
    │   ├── CapacityReallocator.cs          — перераспределяет ёмкость голов при депривации
    │   └── DeprivationExperimentSetup.cs   — создаёт модифицированный датасет для теста
    └── Tests/
        ├── ActivationMonitorTests.cs
        ├── DynamicMaskTests.cs
        ├── AstrocyteLayerIntegrationTests.cs
        └── DeprivationExperimentTests.cs
```

| Фаза | Эксперимент | Ожидаемый результат | Если нет — что это значит |
|---|---|---|---|
| 1 | Граф-батчинг и энтропия голов | Ниже энтропия голов при граф-батчинге | Graph RAG не выполняет координационную функцию |

## Порядок реализации

**Первым делом — фаза 1:** инструментировать существующий код для сбора статистики активации. Это дешёво (один `.RecordStep()` вызов per forward pass) и сразу даёт данные для всех последующих экспериментов.

**Второй шаг — фаза 2:** `DynamicGraphMaskUpdater`. Это расширение уже реализованного кирпича D из X-01. Самая осязаемая проверка основной гипотезы.

**Третий шаг — фаза 4 (депривация):** раньше фазы 3, потому что это наиболее конкретный и верифицируемый эксперимент. Датасет с депривацией легко создать, результат легко измерить.

**Последним — фаза 3 (полный асинхронный слой):** самая сложная инженерно — требует корректной синхронизации между потоками. Реализовывать только если фазы 1–2 показали положительные результаты.

## Почему это важно за пределами этого проекта

Настоящий астроцитарный слой — это первый шаг к **гомеостазу** в ИИ системах. Существующие модели не знают ничего о своём собственном состоянии: они не замечают что "устали", не видят что один модуль перегружен, не чувствуют что давно не получали определённый тип данных.

Медленный слой который накапливает глобальное состояние системы через тысячи шагов и использует его для структурной перестройки — это архитектурный примитив которого пока нет ни в одном опубликованном подходе.

Если эксперименты подтвердят даже часть гипотез — это готовый материал для статьи.
