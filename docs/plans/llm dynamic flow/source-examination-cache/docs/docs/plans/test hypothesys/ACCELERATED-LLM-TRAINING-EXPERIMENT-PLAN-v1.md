**Цель:** протестировать шесть способов ускорить и улучшить обучение языковой модели, комбинируя уже реализованные подпроекты

## Главная гипотеза

Стандартный BPE токенизатор (подпроект 01) производит токены которые несут статистическую информацию о совместной встречаемости, но не несут семантической структуры. Модель вынуждена заново "открывать" эту структуру через миллиарды шагов обучения.

Если заменить плоские BPE токены на структурированные объекты которые уже несут семантику, граф связей, и информацию о роли — модель начинает с более богатого представления данных. Гипотеза: это должно ускорить обучение и уменьшить требования к хранению без потери качества.

## Описание шести экспериментальных подходов ("кирпичи Lego")

### Кирпич A — Семантические объекты вместо BPE токенов

**Что делает:** вместо BPE токенов (которые разбивают слова по статистической совместной встречаемости байтов) — преобразовать каждый токен в структурированный объект с семантическими аннотациями из подпроектов 28S–31S.

**Структура семантического токен-объекта:**
```
BPE токен:  [4821]  "attack"

Семантический объект:
{
  bpe_id:          4821,
  original_text:   "attack",
  frame_family:    "Attack"            (FrameNet: событие нападения)
  semantic_role:   "Action"            (SRL: это действие, не агент и не пациент)
  synset_id:       "attack.v.01"       (WordNet: физическое нападение)
  amr_concept:     "attack-01"         (AMR: концепт атаки)
  ud_pos:          "VERB"              (Universal Dependencies: глагол)
  cluster_id:      47                  (K-Means кластер: слова насилия)
  pagerank_score:  0.0034              (важность узла в графе знаний)
}
```

**Подпроекты:** 01 (BPE), 28S (FrameNet), 29S (SRL), 30S (WordNet), 31S (AMR), 14 (K-Means), 07 (PageRank)

**Как используется при обучении:** объект сериализуется в фиксированный числовой вектор фиксированной размерности. Embedding слой принимает этот вектор вместо одного целого числа. Это даёт модели семантическую структуру с первого шага обучения.

### Кирпич B — Graph RAG хранение датасета вместо плоских шардов

**Что делает:** вместо плоских uint16 массивов (подпроект 02) — хранить датасет как граф знаний (подпроект 08) где каждый токен является узлом, рёбра несут лингвистические связи, и векторный поиск позволяет находить контекстуально похожие примеры для батча.

**Преимущество:** во время обучения батч формируется не случайно, а по семантической близости — модель видит похожие примеры рядом. Это похоже на curriculum learning (обучение с куррикулумом — сначала простые примеры, потом сложные).

**Как строится граф датасета:**
```
Узлы:    каждое предложение из WikiText-103 → узел в графе
Рёбра:
  - "same_topic":   предложения из одной статьи Вики
  - "same_frame":   предложения с одинаковыми FrameNet фреймами  
  - "similar_vec":  HNSW поиск по эмбеддингу предложения (top-5 соседей)
  - "sequential":   следующее/предыдущее предложение в статье
```

**Подпроекты:** 08 (Graph RAG), 05 (Embeddings), 06 (HNSW), 07 (Graph Engine)

### Кирпич C — Алгоритмы компрессии для хранения токенов и весов

**Что делает:** применить алгоритмы сжатия из подпроектов 24–27 на двух уровнях:
1. Датасет: токенные шарды сжимаются LZ4 (быстро, 3–5×) или Zstandard с обученным словарём (медленнее, 5–8×)
2. Контрольные точки: веса модели сжимаются после каждой эпохи

**Интеграция со структурными токенами (кирпич A):** структурированные токен-объекты лучше сжимаются чем случайные BPE числа — семантически близкие объекты имеют похожую структуру, что LZ77 и BWT умеют отлично сжимать.

**Подпроекты:** 24 (LZ4/Snappy), 25 (Huffman/rANS), 26 (BWT+MTF+RLE), 27 (Zstandard)

### Кирпич D — Разреженные матрицы внимания

**Что делает:** стандартный механизм внимания (attention) имеет сложность O(n²) по числу токенов — каждый токен смотрит на каждый другой. Если знать заранее какие токены связаны (из графа связей кирпича B) — можно сделать разреженную матрицу внимания: каждый токен смотрит только на свои K ближайших соседей плюс несколько случайных.

**Как строится разреженная маска внимания:**
```
Для токена T на позиции i:
  1. Граф соседей: смотрит на все токены с рёбрами в графе датасета (из кирпича B)
  2. Локальное окно: смотрит на 32 ближайших токена по позиции
  3. Случайные: 8 случайных токенов из всей последовательности
  
Итого ~50 просматриваемых токенов вместо 512 — в 10 раз меньше операций внимания.
Матрица внимания 512×512 → разреженная CSR матрица с 50×512 ненулевыми элементами.
Экономия вычислений: ~10× на внимание, ~2–3× на всю итерацию.
```

**Подпроекты:** 28M (Sparse CSR matrix), 07 (граф для маски)

### Кирпич E — Усечённое SVD для инициализации и периодической компрессии весов

**Что делает:** два применения матричного разложения:
1. Инициализация: вместо случайной инициализации весов — инициализировать через усечённое SVD заранее вычисленной матрицы статистики совместной встречаемости токенов (PMI matrix — Pointwise Mutual Information)
2. Периодическая компрессия: каждые 1000 шагов применять усечённое SVD к весовым матрицам и заменять их аппроксимацией ранга K. Это одновременно сжимает модель и убирает "шум" из весов.

**Гипотеза для инициализации:** PMI матрица уже кодирует статистические связи слов (аналогично GloVe embeddings). Начать с неё вместо случайной инициализации должно ускорить первые эпохи обучения.

**Подпроекты:** 28M (Truncated SVD), 19 (PCA для PMI матрицы), 30M (Weight SVD Compressor)

---

### Кирпич F — Ассоциативные правила и K-Means для формирования семей токенов

**Что делает:** "скомпилировать" токены в семьи используя два подхода:
1. K-Means: сгруппировать все 50,000 BPE токенов в 5,000 кластеров по их эмбеддинговому вектору. Каждый кластер — одна "семья". При обучении модель предсказывает сначала семью (1 из 5,000) потом конкретный токен внутри семьи (1 из ~10). Это иерархическая softmax.
2. Apriori: найти токены которые всегда встречаются вместе (например "New York", "machine learning") и объединить их в один мета-токен. Уменьшает длину последовательностей.

**Подпроекты:** 14 (K-Means), 18 (Apriori), 05 (Embeddings для вычисления расстояний)

### Эксперимент 0 — Базовая линия (стандартное обучение)

**Конфигурация:**
- Токенизатор: BPE (подпроект 01), размер словаря 50,257 токенов
- Хранение датасета: плоские uint16 шарды (подпроект 02)
- Архитектура: стандартный трансформер GPT-2 стиль (подпроект 03)
- Матричные операции: TensorCore (подпроект 00) — плотные матрицы
- Хранение весов: необработанные float32 тензоры

**Метрики (ожидаемые на WikiText-103):**

| Метрика | Ожидаемое значение | Как измерить |
|---|---|---|
| Потеря после 1 эпохи | 4.2–4.5 (cross-entropy) | `loss` на тренировочном множестве |
| Потеря после 5 эпох | 3.4–3.7 | `loss` на тренировочном множестве |
| Перплексия на тесте (WikiText-103 test) | 80–120 | `exp(среднее loss)` на тестовом множестве |
| Токенов в секунду при обучении | 50,000–80,000 | измеряется в первые 100 шагов |
| Размер датасета на диске | 450 МБ (uint16 токены) | `du -sh` |
| Размер контрольной точки (checkpoint) | 200 МБ | `du -sh` |
| Время 1 эпохи (1 GPU или CPU) | 4–6 часов | `time` |

**Базовый код C# для измерения:**
```csharp
// ExperimentBaseline запускает стандартное обучение и записывает все метрики.
// Это контрольная точка — все эксперименты сравниваются с этим результатом.
public class ExperimentBaseline : BaseService
{
    // Запустить полное обучение и вернуть итоговые метрики
    // datasetPath — путь к WikiText-103 (скачанный, разбитый на train/valid/test)
    // epochCount  — количество эпох (5 для полного сравнения, 1 для быстрой проверки)
    public async Task<OperationResult<ExperimentMetrics>> RunAsync(
        string datasetPath,
        int epochCount = 5)
    {
        var metrics = new ExperimentMetrics
        {
            ExperimentName = "Baseline — BPE + standard Transformer",
            // Запись метрик происходит в методах ниже
        };

        // Шаг 1: токенизировать датасет стандартным BPE токенизатором
        var tokenizeStart = DateTime.UtcNow;
        var tokenizeResult = await RunBpeTokenization(datasetPath);
        metrics.TokenizationTimeSeconds = (DateTime.UtcNow - tokenizeStart).TotalSeconds;
        metrics.DatasetSizeOnDiskMegabytes = GetDatasetSizeMb(tokenizeResult.ShardDirectory);
        metrics.VocabularySize = 50_257; // стандартный GPT-2 размер словаря

        // Шаг 2: обучить модель и записывать потерю после каждой эпохи
        var trainStart = DateTime.UtcNow;
        var lossHistory = await RunTrainingLoop(tokenizeResult, epochCount, metrics);
        metrics.TotalTrainingTimeSeconds = (DateTime.UtcNow - trainStart).TotalSeconds;
        metrics.LossAfterEachEpoch = lossHistory;

        // Шаг 3: оценить на тестовом множестве
        metrics.TestPerplexity = await EvaluatePerplexity(tokenizeResult.TestShardPath);
        metrics.CheckpointSizeMegabytes = GetCheckpointSizeMb();

        return OperationResult<ExperimentMetrics>.Ok(metrics);
    }
}
```

### Эксперимент A — Семантические объект-токены (кирпич A)

**Что меняется:** только шаг токенизации. Всё остальное такое же как в базовой линии.

**Конфигурация:**
- Токенизатор: BPE → + FrameNet фрейм + SRL роль + K-Means кластер
- Размер расширенного "токен-вектора": 512 бит = [bpe_id: 17 бит] + [frame_id: 12 бит] + [role_id: 8 бит] + [cluster_id: 13 бит] + [ud_pos: 6 бит] = 56 бит → округляем до 4 × float32 = 16 байт на токен
- Embedding слой: принимает вектор размерностью 4 вместо одного числа, проецирует в 512 измерений модели
- Хранение: структурные объекты ~16 байт × 103M токенов = 1.65 ГБ (vs 206 МБ для BPE uint16)

**Ожидаемые результаты:**

| Метрика | Базовая линия | Ожидаемое в эксперименте A | Обоснование |

| Потеря после 5 эпох | 3.4–3.7 | 3.2–3.5 | лучшее начальное представление |
| Перплексия на тесте | 80–120 | 65–95 | семантические связи помогают |
| Время токенизации | 10 мин | 3–4 часа | нужно прогнать через FrameNet/SRL |

**Тест корректности:** обученная модель эксперимента A должна давать более осмысленные ответы на вопросы требующие понимания семантических ролей (кто делает что кому) — измеряется на WinoGrad Schema Challenge.

### Эксперимент D — Разреженные матрицы внимания (кирпич D)

**Что меняется:** архитектура attention механизма.

**Конфигурация:**
- Матрица внимания: CSR разреженная (подпроект 29M) вместо плотной
- Маска внимания: каждый токен видит 32 локальных + 8 random + соседей по графу
- Вычисление: вместо `Q @ K.T` (n²) — умножение разреженной матрицы на вектор (n × k)
- Остальное: базовая линия

**Ожидаемые результаты:**

| Метрика | Базовая линия | Ожидаемое в эксперименте D | Обоснование |
|---|---|---|---|
| Потеря после 1 эпохи | 4.2–4.5 | 4.4–4.7 | разреженность снижает точность |
| Потеря после 5 эпох | 3.4–3.7 | 3.5–3.9 | чуть хуже по качеству |
| Токенов в секунду | 50,000–80,000 | 120,000–200,000 | ~2.5× ускорение |
| Время 1 эпохи | 4–6 часов | 1.5–2.5 часа | основной выигрыш в скорости |
| Использование памяти | 12 ГБ | 4–6 ГБ | разреженная матрица = меньше памяти |
| Потеря в длинном контексте | хорошо | хуже | модель не видит далёкие токены |

**Ключевой вопрос:** потеря ~0.1–0.2 в quality — стоит ли 2.5× ускорения? Для большинства задач — да.

---

### Эксперимент E — SVD инициализация + периодическая SVD компрессия весов (кирпич E)

**Что меняется:** инициализация весов и периодическая компрессия.

**Конфигурация:**
- Инициализация: веса embedding слоя инициализируются через усечённое SVD матрицы PMI (Pointwise Mutual Information — поточечная взаимная информация, мера силы ассоциации между токенами)
- Периодическая компрессия: каждые 1000 шагов — усечённое SVD ранга 128 на все матрицы Q, K, V в attention (подпроект 28M, 30M)
- После компрессии: веса заменяются на аппроксимацию, обучение продолжается

**Ожидаемые результаты:**

| Метрика | Базовая линия | Ожидаемое в эксперименте E | Обоснование |
|---|---|---|---|
| Потеря после 1 эпохи | 4.2–4.5 | 3.7–4.0 | хорошая инициализация даёт старт |
| Потеря после 5 эпох | 3.4–3.7 | 3.3–3.6 | лучше или сравнимо |
| Время на вычисление PMI матрицы | — | 20–40 мин | единоразово на датасете |
| Оверхед SVD каждые 1000 шагов | — | +3–5% времени | операция быстрая, веса небольшие |
| Размер модели после компрессии | 200 МБ | 60–80 МБ | SVD сжимает Q/K/V матрицы 3–4× |
| Качество инференса после компрессии | базовая | -1.5% перплексии | небольшая потеря при 3× сжатии |

**Ключевой вопрос:** SVD инициализация через PMI — это по сути GloVe/Word2Vec стиль. Ускоряет ли это первые эпохи значимо?

### Эксперимент F — Иерархические семьи токенов (кирпич F)

**Что меняется:** размер словаря и структура предсказания.

**Конфигурация:**
- K-Means кластеризует 50,257 BPE токенов в 5,000 семей (подпроект 14)
- Apriori находит ~2,000 частых мета-токенов (подпроект 18): "New_York", "machine_learning", "in_the"
- Финальный словарь: 5,000 семей × 10 токенов в семье = иерархическое предсказание
- Предсказание: сначала softmax по 5,000 (семья), потом softmax по ~10 (токен внутри семьи)
- Длина последовательности: Apriori мета-токены сокращают длину на 15–25%

**Ожидаемые результаты:**

| Метрика | Базовая линия | Ожидаемое в эксперименте F | Обоснование |
|---|---|---|---|
| Потеря после 5 эпох | 3.4–3.7 | 3.5–3.8 | иерархия немного хуже flat |
| Токенов в секунду | 50,000–80,000 | 90,000–130,000 | короче последовательности |
| Время 1 эпохи | 4–6 часов | 2.5–4 часа | ~1.5× ускорение |
| Время на кластеризацию (K-Means) | — | 30–60 мин | единоразово |
| Длина последовательности | 512 токенов | 380–440 токенов | мета-токены сокращают |
| Размер softmax слоя | 200 МБ | 40 МБ | 5000 классов вместо 50257 |

### Эксперимент G — Комбинация всех кирпичей (A+B+D+E+F)

**Что меняется:** всё одновременно.

**Конфигурация:**
- Токены: семантические объекты (A) + иерархические семьи (F)
- Хранение: Graph RAG (B) + Zstandard сжатие (C)
- Архитектура: разреженное внимание (D) + SVD компрессия весов (E)

**Ожидаемые результаты:**

| Размер датасета | 450 МБ | 400–600 МБ | A увеличивает, C уменьшает |
| Размер модели | 200 МБ | 50–70 МБ | E+F сильно сжимают |

### Структура ExperimentMetrics

```csharp
// ExperimentMetrics содержит все измерения одного эксперимента.
// Записывается во время и после обучения — не post-hoc.
public record ExperimentMetrics
{
    // Название эксперимента для отчётов
    public required string ExperimentName { get; init; }

    // Когда начался и закончился эксперимент (UTC)
    public DateTime StartedAt { get; init; }
    public DateTime FinishedAt { get; init; }

    // --- КАЧЕСТВО МОДЕЛИ ---

    // Потеря на тренировочном множестве после каждой эпохи
    // lossHistory[0] = потеря после 1 эпохи, lossHistory[4] = после 5 эпох
    public List<double> LossAfterEachEpoch { get; init; } = new();

    // Перплексия на тестовом множестве WikiText-103 после финального обучения
    // Более низкая перплексия = лучше (модель лучше предсказывает следующий токен)
    public double TestPerplexity { get; init; }

    // --- СКОРОСТЬ ---

    // Среднее количество токенов обработанных в секунду во время обучения
    // (измеряется на шагах 100–200 чтобы исключить прогрев JIT компилятора)
    public double AverageTokensPerSecond { get; init; }

    // Полное время токенизации датасета в секундах (единоразовая операция)
    public double TokenizationTimeSeconds { get; init; }

    // Полное время обучения всех эпох в секундах
    public double TotalTrainingTimeSeconds { get; init; }

    // --- ХРАНЕНИЕ ---

    // Размер всего датасета на диске после токенизации (мегабайты)
    public double DatasetSizeOnDiskMegabytes { get; init; }

    // Размер финальной контрольной точки модели (мегабайты)
    public double CheckpointSizeMegabytes { get; init; }

    // Пиковое использование оперативной памяти во время обучения (гигабайты)
    public double PeakMemoryUsageGigabytes { get; init; }

    // --- ДОПОЛНИТЕЛЬНЫЕ ХАРАКТЕРИСТИКИ ---

    // Размер словаря токенов
    public int VocabularySize { get; init; }

    // Средняя длина последовательности в токенах после токенизации
    public double AverageSequenceLength { get; init; }

    // Коэффициент сжатия датасета (1.0 = нет сжатия, 4.0 = в 4 раза меньше)
    public double DatasetCompressionRatio { get; init; }

    // Коэффициент сжатия модели относительно baseline (1.0 = такая же как baseline)
    public double ModelCompressionRatio { get; init; }
}
```

## Порядок запуска экспериментов и рекомендации

### Рекомендуемый порядок (от простого к сложному)

1. **Сначала запустить C (Compression)** — нулевой риск деградации качества, сразу получаем 3–5× сжатие хранилища. Хорошая точка начала.

2. **Затем D (Sparse Attention)** — даёт 2.5× ускорение, небольшая потеря качества. Позволяет быстрее итерировать остальные эксперименты.

3. **Затем F (Token Families)** — K-Means кластеризация — простая операция. Ускорение 1.5× без сложного пайплайна.

4. **Затем A (Semantic Tokens)** — сложнее в реализации, требует FrameNet/SRL разметки, но даёт лучший прирост качества.

5. **Затем E (SVD)** — требует предварительного вычисления PMI матрицы.

6. **Затем B (Graph RAG)** — самый сложный в отладке, требует полного пайплайна.

7. **Наконец G (Combined)** — только после того как все отдельные эксперименты дали стабильные результаты.

## Дополнительные тесты для проверки гипотез

### Тест 1 — Семантическое понимание vs перплексия

**Проблема:** перплексия измеряет предсказание следующего токена, но не понимание смысла. Эксперименты A и B могут улучшить понимание без улучшения перплексии.

**Дополнительные метрики:**
- Winograd Schema Challenge (WinoGrad — тест на разрешение местоименных ссылок требующее здравого смысла): ожидаем +5–10% у эксперимента A vs baseline
- Simple Question Answering на WikiText: ожидаем +3–8% у эксперимента B
- Cloze test (восстановление пропущенных слов): стандартно

### Тест 2 — Стабильность обучения при малом объёме данных

WikiText-103 большой. Тест на малых данных (10,000 статей вместо 103M токенов):
- Ожидаем: эксперимент A (семантика) должен значительно лучше работать с малыми данными
- Эксперимент B (Graph RAG) должен помочь с few-shot за счёт умного батчинга

### Тест 3 — Время достижения целевой перплексии

Вместо фиксированного числа эпох — замерить сколько времени нужно каждому эксперименту чтобы достичь перплексии 100:
