## Как устроено / работает (кратко)

Два легитимных PASS-состояния (CLAUDE.md «Untrained honesty vs trained readiness», OP-56/57) проверяются разными тестами:

1) Честность НЕобученного (`PASS_AS_HONEST_UNTRAINED_SCAFFOLD`). `PromptToTaskMachineSkeletonTests`: пустая `new PromptToTaskMachine().Translate(...)` обязана вернуть `IsSuccess=true`, но `ContractStatus == NotTrainedStatus`, `TaskType == NotReadyTaskType`, evidence содержит `NO_TRAINED_STATE_LOADED` и `NO_SEMANTIC_CLASSIFICATION_PERFORMED`; `ExplicitUserRequirements`/`Deliverables` пусты (никакой семантики). Отдельный тест рефлексией доказывает ОТСУТСТВИЕ скрытого детерминизма: в типе нет полей `Regex`/`Dictionary` и членов `Classifier`/`Trainer`/`Lookup`/`Bm25`/`ExactPrompt`. То есть «необученность» тестируется как честный отказ + запрет shortcut, а не как фича.

2) Приёмка ОБУЧЕННОГО (`PASS_AS_TRAINED_FEATURE`). `SkillSelectionPhase06TrainedSelectorEvidenceTests` — эталон: строит `LearningBatch<SkillSelectionDomain>` + source-disjoint `LearningEvaluationSet`, гоняет `EvaluateAsync` на ПУСТОЙ машине (baseline) и на обученной, требует `evalResult.PassesGate` и `Accuracy`/`RewardMargin`; затем `SaveCheckpointAsync`→`ImportAsync`→`LoadCheckpointAsync` (fresh-load) и проверяет `freshEval.Accuracy == evalResult.Accuracy` (загрузка без переобучения). Ablation/анти-leakage: дельта accuracy обученная−пустая; инвариантность к порядку кандидатов (`EvaluateCandidateOrderLeakage`, реверс `AvailableSkillIds`), запрет `CandidatePositionScaffoldEvidence` в решении, негативный контроль «только source/pair id» (`SelectedFromSourceIdOnly` обязан быть false). Пишет полный evidence-пакет (~22 файла: checkpoint+manifest, train/heldout/positive-negative JSONL, export-import-fresh-load, leakage-ablation, model-lifecycle, code-review cycles, RU completion-report).

3) Held-out + ablation как отдельные раннеры. `PromptToTaskP7EvalAblationTests`: грузит P6 baseline через `LoadCheckpointAsync(checkpoint, manifest)`, оценивает ТОЛЬКО зарезервированные eval/holdout строки (assert `UsedForTrainingInP6=false`), и для каждой строки гоняет ~6 негативных контролей (`exact_prompt_lookup`, `filename_path_title_shortcut`, `keyword_only_classifier`, `source_family_id_shortcut`, `nearest_only_retrieval_only`, + label-shortcut). Ключевой паттерн: тест честно ассертит `p7Pass == false` (нет генерализации без обучения на этих строках) — FAIL фиксируется как правда, а не маскируется. `Learn06HeldOutAblationRunnerTests`: 3 трека (OrchestrationReasoning через публичную `LoadCheckpointAsync`+`Plan`; PromptToTask/SkillSelection — overlay-only, помечены `PARTIAL_NOT_FULL_MACHINE_EVAL`) с 5 именованными контролями: `exact_prompt_replay`, `path_title_source_id_leakage`, `nearest_neighbor_memorization`, `no_trained_state_baseline`, `shuffled_chosen_rejected`. Контроль `no_trained_state_baseline` сравнивает поведение загруженной модели с `new OrchestrationReasoningMachine()` — прямая проверка, что результат идёт от обученного state, а не от детерминированного fallback. Везде явно `SemanticQualityClaimed=false`, `CommonModelMutated=false`, разделение «What this proves / does not prove».

4) DPO-метрики низкого уровня. `DpoTrainerTests`: `DpoMetrics.RewardMargin == ChosenReward − RejectedReward`; `Accuracy ∈ {0,1}` и `=1 ⇔ margin>0`; `Loss>0` и не NaN; атомарная запись `dpo_step_NNNNNN.json` (нет `.tmp`); `StepMany` с копией reference-модели реально УЛУЧШАЕТ reward margin на повторяемом предпочтении (`trained.RewardMargin > initial + 1e-5`, initial==0). Это доказывает, что DPO-сигнал действительно учится, а не статичен.

## Релевантность к ILearningDynamicGraph (DPO / обучение / граф / оркестрация / измерение / teacher-provenance)

Очень высокая для axes «обучение/DPO/измерение/честность», средняя для «граф/оркестрация», нулевая для «teacher-provenance».
- DPO авто-построение: `SkillSelectionPhase06...` и `PromptToTaskP7...` дают готовый шаблон строки датасета — `chosen/rejected` + `SourcePromptEntryId` (source-disjoint), и явный список `ForbiddenSignals` (`candidate_position, source_id, pair_id, file_path, exact_prompt_replay`). Для DynamicGraph это прямой образец, как запрещать leakage-сигналы на рёбрах.
- Измерение/приёмка узла графа: тройка gate — held-out source-disjoint accuracy/`PassesGate` + ablation (5 именованных контролей) + lifecycle (export/import/fresh-load/continue). Это и есть «приёмка обученного» для любого ILearningUnit/Flow/Orchestrator в графе.
- Честность необученного узла: skeleton-паттерн (`NotTrainedStatus` + рефлексия «нет Dictionary/Regex/Classifier») — готовый шаблон теста «честный not_ready» для свежесозданного узла графа до обучения.
- Граф/рёбра: прямого DynamicGraph-теста среди прочитанных НЕТ; ближайшее — `OrchestrationReasoningMachine.Plan` (выбор learned-паттернов) как одиночное ребро решения. Скил `trainable-architecture-decision-SKILL.md` «Graph-Style / DynamicGraph Reconstruction Gate» требует на каждом ребре назвать владельца финального авторитета и привязать hidden-shortcut проверку к ребру — тесты `Learn06`/`Phase06` уже реализуют эту проверку (no_trained_state_baseline, candidate-order, source-id-only), но на уровне машины, не графа. Для плана: эти контроли надо тиражировать per-edge.
- teacher-provenance (legal teacher): среди прочитанных тестов проверок `teacher_access_mode`/`model_license`/`closed_proprietary_model` НЕТ (см. Пробелы).

## Классификация (уровень ILearningMachine vs детерминистический хелпер)

- `PromptToTaskMachine`, `OrchestrationReasoningMachine`, `SkillSelectionMachine` (в `43.SmartSkillsDomain`) — уровень **ILearningMachine\<TDomain\>** (Level 5). Доказательство в тестах: `SkillSelectionPhase06...` вызывает `LearningBatch<SkillSelectionDomain>`, `EvaluateAsync(LearningEvaluationSet<...>)`, `SaveCheckpointAsync`, `ImportAsync`, `LoadCheckpointAsync`, `GetOrchestratorAsync→SkillSelectionLogicalOrchestrator→...Flow→...Unit`. Соответствует allowed-levels из `trainable-architecture-decision-SKILL.md` (Decision Procedure шаг 4). Вердикт скила: `OK_ALLOWED_LEVEL`.
- `DpoTrainer` (`DPO`), `DpoMetrics`, `DpoBatch` — НЕ архитектурный уровень, это **внутренний обучающий механизм/компонент** трансформерной модели (training update + метрики). По скилу — «implementation detail внутри allowed level»; честно помечен как low-level trainer, не выдаёт себя за семантический юнит. Вердикт: `OK_INTERNAL_DETAIL` / `OK_MODEL_COMPONENT`.
- Counter/KNN/candidate-position в `SkillSelectionMachine` — по тестам трактуются как **внутренний baseline/support evidence**, НЕ финальный авторитет: `leakage-ablation-report` фиксирует `HiddenDeterministicShortcutAudit=PASS...` и `BaselineInternalBoundary: Counter and nearest structures remain internal/support evidence; semantic_quality_claimed=false`. Это ровно тот разбор «детерминированный хелпер → eval-only/baseline» из скила (шаг 6). `CandidateOrderLeakageGuardUnit`-подобная логика присутствует как guard (`EvaluateCandidateOrderLeakage`) — пример из скила реализован.
- Тестовые `Learn06Track/Learn06Control`, `P7EvalResult/P7AblationResult` — это **записи-evidence (record-DTO)** внутри тестов, не архитектура.

Граница «детерминированное vs обученное» (скил, Graph Gate): тесты доказывают её через `no_trained_state_baseline` (пустая машина не должна давать learned-результат) и инвариантность к порядку/source-id. Для DynamicGraph-плана это нужно перенести на каждое ребро.
