## Global Same-Scenario Rule

Path A and Path B prove the same scenario only when all of these are true:

1. Both paths carry the same `scenarioId`.
2. Both paths carry the same route-specific equality tuple listed below.
3. Both paths use the same input content hash, not just the same label or marker.
4. Both paths carry the same source unit/path reference, or an explicit `source_path_not_applicable` sentinel with a reason.
5. Both paths assert the same expected output artifact ids and the same expected behavior.
6. Both paths carry the same provenance sidecar refs, legal verdict, and redaction policy refs.
7. Both paths use the same `runId` convention and record comparable `capturedAtUtc` / `executedAtUtc` timestamps for that run.

A `correlationId` or screenshot marker alone is not enough. The join must compare input fixture, route contract, expected result, visible host state, and legal/provenance verdict.

Readiness and scenario coverage are accepted only when Path A and Path B both pass and the join file reports `sameScenarioEquality.matched=true` for the same tuple.
