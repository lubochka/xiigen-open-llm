## B37-L3-004-001 — Teaching: "structure" fires ARCHITECTURE in any context

**Core concept:** "structure" → ARCHITECTURE fires ALWAYS. No context override.

**Why this matters in B37:**
Project governance, organizational design, and RACI frameworks all involve "structure" in a purely human/organizational sense. Yet every occurrence of "structure" in a B37 sentence fires ARCHITECTURE.

**Teaching pair:**
Q: "The escalation structure needs clarification." — does ARCHITECTURE fire?
A: Yes. "structure" → ARCHITECTURE. Always.

Q: "Define the org structure for the programme." — what predicates fire?
A: ARCHITECTURE (structure) + DOCUMENT (define). ["ARCHITECTURE", "DOCUMENT"].

Q: "Create a reporting structure diagram." — what fires?
A: IMPLEMENT (create) + ARCHITECTURE (structure). ["IMPLEMENT", "ARCHITECTURE"].

## B37-L3-004-005 — Teaching: suppression is never the answer

**Wrong:** "Because 'accountability structure' is organizational, not software architectural, ARCHITECTURE should not fire."
**Correct:** ARCHITECTURE fires. Gap warning added. No suppression.

**The three suppression prohibitions in B37:**
1. Do NOT suppress DOCUMENT for "stakeholder" in managing context (Rule 6)
2. Do NOT suppress ARCHITECTURE for "structure" in governance context (Rule 7)
3. Do NOT suppress any predicate for managing intent vocabulary (all Rules)

Suppression always creates a v6 corruption.
