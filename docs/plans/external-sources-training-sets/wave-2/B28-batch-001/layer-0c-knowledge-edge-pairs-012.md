## E012-001 — QA predicate firing summary

QA fires on:
  Abbreviation forms: "QA" (imperative), "QA sign-off", "QA approval", "QA lead", "QA engineer", "QA checklist", "QA gate", "QA pass", "QA fail", "QA report", "QA team", "QA review", "QA testing", "QA automation", "QA harness", "QA criteria", "QA block", "QA environment", "QA owner", "QA metrics"
  Gap forms: "quality assurance" (spelled out), "deploy", "provision", "rollout", "monitor", "alert", "SLO", "SLA", "CI/CD", "continuous deployment", "feature flag", "hotfix", "sign-off" (alone), "approval" (alone), "release" (alone)
  Teaching: QA is a strict abbreviation-gate predicate. Only the "QA" abbreviation fires it.

---

## E012-002 — "QA" preceding any noun fires QA

A: Any request containing "QA" as a modifier preceding a noun → ["QA"]
  "QA dashboard" → ["QA"] | "QA standards" → ["QA"] | "QA workflow" → ["QA"]
  Teaching: QA fires when used as a modifier (attributive adjective form of the QA abbreviation).

---

## E012-003 — "QA" after any verb fires QA

A: Any request containing "QA" as a direct object → ["QA"]
  "run QA" → ["QA"] | "perform QA" → ["QA"] | "do QA" → ["QA"]
  Teaching: QA fires when used as a direct object after any verb.

---

## E012-004 — "QA" as subject fires QA

A: "QA is required before this ships." → ["QA"]
  Teaching: QA fires when "QA" appears as the subject of the sentence.

## E012-005 — Observability vocabulary is universally gap

A: "Track the error rate, monitor latency, and set up PagerDuty alerts." → []
  Teaching: Error rate, latency, P99, P95, throughput, uptime, PagerDuty, Datadog, New Relic → all gap.
