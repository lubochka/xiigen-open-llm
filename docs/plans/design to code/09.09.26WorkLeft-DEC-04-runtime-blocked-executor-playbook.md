## Как действовать при реальном блокере

1. Зафиксировать точную пользовательскую операцию: макет, фраза или prompt.
2. Зафиксировать ожидаемый результат: код, перевод или поток.
3. Зафиксировать, на каком шаге остановилось: загрузка весов, создание пары, проверка качества, откат, публикация, интерфейс.
4. Если desktop/UI недоступен, не останавливать весь продукт: отдельно продолжить автоматическую границу, где она безопасна.
5. Не превращать старый blocked-текст в текущий статус без свежей проверки.

# 14.08.26 WorkLeft DEC-04 — Playbook: исполнитель упёрся в SAC/runtime — что делать

## §0 Смысл одним абзацем

Исполнитель, чей тест/прогон заблокирован Smart App Control (SAC, «умный
контроль приложений»), отсутствием WSL (Windows Subsystem for Linux),
сломанным WSL, отсутствием Docker/Podman или недоступным elevation, НЕ
останавливается и НЕ спрашивает Лубу про runtime. Runtime-резолюция уже
предрешена каноном: WSL2 Ubuntu 24.04 + .NET 9 (DEC-01, маршрут 2b);
установка WSL2 заранее авторизована дефолтом №58 «ставить с уведомлением»
(DEC-02 §1.6). Заблокированная верификация — это lane `verification_blocked`:
результат хранится «применено, не верифицировано», работа продолжается
следующим авторизованным слайсом. Ложный стоп на этом классе — нарушение
(score_delta = -1000).

## §1 Симптом → классификация → немедленное действие → кто владелец

| Симптом | Классификация | Немедленное действие | Кто владелец |
|---|---|---|---|
| SAC блокирует dll до тела теста (события 3033/3077/3089, `0x800711C7`) | `verification_blocked` lane, НЕ терминальный блокер | Пометить семейство «применено, не верифицировано»; продолжить следующий авторизованный слайс; прогнать семейство под WSL2 (§2) | Исполнитель |
| WSL отсутствует (`wsl --status` пуст/ошибка) | Предрешённая установка по дефолту №58 | Уведомить (пакет-уведомление = этот блок) и выполнить §2; разрешения НЕ спрашивать | Исполнитель; 1 elevated/UAC-клик — владелец |
| WSL есть, но сломан (таймауты, сервис не виден) | Ремонт = та же предрешённая установка №58 | `wsl --shutdown`; при неудаче переустановка по §2 (`wsl --unregister -d Ubuntu-24.04` + `wsl --install -d Ubuntu-24.04`); не ждать — идти следующим слайсом | Исполнитель; elevation — владелец |
| Установщик WSL сам сломан (`Wsl/CallMsi/Install/REGDB_E_CLASSNOTREG`, «Class not registered»; встроенный repair-промпт тоже падает) | Ремонт пакета = та же предрешённая установка №58 | Лестница §2-Б: `wsl --update` → при той же ошибке свежий пакет (`winget install --id Microsoft.WSL` или MSI с github.com/microsoft/WSL/releases) → перезагрузка → `wsl --install -d Ubuntu-24.04` → при неудаче DISM-фичи VirtualMachinePlatform + Microsoft-Windows-Subsystem-Linux и повтор; только если исполнитель уже может выполнить это без новой руки владельца; иначе lane остаётся `verification_blocked`, а работа продолжается следующим слайсом | Исполнитель; дополнительных owner-hand действий нет |
| Docker/Podman недоступны | Не вопрос: контейнер — отклонённая альтернатива 2c (DEC-01) | Ничего не чинить; использовать WSL2 напрямую | Никто |
| Elevation недоступен в среде исполнителя вовсе | Узкий hand-off одного действия, НЕ стоп | Выдать владельцу Run-able блок §2 (шаг A); тем временем НЕ ждать — продолжать следующий авторизованный слайс | Луба: один elevated запуск |
| Тест Windows-only (`PlatformNotSupportedException`, real-store координатора) | `WINDOWS_ONLY_RUNTIME`, НЕ провал и НЕ блокер | Пометить ряд; под WSL2 НЕ гонять; стор на фейк НЕ подменять; ждать триггера №57 | Спит до триггера №57 (dev-VM) |

## §2 Готовый Run-able блок (единственная рука владельца — один elevated запуск)

Шаг A — Windows, elevated PowerShell (однократно; возможна перезагрузка):

```powershell
wsl --install -d Ubuntu-24.04
# при запросе — перезагрузка; после неё Ubuntu доинициализируется сама
```

Шаг A-ремонт (только если Шаг A упал с `REGDB_E_CLASSNOTREG` — сломан сам пакет
WSL; elevated PowerShell, по порядку до первого успеха):

```powershell
wsl --update
# при той же ошибке — свежий пакет (перерегистрирует COM-классы):
winget install --id Microsoft.WSL -e --source winget
# либо руками: последний wsl.<версия>.x64.msi с github.com/microsoft/WSL/releases
# затем ПЕРЕЗАГРУЗКА и повтор Шага A; если и после этого падает:
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
# перезагрузка и повтор Шага A
```

Лестница ремонта — работа исполнителя только там, где она уже исполнима в его
авторизованном elevated-контексте. Её нельзя превращать в дополнительные просьбы
или действия руки владельца. Если такого контекста нет, исполнитель сохраняет
узкую метку `verification_blocked` и немедленно продолжает следующий
авторизованный слайс; единственная рука владельца остаётся Шагом A и одобрением
перезагрузки, только если Windows его запросит.

SAC этому пути не мешает: пакет WSL подписан Microsoft и имеет накопленную репутацию.

Шаг B — внутри WSL (исполнитель делает сам; elevation хоста не нужен):

```bash
sudo apt-get update && sudo apt-get install -y dotnet-sdk-9.0
# либо без root: curl -sSL https://dot.net/v1/dotnet-install.sh | bash /dev/stdin --channel 9.0
cd /mnt/c/Projects/llm_mvp_core-DpoImplementation
dotnet test Tests --filter "FullyQualifiedName~DesignConversionModelRepositoryPromotionUploaderTests" --logger "console;verbosity=detailed"
dotnet test Tests --filter "FullyQualifiedName~DesignConversionDpoTeacherAuthoringTests" --logger "console;verbosity=detailed"
dotnet test Tests --filter "FullyQualifiedName~DesignConversionModelServerTrainingIntakeTests" --logger "console;verbosity=detailed"
dotnet test Tests --filter "FullyQualifiedName~DesignConversionImprovementLoopCoordinatorTests" --logger "console;verbosity=detailed"
```

The elevated Windows launch above, plus reboot approval only if Windows itself
prompts, is the sole owner-hand action. The executor must not wait for that hand:
it immediately continues the next authorized slice. Once WSL is available, the
executor owns SDK installation, repository `cd`, and all four test commands.

Откат (если владелец возразит на уведомление): `wsl --unregister -d Ubuntu-24.04`
плюс выключение компонента Windows. Интерпретация падений координатора — по
DEC-01 §4 шаг 4: real-store падения = `WINDOWS_ONLY_RUNTIME`, остальные —
обычные красные, чинить обычным циклом.

## §3 Правила (обязательные)

- `runtime-blocked lane is never a stop; the next authorized slice continues` —
  блокировка верификации меняет маршрут, а не обязанность двигать деливерабл.
  Слайс несёт метку `verification_blocked` с точным списком неверифицированного,
  НЕ закрывается как ACCEPT, но очередь работ продолжается без паузы.
- `WSL2 install is pre-authorized by default №58 — notify, don't ask` —
  пакет-уведомление заменяет вопрос; спрашивать «можно ли ставить WSL2» —
  нарушение дефолта №58 (DEC-02 §1.6). Откат назван и дёшев.
- `never ask the owner to "provide a VM" — dev-VM has its exact trigger (№57)` —
  триггер №57 (DEC-02 §1.5): WSL2-прогон завершён И список `WINDOWS_ONLY_RUNTIME`
  непуст И эти ряды гейтят фазу И №55 спит. До срабатывания просить VM запрещено.
- «Зелёное через исключение тестов» запрещено (DEC-01 invariants): Windows-only
  подмножество остаётся непрогнанным/красным до Windows-среды — это граница
  платформы, не провал и не повод менять тест.
- Честное закрытие: заблокированная мутация становится verified ПОСЛЕ появления
  runtime; до тех пор слайс несёт `verification_blocked` + точный список
  неверифицированного. Выключение SAC (№55) не предлагать — вопрос спит.

### §3.1 Обязательный payload каждого runtime work order

Каждый executor/verifier work order, способный запускать .NET build/test/runtime,
должен не только ссылаться на DEC-04, а нести его исполнимый payload: симптом и
узкую классификацию lane; шаг A; SDK/`cd`; четыре точные команды из §2; триггеры
№55/№57/№58; и поле `unverified_runtime_rows:` с точными FQN и/или идентификаторами
mutation-oracle. Этот список переносится без потерь между слайсами, пока прямое
runtime-доказательство не разрешит каждый ряд. SAC-блокировка, исключение теста,
успех одного другого ряда или build-only proof не имеют права удалить ряд из
списка или перекрасить его в green.
