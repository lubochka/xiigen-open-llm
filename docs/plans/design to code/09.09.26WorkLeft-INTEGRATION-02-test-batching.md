Этот текст не отменяет реальные required checks, ownership и права. Он разделяет (a) Markdown/readback, (b) deterministic rights/schema/state/no-repeat/safety, (c) точную DPO authoring+assessment, (d) authorized optimizer mutation/full recovery, (e) независимое learning improvement per domain/bulk/ordinary consumer + full PC cost, (f) отдельную Windows native и S05 release.

**Изменённая норма к формуле «До изменения выбрать focused/impacted батч» ниже:** для **фактической продуктовой кодовой правки** выбирать существующую затронутую focused/impacted проверку **по защищаемому инварианту**; это НЕ предшествующий обязательный product-test или Windows запуск для документа, дизайна или научной гипотезы об обучении. Только обоснованная native/host зависимость переносит Windows в admission. Для learned gain требуются parent/challenger/no-update, same-panel/independent families, lawful domain/path/semantic-kNN/LoRA examination, предобъявленные правила effect/regression/uncertainty, resource+retention и cold ordinary consumer. Тест/green/loss не закрывает научный verdict.

Windows workflow сохраняется; условия required status rules пока NOT_OBSERVED (GitHub 403). Исторические task IDs/S04/S05/S06/S07 и безопасность сохраняются.

**Текущая область S04/S06/S07 — 02.10.2026.** Этот раздел уточняет текущую работу; он не подтверждает выполнение. Датированные указания 09.09.2026 полностью сохранены в архиве по ссылке ниже. Только в конфликтующих пунктах для S04 их заменяют: существующий noise-aware критерий вместо голого `>=95`; отдельные verdict механизма/реального урока/качества; локальные материалы S04 и отдельная remote-публикация S05; текущие ограничения данных, эффектов и V2. Прочие исходные требования не отменены. Исторические «уже сделано» сверяются с actual core evidence, не повышают статус автоматически.

**Проверки следуют за работающей возможностью, а не создают очередь ради каждой строки плана.** Сохранить исходные IDs, зависимости, обязательные условия и отдельную приёмку задач. Группы поставки: (1) исходная оценка; (2) учитель и сохранённая пара; (3) обновление и измерение; (4) сквозной запуск и восстановление. Это не новые task IDs, не слияние разрешений и не обход опубликованных границ задач.

До изменения выбрать минимальный уже существующий focused/impacted батч. Один сквозной тест может покрывать несколько условий, только если для каждого видно собственное наблюдение и путь до нужного guard. Не суммировать пересекающиеся проверки как независимые доказательства. Новую проверку добавлять для конкретного непокрытого риска; обязательные wider gates не удалять. Неподходящий или пустой фильтр, synthetic вместо real, неполный прогон — не PASS.

Смысловой тест допускает разные корректные решения: проверяет документацию фактического поведения, исполнимость зависимостей или результат задачи, а не единственный route ID/порядок оформления без такого требования. Технические проверки неизменности данных, разрешений, границ памяти, происхождения, полного rollback и отсутствия повторного update остаются. Код не выбирает смысловой ответ через тестовый oracle или фиксированный селектор вместо заявленной обучаемой политики.

**Проверка влияния обучения, а не совпадения с фиксированным маршрутом.** В рамках уже заданных arms/rounds связывать вход, candidate set, исходный/обученный checkpoint, решение политики, реально выполненный путь и outcome. Проводку проверять synthetic state-intervention; пользу — по существующему matched experiment с реально обученным состоянием. Не добавлять новые model-call arms или данные сверх гранта: не поместившийся контроль оформить как отсутствующее доказательство/обычную bounded amendment, не тратить скрытый бюджет.

Переименование только display IDs и перестановка presentation order проверяются с сохранённой биекцией semantic candidates, features и реальных dependency edges. Это не разрешает менять смысл узлов, storage/security identity или dependency order. Для stochastic policy сравнивать при предусмотренных согласованных random draws либо распределения в рамках принятой методики; не требовать побитового совпадения независимых случайных выборок. Допустимые tie/no-signal решения не превращать в искусственную preference.

При отключении/отсутствии/несовместимости learned state путь явно untrained/unavailable либо помеченный допустимый контроль, не скрытая «обученная» эвристика. Round2 использует принятый B1 либо честно сохранённый B0; исходный B0-control остаётся неизменным. Сохраняются fixed-combination, seeded random-route, ordinary-example и frozen-initial-builder controls, их фактическая модальность, count/text-volume matching, лимиты, noise rule, независимые partitions. Снижение DPO loss, другой route ID или новый файл весов не доказывают downstream quality.
