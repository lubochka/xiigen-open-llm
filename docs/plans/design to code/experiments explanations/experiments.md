1. BW01: обучение BPE без повторной обработки одинаковых фрагментов
Где изменили: обучение токенизатора — подсчёт частот пар и выполнение слияний.

Старый способ → UML
BPE ищет часто встречающиеся соседние пары и объединяет их в новые токены. Раньше одинаковые куски текста хранились отдельными списками. Во всех копиях снова считались пары и выполнялись одинаковые слияния.

Обновление на основании эксперимента → UML текущего способа
Теперь одинаковые исходные фрагменты представлены одним списком и числом повторений. Вклад списка в частоту пары умножается на число повторений. Слияние выполняется один раз на представителя.

Сохранён порядок первого появления: он нужен, чтобы при одинаковых частотах выбрать ту же пару. Этот механизм уже находится в основном BpeTokenizer. Позднее добавили проверки старых хэшей словаря и отдельное измерение на повторённом корпусе. Текущий код.

2. HCL01: чтение правильной строки обученной таблицы
Где изменили: чтение иерархической памяти событий. Это таблицы переходов в модуле экспериментов 34, а не изменение матрицы внимания Transformer.

Старый способ → UML
События разбиты на группы — например, проверка данных и сохранение. Сначала модель выбирает следующую группу, затем её таблица предсказывает событие внутри группы.

Ошибка старого читателя: в таблицу выбранной группы передавался локальный номер события другой группы. Но номер 0 в двух разных словарях может означать разные события.

Обновление на основании эксперимента → UML текущего способа
Теперь читатель помнит последнее уже наблюдавшееся событие каждой группы. Для целевой группы берутся её собственная история и её локальный номер.

Сами обученные счётчики переходов сохраняются. Изменение перенесено в E05LocalHierarchy; позднее добавили проверку настоящего E05HierarchicalPrediction.Run. Если целевая группа ещё не встречалась, код использует прежний запасной путь. Текущая реализация.

3. WC01: одинаковые признаки урока вычисляются один раз
Где изменили: подготовку признаков внутри обучения Wiki-маршрутизатора. Здесь обучается лексический классификатор — перцептрон. Название входного типа DpoPair не означает, что этот участок использует DPO.

Старый способ → UML
Текст запроса превращается в числовые признаки. По ним классификатор выбирает действие. При ошибке веса правильного действия увеличиваются, ошибочного — уменьшаются.

Раньше каждое повторное предъявление урока заново запускало извлечение признаков: 8 уроков × 18 эпох = 144 вычисления.

Обновление на основании эксперимента → UML текущего способа
Теперь перед первой эпохой готовятся признаки всех восьми строк. Все 144 предъявления, порядок уроков и правила обновления весов сохраняются.

Это реализовано в ProjectWikiRequestRoutingTrainableModel.Train. Последующие проверки закрепили обученное состояние и его восстановление. Текущий код.

4. PQ01: признаки запроса строятся один раз для всей памяти KNN
Где изменили: сравнение запроса с памятью KNN при определении структуры предложения по частям речи.

Старый способ → UML
Из последовательности частей речи собираются соседние пары — например, «существительное → глагол». KNN сравнивает этот набор с сохранёнными примерами и выбирает ближайшие.

Раньше набор одного и того же запроса пересоздавался для каждого кандидата. Для 32 запросов и 128 записей памяти — 4 096 раз.

Пары кандидата по-прежнему считаются при его сравнении. Сортировка, выбор трёх ближайших соседей и голосование сохраняются. Это уже находится в основном PatternClassifier. Код.

5. AST01: один обход соседей вместо повторного обхода для каждого узла
Где изменили: получение структурных признаков кода перед обучением KNN.

AST — синтаксическое дерево программы. У узла есть родитель, соседи и позиция среди них.

Старый способ → UML
Чтобы определить позицию очередного узла, старая реализация заново получала список всех детей его родителя. При переходе к следующему ребёнку делала то же самое.

У широкого узла с большим числом детей повторялось особенно много работы.

Обновление на основании эксперимента → UML текущего способа
Первое обращение к родителю перечисляет детей и запоминает их количество и позиции. Следующие обращения используют готовые сведения. Кэш действует в пределах одного неизменяемого дерева.

При переносе также исправили обучение по нескольким файлам: их пары собираются вместе перед единственным обучением, чтобы очередной файл не затирал память предыдущего. Одиночное PredictFromNode сохраняет прежний путь без этого кэша. Реализация · сбор нескольких файлов.

Этап: прямой проход RMSNorm → среднее квадратов → суммирование по последней оси.

RMSNorm нормализует масштаб вектора. Для этого ему нужно среднее квадратов его элементов. В эксперименте меняют способ нахождения элементов в памяти, сохраняя само вычисление.

Старый способ → UML

Этот способ правильно считает среднее, но создаёт много небольших служебных массивов.
