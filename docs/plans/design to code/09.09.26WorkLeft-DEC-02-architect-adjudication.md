Назначение файла: фиксировать архитектурное решение, когда спор идёт между хранением артефактов и настоящим улучшением модели.

Решение:

1. Обучение начинается с уже принятых весов. Нет весов — нет скрытого старта с нуля.
2. Ученик выполняет задания; отдельная модель-проверяющий оценивает его ответы и не меняет свои веса в этом цикле.
3. Учитель Qwen создаёт одну пару под найденную слабость. Старые пары можно использовать как контекст, не как повторное обучение.
4. До пары сохраняются веса, адаптер, оптимизатор, счётчики, манифест, список принятых пар и исходная оценка.
5. Хуже — точный откат; равно или сомнительно — прежние веса сохраняются; лучше — принять новую контрольную точку.
6. Для учебных доменов цель качества — 95% и выше к зафиксированному эталону. Если исходная модель уже достигает цели, нужна независимая итоговая проверка, не новая пара.

Ожидаемое и фактическое: существующие checkpoint/DPO механизмы ценны, но архитектурно открытым остаётся полный контур проверки качества и отката.

### 4.4. Полный record дефолта G3 (№6 = DEC-03)

**Что такое G3 по-человечески.** G3 — это замок приёмки обученного чекпоинта: правило, по которому обученная модель получает право стать продуктовым авторитетом (то есть реально влиять на ответы продукта, а не лежать рядом как эксперимент). Форма этого правила была решена архитектором раньше («held-out ≥ порога + сквозное доказательство»); здесь установлено недостающее ЧИСЛО.

**Формула.** Принять чекпоинт тогда и только тогда, когда `wins/N ≥ max(0.55, c(N))`, где `N` — размер held-out набора пар, `wins` — число пар, где обученная модель победила baseline:
- при `N ≥ 200` — win-rate ≥ 0.55 против baseline;
- при `50 ≤ N < 200` — дополнительно порог биномиальной значимости `p < 0.05`: `c(N)` = минимальная доля побед, дающая значимость (N=50 → ≥ 0.64; N=100 → ≥ 0.59);
- при `N < 50` приёмка невозможна вовсе (набор слишком мал).

**Абсолютный пол.** Помимо win-rate обязателен абсолютный пол `accuracy ≥ 0.75` — единый канон с числом, уже стоящим в коде (`TranslationMachine.cs:181`).

**Доказательная цепочка.** Приёмка требует e2e proof-цепочки: typed proof + fresh-load + continue-training (загрузили чекпоинт заново и продолжили обучение с него).

**Обоснование чисел.** 0.55 — минимальный содержательный отрыв (≥ 5 процентных пунктов); при `N ≥ 200` это даёт `p ≈ 0.02`, то есть отрыв уже не случайный. `c(N)` не даёт принять шум на малых корпусах: на 50 парах случайные 55 % встречаются часто, поэтому планка поднимается до 0.64. Пол 0.75 согласован с ЕДИНСТВЕННЫМ числом порога, реально живущим в коде, — чтобы не завести второй несогласованный канон. Тарифные пороги (№36) — ДРУГАЯ ось (деньги/тариф) и в G3 не подмешиваются.

**Имена конфигурации.** `G3_ACCEPTANCE_WIN_RATE=0.55`; `G3_MIN_HELDOUT=50` (цель 200); `G3_SIGNIFICANCE=p<0.05`; `G3_ABS_ACCURACY_FLOOR=0.75`.

**Falsification.** Если ≥ 3 подряд реальных прогона показывают, что правило пропускает шум ИЛИ блокирует измеренные улучшения — вердикт пересматривается новым architect-record. Переигрываемо, необратимого нет.
