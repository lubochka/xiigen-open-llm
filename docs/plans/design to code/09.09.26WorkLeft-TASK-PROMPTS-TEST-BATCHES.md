1. **Человеческий комментарий к каждой изменённой строке кода.** Комментарий объясняет, что эта строка делает здесь по смыслу, а не что значит ключевое слово языка. Поле отчёта и тела коммита — `comments_added_human=true`.

### Правило «номер не стоит отдельно»

Внутренний номер (строка работ, замок, решение владельца, номер батча) никогда не пишется в прозе один: сначала человеческое название и цель, номер — в скобках сразу после, **каждый раз**, а не только при первом упоминании. Голые номера допустимы только внутри машинных блоков и в колонках идентификаторов таблиц. Словарь человеческих названий — `09.09.26WorkLeft-GLOSSARY-human-names.md`. Перед сдачей отчёта исполнитель прогоняет по своему тексту поиск номеров и проверяет, что каждое совпадение стоит в скобках после названия. Ссылки вида «файл : строка» — это цитаты кода, а не внутренние номера: правило на них не распространяется. Измеряемые величины (11 308 строк выполнения, 994 секунды, 92 невыполненные проверки, десять минут) — это числа, а не идентификаторы, и под правило тоже не подпадают.

Хороший и плохой примеры блока §7 обязаны быть **реальными** и иметь источник в этой папке или в репозитории: хороший — фрагмент уже принятой работы, плохой — дословный класс уже случившегося инцидента с указанием файла и строки. ### Одно узкое место на промпт

Промпт закрывает одну дыру. Если в ходе работы выясняется, что дыр две, исполнитель не расширяет промпт молча: он делит строку на две с теми же условиями приёмки и докладывает деление в отчёте. Слитые узкие места делают невозможным ответ на вопрос, какая из двух починок сработала. Ровно поэтому написание запускалки (номер 248) и её первый прогон (номер 251) разведены по разным строкам: иначе они смешались бы в один непроверяемый ком.

### Мутационная чувствительность обязательна в каждой проверке приёмки

В каждом полном промпте этого файла блок §6 содержит **мутацию**: намеренную порчу, после которой проверка обязана начать ругаться. | Часть команды | Что делает | Почему обязательна |
|---|---|---|
| `--no-build --no-restore` | запрещает пересобирать | без этого сорок семь связанных проектов пересобираются на каждый батч и весь выигрыш съеден |
| `--filter "FullyQualifiedName~…"` | отбирает батч по куску полного имени теста | единственный признак, работающий для всех 418 файлов: 175 из них вообще без пространства имён |
| `--results-directory "$BATCH_DIR"` | кладёт результат в **свою** папку батча | это и есть лечение корневой причины: файл появляется по завершении батча, а не в конце трёхчасового прогона |
| `--logger "trx;LogFileName=result.trx"` | пишет читаемый файл результата | без него закрытый батч недоказуем |
| `--blame-hang --blame-hang-timeout 10m` | обрывает **отдельный** зависший тест через десять минут | предел, уже доказавший работоспособность на единственном успешном прогоне 26 августа |
| `--blame-hang-dump-type none` | не собирать дамп памяти | дамп на такой сборке — гигабайты и минуты. Если версия платформы не примет значение «none», ставится «mini»; это единственное место схемы, где допустима разница версий |
| `RunConfiguration.TestSessionTimeout=1200000` | внутренний предел всего батча, двадцать минут в миллисекундах | второй эшелон защиты: обрывает батч, даже если отдельные тесты по десять минут не набрали |

### Промпт 3. Сводчик результатов батчей: один честный итог из восемнадцати файлов без двойного счёта (строка работ номер 250)

### Промпт 7. Пересчёт счётчиков программы работ после внесения строк батчей (строка работ номер 255)

**§1 Роль и режим.** Канон §1, но работа **не репозиторная**: репозиторий кода не открывается вовсе, система контроля версий не используется, платформа .NET не запускается. Рабочая зона — папка планирования.

**§2 Что сделать и зачем.**

- Зачем: двойной живой счётчик — ошибка, которую в этой программе уже ловили; без пометки исторического счёта следующий читатель возьмёт первое попавшееся число и построит на нём план.

**§3 Контекст.**
- Живой канон счётчиков — часть счётчиков секции строк хроники и потерь файла кодовой работы: всего сто семьдесят шесть строк.

- **То же правило для счёта промптов задач:** он читается живым в момент дописки. На день написания этого файла живой счёт — **сто полных промптов плюс десять заготовок** (восемьдесят шесть до раунда, плюс семь промптов обучения, плюс семь промптов батчей = сто полных; девять заготовок обучения плюс одна заготовка батчей = десять).
