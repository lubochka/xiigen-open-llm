# S28 architecture — lawful alternative PATH evidence, not a fifth learning unit

## One real ordinary path under PC budget
`user x, user rights, project → task intent D-04 + SUBJECT/stack/edition D-07 → law passport + versioned token/IR/vector (RP02/RP18) → BM25 + lawful multiple kNN neighbors → ILearningUnit typed many→many associations → ILearningFlow typed corrections → ILearningOrchestrator asynchronous feasible branch execution → ILearningDynamicGraph higher-order route composition → D-15 deterministic arbiter → Student/project adapter where actually relevant → ordinary answer + actual route/cost trace → independent domain judgment → admitted hard-negative PATH evidence → existing RP11/RP13/RP04 policy recipient OR deterministic fix → optionally separate governed RP01 Chinese pair/Student lesson → independent exam → cold accepted ordinary path.`

The connection between *alternative lawful executed paths* and a *qualified preference observation* is S28's only possible original implementation seam. Everything else is reused (or left OPEN if not observed). A proposed path ≠ an executed path; executed ≠ admissible; admissible ≠ learned; changed state ≠ useful end-user quality.

## Path-level preference vs Student DPO — NEVER collapse
Given frozen task x and real eligible paths p and q under law L and budget B: `eligible(p) = hard_law(p) ∧ types(p) ∧ rights(p) ∧ complete(p)`. Only if BOTH eligible, comparable source/version/state, actual outputs exist and independent judge has meaningful strict lawful utility difference, can we admit `pathPreferred(p,q)`. Illegal q is a VETO/guardrail example, *not* a safe negative for learned ranking. Tie / both bad / uncertain => no preference learning.

If an existing differentiable graph policy provides log probability of path conditioned on x and a valid reference, its own owner may choose an appropriate pairwise objective under explicit approval; otherwise a pairwise ranking loss (e.g., Bradley–Terry) can be an **algorithm proposal**, not existing code or automatically true DPO. Student DPO chosen/rejected are **text responses to identical x** authored BOTH by an allowed open Chinese Teacher, separately accepted by CODEX Astra; path preference cannot be passed off as their authorship. Neither S28 nor policy ranker invents those model calls.

## Deterministic / learned interplay
- Domain law, version, output types, permissions, D-15 arbiter and full-PC effects are deterministic admission conditions.
- Law-conditional vector/semantic similarity, adaptive neighbor weighting, association, correction, graph/path ranking and project Student may have separate **real** learned states.
- Cache and kNN retrieval are not by themselves training. Project LoRA is NOT domain-vector tokenization or projection; compatibility and used consumer need RP18 receipts.
- `KnnLogicalUnit` currently finds multiple hits but picks `hits[0]` for returned prediction in inspected method; RP02 owns correction if still current. `LlmIngredientLogicalUnits.BuildBatch` has `DpoExactPairMaterial.Version` branch and a legacy `Compact` (480-character) fallback; version-bound actual use must be traced, not assumed unconditional.
- Strongest counterfactual: compare legal P frozen, C0 no-gradient deterministic fix, T1 real separately authorized single mutable owner, future T2 distinct real lesson only. If C0 wins, trainable architecture is not proven better.

## Stop rules
Insufficient source/legal authority, no real feasible second path, no independent label, no mutable owner, incompatible state/coordinate space, unknown optimizer status, underfunded PC checkpoint, or missing consumer => RECORD and STOP that effect lane. Other independent read-only lanes continue.
