# S17 — law-version drift algorithm and existing hybrid machine boundary

## The new ability — compatibility-aware **change**, not another engine
Input: `(raw task x, source rights, declared/observed subject domain, law/version/dialect/environment claims, typed requested output, current accepted Student/Graph/representation/index state, resource envelope)`.
Output: zero/one/many **lawful candidates** with `lawEnvelopeId, domain/intent, representationVersion, memoryEligibility, linked OutputRef/TypedTarget, routeId, warning/abstention, observed costs, selectedStateId`. **Shape is an illustrative domain contract, not an approved C# DTO or automatic schema migration.** Ground exact types in K first.

### Pipeline and authority
1. **Separate axes:** `taskIntent` (BUG/PLAN etc), `subject` (C#, SQL, EN→RU, DTC), `lawScope` (language/compiler/version, SQL dialect, user-specified locale/register, target browser, constraints), `tenant/privacy`, `unknown/conflict`. Never infer hard law from similarity or normalize away operators/negation/versions.
2. **Authority ledger:** user request is an intent/constraint, not always trusted fact about the external domain. A law source with exact version/effective date and applicable authority determines the constraint; when no reliable source or conflict → `UNKNOWN/ABSTAIN/ASK`, not silent latest-version substitution. Deterministic law, privacy, consent and final arbiter override learned preference.
3. **Drift signal:** compare current verified law fingerprint to the **provenance of the memory and representation**. Distinguish genuine changed law vs new examples/style preferences vs false mapper confidence vs missing context vs encoder mismatch. Do not conflate version with date or compiler dialect.
4. **Eligibility/memory:** label old positive/negative/warning examples `VALID_CURRENT / VALID_OLD_SCOPE / INVALID_SCOPE / UNVERIFIED`; preserve evidence/history (no destructive relabel of prior lesson). Filter incompatible items **before** kNN ranking or fail closed; retain current appropriate controls. A warning may remain explanatory but cannot become a chosen valid answer.
5. **Semantic representation:** source law ID + token/codebook version + predicate/operator/negation/units/direction + typed output mapping. Original `KnnLogicalUnit` BPE/predicate and 60-slot E51B builder differ. A projector is allowed only with proven semantic coordinates and actual trained owner. LoRA adapts Student parameters; it does NOT convert two embedding versions into compatible vectors.
6. **Existing adaptive kNN:** only eligible neighbors enter the RP02 scoring/k/radius/fusion port. For version shift compare `fixed k`, `learned dynamic k`, `no memory`, `exact-vs-ANN` where available under **identical lawful candidate pools and comparable budget**; S17 must not implement a rival k engine. Record which neighbors influenced the actual typed answer.
7. **Four distinct roles:** Unit produces typed many→many with provenance and OutputRef; Flow learns/corrects relationships to next typed Unit while hard law frozen; Orchestrator schedules lawful async alternative routes under total branch budget and cancellation; DynamicGraph learns higher-order pattern relations/new combinations across law versions. No inference from one role's accuracy to another's learned state.
8. **Learning:** only if a weak ordinary Student response remains after correcting deterministic law/retrieval/route. CODEX `gpt-6-astra/ultra` selects a lawful lesson; authorized separate open Chinese Teacher authors both immutable final DPO sides; CODEX separately evaluates **that exact pair**, with rights/context/seals. Existing RP01 trainer and `ILearningMachine` update the owned Student state once, with correct response likelihood/masks/reference/LoRA target. DPO reference is not evaluator.
9. **State migration + PC:** either safe lazy revectorization/reindex with versioned provenance and resource accounting, explicit parallel old/new snapshot, or abstain. Do not silently rewrite old vectors or rerun used DPO. If crash unknown, stop second update until journal reconciled. Cold ordinary consumer proves version adoption, rollback and old-law retention; native/remote releases remain S05/S08/S09 owners.

## Five falsifiable hypotheses — not claims
- H17.1 A version/authority passport lowers **stale-law violation rate** vs same pipeline with generic domain labels alone.
- H17.2 Eligibility filtering improves new-law lawful answer quality vs mere k enlargement; may hurt recall, which is measured.
- H17.3 Recomputing semantically compatible vectors (rather than mixing old dimensions or assuming LoRA is tokenizer) lowers cross-version confusion at an explicitly measured reindex cost.
- H17.4 Law propagation across Unit→Flow→Orchestrator→Graph yields better *best permissible observed* path and/or cost than filtering only at final arbiter, with all branches accounted.
- H17.5 One **authorized novel** law-shift DPO lesson improves Student on independent new-law families without unacceptable regression on old law after a cold load; REGRESS/INCONCLUSIVE are valid outcomes.

### State machine (conceptual; map to K owner)
`LAW_UNKNOWN → LAW_RESOLVED → MEM_ELIGIBILITY_DECIDED → ROUTE_OBSERVED → [optional] CASE_SELECTED_BY_CODEX → PAIR_AUTHORED_BY_CHINESE → PAIR_JUDGED_EXACT_BY_CODEX → EXISTING_TRAINER_TRIAL_ONCE → INDEPENDENT_EXAM → ACCEPT_OR_REVERT → COLD_CONSUME`.
The no-training branch ends after `ROUTE_OBSERVED → INDEPENDENT_EXAM`. No learning claim if only a deterministic version guard improved correctness. A lawful deterministic baseline can beat learned policy; never label it `rejected` solely because it is rule-based.

**Causal owner handoff:** if version detection itself is wrong → RP02 mapper; eligible index never used → RP02.02A; Unit associations lost → RP03; async branch policy wrong → RP04; exact DPO loss/state wrong → RP01; Student feedback/journal wrong → RP05; experiment runner absent → RP09; ordinary DTC/IDE host absent → RP06. S17 changes **only** compatibility seam validated by changed-law examples.
