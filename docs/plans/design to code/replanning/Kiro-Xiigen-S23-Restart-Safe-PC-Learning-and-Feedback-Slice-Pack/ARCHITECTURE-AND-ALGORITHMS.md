# S23 architecture — bounded lifecycle is not a fifth learning model

## Observable route, trace before touching
ordinary PC request → raw stack/law detection (D-07) → separate taskIntent D-04 and subject/domain/edition/project → law-preserving semantic tokens/typed IR and versioned embedding → allowed BM25 + multiple lawful adaptive-k nearest neighbors (RP02) → ILearningUnit typed many→many candidate associations → ILearningFlow input/output corrections → ILearningOrchestrator budgeted asynchronous candidates → ILearningDynamicGraph higher-order pattern combinations → hard-law/type/rights arbiter D-15 → existing Student/project LoRA and ordinary response → user feedback (quarantined) → optionally authorized selection/Teacher/judge → actual RP01 Student update → independent examination → RP10 acceptance pointer → new-process ordinary call.

All four learning roles retain **different** authority and mutable identities:
1. ILearningUnit: domain, input vector/structure and requested output type → IEnumerable-like MANY-to-MANY result associations, not positional ZIP and not one neighbor as decision. Deterministic input/output schema and law; learned rank/association state only where traced.
2. ILearningFlow: relationships and learned corrections between valid typed Unit ports; immutable law/OutputRef resolution remains deterministic.
3. ILearningOrchestrator: deeper asynchronous candidate route scheduling, bounded cancellation/fan-out/deadlines/side effects; trainable route preference, never unmetered retries.
4. ILearningDynamicGraph: versioned higher-order relations/composition of distinct patterns; hard laws and D-15 arbiter reject inadmissible paths regardless of score.
ILearningMachine/Student+LoRA is a separately owned trainable target; a project LoRA is NOT a domain vectorizer, and a semantic projection is NOT proof of a weight update. Builder meta-learning is a further distinct state.

## Unique owned seam S23
S23 does not own the four learners. It owns the question: which actual currently existing atomic barrier guarantees (a) available PC headroom and rollback reserve, (b) immutable pair and only-once update, (c) recoverable weights/optimizer/RNG/reference/token/index/graph compatibility, (d) no unknown gradient replay, (e) accepted cold state in actual ordinary consumer, (f) valid new consented feedback with provenance, (g) old-domain retention, and (h) accounting for every started/failed/cancelled branch?
Trace each barrier to its actual owner and source. If all barriers exist and are used: REUSE_NO_CHANGE. If one gap is proven, S23.05A makes **one minimal compatibility/budget/recovery/consumer integration repair** with the existing owner; do not add a substitute framework.
