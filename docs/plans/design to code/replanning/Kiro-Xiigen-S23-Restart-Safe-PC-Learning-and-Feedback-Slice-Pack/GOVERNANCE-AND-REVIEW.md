# S23 governance, model roles, allowed side effects and acceptance

## Permissions
This published plan grants planning-file writes in P/llm_plan3 only. It does NOT by itself authorize paid external Teacher/CODEX calls, source transfer, nonpublic evaluation leakage, optimizer Step, destructive fault injection, local file deletion, model-state publication, branch force push or bypass of K repository governance. GitHub connector push permission does not imply budget or model authorization. Each task declares read-only baseline; an eventual explicit owner effect grant must specify repo/ref/path, bytes/side effect, role, rollback, budget and acceptance panel. Canonical DPO and model weights live in K/codex/dpo-implementation after separate authorized execution; never in P. No new ignored artifacts.

## Authoritative role separation
CODEX GPT-6 Astra UltraCode chooses teaching target and separately judges EXACT final Chinese-authored chosen/rejected. An approved external open Chinese model AUTHORS BOTH. Student learns via existing RP01 DPO; mathematical reference is not judge. RP09-style independent blinded evaluator scores Student after learning. R25-style independent Astra UltraCode examines exact candidate code/design as separate role. These are distinct real invocations; author self-review is not independent review.

## Deterministic vs learning verification
Tiny deterministic checks can establish permissions, type contract, at-most-once journal, disk-write/reload, no overwrite, locked decisions, project/tenant isolation, version compatibility, native integration and cold pointer. They NEVER establish quality gain. Science requires source-family-independent frozen P/C0/T1/T2, actual used route, law compliance, macro/worst-domain utility, uncertain variation, retention, real PC ledger and cost efficiency. Native/Windows checks are restricted to changed native or release boundaries; no blanket Windows Actions or coverage threshold to close S23.

## Negative and blocked results count
HOLD if no rollback reserve, UNKNOWN_STATE after uncertain optimizer call, QUARANTINE contaminated feedback, NOT_AUTHORIZED for model roles without grant, INTEGRATION_OPEN for absent ordinary host, REGRESS when old-domain declines, INCONCLUSIVE for underpowered panel; choose safe no-update when more compact. These are valid scientific/engineering outcomes. Never retrofit a test to desired score or claim unrun calls happened.

## Independent candidate review
Plan-review self-check for docs may be done by author and labelled SELF_CHECK, not independent Astra. To claim INDEPENDENT_REVIEWED, separate CODEX Astra UltraCode sees exact published candidate SHA and source/claim matrix and emits an inspectable review packet. Fixes create a NEW SHA and need NEW review. If no real reviewer, leave independent review NOT_PERFORMED. Do not infer quality from manifest or passing CI.

Every task returns human RU summary, evidence identity/read depth, actual code caller→method→state→consumer, law authority, assumptions, GOOD/BAD/EDGE, falsifier, changed owned bytes (or NONE), measurable result/uncertainty, WHOLE-PC cost or NOT_MEASURED, feedback/parent/pair state, code/review permissions and smallest next action.
