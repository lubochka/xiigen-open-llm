## D01 — что сохранить и что не делать

Сохранить Unit/Flow/Orchestrator/DynamicGraph, actual ILogical*/Machine mapping, typed many→many, learned semantic choice, deterministic lawful operations, TensorCore/LoRA и существующие механизмы поиска. Не создавать четыре новых Train API; не заменять reasoning unit постоянной заглушкой. Не путать TaskSignal, lexical embedding, TeachingVector scaling, output projection и OutputRefs.

Решение об авторстве DPO уже принято: **CODEX с Astra 6 ultracode выполняет человеческую роль выбора урока; внешняя допущенная открытая китайская модель пишет обе окончательные стороны chosen/rejected; CODEX с Astra 6 ultracode отдельно оценивает точную пару.** Student решает задачи и обучается. Экспертная оценка Student — отдельная роль/контекст. Хороший deterministic ответ не rejected из-за происхождения.

Сохраняются one fresh pair→snapshot→update once→operational assessment→accept/full restore. Bulk — окно наблюдений новых разных уроков, не replay 70/30 и не повтор одной пары под новым ID. Runtime guards и действующие проверки не удаляются; R04 не добавляет coverage/Windows gate и не объявляет skipped checks успешными. S06 multi-lesson путь не сокращается вечным S04 one-update-total лимитом; actual campaign разрешение остаётся отдельным.

## D02 — один опыт представлений вместо декартова произведения настроек

### E01: условный domain-aware representation experiment в существующем kNN learner

**Вопрос:** при одинаковом доступном знании, typed outputs и поиске помогает ли сохранение доменных отношений/порядка выбирать более правильный допустимый результат, и оправдывается ли его полная цена?

**Кандидат предмета для E01:** orchestration / selection of a compatible flow or subphase. Это существующее обязательство WorkLeft, а не новый учебный домен. Выбор требует actual registration/consumer; он не назначает первый E02-урок обязательно в orchestration. SQL/C#/перевод не заменяются этим пилотом; контрастный следующий предмет — EN↔RU с уже найденным scorer. Полный curriculum и UI не являются входным gate этого опыта.

**Текущий механизм:** K0 `21.AgentInfrastructure/Logical/KnnLogicalUnit.cs`, Train и ExecuteAsync/Vectorize. BPE обучается на примерах, token IDs и predicates попадают в две hashed tiers, HNSW ищет k, выход — typed bestExample.Output. Runtime textSelector и predicate_ids должны соответствовать train-side inputs. Это baseline, а не универсально оптимальная архитектура. Ни calibrated confidence, ни abstention, ни rebinding query-specific payload этим классом автоматически не доказаны.

**A0:** исходный BPE/count-hash encoder, сохранённый BPE, фиксированный corpus/examples/outputs, fixed k и HNSW configuration, одинаковый query budget и порядок index build.

**A1:** один domain-aware encoder поверх ТОГО ЖЕ замороженного BPE и тех же примеров. Смысловая добавка ограничена признаками отношений задачи: роль, input/output port meaning, направленная зависимость и порядок semantic task signals. При отсутствии доказанного parser/TaskSignal producer не подставлять oracle features в predicted ветку. Условный seam именно этого сравнения — передать один идентифицированный encoder в index insertion и query, а не реализовать ещё один learner. Это не решение, что весь проект должен сначала выполнить этот patch.

A0/A1 используют одинаковый общий размер/бюджет вектора и памяти, где это технически осмысленно. Если для A1 нужен иной бюджет, это отдельное явно маркированное сравнение качества/стоимости, не скрытая бесплатная прибавка. Сама BPE vocabulary, k, scoring policy, examples и outputs не меняются вместе с representation. Derived index пересобирается для каждого encoder из тех же примеров; время/память этого действия входят в цену вмешательства. Не сравнивать новую query-coordinate систему со старым индексом.

**Что заморожено:** downstream lawful solver/consumer, candidate universe, accepted Student checkpoint, graph/flow policy, reference policy, BPE/codebook, датасет и split, rubric, caps, k/search/index hyperparameters. Внешние обязанности hard-law/final arbiter не отключаются. Если downstream не читает изменённый канал или обе ветки фактически вызывают одинаковый encoder, сравнение не доказывает заявленное вмешательство.

**Три согласованные diagnostic conditions:**

1. Oracle-domain: заранее независимо установленный применимый domain/intent/stack descriptor. Показывает способность представления/решателя при правильном mapping; не выдаётся за обычный runtime.
2. Predicted-domain: реальный router, без доступа к labels. Показывает end-to-end результат.
3. Controlled domain perturbation: правдоподобный wrong/ambiguous/unknown domain с тем же запросом и действующими lawful fallback. Показывает чувствительность и фактический accept/reject/clarification outcome, не разрешает незаконный production bypass. Warning без отказа не считать abstention.

Oracle/predicted нельзя объединить в одну среднюю точность. Если обе ветки solver плохи, равенство их результатов не доказывает хорошее domain mapping. Exact bounded-pool reference может отдельно различить ANN miss и плохую семантику; это не повод одновременно менять representation, pool, metric и k. Следующий domain-metric/adaptive-k contrast принадлежит R06, с проверкой index assumptions у query-dependent score.

### Данные и два вида контрпримеров

Готовые примеры/seed assets допускаются только после проверки R08 по source/license/lineage. Реальное знание labels до опыта разрешено автору эталонов, но не Student/generator через закрытые данные. Семья исходной задачи и все её парафразы/контрфакты остаются в одном split. N−1 negatives одной family не N−1 независимых наблюдений.

Meaning-preserving: разные формулировки одной разрешённой задачи, переименование связанной переменной без смены binding, независимый порядок предъявления кандидатов при сохранённом semantic order.

Meaning-changing near-miss: те же слова при другой направленной зависимости; положительное/отрицательное требование; другой output type или scope; известный предмет с неизвестной версией схемы. Эти случаи нужны для определения сохранности смысла, а не покрытия строк кода.

**Diagnostic input contrast x/x′ не DPO pair.** Для DPO обе окончательные стороны y+/y− отвечают одному frozen task/context x. Разные запросы «не удалить» и «удалить» полезны как representation contrast, но сами не образуют выбранную/rejected стороны одного урока.

Разделить training families, development/calibration, operational monitoring и запечатанный confirmation set. Уже раскрытые диагностические ошибки можно использовать только согласно разрешённой authoring policy, но они не становятся новым untouched экзаменом. Не публиковать ответы closed confirmation в этом пакете.

### Предварительно фиксируемая запись опыта

До разрешённого запуска R13 закрепляет: actual code/accepted state refs; конкретные source family IDs и split; domain descriptor; tokenizer/encoder/index/schema versions; current textSelector и predicate producer; точный consumer и admitted output types; A0/A1 switch; ограничения ресурсов; hardware/software/threading/cache conditions; semantic rubric; useful change/noise decision; остановку и checkpoint для confirmation.

**Открытые реальные предусловия E01:** target PC профиль/лимиты не измерены; manifest выбранной unit/ordinary registration не прочитан; законный набор семей и semantic labels не допущен; graph OutputRefs resolver G01 не прослежен. Эти поля нельзя заполнить выдуманными значениями. Direct typed unit pilot может не зависеть от graph resolver; графовый маршрут не объявлять готовым без него. Эти gaps не блокируют независимый существующий E02-route, который их не использует.

### Что измерять

- Mapping: per-domain и macro summary, domain/intent/stack confusion, multi-domain agreement там, где эталон обоснован, coverage/ошибка среди принятых ответов и actual abstention/OOD outcome. Slice/UnitRole не использовать как предметный label.
- Representation: сохранение заданных отношений/отрицаний/типов/порядка; meaningful neighbor relevance и hard-negative confusions; конфликт версий/пространств. Cosine, hash, shape и compression ratio — диагностика, не семантическая приёмка.
- Typed outcome: правильность requested type и association, lawful completion задачи/маршрута и предметная экспертная оценка результата; отдельно ошибки mapping и ошибки решателя при правильном domain. Копирование чужих request-bound IDs не компенсируется правильным классом ответа.
- Cost: encoding и search p50/p95, полная latency, стоимость всех завершённых/ошибочных/отменённых веток, peak process RAM/VRAM, base/adapters/optimizer/index/graph/cache/snapshots, index build/rebuild, cold/warm behavior, admitted/rejected attempts. GC current-thread allocation не peak RAM. Local и external cost показывать раздельно и в общей цене цикла.
- Learning: отдельное состояние before/after, fresh pair IDs, applied/accepted/restored counts, per-domain change, old-domain retention и ongoing user-input performance до коррекции. Это отдельный опыт E02 ниже; E01 не выдаётся за DPO-update.

Результат качества и стоимость показывать раздельно и как наблюдаемый trade-off. При нуле полезных принятых изменений не делить затраты на ноль: вернуть ноль изменений и полную затраченную сумму/время. Не делать вывод PC-fit только из малого LoRA adapter. «Лучший путь» ограничен названным admissible pool/бюджетом, не global optimum.

### Как принять или отвергнуть гипотезу

**IMPROVE:** на заранее определённой предметной рубрике есть полезный сдвиг при допустимой цене, без нарушения hard constraints/association и неприемлемой потери retention. **REGRESS:** значение/связность/retention ухудшились либо цена превысила согласованную границу. **INCONCLUSIVE:** данных/независимых families недостаточно или наблюдение не различает объяснения. **INVALID_EVIDENCE:** утечка, смена рубрики, неравные данные/бюджет без маркировки, другой consumer, несовместимый index или вмешательство фактически не состоялось.

Useful change/noise и caps определяются по предмету и baseline до просмотра challenger-ответов. Не навязывать универсальные .95/.02/.025 из numeric meter как научное доказательство каждого механизма. Сохранить исходную цель 95% к определённому эталону отдельно от incremental improvement.

Оценивать paired changes на независимых source/problem families, а не считать парафразы независимыми trials. Способ оценки неопределённости выбирается по типу результата и объёму; малую выборку обозначать явно. Не запускать бесконечные seeds или все комбинации domains×k×ranks×graphs. Повторение операционного наблюдения не разрешает повторный gradient. Исторические automatic Tier3/SCALE_UP=algorithm-correct из experiment-design не являются текущими правилами.

**Фальсификатор:** более близкие соседи/короткие токены без улучшения lawful typed outcome; A1 выигрывает только на известных текстах; fixed простой baseline даёт тот же эффект дешевле; reindex/память съедают выгоду. Такой исход сохраняется, а не лечится ослаблением экзамена.

## D03 — отдельный первый учебный опыт E02, без подмены E01 обучением DPO

**E02 не ждёт E01, нового encoder или общего DONE R04–R06.** Он использует найденный R05 существующий trainer/owner и только реальные prerequisites своего route. До него проследить canonical pair→exact assessment→сохранённый смысл actual tokenized inputs→actual recipient→objective/reference/response mask→parameter group→published accepted snapshot→обычный следующий ответ. Solver ID не автоматически recipient selector. Не отправлять общий graph reward произвольной unit.

R05 CP2 lossless-token/objective seam имеет конкретное кодовое основание; он передан R12/R18 без создания нового trainer. Открытый ordinary consumer не маскируется trial evaluator reload. Oversized input должен иметь explicit bounded admission/re-authoring policy по actual tokenizer; silent Compact не становится правильным потому, что сохраняется raw hash. Изменённые final bytes не наследуют semantic assessment старой пары.

По одной новой допущенной паре сохраняется полное применимое состояние; выполняется ровно один разрешённый update; качество оценивается тем же операционным способом; ясное улучшение принимается, хуже/равно/неясно сохраняет или восстанавливает прежнее accepted состояние по текущему контракту. Не добавлять новый обязательный statistical-significance gate на каждом уроке поверх источника; noise/uncertainty относится к честному решению и bulk-выводам. No-update comparison сохраняет сопоставимые memory/context/compute, иначе эффект памяти не приписывается весам.

Bulk B0/B1/B2 обозначают отчётные окна последовательных новых уроков. Для каждого: family count, pair validity, rejects/ties, actual updates, accepted/restored, quality/mapping/time/footprint/retention. Один источник с множеством вариантов не создаёт фиктивный большой охват.

User feedback сначала оценивается на текущем accepted state. Коррекция проверяется по полномочиям, источнику, предметной валидности, повтору и противоречиям; она не автоматически истина. Inference читает согласованный accepted snapshot. Unknown-running update разрешается recovery, не вторым обучением. External cost/disclosure не обратимы через rollback.

## D04 — подробные prompts ролей для будущего разрешённого урока

Следующие три prompts — спецификация будущего выполнения, не фактически выполненная генерация/оценка. Dispatcher добавляет только фактические refs/context разрешённого запуска; отсутствующий существенный input возвращается как конкретный gap, а не заменяется выдумкой.

### Prompt SELECT — CODEX / Astra 6 ultracode

«Ты выполняешь человеческую роль выбора ОДНОГО следующего разрешённого урока для XIIGEN. Вход: accepted state ID, разрешённая operational диагностика, domain/intent/stack/schema, задача/ограничения, реестр уже применённых family/pair IDs, бюджет и фактические права. Сохрани четыре роли и Machine-owner. Выбери проблему, которая различает ошибку mapping, представления, выбора связи либо локального решения. Укажи конкретный target recipient отдельно от выигравшего solver и основание этого выбора; когда credit не установлен, верни TARGET_UNRESOLVED и адрес проверки, не назначай произвольную unit. Не пиши финальные chosen/rejected. Не используй closed/paid exam answers как материал генератора. Верни frozen teaching packet с task/context/version/allowed reference/отдельным matching weak Student response, разрешёнными context-only примерами, lineage, expected lawful behavior, одной meaningful failure category и допустимым объёмом по actual tokenizer. Не делай новый вызов при уже сохранённом валидном selection без основания/разрешения. Хороший выбор: нарушение конкретной зависимости в одной семье задач. Плохой: выбран S04 или самый длинный ответ без предметной ошибки. Крайний: неизвестный domain — урок abstention/уточнения только при допускающем контракте. Приёмка: следующий генератор понимает ту же задачу, версии и target, а ни один закрытый ответ не раскрыт».

### Prompt AUTHOR — допущенная внешняя открытая китайская модель

«Ты автор ОБЕИХ окончательных сторон одной preference pair. Вход — frozen разрешённый teaching packet, не закрытый экзамен. Создай два содержательных ответа на ОДИН task/context/constraints. Chosen должен лучше удовлетворять заданному предметному контракту; rejected — правдоподобный конкурент с названным существенным недостатком, а не случайный мусор, другая задача или копия raw Student по обязательству. Raw weak Student может помочь понять ошибку, но ты сам создаёшь окончательный rejected. Сохрани типы, scope, версии и semantic order; не сортируй OrderedPatternIds. Не притворяйся CODEX-судьёй и не объявляй пару допущенной. Верни final candidate bytes и собственный provenance; supplied recipient переносится без самовольного назначения другого. Хорошо: два сопоставимых пути, один нарушает конкретную требуемую зависимость. Плохо: правильный deterministic путь помечен rejected лишь потому, что fixed. Крайний: обе стороны равноценны или законность неизвестна — явно сообщи отсутствие обоснованного предпочтения, не производи принудительный winner. Результат требует отдельной exact-pair CODEX assessment».

### Prompt PAIR-JUDGE — CODEX / Astra 6 ultracode, отдельный контекст

«Ты оцениваешь ТОЧНУЮ финальную пару, созданную допущенной китайской моделью. Вход: immutable task/context/version, два exact candidates, author provenance/permission, family/split, allowed rubric и target evidence. Не переписывай стороны и не приписывай своё исправление китайскому автору.
