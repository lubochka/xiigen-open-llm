## 3. Architecture recovered: hybrid, not deterministic-versus-learning

The four roles remain distinct:

- **ILearningUnit** — typed domain/input-vector/output contract and potentially many valid outputs/associations.
- **ILearningFlow** — relationships among Units and correction/translation of one unit's output into another's input.
- **ILearningOrchestrator** — asynchronous composition, branch/order/budget handling and combination selection.
- **ILearningDynamicGraph** — higher-order relationships and reusable compositions across patterns.

Training ownership remains with **ILearningMachine** rather than adding Train to each runtime interface. The current ILogical* names must be mapped by behavior, not renamed merely to match the conceptual names.

The governing hybrid rule is:

`input → deterministic admissibility / schema / safety → learned semantic authority → deterministic projection / integrity → ordinary consumer`.

Deterministic helpers are allowed when they enforce laws, candidate admissibility, type/shape, provenance, rollback, resource bounds or exact computation. A correct deterministic answer is never a bad DPO side merely because it is deterministic. Conversely, randomness or a learned flag is not proof of learning.

## 5. Earliest scientifically useful learning path

The strongest joined evidence points to **reuse of the existing training/publication path**, not a new trainer and not a Windows-first campaign.

### Confirmed near-path

R05 traced an existing path through DPO preparation, policy/reference scoring, backward/update, trial assessment and publication. R04/R06 independently accepted that rebuilding tokenizer/kNN/graph first is not required merely to attempt one valid lesson.

### Three causal seams that must be solved for the selected first recipient

**Seam A — exact assessed distinction must survive projection.** Current `LogicalDpoTrainingUnit.BuildBatch/Compact` collapses whitespace and truncates prompt/chosen/rejected to 480 characters before encoding. A semantically decisive difference outside the retained projection can disappear although the raw pair passport is valid.

**Seam B — the learning objective must match the declared preference objective.** Current `ComputeLogProbs` evidence uses non-empty next-token positions over prompt+response with averaging. The active design expects an explicitly response-conditional preference objective. The exact response boundary/normalization must be specified and implemented consistently for policy and reference.

**Seam C — accepted state must be used by the ordinary consumer being evaluated.** Publication/evaluator reload is not enough. R07's bounded trace found that ordinary CodeDocumentation routing uses a routing-profile state family, while repository-owned LlmModel checkpoint lifecycle exists separately. For graph routing, runtime L2 learned authority→L3 Flow execution exists, but accepted training state→preload/registration is not yet proved. R12 must choose one semantic recipient/state family and close only its actual adoption seam.

### Minimum first-lesson subset

A first lesson is **analysis-ready** when the next analysis rounds can fill concrete values for:

- one permitted domain/task family and one semantic recipient;
- frozen parent state and exact ordinary consumer;
- exact pair/context/provenance;

## 7. Domain mapping, tokenization, vectorization, kNN and LoRA remain first-class research axes

R10 does not collapse these into "embedding quality".

For every domain experiment the later analysis must separate:

1. domain/intent/language/stack mapping;
2. tokenization and semantic feature extraction;
3. vector coordinate/projection space and version;
4. candidate eligibility/pool;
5. distance or learned score;
6. fixed/adaptive/learned k or radius;
7. reranker/final authority;
8. LoRA or other mutable parameter group;
9. typed output projection and ordinary consumer.

Required diagnostic conditions include oracle-domain, predicted-domain and controlled wrong/ambiguous-domain input. A higher retrieval relevance score is not enough; the downstream lawful result must improve under matched resources. LoRA matrix shape does not prove that semantic tokens were transposed correctly.

Dynamic k must be justified per domain/family by density, confidence, law-sensitive features, cost or another stated mechanism. "Threshold changes k" is not automatically learning. For small candidate pools, exact search is a useful diagnostic baseline before ANN/k optimization.

## 8. How DPO quality is examined

A useful preference pair is law-sensitive, not just "good answer vs garbage".

The pair should share task/context/source family and differ on a named domain law or decision boundary. Examples that remain illustrative rather than training data:

- SQL: plausible answer that subtly loses LEFT JOIN outer-row semantics.
- Translation: fluent answer that flips negation/quantity/placeholder.
- Orchestration: same Units but invalid dependency ordering.
- Design-to-Code: visually plausible at one viewport but violates required parent/responsive relation.

Bad pairs include unrelated tasks, nonsense negatives, style/length differences without a domain law, or a deterministic answer marked negative solely because of its origin.

The exact projected representation must preserve the difference before optimizer admission. Pair validity, state mutation and Student utility are separate claims.

## 9. Learning evidence replaces coverage as the learning verdict

Deterministic checks remain appropriate for provenance, permissions, schema, pair identity, no-repeat, state machine, rollback, checkpoint/index compatibility and hard laws.

Learning capability is examined with:

- frozen parent vs challenger;
- same-memory no-update vs update;
- held-out source families;
- mapping accuracy separated from solver quality;
- path/consumer quality;
- bulk-to-bulk curves over **distinct new admitted lessons**;
- worst-domain retention;
- time-to-quality;
- p50/p95 inference where relevant;
- peak RAM/VRAM, persistent bytes, reindex/reload cost;
- IMPROVE / REGRESS / INCONCLUSIVE / INVALID_EVIDENCE verdicts.

A green Windows run, test count, pair count, changed hash, lower training loss or new checkpoint alone cannot close learning acceptance.

### 13.2 Functional expectation matrix must survive the join

R10 requires all later analysis to preserve and distinguish these causal objects:

| Capability | Deterministic part that may be checked directly | Learned/non-deterministic capability that must be examined | Minimum causal comparison |
|---|---|---|---|
| **ILearningUnit** | types, domain/version compatibility, admissibility, many→many shape/association | domain-sensitive mapping from input representation to useful typed results | frozen parent vs updated Unit on held-out families with the ordinary consumer |
| **ILearningFlow** | port compatibility, allowed transforms, dependency legality | learned relation/correction between Units | frozen Units + changed Flow, then changed Unit + frozen Flow as contrast |
| **ILearningOrchestrator** | async safety, branch limits, cancellation, hard resource bounds | selection/order/continuation of combinations under quality+cost objective | same candidate set/budget; compare total branch cost and lawful output |
| **ILearningDynamicGraph** | graph/schema/version integrity and allowed relation types | higher-order reusable relations/compositions | same primitives; changed higher-order relation; test unseen compositions |
| **Domain mapping** | label/schema validity | correct domain/intent/language/stack inference | oracle-domain vs predicted-domain vs controlled wrong/ambiguous domain |
| **Token/vector projection** | shape/version/checkpoint compatibility | preservation of domain-law distinctions in semantic coordinates | same pair/task with current vs distinction-preserving projection |
| **Dynamic kNN** | legal pool, index integrity, exact-search baseline | domain-sensitive metric/k/radius/neighbor policy | fixed vs adaptive/learned policy on the same pool/resources |
| **DPO** | provenance, exact pair bytes/context, no-repeat, state/rollback | useful preference update that improves Student behavior | frozen parent + same-memory no-update + admitted-update challenger |
| **LoRA / mutable parameters** | adapter ownership/version and tensor compatibility | semantic effect of the adapted parameter group | frozen vs adapted state with same retrieval/context and held-out families |

Changed hash, green CI, changed tensor shape, lower training loss, successful publication, higher retrieval similarity or more graph edges **cannot alone close any learned-capability row**.
