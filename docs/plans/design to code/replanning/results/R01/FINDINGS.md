## F08. Найдено расхождение пользовательских ролевых имён и реальных контрактов

Core `00.Core/LogicalContracts.cs`, строки 1–145, прочитаны напрямую. Реальная декларация `ILogicalUnit<TInput,TOutput>.ExecuteAsync` принимает типизированный `LogicalUnitRequest<TInput>` и возвращает `Task<OperationResult<LogicalUnitResult<TOutput>>>`. В envelope есть DomainTag, flags, metadata; результат имеет confidence, predicates/domains/evidence и необязательный transition signal.

Это не буквальная декларация пользовательского `ILearningUnit` и не доказательство реализованного many→many IQueryable-пути. R02/R04 должны сопоставить роль с действительным типом, множественностью payload и реальным consumer; переименование абстракции или объявление потери функциональности только по сигнатуре запрещено. R06 проверяет async-композицию по собственным источникам.

Core `00.Core/LearningMachineContracts.cs`, строки 1–170, прочитаны напрямую. Комментарии A-LM-01/A-LM-02 закрепляют ILearningMachine выше ILogicalOrchestrator и Train только у ILearningMachine, не Unit/Flow. Это уже существующее архитектурное решение, которое нельзя потерять при новом описании четырёх уровней. Декларации LearningBatch/LearningBatchResult сами по себе не разрешают replay и не доказывают нынешнюю policy одной пары. Владелец сверки актуального update — R05; решений о миграции — R12/R16.

## F12. Восстановлен первичный план LearningMachine, а не новая замена архитектуры

Источник: core `docs/plans/ARCHITECT-PLAN-LEARNING-MACHINE-EVOLUTION-v1.md`, ветка `codex/dpo-implementation`. Прямой API fetch вернул разделы 1–4; дополнительный `fetch_file` подтвердил строки 85–210 и blob `8ff04c8a6d869269c2cd2ee0364848516ab0925a`. Внутренняя дата проектирования — 2026-05-28, не дата нынешней реализации.

В разделе 2 обучение принадлежит `ILearningMachine<TDomain>`; runtime-иерархия остаётся `ILogicalOrchestrator → ILogicalFlow → ILogicalUnit`. `GetOrchestratorAsync()` должен отдавать исполнителя, использующего обученное состояние. План предусматривает независимый от исполнения training bridge, измерения before/after, экспорт/импорт, общий ModelServer и пару personal/global с анонимизированным обменом. Это первичное обоснование сохранённого в F08 решения, а не предложение заново добавить уже существующие контракты.

Содержательная проблема для дальнейшей сверки: исторический раздел 3 предлагает проверять, что ответы bootstrap и trained реализации различаются. Различие ответа само по себе не доказывает улучшение. Аналогично историческая фраза «нет top-level interface» в разделе 1.5 не описывает сегодняшний код: F08 уже содержит декларацию LearningMachine.
