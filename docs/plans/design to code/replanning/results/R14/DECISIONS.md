# R14 DECISIONS — capability-first queue

## D-R14-01 — capability DAG replaces both slice-number order and a fixed M0→M7 tunnel
The active structure is a capability DAG plus an E1–E4 candidate queue. Old slice IDs remain traceability keys; they are not deleted. M0–M7 labels describe capability/claim nodes, not an unconditional execution sequence.

## D-R14-02 — first-lesson readiness and whole-delivery readiness are separate
M0 may proceed once its exact learner seam and R13 recipe are valid. DTC/IDE/native/full curriculum/full graph stay owned but do not block M0 without a causal dependency.

## D-R14-03 — Windows/coverage are not universal learning gates
Keep deterministic/native checks for the properties they actually prove. They cannot close learning efficacy.

## D-R14-04 — DPO role split is locked
CODEX GPT-6 Astra UltraCode performs human lesson selection and separate exact-pair quality judgment. External open Chinese model authors both final chosen and rejected. Student learns from admitted material.

## D-R14-05 — domain/vector/kNN/LoRA are explicit capabilities, not indefinite later optimization
M2 must address domain mapping, law-preserving representation, candidate/retrieval policy, dynamic-k hypotheses and learned projection/LoRA semantics with causal experiments.

## D-R14-06 — four learning roles remain distinct
Unit, Flow, Orchestrator and DynamicGraph each require their own state/signal/consumer/falsifier. One improved DPO checkpoint cannot prove all four.

## D-R14-07 — first experiment result controls the next seam
IMPROVE, REGRESS, INCONCLUSIVE and INVALID_EVIDENCE have different next actions. No branch automatically restarts full planning.

## D-R14-08 — existing code is reused before new framework work
A new trainer, tokenizer stack, vector database or graph framework is not built unless the selected capability proves the existing path insufficient.

## D-R14-09 — second structurally different domain gates broad-transfer claims
After the first valid positive observation, a structurally different domain/source family is required before claiming broad transfer. It does not block an independent E2/E3/E4 investigation whose own causal prerequisites are satisfied. Same-family paraphrase breadth is insufficient.

## D-R14-10 — PC continual learning is measured as full-system cost
Checkpoint size alone is not compactness. M6 includes model/reference/adapters/optimizer/index/graph/cache/snapshots/evaluation and failed attempts.

## D-R14-11 — upstream gaps are localized and R13 is no longer missing
R13 is observed and its E1–E4 protocol is current input. R12-F still must bind exact architecture recipient/state/consumer for candidates that depend on it; numeric domain thresholds are bound before execution by the domain/experiment owners. These gaps do not invalidate the capability DAG.

## D-R14-12 — DTC/IDE/native obligations are preserved
They move to explicit capability triggers rather than disappearing because they do not measure learning.

## D-R14-13 — old IDs cannot be removed as duplicates without equivalence evidence
REMOVE_DUPLICATE/REPLACE_DUPLICATE requires source-bound proof of functional equivalence and a surviving owner/consumer.

## D-R14-14 — learning evidence remains empirical
All algorithm gains, domain accuracy improvements, best dynamic-k values, LoRA utility and PC-fit are NOT_MEASURED until real controlled observations exist.

## D-R14-15 — first experiment is selected by information gain per implementation cost
Rank E1 DPO, E2 domain/vector/dynamic-kNN, E3 Flow/Orchestrator and E4 DynamicGraph against causal validity, reusable seam, ordinary consumer, lawful panel, confounders, PC cost and invalid-evidence risk. E1 is not automatically first.

## D-R14-16 — concurrent R01–R06 evidence is admissible with attribution
A sibling run need not be globally DONE for its published current finding to be consumed. Preserve its status and evidence scope; do not turn PARTIAL into completion, but do not ignore current R04–R06 algorithm findings while replanning.

## D-R14-17 — selected execution packet must be model-ready
The selected packet must contain prompt, context, skills, RAG/primary references, exact seam, examples, edge cases, one changed factor, frozen controls, functional examination, ordinary-consumer check, outcome branches, resource metrics, and allowed/forbidden scope. Test coverage is never the learning acceptance criterion.
