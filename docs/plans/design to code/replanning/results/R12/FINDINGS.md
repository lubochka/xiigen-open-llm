## Главный вывод для человека

Системе нужен не «один DPO-тренер вместо четырёх уровней» и не четыре новых тренера. Нужна одна обучающая инфраструктура с различными **адресатами улучшения**: (1) полезность отдельных typed Unit-результатов, (2) исправление связи Unit→Unit, (3) выбор допустимой асинхронной комбинации и (4) перенос связей паттернов более высокого порядка. Закон домена и финальный arbiter проверяют допустимость; обучаемая часть выбирает, уточняет и переупорядочивает действия *внутри допустимого пространства*. Правильный детерминированный результат остаётся положительным.

В текущем core уже есть usable строительные блоки: ILogicalUnit envelopes, DpoTrainer и LoRA, DomainClassifierUnit, KnnLogicalUnit+HNSW, TrainableRoutingFlow, edge-authority pipeline и L3 selected-target executor. Но их наличие **не равно** проверенной способности обучаться всем четырём поведениям. DynamicGraphMachine сообщает RuntimeMode=honest_untrained и TRAINING_NOT_ACTIVATED; ordinary CodeDocumentationRoutingFlow не доказан потребителем выбранного DPO policy checkpoint. Нельзя замыкать эти недоказанные мосты словами «уже реализовано».

## R12-B. Полная причинная архитектура

Читаемый маршрут (Graph specialization can participate in selecting routes but is **not mandatory on every request**):

1. Вход: оригинальный запрос и происхождение/права → identity (domain family, intent, project, stack, language, desired output type, source rights). Stack markers extracted before lossy normalization.
2. Semantic compiler maps original meaning/constraints/order into versioned predicates/edges. Predicted-domain plus unknown/mixed path; no forced nearest domain.
3. **Deterministic layer** builds lawful candidate sets; domain-specific representation and retrieval (BM25/exact/HNSW; positive/negative/warning histories) offer evidence, *not* acceptance.
4. **ILearningUnit** returns typed many→many candidates + stable associations/evidence. A current ILogicalUnit<TInput,TOutput> returns one LogicalUnitResult<TOutput>; multi-association envelope is **PROPOSED compatibility layer**, not assumed existing public API.
5. **ILearningFlow** corrects/links Unit outputs by admissible typed ports, preserves meaning, dependencies and alternatives. Learned relation state changes which lawful relation/correction is preferred.
6. **ILearningOrchestrator** selects and asynchronously executes viable Unit/Flow combinations with dependency DAG, fan-out/fan-in, cancel, resource/permission limits. Learned path policy changes ordering/stop/branch choice, not hard validation.
7. **ILearningDynamicGraph** represents ordered higher-order pattern relations across runs/domains, proposes transferable lawful compositions. Actual DynamicGraphMachine L5 training is **not activated**; later learned graph weights/edges require a real trainer update, persistent state and ordinary L2/L3 adoption.
8. Arbiters validate formal output; rejected results return to explicit reprocess/clarify route. Valid final results go to user/application. User consented feedback enters a distinct validated teaching queue; it is not automatic optimizer admission.

**One training infrastructure:** ILearningMachine/trainer owns explicit updates of named parameter groups; Unit/Flow/Orchestrator/Graph are *learning targets / consumers*, not four uncoordinated trainers. Per-target objective and checkpoint namespace prevent CodeDocumentation solver weights from being mislabeled trained graph authority.

### Four causal contracts (exact behavior + current code vs target)

**B1 — ILearningUnit: typed many→many.** Input = (domain law version, vector/token schema, input type, requested output type, raw/source identity, constraints). Deterministic = schema/type/rights/association/law filtering and safe fallback. Learned = explicit Unit policy weights or indexed example representation/rerank state, scoped to UnitId+domain+schema; ordinary output = list of typed alternatives with stable association IDs, scores, provenance and uncertainty, not merely top-1. Signal = accepted lawful output choice, exact domain critique or response-conditioned DPO for *that actual Unit model*. Update owner = existing ILearningMachine/trainer or explicit versioned KNN memory learner; never inferred solely from UnitId string. Mutation/version = accepted adapter/index + tokenizer/codebook/manifest/rollback; ordinary consumer = ILogicalUnit invocation plus a proposed many-to-many compatibility adapter; falsifier = weights changed but selected typed output/utility at frozen law and input did not, or associations/order are lost. CODE: 00.Core/LogicalContracts.cs contains ILogicalUnit single-result envelope; 21.../KnnLogicalUnit.cs trained HNSW+BPE and uses first neighbour; 18.../LlmIngredientLogicalUnits.cs owns DPO batch producer. **STATUS PARTIAL/PROPOSED.**

**B2 — ILearningFlow: relation/correction.** Input = typed Unit outputs/association IDs, compatible input/output ports, claimed invariants, ordered dependencies and correction context. Deterministic = legal port type, edge conditions, dependency preservation, semantic loss guard. Learned = relation score/correction policy, versioned separately from Unit solvers; objective = prefer successful lawful transition/repair with same frozen Units and same source; output = corrected edges and documented alternatives. Update via actual authority owner, not updating winning solver. Ordinary consumer = ILogicalFlow/TrainableRoutingFlow and downstream selected-target execution once state adoption is wired; falsifier = identical Unit results + different learned relation state produce no route/quality effect, or the result never reaches consumer. Current TrainableRoutingFlow has scorer/thresholds/KnowledgeEdge; it does not by its name establish a trained corrective relation. **STATUS PARTIAL/PROPOSED.**

**B3 — ILearningOrchestrator: async compositions.** Input = candidate DAG with costs, independent/dependent Units/Flows, hard deadlines/grants/budget. Deterministic = dependency ordering, safe cancellation, idempotent side effects, arbiter acceptance, timeout/fail-safe. Learned = policy for branch ordering, fan-out size, early stop, correction path and expected incremental utility; objective = accepted correct result per total time/memory/permission-safe execution, compare same frozen solvers. Update only the orchestrator policy state through named owner; ordinary consumer = ILogicalOrchestrator/DynamicGraphLogicalOrchestratorRuntime where actual async execution trace is observed. Outputs = winning *valid* path, rejected alternatives and reasons, cost, versions. Falsifier = improved solver alone explains effect, route unchanged, cancellation not executed, or policy never used. **STATUS PARTIAL/PROPOSED**; async composition ≠ merely changing score after fact.

**B4 — ILearningDynamicGraph: higher-order transferable relations.** Input = admitted ordered lower-level patterns, domain laws, edge/success/failure provenance, degree of composition. Deterministic = valid ordered pattern IDs, typed edge and permission checks, no cycle/dependency violation; learned = edge-authority/higher-order motif or adapter state, conditional on lawful context; objective = transfer success on *unseen* composition while Unit/Flow/Orchestrator parameter groups frozen. Update via a real ILearningMachine training owner, persistent graph-adapter/index state, safe rollback; ordinary consumer = RegistryDynamicGraphEdgeAuthorityResolver → EdgeAuthorityExecutionPipeline → L3 selected-target executor after verified trusted preload and checkpoint mapping. Graph advisory memory precedes arbiter verdict. Falsifier = only memorized path wins, graph state never loaded, or lower-level solver changed simultaneously. CODE DynamicGraphMachine has explicit TRAINING_NOT_ACTIVATED. **STATUS INTERFACE/EXECUTION COMPONENTS EXIST, LEARNING PROPOSED/NOT ACTIVATED.**

## R12-C. Correct DPO and independent judgment

Student weakness can be context; Student output is not automatically final rejected. This R12 documentation is not an actual invocation of those models.

**Proposed state machine (per unique pair_id):** weakness/feedback detected → CASE_ELIGIBILITY (rights, novelty, disjoint held-out) → CODEX_CASE_SELECTED (persist exact decision and source bindings) → TEACHER_AUTHORIZED (license, service terms, model digest and context consent) → CHINESE_BOTH_SIDES_GENERATED (byte-preserved) → CODEX_PAIR_ASSESSED → either REJECTED_AS_LESSON (TIE/BOTH_BAD/UNJUDGEABLE/invalid) or PAIR_ADMITTED → PARENT_DURABLY_SNAPSHOTTED → APPLIED_ONCE to explicit parameter group → CANDIDATE_CHECKPOINT_SEALED → ORDINARY_CONSUMER_REOPENED → FROZEN_PANEL_EVALUATED → PROMOTE / KEEP_PARENT / ROLLBACK / INCONCLUSIVE. Crashed UNKNOWN outcome = recovery/readback, never second blind application. Each transition has committed journal and actor authority.

**Pair passport fields:** pair_id/lesson_id, case selection decision id and CODEX model+reasoning mode, domain family+intent+stack+language, input/output schema and law version, raw task/context bytes hash, external model/provider/license/service permit/model digest, chosen/rejected raw hashes+author identities+generation IDs, exact judge-view projected prompt/answer representation hashes, CODEX pair judgment/rubric/verdict/evidence, tokenizer+codebook+max context/response mask/EOS/length strategy, reference-policy parent and target parameter-group identity, rights/no-repeat/holdout flags, admission lease, parent and candidate full-state manifest, ordinary consumer and downstream artifact version, outcome and rollback journal. A lossy projection or changed whitespace invalidates old assessment until re-judged; merely copying raw SHA into the passport does not repair a changed batch.

**Preferred objective, once recipient is verified:** standard response-conditioned DPO, loss = −log σ(m), where m = β[(log πθ(y+|x) − log πref(y+|x)) − (log πθ(y−|x) − log πref(y−|x))]. πref is frozen from compatible parent. For each side, only response targets after the exact prompt boundary contribute; context is conditioning input but not counted in response loss. Bind explicit tokenizer boundary markers, response target mask, BOS/EOS policy, pad exclusion, empty/oversize reject-or-rejudge branch and *the same* sum/length normalization for forward and backward. Prefer whole-response log-likelihood (sum) for canonical DPO; if length-normalized variant is chosen, it is a separately named and measured objective, not silently called equivalent. β fixed in a candidate and chosen before observing evaluation; zero margin when policy=reference is mathematically normal, not grounds for semantic rejection. Preserve public EvaluateAverageNextTokenLogProbability behavior unless separately versioned.

## R12-D. Domain mapping, law-aware vectors and learnable dynamic kNN

A domain is not a single string label. Classification dimensions: domain family, task intent, stack/version, language pair, project/slice and output role. For mixed queries retain multiple domain hypotheses and scoped lawful candidate pools. Unknown/OOD = abstain/clarify/knowledge-edge route, not forced nearest match. Compare predicted-domain and oracle-domain copies to isolate mapping error.

Representation contract per domain d:
- raw bytes + source/rights hashes (immutable);
- canonical meaning/predicate/ordered-edge IR with forbidden-loss rules, compiler/index version;
- text tokenizer and domain-specific structural tokens/codebook (may differ by language/stack);
- semantic features with law/provenance flags;
- vector schema/dimensions/normalization/metric version, domain/index version;
- retrieved positives, hard negatives and warning-only memories with disjoint roles.

| Family | Hard deterministic laws / what must never vanish | Candidate vector/token emphasis | Good vs bad diagnostic contrast |
|---|---|---|---|
| EN↔RU translations | negation, actor, quantity, tense scope, placeholders, protected names, direction | aligned bilingual concepts, morphology, slots, order/dependency and token identity | Preserve “not more than 3 {0}” vs “more than 3 {0}”; superficially similar bad translation must not win |
| C# documentation | public API semantics, nullability, exception/effect evidence, async and version/caller | AST symbols/types, call edges, async/result contracts + text | Async method documenting a fabricated synchronous DB write is negative |
| Angular documentation | component lifecycle, signals/observables, actual HTTP vs local state, version | TS symbols, template binding, signal dependencies, side effect evidence | Description invents HTTP call where code only mutates signals |
| SQL / stored procedure docs | transaction boundaries, WHERE, JOIN keys, security/parameters, null semantics, affected rows | query AST, predicate/selectivity, parameter types, dependency graph | DELETE with/without WHERE cannot become near-equal because vocabulary overlaps |
| Figma→HTML/CSS | original hierarchy, constraints, screen sizes, accessibility, design tokens and responsive semantics | tree/layout vectors, hierarchy/order, CSS constraints and screenshot evidence | Pixel-close single viewport but broken mobile/layout hierarchy must not pass |
| Programming orchestration | dependency DAG, input/output contracts, source/permission/order, branch cancellation | task graph motifs, typed transitions, source-status and cost | Running deploy before validated build cannot be accepted for lower latency |
| DPO Builder / mixed cross-domain | provenance of chosen/rejected, admissible lesson rights, new lesson identity, per-domain law | curriculum/weakness, negative type, learning target, adapter/recipient identity | One lesson on SQL+Angular combines lawful units without changing hidden exam answer |

**Candidate algorithm, not measured optimum.** First compute admissible(d,q,n) deterministic, excluding wrong rights/types/constraints. Generate candidate pool with domain-scoped BM25 plus existing fixed-vector ANN and a small exact-search reference. For lawful candidates, let φ(q,n,d) include calibrated lexical match, semantic similarity, law-feature match, structural/intent agreement, source-family independence and historical warning/arbiter features. Learned nonnegative bounded weights wθ(q,d), normalized per query, produce scoreθ(q,n,d)=Σj wθ,j(q,d)·φj(q,n,d). Train weights/reranker on distinct adjudicated lawful choice contrasts; use failure memories for *warnings* and legally admissible negatives, not as accepted targets.

Select k dynamically only **after** a real multi-neighbour consumer exists: kθ(q,d) = clamp[kmin(d),kmax(d)] of a budget/uncertainty/diversity policy; stopping considers calibrated gap, source diversity, available time and risk but cannot turn fail into pass. A fixed-k baseline, exact unbounded diagnostic and an ablation with fixed learned rerank isolate which component helps. Candidate re-ranking can use query-dependent nonmetric features; existing HNSW geometry cannot silently implement arbitrary new score. Use ANN only to generate a larger pool under a fixed compatible index and rerank outside it, or validate a rebuilt metric/index/version with separate reindex costs. New k alone is **not learning**, and warning+answer is **not abstention**.

## R12-E. LoRA is a parameterization, not vector meaning; PC learning is full-state

Existing 10.LoRA/LoraLinear.cs implements frozen-supplied base projection + low-rank A/B residual (B zero-init) and seeded/dropout paths. It does **not** by itself establish an input tokenizer, a domain embedding contract or projection from a solver answer to requested typed vector. Proposed learned ResultProjection_d must name:
- source: versioned typed solver output + canonical semantic IR/provenance;
- target: dimensioned domain/intent token-vector codebook with law-preserving labels and output association;
- trainable parameters: named projection matrix or low-rank A/B on that matrix, separate from solver/Flow/Graph unless actual joint objective approved;
- frozen control: base/tokenizer/legal compiler/held-out datasets;
- loss: contrastive semantic/typed retrieval or source-aligned reconstruction + law violation penalty, chosen before runs (not generic DPO by name);
- consumer: explicit downstream Unit/Flow retrieval/association method, not a discarded exported vector;
- versions: tokenizer, codebook, projector, index, base, adapter, schema and checkpoint mutually compatible;
- rollback/reindex: atomic compatible bundle, full index migration/effect receipt.

An adapter may reduce trainable parameters yet still collapse “NOT”, ordering or SQL predicate relations. **Only frozen domain-law counterexamples and downstream response quality** can establish semantic usefulness.

PC budget must measure peak/resident RAM, peak VRAM, disk for base+reference+adapters+optimizer/scheduler+activations/KV+tokenizer/codebooks+indices+graph+cache+pair manifests+snapshots+reindex copies; as well as cold-load time, teacher/assessor/evaluator wall time, train per unique pair, ordinary inference p50/p95, budget exceedances, energy if observable and storage growth per bulk. Historic Qwen local hardware/context suggestions and old 2 MB adapter estimate are **proposals**, not proof of current fit; training model, teacher model and judge can have different residency/cost. Pair state and checkpoint must reopen from disk and continue without resetting accepted knowledge. User feedback is filtered by consent/rights/source fidelity/novelty/conflict/holdout before becoming a *new* lesson; never silently reapply an old pair.

## R12-F. Three end-to-end walkthroughs, causal alternatives and concrete handoff

**F1 — single-domain law.** User requests RU translation of “You may not withdraw more than 3 items; keep {0}”. Classifier returns Translation/EN→RU, laws preserve negation, limit and placeholder. Frozen EN↔RU held-out family must improve through the actual translation consumer before any claimed learning.

**F2 — mixed domain/dependencies.** User asks for Angular form and SQL stored procedure docs explaining a validated field. Orchestrator can concurrently inspect independent code sources but waits for signature before final cross-reference; only lawful DAG paths can win. Learned Flow experiment freezes both Unit outputs to see whether relation corrections alone improve quality; learned Orchestrator experiment freezes Unit and Flow to test branch cost/order. Correct fast SQL-only answer is rejected if Angular requirement omitted; a slower lawful deterministic route is allowed.

**F3 — unseen lawful composition.** Figma design tree + server C# DTO + Angular component → responsive HTML/CSS and compatible documentation. Pattern graph observes previously accepted Unit/Flow patterns but the held-out *composition of patterns* must not appear in training. DynamicGraph proposes a typed high-order relation (layout→binding→documentation) and selected-target executor applies it after lawful admission. Compare same lower-level weights and source budget with/without accepted graph adapter; if only copied original pattern works, no transfer gain.
