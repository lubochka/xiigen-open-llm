## D-R09-02 — Keep deterministic safeguards; stop using them as learning proof

**KEEP:** provenance, permissions, immutable state, pair identity/no-repeat, rollback/recovery, storage bounds, real native process/security properties.

**NOT learning evidence:** green count, coverage, changed route ID, new weights file, lower DPO loss by itself. Learning verdict — controlled behavior, не наличие механизма.

## D-R09-03 — Global “tests are being fitted” claim remains INCONCLUSIVE

Один RED→GREEN episode недостаточен. Нужна exact chain requirement→assertion→diff→authority. До такой трассы запрещено предполагать, что каждый failed test фиктивен.

**Corrected RCOR wording:** объём review/evidence artifacts поддерживает process-overhead risk, но не измеренный bottleneck/время труда/экономию. Оптимизация causal dependencies не требует обвинительного test-fitting verdict или неподтверждённых CI ratios.

## D-R09-04 — First learning path reuses existing DPO implementation

R05 code trace — attributed baseline. Не создавать новый trainer/framework до проверки exact-pair representation, response-conditional objective и ordinary consumer. Использовать поздние source-backed R18 additions; старое NOT_TRACED не означает отсутствия generator во всём repo.

**Последовательность:** parent baseline → допустимая exact pair → one bounded update → isolated candidate evaluation → accept/retain/recover → cold ordinary selected-state use. Не менять порядок на promotion-before-evaluation.

## D-R09-05 — Learning acceptance is functional and empirical

Требуются parent/candidate, same-memory/context/compute no-update control, independent held-out families, quality/domain/path/retention metrics, full time/resource accounting и predeclared IMPROVE/REGRESS/INCONCLUSIVE/INVALID_EVIDENCE. Stable anchor между bulk; вариации одной family не independent samples. Unit-test coverage не закрывает utility. Валидный отрицательный опыт завершает опыт, не requirement доказанного improvement.
