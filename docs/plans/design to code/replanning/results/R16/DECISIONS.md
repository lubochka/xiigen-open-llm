## D-R16-01 — learning efficacy is a behavioral/functional claim

Coverage, build, hash changes, loss decrease, nonzero gradient or Windows success cannot close a learning-efficacy requirement by themselves.

## D-R16-02 — valid negative experiments are completion

A correctly run experiment may finish as REGRESS or INCONCLUSIVE. The bad candidate is not promoted; parent is retained/restored. This is not a failed planning task.

## D-R16-03 — invalid evidence is not negative evidence

Leakage, incomparable panels, wrong pair projection, unknown state or incompatible representation produce INVALID_EVIDENCE. Fix the experiment; do not lower the threshold.

## D-R16-04 — one-pair/no-repeat remains current

One new pair_id gets one authorized application. Bulk is an observation block of unique new lessons, not an implicit replay/minibatch authorization. Historical 70/30 replay remains non-current for continual-learning evidence until an explicit owner migration decision exists.

## D-R16-05 — 95% remains a product goal, not a proxy

95% refers to the applicable owner-defined domain reference/rubric. It is not router confidence, coverage, test pass rate or a mandatory prerequisite for the first causal learning observation.

## D-R16-06 — deterministic + learned is the architecture

Hard domain laws, types, admissibility, schema/version compatibility, safety and final arbitration remain deterministic. Learned state may map/rank/adapt/select only inside the lawful space.

## D-R16-07 — four learning roles remain distinct

ILearningUnit, ILearningFlow, ILearningOrchestrator and ILearningDynamicGraph need separate owner/state/signal/consumer/falsifier contracts. Improvement in one does not prove another.

## D-R16-08 — domain mapping and representation are measured capabilities

Predicted vs oracle domain, mixed/unknown input, law-sensitive representation, token/feature/vector/index identity and ordinary consumer effects must be examinable separately.

## D-R16-09 — dynamic kNN needs learned authority

Manual k/radius/threshold changes are configuration. A learned dynamic policy requires a signal, mutable state/update owner, consumer and causal contrast against fixed/exact references.

## D-R16-10 — LoRA is not tokenizer semantics

Every learned projection names source/target space, trainable group, frozen state, objective, version, consumer, rollback and index migration/compatibility.

## D-R16-11 — DPO roles stay locked

## D-R16-12 — pair validity and Student utility are different

A semantically valid DPO pair may yield no useful Student gain. Pair assessment happens before update; utility is measured after update on independent families.

## D-R16-13 — PC compactness is full-system cost

Measure base/reference, adapters, optimizer/activations, tokenizer/encoder/codebook where applicable, index, graph, cache, snapshots, reindex, failed attempts, evaluation and persistent growth.
