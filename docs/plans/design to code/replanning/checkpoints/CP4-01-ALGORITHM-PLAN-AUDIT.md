## Неизменяемые функциональные ожидания этого уточнения

| Блок / механизм | Что должно остаться в заданиях и будущем наблюдении |
|---|---|
| ILearningUnit | Domain, input/vector/output schema; typed many→many, queryable results и materialization/consumer. Сопоставление с фактическими C# именами отдельно от пользовательских aliases. |
| ILearningFlow | Связи между Unit и коррекция input→output; кто предлагает допустимые связи, кто обучаемо выбирает их, куда доходит сигнал качества. |
| ILearningOrchestrator | Асинхронные комбинации, состояние и границы обработки, итоговая полезность и полная цена маршрута, а не только удачный запуск. |
| ILearningDynamicGraph | Паттерны разных порядков, обучаемое изменение отношений и перенос; не объявлять графом фиксированный маршрут и не создавать новый trainer без решения владельца. |
| Domain / representation / dynamic kNN | Domain и intent отдельно; признаки и законы домена; версия векторного пространства; pool/metric/k/policy/memory/final arbiter; оценка неверной маршрутизации и неизвестного домена. |
| DPO | Источник пары, chosen/rejected и основания предпочтения; TIE/BOTH_BAD/unknown; применимый objective/reference; pair→actual state mutation→обычный consumer. Невалидная пара не становится учебным материалом ради объёма. |
| LoRA | Точная изменяемая проекция и её consumer; смысл и совместимость представления, а не только shape/loss/hash. LoRA не тождественна tokenizer. |
| Обучение на ПК | Полный runtime/model/adapters/index/graph/snapshot footprint, end-to-end время, качество и retention по каждому домену. Никаких выдуманных измерений. |
| Пользовательское продолжение | Сначала оценка нового входа, затем допуск коррекции/пары и обучение; сохранённое состояние, admission и rollback. Bulk не отменяет действующий one-pair/no-repeat. |

## Что должно получиться из оставшейся работы над планом

Не ещё одна общая декларация, а точечное устранение установленных пробелов: для каждого затронутого Rxx — конкретный алгоритмический вопрос, источник/диапазон, детальный prompt, actual skills, выход, хороший и плохой пример, edge case, документная приёмка сегодня и будущий различающий learning experiment с owner. Если содержание уже есть и пригодно, сохранить его и указать единственный действующий маршрут, а не размножать карточки.

Проверить связь четырёх уровней с DPO/LoRA/kNN и причинное влияние каждого обучаемого состояния. Разделить: восстановленное требование, найденный контракт, реально прослеженный код, гипотеза об улучшении, измеренный результат. Предпочесть первый минимальный реализуемый учебный маршрут общей полировке, но не удалять конечные DTC/IDE/domain obligations.
