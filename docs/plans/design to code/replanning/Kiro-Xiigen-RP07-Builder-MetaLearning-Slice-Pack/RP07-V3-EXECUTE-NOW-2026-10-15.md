## Детерминированное + обучаемое: нельзя смешивать получателей
- **RP02**: domain identification+UNKNOWN, law versions, semantic token/vector & referent/role, law-first candidate gate, реально используемые **несколько соседей**, адаптивное k, learned rerank, LoRA alignment только при фактическом изменении параметров и определённом получателе.
- **RP03**: `ILearningUnit` typed domain/vector/input→many-to-many outputs, `ILearningFlow` коррекции связей Unit; каждый имеет свой state/signal/update.
- **RP04**: `ILearningOrchestrator` асинхронный dependent/budget/cancellation path и `ILearningDynamicGraph` higher-order composition; graph route output ≠ Builder gradient.
- **RP01**: Student DPO objective, exact judged pair, optimizer, reference, LoRA state; **RP05**: feedback→continuation→rollback/PC/cold adoption; **RP07**: Builder *педагогическая* политика, обучаемая на независимом downstream выигрыше Student, не на pair judge score.
Hard domain/type/rights/admissibility laws фильтруют кандидатов **до** learned scoring. Близость kNN не заменяет падеж, согласование кореференции, SQL NULL, cancellation, input/output typing, authorization. LoRA — параметризованная адаптация, а не просто vector-token ID.
