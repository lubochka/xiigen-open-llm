## Computation contract: deterministic rules plus learned decisions

1. Ordinary request → subject(s), task intent(s), answer/source language and direction, stack/dialect/version, output type, uncertainty. Rights are trusted metadata, never inferred access from a user-supplied domain hint.
2. Establish authorized source/tenant/type/partition/coordinate eligibility **before candidate access**. Use a verified eligible partition or equivalent access-safe retrieval. Do not retrieve private data globally and hide it only at final output.
3. Extract domain features ψ from history and candidate: semantic similarity plus actually computable AST/POS/dependency/referent/negation/type/version distinctions and explicit UNKNOWN masks. A first pilot may use similarity and two relevant law features; it must not claim full grammar coverage.
4. Search the eligible recall pool with exact or ANN retrieval. Semantic law scoring need not be an index metric: use a fixed compatible recall representation plus contextual reranker initially. Query-dependent nonmetric scores are not silently installed as HNSW geometry.
5. Apply source-established hard laws only when their assumptions are known. Uncertain parses/referents produce soft hypotheses, not an invented hard veto. Rank lawful same-type alternatives with named θ. Positive memory informs what to produce; authorized negative-role memory informs what to avoid; warning memory informs risk. Negative evidence is not accepted positive output. Final arbiter remains authoritative.
6. Select a typed answer, next AST/action/role, or justified abstention. Distinguish selected one-of-many from optional typed evidence fusion and from RP03 many→many. Provenance/evidence-ID count alone is not neighbor influence.
7. New admissible preference → named learner update → versioned trial checkpoint → isolated cold examination → accept parent or challenger → ordinary cold adoption. User feedback reuses this cycle, not a second trainer.

## First θ learner: concrete proposed equation

For same query/context/type/domain/schema `(q,z+,z−)`, compute `d = ψ(q,z+) − ψ(q,z−)` in fixed coordinates. Initial compact candidate model is `sθ(q,z)=θ·ψ(q,z)` with no unidentifiable common intercept. Objective `L=softplus(−θ·d)+λ||θ||²/2`; gradient `g=−sigmoid(−θ·d)d+λθ`; bounded SGD `θ1=θ0−η clip_norm(g,G)`. η, λ, G, normalization and parameter ownership are fixed on TRAIN/OP_DEV before the trial, not selected from SEALED. Stable sigmoid/softplus and finite inputs/outputs are required.

Diagnostic arithmetic, **not a required optimizer setting and not a hidden exam**: with θ0=(0,0), d=(1,−1), λ=0, η=0.1 and inactive clipping, g=(−0.5,0.5), θ1=(0.05,−0.05), margin=0.1. This checks direction; it does not establish semantic usefulness. Equal feature deltas cannot teach this scorer. A regularization-only change on d=0 is not a preference-learning success. Rank loss is distinct from RP01 response-DPO policy/reference log-ratio.

Persist parent, trial θ, feature/tokenizer/index versions, immutable eligible-corpus identity and durable applied-pair lineage; include optimizer/RNG/counters only when mutable. Once identity includes actual semantic lesson/content and target lineage, not just a renamed pair_id; it must not permit retry merely because the parent hash changed. A crash with unknown effect is reconciled or rolled back, not followed by an unverified second update. Save a reusable pair before another teacher call. No silent random reinitialization on cold-load failure.

## Domain-specific representation and dynamic search

C#: AST operator role (`?.` conditional access versus `??` fallback), receiver/result type, nullable-flow state, operator order and language/compiler context. SQL: dialect/schema, table aliases, join predicate location, NULL/three-valued logic and multiplicity. RU: POS/dependency hypotheses, per-object referent identity, agreement conditioned on that identity, polarity/negation scope and uncertainty. Local referent IDs are not global numeric semantics: renaming entity IDs must not change the relationship encoded. Cross-domain incompatible schemas never share an unversioned similarity space.

`Книга лежала на столе; он был тяжёлым`: masculine `он` can refer to `стол`; feminine `книга` does not forbid every subsequent masculine token. Unknown antecedents retain alternatives. `Do not send until approved` must retain both negation and condition. These are public illustrations, not SEALED records.

Dynamic k has **two stages**. Pre-query known features can choose no-search/probe/bounded-search. After a paid bounded probe, observed score margin, density and ambiguity may choose further effort and consumed k. Record `probe_count`, search effort/ef, returned candidates, consumed k, radius if supported, early-stop/abstain and total work. HNSW `topK` and `efSearch` are different: returning fewer hits alone does not prove faster search. Compare exact and ANN under the same eligible vectors/metric. A heuristic policy is `HEURISTIC_ADAPTIVE`; a learned policy needs named θk, a real authorized update, cold use and its own no-update control. 02B2 owns it; first θ ranking does not wait for it.
