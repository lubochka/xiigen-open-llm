## GOOD / BAD / EDGE with reasons

GOOD: two authorized explanations of `s?.Length ?? 0` differ in their candidate-specific description of fallback behavior; the actual extractor can represent that distinction. Merely marking the QUERY as containing both operators is insufficient because both alternatives receive the same query flags.

GOOD: `Книга лежала на столе; он был тяжёлым` allows referent=`стол`; agreement is conditioned on that object. BAD: every feminine noun forbids all masculine continuations. BAD: both candidates have identical law features after filtering, but different IDs are called a useful learning signal. BAD: a hidden final grade is copied into ψ at training time although the runtime cannot compute it.

EDGE: both good, both bad, tied preference, only one eligible candidate, unknown dialect/compiler, uncertain antecedent, missing parser, or α-renaming changes prediction. Return the exact NO_INFORMATIVE_PAIR/UNKNOWN/source gap as a planning or diagnostic disposition, not a new public API enum. Repair the relevant relation/extractor or obtain a NEW authorized contrast; no hidden-rubric changes and no replay of an applied lesson.
