## Examples and reasons

GOOD: `A LEFT JOIN B ON B.a_id=A.id AND B.flag=1` can retain A rows without a qualifying B. BAD: move `B.flag=1` into WHERE and declare universal equivalence; null-extended rows may be removed. Downstream WHERE/aggregation must be specified before claiming a result.

GOOD: `IS NULL` tests nullness under the specified dialect. BAD: treat `x = NULL` as ordinary equality or NULL as zero. BAD: discard duplicate matches without permission; multiplicity changes.

EDGE: empty tables, NULL join keys, duplicate B rows, dialect-specific null functions, missing schema. Use a qualified oracle or UNKNOWN, never guessed results. EDGE: identical schema with aliases renamed remains one family.
