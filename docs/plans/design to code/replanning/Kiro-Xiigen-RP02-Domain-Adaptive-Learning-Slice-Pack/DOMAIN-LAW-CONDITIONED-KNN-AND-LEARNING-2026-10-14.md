## 2. Что должен прогнозировать гибридный алгоритм

Для запроса `x`, домена `d`, позиции/шага `t`, истории `h_t`, возможного next output `y`:
1. **Domain identification**: subject (C#/SQL/RU/EN/...), intent, language + direction, dialect/framework/version, права на источники, mixed/unknown. Не путать CODE_Q (тип задачи) с языком C#.
2. **Domain-aware vector/token representation** `φ_d(h_t,y)`: версионированные поля не только surface BPE/byte ID, но типизированные семантические/структурные признаки, поддомены и source version; роль токена в структуре. Лингвистика: language, lemma/surface, candidate POS, morph number/gender/case/person/tense, syntactic dependency, governing word/referent/coreference ID, polarity, clause boundary, uncertainty. Код: AST operator/expected syntax role/type/nullability/control-flow/version. SQL: AST/NULL three-valued logic/ON vs WHERE/joins/dialect. **Не утверждать**, что нынешняя K implementation уже кодирует эти признаки.
3. **Domain legality** `L_d(y|h_t,version,rights)`: какие условия действительно hard (security/tenant/source/version, синтаксическая/типовая невозможность при установленном parse) и какие мягкие вероятностные предпочтения (неоднозначный parse, стиль, грамматические альтернативы). Hard arbiter запрещает неправомерное, но не навязывает ложный «все слова этого предложения одного рода»; при неоднозначности возможны multiple parses и ABSTAIN/ASK.
4. **Contextual candidate evidence**: поиск в legal domain/version-scoped pool по семантической/структурной совместимости, history positive/negative/warning и полноте признаков. Не только геометрическая близость, не слепой top1/multi-hit.
5. **Domain-conditioned dynamic kNN policy** `k_d(h_t, candidate_density, confidence, entropy, risk, pc_budget)`: выбирать размер/радиус соседства и степень использования разных evidence roles. Возврат `k=1`, отказ от kNN при высокой уверенности или fallback на строгий parser/arbiter — допустимая научная победа, если лучше latency/error. Нельзя просто сделать k>1 всегда.
6. **Learned scoring / transition**: кандидатный posterior `p_d(y|h_t)` из Student/model prior + feature/rule-aware retrieval signals + научно обоснованного learned domain state, нормализованный по допустимым кандидатам. Различать trained parameter update, изменение памяти/index и deterministic law filter. Не выдавать наименование `kNN` за доказательство того, что существует trained adaptive policy.
7. **Actual typed consumer**: выбранный допустимый next token/role/AST/OutputRef попадает в реальный generation/Unit→Flow→Orchestrator/Graph, а не только в `EvidenceIds`. Изменение learning state реально меняет candidate ranking/answer через обычный cold user path.

Это **целевой дизайн и пакет гипотез**, а не заявление о существующем в K API; точные типы, владельца mutable state, loader, callers и optimizer надо найти в коде. Не придумывать `IGrammarPredictor` в статусе implemented.

### Иллюстративные GOOD/BAD/EDGE (НЕ train и НЕ sealed exam)
| Домен / контекст | GOOD и почему | BAD и почему | EDGE / правильное поведение |
|---|---|---|---|
| RU согласование и coreference | «Эта новая книга оказалась очень **интересной**»: role=predicative adjective, fem/singular, referent=книга; совместимая роль и связь, не ближайший поверхностный токен | «…оказалась очень **интересным**», если прилагательное относится именно к «книга», нарушает согласование | «Книга лежала на столе; **он** был тяжёлым» — мужской род законен, если **он** относится к «стол»; нельзя глобально veto мужской род из-за упоминания книги |
| RU/EN вероятная роль слова | После установленного parse сравнивать вероятности noun/adjective/verb/preposition с учетом зависимости и ожидаемой позиции; разные легальные формы могут остаться кандидатами | «Слово похоже на прошлое, значит ближайший сосед всегда верен»; игнорирует POS/зависимость | Цитата, неизвестная форма, эллипсис, согласование при нескольких объектах: учитывать uncertainty и альтернативные parses, не выдумывать один закон |

| SQL | `WHERE value IS NULL`, dialect/3VL и место WHERE/ON сохраняются в features и candidate laws | `WHERE value = NULL` объявлен эквивалентом, потому что похожи токены | `IS DISTINCT FROM`/null-safe syntax dialect-specific: уточнить диалект, не применять универсальный hard синтаксис |
| EN→RU polarity | «Do **not** delete the file» → «**Не** удаляйте файл»; negation/modal/direction preserved | «Удалите файл» — семантический разворот, даже если фраза гладкая | Double negation, quotation and scope; сначала решить семантическую область действия отрицания |

## 3. Что именно тестируем ВМЕСТО code coverage

**Абляции с одним изменяемым фактором**:
- A0: existing Student/predictor baseline, static domain parser/rules only (если реально доступен);
- A1: same Student + generic BPE/cosine kNN, frozen candidate pool/solver;
- A2: same Student + domain law-aware vector `φ_d`, fixed k and same legal pool;
- A3: same Student + `φ_d` + proper law-conditioned score/rerank, fixed k;
- A4: same Student + `φ_d` + score + adaptive k/early-exit under equal **PC cost envelope**;
- A5: same as strongest admissible A-arm with **one real RP01 Student DPO LoRA update** (compare against *the same A-arm with no DPO update*). Separately, RP02 learned-reranker weights P/C0/T with Student checkpoint frozen. Do NOT compare A0(no DPO) to A5(DPO+k+vector) and credit DPO/kNN all gain.
- If compute/time limited, **minimal preregistered 2x2**: Student P vs T crossed with law-aware kNN OFF vs ON; separately fixed law-filter OFF only for safe diagnostic cases and never bypass security/tenant. Interaction `(T_on-P_on)-(T_off-P_off)` is hypothesis, not guaranteed positive.
- C06 top1-vs-multi-neighbor is one **optional subfactor** when real typed consumer needs complementary evidence; `hits[0]` is not the universal bottleneck, nor automatic solution.
- Shared parser, candidate law filter, source metadata, model checkpoint, decoding, hardware and frozen question families across arms; report absent/not-wired as NOT_SUPPORTED, not zero.

**Metrics PER domain and PER phenomenon**: lawful next-token accuracy, top-k legal candidate recall where labels exist, `P(POS|context)` calibration (Brier/ECE with credible data), coreference identification precision, agreement violation by *same referent*, syntax parse/type correctness, SQL 3VL/null/ON-WHERE law errors, EN↔RU negation/modal/direction preservation, output task success/path-regret, uncertainty/abstention correctness, old-domain retention, p50/p95 latency, CPU/RAM/VRAM/index/rebuild/disk/Teacher+judge+failed-run spend and whole-PC fits. At small N label **PILOT_ONLY** and present interval by source family; no retroactive pass threshold.

**DPO negative quality**: same frozen x/context with allowed Chinese Teacher producing BOTH final sides; choose plausible near-miss y- violating ONE domain law (e.g. same-referent gender agreement, C# `?.` vs `??`, SQL NULL 3VL, lost negation) versus lawful y+.
