## Explicit decisions instead of synthetic confidence
`NO_GRANT`: no training; `NO_NEW_SIGNAL`: no next lesson; `LAW_FAIL`: veto; `EVIDENCE_INVALID`: isolate candidate; `REGRESS`: keep P; `INCONCLUSIVE`: keep P and register bounded next diagnostic; `IMPROVE_NOT_ADOPTED`: evaluate pointer/consumer; `PROMOTED_LOCAL`: only after actual permitted promotion + cold use; `NATIVE_PENDING`: historical S10/host owner still open. A dynamic policy may abstain if it cannot rank legal candidates.

A progress dashboard must expose **five separately measured axes**: ordinary answer quality, domain-law accuracy, resource/time efficiency, safe actual state usage after cold restart, retention on new feedback. A single training-loss number, GitHub green check or source-file count never advances any of them.

## Error/failure matrix
- Power loss after optimizer before commit: journal shows ambiguous consumed pair → reconcile, never replay automatically.
- Model accepted but index vector dimension/law version changed: version compatibility denies selection; rebuild only under RP02 authorized owner, keep P.
- kNN adaptive k=12 retrieves 12 but consumer reads one: record baseline first-hit, do not award multi-hit gain.
- Async graph branch late/cancelled: unawaited result not accepted; account full attempted compute.
- Feedback arrives from other tenant or unconsented confidential code: isolate, do not send to Chinese model.
- A running process secretly swaps adapter after independent T exam: invalidate acceptance; pin same selected state/consumer hash at A cold run.
- RP09 experiment high score but independent Astra review absent: `REVIEW_NOT_PERFORMED` / `PROMOTION_PENDING`, not auto-accept.
- Native S10 GUI uninstalled: record `CORE_COLD_USED` only, not `FINAL_COMPLETE`.
