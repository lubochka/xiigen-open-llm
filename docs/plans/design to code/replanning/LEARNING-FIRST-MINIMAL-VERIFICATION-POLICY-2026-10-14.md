## 1. Four distinct completion claims; NEVER substitute one for another
1. **IMPLEMENTED:** actual ordinary caller reaches algorithm and correct typed output. A new interface/file/mock is not enough.
2. **STATE_CHANGED:** declared trainable parameter owner received a single authorised update; identity/version/journal/checkpoint are observed. A change in a diagnostic score is not enough.
3. **LEARNING_MEASURED:** frozen, source-family-disjoint baseline parent P, corrected no-update C0 and treatment T; one factor varied; independent lawful domain rubric; time, RAM/VRAM/CPU and total PC state/storage; bulk-to-bulk retention, failure and uncertainty. Same training pair or learned margin is not test accuracy.
4. **COLD_ORDINARY_ADOPTION:** process restart and genuine CodeDocumentation / DTC / IDE consumer uses the accepted *complete* state with matching tokenizer, domain-law version, LoRA, graph, index and resource policy. A sample harness or evaluator-only API is not adoption.

An execution report may stop at any honest stage: `NOT_RUN`, `NO_AUTHORITY`, `INCONCLUSIVE`, `REGRESS`, `INVALID_EVIDENCE`, `STATE_CHANGED_NO_GAIN`, `MEASURED_GAIN_NOT_ADOPTED`. Neither publication of task packets nor CI-green upgrades these statuses.
