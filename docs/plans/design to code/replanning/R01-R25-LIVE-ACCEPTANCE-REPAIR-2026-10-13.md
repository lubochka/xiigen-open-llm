## Decision: a compact learning system, not coverage-driven development

### Four different learnable mechanisms

| Role | Preserved functional obligation | Deterministic / learned boundary | Independent falsifier |
|---|---|---|---|
| **ILearningUnit** | Domain + input-vector schema + output schema -> requested typed, associated **many-to-many** result set (the original spelling is not a compiled API claim) | Type, constraints, associations and schema validation deterministic; matching/selection/update only where a named learned recipient actually exists | Candidate list exists but wrong requested type, wrong association or no learned effect on ordinary result |
| **ILearningFlow** | Relationships between units, correction of intermediate input/output, fan-out and fan-in | Port compatibility and invariant transformations deterministic; edge selection/correction state trainable if explicitly owned | Updated unit improves but frozen-unit unseen compositions do not, or corrections never reach the next unit |
| **ILearningOrchestrator** | Deeper async input-to-output combination, parallel branches, budget/stop/cancellation policy | Execution/resource permissions deterministic; lawful path choice and routing policy may learn | Winning answer selected only by handcrafted fixed sort; cancellations leak output; no accepted change under frozen units |
| **ILearningDynamicGraph** | Higher-order relations and patterns, multiple unit combinations, and future learned DPO Builder | Graph legality, lifecycle and provenance deterministic; cross-pattern learned authority and candidate DPO construction separately trained/assessed | Memorizes seen paths, fails novel lawful graph compositions, or emits pairs without qualified semantic preference |

There is **one existing training infrastructure** where evidenced, not four automatically created DPO trainers. The four roles have **different target state, credit assignment and ordinary consumer**. No amount of tensor shape/LoRA naming/graph edge count proves that a role learned. Dynamic kNN requires a domain/query-conditioned policy **and a consumer of multiple neighbors**, not merely changing k while returning neighbor[0]. Domain-sensitive tokenizer/vectorization requires proven preservation of law-relevant meaning, versioned coordinates and downstream acceptance, not just embedding dimensionality. A LoRA adapter is parameter-efficient state, **not** by itself a semantic token/vector transposition.

**CODEX running GPT-6 Astra 6 UltraCode does the human choice of the lawful learning case.** The **approved external open Chinese model authors BOTH final chosen and final rejected for the same exact x**. **CODEX running GPT-6 Astra 6 UltraCode separately examines the exact final pair** (law, better/worse difference, meaningful defect, provenance, TIE/BOTH_BAD/UNJUDGEABLE). Student weak answer/user edit is not silently rebranded as Chinese-authored rejected. Historical provider shortlists are not current grants. In planning-only mode, none of these calls is authorized or claimed.

**Pre-optimizer falsifier:** raw assessed chosen/rejected differ lawfully but a 480-character compacting/truncating stage or wrong BPE join discards the discriminating span: must reject the material or correct the separate material path before update; new pair hash alone is not proof. Response-only DPO objective and backward must be consistent (not forward sum/backward mean); LoRA key allowlist, frozen reference, no-repeat journal, save/reload, and ordinary adoption must be demonstrated by their own evidence. Preserve the current bounded R18-A–D contracts; do not rewrite a second optimizer.
