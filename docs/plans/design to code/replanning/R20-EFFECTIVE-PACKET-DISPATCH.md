## 2. Полное содержимое packet и независимые признаки готовности

Это contract будущей сборки. Таблица §3 сама по себе — только manifest. В каждом фактически собранном тексте присутствуют:

1. **CURRENT / NOT:** назначение, пользовательская цель, явный mode (documentary preparation / separately authorized product implementation / read-only examination / training), запреты и полномочия.
2. **STATE:** exact own checkpoint/IDs/visited/remaining, pinned relevant blobs, применяемая delta и уже принятые NO_CHANGE receipts. Новый unrelated HEAD не стирает прогресс.
3. **ROLE / SKILLS:** реальные относящиеся skill excerpts с источником и применением. В R20 карточке встроены правила planning, plan review, architecture, code examination, prompt engineering и human readability; имена без текста недостаточны. Current unsupported model alias остаётся UNRESOLVED, не actual Astra call.
4. **CONTEXT:** нужные original clauses, WorkLeft/RAG→primary/code, authority reconciliation. Direct read, attributed trace, structural survey и not-read различаются. Для actual code claim нужны целые затронутые файлы/контракты и callers→producer→consumers, не только grep.
5. **MECHANISM:** current→target, law/eligibility, deterministic authority, learned state/objective/owner, input/output and ordinary consumer. Не «добавь LoRA/kNN», а какое решение изменится и кто его использует.
6. **ACTIONS / OUTPUTS:** bounded шаги и материализуемые deliverables. Большая часть делится по независимым seams; children получают тот же полный contract, а не заголовки.
7. **GOOD / BAD / EDGE:** конкретная задача/ответ или source conflict, различающий контрпример и ожидаемое действие. Иллюстрации не становятся DPO training rows без отдельного допуска.
8. **EXAMINATION:** приёмка документа сейчас; отдельно future N/U causal study с frozen factors, laws, metrics, cost, retention и falsifier. Уменьшение loss/новый hash/green Windows не заменяет learning outcome.
9. **BOUNDS:** allowed/forbidden paths and commands, фактический budget либо unresolved value с resolver, stop, return consumer. Не выводить actual context tokens из bytes файлов и не обрезать обязательные clauses молча.
10. **RETURN / EVIDENCE:** actual assembled content или точный gap, source-content manifest, dispositions, own carrier changes, consumer receipt, publication/readback, claim/evidence scope, count, independent count и actual subagent ID либо NONE.

### Старт не равен разрешению завершить любой шаг

`ROUTE_RESOLVED`: exact source/card paths найдены. `CONTENT_ASSEMBLED`: имеется actual text со всеми обязательными для данного action содержательными inputs. `PREPARATION_READY`: можно выполнить явно названное независимое чтение/дизайн; неизвестные runtime fields имеют resolver. `FINAL_DECISION_READY`: конкретный вывод имеет необходимые принятые evidence/authority. `IMPLEMENTATION_AUTHORIZED`: есть отдельное полномочие и exact ready implementation packet. `INVOCATION_OBSERVED`: есть actual run identity/receipt. Это независимые признаки; последнее не следует из предыдущих автоматически.

Для каждой строки сохранять `allowed_next_action`, `blocked_action`, `missing_input`, `resolver`, `source_version`, `content_location`, `actual_delivery_receipt_or_NONE`. Поле UNKNOWN разрешено в preparation packet, но не притворяется заполненным final/implementation input. При overflow сначала исключить нерелевантное/дубликаты; затем разделить независимые части с полным контекстом. Непоместившееся обязательное — конкретный BLOCKED_CONTENT, не бесконечная перезагрузка всей библиотеки.

## 4. Смысл обучения, который нельзя потерять при упаковке

### Четыре роли и гибридный механизм

**Unit:** получает domain, input-vector schema и output-type schema; выдаёт typed many→many results с identity/associations. Laws определяют допустимость, trainable mapping имеет state/signal. Контраст: изменить Unit при frozen Flow и исследовать сохранение смысла/полезность результатов.

**Flow:** корректирует вход→выход и отношения Units. Updated relationship должна использоваться ordinary consumer. Контраст: same Units с fixed versus learned Flow на новой композиции; сохранённая запись без изменения поведения — не adopted learning.

**Orchestrator:** выбирает законные async combinations, порядок/fan-out/fan-in/cancellation и расходы всех запущенных ветвей. Сравнивать learned routing при frozen downstream solver и solver improvement при frozen route отдельно. Быстрый ответ одной ветви не обнуляет цену остальных.

**DynamicGraph:** higher-order pattern relations и перенос на unseen compositions, реальные edge/path decisions с semantic OrderedPatternIds. Graph — L5 specialization внутри existing hierarchy, ILearningMachine — training owner, не четыре trainer и не шестой уровень. Постоянный hollow adapter/скрытый fixed solver не выдается за learned authority.

По каждому блоку/ребру packet включает law/eligibility, input/output contract, deterministic and trainable authority, parameter/state owner, objective/signal, caller/ordinary consumer, version and lifecycle, intervention, frozen controls и falsifier. TensorCore/shared base/project LoRA, StackDetector-before-normalization, semantic compression, BM25+kNN, positive/negative/warning memory, final arbiter и mandatory skills вне top-k сохраняются до предметного обоснованного решения о миграции.

### DPO, векторы, LoRA и dynamic kNN

У обеих сторон preference одна задача/контекст/доменный закон. Разрешённая внешняя открытая китайская модель создаёт обе final chosen/rejected; CODEX с назначенным Astra-профилем выполняет отдельно human lesson selection и exact-pair quality judgment. Student тренируется; независимый post-update evaluator измеряет другое. Профиль из планового текста не actual model invocation. Judge не переписывает teacher bytes под чужим авторством; существенная правка требует нового допуска exact pair. `preferred_side` и `pair_usable` различаются; TIE/BOTH_BAD/UNJUDGEABLE не принудительная пара. Правильный deterministic кандидат не rejected лишь по происхождению.

Packet сохраняет provenance/authority, domain laws, exact input/chosen/rejected meaning, material segmentation, token/mask/stop versions, condition/objective/reference, actual trainable keys и ordinary adopter. Стандартный DPO не равен произвольному similarity score; для vector/path preference нужен определённый вероятностный objective либо честно названный иной pairwise метод. Научные anchors: Rafailov et al., arXiv:2305.18290; Hu et al., arXiv:2106.09685 (первичные abstracts сверены 13.10.2026; это не evidence эффективности XIIGEN).

Domain, intent, stack, project, slice и Student identity различаются. Encoder/projection/tokenizer/codebook определяют смысл и совместимость vectorized token; LoRA задаёт low-rank trainable weight update, не автоматическую токенизацию. Same dimensions недостаточно: нужны schema/version/semantic probe/consumer и migration/reindex с учётом peak memory. Отдельно исследуются representation fidelity и downstream task utility.

Dynamic kNN описывается полностью: domain eligibility, feature source, metric/score, k/radius, index approximation, neighbor weighting/aggregation, learned policy state/update signal и final arbiter. При k>1 producer может вернуть много IDs, а consumer брать только первый content: тогда k-only contrast не доказывает multi-neighbor learning. Нужны lawful exact/fixed reference, same candidate pool и изолированный эффект выбранной политики. Oracle-domain используется только как отдельный диагностический arm; основной путь использует predicted/unknown/mixed domain.

### Что измерять по доменам и bulk

Семь исходных subjects — EN↔RU, orchestration, Figma→HTML/CSS, C#/Angular/SQL documentation, Builder — плюс discovered extras/languages/intents, не закрытый список допустимых доменов. Domain passport содержит закон, input/output semantics, admissible/rejected paths, characteristic tokens/relations, positive/negative/tie and edge examples, source-family split и различающий experiment. Например, в SQL надо сохранять смысл NULL, а не просто похожие tokens; в orchestration — зависимости/отмену; в Builder — правильные typed associations. Эти примеры — design probes, не выполненные эксперименты или разрешённые training rows.

Для каждого bulk новых pair IDs заранее фиксировать protocol/panel/rubric и наблюдать law violations, domain mapping/unknown/mixed, solution quality/accuracy per domain и worst domain, path quality среди рассмотренных законных альтернатив, representation fidelity, retention и uncertainty по независимым source families. Измерять time-to-useful-lesson, latency distribution, полные RAM/VRAM/disk/index/graph/base/reference/optimizer/activations, teacher/judge и все async attempts. Меньше trainable parameters не доказывает PC-fit всего процесса. Следующий более лёгкий bulk не доказательство improvement; operational panel, влиявший на выбор, не untouched confirmation.

**N/U:** N = frozen no-update parent; U = isolated updated challenger. Одинаковая corrected material/token/mask/stop/input renderer/ordinary-consumer pipeline, comparable evaluation context/RNG policy/budget. Legacy L→N показывает engineering correction; N→U проверяет обучение. Не гарантировать numerical equality от одинаковых weights при разных stochastic modes. Controls fixed/learned/hybrid не снимают обязательные hard laws: learned-only означает отсутствие сравниваемого optional heuristic, не разрешение небезопасных путей.

Outcome: IMPROVE / REGRESS / INCONCLUSIVE / INVALID_EVIDENCE / NOT_MEASURED; отдельно promote/keep-parent/rollback и separately qualified native/release property.
