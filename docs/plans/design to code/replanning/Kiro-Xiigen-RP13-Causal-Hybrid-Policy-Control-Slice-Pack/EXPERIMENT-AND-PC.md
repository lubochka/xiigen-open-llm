# RP13 — причинный научный протокол вместо Windows coverage

## Pre-registration, затем только наблюдение

Перед outcome treatment закрепить: (1) задача/домен/версия закона/источник права, (2) intact split by primary source family, (3) true P baseline, `C0` corrected deterministic no-update, `T` одно target-policy change при законном grant, (4) candidate universe, typed graph, model/Student checkpoint, decoder, index, hardware state, scoring rubric/assessor blind, (5) один изменяемый фактор, finite repeat/N, (6) критерий опровержения и законная остановка/откат, (7) полный PC/teacher/solver бюджет. Эксперимент до T без grant разрешён как `P/C0 observational` и `NOT_MEASURED` по обучению.

## Причинные contrasts

- `A0` current ordinary baseline: домен, candidates, chosen route, end-task functional utility, full cost.
- `A1` same solver/memory, oracle-lawful domain instead of actual detector → кто виноват: classifier/stack normalization? Контрольная диагностическая oracle branch никогда не маскируется под production.
- `A2` same domain & solver, kNN first-hit vs true allowed multi-neighbor fusion with exact same candidate pool/budget → RP02 retrieval contribution; varied metric/k/ANN как отдельные arms, не одновременно.
- `A3` frozen Unit outputs, change only Flow correction / typed association; `A4` frozen Units/Flow, change only Orchestrator route; `A5` frozen lower layers, higher-order Graph motif; сохранять version and fallbacks. Результат может быть неидентифицируем при взаимодействии.
- `A6` same route/inputs, frozen Student vs one authorized exact DPO LoRA state; не считать LoRA weight delta улучшением без heldout outcome.
- `A7` RP13 selector: same lawful `A_lawful` and downstream owners frozen, changed policy only; measure right-recipient/cost/route quality; `NO_UPDATE` arm обязателен.
- `A8` real hybrid vs deterministic-only vs learned-only-if-lawful, same budget and source families; separate required safety veto; отчёт взаимодействия без «causal proof» из single uncontrolled run.
- `A9` old-domain retention across two novel bulks; cold restart, no self-training CERT contamination, user feedback permission.

Прямое сравнение `T−P` без `C0` смешивает deterministic bug fix с learned gain. Если path alternatives не перечислены, нельзя говорить `best path` кроме `best observed among supplied candidates`. Если два звена меняются, interference/IPW/interaction hypothesis must be predeclared and uncertainty explicit; лучше ограничить одну branch.

## Метрики (нельзя заменять «pass tests»)

`domain macro-F1 / multi-label; UNKNOWN/OOD false route+abstention; hard-law violation count/severity; meaningful semantic representation loss; retrieval relevance@k/coverage; true typed association accuracy; ordinary end-task utility; fraction selecting best lawful among enumerated options and bounded regret; per-family ΔQ(T−C0); stderr/interval with family N; old-domain retention; wall p50/p95 + per-stage CPU, peak whole-process RAM/VRAM, disk (weights+adapter+optimizer+index+graph+cache), total setup/index/teacher/judge/update/inference/rollback cost; novel bulk trend`. Record failure/error retries, speculative branches and failovers, not just successful inference.

**Safety engineering is distinct:** narrow local property checks for correct law admission, request/response types, masks, causal identifiers, replay/no-repeat, checkpoint restore, cancellation, rights and version, and affected native tests when actually required. No Windows GitHub workflow as scientific quality gate; never disable preexisting mandatory release checks.

## Verdict decision

`IMPROVE` only after valid causal contrast, independent heldout law-aware score and measured resources; `REGRESS` if validated worse, revert/retain P; `INCONCLUSIVE` for underpowered/tie; `INVALID_EVIDENCE` for leakage, mock, changing multiple arms, wrong consumer or unverifiable authority; `NOT_MEASURED` for no real run. Even IMPROVE does not imply `ORDINARY_ADOPTED`, which needs accepted cold actual consumer, or `INDEPENDENT_REVIEWED`, which requires separately invoked reviewer exact candidate SHA.

## PC constraint

PC-fit is an *observed resource property*, not "Q4" or checkpoint file smaller. Historically proposed RTX 3050 8GB, i5-9400, 16GB RAM is target **hypothesis only** until the executor records current actual hardware; do not hardcode or promise support. Strict per-trial budget and small intervention; no full seven-domain GPU campaign until one lawful useful local observation.
