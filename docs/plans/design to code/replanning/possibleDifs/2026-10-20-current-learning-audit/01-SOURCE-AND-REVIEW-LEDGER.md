## RAG и архитектурные требования

Использован [RP01 SOURCE-AND-ARCHITECTURE](https://github.com/lubochka/xiigen-planning/blob/1ad622fe1f6d1e8b0860265d8c208aeada3fefb0/llm%20mvp/design%20to%20code%20session/replanning/Kiro-Xiigen-RP01-Learning-First-Slice-Pack/SOURCE-AND-ARCHITECTURE.md), исходный README и recovery audit RP01, адресные WorkLeft-RAG-01/RAG-03 и training integration разделы. Ссылки на `dpo legal build`, `llm dynamic flow` и `visual studio & visual studio code continue` разрешались как соседние каталоги внутри `llm mvp`, а не как дочерние папки `design to code session`.

Из родительских источников прочитан [ARBITER-KNN-AUTHORITY-AMENDMENT](https://github.com/lubochka/xiigen-planning/blob/1ad622fe1f6d1e8b0860265d8c208aeada3fefb0/llm%20mvp/llm%20dynamic%20flow/ARBITER-KNN-AUTHORITY-AMENDMENT-v1.md). Он различает positive, negative/warning память и применение закона к ответу; сходство с сохранённым примером само по себе не делает его допустимым ответом. Архитектурные роли Unit/Flow/Orchestrator/Graph учитываются как отдельные требования. Текущий интерфейс с фиксированным packet или confidence не объявляется обучаемым без state/update/consumer.

Полное чтение всех документов G/F/V, всей истории R01–R25 и всех исходников core **не заявляется**. Для причинных выводов используются конкретные указанные методы и источники. По остальному корпусу честно различены навигационный поиск и содержательное чтение.

## Применённые навыки

Применялись запрошенные пользователем архитектура, планирование, проверка плана/кода, prompt engineering и человеческая коммуникация. Использованы предоставленные skill-материалы и текущие [docs/skills](https://github.com/lubochka/llm_mvp_core/tree/bf9b543e149ef197da85a767821d98c9b67916d2/docs/skills): `human-readable-architecture-audit`, `architectural-decision-testing`, `intent-to-plan`, `plan-self-validation`, `code-examination`, `learning-path-audit`, `improvement-measurement`, `prompt-patch-authoring`, `human-communication-GLOSSARY`.

Практические следствия: назвать настоящий learner и изменение его состояния; не смешивать предметную область с механизмом; выбрать один фактор; проверить реальный caller; сохранять исходный смысл метрик; отделить ожидаемое от измеренного; написать понятный вывод с границами. Компактные приложенные skills прочитаны полностью, длинные текущие инструкции — по нужным разделам. Полное повторное чтение всего каталога skills не заявляется. Исторические пороги обязательного выигрыша и старые blanket approvals не заменяют прямое правило пользователя о любой полезной измеренной метрике.

## Независимая проверка и внесённые исправления

Исследование ядра, исторических/kNN механизмов и protected каталога выполнено отдельными проверяющими направлениями. Авторский вывод проверялся другим направлением и итоговым редактором по исходникам. Это source/protocol review, не второе исполнение опыта.

| Проверенный риск | Что исправлено до публикации |
|---|---|
| Дополнительные warmup updates скрывались бы за рамками маленького бюджета | В LC-REF-CACHE запрещены дополнительные обучающие шаги разминки. Cold JIT, оставшийся к первому update, честно входит в малый run |
| Метрика `StepVector` могла быть названа post-update, хотя вычислена до AdamW | Before/after задан через четыре настоящих `EvaluateMany`; их 16 reference и 16 policy evaluation forwards учтены отдельно от training window |
| Неоднозначное «4 cache hits» для helper, который хранит целую пару | Счётчик измеряется парами: B ожидает 2 pair misses, 2 pair hits, 4 reused scores и 4 actual reference forwards. Это расчёт, не измерение |
| Несовпадение исходного D04 и cache-опыта | Явно сохранены разные расписания и разные вопросы. Cache не считается выполнением семантического D04 |
| Новый routing дефект мог быть ошибочно назван регрессом текущего PR | Проверена соседняя ветка: расхождение унаследовано. Добавлен контроль masking hint и регрессионный запрос о переводе C# текста |
| Поздние изменения каталога могли сделать аудит устаревшим | Перечитаны изменённые 152 документа, сохранены исходный и текущий census, E1/E2 больше не объявляются отсутствующими |
| Исторические PASS/FAIL могли скрыть разные экзамены или таймеры | У E09 и E07 приведены точные различия, у E25 — synthetic POS и время без Train, у E26 — BuildDefault, у E43 — обучение bigram с нуля |

Все новые JSON fixtures разобраны; строки source-selection сверены по IDs и digest нового двухстрочного файла. Relative links проверяются для конечной структуры пакета. Git blob IDs исходных файлов отделены от хешей локальных выгрузок и новых fixtures: локальный дополнительный перенос строки не выдаётся за исходный remote SHA. В пакет не включены временные download URLs или сырые ответы API.

## Чего этот пакет не утверждает

### Параллельное обновление planning при публикации

После исходного снимка `1ad622fe…` другой исполнитель опубликовал commit [`426385f…`](https://github.com/lubochka/xiigen-planning/commit/426385f91e7cb454e7e6827d9102d1e0d1284534): 18 новых файлов пакета 61 и обновление README. Получены все девять изменённых Markdown, адресно прочитаны новые гипотезы и проект caller; выполнен поиск пересечения по reference-score cache и keyword normalization. Общие исторические выводы и каталог закономерно пересекаются. Два заявленных им новых механизма — перезапись входных weights одного Flow и несогласованность выбранного Flow с глобально найденным learned plan — отличаются от LC-REF-CACHE/KN-ROUTER. Их авторство и самостоятельные карточки сохранены: [пакет 61](https://github.com/lubochka/xiigen-planning/tree/426385f91e7cb454e7e6827d9102d1e0d1284534/llm%20mvp/design%20to%20code%20session/replanning/possibleDifs/61-LEARNING-FIRST-AUDIT-2026-10-20).

В его neural caller design найдено полезное общее уточнение: существующий `issuedPath` зависит от domain/mode/TRAIN hash, поэтому новые RunId не создают законные независимые A/B на тех же данных. Это дополнительно сверено по `CodeDocumentationSimulationDpoExperiment.cs:85–87,173` и включено в наш DPO design. Смена пути или удаление marker не предлагаются. PAD-вмешательство и его однократное расписание не переносятся в cache-опыт.

Счёт 869/555 относится к исходному baseline и не объявляется новым полным размером каталога после чужого commit. Полный census не выдаётся за содержательную проверку всех утверждений нового пакета 61; его новые измерения не переисполнялись. Публикация настоящего пакета строится поверх commit426, с сохранением чужого добавления и актуального README.

### Предел итогового вывода

Не утверждается, что найдена единственная причина деградации RP01, что все 555 документов прочитаны построчно или что 470 исторических подслучаев семантически сертифицированы. Не утверждается, что карточки уже превратились в работающие native hosts. Отсутствие .NET runtime в текущей среде зафиксировано; вычислительная имитация на другом языке не выполнялась.

Пакет позволяет проверить происхождение каждого принятого вывода, не повторять уже внесённые изменения и выбрать следующий маленький опыт с точным получателем, данными и метрикой. Любой его будущий численный результат должен появиться в отдельном отчёте с реальными наблюдениями; таблица ожидаемых счётчиков таким отчётом не является.
