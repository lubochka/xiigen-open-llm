## N33-A · P0 для предварительного обучения/SFT, НЕ доказанная причина RP01 DPO-only

**Утверждение по коду (C):** `Embedding.Weight` — trainable `Parameter`, но `Embedding.Forward` возвращает новый `Tensor(data,shape)` без `requiresGrad:true`, `Children.Add(Weight.Value)`, `BackwardFunc` или scatter-add backward.

Поэтому при отсутствии других специально запрограммированных путей градиент `token_embedding.weight` через этот forward получить **невозможно**, и optimizer не обновит эти веса. Другие матрицы могут обновляться, значит decrease training loss не свидетельствует, что обучились embeddings.

**Причинная граница:** текущий RP01 C#500/ENRU500 обучал *только q_proj/v_proj LoRA на замороженной случайной B0*. Для него отключённое обучение самой таблицы эмбеддингов ожидаемо и **не объясняет непосредственно** 0/3 и 0/4; его главная угроза — предлагаемый в [RP01 learning recovery](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md) путь *SFT/pretraining → DPO*, если планируется разрешить обучение эмбеддингов. Нельзя назвать этот proposed repair «полным обучением с нуля», пока gradient reachability не проверена.

**Исторический/branch контроль:** в `DesignToCode` и `language_translate` старый `Embedding.cs` (blob `ee029cf858ad32667f4324d9533891c1ba1a1f24`) также завершает Forward через `return new Tensor(data,...)`; на нынешнем core/main код имеет blob `4c975d4e3a492edd90896c64e77a5c93b104ab1b` и тот же disconnect. Дефект не следует выдавать за regression *именно* после переноса с DesignToCode. Успешные E26/E09/Translation Units используют иные механизмы; эта общая унаследованная ошибка не отменяет их positive receipts.

[Linear.Forward L50–66](https://github.com/lubochka/llm_mvp_core/blob/32ac6e741ce4cfb2dd8ac024716e470f8d0f18f7/00.TensorCore/Layers/Linear.cs#L50-L66) вызывает `ExpandBias(Bias.Value,...)`; [ExpandBias L70–87](https://github.com/lubochka/llm_mvp_core/blob/32ac6e741ce4cfb2dd8ac024716e470f8d0f18f7/00.TensorCore/Layers/Linear.cs#L70-L87) копирует `bias.Data` в новый `Tensor` без backward-ребра. Весовая ветка `MatMul` сохраняет gradient, но gradient Bias недостижим (код даже комментирует, что bias не участвует в вычислении градиента через этот путь).

**Не причина нынешней C#/ENRU q/v LoRA:** [LlmModel.cs L109](https://github.com/lubochka/llm_mvp_core/blob/32ac6e741ce4cfb2dd8ac024716e470f8d0f18f7/03.TransformerModel/LlmModel.cs#L104-L116) использует `lm_head(useBias:false)`, а [CausalSelfAttention.cs L68–72](https://github.com/lubochka/llm_mvp_core/blob/32ac6e741ce4cfb2dd8ac024716e470f8d0f18f7/03.TransformerModel/Layers/CausalSelfAttention.cs#L67-L72) — проекции без bias. P2 становится P1, только если конкретный learned Unit/head/domain model реально содержит `Linear(useBias:true)` и рассчитывает адаптировать bias. Это **не** evidence ошибок во всех линейных слоях.
