## A. Почему результат RP01 нельзя приписать одной неисправности

Замороженные [RP01 recovery measurements](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md): 500 C# simulation pairs, 25 law/template families ×20, 50 optimizer steps, 16 LoRA tensors изменились, 39 base tensors frozen, preference margin +0.0012275314, **ordinary free 0/3→0/3**. Продолжение EN→RU500: 20 категорий ×25, ещё 50 steps, preference margin +0.0001100063, **ordinary free 0/4→0/4**. Это **не новый прогон** и не измерение «процента изученных знаний». В этом пути [Simulation Inspect L57–75](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/14.ContinuousLearning/Training/CodeDocumentationSimulationDpoExperiment.cs#L57-L75) правильно помечает оба ответа как `DeterministicGenerator`, а [Run L103–125](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/14.ContinuousLearning/Training/CodeDocumentationSimulationDpoExperiment.cs#L103-L125) выполняет подготовку exact DPO. **Не считать эти synthetic пары результатом разрешённой китайской модели.**

Разные «ученики»:
- **Нейронный Student:** exact response DPO → gradient → LoRA q/v → full checkpoint → [TextGenerator](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/09.Inference/TextGenerator.cs). Правильный критерий: законный независимый ответ на обычном generation route.
- **Структурные Units / KNN:** урок → tokenizer/Executor/Verifier maps и source-aware nearest → [ordinary TranslationRoutingFlow](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationRoutingFlow.cs). Правильный критерий: unseen semantic correctness после точного state restore.
- **Алгоритмические правила и эксперименты:** AST/context/POS/reorder/route/quality gates. Их deterministic benefit не приписывать изменению LoRA; успешный proxy на 7 шаблонах не равен generalization.

## E. Минимальная очередь для исправления диагностики, а не тотальной переписи

1. **MICRO-NEURAL-COLD:** frozen B0, 8–32 chosen-only cases, gradient finite difference, single law free-generation, cold readback. Это P0 до масштабирования KNN как причины neural 0/3. Использовать [RP01 Recovery](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md). Если Student не может переобучиться одному простому закону, дальнейшие 500 бессмысленны.
2. **MICRO-PAIR-CONTRAST:** один разрешённый источник, точная DPO пару; chosen vs rejected target/mask/grad sign and no-op when chosen=rejected; CODEX Astra grade + actual open Chinese author при новом уроке, без маскировки synthetic authorship.
3. **MICRO-HISTORICAL-UNIT:** исторический non-exact переводческий Unit/KNN transfer из [11](11-CROSS-BRANCH-REAL-LEARNING-RESULTS.md) сравнить old algorithm vs current KNN на одинаковом 12+12 source-disjoint lawful panel, один ordinary consumer и cold state.
4. **MICRO37-KNN:** три отдельные новые code seams + доменные панели по [MICRO37](37-MICRO-DOMAIN-KNN-METAMORPHIC-CAUSAL-PLAN-2026-10-16.md), без новых DPO до эффекта на ordinary caller.
5. **MICRO-RESTORE-AB:** один лучший кандидат, same panel warm vs cold vs parent, same tokenizer/index/LoRA state/passport; не смешивать effect training и adoption/consumer.

**Обязательные outcomes:** `IMPROVE` / `REGRESS` / `INCONCLUSIVE` / `INVALID_EVIDENCE` / `NOT_MEASURED`; отдельно `SOURCE_CONFIRMED` и `NATIVE_BRANCH_CONFIRMED`. При любом эффекте сравнивать worst-domain, critical-wrong, correct-at-coverage, retention, time/PC budget. Артефакт quality verdict должен содержать source/evaluator/model snapshots и provenance. Граница 95% из [RESEARCH-01](../../09.09.26WorkLeft-RESEARCH-01-training-quality-speed-accuracy-program.md) — стратегическая цель, а не право назвать первый маленький результат «готовой системой».

## F. Роли и применение скилов

**CODEX / Astra 6 UltraCode** выполняет человеческую работу выбора допустимого нового случая/семейства и утверждения закона, **разрешённая внешняя открытая китайская модель** создаёт обе стороны новой настоящей DPO (chosen и rejected), **CODEX / Astra 6 UltraCode** отдельно оценивает обе финальные стороны DPO и затем независимо оценивает качество обычных Student/Unit ответов и принятие/rollback. Де-факто вызовов этих моделей в данном исходниковом аудите **не было**. Не объявлять `CODEX_APPROVED` без реального поручения и receipt.

Соблюдены методы `human-readable-architecture-audit-SKILL` (границы получателя), `phase-planning-SKILL` (микрошаги), `plan-review-SKILL` (отрицательные контролы), `generated-code-review-SKILL` (точные строки и source conditions), `prompt-patch-authoring-SKILL` (ограниченный наряд), `experiment-design-SKILL` (falsifier), `reference-inventory-and-source-map-SKILL` (история) и `conversation-intent-and-self-reflection-SKILL` (объяснимые честные статусы). [Готовый порученческий prompt](37-CODEX-ASTRA-IMPLEMENTATION-AND-REVIEW-PROMPT-2026-10-16.md).

**Не сделано:** полное машинное сканирование каждого RAG, всех соседних веток и всех ранее опубликованных заметок; запуск native Student/Unit причинных опытов; непосредственная независимая Astra-рецензия; новые разрешённые Teacher-пары; production исправления. Это **доказательный план и 3 новые условия KNN**, не заявление о завершённом восстановлении обучения.
