# Дополнение к аудиту RP01: новые гипотезы и проверка экспериментов

**21 октября 2026. Добавочный документный пакет.** Источники: `llm_mvp_core@26332500f76ea8345256c73ecfd44c0023b7e883`, `xiigen-planning@14308ff181c5a93d837d92b85b2f35c41b863565` и закреплённые соседние ветки.

**Результат:** найдены три новых узких фактора для причинных экспериментов, проверены связи всех 50 записей текущей очереди и разобраны сохранённые результаты 13 её попыток. Для новых факторов приложены карточки и промпты с конкретным learner, набором, before/after, местом, командой и бюджетом. Новых обучающих запусков нет; измеренные числа ниже принадлежат сохранённым исходным результатам.

Единственная доказанная причина всего провала RP01 пока не установлена. Два новых исторических дефекта могут объяснять ошибочную оценку старого обучения, но их включение в RP01 Student не найдено. Третий фактор касается цены реального обучения. Это различие сохранено в названиях, статусах и выводах.

## 1. Три новые гипотезы

### Почему два исторических фактора не объявлены регрессией нового PR

E05/E10 с теми же механизмами найдены в соседних ветках; текущий вариант отличается в рассмотренных файлах добавленным лицензионным заголовком. Это унаследованная логика. Поэтому эти находки обосновывают пересмотр старого эксперимента и отдельное восстановление полезного механизма. Они не доказывают, что именно новый RP01 потерял эти функции. Не смешиваются также 34/E05, 34/E10 и одноимённые номера 35.ExperimentsV2. [Код, branches и blob evidence](historical/HISTORICAL-PPMI-HIERARCHY-FINDINGS.md).

## 2. Что показал аудит существующих карточек

Проверены все **50 ID/card/next** активного реестра, точные anchors, **37 future output records** и обязательные contract/STOP/NEXT/default-model/Russian-report поля в **188 Markdown**: 171 карточка, индекс и 16 standalone prompts. По структуре маршрутов расхождений нет. Это не аттестация смысловой корректности всех 171 рецептов и не доказательство работоспособности ещё не созданных hosts. [Полная таблица по 50 ID](audit/registry-coverage.md), [машинная сверка](audit/registry-coverage.json).

Многие проблемы из приведённых пользователем диалогов уже исправлены в текущем core: переходы по stable ID, ожидание того же процесса, запрет выдавать 0→0 за закрытую учебную цель, часть acquisition-бюджетов, смысл одноклассового WIKI-MARGIN и запрет объяснять его регрессию сравнением с другим набором WIKI-TAXONOMY. Они не зарегистрированы повторно как новые находки.

Остались конкретные документные расхождения:

- **GRAD-ACCUM-COPY-01 и FROZEN-BROADCAST-MAP-01:** карточки/один контракт назначают `pwsh`, JSON/другой контракт — `powershell` для того же wrapper. Это разные runtime contracts. Подготовлен точный проект согласования с PowerShell Core 7 на Windows x64 и обязательной записью фактически доступной версии; её наличие не проверено. Автоматической подмены executable нет.
- **WIKI-FEATURE-KEYS-01 и WIKI-FEATURES-ONCE-01:** в индексе остаётся «Документация / Wiki», хотя обучается выбор маршрута, то есть оркестрация D07. Подготовлена адресная поправка маркировки; данные и учебная цель не меняются.

Резолюции и поля для будущего согласованного изменения — [additive-card-amendments.md](audit/additive-card-amendments.md). Защищённая папка в этой сессии не изменена.

## 4. Успешные старые механизмы в соседней ветке

Первичные сохранённые записи `external_domains` подтверждают, что историю нельзя свести к неудачным экспериментам:

- **E25:** accuracy 0,3438→0,875 у действительно обучаемого POS/шаблонного классификатора; время 0,4→15,4 ms. Это полезность конкретного признакового ученика на синтетической панели.
- **E43:** retention 0,3226→0,3978 при добавлении replay в обучение bigram; время 0,1→5,8 ms. Это реальное обучение счётной памяти, не продолжение LoRA checkpoint.
- **E09:** raw0,2413→0,3507 сохраняется, но baseline и kNN оценены на разных количествах переходов. Утверждать эту величину как чистый causal gain нельзя; AST-признаки при этом относятся именно к коду.
- **E26:** 0,4→1 демонстрирует полезный контекстный словарь; runner использует BuildDefault, поэтому эта запись сама по себе не доказывает приобретение новых знаний.

[Таблица raw/source, точные ограничения и ветки](historical/HISTORICAL-PPMI-HIERARCHY-FINDINGS.md). Переносить все четыре результата на один нейронный Student или на все предметы нельзя.

## 5. Что делать с этим пакетом

Текущий приоритет сохранён: **разблокировать настоящее обучение → согласовать конфликты → принять обновления/новые карточки → заниматься периферийными проверками**. При отсутствии назначенного ID canonical маршрут начинается с PA01, затем исправленный ingress, затем открытая учебная цель N63C. Прямое указание пользователя по ID выше любого локального порядка.

Для новых документных кандидатов порядок **HCL → SVD → attention** задан в [реестре принятия](02-priorities-and-adoption.md) и [registry.json](registry.json). После измеренного полезного результата появляется кандидат исправления с регрессиями; решение о product transfer остаётся за Любой. Source-only гипотеза пока не получает статус «удачное исправление».

Требование «все найденные детали уже покрыты в защищённых экспериментах» **пока не выполнено для трёх новых факторов**: их отдельные A/B-карточки там не найдены. Этот пакет закрывает описание в разрешённом `possibleDifs` и явно показывает, что нужно принять в канонический каталог. Он не скрывает эту границу утверждением о полном покрытии и не меняет запрещённую папку.
