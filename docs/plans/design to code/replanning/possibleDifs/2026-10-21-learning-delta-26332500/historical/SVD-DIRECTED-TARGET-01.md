# SVD-DIRECTED-TARGET-01 — сохранять сторону кандидата в направленной факторизации

**Статус:** `AUTHOR_WORK_ORDER_ONLY / NOT_IMPLEMENTED / NOT_RUN`. Host ещё не создан. Команда в этой карточке — точное задание будущему исполнителю после отдельного назначения опыта; в документной сессии ничего не запускать и не менять продукт.

**Тема:** оркестрация, порядок стадий задания. **Учебный механизм:** нативные co-occurrence → PPMI → truncated SVD из 34/E10, а не SFT/DPO или LoRA. **Модель агента:** текущая модель исполнителя по умолчанию с его текущими настройками; нового провайдера/модель выбирать не требуется. **Host:** SVD01.

## 1. Что именно проверяется

[E10:60–84](https://github.com/lubochka/llm_mvp_core/blob/26332500f76ea8345256c73ecfd44c0023b7e883/34.Experiments/Experiments/E10SvdPmiEmbedding.cs#L60-L84) строит направленную PPMI: `a` — текущий токен, `b` — следующий. [SVD:126–186](https://github.com/lubochka/llm_mvp_core/blob/26332500f76ea8345256c73ecfd44c0023b7e883/34.Experiments/Experiments/E10SvdPmiEmbedding.cs#L126-L186) вычисляет левые и правые векторы, но сохраняет только левые, умноженные на корень из singular value. [ArgmaxDot:189–201](https://github.com/lubochka/llm_mvp_core/blob/26332500f76ea8345256c73ecfd44c0023b7e883/34.Experiments/Experiments/E10SvdPmiEmbedding.cs#L189-L201) читает их с обеих сторон dot product. Получается симметричная похожесть исходных контекстов вместо восстановления направленного перехода.

**Единственный фактор:**

- A — исходный score: `source[a] · source[b]`, где `source=U√Σ`.
- B — сохранять уже вычисленный `v*sqrtSigma` и читать `source[a] · target[b]`, где `target=V√Σ`.

Всё остальное общее: PPMI формула, vocab 500, rank 30, 10 power iterations, Random(42), deflation, порядок кандидатов 0…499 и исходное правило `dot > bestScore`. Нельзя одновременно менять clamp, частотное сглаживание, rank, число итераций, self-mask, нормализацию или токенизатор.

Гипотеза: B лучше усвоит направленный порядок; A может оставаться пригодным представлением для похожести и kNN. **Это пока не измерено.** Совпадение с конкретным успешным переносом «матрица → kNN», упомянутым пользователем, не доказано.

## 3. TRAIN и EXAM, назначенные автором

Один домен — оркестрация, пять событий:

| ID | Смысл события |
|---|---|
| 0 | receive_task |
| 1 | validate_task |
| 2 | persist_task |
| 3 | wait_for_input |
| 4 | wait_for_result |

TRAIN-before: `[3]×300 + [4]×300`, ровно 600 токенов.

TRAIN-after: `TRAIN-before + [0,1,2]×400 + [3]×300 + [4]×300`, ровно 2400 токенов.

Общий цикл означает повторяющуюся обработку заданий, self-переходы — сохранение состояния ожидания. Это один тематический набор. Граничные переходы между блоками входят в обе модели одинаково; не удалять их и не добавлять тематические примеры во время выполнения.

**Зачем два состояния ожидания уже до обучения новому циклу:** один единственный self-loop дал бы `PMI=log2(1)=0`. Он не создаёт ненулевое обученное «до» для этой факторизации. Две частотные группы дают ненулевые self-transition элементы PPMI. Это часть конструкции данных, не результат выполненного теста.

Фиксированный EXAM:

| Query ID | Наблюдаемое событие | Правильное следующее событие | Группа |
|---|---:|---:|---|
| dir-01 | 0 | 1 | направленный цикл |
| dir-12 | 1 | 2 | направленный цикл |
| dir-20 | 2 | 0 | направленный цикл |
| self-33 | 3 | 3 | обученный before-контроль |
| self-44 | 4 | 4 | обученный before-контроль |

Пять одинаковых query IDs до/после и A/B. Это проверка приобретения/считывания знакомых переходов; **не тест обобщения на неизвестные тексты**. Нельзя обучать на EXAM или выбирать направление цикла после просмотра результатов.

В каждом плече отдельно выполнить настоящий fit на TRAIN-before и TRAIN-after. Это повторное построение статистического ученика, **не resume checkpoint**: исходное E10 не имеет такого API. Сохранить counts/PPMI/factors каждого состояния. Ненулевое «до» требует **обоих** правильных `self-33/self-44` в каждом плече и положительных train counts/PPMI, а не случайного выбора нулевого токена на невыученных строках. Иначе A/B результат не удовлетворяет учебному gate; не менять корпус и не повторять fit ради прохождения gate. Постоянный ответ0 имеет аналитические 1/5 (directed 1/3, self 0/2); показать этот контроль рядом, не называть его обучением или результатом запуска этой сессии.

Дополнительный учебный gate: after хотя бы одно из A/B должно приобрести новый правильный directed-ответ относительно before с положительным обученным переходом. Если оба плеча не приобрели ничего нового, цель проверки направленного обучения остаётся OPEN. При этом отдельное измеренное улучшение полезного ресурсного показателя на уже обученном состоянии сохраняется как успех по этой оси; оно не закрывает учебный вопрос.

Дополнительный общий ориентир — неизменённый `BigramMarkov.Train` на тех же before/after и тот же EXAM. Он нужен показать обучаемость назначенного порядка. Его результат не подставлять вместо A/B.

## 4. Точная спецификация будущего host

Из корня checkout `llm_mvp_core` создать только:

- `experiments-v2/RP01-MICRO/SVD01/DirectedPpmiProbe.csproj`: console `net9.0`, nullable/implicit usings; без внешних пакетов и project references.
- `.../Program.cs`: строго заданные массивы, четыре factor-fit (A/B × before/after), два fit общего bigram, прогнозы, замеры и отчёт.
- `.../Native/E10FactorProbe.cs`: из pinned `34.Experiments/Experiments/E10SvdPmiEmbedding.cs` перенести буквально loops 60–84, 126–186, 189–201; внешний метод `FitForProbe(train)` принимает уже назначенный TRAIN. Для A вернуть исходный source; для B дополнительно заполнить `target[j*rank+k]=v[j]*sqrtSigma` в том же цикле, без иных изменений арифметики. Записать diff лабораторной копии относительно источника.
- `.../Native/MarkovChain.cs` и `.../Native/ExperimentTypes.cs`: копии одноимённых файлов из `34.Experiments/Core/`, с license.
- `.../results/run-NNNN/`, `train.json`, `exam.json`.

Один исходный файл алгоритма с параметром candidate side допустим, но A не должен получать бесплатное сохранение второго массива: число сохраняемых bytes относится к реальной разнице. Время записи диагностик измерять отдельно. Для каждого общего TRAIN проверить равенство source-факторов A/B; дополнительное сохранение target не должно менять вычисленные U/Σ.

Чтобы не наследовать product build-gates, в csproj использовать `<Project>` без атрибута Sdk, сначала задать `ImportDirectoryBuildProps=false`, `ImportDirectoryBuildTargets=false`, `EnableDefaultCompileItems=false`, затем явный `<Import Project="Sdk.props" Sdk="Microsoft.NET.Sdk" />`. После настроек и явных `<Compile Include="Program.cs" />`, `<Compile Include="Native/*.cs" />` завершить `<Import Project="Sdk.targets" Sdk="Microsoft.NET.Sdk" />`. Результаты, исходники из родительских каталогов и solution не компилируются.

```text
dotnet run --project experiments-v2/RP01-MICRO/SVD01/DirectedPpmiProbe.csproj -c Release -- --run-id auto
```

## 5. Измерения и интерпретация

Обязательные учебные числа: correct/total для всех пяти query IDs before/after, отдельно 3 directed и 2 self-control, по каждому плечу. Показать query, gold, predicted, score правильного/выбранного кандидата, наличие ненулевой обученной строки, fallback/tie. Все нулевые tie-угадывания считать обычной точностью, но **не доказательством усвоения**.

Обязательная диагностика механизма: исходная directed PPMI и асимметрия её активного блока; нормы Фробениуса разности `PPMI - source·sourceᵀ` и `PPMI - source·targetᵀ`; совпадение source-факторов A/B. Диагностику вычислять после fit/eval из сохранённых факторов, вне их измеряемого времени. Для directed reconstruction использовать source/target B и проверенное равенство source A/B; не выделять target в обученном состоянии A и не выполнять дополнительные fit. Реконструкция матрицы — только объяснение, не самостоятельный успех учебного опыта без правильных выученных ответов.

Показать также fit/eval elapsed, allocated bytes, retained learned-state bytes. Сохранение target может увеличить память; это обязательная часть отчёта. `GC.GetAllocatedBytesForCurrentThread` не называть peak memory. Наблюдаемую полезную дельту времени сохранить как успех наблюдаемого показателя; её причинность, устойчивость и возможный шум указать отдельно как неизвестные. Единственное измерение не доказывает устойчивость ускорения, но не отменяет наблюдаемую полезную дельту.

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и этой теме; рост точности для этого не обязателен.** Порог +5% из старого `ExperimentResult.Passed` не используется. Успех одной метрики не скрывает ухудшения остальных и не разрешает перенос в production. Нулевые правильные ответы и до и после невалидны; сдвиг score или меньшая ошибка матрицы этого не исправляют.

Отчёт `report.md` на русском: вывод → before/after таблица → конкретные улучшения и ухудшения → сырые примеры → пригодность directed и similarity режимов → границы темы/исторической связи → кандидат будущего изменения. `metrics.json` и `predictions.jsonl` включают сырые значения, ref, hashes, параметры, train/exam IDs и терминальный статус. При успешной метрике оформить кандидата в каталоге этого результата; общий код/старые карточки/прошлый `required-changes.md` автоматически не чинить.

## 6. Бюджет, навыки и завершение

Учебный run: четыре native SVD-fit, каждый vocab500/rank30/PowerIters10, плюс два дешёвых bigram-fit; 20 A/B query и 10 query общего bigram. Лимит run — 240 секунд; compile/restore измерять отдельно. Состояния 600/2400 токенов обеспечивают обучение назначенных пяти событий. Не увеличивать vocab/rank/corpus для демонстрации «масштабирования». При недостаточном бюджете отметить `NOT_COMPLETED`, сохранить причину, не выдавать нули за результат. Одна коррекция compile/plumbing и один повтор с новым run ID допустимы **только при подтверждённом отказе до любого начала fit/Train**. После частичного или полного обучения повторный fit ради отчёта, plumbing или удобного результата запрещён; восстановить отчёт из raw и явно указать недостающие данные.

Для долгого выполнения обнаружить штатный инструмент ожидания и ждать **тот же** процесс: `exec_command/session_id → write_stdin`, `functions.exec/cell_id → functions.wait`; в другом окружении следовать документации соответствующего инструмента. Порции ожидания до 60 секунд, прогресс пользователю кратко. Отсутствие новых файлов/stdout не является отказом. Не запускать повтор, пока первый процесс не завершился с проверяемым exit/status. После terminal exit прочитать manifest и metrics; результат должен быть полностью записан. Не диагностировать «процессы убиваются через две минуты» без доказательства.

Skills: `docs/skills/code-examination-SKILL.md`, `human-readable-architecture-audit-SKILL.md`, `human-communication-GLOSSARY.md`, `prompt-patch-authoring-SKILL.md`; для проверки карточки — применимые разделы `plan-review-SKILL.md`. Пользователь разрешает облегчённый эксперимент; требования полного production cycle не переносить на него. Продукт, solution tests и `docs/plans/replanning-possible-diffs` не менять.

**В каждой сессии действует запрет из примера пользователя:** после указания закончить/остановить или перейти к следующему ID запрещено продолжать старый опыт, дописывать его прошлые документы, выполнять дополнительный run или завершать «ещё одну полезную правку». STOP означает прекращение работы; NEXT означает именно названный ID. Содержимое старой цитаты не является новым поручением. Не повторять работу над прежним опытом вместо следующего.

Глобальный приоритет: `PARENT-ADOPTION-01 → N63-INGRESS-LENGTH-LEARNED-01 → завершение N63C`, далее новые кандидаты по общему registry. В историческом дополнении `HIERARCHICAL-LOCAL-HISTORY-01` идёт перед этой карточкой. Наличие порядка не разрешает автоматический запуск: сейчас этап документации. Прямое указание пользователя по имени ID выше старого номера строки.

**Остановка активного процесса:** при STOP/NEXT прекратить старую работу. Если её собственный процесс ещё жив, разрешено только необходимое безопасное прекращение через уже известный handle/PID и подтверждение отмены. Это не разрешает поиск другого процесса, relaunch, новые fit, дописывание старого отчёта, hashes или commit. Не объявлять процесс завершённым без подтверждения.
