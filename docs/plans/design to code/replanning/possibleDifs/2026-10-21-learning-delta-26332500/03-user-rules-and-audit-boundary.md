# Требования пользователя: применение и предел проверки

Сессия 21.10.2026 — read-only исследование кода и сохранённых результатов, с добавлением документов только в `xiigen-planning/llm_plan3/.../possibleDifs`. Исходный core, защищённая `docs/plans/replanning-possible-diffs`, старые эксперименты и результаты не изменяются. Ни один новый обучающий run этим пакетом не заявлен.

## 1. Все 18 требований

| № | Требование | Как выполнено / что остаётся открытым |
|---|---|---|
| 1 | Небольшой причинный опыт по теме | Три новые карточки задают один фактор, фиксированные TRAIN/EXAM и before/after. HCL/SVD — оркестрация; CS01 — C# выражения. Нет утверждения о переносе на все темы |
| 2 | Любое полезное измеренное улучшение — успех по своей метрике | Правило включено в каждую карточку и промпт; рядом обязательны регрессии. Исторические N60/WT/N-KU не отбрасываются из-за неизменной общей accuracy или вреда по другому показателю |
| 3 | Измерять обучение, не постороннюю функцию | HCL: Train→counts→reader. SVD: counts→PPMI→factors→prediction. CS01: native Trainer→LoRA→optimizer→тот же Student. Статическая инвариантность/счёт операций не заменяют учебный результат |
| 4 | Зависимая функция допускается с точным кодом и способом исправления | У новых карточек приведены конкретные методы оригинала и будущий source-copy patch. StackAndVersion без установленного fit/learning link не получает эксперимент |
| 5 | Сначала разблокировать обучение | Сохранён текущий порядок PA01→исправленный ingress→открытая цель N63C; не переназначены потреблённые старые runs |
| 6 | До успеха изолированный эксперимент, без полного ремонта продукта | Только documentary author work orders. Ни реализации runner, ни product patch, ни полного CI. Future candidate создаётся после измеренного полезного результата |
| 7 | Не заставлять исполнителя искать место, модель, команду, решение конфликта | Каждая карточка содержит host, fixed inputs, CLI, source paths, default session model, no-overwrite и правила конфликта. Future CLI явно не выдаётся за существующую |
| 8 | Не удалять старые эксперименты | Публикация этого пакета только добавляет новый каталог; все прежние файлы сохраняются |
| 9 | Обучение → конфликты → обновления → периферия | Отдельный [реестр приоритетов](02-priorities-and-adoption.md); конкретный launch conflict остаётся проектом резолюции в разрешённом каталоге |
| 10 | Экспериментальные исключения не равны prod/submission | Малый source-copy host допустим для опыта; это не ослабляет product контракты и не разрешает интеграцию. Полная производственная цепочка не навязывается до результата |
| 11 | Сейчас документировать результаты и кандидатов | [Аудит результатов](audit/README.md) сохраняет полезные измерения и их пределы. Три новые идеи помечены гипотезами без измеренного выигрыша; их нельзя выдавать за успешные исправления |
| 12 | Язык отчёта и навыки заданы заранее | Русский; точные skills и роли приведены ниже и в карточках/промптах. Агент не выбирает новую модель или формат |
| 13 | После NEXT/STOP не продолжать старую работу | Отдельный явный запрет в каждой новой карточке и каждом новом промпте. Цитата из прежнего разговора трактуется как пример недопустимого поведения, а не как текущий приказ остановить этот аудит |
| 14 | Порядок понятен из registry | Существующая очередь отделена от реестра документных добавлений; новые ID имеют определённый локальный порядок и next, без автоматического запуска |
| 15 | Настоящий минимальный learner, ненулевое before и достаточный бюджет | HCL/SVD назначают реально обученные controls; CS01 — общий acquisition до S0 с 400 actual updates и явной проверкой приобретённого ответа. Предположение о достаточности бюджета не выдаётся за измеренный факт; 0→0 остаётся открытой целью |
| 16 | Уметь находить инструменты и ждать | В карточках/промптах указаны discovery, session/cell handles, bounded waits того же процесса, запрет relaunch по пустому логу, учёт поздней ошибки после Train. Runtime не запускался |
| 17 | Индекс и карточки согласованы | На текущем core сверены все 50 ID/card/next, точные anchors и 37 future entries; структурных ошибок нет. Найдены два literal runtime conflicts вне этой структурной проверки. JSON и подробности в [аудите](audit/README.md) |
| 18 | Не смешивать темы и не делать ложный вывод из состава TRAIN | Новые наборы фиксированы одной темой, классы/controls явны, constant baseline и familiar-transition limits раскрыты. WIKI-MARGIN one-class collapse и N60 false-accept regression сохранены в выводах; causal объяснение между разными наборами не выдумано |

## 2. Использованные навыки

Источник — запрошенная пользователем [папка docs/skills на pinned core][skills]. Применялись правила, относящиеся к документному исследованию; старые generic production gates и overrides моделей не подменяют текущий пользовательский объём.

| Роль | Файл | Практическое применение |
|---|---|---|
| Архитектор | `architect-behavior-classifier-SKILL.md`, `human-readable-architecture-audit-SKILL.md` | Отделить обучение, состояние и потребителя; назвать конкретный дефект чтения состояния, не предлагать «сделать всё обучаемым» |
| Планирование | `phase-planning-SKILL.md`, `planning-session-startup-SKILL.md`, `context-package-design-SKILL.md` | Точные входы, host, бюджет, текущая фаза, next ID и критерий завершения |
| Проверка плана | `plan-review-SKILL.md` | Увидеть противоречия runtime, скрытый повтор обучения, неверный счёт native calls, неподтверждённую readiness |
| Проверка кода | `code-examination-SKILL.md` | Читать caller→learner→reader, pinned версии и реальные операции; различать статический факт и причинный эффект |
| Эксперимент | `experiment-design-SKILL.md` | Один фактор, общий набор, trained before, useful metrics и отрицательные/постоянные controls; без автоматического scale-up |
| Промпт | `prompt-patch-authoring-SKILL.md` | Полное задание автору/исполнителю, фиксированные пути и STOP/NEXT, отсутствие произвольной смены модели/набора |
| Человеческая коммуникация | `human-communication-GLOSSARY.md` | Тема отдельно от механизма, успех метрики отдельно от интеграции, наблюдение отдельно от гипотезы |

Для больших файлов навыков применялось адресное чтение релевантных разделов; полная повторная загрузка всех многотысячных governance-файлов не заявляется. `code-examination`, `prompt-patch-authoring`, `human-communication`, `experiment-design` и `context-package-design` прочитаны полностью. Контекст предыдущих сессий использован только как указатель; факты проверялись по актуальным pinned источникам.

## 3. Как выполнялась проверка

1. Зафиксированы HEAD core/planning и SHA соседних веток. Кэш core обновлён на все 263 изменённые/добавленные файла между предыдущим снимком и текущим HEAD; полученные bytes проверены по Git blob SHA. Это техническая проверка версии, не смысловое чтение каждого файла.
2. Выполнен поиск новых механизмов в 976 Markdown `possibleDifs` и 406 Markdown protected каталога, с сопоставлением ближайших owners. Отсутствие поискового совпадения не доказательство абсолютной новизны; точные механизмы дополнительно сверены по смыслу.
3. Полностью механически проверены 50 registry записей и обязательные contract/STOP/NEXT/default-model/Russian-report ссылки в 188 документах: 171 карточка, индекс, 16 standalone prompts. Содержательная проверка каждого из 171 рецептов не заявляется. Сохранённые 13 attempts и их ограничения разобраны отдельно.
4. Новые карточки прочитаны другим исследователем. Замечания о числе native Train, constant baseline, retry после частичного обучения и трактовке шумной ресурсной дельты учтены до публикации. Это документный review; компиляция и runtime не выполнялись.
5. Перед публикацией проверяются только ссылки, counts, статусы и additive write scope. В защищённую папку ничего не записывается; её текущий SHA остаётся источником, а не местом правки.

## 4. Что этот пакет сознательно не утверждает

- Не все детали уже описаны **в защищённой папке**: для трёх новых факторов отдельного причинного опыта там не найдено. Здесь приложены карточки для принятия; перенос в protected в этой сессии запрещён пользователем.
- Не доказана единственная причина провала RP01, научная новизна идей вне проверенного корпуса, работоспособность будущих hosts или успех новых A/B.
- Не доказано широкое обобщение по результату на знакомых переходах, одном C# семействе, one-class маршрутизаторе или разных baseline/kNN панелях.
- Source snapshot не удостоверяет автоматически происхождение каждого сохранённого бинарника. Для N63C это материальный открытый вопрос, а не формальная придирка.
- Новые файлы не переписывают ранее измеренные цифры и не отменяют полезные результаты из-за регрессии другого показателя. Все ограничения показаны рядом с соответствующим успехом.
