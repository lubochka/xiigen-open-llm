## 0. Человеческий вывод, не путать три разных вида обучения

**Было реально три разнородных механизма:** (1) Student DPO с обновлением LoRA, (2) отдельные обучаемые Unit, contextual dictionaries, phrase/word memory и structural kNN, (3) детерминированные доменные ограничения / product routing / verifier. Успех узкого старого Unit/kNN не доказывает обучение Student, а отсутствие Student gain не обесценивает обучаемую память. Потеря качества может произойти на data→gradient, gradient→generation, chosen→Unit, learned state→KNN index, KNN→final verifier, storage→cold consumer или eval→заявленный результат. Для каждой гипотезы **обязательно назвать получателя**.

**Документ RP01 от 16.10:** B0 random-untrained vocab 629, hidden 512, layers 4; C#500 и ENRU500 дали реальные LoRA обновления, но heldout/free `0/3→0/3` и `0/4→0/4`. 500 C# examples получены из 25 parameterized families; `16` LoRA tensors изменились, `39` base tensors не изменились. Это **исторические сохранённые** наблюдения, не новый переизмеренный здесь результат: [RP01 causal diagnostic](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-CAUSAL-LEARNING-DIAGNOSTIC-PACK.md) и [RP01 code audit](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md).

## 3. Доменные включатели — не одна глобальная метрика сходства

| Домен | Сигналы, которые **должны рассматриваться** | Когда применять и когда НЕ применять |
|---|---|---|
| C# / Design-to-Code | Roslyn AST node kind + parent/role + method context + operator/nullability precedence | Feature-gated KNN/learned path; не использовать POS русского перевода как AST |
| SQL | SQL AST, `JOIN ON` vs `WHERE`, NULL/UNKNOWN, dialect, column identity, predicate scope | Separate SQL semantic gold; числа cosine не подтверждают эквивалентность запроса |
| RU/EN/HE/ES | POS left/right, agreement, case, negation scope, language direction, token order; для phrase+word N33 original-index | Только для meaningful grammar; не запускать C# AST parser на естественный язык; `—` может быть безобидным в RU_EN и семантическим в DSL |
| DSL / graphs / workflows | Type of edge, direction `->`, `=>`, relation role, scope, legal graph composition | Operator-preserving tokenizer; сохранить N30-03 false adjacency независимо от N33 ordinal fix |
| Domain-independent episodic control | context/time, replay age, source-family validity, learned recipient identity, previous-law regression | Нельзя обобщить один context action KNN на все домены; k/threshold адаптивные по budget & correctness |
| All domains | Training vs ordinary inference shape, checkpoint/state identity, independent gold, correct domain law, failed attempts / abstain | Может быть универсальным validation **контрактом**, но не универсальной feature function |

## 4. Самый короткий порядок следующих действий: без очередной 500-pair кампании

**Stage B2: alias collision kNN (отдельная переменная):** [N34](34-NEW-ONE-LESSON-DOUBLE-INSERT-UNDER-ALIAS-SIGNATURE-2026-10-16.md), выполняем только если actual Unit key equality и KNN path достигнуты. Один native short probe против per-lesson signature dedup, одинаковая память и слепой target-law, не смешивать с N33 или DPO.

**Stage C: другой приоритет по реальному домену:** если основной сбой выявлен в E09, восстановить один **same-file paired validation set** со стабильным AST mapping; если E26 context disambiguation — смоделировать one-factor POS left/right memory; если kNN consumer не используется — сначала починить adoption, а не пробовать новую метрику расстояния.

**Stage D: решение:** `MECHANISM_VERIFIED` ≠ `HELDOUT_GAIN_OBSERVED`. По каждой микропроверке сообщить `source_verified/native_run/changed_learned_state/consumer_used/cold_restore/semantic_wins_losses/cost/roll_back`. Жизнеспособная гипотеза переносится в приоритетный план **после** существенного paired выигрыша и без критических нарушений законов.
