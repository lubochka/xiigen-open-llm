### Риск потери журнала и точный add-only override

Единственный текущий `Run-With-Learning-Signal.ps1` сначала выполняет build A/B с перенаправлением в существующие host logs, затем строкой19 вызывает подготовку с `*> preparation.log`. Внешний guard перед этими действиями в wrapper отсутствует. При ошибочном повторном вызове перенаправление способно затереть прошлый журнал **до** отказа внутренней custody-границы. Существующий native claim не даёт wrapper права повторно запускать обучение и не защищает уже открытые shell redirect logs.

В новую добавочную карточку статуса необходимо буквально перенести:

1. ID `LC-REF-CACHE` имеет issued evidence. Нельзя выполнять `Run-With-Learning-Signal.ps1`, отдельный `Run.ps1`, build, prepare, arm, создавать `results-NN` или удалять marker. Это состояние с неизвестным завершением, не свободный слот.
2. Существующий handle из исполнительской сессии наблюдать штатным wait по контракту31. В сессии без handle сначала разрешён только read-only поиск сохранённого terminal receipt/логов и проверка точного PID+processStart; один PID без времени не подтверждает владельца. Отсутствие terminal-файла не разрешает повтор.
3. При завершении сохранить отдельно completed common updates, `learning_qualified`, A/B execution и causal verdict. До наличия данных не писать нули вместо неизвестных чисел и не объявлять gain cache.
4. Для будущих ещё не выданных копий этого wrapper предписать проверку existing host/result/claim **до build и до первого log redirect**, с сохранением всех старых файлов. Изменяемое место: `experiments-v2/RP01-MICRO/N61-REF-CACHE/Run-With-Learning-Signal.ps1:9–19`; продуктовые custody guards не ослаблять. Эта запись — кандидат исправления экспериментального запуска, не команда менять существующий работающий процесс.

## 9. Воспроизводимость самого аудита

[experiment-card-coverage.json](evidence/experiment-card-coverage.json) содержит все50строк, исходную позицию/статус/NEXT, локальный read-only source, source URL, marker presence, anchor/next checks, audit_status и примечания. Проверка marker presence не маскируется под проверку качества опыта. Исходные index/status/NEXT сохранены внутри того же JSON. В `protected-read/` сохранены прочитанные pinned документы и raw, необходимые для проверки ключевых цифр; эта временная кеш-копия не меняет remote core.

Скиллы использованы по назначению: архитектурный взгляд source→learner→state→consumer; plan-review — явные зависимости/ready vs designed; code-examination — различение исходника, raw и inference; prompt authoring — точный entry/state/STOP/NEXT; human communication — результат и предел на русском без замены задачи пользователя. Исторические требования об отдельных недоступных моделях/десятках review-проходов не перенесены как новый блокер поверх прямых указаний пользователя.
