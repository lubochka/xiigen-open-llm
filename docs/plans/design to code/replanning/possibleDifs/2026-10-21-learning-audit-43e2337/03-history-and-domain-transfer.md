## 1. Что удалось подтвердить

В истории есть положительные результаты обучаемых kNN. Ранний отрицательный статус семейства не позволяет отбросить его позднюю версию. В частности, E09 Tier1 сообщает рост на той же оценочной панели; E40V2 сообщает рост после исправления состава train/validation. Эти факты сохраняются вместе с затратами и ограничениями. Они не доказывают автоматически, что текущий RP01 вызывает именно такой learner или восстанавливает именно его обученную память.

Точная единая цепочка «данный механизм сначала обучался внутри матрицы → тот же механизм с теми же примерами/целями перенесён в функцию kNN → получен сопоставимый положительный результат» по лично прочитанным E07/E09/E22/E34/E36/E40 источникам не установлена. Это ограничение данной выборки источников; пользовательское свидетельство исторического успеха не опровергается. Совпадение номера E09 или слов matrix/kNN в commit message недостаточно для такого отождествления.

## 3. E09: что действительно перенесли и что изменилось

`E09StructuralKnn.Run:64–67` обучает список `(StructuralVector,nextLabel)`, `:74` читает его для EXAM. Это обучаемая exemplar memory, хотя distance задаётся фиксированными весами. Слово `BpeId` в этом опыте не означает BPE: `BuildTokenVectors:113–120` ранжирует набор Roslyn node kinds **отдельно для каждого файла**. Один и тот же integer может иметь разные смыслы между файлами. `:30–32` режет соединённую последовательность узлов80/20; `:70` ограничивает только kNN-панель500узлами. [Полный source](https://github.com/lubochka/llm_mvp_core/blob/43e2337d68dad0e4ab8d7fbb0cea38406b592b61/35.ExperimentsV2/Experiments/E09StructuralKnn.cs#L18-L123).

Реальный [commit переноса27ae0326](https://github.com/lubochka/llm_mvp_core/commit/27ae03266ae2f7300d63e915795c0ff62369fa67) добавляет `12.SemanticCompiler/Prediction/StructuralKnn.cs` и удаляет старые predictor/extractor из35.ExperimentsV2. В новом `TrainFromSource:132–141` label — `NodeTypeId(nextNode)`; `NodeTypeId:99–102` берёт kind modulo200. Значит production и исторический runner имеют разные target codecs. `Predict:156–160` при равном количестве голосов выбирает минимальный integer label; удалённый predictor выбирал первый максимальный count из последовательности соседей. Это подтверждённое изменение алгоритма выбора, но его величина влияния на RP01 здесь не измерена. [Текущий код](https://github.com/lubochka/llm_mvp_core/blob/43e2337d68dad0e4ab8d7fbb0cea38406b592b61/12.SemanticCompiler/Prediction/StructuralKnn.cs#L99-L167).

Текущий production путь требует явного обучения и включения функции. `SemanticCompilerFacade.TrainStructuralKnn:206–225` собирает пары отдельно по C# files и вызывает `Train` только при≥10парах. `PredictStructuralNextTokens:299–310` ограничивает consumer C# и обученным predictor. `SemanticCompilerOptions:14–15` оставляет `UseStructuralKnn=false` по умолчанию. Наличие класса/исторического success не подтверждает вызов этого пути в RP01. [Writer/reader](https://github.com/lubochka/llm_mvp_core/blob/43e2337d68dad0e4ab8d7fbb0cea38406b592b61/12.SemanticCompiler/SemanticCompilerFacade.cs#L206-L310), [default](https://github.com/lubochka/llm_mvp_core/blob/43e2337d68dad0e4ab8d7fbb0cea38406b592b61/12.SemanticCompiler/SemanticCompilerOptions.cs#L14-L33).

Commit labels также не заменяют receipt. Историческая последовательность включает introduction `7f6deeeceb2386fef18ebfff0c7f4cfd3d69302f`, временное снижение порога pass `0414c8b38d6f03a3200fb309d104f9eb5c4bc0f8` и возвращение5% `75d9330ab2adc82bd08ceebd807dc9696332920a`. Сообщение «FAILED +3.1%» и сохранённое `passed=true` могут отражать разные policy/состояния отчёта. ## 5. Домены и состояние обучения

| Учебная тема | Подтверждённая форма механизма | Ограничение переноса |
|---|---|---|
| Программирование/C# | E09 структурные Roslyn признаки, предки/роль/порядок дочернего узла; memory обучается на следующем AST kind | AST distance не является универсальным language embedding. В natural-language переводе нет тех же node types и train target. |
| Оркестрация | E22 routing; E34 retrieval/fusion; E36 correction routing; E40 выбор источника | Разные labels и отрицательные контроли внутри routing topic допустимы. Смешение предметных уроков и смешение route labels — разные вещи. Нужно проверять именно downstream consumer, если claim касается исправления другого learner. |
| Перевод | `TranslationTrainedUnits` хранит поправки tokenizer/word map/exact map/phrase/kNN; prediction читает эти состояния каскадом | Синтаксис обычного предложения, agent/recipient, tense и отрицание значимы иначе, чем C# AST. Положительное memorization нельзя выдавать за правило на новые композиции без отдельного EXAM. |
| Логические Units | `KnnLogicalUnit` строит BPE/predicate vector и HNSW из размеченных примеров, затем выбирает ближайший output | Bag features могут терять порядок/роль; этот вывод — свойство representation, не измеренная регрессия. Перед экспериментом нужен конкретный topic и набор различающих примеров. |

В `TranslationUnitContracts.TranslationKnnStore` insert append-ит пары, а nearest/cascade читает bucket order. `TranslationTrainedUnits` проверяет exact/phrase/word-map до kNN. `TranslationMemorySourceLaw` использует ограниченные фиксированные английские шаблоны для противоречий. Эти факты требуют при переносе сохранять и изучать не только neural weights, но и настоящую learned memory, её порядок, codec, source-language/context и consumer. Из этого не следует новое измеренное улучшение. Первичные файлы сохранены полностью; детали уже описаны в существующих карточках, поэтому новый дублирующий ID не создаётся.

## 6. Сопоставление с уже существующим расследованием

Лично перепроверенные механизмы **не объявлены новыми гипотезами**: `01-historical-experiments-and-comparability.md` уже различает старый/новый E09; `10-historical-function-transfer-and-learning.md` уже описывает E40V2, его потерянную обучаемую память при production-переносе, E38V2 consumer и E35; `38-e09-transfer-labels-and-opt-in-consumer.md` и P27 покрывают E09 label codec; `2026-10-20-primary-evidence.md:109–143` уже сохраняет именно положительный E09 Tier1 receipt и его193 matched transitions. `09-domain-functions-and-sibling-branches.md` уже рассматривает morphology из `language_translate` и не приравнивает наличие appender к доказанному улучшению.

Этот подпроход добавляет проверку актуального pinned snapshot и повторное чтение primary JSON/code, а не новое утверждение об их новизне. Для главного отчёта существенны три действия: не потерять реальные положительные сигналы при агрегации статусов; не превратить ограничение EXAM в отказ от обучаемого механизма; не назвать lookup/metadata/statically initialized rule успешным обучением без изменения state и его реального reader.

Новые эксперименты здесь не назначены. Никаких рекомендаций незаметно повторить обучение, изменить production или восстановить state через новый warm-up не выдано. Если автор нового recipe продолжит исторический lead, его обязательный deliverable — конкретный matrix donor/ref, состояние learner, lesson/query IDs и единый semantic target/EXAM после переноса. Невозможность найти этот quartet в проверенных кандидатах нельзя перекладывать на исполнителя как неопределённое поручение «сам найди эксперимент».
