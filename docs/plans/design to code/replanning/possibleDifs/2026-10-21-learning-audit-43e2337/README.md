## Что удалось установить

Объяснение ухудшения нельзя свести к «неправильной LoRA» или «kNN не обучается». В существующих источниках уже разобраны несколько разных разрывов: качество урока, поступление его нужному Unit, настоящий update, восстановление состояния и использование выученного результата обычным consumer. Для каждого нужны собственные доказательства. В этом проходе **не установлен один причинный дефект, объясняющий всю деградацию RP01**.

Получены три конкретных новых проверяемых фактора. Один касается неправильных учебных меток C# FileAction kNN; два — лишней работы в настоящем нейронном обучении. Их влияние пока не измерено. Сопоставление с существующим корпусом отделяет новый подслучай от уже известных N48/NG01, forward RMS, softmax scratch и gradient-copy.

Сохранённые положительные результаты действительно есть, включая исторические kNN и недавние native SFT/DPO/Unit-опыты. Они включены с регрессиями и ограничениями; старое слово FAILED не обнуляет полезный показатель. Вместе с тем 22 правильных токена из23 не превращены в полный правильный ответ, а предсказание одного класса на всех запросах — в доказательство различения классов.

## Что делать первым

1. **Переиспользовать уже сохранённый LC-REF-CACHE.** Поздний core0cf3634 содержит квалифицированные веса и A/B raw: два TRAIN ответа приобрели teacher-forced exact, а allocated bytes во время DPO снизились на18.01%. Подготовка закончила1000 SFT и упала на последующей валидации; это не пропажа обучения. Сохранённые weights-only нельзя выдавать за полный SFT optimizer/RNG bundle. Новых model calls не требуется; ограничения измерителя и независимого terminal receipt указаны в дополнении09.
2. **Применять уже назначенные общие обученные состояния.** Core0cf3634 закрыл проектный конфликт трёх повторных подготовок контрактом33. Наши новые нейронные пары теперь явно читают только canonical `h64-rms-row/v1` bundle. Старый RD01 common — источник будущего экспорта, а не второй путь выбора. Полные bundles ещё не materialized; отсутствие prerequisite не разрешает повторное обучение.
3. **Сохранить полезные измерения кандидатами, сохранив отрицательные дельты.** Подтверждённые N63C, WT, WM, N60, N-KU, BPE уже присутствуют в защищённом `required-changes.md`; здесь добавлено согласованное прочтение, а не дубликат нового «открытия».
4. **После отдельного поручения реализовать новые небольшие опыты.** Порядок и зависимости указаны в собственном [реестре](registry.md). Карточки, связанные лишь с чтением результата обучения, остаются ниже прямых learning blockers. Защищённая очередь из53 ID этим пакетом не перенумерована.
