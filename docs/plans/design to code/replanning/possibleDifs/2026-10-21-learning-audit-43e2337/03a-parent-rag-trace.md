## 3. Где старый документ способен снова подменить текущую задачу

1. **Перезапуск Main500 из LEARNING-EXAMINATION13/23.** Его методика относится к замороженному BATCH500. README3–21 и ACTIVE-REPAIR3–5 уже заменили dispatch на REC01–05. Наше текущее поручение ещё уже: только документировать и проектировать опыты, не исполнять REC. Старую команду нельзя использовать как разрешение на запуск.
2. **July DPO-last вместо актуального learning-first.** G/plan07:1–14 и RAG01:75–91 содержат исторические code-first/DPO_LAST/default-off statuses. Их источники сохраняются для lineage; они не отменяют сегодняшние явные правила пользователя о приоритете разблокировки обучения и исключениях для исследовательского опыта. Нельзя возвращать весь production pipeline перед доказательством маленькой гипотезы.
3. **Accuracy-only как общий критерий успеха.** F/DECISIONS:D14 говорит про установку адаптера в production; LEARNING-EXAMINATION35 — про старый semantic-result label. Текущее пользовательское правило принимает любое измеренное улучшение полезной метрики в данном домене с явными остальными дельтами. Документный кандидат не равен production adoption. Поэтому успех по latency/bytes не должен автоматически исчезать из отчёта из-за неизменной accuracy, если измерение участвует в настоящем учебном пути и учебный before/after валиден.
4. **Новое SFT вместо восстановления состояния.** Recovery23/101 предлагал diagnostic SFT→DPO versus DPO-only на историческом random B0. Это гипотеза предпосылки, не универсальная инструкция заново тренировать каждый опыт. Сегодняшний recipe обязан вначале назначить уже обученный checkpoint/tokenizer/optimizer/RNG или конкретный one-time donor builder и shared saved path. Source-generated Warmup without saved state не доказывает restoration.
5. **Память ошибок удалена как «плохие данные».** ARBITER77–96,251–271 требует сохранять rejected/warning memory с правильной ролью. Непринятый output нельзя выдавать за positive target; его failure/constraint signal всё ещё может учить retrieval, выбор validators и upstream correction. Это важно для части исторических «неудачных» опытов, которые полезны в другом consumer.
