## 1. Два списка, два временных среза — нельзя выдавать старый полный охват за нынешний

- В исходном снимке 19.10.2026 **до записи пяти документов N56** директория `possibleDifs` содержала **479 top-level entries, 463 regular files и 16 directories**. После наших пяти добавлений число файлов закономерно увеличилось; эти числа относятся только к исходному срезу. В [protected 01-full-source-registry](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/01-full-source-registry.md) исторический freeze — **360 files** от 18.10.2026 с SHA-256 и прямыми source-карточками; **103 из 463 root file names исходного среза отсутствуют именно в этом старом списке**. Это дельта имён, **не 103 новых научных находки** и не 103 без эксперимента.
- [Protected 06-findings-map](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/06-findings-map.md) отдельно сообщает актуальный рекурсивный planning-срез **790 файлов** и дополнительные дельты N53–N55; значит защищённый проект **не остановился на 360**. Нельзя объявить его «старым и неактуальным целиком».
- [Protected 00-README](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/00-README.md) описывает **125 карточек P01–P125 и 470 подслучаев**. Это число планов, а не выполненных опытов и не количество доменов.
- [Актуальный краткий план](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/README.md) направляет сначала к самому дешёвому отличающему 2-lesson/4-exam опыту и его реальному learner. `NOT_RUN` в карточках остаётся верным: [отдельный реестр 18-Oct RESULTS](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/README.md) **имеет реальные запуски**.

**Статус инвентаризации:** `SNAPSHOT_LINEAGE_MIXED` и `CURRENT_HEAD_HASH_FREEZE_MISSING_FROM_THIS_AUDIT`; нельзя получить `ALL_DETAILS_COVERED` только по числу файлов. Следующий аудит должен пройти **рекурсивно** по всем текущим файлам; для каждого извлечь `source_sha, claim, empirical_counterevidence, donor, recipient, domain_profile, experiment_id/subcase, test_status`; зафиксировать hash обоих репозиториев и искать *содержательные* дубли, не совпадения номера.

## 3. Недостатки описания эксперимента, влияющие на валидность

**3.1 Нельзя исполнить design-only опыт, которого не поддерживает production caller.** [Protected D](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/04-documentation-neural.md) прямо признаёт, что действующий `CodeDocumentationSimulationDpoExperiment` поддерживает `calibration1/main500`, а не две контрастные pairs. Рецепт логически полезен, но **не запускаем без минимального admitted micro caller**. Указать `REQUIRES_INTEGRATION`, имя точного entrypoint/CLI, входы, frozen state и security/provenance gate; до него не заявлять 2-lesson learning.

**3.2 Source hyperlinks не всегда воспроизводимы другой машиной.** Например [protected P119](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/cards/P119-learning-dynamics.md) ссылается на `C:/Users/lubao/Documents/.../possibleDifs/...md:36`; [protected programming recipe](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/02-programming.md) использует `C:/Projects/llm_mvp_core/12.SemanticCompiler/...` и строку. На другой ОС эти ссылки **не являются переносимым source evidence**. Точное исправление для будущей копии/индекса: immutable GitHub SHA URL + `#L...`, blob SHA и отдельно Path/Line, либо repo-relative Markdown ссылки с указанным branch/commit. Пользователь запретил правку protected папки — здесь только обнаружение и work order.

**3.3 16 ответов не равны одному измерению роста.** [Общая protected методика](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/01-method-and-report.md): `A0/A1/B0/B1` 4 EXAM → до16 calls, допускается переиспользовать baseline **только при доказанном функциональном тождестве**. 2 lessons/4 EXAM достаточны как дешевый *falsifier*; это **не** статистическое доказательство качества на всех доменах. Для mixed HE/EN/ES и code+SQL нужна отдельно pre-registered проверка cross-domain interference и retention.

**3.4 Конкурирующий правильный ответ не должен строить scorer.** Gold, допустимые варианты, запрет leakage и метрики «верно по смыслу» фиксируют до обучения; DPO margin/UnitCoverage/teacher answer/BuildDefault нельзя выдавать за независимый потребительский экзамен. Для абляции морфологии нельзя одновременно менять tokenization, RAG и порядок ответа. Для Native P86.a нельзя обобщать экспериментальный fractional mask на поддерживаемый binary RP01 без actual data admission trace.

**3.5 Происхождение и старые успешные результаты требуют отдельного доказательства.** Результат 19/24 в [P125](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/README.md) сильнее любого proxy, но не становится «движок всегда даёт 19/24» для другого языка или класса; фиксировать `donor_sha, checkpoint_sha, source split, train/exam, actual Flow, versions, stderr/review`. Помечать `PASSED_LOCAL_RECALL_OR_COMPOSITION`, а не `GENERAL_LEARNING_PROVEN`.

## 4. Следующая работа для read-only каталога и правила crosswalk

Созданные N56 файлы **содержат полные спецификации** новых M1/M2/M3 и доменные mini A/B; защищённый каталог содержит правильные общие рецепты, но **не содержит проверенного в этом проходе соответствия 1:1 каждой новой точной гипотезы**. Из-за read-only запрета изменения там не выполнялись.

**Acceptance для заявления `ALL_FINDINGS_COVERED`:**
1. Фиксировать HEAD обоих repos и рекурсивные manifest+SHA; выделить `source claims`, а не считать .md/.json самостоятельными гипотезами.
2. Сопоставить каждый уникальный `claim/mechanism/owner/domain/consumer` с **точным** `card+subcase+small-probe`, выделить `EXISTING`, `DESIGN_REQUIRED`, `MISSING_CALLER`, `NATIVE_DONE`, `NATIVE_REJECTED`, `BLOCKED`; N56 M1/M2/M3 пока `DESIGN_REQUIRED_FOR_READ_ONLY_CATALOG`.
3. Проверить A/B isolation, independent gold, before/after, actual update, consumer, process restore, units/time/memory, invariants и negative controls **в коде исполнителя**, не только в описании.
4. Запускать только явно разрешённые micro-cases, фиксировать raw results и независимое review; обновить **только** собственный `possibleDifs` с внешними ссылками на уже read-only receipts.

**Результат этого аудита:** `PARTIAL_COVERAGE_CONFIRMED`; `100_PERCENT_RECONCILIATION_NOT_PROVEN`; `PROTECTED_DIR_UNCHANGED`; `NATIVE_NEW_EXPERIMENTS_NOT_RUN`.
