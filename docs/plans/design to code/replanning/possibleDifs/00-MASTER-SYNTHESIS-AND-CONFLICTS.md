## Дополнение: доказанные опасные подмены в раннем переводческом API (source-only)
1. **Искусственный рост accuracy без обучения.** `TranslationMachine.TrainBatchAsync` [строки 51–86](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationMachine.cs#L51-L86) обозначен `Legacy scaffold` и возвращает `AccuracyAfter=Math.Min(AccuracyBefore+0.01,1)`, увеличивает версию, но не вызывает `ITranslationUnitTrainer.TrainOnExample`. **Это подтверждённый synthetic progress для данного API, не доказательство, что RP01 вызывал его**; другой метод `TrainStructuredBatchAsync` действительно вызывает обработку unit examples. Нужен caller-to-scientific-metric audit и запрет приравнивать history field к измеренной точности.
2. **Два API восстановления дают принципиально разную глубину.** `TranslationMachine.ExportAsync/ImportAsync` [строки 203–251](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationMachine.cs#L203-L251) работают лишь с metadata/placeholder checkpoint ref. `ExportCheckpoint/ImportCheckpoint` [строки 261–308](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationMachine.cs#L261-L308) включают настоящую KNN-store, tokenizer, executors и verifier. Это реальный **interface trap**, если вызывающий generic `ILearningMachine.ImportAsync` ожидает восстановленного поведения; при этом *RP01 full LlmModel restore уже доказан отдельно* и не должен быть смешан с этим случаем.
3. **Проверка актуальности cache.** `TranslationCheckpointCache` [строки 14–64](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationCheckpointCache.cs#L14-L64) использует mtime+byte length, не content digest. Замена файла с тем же timestamp/size может вернуть stale state, **если writer не вызывает Invalidate**; поэтому проверять caller writer прежде чем ставить BUG.
4. **Даже ранняя E09 had non-stable training labels.** `E09StructuralKnn.BuildTokenVectors` [строки 107–120](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/35.ExperimentsV2/Experiments/E09StructuralKnn.cs#L107-L120) строит `kindMap` **заново для каждого файла**. Индекс одного SyntaxKind зависит от встреченных в данном файле видов AST; смешанный corpus может обучаться на несогласованных label IDs. Плюс baseline/treatment оцениваются на разных validation subsets. Поэтому исторический E09 PASS — сырой экспериментальный сигнал, не установленное причинное превосходство.
5. **Chosen-only Unit training не является DPO.** `ExecutorUnit.TrainOnExample` [строки 403–445](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L403-L445) записывает выбранную сторону в exact/knn/word maps, но не использует rejected в objective. Это legitimate imitation/memory, однако `DPO→specialized Unit` требует отдельного adaptation contract. Подробнее: [10 — API, restore и подмена](10-TRANSLATION-UNIT-AND-RESTORE-EDGE-GAPS.md).

## 16.10 — новая независимая causal family N23: качество оценки и ложные sub-Unit labels

После первоначального синтеза отдельный [source-audit N23](23-INDEPENDENT-TATOEBA-QUALITY-SCORER-LEXICON-CACHE.md) адресно проверил `TatoebaPilotLoopRunner.cs` на core `0eccbdc3c4efb90adf1d699806cbfa9f5610998d`. Это НЕ новая версия одной из 44 *Student-RP01* причин: настоящий consumer — `TatoebaPilotLoopRunner/TranslationMachine`, а не `CodeDocumentationSimulationDpoExperiment`.

- **N23-01 (P0 local loop):** `ProductMatch` есть `>=0.5` content-word recall, который игнорирует удалённые `не/not`, digits, roles и overgeneration, поэтому может подтвердить якобы выученный закон при противоположном реальном ответе. [12-сценарная synthetic proxy](23-MICRO-SCORER-LAW-PROXY-RESULT.json): 8 false accepts / 1 false reject. `JS_ONLY; NATIVE_NOT_RUN; actual learning gain NOT_MEASURED`. Объявлять эти доли реальной accuracy категорически нельзя.
- **N23-02 (P1 conditional):** EN_HE target-language направляется в Latin script check, точный Hebrew output получает false negative; реальный caller ещё не проверен.
- **N23-03 (P1):** `InduceLexicon` по четырём законным парам `dog barks…→собака/пёс лает…` выводит ложный `dog→лает` (score1 против score.75 у `собака`); [synthetic proxy](23-MICRO-LEXICON-COOCCURRENCE-RESULT.json), нативный/consumer эффект не проверен. Здесь ложная метка рождается **из правильной пары ДО обучаемого Unit**.
- **N23-04 (P2 conditional):** `TranslationCheckpointCache` хранит mutable Machine по file stamp без SHA. Штатный runner invalidates cache, поэтому нет общего доказанного restore failure.

[Микроплан причинной проверки](24-MICRO-TATOEBA-QUALITY-GATE-EXPERIMENT.md): сначала native 12-case `BuildRowResult` + native 4-row `InduceLexicon`, потом только если подтвердились source-seams сравнить при одинаковых данных реальные `promotion→Unit state→cold ordinary consumer`. Роль человеческого выбора и судьи — CODEX/Astra 6 UltraCode, создание обеих DPO sides — внешняя разрешённая открытая китайская модель. Самостоятельный reviewer с exact SHA не запускался.

**Место в общей очереди:** для вопроса «почему RP01 DPO Student всё ещё 0/3–0/4» P0 остаются B0 warm-start, качество exact pair, LoRA capacity, causal 4-arm historical Units vs Student. N23 — подтверждённая дополнительная ловушка измерения/переноса learned Unit, а не основание автоматически исправить LoRA или изменить глобальный план.
