## Какой опыт допустим

**В каждом A/B есть конкретный реальный получатель обучения или реальный зависимый путь его входа/сохранения/выдачи.** Записать source-method, кто вызывает его, какое learned state изменяется или читается и каким исходным кодом затем измеряется результат. B меняет один фактор. Формульная иллюстрация, выдуманный scorer, helper-speed без достижимого Train и программа с заранее заданным «улучшением» не заменяют опыт.

Reader выученного состояния допустим без искусственного нового update, когда показан путь Train → state → reader → измеренный результат. Его результат называется улучшением использования обученного состояния. Для новой способности от урока нужна настоящая оценка одного и того же задания до/после Train. Такие зависимые readers стоят после прямых учебных блокеров.

Запрещены случайный запасной B0, hardcoded gold в consumer, подмена typed admission на true, новый teacher/синтетический ответ вне карточки и незаявленное совмещение оптимизаций. Экспериментальная копия может иметь простой host/DTO, `void`, `try/catch`, `throw` и JSON observer; производство не обязано принимать эти исключения.

## Что считается успехом и что именно измерять

**Любое измеренное улучшение полезного показателя — успех по этому показателю и домену. Рост accuracy не обязателен.** В отчёте рядом показываются все остальные измеренные изменения, в том числе ухудшения. Не вводить порог 5%, обязательный exact gain, статистический gate или большой Tier как условие признания уже измеренной пользы.

Отдельные поля:

- `observed_metric_success`: какое полезное изменение измерено и на каком материале.
- `causal_attribution`: какая часть эффекта изолирована, какие альтернативные причины остались.
- `learning_readout`: A0/A1/B0/B1 по одной панели либо честное «не измерено».
- `regressions`: неблагоприятные дельты; отсутствие измерения не равно нулю.

Стоимость — одинаковый завершённый участок работы в A/B, с явно указанным временем/CPU/выделениями/GC/retained/peak. Allocated bytes, удерживаемая память и process peak различаются. Одна фиксированная A→B последовательность сохраняет полезный наблюдаемый знак, но не даёт сама по себе переносимого причинного множителя ускорения.

Для neural-пунктов, назначенных текущим [протоколом TRAIN-сигнала](https://github.com/lubochka/llm_mvp_core/blob/66947785d1318f7cbbc88118f3156cdc75001e16/docs/plans/replanning-possible-diffs/experimets/24-neural-learning-signal-protocol.md), показатели из одной и той же chosen TRAIN-панели снимаются до и после по прежним IDs/masks. Цена дополнительных forwards учитывается отдельно. **StepVector return — метрики forward до optimizer**, это не final after; нельзя сравнить разные уроки как одну before/after-панель. Протокол не требует задним числом повторять завершённый N62-R1.
