## 4. Минимум корректного измерения для каждого следующего опыта

Сначала назвать конкретный навык и его получателя. Для нейронного learner это реальные trainable tensors/optimizer; для памяти — реальные examples/maps/index и обычный путь их чтения. При проверке зависимости назвать, какой существующий результат обучения теряется или меняется.

**A0/A1/B0/B1:** A0 и B0 — исходные состояния перед выбранным обучением; A1 и B1 — состояния после него. Данные, исходная функция, decoder, splits и рамки затрат общие. Меняется один фактор. Для полезного quality показателя публиковать `A1−A0`, `B1−B0` и разность изменений. Для стоимости сравнивать одинаково очерченные законченные workloads и отдельно показывать число actual updates; меньший update budget из-за нового stop rule не скрывать.

Эта четырёхточечная схема относится к вмешательствам в обучение. Для разрешённой проверки restore/loader сравниваются сохранённое обученное состояние и результаты его обычного потребителя; дополнительные уроки и updates не требуются.

Возвращённую training-step loss подписывать её настоящей фазой. Before/after оценивать одной функцией на одинаковых masks/weights/material; exact-vector objective не заменять равномерной `EvaluateMany`. Отдельно показать обычный предметный ответ и ошибки. Hash/Δweights доказывают изменение/идентичность состояния, а не полезность сами по себе.

В отчёте достаточно одной небольшой заранее определённой панели для диагностического старта. Не превращать её в требование обязательно запустить все домены, много seed или всю историческую матрицу. Указать размер и границу обобщения; если короткое время зашумлено, сохранить измерение с этой оговоркой, а не придумывать ускорение. Повтор нужен для конкретной неясности, а не как новый обязательный барьер перед первым уроком.

Для ресурсного опыта настоящего update генерации не обязательны: это прямо допускает latest policy. В таком профиле states и реальные updates измеряются, свободная accuracy остаётся `NOT_MEASURED`; её нельзя записывать нулевой или неизменившейся. Пример — основной E-REF-CACHE:4 updates/0 generations, предметная панель отдельна и необязательна для cost-вопроса.

**Правило карточки и промпта:** любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост accuracy не обязателен. Одновременно показать остальные показатели и ухудшения. `NOT_RUN`, `PREPARABLE`, адресный `NEEDS_INPUT`, `INVALID_COMPARISON` и `UNRESOLVED_CALLER` не заполнять выдуманными нулями или PASS. `NOT_RUN` не означает запрета выполнять порученную программу.

## 5. Что уже можно считать завершённым в этом аудите

Проверены все 125 исходных карточек, их 470 подслучаев и 125 существующих ссылок/anchors на малые преемники; 164 основных source snapshots совпали с Git blob SHA. Прочитаны сохранённые результаты обучения памяти и восстановления, текущие code owners ключевых выводов, исторические экспериментальные исходники и parent RAG spans. По всем 555 planning Markdown выполнен поиск для устранения дублей; этот объём не называется полным последовательным ручным чтением.

Не завершены и не скрыты: native bindings малых нейронных опытов, новые causal runs, величина эффекта cache/phase/window и точная matrix→kNN lineage. Ни одно из этих состояний не означает, что прежних успешных возможностей не было. Рабочие доказательства памяти и исторические положительные показатели остаются опорой дальнейших изменений.
