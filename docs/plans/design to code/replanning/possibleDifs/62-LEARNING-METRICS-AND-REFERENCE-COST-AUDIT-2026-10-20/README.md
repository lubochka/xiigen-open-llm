## Порядок работы по текущему указанию пользователя

1. **Сначала конкретные препятствия настоящему обучению:** поступление допущенного урока, реальное изменение весов или Unit/kNN-памяти, доступный родной caller, корректная оценка изменённого состояния. Нейронное обучение и обучение памяти имеют равный статус. Чтение документов или один только hash не закрывает этот этап.
2. **Сохранить и применять уже принятые успешные изменения.** Перенос `phrase_mappings` уже выполнен; не превращать его снова в гипотезу и не откатывать из-за новой очереди. Далее — один конкретный прямой учебный вопрос, выбранный по реальному blocker или потерянному навыку. Новизна reference cache сама по себе не делает его первым приоритетом.
3. **Другие проверки зависимостей результата — после прямых учебных задач.** Loader/restore/consumer допустимы, если указан `writer → stored state → reader → affected result` и точное место ремонта. Если такая зависимость блокирует сам урок, она относится к первому пункту. Бессмысленные дополнительные updates ради формального допуска не нужны.
4. **Неустановленный learner/caller и посторонние проверки не запускаются вместо обучения.** Условные архитектурные вопросы сохраняются в реестре с честным статусом. Этот пакет не создаёт очередь из 125 обязательных запусков.

Подробная привязка к коду, защищённым карточкам и следующим действиям: [03-PRIORITY-AND-COVERAGE.md](03-PRIORITY-AND-COVERAGE.md). Исторические приоритеты соседних пакетов остаются источниками, но не заменяют это текущее указание пользователя.

## Правило результата и граница завершения

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности не обязателен. Остальные изменения, включая ухудшения, показываются рядом.** Это правило есть в новых карточках и промптах; старые пороги +5% и требование непременно увеличить accuracy его не заменяют.

Реестр содержит **67 direct, 40 dependency, 16 unknown и 2 outofscope** по главному механизму карточки. Это классификация содержания, не 125 подтверждённых багов и не 125 готовых запусков. В смешанной карточке отдельный подслучай может иметь другой приоритет.

E-REF-CACHE, объединённая по смыслу с параллельной LC-REF-CACHE, — `NOT_RUN`, подготовка `PREPARABLE`; эффект не измерен. Её основной бюджет — **4 настоящих updates и 0 генераций**. Неизмеренная accuracy остаётся `NOT_MEASURED`; cache cost допускает успех по времени/памяти без нового экзамена генерации. Точный experimental-copy caller ещё нужно подготовить. Product journal запрещает повторные server attempts на тех же identities; это не общий запрет на разрешённую экспериментальную копию. Подмена identities и удаление reservations не предлагаются. Фаза train metrics — уже известный факт с дополненным экспериментальным покрытием. Default convergence window25 при cap5 — уточнение P78, применимое только к соответствующему caller/configuration; обычный logical caller задаёт window1. Точная историческая цепочка «неудачно в матрице → тот же механизм успешно в kNN» остаётся **UNRESOLVED**, а не опровергнутой. Прочтение каждого из 555 planning документов подряд и восстановление всех исторических веток не заявляются.
