## Обучающее математическое условие
При одинаковом x:
`L_DPO = -log(sigmoid(beta * [(log π(y+|x)-log π(y-|x)) - (log πref(y+|x)-log πref(y-|x))]))`.
Здесь `beta=0.1`, `lr=1e-5`. Response-only targets суммируются в `ComputeTargetLogProbs(..., sumTargets:true)`; в backward `upstream * beta` имеет правильные противоположные знаки chosen/rejected. По прочитанному коду **нет основания уверенно объявить ошибочную формулу или перепутанный знак**: [DpoTrainer.cs](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/11.DPO/DpoTrainer.cs#L891-L905), [DpoTrainer.cs](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/11.DPO/DpoTrainer.cs#L1002-L1109).

**Непроверенные потенциальные seam:** finite-difference of analytic gradient для tiny fixed seed; shape/mask `i+1` сдвиг и zero-length отказ; conditioning одинакового prompt на обеих сторонах; prompt/response concat vs independently tokenized boundary; optimizer actual A/B gradient norm и clipping; reduction sum vs mean и unequal response lengths; rewards до/после; stable training dropout0. Различающий критерий — можно ли сначала переобучить 8–32 *train* предпочтения, затем появляется ли хоть какое-то changed prediction на неповторяющихся фразах. Не запускать ещё 500 без tiny signal.

## Прицельные различающие проверки
1. Exact material: bytes of prompt, y+/y-, token IDs, masks, length, decode, 1-token prediction boundary, compare `legacy` but не переобучать frozen data.
2. Numerical grad vs analytic directional derivation with all updated A/B keys; detach ref and freeze base; no finite-difference on random multiple variants.
3. Overfit 8–32 pair train, train choice hit, chosen loss and forced-token logit; only then heldout/new laws. Two metrics separated.
4. New chosen/rejected audit per independent family by source validator and second judge, without exposing sealed exam gold to trainer.
