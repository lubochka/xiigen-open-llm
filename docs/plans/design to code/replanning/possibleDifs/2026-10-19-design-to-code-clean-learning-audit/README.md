## Основной результат

Архив CodeTrace019 действительно присутствует на **DesignToCode-clean**: в диагностике указаны 49 правильных предпочтений из 50 held-out пар; это продолжение от policy/reference batch018, а не обучение случайной модели с нуля. В доступном Git tree файлы весов — LFS pointers: наличие этих указателей не доказывает загрузку payload или холодное восстановление. Более поздние CodeTrace064 / QueryPlanning134 / ContextRouting075 обнаружены в соседнем `local_wiki_planning`; их результаты нельзя приписывать clean. Точные первичные источники, значение метрики и границы — в [главе 00](00-DESIGNTOCODE-CLEAN-RESTORATION-FIRST.md).

E25, E26, E09 и E43 имеют положительные архивные результаты на clean, но относятся к разным механизмам: память POS-паттернов, контекстное значение слова, структурный KNN и bigram replay. У проверенных реализаций этих экспериментов исходники сохранены в current. Проверять надо перенос **представления, состояния и обычного потребителя**, а не только наличие класса и не переносить их accuracy на neural Student. Отрицательный результат добавления структуры в матрицу E07 не отменяет положительный эксперимент со структурой внутри KNN E09; сопоставимость выборок проверяется отдельно.

Подробно проверены **шесть механизмов/контрпримеров**. После сверки параллельных публикаций **четыре семьи сохраняют ограниченную новизну: DC-01 и KU-01…03**; DC-02/03 уже описаны другим пакетом54 и здесь независимо уточняются. Нормализация DC-01a и KU-механизмы унаследованы из clean. **DC-01b содержит реальное изменение совместимости: новый whitelist отвергает underscore generic, который clean сохранял; из-за этого otherwise-valid старый checkpoint может целиком не пройти import.** Общее следствие отказа всего checkpoint уже описано в [CLEAN-CP01](../54-DESIGNTOCODE-CLEAN-RECOVERY-2026-10-19/02-NEW-CHECKPOINT-AND-CONTEXT-GAPS.md); здесь добавлена конкретная причина canonical generic/underscore и проверка миграции двух alias. Влияние на качество и факт такого отказа на реальном архиве ещё не измерены.

## Новизна и пределы завершённости

Дедупликация выполнена по **415 Markdown в possibleDifs и 92 из 274 Markdown в защищённом каталоге core**, с чтением его общего индекса. Это 507 полных текстов; точность кэша проверена по Git blob SHA. Известные DPO/LoRA, E25/E26, restore, routing и другие находки не переобъявляются новыми. Автоматическая проверка отклонила дочитывание оставшихся 182 protected Markdown; после отказа обходов и новых чтений этой части не было. Поэтому статус новизны — **BOUNDED_NEW**, а не полная проверка всех работ других агентов. Дополнительно дочитаны 33 новых/изменённых planning Markdown (31 новый путь) и очередная редакция master: текущий объём — 446 planning + 92 protected, всего 538 уникальных путей. Следующий parallel commit потребовал дочитать ещё 15 версий (14 новых путей): охват достиг 460 planning + 92 protected = **552 пути** ([квитанция](evidence/publish-head-delta-receipt.json)). Затем на `33bf0f449d0a440a6ef6f0a32799ce5e1b4af1de` прочитаны ещё **12 версий, включая 11 новых путей**: финальный объём — **471 planning + 92 protected = 563 уникальных пути**. Четыре bounded семьи сохраняются; общее whole-import следствие DC-01b теперь имеет статус **KNOWN_LATE_CORROBORATED** с приоритетом [CLEAN-CP01](../54-DESIGNTOCODE-CLEAN-RECOVERY-2026-10-19/02-NEW-CHECKPOINT-AND-CONTEXT-GAPS.md), а новым уточнением остаётся generic-specific producer/alias. Первая поздняя сверка потребовала снять новизну DC-02/03; [поздняя квитанция](evidence/planning-late-dedup-receipt.json) сохраняет точные версии и решения.

Отсутствие нового neural дефекта в изученном пути не является PASS всей модели. В [03](03-MECHANISM-COVERAGE-AND-DPO-LORA.md) отдельно сохранены уже исправленные градиенты, response masks и LoRA-механизм: слепой rollback на clean способен вернуть старые проблемы. Принятие исправления требует полезного изменения обычного ответа на новых source families, сохранности старых навыков и повторения после загрузки состояния.
