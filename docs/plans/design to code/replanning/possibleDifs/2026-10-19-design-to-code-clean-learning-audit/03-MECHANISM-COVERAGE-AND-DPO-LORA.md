# Карта причин: DPO, LoRA, представления, KNN, Units и восстановление

## Как читать доказательства

Ниже объединены проверенные исходники и уже опубликованные гипотезы. **KNOWN** означает, что механизм описан другими авторами; здесь он не получает новый номер. **RETAIN** — подтверждённую нынешнюю реализацию/исправление следует сохранить. **HYPOTHESIS** — влияние на качество требует опыта. **INHERITED** — поведение есть и в успешной clean, поэтому само по себе не объясняет разницу веток. **HISTORICAL** — пересчитан старый архив; новый запуск не выполнен. Новизна DC/KU ограничена прочитанными документами, как описано в [05](05-SOURCES-NOVELTY-AND-REVIEW.md).

Задача пользователя охватывает и обучение нейронных весов, и обучение доменной памяти. Их состояния, цели и потребители различаются. В исторических планах слово «обучение» иногда применялось также к фиксированному словарю или deterministic scaffold. Для каждого результата здесь указан реальный механизм; ни формирование rows, ни смена веса, ни local fit не приравнены к улучшению обычного ответа.

## Обязательная трасса одной DPO-пары до подюнитов

Родительский [план DPO builder, §3.2a](../../../../dpo%20legal%20build/active-codex-execution-plan-07-dpo-builder.md) задаёт canonical serialization, policy/reference reward и winner-vs-each-loser. Это источник проектного требования, а не доказательство, что любой нынешний domain builder реализовал всё правильно. Current RAG [RESEARCH-03](../../../09.09.26WorkLeft-RESEARCH-03-dpo-algorithm-conformance.md) отдельно требует оценить именно final projected pair и не смешивать fan-out, rows и optimizer steps.

Для одной принятой пары в малом опыте сохранить: исходную задачу и source family; teacher-authored final sides и hashes; независимое предпочтение и отвергнутую смысловую ошибку; recipient Unit; список проекций; точный handler; изменённые поля state; consumer после загрузки. Проверка должна ответить, где остаётся отрицательная сторона: в gradient, в negative memory, в исправлении правил или исчезает при supervised chosen-only projection. Разные получатели могут законно использовать разные механизмы, но отчёт не должен называть их одним standard DPO update без фактического policy/reference log-ratio.

Для переводчика producer и consumer конкретны: [BuildGeneralBatch:76–142](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/27.TranslationDomain/TranslationStructuredBatchBuilder.cs#L76-L142), [TrainOnExample:404–449](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/27.TranslationDomain/TranslationTrainedUnits.cs#L404-L449), [Adapter:124–139](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/27.TranslationDomain/TranslationDirectionAdapters.cs#L124-L139). При смене encoder нельзя незаметно сменить и WordMappings: builder выводит часть mappings из token.Concept. Это ограничение причинной атрибуции добавлено независимым review в [KU-01](02-NEW-TRANSLATION-REPRESENTATION-GAPS.md).

## Сопоставление domains и переносимость функции

| Предметная область | Полезный структурный сигнал | Что оценивать в обычном ответе | Где не переносить вывод автоматически |
|---|---|---|---|
| C# documentation / code trace | AST node roles, call/value flow, order, operators | Реальные callee, argument handoff, return/branch meaning, отсутствие придуманных символов | Обычная проза без синтаксического дерева языка программирования |
| Технический RU→EN | Concept слова, контекст значения, subject/object и отрицание | Правильное действие над правильным объектом, полное отрицание | Обратное EN→RU без проверки его собственного extractor/gates |
| Бытовой RU→EN | POS order, tense, gender/agreement, границы предложения | Кто сделал что, время действия и согласование | Универсальная нормализация любой пунктуации |
| Дизайн → HTML/CSS | Дерево компонентов, visual defects, связь с viewport | Устранение реальных дефектов без новых, поведение на нескольких ширинах | Pair score/local feature-fit как заменитель render |
| Маршрутизация задач | Язык, предмет, требования к получателю, несколько допустимых outputs | Выбран действительно нужный consumer; его конечный результат | Конфигурационное совпадение имени adapter как quality proof |

## Адресный neural audit: что найдено, что сохранено

### Заключение по прочитанному neural path

**В проверенном нейронном тракте не найден новый подтверждённый дефект, который объяснял бы ухудшение относительно DesignToCode-clean.** Это не вердикт о достаточности обучения всей системы. ### Как использовать вывод для восстановления

До расширения бюджета полезен **уже существующий**, а не заново названный микропротокол neural parity: один проверенный tiny B0/reference, exact tokenizer, 4–8 допущенных контрастных пар, frozen dropout0, те же порядок и seed. Сначала проверить одну ненулевую LoRA производную finite difference и state/logit change; затем 1–4 real updates и новые смысловые вопросы после cold-load. Для C# — оператор/ветка и её объяснение; для EN→RU — отрицание/роли с независимыми source families. A/B меняет только проверяемую причину: например отдельный warmed-base arm после подтверждения непрерывного gradient-path. Не объединять warmup, rank, target modules и objective в одно вмешательство.

**Фальсификатор нейронной регрессии:** при одинаковых весах, tokenizer, exact material и режиме loss clean-compatible kernel/control и current дают совпадающие selected logits/derivatives в допуске, а качество не различается. Тогда причину следует искать в данных, потерянном Unit consumer, компетенции базовой модели либо оценке, а не объявлять сломанным LoRA по одному плохому итоговому ответу.

Роли будущих DPO-опытов: задачу и предпочтение выбирает CODEX с запрошенной моделью **Astra 6 ultracode**; обе окончательные стороны DPO создаёт внешняя открытая китайская модель; качество принимает CODEX с **Astra 6 ultracode**. Такие model calls здесь не выполнялись. Simulation DeterministicGenerator в прочитанном runner — исторический/отдельный режим и не выдаётся за соблюдение этих ролей в новом опыте.


Выполнены source review и сравнение Git blob identities. CLR gradient, native learning, free generation и model quality calls в данном пакете не запускались. Новые DC/KU механизмы не используются как объяснение neural RP01 без доказанной связи с его выбранным получателем.
