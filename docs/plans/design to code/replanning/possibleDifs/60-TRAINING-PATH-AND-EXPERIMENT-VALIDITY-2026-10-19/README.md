# Аудит потерь обучения: реальные пути, новые гипотезы и качество экспериментов

**19 октября 2026. Итог — документарный аудит и пять небольших проектов учебных опытов. Новые обучения, сборки и вызовы teacher/judge в этой работе не выполнялись.** Исходники core и защищённая папка `docs/plans/replanning-possible-diffs` этим аудитом не изменялись. Публикуется только этот пакет в `xiigen-planning/llm_plan3/.../possibleDifs`.

## Главные результаты

Найдены **три новых узких кандидата**, проверенные на дубли по исходному корпусу525 Markdown и поздним дополнениям. Два дополнительных опыта закрывают точные подслучаи уже известных тем SFT; они не выданы за новые общие открытия. Для каждой находки отделены факт кода, возможное влияние, домен, настоящий получатель обучения и ещё не выполненное измерение. **Единственная доказанная причина общего ухудшения RP01 не установлена.**

| Находка | Подтверждено исходниками | Что проверить | Применимость |
|---|---|---|---|
| **ND-DPO-SFT: после DPO учатся те же адаптеры, но уже на исходных файлах** | Combined incremental path выполняет DPO, затем обязательный full-sequence SFT по C# source с другим optimizer, затем сохраняет adapter | Изменяет ли порядок стадий полезное обучение и retention? | C# combined path; прямой RP01 simulation другой. Нужен отдельный order-only research host: simple reorder существующего wrapper меняет reference |
| **ND-DPO-PAD: маска исключает хвост из цели, но вычисления хвоста остаются** | Exact sides дополняются до max длины; reference/policy forward и policy backward обрабатывают полный tensor | Можно ли уменьшить время/память настоящего DPO update, ограничив execution собственной valid length стороны? | Прямой exact StepVector. C# и отдельно подтверждённый переводческий research profile; эффект пока не измерен |
| **N-KU-01: E14 учится на ложных ADD_LOOP** | Label producer не распознаёт ForEachVariableStatement и DoStatement; эти labels попадают в native KNN Train | Поможет ли исправление только производителя меток уменьшить лишние рекомендации цикла? | C# action-memory; features/k неизменны, independent gold. Активность этого пути в конкретном RP01 не установлена |

Доказательства с immutable SHA и строками, однофакторные карточки и промпты: [DPO/LoRA](01-DPO-LORA-NEW-TRAINING-DIFFERENCES.md), [KNN/Units](02-KNN-UNITS-AND-HISTORICAL-LEARNING.md). Новизна ограничена проверенным корпусом и прочитанными близкими механизмами; она не означает поиск по всем возможным веткам и всей истории проекта.

## Что важно исправить в трактовке результатов

**У RP01 уже был небольшой положительный результат по preference margin.** C# normalized mean вырос на0.0012275314331054651, ENRU — на0.00011000633239746093. Это успех по данному измеренному показателю. Свободная правильность осталась0/3 и0/4, а у11/25 и9/20 отдельных случаев margin ухудшился. Эти оси показаны рядом в [разборе первичных результатов](04-RP01-RESULTS-AND-MECHANISM-MAP.md#1-rp01-движение-предпочтения-было-свободные-ответы-не-улучшились).

[История и границы сравнения](02-KNN-UNITS-AND-HISTORICAL-LEARNING.md#3-история-положительные-сохранённые-результаты-действительно-найдены).

## Проверка защищённых экспериментов с учётом новых правок

Во время аудита другие процессы дважды обновили защищённые документы. На c3f1 правило успеха было добавлено в125 P-карточек и133 извлечённых блока промптов. Следующий внешний commit f50 также исключил самостоятельные serving/reporting/zero-update проверки из учебной очереди и запретил формальный посторонний Train ради видимости обучения. **Устранённые претензии сняты; прежний анализ сохранён с датированным snapshot, чтобы не выдавать его за текущий дефект.** [Текущий аудит покрытия](03-EXPERIMENT-COVERAGE-AND-VALIDITY.md).

Это улучшение инструкций не означает, что каждая оставшаяся гипотеза уже имеет реализованный host и доказанную цепь обучения. Наличие карточки, имени Train или ссылки на источник недостаточно. Для собственных пяти опытов этого пакета отдельно обозначены отсутствующие точные подслучаи и native seams. Они опубликованы в разрешённом planning, **не добавлены в защищённую папку**.

## Небольшие опыты, подготовленные здесь

| Опыт | Единственный фактор | Бюджет на плечо | Основные полезные показатели |
|---|---|---|---|
| E-DPO-SFT-ORDER | Порядок DPO/SFT при одном frozen R0 и одном fixed exact-v2 research profile | 1 DPO update на4 парах +2 SFT updates | Response quality/NLL, preference, completion, retention, цена обучения |
| E-DPO-VALID-LENGTH | Valid side execution length после неизменённой admission | 2 DPO updates,4 пары | Sec/update, allocations/peak RAM, предметные deltas |
| N-KU-01 | Два loop kinds в train-label producer | Память4→6→8;18 предъявлений,3Train,24Predict | Ложные ADD_LOOP, recall нужного цикла, retention и цена приобретения памяти |
| E-SFT-MOMENT-CONTINUITY | Перенос AdamW m/v/step при одинаковом LR | 2 SFT updates | Response/retention, следующий update и стоимость |
| E-SFT-RESPONSE-MASK | Нулевой вклад prompt targets при том же denominator | 2 SFT updates | Response NLL, completion, gained/lost cases и цена обучения |

Первые три — новые конкретные гипотезы; последние две — уточнение известных тем. Полные условия, границы, измерения и промпты содержатся в [общем контракте и навигации](05-LEARNING-EXPERIMENT-CONTRACT.md) и [отдельной SFT-mask карточке](06-SFT-RESPONSE-MASK-EXPERIMENT.md).

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности для этого не обязателен. В отчёте рядом показываются изменения остальных показателей, включая ухудшения.** Это правило включено в каждую нашу карточку и каждый исполнительский промпт. Самостоятельный опыт без причинного изменения обучения не назначается. Native KNN Train считается обучением памяти даже при нуле neural optimizer steps.
