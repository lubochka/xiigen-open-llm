## Область применимости не определяется номером эксперимента

Домен здесь — предметная тема: программирование, перевод, документация, оркестрация, преобразование дизайна в код. EN→RU и RU→EN — профили перевода. C# и SQL уточняют язык/задачу программирования. AST, kNN, LoRA и Unit — признаки, механизмы и архитектурные сущности, а не отдельные домены автоматически.

Для структурных признаков C# отдельно нужны отношение операндов, область видимости, тип и порядок; для SQL — смысл JOIN, чтение/изменение и порядок зависимостей; для перевода — участники события, отрицание и связи внутри группы; для оркестрации — доступный инструмент, предусловия, порядок и сохранение результата. Перенос полезной функции между темами допустим как гипотеза, но её пользу проверяют на новой задаче.

Ранний отрицательный результат с матричной архитектурой не закрывает использование того же вида информации в функции расстояния, отборе соседей или обучаемой памяти. Обратное также верно: успешный поиск не доказывает, что его score можно без проверки поместить в neural loss. В сравнении сохраняют одинаковый смысловой EXAM, выделяют один меняемый механизм и записывают реальный объект, который учится и отвечает.

## Что нельзя объявлять новым или неисправленным

* Общие `hits[0]`, потеря исходной DPO-тройки, q/v-only capacity, случайный B0, default scaffold, replay top3 и nested memory уже описаны. Новая карточка обязана показать добавленную конкретную операцию или условие.
* Существующие исправления ingress/embedding/bias/mask остаются в current-контроле. Повторное чтение старого failing receipt не отменяет последующего исправления.
* Чужой архивный FAIL не является окончательным при наличии позднего успеха. Чужой PASS также не переносится на другой branch/корпус/consumer без сопоставления.
* Историческое улучшение, исходниковое несоответствие, аналитический контрпример, новый native A/B и прирост предметного качества — пять разных уровней доказательства.
