# DesignToCode-clean: восстановление обучения и новые причинные гипотезы

**19 октября 2026. [Первая глава — эксперименты, возвращающие поведение успешной ветки](00-RESTORE-DESIGNTOCODE-CLEAN-FIRST.md).** Здесь исходная точка сравнения — именно `DesignToCode-clean@e346b88a`. `language_translate`, `external_domains`, `local_wiki_planning` и `orchestrator-extensions` используются как отдельные исторические источники, когда совпадение конкретного механизма доказано.

Главный результат исследования: библиотека содержит полезные обучаемые механизмы, но название «обучение» объединяет разных получателей. Память шаблонов, kNN, таблица выученных поправок и q/v-LoRA меняют разные состояния. Успех одного получателя не объясняет автоматически свободный ответ другого. Во многих проверенных компонентах старое и нынешнее тела совпадают; для них первым предметным вопросом остаются доставленный урок, используемый checkpoint и реальный вызывающий путь. Конкретное различие кода, унаследованное ограничение и доказанное изменение качества отмечаются раздельно.

**Итог по новизне: шесть новых точечных проверок и две подтверждающие/уточняющие проверки N54.** На последнем этапе прочитана параллельная публикация, поэтому потеря полярности Critic и CSS fallback не объявлены независимыми открытиями. Полный охват поиска: 689 исходных Markdown плюс 33 новые/изменённые версии, ещё шесть поздних редакций существующих Markdown, всего 720 уникальных путей. Это текстовая дедупликация, не 720 полных аудитов кода.

## Что уже доказано, а что остаётся гипотезой

Выполнены свежая фиксация веток, адресное чтение первичных исходников/результатов, сопоставление старых и нынешних Git blobs, поиск пересечений с обоими прежними реестрами и вычислительный разбор небольших контрпримеров по прочитанным формулам. **Новые native/.NET обучение, inference, вызовы учителя и предметные A/B этого пакета не запускались.** Числовой или алгоритмический контрпример показывает механизм риска; влияние на полезность обучения того же получателя ещё нужно измерить.

Известный [выполненный опыт доставки частей переводческого урока](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/translation-memory-ingress-01/report.md) действительно дал **11/24 → 19/24** на одной панели из 24 заданий. Он уже опубликован другим исполнителем. [Пять нейронных запусков после трёх исправлений](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/human-summary.md) сохранили **0/24**; это другой получатель. Эти наблюдения не переименованы в результаты нового аудита.

## Роли в новых опытах

**CODEX с запрошенной моделью `Astra 6 UltraCode` выполняет роль человека при выборе урока. Внешняя открытая китайская модель создаёт обе стороны DPO — `chosen` и `rejected`. Отдельный CODEX с `Astra 6 UltraCode` оценивает качество точной неизменённой пары.** Независимая оценка собственных ответов ученика — отдельная операция CODEX; reference policy в формуле DPO не является судьёй. Историческое авторство сохраняется: если старый материал создавал Astra, нельзя задним числом называть его выводом китайской модели.

Это исследовательский пакет с постановками опытов, а не утверждение о восстановленном продукте. Все новые записи публикуются только в `xiigen-planning/.../possibleDifs`. Каталог `llm_mvp_core/docs/plans/replanning-possible-diffs` использован для чтения и дедупликации.
