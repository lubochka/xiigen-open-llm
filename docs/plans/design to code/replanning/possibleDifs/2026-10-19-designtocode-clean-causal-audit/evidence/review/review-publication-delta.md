# Финальная дедупликация восьми checks по параллельной публикации

Дата: 19.10.2026. Проверяющий — `units_restore`, по отдельному поручению родительского агента перед публикацией.

**Результат: нельзя публиковать все восемь checks как независимо новые находки.** U-DTC-1a уже прямо описан в новом N54. U-DTC-2 существенно пересекается с опубликованным тем же механизмом fallback при неположительных весах; его следует оставить дополнительным контрпримером отрицательной полярности, без счётчика новой независимой причины. Для остальных шести точных checks в проверенной дельте повторов не найдено; рядом с U-DTC-1b уже существует другой конкретный train/serve mismatch, которому нужно отдать ссылку.

## Почему новые 53-/02, 03, 04 не дублируют оставшиеся checks

**KU-01, `02A-NEW-SEGMENT-AGGREGATION-GAP.md:3–24`:** разные producer-generated DocumentId приводят к отказу при объединении правильных learned результатов одного target. Это не PRON/spans, feature map Critic или округление накопленной суммы.

**KU-02, `02B-NEW-CANDIDATE-ELIGIBILITY-GAP.md:3–36`:** global relative floor применяется до ограничения разрешённым targetset, после чего shortlist пуст. Это композиция eligibility и порога на уровне graph authority, а не условие положительного веса в DesignConversion Improver. Общая тема преждевременного ограничения кандидатов соседняя, источник и минимальное вмешательство другие.

**PT-01/PT-02, `03-NEW-PROMPT-PATTERN-GAPS.md:13–31,49–71`:** семантический дубликат уменьшает top-two margin до нуля; generic alias `gate→missing_gates` создаёт ложный сигнал, в том числе из `delegated`. Это другие конкретные owners, triggers и consumers. Сходство слов «fallback»/«нечувствительный сигнал» не делает их дублями наших восьми checks.

**AUT-WEIGHT-01/AUT-REPLAY-02, `04-AUTONOMOUS-LEARNING-CONDITIONAL-GAPS.md:15–46,64–87`:** mono-domain batch превращает допустимые веса больше 1 в 1; уроки технически успешного кандидата попадают в replay до решения качества. Это не восстановление округлённой суммы и не SIMD AdamW contrast. Не следует смешивать разные виды «весов» и разные решения admission.

## Рекомендуемая правка представления результата

Оставить **восемь адресных проверок**, если все полезны для пользователя. Представлять их как **шесть точных checks без найденного повторения в финальной дельте и две проверки, подтверждающие/уточняющие уже опубликованный N54**. Счётчик «восемь новых причин» убрать. Для U-DTC-1b явно указать предшествующую train/serve семью. Две снятые заявки на новизну не требуют удаления полезных исходных доказательств, контролей и маленьких опытов.

Это финальное решение ограничено новой эпохой `64ade14…`; оно не заявляет вечную глобальную уникальность остальных шести механизмов и не превращает source-level повтор в подтверждение качества обучения.
