## 0.4. Критерий решения после каждого опыта

Записать: `source branch+SHA`, материалы и лицензированный источник, hashes train/holdout, задача и направление, donor owner, student owner, tokenizer and normalization identity, DPO chosen/rejected distinction, LoRA target/rank, trainable weight hashes before/after, kNN-store size/index/query signature, checkpoint file hash, cold-process recipient binding, ordinary consumer trace, blind expected/actual, score definition, cost and seed. Отдельно учесть deterministic safety/legal constraints; скрытый fixed lookup не считать learned capability. **Победил механизм**, только когда matched baseline→enhanced по одному судье повышает unseen качество и это переживает cold restore.
