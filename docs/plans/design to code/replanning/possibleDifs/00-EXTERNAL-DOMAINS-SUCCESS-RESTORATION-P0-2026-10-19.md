## 0.2. Что действительно изменилось между ветками — точное пофайловое доказательство

В этой сессии прочитаны **оба полных файла** каждого пункта: [E25 driver](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/35.ExperimentsV2/Experiments/E25PatternClassifier.cs), [E26 driver](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/35.ExperimentsV2/Experiments/E26ContextualDictionary.cs), [E09 driver](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/35.ExperimentsV2/Experiments/E09StructuralKnn.cs), [E43 driver](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/35.ExperimentsV2/Experiments/E43ReplayBuffer.cs), [PatternClassifier](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/12.SemanticCompiler/Translation/PatternClassifier.cs) и [PatternReorderer](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/12.SemanticCompiler/Translation/PatternReorderer.cs). Во всех шести парах содержимое current **после исключения ровно пяти строк нового лицензионного заголовка совпадает полностью** с содержимым donor. Это `SOURCE_IDENTICAL_AFTER_LICENSE_HEADER`, **не** `BEHAVIORAL_PARITY`: работающий старый экспериментальный код присутствует на диске, но не доказано, что его загружают, обучают, восстанавливают и вызывают с теми же features и состоянием.

Особенно важный контрпример:
- [E25](https://github.com/lubochka/llm_mvp_core/blob/3036a01acec938f0b83fa4ffbda26202cc35d639/12.SemanticCompiler/Translation/PatternClassifier.cs#L29-L86) хранит `_train` и использует `Predict()` по POS bigrams.
- [Текущий Tokenizer](https://github.com/lubochka/llm_mvp_core/blob/649b9343cfda5b81cc54396a3840ad5db5e0b179/27.TranslationDomain/TranslationSemanticTokenizer.cs#L351-L362) возвращает `IMPERATIVE_V/SOV/SVO` через фиксированные условия и не вызывает E25 kNN.

- [Текущий ExecutorUnit](https://github.com/lubochka/llm_mvp_core/blob/649b9343cfda5b81cc54396a3840ad5db5e0b179/27.TranslationDomain/TranslationTrainedUnits.cs#L264-L330) выбирает exact/phrase/word maps/kNN и затем fallback; [ApplyE27Reorder](https://github.com/lubochka/llm_mvp_core/blob/649b9343cfda5b81cc54396a3840ad5db5e0b179/27.TranslationDomain/TranslationTrainedUnits.cs#L729-L742) лишь обменивает конкретную локальную пару, а не восстанавливает все структурные операции E27. Общее сокращение E27 уже установлено в [N26](26-NEW-E27-STRUCTURAL-REORDER-COVERAGE-LOSS-2026-10-16.md); повторным открытием оно не считается.

**Граница сравнения:** ветка `external_domains` не содержит `27.TranslationDomain` как каталог. Поэтому сопоставление E25→нынешний Unit — архитектурное сравнение требуемой функции, **не** diff двух версий одного и того же файла. Нельзя утверждать, что `external_domains` уже запускала современную `TranslationMachine`.

## 0.3. Какие пробелы уже документированы; чего не делать повторно

Общие направления и предметные доказательства находятся в [44 — 25 механизмов](44-REQUESTED-MECHANISMS-COVERAGE-2026-10-19.md), [43 — матрица и нейронная цепь](43-PREPARETOGPL-RESTORATION-AND-NEURAL-DIFFS-2026-10-18/05-COVERAGE-AND-EXISTING-CARDS.md), [12 — матрица -> kNN](12-MATRIX-TO-KNN-EXPERIMENT-MISREADS.md), [48 — новые source-level гипотезы](48-LANGUAGE-TRANSLATE-AUDIT-2026-10-19/02-NEW-HYPOTHESES.md) и в защищённом [core catalog](https://github.com/lubochka/llm_mvp_core/tree/codex/dpo-implementation/docs/plans/replanning-possible-diffs) (**READ-ONLY**).

Проверять **по оси причинности**, а не переписывать общий алгоритм сразу: пригодность chosen/rejected и gradient; warm base против random B0; LoRA topology/optimizer/scale/mask; vector tokenizer/encoder/index identity; retrieval kNN (k/normalization/filter/order/AST/POS); перенос DPO -> typed sub-units/flow; atomic admission/duplicate/restore; обученные значения против жёстких правил; reply через настоящего consumer; cross-domain interference; snapshot identity; исторические matched denominators и shadow leakage. Для каждого утверждения различать `SOURCE_CONFIRMED`, `HISTORICAL_RUN`, `ANALYTIC_PROXY`, `HYPOTHESIS` и `NATIVE_CAUSAL_RUN`.

**Новая адресная дельта этой сессии:** [50 — три проверяемых E25 seam-а](50-EXTERNAL-DOMAINS-E25-NOVEL-POS-SEAMS-2026-10-19.md): (N50-01) конкретное схлопывание verb-first структур при current `ClassifyPattern`; (N50-02) пустой набор POS-bigrams даёт kNN distance=0 для разных однотокенных классов; (N50-03) `PatternClassifier.Train` полностью заменяет память на каждом вызове. Общая потеря E25-получателя **уже** отражена в существующих обзорах и не объявляется новой; N50-02/03 — унаследованные ограничения donor learner, не установленная regression. [Различающие доменные опыты](50-EXTERNAL-DOMAINS-CAUSAL-MICRO-EXPERIMENTS-2026-10-19.md) исполняются только после отдельной проверки, что конкретный Unit/consumer действительно использует этот механизм.

## 0.4. Решение о переносе

Сначала воспроизвести архивный E25 по существующему source и корпусу и проверить реальную connected path на новых family-heldout примерах. Только затем переносить **данные + обученную память + условную доменную функцию + checkpoint + вызов consumer** как единый маршрут. Для C# E09 — отдельный AST/kNN маршрут; POS grammar нельзя автоматически применять к C# или семантическому поиску. Для E43 replay — отдельно bigram, kNN memory и LoRA с независимыми бюджетами. При неуспешном переносе предъявлять диагностическое доказательство, **где именно исчезло улучшение** (train, serialize, load, route, rank, consumer, evaluation), не считать проверку `weights_changed` достаточной.

**Не выполнялось:** .NET build/native learning, реальный customer-run, cherry-pick функций, модификация core или защищённого каталога, изменение критериев или данных ради красивого PASS.
