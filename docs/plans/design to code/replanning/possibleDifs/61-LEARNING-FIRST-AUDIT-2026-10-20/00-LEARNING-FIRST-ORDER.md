# Порядок работ: сначала учебная цепь, затем её зависимости

Этот документ применяет последнее поручение пользователя к исследованному коду и карточкам. Он не создаёт новый круг разрешений и не является отчётом о выполненном обучении. Состояние документов сверено также с core `de4ef0f14172dada4daf142a4c66ba19e96bb6d4`; исходные реализации исследованы на `bf9b543e149ef197da85a767821d98c9b67916d2`, между этими версиями они не менялись.

## 3. Допуск конкретного опыта

У каждого выбранного опыта должна быть короткая доказательная цепочка: **урок → реальный writer/update → сохранённое состояние → код, от которого зависит результат → полезная метрика**. Для ресурса настоящего update последний consumer может не генерировать ответы. Для restore допускается уже доказанно обученный checkpoint без декоративного повторного обучения.

До исполнения фиксируются предметная тема, модель/Unit, реальные входы и начальное состояние, один меняемый фактор, исходный код и точное исправление, число уроков/updates/ответов и неизменный измеритель. Доступные поля заполняет исполнитель. Недоступный вход называется конкретно; его отсутствие не останавливает независимые готовые части.

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности не обязателен.** Рядом показываются изменения остальных измеренных показателей и ухудшения. Число правильных ответов, correct/all, correct/accepted, coverage и wrong-accepted — разные величины, их нельзя скрывать общей отметкой PASS. Неизмеренные величины не записываются нулями.

Для сломанного loader/admission плечоA может честно отвергнуть или потерять урок. Оба плеча должны реально вызвать исследуемый процесс с одинаковым исходным материалом; успешный update в плохомA не является искусственным условием валидности. Отказ intended code — результат; недостижение intended code из-за ошибочного harness — недостаток постановки.

`REACHED_NO_EFFECT` означает, что операция действительно достигнута, но effect не обнаружен или идемпотентен. `NO_CONTRAST` означает отсутствие выбранного различия. `UNREACHED_CALLER` означает недостижение требуемого пути. Эти состояния не следует объединять в `NO_CAUSAL_LINK` по одному равенству hashes.

## 4. Домены и границы переноса

| Представление/навык | Предметная применимость | Что нельзя заключать из положительного результата |
|---|---|---|
| Roslyn AST, ancestor/child role, scope | C# и аналогичный разбираемый программный синтаксис | Что автоматически улучшились перевод, визуальная композиция или SQL на другой схеме |
| POS bigrams, sentence order, роли/операторы | Языковая структура и конкретная задача перевода/классификации | Что POS accuracy равна точности конечного перевода |
| Фразы и learned mappings | Композиция знакомых частей в соответствующем направлении перевода | Что усвоены отсутствовавшие в TRAIN законы отрицания, времени или вопроса |
| FlowRef + learned plan body | Оркестрация и удержание связанных входных описаний | Что улучшилось нейронное free generation или что выучена произвольная плановая топология |
| q/v-LoRA DPO | Указанный Student, vocabulary/config, материал и objective | Что обновилась вся система Units/KNN/Flow без доставки того же сигнала этим получателям |

EN→RU — направление внутри предмета «перевод». LoRA/kNN — механизмы, Unit/Flow — уровни организации. Такое разделение позволяет честно считать полезный локальный успех и одновременно не обещать перенос во все предметы.
