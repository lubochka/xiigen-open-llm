- [Реестр очереди переносов](C:/Projects/llm_mvp_core/docs/plans/replanning-possible-diffs/fixes-based-on-experiments/01-registry.md) и [общий контракт тестов](C:/Projects/llm_mvp_core/docs/plans/replanning-possible-diffs/fixes-based-on-experiments/03-test-and-execution-contract.md) содержат навигацию и новые требования к последующим карточкам.

## Что существенно для решения о переносе

| Основание | Наблюдение | Что из него следует |
|---|---|---|
| P18 | 63-мерный запрос к обученной 64-мерной памяти без guard принят; guard даёт явный отказ, 12/12 обычных ответов сохраняются | Исправлять форму запроса до расстояния; не объявлять измеренным рост точности |
| P19 | После изменения исходного DTO сохранено 9/12 → 12/12 | Нужен явный контракт независимого тела ответа. Копирование метаданных в текущем коде уже есть и не копирует generic Output |
| P17 | Полный refit сохраняет старые ответы 8/8 против 6/8 у смешанных кодировок | Нативный Train уже делает положительное плечо; новый алгоритм не нужен, нужна учебная защита |
| P36 / P37 | Полная память после нового урока даёт 3/3 вместо 1/3; пустой запрос не должен выбирать первый уложенный класс | Разделить полный Train и append; после обучения явно отвергать пустые признаки |
| P32 | Выбранный и загруженный навык со своими шагами: 6/12 → 12/12 | До ранжирования должен дойти именно обученный сигнал. ScoreForKnn здесь был нулём; полный каталог пока не проверен |
| P28 | EN walk/sail: 2/4 → 4/4; новый контроль показывает 4/4 и у прямого чтения заранее данной таблицы, без обученной памяти | Только условный 10-мерный профиль представления; самостоятельный приоритетный перенос обучаемой морфологии не допускается. Формы новые для памяти, но их семьи уже известны кодировщику; это не доказательство для RU/HE |
| P26 / P27 | 2/40 → 39/40 при правильной позиции; 0/12 → 12/12 при сохранённой схеме имён | Предупредительные контракты будущих входа/сохранения. Сейчас продукт передаёт узел напрямую и не имеет такого Save/Load |

Ресурсные ухудшения остаются видимыми: у P19 RSS/peak +8,543%; у P17 перекодирование +145,43% выделений; логическое исключение не является общим ресурсным успехом. P31 (7/9 → 9/9) не допущен к общей замене: выделения 2584 → 21216 байт (+721,05%). У P34 точнее разметчик, но ответ обученного маршрутизатора остаётся на уровне постоянного; учебного результата для переноса нет.

Новый непроверенный остаток P19 — мутация объекта, который ранее вернул Execute. Входная копия не защищает этот канал. В 97 ему назначена обязательная проверка с отдельным реальным обучением; результата этой проверки пока нет. Аналогично roundtrip mutable-ответа с версией политики ещё не измерен.

Ни контрольные числа, ни заголовок старого коммита не заменяют чтение текущего кода. P39 уже учитывает закрытый канал через массивы метаданных; его поздний контроль обучает отдельную единицу с изменённой меткой. Старую формулировку «память всё ещё меняется через эти массивы» повторять нельзя.

Источники с точными путями отчётов, данных, кода, параметрами моделей, будущими тестами/бюджетами и пределами каждого вывода находятся в канонических 97–99. Это документные дополнения, не независимое субагентное ревью и не утверждение о завершённой реализации.
