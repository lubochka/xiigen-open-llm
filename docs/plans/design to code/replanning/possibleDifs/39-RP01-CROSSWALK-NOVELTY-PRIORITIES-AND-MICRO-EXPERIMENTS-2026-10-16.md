Исторические успехи были другого типа: exact+signature KNN memory, learned token corrections, word/phrase mappings, verification source laws, AST-context retrieval, replay, отложенная грамотная маршрутизация и местами небольшие нейронные модели. ## 4. Минимальные практические шаги с максимальным информационным выигрышем

1. **P0-NEURAL / C# + ENRU**. Возьмите уже замороженные correct/incorrect пары и одинаковые ordinary heldout queries, отдельно измерьте `model-visible ids, response mask, chosen logP, rejected logP, free answer, law correctness, stop reason`. Прекратить, если 8–32 known pairs вообще нельзя переобучить. **Это различает недостаток базы и optimizer/feature loss**, не требует 500-строчных повторов.
2. **P0-TRANSFER / translation + C# structure**. Сравните на *одних входах* (A) random neural B0; (B) старые trained `TranslationTrainedUnits`; (C) B0+Units; (D) DPO-B0+Units с отдельным одинаковым test budget. Исторический успех должен быть самостоятельным `actual answer`, а не `non_exact_probe_proves_generalization=true`. Сохранить до/после и exact/nonexact/semantic law.
3. **P1-UNIT / DesignToCode phase handoff**. Запустить только [N38 A/B/C](38-MICRO-T35-COUNTERFACTUAL-SOURCE-BOUNDARY-2026-10-16.md), сначала проверить отсутствие вызова из neural RP01 и реальный downstream arbiter; не учить LoRA ради фиксированного oracle.
4. **P2-ROUTER / devops/security/analytics/mobile/SQL**. Запустить только [N39 conditional route](39-NEW-E47-LEXICAL-ORACLE-CONFOUND-AND-DOMAIN-ROUTING-2026-10-16.md), заранее создать независимую tag-absent панель, подбирать hybrid порог не на hidden exam.
5. **P1-STRUCTURAL-KNN / C# AST и translation word-order**. При обучении менять по одному признаку: source-span AST parent/sibling vs ordinal/order vs exact memory, отдельно для структурного кода и языкового порядка. Если обычная ENRU sentence не требует AST, не навязывать Roslyn и не ухудшать recall.

Все шаги **предложения, не выполненные опыты**; никакого изменения frozen historic receipts и thresholds после просмотра выхода. Для small sample публиковать отдельные exact counters и uncertainty, не объявлять +2/12 mandatory или «95% достигнуто» по оптимистичному proxy.

## 5. Source provenance, ветки и роли исполнителей

Реальная история имеет **отдельные branches** core: `DesignToCode`, `language_translate`, `external_domains`, `codex/dpo-implementation`, `orchestrator-extensions`. Наличие веток и старых results — указатель на исследование, не доказательство причинной миграции. Для заявленного «matrix FAIL → successful KNN» требовать `old commit + old exact mechanism + changed candidate + matching data + production caller + cold checkpoint + same-input independent positive`. Уже разобрано в [branch archaeology](11-BRANCH-ARCHAEOLOGY-AND-LEARNING-PROOFS.md) и [matrix audit](12-MATRIX-TO-KNN-EXPERIMENT-MISREADS.md). **В этом новом проходе мы не нашли окончательный коммит указанного переноса и не перечитали каждый соседний branch**.

Навыки/роль применены как способы анализа: `architect-behavior-classifier` (scope и causality), `phase-planning` (диагностические этапы), `plan-review` (falsification), `code-examination` и `root-cause-tracing` (метод→caller→consumer), `experiment-design` (baseline/enhanced/metric/tier), `prompt-patch-authoring` (one bottleneck at a time), `output-readability-gate` и `human-readable-architecture-audit` (разделение source и inferential). **Независимый CODEX/Astra6 UltraCode review этим документом не выполнен**, external Chinese model не вызывалась, DPO пары не создано.

**Результаты текущей сессии:** найдены и документированы два новых узких source discrepancy, выполнена только source-logic JS проверка E47 12/12, сформирован трёхвходовой T35 JSON, создан набор быстро исполнимых причинных опытов. Никакие native модели, тесты/Windows CI или production flows не запускались. Критерий закрытия RP01 остаётся прежним: *получатель обучения действительно изменился, состояние восстановлено, обычный consumer стал содержательно лучше на неизменённой отложенной панели*, а не «исправили отчёты».
