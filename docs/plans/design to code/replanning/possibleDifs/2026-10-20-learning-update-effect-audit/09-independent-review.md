## Source-backed выводы и причинная валидность

### R1

В первом проходе независимо прочитан `DpoProjectLoraRecipient.RequireValid` и его вызовы внутри реального StepVector-пути. Точный Git blob `DpoTrainer.cs` — `0a7fd4d088fd37824aa213ddf0c6189675fe7dc2`.

[R1](05-new-R1-frozen-base-comparison.md) меняет только полное побитовое сравнение base arrays. Сохраняются signed zero/NaN payload, guards, topology/shape/identity проверки, reference hash и места отказа. Ограничение длины byte-span и допустимый сохранённый путь для чрезмерных размеров оговорены. Ни ускорение, ни причина старых0/4 не объявлены измеренными.

### R2

Исходный `BackwardLogProbs` выделяет `new float[v]` внутри token-loop и полностью переписывает буфер до чтения. [R2](06-new-R2-softmax-buffer.md) переносит выделение после `cnt<=0 return` и перед циклом, оставляя отдельный локальный буфер на каждый backward, без shared/static/pooling и изменения арифметического порядка.

Формула payload `(N−2) × v × sizeof(float)` корректна для двух непустых сторон. Она отделена от измеренных allocations, header/alignment, live heap и peak RAM. Изменение final LoRA/optimizer и сохранение одинаковой учебной работы должны проверяться при будущем исполнении; здесь их равенство не заявлено как результат запуска.

### N03 и бюджет

Исходный once-marker зависит от canonical root, domain, Mode и InputSha256, но не различает два A/B-плеча с одинаковыми bytes. [04](04-small-neural-learning-contract.md) правильно требует заранее ограниченный two-arm manifest, once-per-arm и сохранение legacy guards. Произвольный новый RunId/manifest после неизвестного эффекта не разрешает повтор.

Финальные README,01,04,08 и [10](10-concurrent-planning-update.md) сняли с N03 претензию на новизну относительно позднего planning-среза: та же коллизия уже описана пакетом61 другого помощника. N03 остаётся общим уточнением подготовки, а не третьей новой гипотезой или отдельным опытом.

Для каждой ресурсной карточки предусмотрены два последовательных урока на плечо: **4 StepVector,4 presentations,2 уникальных исходных урока,0 Generate**. **16 forwards** — верный структурный расчёт, а не новый runtime counter. Отдельный semantic D-профиль имеет **16 Generate и32 side-score computations**; он не добавлен скрытно в R1/R2. Различие evaluator settings с текущей CLI и отсутствие доказанного clipping160 явно сохранены.

Уточнение pre-update метрик проверено по порядку исходного StepVector: loss/margin вычисляются до `ApplyOptimizer`. В04–06 и полных промптах они названы журналами соответствующего шага; отдельные final A1/B1 loss/margin без Evaluate остаются `NOT_MEASURED`. Дополнительные Evaluate/EvaluateMany не назначены, бюджет четырёх updates не изменён.

Новый экспериментальный host обозначен как подготовка точной копии с нужной границей сборки/internal API и прежним admission-контрактом. Готовая команда или уже существующий micro-режим не выдуманы.

## Пределы PASS

Этот PASS означает согласованность проверенного документального кандидата с его источниками, актуальными a822-ограничениями и заявленным объёмом. Он не является:

- подтверждением работоспособности будущего host, сборки экспериментальной копии или полученного ускорения;
- новой полной семантической аттестацией всех555 документов и470 причинных цепей;
- доказательством отсутствия похожих идей вне закреплённого корпуса;
- утверждением, что публикация, перенос в основной код или новые native runs состоялись.

Reviewer не изменял кандидат, оригинальный код, защищённую папку или удалённые репозитории. Выполнялись чтение, документальная сверка, подсчёт записей/ссылок и проверка hashes. Запуски Student/teacher/judge, training/inference, build/test, benchmarks и изменение весов для этого review не требовались и не выполнялись.

Любое последующее изменение входных файлов должно быть связано с новым manifest и отдельной проверкой соответствующей дельты; настоящий digest относится именно к перечисленным30 входам.
