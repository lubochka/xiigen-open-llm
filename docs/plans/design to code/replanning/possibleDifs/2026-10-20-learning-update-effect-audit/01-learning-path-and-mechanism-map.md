# 01. Где именно может теряться обучение

## Требование и три разных получателя

Исходный RP01 pack требует сохранения смыслового контраста DPO, предметных представлений, обучаемого выбора в kNN, корректировки связей Unit/Flow и доставки принятого состояния обычному пользователю. Сам pack различает требования и подтверждённую реализацию. [SOURCE-AND-ARCHITECTURE](https://github.com/lubochka/xiigen-planning/blob/1ad622fe1f6d1e8b0860265d8c208aeada3fefb0/llm%20mvp/design%20to%20code%20session/replanning/Kiro-Xiigen-RP01-Learning-First-Slice-Pack/SOURCE-AND-ARCHITECTURE.md), [REC04 hybrid](https://github.com/lubochka/xiigen-planning/blob/1ad622fe1f6d1e8b0860265d8c208aeada3fefb0/llm%20mvp/design%20to%20code%20session/replanning/Kiro-Xiigen-RP01-Learning-First-Slice-Pack/tasks/recovery/RP01.REC04-HYBRID.md).

| Получатель | Реальная цепочка | Изменяемое состояние | Что доказывает положительный результат |
|---|---|---|---|
| Нейронный Student RP01 | `Inspect → LogicalDpoPreparedBatchMaterializer → DpoTrainer.CreateForProjectLora → StepVector → full checkpoint → Evaluate/Generate` | Присоединённые q/v LoRA, AdamW m/v/step, связанные RNG/counters | Изменение этой модели и отдельно измеренная способность её собственного ответа |
| Переводческая память | `ReadTranslationCorpusRowsAsync → BuildTranslationContinueExample → TranslationMachine.TrainStructuredBatchAsync → ExecutorUnit → ordinary Flow` | Точные примеры, phrase/word mappings и kNN-состояние Unit | Усвоение/восстановление конкретной памяти и её использование в переводе; neural optimizer здесь не обязателен |
| Предметный kNN-донор | Извлечение POS/AST-признаков → `Train` таблицы → `Predict` → конкретный typed consumer | Примеры, признаки, метки, индекс | Классификация/поиск/решение по этим признакам. Чтобы заявить улучшение свободного ответа, нужен соответствующий читатель |

Первичные источники: [RP01 Run](https://github.com/lubochka/llm_mvp_core/blob/de4ef0f14172dada4daf142a4c66ba19e96bb6d4/14.ContinuousLearning/Training/CodeDocumentationSimulationDpoExperiment.cs#L106-L205), [Evaluate](https://github.com/lubochka/llm_mvp_core/blob/de4ef0f14172dada4daf142a4c66ba19e96bb6d4/14.ContinuousLearning/Training/CodeDocumentationSimulationDpoEvaluation.cs#L45-L109), [переводческий результат с трассой](https://github.com/lubochka/llm_mvp_core/blob/a8222d1b15745fe6207f36cd294fd3fb61c01d3b/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/translation-memory-ingress-01/report.md), [E25 Train/Predict](https://github.com/lubochka/llm_mvp_core/blob/f6032aff81f1f83de7c09cf9b9efe6b058dd12b9/12.SemanticCompiler/Translation/PatternClassifier.cs#L29-L86).

## Как читать отрицательный результат

Отсутствие изменения свободных ответов не отменяет сдвиг полезной другой метрики; сдвиг margin не доказывает новый переводческий навык. Отсутствие доступа к одному checkpoint не запрещает готовый опыт другого Unit. Отсутствие causal consumer в прочитанном участке означает незакрытую связь, а не отсутствие алгоритма во всём репозитории. Показатели должны быть подписаны получателем, предметной темой и панелью.
