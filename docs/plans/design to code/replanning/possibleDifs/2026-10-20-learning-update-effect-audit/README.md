## Главные выводы

1. **Прежние успешные обучения существуют; их нельзя обнулять общим выводом «RP01 не научился».** Исправление доставки `phrase_mappings` в настоящий Executor дало **11/24 → 19/24** после одинаковых восьми уроков, одновременно ошибочно принятые ответы выросли **1 → 3**. Отдельный опыт приобретения навыка показал **0/24 → 19/24**. Это обучение памяти переводческой единицы. Нейронный RP01 — другой получатель: в сохранённом EN→RU опыте 50 новых updates изменили 16 LoRA-тензоров, а свободные ответы остались **0/4 → 0/4**; средний preference margin вырос на **0,0001100063**. Последнее — локальный сдвиг именно margin, без подтверждённого улучшения перевода. [Первичные результаты и ограничения](02-historical-positive-evidence.md).

2. **Между успешным донором и текущим потребителем бывает подмена механизма.** В `language_translate` E25 обучает kNN на POS-биграммах; найденный нынешний `TransformerEmbeddingKnnLogicalUnit` использует другой `PatternClassifier` с фиксированными словарями и условиями. Наличие похожего имени и комментария об успехе не доказывает перенос обученной функции. Для C# значимы AST, роли операндов и границы файлов; для языка — порядок, POS и смысловые операторы. Их нельзя заменить одним неупорядоченным набором токенов. [Карта механизмов](01-learning-path-and-mechanism-map.md).

3. **Общая блокировка карточек отменена; для будущих опытов требуется точная экспериментальная копия.** За время аудита core обновился с `bf9b543…` через `de4ef0f…` до `a8222d1…`: появилась [политика 20 октября](https://github.com/lubochka/llm_mvp_core/blob/a8222d1b15745fe6207f36cd294fd3fb61c01d3b/docs/plans/replanning-possible-diffs/experimets/00-execution-policy-2026-10-20.md), обновились 125 карточек и малые протоколы. В последней дельте 146 документов уточнён порядок: копия исходного механизма в 34.Experiments/35.ExperimentsV2, один фактор A/B, настоящие измерения, затем показ результата и кандидата переноса. Оригинальный код до отдельного решения Любы не меняется. Подготовка паспортов, точной копии и команд — работа исполнителя в порученной программе. Проверка загрузки/восстановления/использования выученного состояния допустима по доказанной зависимости; повторный Train ради формальности не требуется. В отдельных старых телах ещё остались противоположные фразы. Они перечислены с адресами и предлагаемой заменой в [аудите экспериментов](03-experiment-coverage-review.md).

4. **Нашёл две новые точные гипотезы экономии настоящего DPO-update.** R1 заменяет только способ полного побитового сравнения frozen base, сохраняя все проверки. R2 выделяет один локальный softmax-буфер на отдельный backward вместо массива на каждый response-token. Эти операции не найдены как отдельные ранее описанные факторы в исходных 555 + 249 Markdown и в 24 Markdown поздней planning-дельты. [Сверка новых пакетов других помощников](10-concurrent-planning-update.md). Их выигрыш пока не измерен; это не объявленные причины нулевой семантической точности RP01. Для каждой подготовлена небольшая карточка, данные, измерения и полный промпт. [R1](05-new-R1-frozen-base-comparison.md), [R2](06-new-R2-softmax-buffer.md).

5. **Добавил существенное уточнение подготовки нейронного A/B.** Существующий runner принимает один calibration-пример либо 500 main-примеров. Кроме малого режима, нужен корректный учёт двух заранее определённых плеч: текущий marker зависит от domain/mode/input hash и не различает A/B с одинаковыми байтами корпуса. Просто сменить RunId не поможет и не должно становиться обходом защиты. Это часть проекта малого host, а не отдельный опыт качества. Перед публикацией тот же механизм обнаружен в параллельном пакете61: N03 теперь отмечен как общее независимо выявленное уточнение, а не новая находка относительно актуального planning. [Контракт копии и будущие адреса переноса](04-small-neural-learning-contract.md).

## Что значит «покрыто экспериментами»

Проверен полный структурный каталог **125 карточек / 470 подслучаев**, получены точные байты **249 Markdown** с правилами и протоколами. Все **555 исходных Markdown** имеют текстовую ссылку в этом каталоге: 542 по полному относительному пути, 13 только по имени. Это навигационная полнота, **не доказательство корректности всех 470 причинных экспериментов**. Содержательно проверены ключевые нейронные, переводческие, AST/POS, ресурсные и restore-связи, описанные в пакете; ограничения остальных сохранены в поштучном реестре.

Последний документ 23 уже содержит SFT-mask, перенос optimizer moments, DPO valid-length, порядок DPO/SFT, учебную метку do-loop, curriculum/feedback, N60-E1 и N60-E2. Они не объявляются новыми нашими открытиями. **Новые R1/R2 пока отсутствуют в защищённой папке**: их полноценные карточки находятся здесь, в разрешённом месте. Это явный остаток покрытия, а не скрытое обещание, что все наши дополнения уже внесены туда. N03 — техническое дополнение к существующей D-карточке, самостоятельного запуска не требует.

## Порядок дальнейшей работы

| Очерёдность | Конкретное действие | Что считается результатом |
|---|---|---|
| 1 | Подготовить достижимый малый путь настоящего обучения и его обычного читателя на точной экспериментальной копии; убрать из активного наряда отменённые требования повторного личного допуска | Один выбранный фактор, известные входы/состояния, поддержанная команда и конечный бюджет; без объявления всей очереди заблокированной |
| 2 | Сохранить уже внесённый `phrase_mappings` ingress и включить актуальные N60-уточнения; не повторять успешные большие опыты ради отчётности | Проверяемая связь урока с нужным Unit/Student; применённое изменение не числится потерянным |
| 3 | Проверять выбранные семантические различия по доменам, затем новые R1/R2 раздельно | Реальное до/после, полезные сдвиги по каждой оси вместе с ухудшениями |
| 4 | Рассматривать остальные проверки по доказанной зависимости от обучения или его результата | У каждой — точный writer/reader, оригинальное место ремонта; действительно несвязанные проверки остаются вне этой задачи |

Этот порядок — [развёрнутый наряд](07-prioritized-work-order-and-reporting.md), а не назначение всех перечисленных опытов одним запуском. Он не требует от Любы вручную выбирать каждую карточку или предоставлять SHA, которые исполнитель может получить сам.
