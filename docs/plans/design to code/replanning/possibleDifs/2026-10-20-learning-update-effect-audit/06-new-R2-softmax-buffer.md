## Факт кода и гипотеза

[BackwardLogProbs:1072–1121](https://github.com/lubochka/llm_mvp_core/blob/de4ef0f14172dada4daf142a4c66ba19e96bb6d4/11.DPO/DpoTrainer.cs#L1072-L1121) для каждой активной shifted response-position выделяет `new float[v]`, заполняет все v элементов экспонентами, считает сумму и применяет gradient. Ссылка на `expVals` не выходит из итерации; следующая строка снова полностью заполняет все элементы. [StepVector](https://github.com/lubochka/llm_mvp_core/blob/de4ef0f14172dada4daf142a4c66ba19e96bb6d4/11.DPO/DpoTrainer.cs#L895-L909) вызывает настоящий backward отдельно для chosen и rejected.

Гипотеза: один локальный массив на отдельный backward уменьшит суммарные allocations и, возможно, GC/CPU/elapsed полного шага при неизменной арифметике. Это может не уменьшить peak RAM и не ускорить весь trainer. Никакого semantic gain пока не измерено.

## Точное одно изменение

A: точная экспериментальная копия с нынешним `new float[v]` внутри token-loop. B: та же копия; перенести именно это выделение **после `if (cnt <= 0f) return;` и до `for (int i...)`**. Сумма cnt, scale, masks, порядок max/exp/sum/gradient и `logits.Backward` остаются прежними.


Это иллюстрация места перемещения, **не полная заменяющая реализация цикла**. Не вводить static/shared buffer, ArrayPool, кэш, общий массив chosen/rejected, parallel mutation или другой порядок reductions. При нулевом числе targets scratch по-прежнему не создаётся; ранее существующее выделение logits.Grad не меняется.

Если у chosen/rejected вместе N активных targets, прежний путь выделяет N таких массивов, предлагаемый —2 при непустых обеих сторонах. Расчёт разницы payload: `(N−2) × v × sizeof(float)` на пару; header/alignment и все остальные выделения сюда не входят. Для N=2 ожидаемого сокращения этой части нет. Это **вывод из кода, не измеренные bytes**. На текущем профиле v=629, но фактические token counts исполнитель получает из exact materializer до измерения; их нельзя подставлять из числа слов.

## Малый эксперимент

Использовать ровно материал и состояние [04](04-small-neural-learning-contract.md): два настоящих урока D-T1→D-T2 на плечо,2 updates,batch1,всего **4 StepVector**, **0 Generate / 0 дополнительных Evaluate**,0 teacher/judge. Оба варианта обучают один и тот же LlmModel из одинаковых initial LoRA/base/reference/tokenizer/AdamW/RNG. Source versions остальных участков одинаковы. R1,valid-length optimization и SFT-mask не добавляются в B.

| Метрика | Основной ожидаемый полезный сдвиг / обязательное уточнение |
|---|---|
| Allocated bytes за реальные StepVector | Основная ось: меньше выделенной памяти для той же работы; измерять process allocation delta, не только live heap |
| GC collection counts, CPU, elapsed | Может снизиться; отсутствие сдвига не отменяет выигрыш allocations. Единичный runtime effect признаётся локальным наблюдением с границами |
| Process peak RAM, checkpoint bytes | Измерять отдельно; они могут остаться прежними или ухудшиться |
| Учебное действие | Issued/completed updates, pre-update loss/margin каждого шага, optimizer step, параметры до/после и full readback; отдельная final A1/B1 loss/margin не измеряется |
| Эквивалентность арифметики | Полная перезапись scratch, прежний порядок операций; ожидаемое равенство final LoRA/optimizer должно быть проверено в этом A/B, здесь оно не заявлено |
| Свободная точность | `NOT_MEASURED`; никакого вывода о новых ответах по одному изменению allocation |

Низкое число активных targets, runtime noise или доминирование других выделений могут скрыть изменение полного process delta. Не заменять отсутствие измеренного эффекта расчётной формулой и не наращивать количество уроков после просмотра. Измеритель и его границы одинаковы в A/B; не считать суммарные выделенные bytes пиком RAM.
