# Проверка новизны: Units, kNN и восстановление
Дата: 2026-10-20. Проверенный core: `dd150aa5216e42b8a8bba14955337398ec5f8397`; planning snapshot: `0ea8f0b0094e234ffe7734adfa95e2a9e53203f5`.

## Решение
**Новых кандидатов в этом ограниченном проходе не продвигаю.** Ни один из найденных точных механизмов не выдержал дедупликацию по локальным planning `possibleDifs` и защищённым карточкам core. Это не заключение, что все проблемы проекта уже найдены, и не доказательство исправности кода. Сохранены полезные маршруты к прежним владельцам, чтобы не создавать повторные опыты под другими именами.

Нативные обучение, build, генерация, тесты не запускались. Production, protected docs, runtime state и remote ветки не менялись. В scratch сохранены только полученные source-файлы и эта записка.

## Другие рассмотренные кандидаты, не подлежащие продвижению

- Повтор `requiredTerms.Add` способен повторять missing-term issues и менять scalar score, но старый документ `23-VERIFIER-ACCUMULATED-RULE-CONFLICT-AND-DIRECTION-SCOPE-2026-10-16.md` прямо фиксирует возможность дублей. Нативный значимый downstream effect этой конкретной кратности не доказан. Не переименовывать общее накопление в новый «открытый» learning gap.
- Переобучение BPE на объединённых текстах, top1 consumer вместо агрегации k соседей, недостоверный pattern bonus, 64-token cutoff, shared normalization tiers, случайная HNSW перестройка, repeated per-query BM25 scans уже явно представлены в старом корпусе. Нового точного фактора в просмотренных spans не установлено.
- `RoutingProfileTrainer` учит наборы keywords из chosen-only labels. Из одной этой конструкции нельзя вывести ошибку DPO или заявить новую гипотезу: это другой детерминированный learner состояния, а не DPO optimizer.

## Связь с заданием и пределы
Прочитаны полностью небольшие `KnnLogicalUnit`, `TranslationUnitContracts`, `RoutingProfileTrainer`, `TrainableRoutingFlow`, `RoutingDpoPairBuilder`, `TranslationDirectionAdapters`, `ReplayFusionRanker`; у крупных `DefaultLogicalCapabilityTrainer`, `LlmIngredientLogicalUnits`, `TeachingRegistryPersistence`, `TranslationMachine` читались целевые связные участки/callers, а не заявляется полный построчный аудит всего файла. `TranslationTrainedUnits` исследован по writer/reader/restore всех трёх unit типов. Source тексты зафиксированы по SHA; не делалось утверждения о текущем runtime.

Архитектурные, code-examination, plan-review, human-language скилы прочитаны из приложенного `01-all-skills`; scoped replanning AGENTS прочитан. Нет основания менять пользовательские приоритеты или запускать завершённые опыты ради новой записки.

Проверки новизны использовали `rg` с точными API и русскими/английскими описаниями причин по двум локальным корпусам. Возможное обновление удалённой ветки после pin не покрыто этим shard; parent выполняет финальную сверку всей публикации.
