# Добавочный реестр: порядок действий без повтора старых опытов

**Текущая фаза этой публикации — документация. Ни один запуск здесь не назначен.** В историческом core index 40 позиций, но первичные raw подтверждают завершение **01–08; следующий ID — N63-AR-CAP (09)**. Поздний planning registry согласует42 существующих ID и два чужих предложения; здесь добавлен один отдельный кандидат A3. Проверка/подготовка конкретного рецепта не равна разрешению исполнить его в этой исследовательской сессии.

Этот реестр не меняет защищённый индекс и не создаёт другую числовую очередь. Он показывает документные уточнения к каждой существующей позиции. Пользовательское NEXT имеет приоритет над оформлением предыдущей; STOP прекращает работу немедленно.

## Приоритет подготовки

1. Устранить препятствия реальному обучению и назначить диагностичное исходное состояние/достаточный конечный бюджет для адресных карточек; не блокировать независимые BPE, memory и kNN пути.
2. Устранить конкретные противоречия: cold B0 vs warm state, порядок и цель эксперимента, фактический readout, единственный output root. Исполнитель не выбирает решение сам.
3. Применить присланные требования к будущим паспортам: любой полезный показатель, доменная граница, модель сессии по умолчанию, сохранение истории, короткий русский отчёт, немедленные NEXT/STOP.
4. Последними — участки чтения/восстановления результата, когда показана точная причинная связь с обученным состоянием. Чисто посторонние проверки не становятся экспериментами.
