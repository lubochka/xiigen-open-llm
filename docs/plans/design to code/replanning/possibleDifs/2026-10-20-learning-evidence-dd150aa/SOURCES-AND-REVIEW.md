## Родительские RAG и исходные требования

Прочитаны RP01 pack и релевантные разделы `09.09.26WorkLeft-RAG-MASTER-INDEX`, `RAG-01-dpo-legal-build`, `MECH-01`, `RESEARCH-03-dpo-algorithm-conformance`, `Алгоритм создания ДПО`, а также первичные guide/plan в родительских `llm mvp/dpo legal build` и `llm mvp/language translate learning`.

Исторические документы содержат старые назначения human/teacher/judge, 50-парные программы и продуктовые promotion gates. Они дают происхождение ожидаемой архитектуры, но не отменяют сегодняшние прямые требования: малый эксперимент, полезный выигрыш любой оси, default executor model, CODEX/Astra selection+quality judge, внешний открытый китайский автор DPO, отсутствие запуска в документной задаче.

Охват родительской библиотеки — адресное чтение найденных источников и навигации, а не утверждение о прочтении каждого старого файла и всех внешних ссылок.

## Правила интерпретации

1. Изменение source подтверждает свойство кода; оно не доказывает величину улучшения качества RP01.
2. Сохранённый raw подтверждает записанное наблюдение в указанном запуске; без достаточной связи source→binary→run граница вывода уже, чем универсальная эквивалентность.
3. Успех по одной метрике не скрывает ухудшения другой. Отсутствие роста accuracy не аннулирует полезный ресурсный результат.
4. Нулевая панель не доказывает сохранность или приобретение навыка. Подготовительный статус не должен превращаться в бесконечную настройку или запрет всей очереди.
5. Сохранённый donor1000 и результат после1200 — разные состояния. Наличие LFS pointer не равно загрузке бинарника этой сессией.
6. Новые факторы проверены на ближайшие дубликаты, но полнота всех возможных гипотез не заявлена.

## Публикация и защита исходников

Разрешённая область записи — только новый пакет и навигационный Markdown внутри planning `possibleDifs`. GitHub commit создаётся поверх актуального head и продвигается с expected-head проверкой; чужие изменения не удаляются. Изменения core не отправляются. После публикации проверяются commit file list и чтение опубликованных файлов. Это документная проверка, а не запуск учебных тестов.
