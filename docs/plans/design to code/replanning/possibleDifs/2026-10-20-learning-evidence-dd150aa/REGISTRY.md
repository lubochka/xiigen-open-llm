## Правила перехода и результата

- Сначала подготовить и разблокировать конкретный учебный вызов назначенного ID. Затем разрешить его точные документные противоречия. Не обходить всю библиотеку и не блокировать всю очередь из-за одного отсутствующего host.
- При обычном завершении — русский отчёт до350 слов объяснений плюс таблица метрик и ссылки; кандидат изменения отдельно. Любой полезный измеренный выигрыш — успех своей метрики/предмета; все регрессии рядом. Решение о переносе в продукт принадлежит пользователю.
- Прямое «заканчивай и переходи» немедленно прекращает дооформление прошлого: без hashes, Git, дополнительного review, повторного run или проверки ради закрытия. Перейти к следующему назначенному ID в разрешённой фазе. Прямое «остановить всё» прекращает работу.
- Старые результаты, claims и partial не удалять. Если попытка уже issued, наблюдать её существующий процесс; занятый путь не обходить новым attempt. Не путать ошибку запуска до обучения с нулевым результатом обучения.
- Никакие новые teacher calls не подразумеваются автоматически. Если поручено создание DPO, обе стороны генерирует внешняя открытая китайская модель; CODEX/Astra6ultracode выбирает и оценивает качество. Simulation fixture помечается как таковой.
