## Главный результат

**Нашлись два узких кандидата, для которых не найден отдельный прежний причинный эксперимент: остановка всей учебной пачки одним длинным исходником и вытеснение истории адаптера общей FIFO-памятью.** Первый подтверждён порядком действующего continuous-learning кода; второй требует общего lifetime replay buffer, который в нетестовой сборке пока не установлен. Ни один не объявляется доказанной причиной всех неудачных RP01-прогонов. Ещё одно наблюдение уточняет уже известный конфликт DPO→SFT: исправленный feedback попадает в cache, но активный SFT может вновь взять ровно отвергнутый исходник с диска.

Проверка сохранённых опытов также не поддерживает общий вывод «обучение не работает». Есть успехи памяти перевода, POS-памяти, replay и исправления учебной метки. В нейронном SFT-опыте уменьшилась измеренная учебная потеря при неизменной точности перевода. Получатель знания, домен, профиль и показатель у этих результатов разные; перенос между ними требует отдельного доказательства. [Разбор данных](experiments/04-MEASUREMENT-EVIDENCE-AUDIT.md), [исторические ветки](replay/01-NEW-REPLAY-CAPACITY-AND-HISTORICAL-EVIDENCE.md).

**Утверждение «всё уже корректно покрыто готовыми экспериментами» подтвердить нельзя.** Все 470 подслучаев P01–P125 адресованы в общей карте, но это покрытие идентификаторов. На позднем core-срезе всего 130 файлов карточек, а часть их тел всё ещё противоречит действующей политике допуска. Для двух новых узких случаев в проверенном защищённом каталоге не найден отдельный причинный паспорт; соседние общие темы уже присутствуют. Здесь добавлены их внешние паспорта и адресное разрешение противоречий; защищённая `docs/plans/replanning-possible-diffs` не изменялась. [Проверка каждой карточки](experiments/03-CARD-BY-CARD-AUDIT.md), [разрешения конфликтов](experiments/02-CONFLICT-RESOLUTION-OVERLAY.md).

## Новое и уточнённое

### 1. Один длинный исходник прекращает всю пачку до updates

`ProjectIndexer` превращает полный `.cs`-файл в supervised response. Pipeline объединяет файлы одного домена. Затем `IncrementalTrainer` проверяет каждый закодированный `Prompt + LF + Response`; первый пример длиннее `ContextLen + 1` возвращает ошибку **из всего вызова**. LoRA preparation, DPO и SFT находятся ниже этого возврата. Поэтому допустимые короткие уроки и отдельно ограниченные DPO-пары могут вообще не получить обновление. Это вывод из исходника, а не измеренная нами частота таких отказов. [Точный source trace](ingress/01-DATA-INGRESS-FINDINGS-AND-COVERAGE.md#ingress-length-01-цепочка-доказательств).

Предложенный опыт оставляет настоящий trainer и проверку длины без изменений. A передаёт исходную пачку из двух коротких и одного длинного файла. B передаёт допустимые короткие файлы, а длинный сохраняет в явном deferred manifest. Измеряются реальные optimizer steps, изменения состояния и NLL до/после на учебных и проверочных строках. Скрытая обрезка и заявление «обучен весь домен» исключены. Маленький публичный SFT-путь позволяет проверить блокер без построения DPO authority-цепи. Следствие для DPO остаётся подтверждённым порядком кода, а не новым DPO-результатом.

Приоритет — первый среди **новых** опытов этого пакета, если применяется continuous-learning caller. Direct RP01 simulation использует другой путь: данная находка не позволяет заменить исследование его собственных уроков, objective и состояния.

### 2. История адаптера удаляется до того, как фильтр replay может её выбрать

В `16.AutonomousLearning` общий FIFO удаляет старейшие записи без учёта Domain. `Sample` затем выбирает только записи домена новых уроков. При общей последовательности A→B→A поток B может полностью вытеснить прежние A. Возврат к A не получает replay, хотя прежний адаптер A существует. [Source trace, соседняя ветка и ограничение достижимости](replay/01-NEW-REPLAY-CAPACITY-AND-HISTORICAL-EVIDENCE.md).

Это новая конкретная связь **общего лимита и фильтра допустимости**, а не новая общая идея retention. Старые replay-before-quality и схлопывание весов уже описаны в пакете 53 и защищённом дополнении 15; они исключены из счёта новизны. Нетестовой composition root с общим buffer не найден, поэтому статус — условный публичный API-сценарий, приоритет P2.

В опыте A сохраняет нынешний FIFO, B резервирует долю каждой из двух очередей при том же общем лимите. C контролирует число дополнительных обновлений, чтобы эффект старых примеров не спутать с дополнительным compute. Все arms используют настоящий `Trainer.TrainSupervisedNextTokenStep`, LoRA и AdamW. Сравниваются response NLL прежних и новых правил; количество предъявлений, токенов и затраты показываются отдельно. Это маленькая исследовательская модель для C#, не восстановление большого RP01 checkpoint.

### 3. Исправление в cache и активный SFT target расходятся

`RouteEdited` создаёт chosen=исправление, rejected=старый ответ и сохраняет положительное исправление в cache. Pipeline для SFT снова берёт `indexResult`. При точном совпадении domain, prompt и indexed response с rejected после DPO тот же отвергнутый ответ становится SFT target. Общий порядок DPO→SFT известен; здесь уточнён **источник конфликтующего target**. Если файл уже исправлен или prompt иной, этот вывод неприменим. [Условия и места возможного ремонта](ingress/03-CORRECTION-COLLISION-REFINEMENT.md).

Это refinement с зафиксированной fixture и состояниями S0/post-DPO/post-SFT. Полный DPO host ещё не замкнут; документ честно отмечает оставшийся пробел и не выдаёт выдуманную команду за готовый запуск. Он не задерживает полностью специфицированный публичный SFT-опыт. Простое подключение cache без canonical SourceId также не является готовым исправлением.

Правило применяется отдельно к каждой оси: **любое измеренное улучшение полезного показателя — успех по этому показателю и домену; рост accuracy не обязателен**. Регрессия другой метрики не стирает этот успех, но влияет на решение о внедрении. Изменившийся hash или просто наличие градиента подтверждают исполнение механизма и сами по себе не доказывают полезность.

## Приоритет следующей работы

1. **Разблокировать конкретный действующий learner.** Для continuous-learning входа проверить INGRESS-LENGTH-01. Для прямого RP01 сохранить его точный caller, checkpoint и objective; не объявлять отсутствие updates без фактического trace. Сохранённые native результаты уже показывают, что LoRA-параметры менялись.
2. **Применить адресные разрешения конфликтов.** На исходном срезе было 24 файла с blanket-исключениями; поздняя дельта уже исправила P51, P94, P110. Остаётся 21 файл, для которых в overlay дано узкое решение. Не считать эти файлы целиком неправильными и не запускать 21 новый опыт ради исправления текста.
3. **Сохранить текущие пользовательские уточнения в каждом задании.** Один фактор, известные inputs и пути, одинаковая панель, реальные updates или доказанный consumer обученного состояния; успех по любой полезной оси; только экспериментальная копия до решения о продукте. Полный CI, публикация продукта и переписывание старых результатов в эту стадию не входят.
4. **После этого — условные и косвенные проверки.** Replay lifetime, correction collision, restore/consumer seams допускаются по точной связи с обучением. Чистое оформление отчёта, искусственный scorer или lookup без learned state не получают отдельный учебный запуск.

## Что завершено и чего этот пакет не утверждает

Завершены source audit новых кандидатов, проверка новизны по доступному корпусу, адресная сверка карточек, анализ соседних веток и повторный расчёт сохранённых измерений. Добавлены новые документы, fixtures, provenance и точные проектные рецепты. Ничего из прежних экспериментов не удалено.

Новые native эксперименты не запускались; .NET в этой среде отсутствует. Blueprint не равен проверенной сборке. Все улучшения в таблице относятся к явно названным прежним прогонам, а не к нашему запуску. Два новых кандидата остаются гипотезами о влиянии на качество до их малого измерения. Автоматического переноса в production, полного исправления тестов или решения за пользователя о внедрении нет.
