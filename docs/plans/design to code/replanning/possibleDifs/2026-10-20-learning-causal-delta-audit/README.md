## 2. Что ещё актуально в реализации

**N-KU остаётся кандидатом для решения пользователя.** Текущий ActionLabelGenerator.Label учитывает ForEach/For/While, но не DoStatement. Сохранённый эксперимент меняет реальные учебные метки перед Train, поэтому относится к обучению. Минимальный предлагаемый original fix и raw уже существуют; повторное обучение ради регистрации не требуется. Этот пакет подтверждает результат, а не заявляет новый опыт. [Кандидат и текущий source](candidate-register.md#n-ku-01-измеренный-кандидат-ещё-не-внедрён).

**Для ProjectWiki подтверждена замена содержательной пары служебными строками.** Два текущих ToDpoMetricPair строят prompt/chosen/rejected из RejectedType и маркеров, тогда как donor передаёт действительные запрос и ответы. Это сильная гипотеза о потере содержательного учебного сигнала в названных pipelines. Её эффект на нынешнее качество ещё не измерен; она уже известна в P04/P108/P118. [Первичные current/donor источники](axis-coverage.md#dpo-что-именно-доходит-до-учебного-получателя).

**Есть конкретные несовместимости восстановленного состояния.** Tracked translation checkpoint содержит четыре направления, current runtime — шесть; manifest OrchestrationReasoning schema1 отклоняется current loader. Это допустимые зависимые участки: от них зависит доступность ранее обученной памяти обычному потребителю. Успешный P25 не закрывает все другие схемы, а ошибка загрузки не доказывает отсутствия самого исторического обучения. [Точные loader/consumer](axis-coverage.md#восстановление-зависимость-от-результата-обучения).

**Не все прежние диагнозы остаются дефектами.** Backward Embedding, fractional-mask derivative и доставка phrase_mappings уже присутствуют в current code. Их положительные результаты сохраняются, повторное внедрение не предлагается. Знаки native DPO и нулевой первый gradient LoRA-A при B=0 не объявляются ошибками без доказательства. [Нейронный разбор](core_learning.md).

## 3. Новая гипотеза: RMS-COORD-ALLOC-01

В MultiplyBroadcast каждый выходной элемент вызывает FlatToIndices, который выделяет отдельный массив координат. RmsNorm вызывает MultiplyBroadcast дважды; эта работа выполняется внутри настоящего Trainer → Forward → Backward → AdamW. Возможная экономия allocations и времени обучения проверяется заменой только способа вычисления broadcast-индекса на арифметику strides. Умножения, обратный проход, накопление gradients и сам mappedBIndices сохраняются.

Статус — **NEW / SOURCE_CONFIRMED / NOT_RUN**. Выигрыш не измерен и причиной плохих ответов RP01 не объявляется. Первый доменный профиль — программирование на C#, задача определения знака целочисленного вычитания. Четыре настоящих SFT updates на q/v-LoRA в каждом плече; одинаковые начальные weights и данные; одинаковый EXAM readout до четырёх updates и после них; полезная стоимость обучения оценивается вместе с loss, outputs и изменением обучаемого состояния. Перенос экономии на иные формы tensors или DPO остаётся предметом отдельного опыта.

[Карточка](RMS-COORD-ALLOC-01-CARD.md), [промпт](RMS-COORD-ALLOC-01-EXECUTOR-PROMPT.md), [36 исходных файлов и Git blob](RMS-COORD-ALLOC-01-SOURCE-MANIFEST.json), [поиск новизны](RMS-COORD-ALLOC-01-NOVELTY-SEARCH.json).

## 4. Все ли детали уже правильно представлены в защищённой папке?

**Нет оснований утверждать полную готовность всех экспериментов.** В актуальном срезе имеются 137 карточек и 470 P-подслучаев. Это исчерпывающий структурный учёт карточек, а не 470 выполненных опытов и не ручная аттестация каждого сочетания «подслучай × домен». В 125 P-карточках остаются общие незаполненные execution passports. Некоторые описания касаются лишь отчётности и ещё не указывают потребителя, через которого меняется обучение или используется обученное состояние. [Аудит](experiment_audit.md).

Во время работы core обновился: **правило немедленного stop/next уже добавлено во все 137 актуальных карточек** другим коммитом. Также добавлены N63-ingress-length и N63-replay-capacity и укорочены пути BPE. Поэтому этот пакет не дублирует 135 более не нужных приложений и не сообщает об уже исправленном правиле как о текущем пробеле. [Сверка поздней дельты](latest-source-delta.md).

Новая RMS-деталь отсутствует в защищённом каталоге на проверенном срезе. Она подготовлена здесь как конкретное добавление. Запрет изменения защищённой папки соблюдён: её физическое покрытие не объявляется достигнутым через ссылку на внешний документ. То же различие сохранено для новых cost-кандидатов, опубликованных другими агентами.

## 5. Порядок следующих решений

1. Сначала реальные препятствия прохождению урока и изменению обучаемого состояния: известные ingress-length, data/host dependencies и адресные учебные дефекты. Не вводить общий запрет на экспериментальные копии.
2. Затем разрешить конкретные противоречия назначенной карточки: автор выбирает ID/домен/данные/host/команды; исполнитель не должен изобретать их или продолжать старый опыт.
3. Сохранить уже измеренные успехи как кандидаты с ухудшениями рядом. Внедрение N-KU и прочих невнесённых product changes остаётся отдельным решением пользователя.
4. Назначать один будущий маленький опыт по готовому рецепту. Сейчас RMS только задокументирован; автоматического запуска из факта публикации нет.
5. Чистые пересчёты отчётности, serving-проверки без learned-state dependency и архитектурные проверки без учебного получателя — последняя очередь, без расходования токенов на фиктивное обучение.

**Команда пользователя «следующий эксперимент» немедленно завершает работу над предыдущим. Команда «остановиться» останавливает всю текущую работу.** Запрещено после неё дочитывать прежние логи, исправлять отчёт, выполнять «последнюю проверку», сохранять новые служебные файлы или публиковать старые изменения. Полное правило отдельно присутствует в новой карточке и в её промпте.
