## Что осталось в двух новых N63

**N63-ingress-length:** A имеет 0 updates из-за остановки ingress; B допускает два урока и имеет 2 updates. Карточка честно проверяет проходимость обучения, а не эффект при одинаковом compute. Actual checkpoint/host и frozen DLL должны соответствовать назначенному рецепту; совместимость не доказана чтением текста.

**N63-replay-capacity:** общей точкой служит WA после приобретения старого навыка; A делает 2 новых updates, B — 3 с replay. Весь budget составляет 9 updates с учётом предварительных учебных шагов. Цена дополнительного replay показана, равенство compute не заявляется. Retention интерпретируется только если old NLL действительно улучшился W0→WA.

Обе карточки содержат конкретные count budgets, но их host ещё не материализованы/не собраны и naked build/run commands не задают явный wall-clock timeout. Это ограничение будущего выбранного recipe; оно не служит общим запретом обучения. Новый timeout или ABI fix не выдумывается как уже проверенный результат. [Подробные первичные ссылки](experiment_audit.md).

## Новизна после этой дельты

RMS-COORD-ALLOC-01 повторно проверен по прежним 678 planning Markdown, 301 protected Markdown, новым 18 planning Markdown, двум N63 и добавленному тексту всех 156 core changes. Точный механизм per-element FlatToIndices allocation в настоящем RMS learning path не найден; имеющиеся MultiplyBroadcast упоминания описывают правильный autograd. [Ledger](RMS-COORD-ALLOC-01-NOVELTY-SEARCH.json).

Это заявка на новизну **относительно проверенного корпуса**, не обещание, что никто нигде прежде не обсуждал такой механизм. Другие нейронные идеи — FP32 totals/margin, softmax scratch, gradient clone, frozen transpose — не представлены как новые.
