## Как закончить

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост accuracy не обязателен.** Снижение allocations при тех же ответах — полезный исход; все ухудшения CPU/времени/NLL/exact/peak памяти показать рядом. Для валидности A/B требуются одинаковое начало/материал/бюджет и actual parameter updates. Отсутствующие числа пиши «не измерено», ожидание — «гипотеза».

Запиши `C:/xg/RMS01/aNNN/results/report.md`: до350 слов плюс таблица «что меняли; на чём; A0/A1/B0/B1 и две цены TRAIN; выигрыши/ухудшения; граница». Raw — `results/A/code-sign.json` и `results/B/code-sign.json`; из report относительные ссылки `A/code-sign.json`, `B/code-sign.json`, `one-factor.diff` и имена logs по карточке, без повторного `results/`. При полезном измеренном улучшении добавь `results/candidate.md` до120 слов со ссылкой `[report](report.md)` и исходный `MultiplyBroadcast` diff для решения Любы. Это кандидат, не разрешение переноса в prod.
