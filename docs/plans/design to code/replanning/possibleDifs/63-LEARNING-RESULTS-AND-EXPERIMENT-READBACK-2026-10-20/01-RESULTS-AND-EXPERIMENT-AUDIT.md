## 3. Конкретные оставшиеся замечания

### E-AUD-01. Справочник не закрывает точный опыт автоматически

В P01 прямо перечислены незаполненные поля: подслучай/предмет, actual native caller/command, точные данные/initial state/model/reference/optimizer/RNG, factor, output и counts. Аналогичная роль задана всем 125 P-карточкам. [P01, строки 88–106](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P01-trainable-recipient.md#L88).

Поправка обзора: помечать эти записи «гипотеза описана, точный recipe назначен отдельно/ещё не назначен». Не объявлять их невалидными только из-за нулевого числа новых updates: restore существующего learned state разрешён при доказанной связи. Перед выдачей нового задания автор заполняет конкретную карточку; исполнителю не поручается выбирать место, learner или способы обхода конфликтов. Самостоятельно клонировать 153 карточки в ещё один каталог с теми же общими абзацами не нужно.

### E-AUD-02. В P86 остался конфликт старого prompt; native успех уже сохранён

Верх P86 уже имеет статус `SOURCE_ALREADY_PRESENT` и ссылается на успешный native `dpo-mask-live8-01`: восемь DPO updates на плечо, согласованность производной и различия, достигшие optimizer first moments. Текущий backward уже учитывает mask; binary exact-v2 этим дефектом не объяснён. Это существующая успешная история, не новая гипотеза и не основание повторить patch или откатить нынешний код. [P86, строки 133–139](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P86-fractional-response-mask.md#L133-L139).

Остаточный конфликт находится в старом профильном prompt: «Без legacy caller ограничь вывод формулой/компонентом». При действующем пользовательском запрете он не разрешает новый runtime опыт вне реальной учебной зависимости. [P86, строки 148–171](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P86-fractional-response-mask.md#L148-L171).

Конкретная сопроводительная поправка: алгебра остаётся историческим объяснением, сохранённый native успех — существующим результатом. Без точного native учебного caller или доказанного участка использования learned state новый runtime опыт не назначается; standalone симуляция не подставляется. Новый опыт возможен только по отдельному полному рецепту ещё не проверенного отличия. Повторный patch/rollback нынешнего backward из старого prompt не следует. Защищённая карточка этим обзором не редактируется. Открыта точность инструкции, а не необходимость ещё одного запуска P86.

### E-AUD-03. Старое причинное объяснение в skill нельзя принимать за доказательство

`experiment-design-SKILL.md` продолжает объяснять правило ×10 тем, что оно вызвало catastrophic forgetting в E44v2. [Строки 73–77](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/skills/experiment-design-SKILL.md#L73). Защищённое исследование уже описало confound: менялись targets, число updates и порядок; `weighted_f1` был смесью accuracies, а general accuracy была нулевой в обоих плечах. [Уже существующая сверка, строки 7–30](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/57-e44-e45-target-confound-and-future-controls.md#L7).

Это подтверждённое **сохранение старого противоречия**, не новая гипотеза и не оправдание постоянного ×10. В новых карточках frozen пары создаются до перемешивания; выбор weighting, числа шагов и curriculum — отдельные факторы. Содержимое skill за пределами write scope не меняется; при применении skill его причинная формулировка не используется как доказательство.

### E-AUD-04. Предмет и точность называются на уровне фактически измеренного

В отчёте transpose заголовок домена говорит об «обучении нейронных весов» — это механизм, тогда как реальные данные задают программирование, определение знака результата C#-выражения. В BPE речь о токенизации материалов двух тем, не об улучшенном переводе. `3/4` N-KU соответствует узкой рубрике отсутствия ложного совета о цикле; `1/2` diagnostic — частичный полезный ответ с провалом второго знака. Это правка описания, не основание запускать новый probe. [Словарь, строки 5–22](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/skills/human-communication-GLOSSARY.md#L5).

### E-AUD-05. Остаточные component-абзацы не отменяют учебную границу

Адресный поиск по125 P-карточкам выделил P11.5–.8 (`L=sum`, caller CONDITIONAL), P12.4 (`отсутствие hook — component-only`), P109.2/профили (provenance/gold audit как отдельный проект) и старый P86 prompt. Верхний binding этих карточек уже требует actual learning connection и exact recipe, поэтому это не действующее разрешение standalone и не новые дефекты autograd или optimizer. В будущем поручении надо сохранить эту границу прямо в локальном тексте, чтобы историческое описание не превратилось в отдельный запуск. Точные места и поправки — [TARGETED-ERRATA.md, E-AUD-05](05-TARGETED-CARD-ERRATA.md#e-aud-05--старые-component-формулировки-уже-подчинены-учебному-binding).

Компонентное native измерение допустимо, когда реальная связь с обучением/его входом/восстановлением/результатом показана кодом. Само слово component и отсутствие нового update не повод запрещать его. P09/P10, P75/P89.1/P99/P100 и P110 уже содержат адресные корректные ограничения; повторные запреты и дополнительные runtime gates им не нужны.

## 4. Ограничения доступа к сохранённым артефактам

Материализованы 1007 текстовых файлов из 1207 Git blobs каталога; бинарные DLL/PDB/архивы не запрашивались. Восемь `comparison.json` являются Git LFS pointer blobs, включая все три новых сводных сравнения. Поэтому `comparison.json parsed` или «проверены все поля comparison» здесь не заявляется. Основные raw A/B доступны и позволяют независимо проверить перечисленные числа и совпадения. Один исторический N-KU build.log декодирован connector из иного текстового представления; он не используется для проверки побайтной идентичности. Эти ограничения не отменяют непосредственно проверенные метрики и не назначают повтор опыта.
