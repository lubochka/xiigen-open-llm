## Правило перехода

После внешнего завершения N62-R1 следующий ID — №05. Адресная проверка обнаружила, что исходный №16 IDENTITY-M1-01 меняет reader уже обученной памяти. По прямому правилу пользователя его следует выполнять после прямого обучения, хотя старый index ставит раньше. Поэтому для порученной программы существующих ID действует уточнённый маршрут **05–15 → 17–31 → 16 → 32 → конец**. Если поручена дополненная программа с двумя новыми карточками этого пакета и сохранённым NG01 из параллельного обновления: **05–15 → 17–31 → S01 ROPE-TRAIN-TABLE-01 → S02 AST-SIB-CACHE-01 → S03 NG01 → 16 IDENTITY-M1-01 → 32 KN-ROUTER-LEARNED-KEY-01 → конец**. Номера исходных карточек сохранены, S01/S02 обозначают наши новые карточки, S03 — уже опубликованный другим автором NG01; постоянные ID чужих опытов не меняются. Различие внешних номеров и точный override NG01.next_id разобраны в [12-CONCURRENT-RECONCILIATION.md](12-CONCURRENT-RECONCILIATION.md). При поручении отдельного ID выполнить только его назначенную фазу и закончить. Недостающий host не превращает NOT_RUN в неудачный результат обучения: стадия подготовки фиксируется отдельно.

Документная сессия сначала устанавливает реальный learner и устраняет ошибочные блокировки/подмены его проверки, затем разрешает противоречия карточек, затем учитывает присланные обновления. Только после этого рассматривается зависимое чтение выученного результата. Данный пакет выполнил документную часть этого порядка; product promotion и новые runs ему не приписываются.

## STOP/NEXT, модель, отчёт

Любое измеренное улучшение полезного показателя — успех по своей метрике и предметной теме; точность расти не обязана. Ухудшения и несовпадение learned state показываются рядом. Предметная эффективность, скорость, allocations, удерживаемая память и корректность восстановления не взаимозаменяемы.

Модель исполнителя и назначенного reviewer — default текущей сессии, без выбора другого класса/версии из старого файла. Карточка задаёт native Student отдельно от модели ассистента. Чужое историческое требование модели или полного product workflow не создаёт новый конфликт для малого экспериментального host. Русский report и candidate-шаблон даны в самой карточке; поиск нового шаблона не нужен.

При «заканчивай и переходи к следующему» немедленно прекратить прежнее задание и перейти к следующему указанному ID **в разрешённой фазе**. Не дописывать прежние отчёт/карточку/реестр/hashes/Git/review, не повторять запуск и не выполнять «последнюю проверку». При «стоп/закончить немедленно» остановить всю работу; допустимо только необходимое прекращение собственного ещё работающего процесса. Частичные файлы сохранить. Конец очереди означает конец, а не возврат к старой задаче.
