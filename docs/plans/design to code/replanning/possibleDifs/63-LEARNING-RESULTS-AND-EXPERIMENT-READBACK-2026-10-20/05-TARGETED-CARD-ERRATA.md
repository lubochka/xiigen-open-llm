**Доказательство ограничения:** [P01 L88–106](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P01-trainable-recipient.md#L88-L106) прямо обозначает историческое семейство, не готовый паспорт, и перечисляет недостающие selected subcase/domain, точные данные/initial state/model/tokenizer/reference/optimizer/RNG, native caller/command, одно изменение, output, budget. **Текст для сопроводительного реестра:** «P-карточка подтверждает, что гипотеза и варианты предметной проверки описаны. Готовность конкретного задания определяется отдельным рецептом с точным native caller, входами, состоянием, моделью Student, одной A/B-правкой, путями, командой, бюджетом и следующим действием. Не копировать 153 общих карточки как новые задания. Добавлять только новые проверяемые гипотезы и адресные недостающие рецепты. Отсутствие новых updates само по себе не исключает восстановление или использование уже выученного состояния: нужна точная доказанная зависимость.

## E-AUD-02 — P86: старый formula fallback не становится новым опытом

**Уже исправлено/известно:** [P86 L133–139](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P86-fractional-response-mask.md#L133-L139) имеет статус `SOURCE_ALREADY_PRESENT`. Там указан настоящий сохранённый `dpo-mask-live8-01`, восемь DPO updates на плечо, полезная согласованность native производной и достигшее optimizer first moments различие. Текущий backward уже учитывает mask; binary exact-v2 этой причиной не объяснён. Это существующая успешная история, а не новая гипотеза и не основание откатить текущий код ради повтора.

**Остаточный конфликт:** [P86 L148–171](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P86-fractional-response-mask.md#L148-L171) сохраняет старую фразу «Без legacy caller ограничь вывод формулой/компонентом». При действующем пользовательском запрете она допускает неправильное прочтение как отдельный runtime опыт вне обучения.

**Текст поправки к любому будущему поручению P86:** «Исторический формульный proxy остаётся объяснением и не запускается повторно. Без названного native учебного caller или доказанного участка использования learned state новый runtime опыт не назначается; standalone симуляция не подставляется. Существующий `dpo-mask-live8-01` и SOURCE_ALREADY_PRESENT сохраняются. Новый опыт возможен только по отдельному полному рецепту для ещё не проверенного отличия; повторный patch/rollback нынешнего backward из старого prompt не следует».

Таким образом, открыта точность инструкции, а не необходимость ещё одного запуска P86. Защищённый текст и старые raw сохраняются.

**Действующее правило уже исключает подмену.** Например [P11 L70–72](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P11-autograd-reachability.md#L70-L72) требует назначенный конкретный recipe и настоящий learner; [P11 L121–125](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/P11-autograd-reachability.md#L121-L125) прямо запрещает назначать проверку без доказанной учебной связи. ## Граница проверки

Получены 1007 текстовых файлов защищённого каталога; они обработаны при структурном пересчёте. Выполнены полный структурный census карточек, адресные смысловые проверки и readback сохранённых raw новых трёх результатов плюс отдельного диагностического 400-step файла. Новое обучение, сборка и hosts не выполнялись. Восемь `comparison.json` являются LFS pointers; арифметика пересчитана из доступных raw A/B. Сохранённые hashes сравнивались как значения, tensor hashes не восстановлены из отсутствующих весов. Полная причинная validation всех 470×всех предметных тем не заявляется.

## E-AUD-06 — результаты смысловой проверки всей назначенной очереди

[Таблица32 рецептов](10-QUEUE-SEMANTIC-REVIEW.md) добавляет четыре адресных поправки к общему структурному census.
