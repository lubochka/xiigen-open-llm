## Первый опыт: протокол теперь пригоден для отдельной реализации

[Глава 05](../05-SMALL-DOMAIN-EXPERIMENTS.md) оформлена как **PLAN / NOT RUN** и задаёт конкретный первый AC-SQL01 опыт. Точные причинные условия сохранены:

- Меняется только TRAIN representation. Обе ветви используют один frozen HELDOUT/EXAM: одинаковые triples, ID, masks и scorer. Общий вопрос с разными экзаменационными targets не выдаётся за одинаковый экзамен.
- Есть 50 различных TRAIN и 50 HELDOUT строк, source-family split, один epoch, minibatch 5 и 10 updates на плечо — 20 updates для A00/A10. Два урока не размножаются до минимального размера runner. Продление до верхнего предела сохраняет trainer state; curriculum 35/50 проверяется отдельным последующим 2×2.
- До обучения проверяются actual token IDs, бюджет prompt/response и видимость признака. Пустой список SqlTablesWritten не считается доказанным read-only без проверки достаточного SQL evidence.
- Общие policy/reference/state и budget изолируют влияние representation. До/после/cold оцениваются собственные ответы нужного consumer. В AC-EV02 дополнительно предусмотрены A_before и B_before, чтобы отделить доставку контекста от разности учебных приростов.
- Панель включает четыре новых контраста, два unknown и два retention/control случая. Это короткий screening, не статистическое доказательство общей точности. Для retention требуется подтверждённая baseline-correct история; критическая ложь и потеря retention остаются регрессией.

**Роли зафиксированы точно.** CODEX с **запрошенной Astra 6 ultracode** выбирает задачу, допустимые источники и материал. Внешняя открытая китайская модель создаёт **обе окончательные стороны** DPO; в SQL A/B она возвращает chosenA/chosenB/common rejected. Отдельный CODEX judge принимает exact pairs и разрешённый diff, с исходами tie/both_bad/needs_info. Принятые candidate bytes не дописываются и не меняют автора. Другой сеанс judge проверяет собственные ответы consumer вслепую, без arm/checkpoint/teacher answer и training labels. Разделение ролей не выдано за уже состоявшиеся модельные вызовы.

**Ограничение существующего входа также исправлено.** Обычный AnswerComposerTrainingPipeline сам строит fixed pairs, а обычный ToTrainingBatch выставляет DeterministicGenerator admission. Новый внешне написанный Q не должен проходить этот путь под переименованным происхождением. Документ называет существующий repository-owned entry с dataset address/manifest/checkpoint context и сохранением original pair; при отсутствии нужного SQL-соединения это ограниченная задача следующей реализации. Ни готовая one-command CLI, ни уже подключённый reader не заявлены. Отсутствие reader ограничивает результат preference pilot и не превращает deterministic composer answer в эффект DPO.

## Оставшиеся границы PASS

Неизвестные actual callers условных KNN/tensor путей, точная identity исторического исполнявшегося бинарника, нужный SQL author-preserving ingress и ordinary neural reader остаются вопросами будущей реализации/preflight. Они названы открыто, имеют проверяемые условия и не требуют выдавать неподтверждённое поведение за факт. Поэтому они не блокируют публикацию исследовательского пакета.

Пакет можно публиковать в указанном виде вместе с этим отзывом и manifest. Следующий содержательный результат должен быть ограниченным matched опытом с реальными state/consumer и сохранёнными ответами; нынешний PASS не является его заменой.
