## Текст для пункта сохранения SFT state

> `after-sft.rng.json` нельзя передавать native `RepositoryOwnedDpoRandomStateFile.WriteCreateNew`: writer требует каноническое имя. В новой отдельно назначенной экспериментальной реализации одинаковая обвязка обоих плеч создаёт owner-only `R/<arm>/sft-state/`, получает actual snapshot после SFT и вызывает writer с `Path.Combine(sftStateRoot, RepositoryOwnedDpoRandomStateFile.BuildFileName(snapshot.RandomStateStep))`. `stage=SFT`, конкретный SFT optimizer step и веса/optimizer/RNG связываются в одном receipt. DPO-state сохраняется отдельно в `R/<arm>/checkpoints/`. Native path/custody guards не меняются. Для последующего продолжения нужны те же tokenizer, q/v-LoRA topology, weights, m/v/step и actual RNG; совпадение одного loss не считается восстановлением всего состояния.

## Текст для счётчиков частичного результата

> Учёт учебных вызовов независим от успеха сохранения отчёта. После успешного возвращения `StepVector` фиксируется один завершённый DPO update, после `TrainSupervisedNextTokenStep` — один завершённый SFT update. Последующая ошибка не обнуляет эти значения. `attempted`, `completed`, `armCompleted`, `persistenceCompleted`, `errorStage` раздельны. Неопределённый исход внутри update обозначается UNKNOWN и сверяется с receipts того же запуска; повторная команда не средство проверки. В старом N63C A фактически выполнено DPO1+SFT1; исторический JSON не редактировать, читать с этим erratum.

## Условия авторского завершения исправленного учебного рецепта

**Сейчас новый учебный рецепт не готов.** Совместимый H512 before с подтверждённым ненулевым предметным результатом не установлен. H16/H32 partial snapshots не подменяют H512; локальная probe из сообщения пользователя не считается полученной с GitHub. Нельзя выдавать ещё один повтор четырёх холодных updates за исправление.

Перед отдельным будущим поручением автор назначает точный совместимый Student, конкретную frozen TRAIN/EXAM/CONTROL панель, snapshot/подготовку с явным происхождением, единственный host, entry, output, конечный budget и criterion ненулевого предметного результата. Должен быть показан ненулевой навык перед вмешательством, если проверяется его удержание/разрушение. Общая подготовка не включается скрытно в цену одного плеча. Недостижение критерия завершает эту подготовку как недостаточную, без автоматического изменения seed/модели/данных/бюджета. Следующий исполнитель не принимает эти решения вместо автора.

Любое измеренное улучшение полезного показателя на валидной учебной постановке считается успехом этого показателя и домена; рост accuracy не обязателен. Рядом обязательны остальные показатели и ухудшения. 0→0 не превращается в учебный успех из-за margin тысячных. Устранение filename error подтверждает исправление обвязки, но само по себе не доказывает пользу замены stale SFT.Response.
