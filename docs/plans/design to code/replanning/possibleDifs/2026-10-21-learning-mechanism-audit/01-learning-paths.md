Это актуализация существующих находок, а не присвоение их авторства. Пин кода — `d962f95805ae0c9c4ef5b3f50f0f65b2a4109d19`. Перечень сопоставляет запрошенные механизмы; он не доказывает полноту всех возможных ошибок и не устанавливает одну причину неудачи RP01.

## 1. Что действительно произошло в исходном RP01

Сохранённый C# результат содержит 500 пар / 50 updates, изменение всех 16 разрешённых adapter tensors и отсутствие изменения 39 base tensors. Веса, optimizer и RNG были сохранены и открыты заново. Свободные ответы остались **0/3→0/3**, все три пары ответов побайтно совпали. EN→RU затем продолжил C50 ещё на 50 updates до step100: frozen reference сохранена, полный state открыт и совпал с live, семантическая оценка **0/4→0/4**. Изначальный B0 был необученным. Это несовместимо с обвинением «обновлений вообще не было» и не доказывает приобретение способности. Также нельзя называть всякий RP01 continuation новым random-start: второй запуск действительно продолжал C50. [C# primary result][rp-cs]; [EN→RU primary result][rp-ru].

Эти результаты показывают, почему одинаковое слово «обучение» недостаточно: neural Student меняет веса; memory learner запоминает примеры, части и метки; ответ может читать другой Unit либо фиксированное правило. Проверять нужно связь урока, изменённого состояния и конкретного ответа.

## 3. Успешная соседняя ветка и подмена функции при переносе

Повторно проверены указатели реальных веток: `language_translate@f6032aff81f1f83de7c09cf9b9efe6b058dd12b9`, `PrepareToGPL@31346d8928be4469b01aaf313780e8f950ff91e2`, `DesignToCode-clean@e346b88a3cc1fcce48aefa626bfc7b00509eefd6`. Чтение branch heads не означает полного аудита всех их файлов. Primary E25 source/raw прочитаны в language_translate; current learner и current consumer — на d962.

[E25.Run:17–43][e25] создаёт 160 POS-последовательностей, Train получает 128, обе оценки — те же 32. [Raw 1 мая][e25raw] сохраняет accuracy0.3438→0.875, то есть 11/32→28/32, и время 0.4→15.4 мс. Время относится к Predict после Train, не к обучению. Другой receipt может иметь 9.7 мс: их нельзя смешивать в одну строку. Маленькая синтетическая панель не доказывает покрытие естественного языка или «95% запросов» из комментария.

Текущий [PatternClassifier проекта 12][pos12] хранит обучающие POS/labels, считает Jaccard bigrams и голосует k3. [Проект 29][pos29] вместо этого выводит теги из фиксированных списков и выбирает rule label; Train отсутствует. [Реальный fusion:213–245][fusion] создаёт именно проект 29. Родительский [PLAN-KNN-MATRIX-INTEGRATION-v3:312–323][parent] ссылается на +155% E25 и одновременно предписывает helpers проекта 29. Это конкретная потеря тождества экспериментального алгоритма при планировании/подключении. Сам риск уже известен предыдущим агентам; этот пакет подтверждает его по родительскому плану и current source, не объявляет новым.

Не следует объявлять любую неудачную матрицу доказанно успешной после kNN только по совпадению номера E. Нужны matched label codec, split, denominator и consumer. Late E22 positive уже отражён в корпусе; менялись corpus/labels, поэтому отдельный причинный эффект «матрица→kNN» из него не установлен. [Существующий разбор][e22prior].
