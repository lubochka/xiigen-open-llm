## Основные выводы

1. **У нового N63C-PROBE есть полезный измеренный результат.** Приобретение T1: 0/23→22/23 правильных токенов. После одинакового DPO старый SFT-текст оставляет 20/23, исправленный — 21/23, с лучшим T1 NLL и сохранённым положительным предпочтением. Оба плеча теряют токены относительно before; EXAM остаётся нулевым, полного ответа нет. Кандидат уже добавлен автором в core — здесь он сохранён с регрессиями и проверкой доказательств.
2. **Первый N63C и новая probe — разные записи.** Старый A-only запуск действительно сделал DPO1+SFT1, затем упал при сохранении RNG; B отсутствует. Новая probe содержит 802 updates и 60 scoring forwards. Current source уже имеет другие параметры — 60/20 вместо 600/100 — и не воспроизводит completed raw. Отдельные results-02/results-03 не смешиваются с ним.
3. **SFT учится и оценивается на разных carriers.** В current probe acquisition и SFT кодируют `Prompt+LF+Response`; readout идёт через exact DPO без разделителя и с отдельной BPE-сегментацией. Это конкретный same-model разрыв известной P07-семьи. Он может мешать полноте измеряемого before, но причинность ошибки 22/23 пока не доказана. Нельзя заранее считать её ошибкой LoRA/backward или лечить только увеличением шагов.
4. **Часть конфликтов уже исправлена во время нашего аудита.** N63C status, canonical RNG filename и stage counters исправлены в документации core256; protocol30 запрещает заранее недиагностичный опыт и blind retry; поздний protocol31 различает настоящий wait, быстрые snapshot и experiment deadline. У 15 прежних unqualified-рецептов изменены заголовки и guards, но прежние малые бюджеты сохранены. Готовность конкретного учебного контраста всё ещё должна быть установлена.
5. **Успешный исторический kNN не всегда совпадает с current consumer.** E25 действительно обучает POS-память проекта 12 и даёт 11/32→28/32 на небольшой синтетической панели; fusion создаёт rule-classifier проекта 29. Родительский план связывает эти разные алгоритмы. Это подтверждение известного существенного расхождения, с доменной границей, не новая присвоенная находка.
6. **Новая самостоятельная гипотеза — POS-QUERY-SET-ONCE-01.** Query bigrams одного запроса строятся заново для каждого обученного соседа. Задан конечный native опыт: одна генерация fixture, 2 Train и 128 Predict; качество и стоимость до/после, один фактор, отдельные ownership/claims. Это стоимость чтения выученного результата, поэтому последний приоритет. Выигрыш пока не измерен.
