## Действующее уточнение после P128 — Четыре ступени доказательства и одна работающая приёмка

Проверенный core: `f8784df037b59cf878889eef4d0956f5d0c985e7`; planning: `5df24354aa803f7ed5dd3bac48146466e2feb189`. Это адресное усиление приёмки соответствующего класса, а не новая аттестация всех исторических опытов карточки.

Назвать producer→байты→actual state→обычный ответ→mandatory predicate→verdict/exit. Сохранённый hash или ExactCorrect не влияет на приёмку, пока его потребитель не прослежен. Честный полный набор принимается; одна порча достигает того же проверяющего. P128: размер 28 167 байт, SHA и StableState совпали в факте, но полнота сверки и связь outcomes с итогом недостаточны. P126: квалификационный отказ и отсутствие restore могут достичь DONE; фактические completed updates считаются отдельно от plan. Нативная приёмка Release имеет свежий run ID, raw TRX и source/DLL identity; historical artifacts доступны только для чтения. Python recount не тождествен нативному прогону.

**Передать исполнителю вместе с собственным паспортом:** проследить названный actual consumer, сначала принять полный honest пакет, затем отвергнуть одну адресную порчу тем же checker; результат включить в общий verdict и внешний exit. Указать источник/сборку, фактический расход каждой попытки и предел утверждения. Ремонт expected опирается на независимый договор, не на actual сломанного кода. Сохранённый PRIMARY не повторять; gold, исходные бюджеты и прошлые результаты не менять. Активная попытка сохраняет ранее выданный ей pin карточки. Native source/static counterexample и исполненный тест обозначать отдельно.

В прочитанных индивидуальных P02/P51/P52/P53/P54/P60/P67/P95/P107/P113/P122/P125 **правило пользователя присутствует и в тексте, и в общем промпте**: любой полезный измеренный gain по оси/домену достаточен для *локального успеха*, accuracy не обязательна, остальные gain/loss публикуются рядом; выполнены различия между слоями Unit/Flow и total/trainable neural layers. Поэтому нарушение «во всех индивидуальных карточках нет правила» было бы ложным. **Полнота построчно у остальных 113 карточек не проверена в этой сессии; ранее другие агенты проверяли больше — это не наши свежие native results.**

## Главный критерий валидности (более строгий, чем «прошёл метод»)
Карточка, обещающая выяснить `влияние на качество обучения`, получает `LEARNING_VALID` **только если одновременно**:
1. Названа предметная **тема обучения** (например, перевод, C# документация, SQL, оркестрация), задача/направление и **реальный получатель изменения** (`DpoTrainer`+Student/LoRA или `ExecutorUnit`/memory/`ILearningFlow`). `kNN`, `LoRA`, векторизация, поле `sourceLang` не являются темой сами по себе.
2. Доказан **actual caller path**: existing producer → `Train*/Step*/AddLesson*` → changed accepted state (tensors/entries/Unit/Flow) → ordinary consumer of THIS SAME state. Если неизвестен owner/caller, **BLOCKED**, не симулировать продукт.
3. A/B фиксирует одинаковое исходное состояние, train families, независимый heldout, настройки, budget/seed, если не выбран отдельный contrast; pre/post `A0/A1, B0/B1` при сравнении того, *как* обучается новая система. Для смены только inference-policy можно измерять `USE_OF_LEARNED_MEMORY`, но нельзя называть это изменением самого learning process без взаимодействия с реальным учебным состоянием.
4. Реальные ответы именно `Student/Unit/Flow` до и после; исключены подставленные expected/oracle, generated mock, pure code branch proxy. Negative: shuffled targets/no-update; edge: negation/role/order/unknown; при необходимости проверяется cold import без нового урока.
5. Метрики *заранее* по соответствующей теме: смысловая корректность/частичные приобретённые навыки, critical accepted errors, coverage/abstention, correct/answered, latency, RAM/VRAM, cost of training/teacher/annotation, param/index bytes, native layer/Unit/Flow counts. **Любое фактически измеренное полезное улучшение означает успех по ЭТОЙ оси для ЭТОЙ темы; accuracy может быть прежней; каждая другая ось, включая ухудшение, записана рядом.** Report не должен прятать увеличение wrong-accepted и классифицировать замену поля `AccuracyAfter` на coverage как обучение.

**Если нарушен п.1/2/4:** `INVALID_AS_LEARNING_EXPERIMENT`, не расходовать токены на запуск. Прямой арифметический debug/инвариант можно записать без вывода о learning; под него не назначать отдельного дорогостоящего исполнителя. Тот факт, что карточка существует, сам по себе не авторизует её запуск.
