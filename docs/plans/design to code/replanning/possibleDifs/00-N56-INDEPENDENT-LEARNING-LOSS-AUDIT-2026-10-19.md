## 3. Новые независимые **узкие** кандидаты N56 (не объявлены исправлениями)

В ходе source review обнаружены новые точные стыки в [`LogicalCapabilityTrainingPreferenceProjector`](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/21.AgentInfrastructure/Logical/LogicalCapabilityTrainingPreferenceProjector.cs); у каждого есть похожие **родственные** P-карточки, но прочитанные карточки не исследуют именно эту комбинацию метода и recipient. Новизна относится к **локализованному условию и проверочному контракту**, не к мировому открытию совершенно иной категории:

1. **N56-O1 — `chosen/rejected` как шаблон лояльности к подфазе вместо предметного действия:** prompt уже содержит `sub_phase: id/name/purpose`, chosen = `Generated capability for sub-phase ...`, rejected = `Do not generate ...`. Может обучать выходной шаблон и метку, а не правильное исполнение работы. Нужна настоящая neutral-label и противоположная рабочая цель. [Доказательства и фальсификатор](N56-NEW-ORCHESTRATION-PROJECTOR-SEAMS-2026-10-19.md#n56-o1).
2. **N56-O2 — модель видит 3 decimal places vector, паспорт видит полную точность:** `vector.ToString("0.###")` в prompt против SHA/отдельного TeachingVector float. Сперва установить, есть ли реально две допустимые разные semantic projections, дающие одно округлённое model-visible представление; иначе **NOT_REACHABLE**. [Разбор](N56-NEW-ORCHESTRATION-PROJECTOR-SEAMS-2026-10-19.md#n56-o2).
3. **N56-O3 — `.Distinct(Prompt)` в authorized replay удаляет частоту повторённого учебного события:** при одинаковом тексте и разных реальных source binding, replay text не отражает кратность. Это может быть **правильной дедупликацией**, поэтому требуется отделить качество от экономии, узнать downstream weight/replay consumer. [Разбор](N56-NEW-ORCHESTRATION-PROJECTOR-SEAMS-2026-10-19.md#n56-o3).
