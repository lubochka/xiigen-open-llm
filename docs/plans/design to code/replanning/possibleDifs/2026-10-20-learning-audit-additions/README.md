## Главный результат

Подготовлены **четыре дополнительные гипотезы**, привязанные к настоящему обучающему пути. Три проверяют лишнюю работу внутри обучения или подготовки непосредственно используемой DPO-пары. Четвёртая проверяет смешение типов признаков обучаемого Wiki-классификатора. Для каждой есть отдельная карточка, буквальные входные данные, один изменяемый фактор, точные исходники, проект будущей экспериментальной копии, команды, показатели и промпт. **Это `DESIGNED_NOT_RUN`: наличие рецепта не означает готовый собранный runner или уже измеренный выигрыш.**

| ID и карточка | Подтверждено по исходникам | Что ещё требуется измерить | Предметная применимость |
|---|---|---|---|
| [BPE-WEIGHTED-CHUNKS-01](neural-bpe/BPE-WEIGHTED-CHUNKS-01.md) | Одинаковые chunks повторно обходятся при подсчёте пар и слияниях BPE | Стоимость одного настоящего `BpeTokenizer.Train` с сохранением кратностей, порядка ties и token IDs | Код/документация и EN→RU; проверяется обучение токенизатора |
| [DPO-TOKENIZER-SNAPSHOT-01](neural-bpe/DPO-TOKENIZER-SNAPSHOT-01.md) | Для каждой допустимой пары снова делаются Save→Load токенизатора и вычисление его состояния | Цена подготовки реально потреблённых DPO-пар при одном приватном frozen snapshot на `PrepareExecution` | Документация C#; тот же exact DPO, LoRA и reference |
| [WIKI-FEATURES-ONCE-01](wiki/03-features-once-experiment.md) | Неизменные текстовые признаки каждой строки вычисляются внутри всех 18 эпох | Время и аллокации полного Train при расчёте признаков один раз, с учётом удерживаемой памяти | Маршрутизация запросов по документации проекта |

Эти механизмы не найдены как те же однофакторные опыты в просмотренном корпусе прежних документов, включая позднюю публикацию `a868f46e`. Соседние темы и точные отличия указаны внутри карточек. Это ограниченная проверяемым корпусом новизна; не утверждение об отсутствии таких идей где-либо ещё. Причиной неудачи конкретного RP01 эти четыре механизма пока не доказаны.

## Покрытие и оставшиеся конфликты

Базовый поэлементный аудит охватывает **135 карточек / 470 P-подслучаев**; поздняя delta добавила две N63-карточки, поэтому проверенный текущий каталог содержит **137 карточек**, а P-подслучаев по-прежнему 470. Структурное наличие строк и ссылок не считается доказательством того, что каждый опыт уже готов, выполнен или причинно валиден.

Во время работы core самостоятельно обновился: правило немедленно выполнять «стоп/следующий эксперимент» добавлено в карточки. Поэтому отсутствие этого правила описывается только как исторический факт на `ab583032`, **не как оставшийся дефект `65d03a73`**. Поздние изменения коротких путей BPE/Wiki учитываются в [аудите карточек](experiment-audit/README.md). Неразрешённые противоречия модели по умолчанию, выбора незаполненного паспорта и output в запрещённую папку перечислены адресно.

**Нельзя честно заявить, что все четыре новые детали уже покрыты защищённой папкой:** точные новые опыты добавлены здесь, а не туда, поскольку пользователь запретил её менять. [Матрица покрытия](experiment-audit/per-subcase-coverage.csv) и карточки показывают, где есть существующая родственная тема, а где нужен новый отдельный опыт. Старые эксперименты не удалены и не заменены.

## Правило исполнителю этого пакета

Текущая работа — документация. Следующий эксперимент определяется прямым поручением пользователя; этот индекс не назначает новый запуск. Модель исполнителя — текущая модель сессии по умолчанию, без навязанной замены; отчёт по-русски. Любое измеренное улучшение полезного показателя признаётся успехом по этому показателю и предметному домену, с остальными изменениями рядом. Внедрение в продукт решает пользователь.

**При «переходи к следующему» немедленно прекратить прежнюю задачу и перейти только к уже назначенной следующей; запрещено доделывать прежний отчёт, проверки, публикацию или повтор. При «остановить всё» прекратить всю работу; допустимо только остановить собственный ещё работающий процесс. Никаких завершающих обходов, hashes, новых вызовов или удаления старых данных ради оформления.**
