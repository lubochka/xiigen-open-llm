## Остальные будущие result-пути: один точный способ разрешить конфликт

В **135 из 137** текущих карточек есть назначенный output или незаполненный шаблон внутри защищённого `docs/plans/replanning-possible-diffs/experimets/results/`. В двух Wiki путь уже вынесен наружу. Это конфликт **будущей записи при нынешнем read-only условии**, не новый запрет читать, готовить документацию или исполнять другие уже порученные опыты.

Для BPE01 и двух N63 действуют индивидуальные точные пути выше/ниже. Для остальных карточек при будущем порученном выполнении заменить только абсолютный префикс `C:/Projects/llm_mvp_core/docs/plans/replanning-possible-diffs/experimets/results/` на **`C:/xg/r/`**, сохранив существующие суффиксы даты/ID/A/B и имена raw. В PowerShell переменную output задать полученным абсолютным путём, не соединять его с `$...Root`. Например N-KU output становится `C:/xg/r/2026-10-20/N-KU-01-do-loop-label-01/`, frozen transpose — `C:/xg/r/2026-10-20/NEURAL-FROZEN-TRANSPOSE-01/`. Производственный код и исходные рецепты не редактируются; это адресный companion текущего задания.

Если в исходной P-карточке вместо literal даты/ID стоят placeholders, правило префикса **не заполняет их и не делает рецепт READY**. Их обязан назначить автор конкретного опыта, вместе с его учебными данными/моделью/командой, до передачи runtime-исполнителю. Исходные P-варианты остаются каталогом. Существующий новый output также не очищается и не повторяется автоматически. Запись текущего документа или source review не требует создавать эти каталоги.
