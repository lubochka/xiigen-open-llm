## 2. Результат семантической проверки

У всех 125 P-карточек один и тот же обязательный раздел немедленного завершения, явно распространённый на **каждый подслучай и каждый промпт**. Он различает переход к следующей назначенной задаче и полную остановку, запрещает продолжение прежней задачи ради отчёта, hashes, review, Git или ещё одного запуска. Модель сессии по умолчанию также указана в обязательной оболочке карточек. Правило полезного выигрыша присутствует непосредственно во всех 133 коротких P-текстах.

| Проверяемое требование | Полная P-карточка с обязательными вставками | Только вырезанная короткая цитата |
|---|---|---|
| Немедленный NEXT без возвращения к прежнему оформлению | Есть для всех 125 карточек и их промптов | Нет самостоятельного STOP/NEXT-текста в 133 цитатах |
| Полный STOP, сохранность уже записанных результатов | Есть; допускается только необходимая остановка собственного работающего процесса | Теряется при передаче одной цитаты |
| Модель сессии по умолчанию, без выбора другой модели | Есть | В 133 цитатах самостоятельно не повторяется |
| Любое полезное измеренное улучшение — успех своей оси и домена | Есть | Есть во всех 133 |
| Рост accuracy необязателен; остальные изменения и ухудшения рядом | Есть | Есть во всех 133 |
| Связь с обучением либо использованием обученного состояния | Есть; нужен настоящий source → state → consumer | Также сформулирована в 133 цитатах, но не заменяет конкретный заполненный рецепт |
| Точные входы, проект, команды и бюджет | Задаются конкретной исполнительской карточкой назначенной строки | Справочная цитата сама их не создаёт |

Это **не отсутствие STOP/default/success в полном действующем тексте карточек**. Выявлен риск передачи: если передать только короткую цитату из нижнего раздела, обязательная оболочка потеряется. Такой фрагмент нельзя называть полным handoff.

Нельзя лечить этот риск повторным запуском или 133 дублирующими файлами. При передаче назначенного опыта прикладывается конкретная карточка целиком и приведённая ниже короткая оболочка. П-карточка вариантов не становится готовым runtime-рецептом от одного добавления оболочки.

## 4. Один дополнительный конфликт справочника

В [`experimets/03-metrics-and-reporting.md`, строка 3](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/03-metrics-and-reporting.md#L1-L7) актуализированная шапка всё ещё говорит: «Исполнитель сам выбирает и готовит опыт». Это противоречит уже назначенной очереди и требованию пользователя не заставлять модель искать другой эксперимент, проект, модель или путь.

Для будущей передачи применяется адресное уточнение:

> Исполнитель берёт уже назначенную строку действующего реестра и её конкретную карточку. Он не выбирает другой опыт, host, Student, данные или команду. Недостающий рецепт закрывает автор карточки; если конкретного необходимого артефакта нет, исполнитель фиксирует именно эту недостачу, сохраняя текущие результаты. Уже данное поручение продолжать программу не требует повторного разрешения каждого ID.

Защищённый файл здесь не редактируется. Поправка добавлена как правило передачи в новый пакет.

Новых содержательных пропусков STOP/default/useful-success в полных 125 P-карточках эта сверка не обнаружила. Конфликты P54, неправильного learner KH-COST и трёх устаревших внутренних номеров разобраны отдельно в [03](03-knn-units-and-domains.md), [05](05-card-protocol-and-conflicts.md), [06](06-P54-learned-reader-addendum.md) и [08](08-execution-registry.md); они не объявляются новыми находками этой проверки.

## 5. Обязательная короткая оболочка будущей передачи

Ниже готовый текст управления работой. Вместе с ним передаётся **целиком конкретная карточка назначенного опыта**, включая данные, исходники, команды, пути, бюджет, форму отчёта и текущий статус. Название карточки и номер не выбирает получатель. Оболочка не разрешает запуск в текущей документной сессии.

```text
Работай в уже назначенной фазе и по приложенной конкретной карточке целиком.
Модель исполнителя и последовательного проверяющего — модель их текущей
сессии по умолчанию, без model/reasoning override и поиска другой модели.
Student/Unit указан в карточке отдельно. Используй названные в ней навыки;
отчёт и кандидат исправления — по-русски по её готовому каркасу.

Порядок задаёт 08-execution-registry.md этого пакета. Защищённый
cards/00-execution-index.md на 0b76ab9 — базовая очередь, а 08 — её
явное добавочное уточнение. Сейчас 01–03 завершены, следующий 04 N62-R1.
Не повторяй завершённые опыты. Поручение выполнять или продолжать программу
уже включает её последующие назначенные строки; повторный допуск каждого
ID не нужен. Поручение одному ID само по себе не назначает всю программу.

В нынешнем задании только документируем: core и защищённый
docs/plans/replanning-possible-diffs только читаются; код и обучение не
запускаются. При уже порученной будущей runtime-фазе используй только
точную изолированную экспериментальную копию, путь и команды карточки.
Не ищи другой host, модель, данные или способ измерения. В минимальном
экспериментальном host допустимы throw/try-catch/void и простые DTO;
продуктовые требования не расширяют этот опыт до product/tests/CI.
Недостающий обязательный файл назови точно; не подменяй его симуляцией.

Проверяемый участок должен участвовать в обучении или использовании его
результата. Укажи настоящий source → writer/state → consumer и точный
исходный файл/метод. Reader-проверка обученного снимка может иметь ноль
новых Train; доказанный обученный снимок нельзя выдумать. Измерь назначенные
before/after отдельно по доменам. Любое фактически измеренное улучшение
полезного показателя — успех по этому показателю и домену; рост accuracy
не обязателен. Покажи остальные изменения и ухудшения рядом. Наблюдение
одного fixed-order замера не выдавай за доказанную причинность скорости.
Не добавляй вызовы, прогревы, контрольные повторы или полную цепочку ради
красивого отчёта. Сохраняй уже записанные raw и failed attempts, не удаляй
и не перезаписывай их. Обычный итог — русский отчёт и кандидат изменения;
production исправляет только отдельно порученная работа по решению Любы.

NEXT: на «заканчивай и переходи к следующему» немедленно прекрати прежнюю
задачу и перейди к уже названной следующей в разрешённой фазе. Если сказано
просто «следующий», возьми следующую строку реестра. Не дописывай прежний
отчёт, реестр или команды; не считай hashes, не проверяй Git/публикацию,
не делай ещё один review, build, run или «последнюю полезную проверку».
Не возвращайся к предыдущему опыту после перехода.

STOP: на «остановить всё», «стоп» или «закончить немедленно» прекрати всю
работу без следующего tool call, оформления или обновления памяти.
Допустимо только необходимое прекращение собственного уже работающего
процесса, чтобы он не продолжал обучение. Существующие файлы оставь как
есть; краткий статус сообщи только по известным фактам, без новой проверки.
Не подменяй NEXT полной остановкой программы, а STOP — новым запуском.
```

## 6. Граница этого дополнения

Эта оболочка решает потерю управляющих правил при передаче фрагмента. Она не заполняет отсутствующие датасеты, checkpoint, host или команды и не доказывает готовность всех подслучаев каталога. Для NG01 уже есть отдельные [карточка](cards/NG01-null-guard-label.md) и [полный промпт](prompts/NG01-executor.md); их STOP/NEXT, default-модель, метрики, путь и строка очереди записаны непосредственно в каждом файле. Прежние эксперименты и промпты сохранены.
