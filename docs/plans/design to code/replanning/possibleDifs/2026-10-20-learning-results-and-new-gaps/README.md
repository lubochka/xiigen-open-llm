## Главные выводы

1. **Первые три опыта уже завершены. Следующий — N62-R1, строка 04.** Ошибка Windows при старой попытке BPE не является его последним состоянием. Свежие результаты BPE и frozen-transpose содержат полезное уменьшение выделений памяти. N-KU-01 улучшает общий результат, одновременно ухудшая один необходимый класс. Это три кандидата для решения Любы, с разными ограничениями, а не поручение немедленно менять продукт. Источник: [действующий защищённый реестр](https://github.com/lubochka/llm_mvp_core/blob/0b76ab950d82534f5904005dda096545505ae307/docs/plans/replanning-possible-diffs/experimets/cards/00-execution-index.md) и [разбор raw](02-learning-measurement-audit.md).
2. **Нельзя объяснять всё отсутствием обучения.** В текущем DPO есть настоящий backward, LoRA и AdamW; одновременно успех исторического kNN на частях речи не доказывает способность случайно инициализированного нейронного Student писать C# или переводить. Различаются получатель обучения, представление, данные и способ проверки. См. [нейронный путь](04-neural-data-restore-audit.md) и [историю соседних веток](01-evidence-and-lineage.md).
3. **В защищённых карточках остались содержательные противоречия.** P54.1–P54.7 ошибочно исключают reader обученных maps, хотя он участвует и в оценке внутри `TrainStructuredBatchAsync`. KH-COST-01 в обязательной вводной называет `MethodKnn.Train`, а фактически проверяет `FileActionKnnPredictor.Train`. Здесь добавлены адресные исправления; защищённые тексты не переписаны. См. [протокол](05-card-protocol-and-conflicts.md), [P54](06-P54-learned-reader-addendum.md).
4. **NG01 — новый узкий проверяемый подслучай, а не повторное открытие всего семейства N48.** Условие `if (n is > 0)` над `int n` может ошибочно считаться null-защитой для другого receiver и портить учебную метку. Карточка изолирует этот фактор, сохраняет законные null/type/nullable-relational guards и вызывает настоящий native learner. Эффект пока не измерен. См. [карточку](cards/NG01-null-guard-label.md) и [промпт](prompts/NG01-executor.md).
5. **Проверка покрытия не даёт основания объявить все опыты готовыми.** Составлен пофайловый перечень всех 153 карточек и отдельно индекса; 125 P-семейств содержат 470 подслучаев. Наличие правил в шапке не устраняет противоречие в конкретном подслучае, отсутствие host не означает отсутствие рецепта, а `passed=false` в историческом JSON не отменяет полезную положительную дельту. Детали и пределы проверки: [источники и новизна](07-source-and-novelty-index.md), [инвентаризация](card-inventory.json).

**Правило результата:** любое измеренное улучшение полезного показателя — успех по этому показателю и домену. Рост accuracy для этого не обязателен. Все остальные измеренные изменения, в том числе ухудшения, публикуются рядом. Успех измерения и решение о переносе в продукт — разные решения.

**Правило немедленного перехода:** «заканчивай и переходи» немедленно прекращает работу над прошлым опытом. Не дописывать его отчёт, hashes, commit, review или проверку; перейти к названному следующему. «Остановить всё» прекращает все действия. Старые результаты не удалять.
