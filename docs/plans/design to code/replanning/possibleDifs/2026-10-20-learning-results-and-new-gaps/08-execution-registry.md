## Применить документные исправления до соответствующего ID

Внутренние старые номера в карточках читать по этому реестру: **KH-COST-01 —22→23 KH-EXT-01; KH-EXT-01 —23→24 GRADB-LOCALITY-01; GRADB-LOCALITY-01 —24→25 RMS-COORD-ALLOC-01**. Старое «конец очереди» в GRADB не действует.

При KH-COST-01 заменить ошибочную вводную `MethodKnn.Train` на **FileActionKnnPredictor.Train**, не добавлять второй learner. Для всех ID действует текущий успех по любому полезному показателю, default executor model, работа только в экспериментальной копии, русский report и запрет продолжать прошлую задачу после NEXT/STOP. Для №01–03 использовать существующие отчёты и [CANDIDATES](CANDIDATES.md), не запускать заново из-за обновления текста.

Фраза старого справочника «Исполнитель сам выбирает и готовит опыт» не меняет назначение: исполнитель берёт строку этого реестра и её полную карточку. Передача одного короткого P-промпта без обязательной оболочки недопустима; точный порядок передачи описан в [09-prompt-handoff-audit.md](09-prompt-handoff-audit.md).

## После прямого обучения: P54.1–P54.7

P54 относится к обученным maps и feedback, а не OUT_OF_LEARNING_SCOPE. Однако адресные missing fixtures/contracts из [06](06-P54-learned-reader-addendum.md) не надо угадывать. Это семь кандидатов следующего этапа в порядкеP54.1,P54.2,…,P54.7, **не семь уже готовых hosts**. При назначении конкретного подслучая использовать его exact consumer/fix и указанный обязательный вход. Если вход отсутствует, коротко записать `NEEDS_INPUT` с конкретным именем, сохранить partial state и следовать следующему прямо порученному пункту. Не назначать новые Train только ради формального статуса learning и не запускать инфраструктурные проверки вне causal path.

## Исполнение и пределы

Один исполнитель одновременно; агент использует текущую модель сессии по умолчанию. Source commit, trained model, данные, short path и команды берутся из указанной карточки. «Рецепт есть» не означает, что host уже создан или сборка проверена; реализуется только назначенный экспериментальный проект. Не начинать full product tests и правки production до измеренного результата и отдельного решения Любы о переносе.

Любое измеренное улучшение полезной метрики — успех по метрике и домену; accuracy не обязательна, ухудшения рядом. После обычного завершения — один русский report и кандидат в разрешённом файле, один readback. Старые results не удалять, failed run не перезаписывать.

**НЕМЕДЛЕННЫЙ NEXT/STOP:** «заканчивай и переходи» немедленно завершает работу над прошлым опытом — без отчёта, hashes, Git, review, rerun или финальной проверки — и переводит к явно названному ID/полю «Дальше». «Остановить всё» прекращает любые действия, включая следующий опыт и housekeeping. Это сильнее обычного checklist сохранения.
