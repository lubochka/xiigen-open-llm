## 0. Главное для читателя, без маркетинга про PASS

Факт RP01: 500 C# и 500 EN→RU пар, по 50 шагов, LoRA изменяется, но самостоятельное решение минипанели остаётся `0/3 → 0/3` и `0/4 → 0/4`. Сохранение checkpoint, прохождение теста, рост reward-margin или совпадение хешей не являются улучшением ответа. [RP01 recovery/code audit](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md).

Основная архитектурная развилка:
- **Neural RP01** `CodeDocumentationSimulationDpoExperiment → DpoExactPairMaterial (segmented-byte-BPE-v2) → DpoTrainer → Q/V LoRA → TextGenerator` на маленькой исходной B0. Это один настоящий trainable Student, но пока без подтверждённой новой semantic competence.
- **Historical structured learning** `SemanticTokenizer/ExecutorUnit/Verifier + syntax-aware/phrase-aware KNN, Replay, contextual dictionary` — другие owners, stores, metrics, consumers. В этом контуре уже зафиксированы узкие успехи. Их отсутствие в RP01 candidate *не доказывает*, что LoRA broken, но показывает потерянные **способы обучения и применения знаний**.

Оценивать должны **независимо**: закон/ответ, фактический маршрут, состояние до/после, new-source generalisation и retention, а не RAG-ярлык.

Важная методологическая поправка: `failed experiment` = отрицательное наблюдение **данной комбинации domain/feature/recipient/metric/tier**. Это НЕ доказательство, что его функция бесполезна вообще. Но обратное тоже верно: другой успешный Tier1/2 НЕ отменяет отрицательный Tier3. Для гипотезы «неудачная матрица → успешный KNN» нужны **первичный код двух механизмов, архивные receipt двух запусков и совпадение проверяемого закона/сопоставимая выборка**; в отсутствие второго receipt статус `HYPOTHESIS`.

## 3. Быстрый, честный causal order (не исправлять всё разом)

1. **Gate 0 — реальный маршрут/владелец.** Для каждого домена доказать `input → raw DPO pair → exact Tensor / structured Unit → optimizer or KNN index → saved state → ordinary consumer → judged output`. Каждому фрагменту присвоить `CODE_CONFIRMED` / `HISTORICAL_EXECUTED` / `PROXY_ONLY` / `QUALITY_NOT_RUN` / `NOT_WIRED`. Прежде всего не переносить generic TranslationBridge дефекты на RP01 exact-v2.
2. **Gate 1 — нейронный RP01:** без изменения весов проверить C0/C50/C100 first-token rank, forced common response prefix и свободный ответ; если база не умеет слова/форму — небольшая SFT проверка и finite-diff по Embedding, а не рост числа DPO шаблонов. Независимый DPO-authoring gate по законности pairs.
3. **Gate 2 — структурные получатели:** KNN correct law@1, learned tokenizer key parity, negation preservation, AST/order gated features, N38 replay pattern. Для C#, SQL и ENRU запускать разные условия и разные safety clauses; SQL parse tree ≠ Roslyn AST ≠ POS.
4. **Gate 3 — retention:** отложенная correction + 3 следующих разных легальных урока + cold fresh-process restore; измерить forgotten old law и learned new law. Наличие manifest на диске недостаточно.
5. **Gate 4 — итог и release:** CODEX/Astra independent review получает негативные controls, полный paired score + потерянные critical laws, SHA-code/source/teacher provenance и прожитый обычный consumer. Не использовать «green unit test» вместо обучения.

## 4. Неподменяемое распределение ролей DPO

- **«Человек, выбирающий, что учить»: CODEX с моделью Astra 6 UltraCode.** Выбирает домен, исходную ситуацию/case, цель, критерии успеха и legal source ДО создания DPO.
- **Создание обоих DPO ответов: реальная внешняя ОТКРЫТАЯ КИТАЙСКАЯ модель.** Она автор `chosen` и `rejected` (или двух кандидатов, из которых затем маркируют chosen/rejected). Разрешение/лицензия/версия/URI/revision/сведения о двух сторонах обязательны. Не маскировать `DeterministicGenerator` или Astra как китайского генератора. Если внешняя модель отсутствует, записать `NOT_EXECUTED`, не придумывать вызов.
- **Оценка качества DPO: независимый CODEX с Astra 6 UltraCode.** Проверяет обе стороны, контрастный закон, domain validity, no-answer-both-correct, no-answer-both-wrong, no-leakage; принимает/отклоняет до mutation. Для слепого after-training ответа другой независимый CODEX/Astra 6 UltraCode evaluation pass.
- **Нейронный Student** не имеет права сам себе выдавать semantic PASS по gradient/checkpoint; evaluation исключён из train examples.
