В историческом отчёте P127/attempt-0002 обнаружены **две точные ошибки**. Ресурсные числа в§13 принадлежат attempt-0001. В§15 p2 и h2 названы двумя экзаменационными строками, хотя в raw p2=TRAIN, h2=EXAM. Поправка153 содержит раздельные числа и SHA256 обоих metrics; исходные свидетельства сохранены.

В P115 найдено противоречие договора и кода, а не измеренная потеря точности: если producer уже превратил null в empty, более сильный hash не различит их. Текущие snapshot и память создаются совместно; подмена живого snapshot в этой работе не воспроизводилась. Предложенное исправление сохраняет допустимость null-output и использует существующий null-tag, не вводит новый отказ входа ради теста.

Для P127 проверенный обычный путь обучения/serving использует `TransformerEmbeddingKnnLogicalUnit`, а опыт — `KnnLogicalUnit` с BPE/predicate-признаками. Эти типы нельзя считать одним измеренным механизмом. Владелец105§5 должен назначить точный caller и одинаковый input-only encoder для Train/query; архитектурный выбор не подменяется ещё одним микроопытом без паспорта.

Общие договоры39/120 усилены на примере этих находок: каждое число связано с attempt/arm/phase/raw-key; TRAIN/EXAM и cold/warm не смешиваются; helper проверяется вместе с предшествующим producer. Это профилактика аналогичных ошибок других карточек, а не заявление о новом дефекте в каждой из них.

Проверка источников выполнена родителем и исследовательским субагентом `/root/post131_context_review`. Ни native PASS, ни полный аудит всех веток, ни полная повторная смысловая перечитка огромного набора навыков не заявляются. Правки действуют в живых карточках и owner-разделах, а не только в этом обзоре.
