## Вывод

Нынешние MASK, SFT-STATE, PAD и ORDER уже описывают реальные маленькие изменения обучения и правильно отделяют свои факторы. Они **PREPARABLE**, без общего approval blocker. Требуются конкретная подготовка штатного малого caller, верификация фактического начального состояния и наблюдения; отсутствие этих полей в Markdown не доказательство недоступности ресурса. Повторное личное подтверждение ID/SHA отменено [execution-policy20.10][policy]. Текущий результат этой работы — документы, не запуск программы.

Два пункта требуют строгого прочтения при исполнении: (1) current фазовый timer не наблюдает raw gradients, хотя N60 PAD предлагает такое измерение; (2) старые локальные ограничения ответа/serving/0-update в отдельных параграфах не могут отменить новое правило пользователя. Положительный полезный результат засчитывается именно по измеренной оси и домену; улучшение качества свободного ответа не требуется для ресурсного успеха настоящего обучения. Восстановление или consumer можно сравнивать на одном доказанно обученном состоянии, если назван original участок, связь с получателем и как его исправить; декоративное повторное обучение не нужно.

## Остаточные двусмысленности документации

**10 L:** фраза «результат отрицательный для гипотезы пользы, если ΔBA различается, но ответы не улучшаются» должна ограничиваться **пользой по ответам**. Она не может отменить measured improvement response NLL, retention, стоимости update или другой полезной оси. Исполнитель пишет отдельные результаты: «ответы не улучшились; CPU снизился; по CPU локальный успех». Хэши или только численное отличие BA полезную метрику сами не создают. Это interpretation repair действующего текста, а не новый эксперимент.

**Старые N59 statements в12/16/21:** общая новая policy20.10 разрешает реальные загрузку/restore/consumer, когда есть причинная связь с обученным результатом. Нельзя выводить OUT_OF_LEARNING_SCOPE только из слова serving/cold или количества0updates. В то же время чужая независимая score-таблица/синтетический operator не получает учебную связь автоматически от соседнего checkpoint. Для решения нужен конкретный writer/state/reader либо data-preparation→learner путь. Политика разрешает такую проверку, но не доказывает отсутствующий caller за исполнителя.

**Данные, шкала и четыре состояния:** для новых learning-factor опытов сохраняются A0/A1/B0/B1. Свободный ответ, chosen likelihood, rejected likelihood, DPO reward margin, retention и actual cost — разные показатели. Во время самого DPO шага logged reward — это разность log-prob policy/reference после умножения на Beta, а не качество текста. Ресурсный PAD не измеряет accuracy; не записывать отсутствующие ответы как0/4. Условные примеры «10→8» в карточках не перенесены в actuals.

## Новое дополнение, которого не было в проверенном каталоге

**N-HEAD-01:** выводить logits только для scored response positions после полного того же Transformer context. Исходники показывают полную LM-head проекцию до mask filtering. Новый фактор сохраняет общий T и отличается от уже внесённого PAD. Реальное участие — native Forward→exact masked log-probs→Backward→AdamW. Потенциальная экономия относится к actual update, не доказывает причину исходной RP01 accuracy. Существующий detached Gather нельзя использовать для реализации без gradient edge. Полный паспорт, original fix locations, модель/данные/метрики/промпт и ограниченная дедупликация есть в соседнем HEAD-документе.
