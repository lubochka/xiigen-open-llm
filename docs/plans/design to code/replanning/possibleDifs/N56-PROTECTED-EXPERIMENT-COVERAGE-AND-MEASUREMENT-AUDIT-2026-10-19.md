## Четыре обязательных состояния и честные измерения

Основной протокол защищённой папки правильно требует `A0=control before`, `A1=control after`, `B0=intervention before`, `B1=intervention after` и independent EXAM: см. [`01-method-and-report`](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/01-method-and-report.md). Для каждого конкретного N56-опыта обязательно сохранение начальных byte hashes, неизменных model config/rank/optimizer/randomness, frozen source family split, prompt/adapter/route IDs, обновлённых параметров **своего** получателя, own ordinary outputs и latency/VRAM/RAM. Никогда не переписывать параметры exam после первого ответа.

**Предметные метрики до/после**, одинаковый denominator и blind rubric:

- `correct/all`, `answered/all`, `correct/answered` (не подменять accuracy на удобный subset); `false-accepted/all`, `abstained/all`; число критических ошибок по классу/домену.
- `train state delta`, `trainer mutation calls`, `effective admitted pairs`, `source unique families`, `selected recipient`, `route`, `replay selected identities`; `loss`, `margin`, `gradient` **вспомогательные технические**, не заменяют правильный ответ.
- `wall/update`, `latency per own query`, prompt/BPE tokens and sequences, memory group peak, VRAM, checkpoint/index bytes; total/trainable neural layers и Unit/Flow depth отдельно. При smoke с 2 update не объявлять speedup без статистической репликации.
- `cold_restore` — отдельная проверка retention и consumer registration; холодный запуск без обучения не выдавать за after-training success. Если baseline не загружается (`B_FAIL_LOAD`), не записывать ему `0/N` в качестве semantic accuracy.

Для neural P10 mechanics с `dropout=0` численное совпадение не автоматически аттестует вариант `dropout>0`; но именно [RP01 generation-v1.json](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/config/code-documentation/generation-v1.json) задаёт `dropout=0`, поэтому гипотеза «dropout default .05 сломал наш RP01» на текущих данных **не подтверждается**.

## Обнаруженные пробелы в документировании экспериментов — без изменения protected каталога

**COVERAGE-GAP-N56-O1.** В прочитанных P34/P39/P81 отсутствует один и тот же `ProjectCurrent` producer, `BuildChosen/BuildRejected` шаблонные outputs, actual orchestration receiving Unit и контроль task execution. [Эксперимент O1](N56-THREE-FAST-ORCHESTRATION-AND-REPLAY-EXPERIMENTS-2026-10-19.md#o1). Новизна — конкретная source/consumer связь, не абстрактная опасность label echo.

**COVERAGE-GAP-N56-O2.** Нет явного опыта `raw float[]` vs `ToString("0.###")` в `ProjectCurrent` с gate достижимой коллизии полного model-visible prompt, с запретом считать разную только numeric SHA семантическим gain. [Эксперимент O2](N56-THREE-FAST-ORCHESTRATION-AND-REPLAY-EXPERIMENTS-2026-10-19.md#o2). Если compiler дает только целые values, закрыть как unreachable.

**COVERAGE-GAP-N56-O3.** P24/P48 не проверяют **именно** `ProjectAuthorizedReplay.Select(Prompt).Distinct` против кратности разрешенных feedback observations и weight downstream. [Эксперимент O3](N56-THREE-FAST-ORCHESTRATION-AND-REPLAY-EXPERIMENTS-2026-10-19.md#o3). Успех экономии без роста loss тоже допустимое полезное техническое улучшение; не требовать «выигрыша» там, где кратность не должна учитываться.

**DOC-PORTABILITY-GAP.** Например, [P10 L37–38](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/docs/plans/replanning-possible-diffs/experimets/cards/P10-composed-gradient.md#L35-L40), [P125 L22–24](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/docs/plans/replanning-possible-diffs/experimets/cards/P125-executor-memory-learning.md#L20-L26) и `06-findings-map` содержат ссылки на локальные `C:/Users/...` пути. Они могут работать лишь в авторской рабочей копии; remote Codex/CI worker не сможет обязательно dereference источник по ним. При запуске делайте explicit resolver `repo + branch SHA + relative path + line span + blob hash` через source-ledger, fail on missing, не угадывайте файл по названию. **Это пробел portability/evidence trace, не доказанный баг обучения**. Здесь запрещено чинить protected Markdown.

**REVIEW-BOUNDARY.** `01-method-and-report` корректно маркирует GOOD иллюстрации как «не измерено», а P125 имеет независимое native review. Для остальных выбранных P-карточек `READ_ONLY_RESEARCH; проект, не выполнено`, поэтому нельзя утверждать «experiments действительно измеряют before/after» — они **задают** такую схему, но результаты в большинстве отсутствуют. Исторические отчёты имеют собственные версии/shas и должны сверяться против своего exact source snapshot перед переносом в CURRENT.

## Независимая проверка качества карточки перед native исполнением

1. `CASE_ID`, домен как **учебная тема**, профиль языка и точный `TrainRecipient/Consumer`; provenance/branch+commit SHA. Для AST функций — C#; для EN→RU слово/order; не объявлять AST обязательным для языка.
2. Изолированное A→B в одном классе/методе; `A0=B0` по hash и own outputs там, где предполагается одинаковый cold start; EXAM sealed раньше TRAIN.
3. Для constructed invalid DPO/rejected не менять одновременно invalidity type, output length и writer model; иначе confounded.
4. Real train receipt: raw/admitted/derived/executed **source law count**, chosen/rejected semantic verification, target Unit id и mutation state hash. Из одной пары 3 derived signatures ≠ 3 независимых урока.
5. Реальный output ordinary Flow/TextGenerator, авторизированный scorer читает gold **после** сохранения native raw, report показывает каждый case и negative controls; disagreement between accuracy scalar и external panel не замалчивается.
6. History/cold version/import/target live consumption отдельно; reference, neural base, KNN memory и verifier отмечены independently. `PASS_SOURCE` ≠ `PASS_NATIVE` ≠ `QUALITY_GAIN`.

## Итог

**Честный вердикт:** общая защищённая экспериментальная методология и проверенные выборочные P-карточки **спроектированы в основном корректно**, native P125 действительно измерил до/после и прошёл независимую оценку со строгими ограничениями. Новые N56-O1/O2/O3 **не подтверждены исполненными экспериментами и не обнаружены в проверенных точечных protected карточках как готовые рецепты**; им назначены маленькие внешние (planning-only) протоколы. Полную гарантию «все возможные детали уже покрыты и каждый опыт правильно измерен» этот аудит давать не может.
