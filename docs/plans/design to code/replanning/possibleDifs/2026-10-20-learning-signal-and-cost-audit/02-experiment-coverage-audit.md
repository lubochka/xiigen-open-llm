### Обязательная симметричная классификация

| Класс | Достаточная связь с обучением | Что нельзя утверждать |
|---|---|---|
| TRAIN_UPDATE | Named native операция реально пишет веса, moments, merge table, memory/index или accepted lesson state; тот же owner/consumer читает результат | Сам вызов Train или изменение hash не доказывает полезный эффект |
| TRAIN_INPUT | Loader, tokenizer, annotation, admission или curriculum меняет действительный вход конкретного native update | Перестановка synthetic metadata без вызывающего trainer не обучающий опыт |
| LEARNED_OUTPUT | Загрузка, decoding, retrieval, composition, routing либо evaluator читает конкретное доказанно обученное состояние и влияет на доступность/смысл его результата | Новый frozen-reader эффект не новое приобретение способности и не LoRA repair |
| UNRELATED / OPEN_LINK | Нельзя предъявить указанную выше цепь; есть только формула, mock, generic registry, report-only scalar или неиспользуемый API | Нельзя добавлять декоративные два урока, чтобы замаскировать отсутствие связи |

Пункт 4 текущего пользователя прямо допускает загрузку данных и потребление результатов обучения, если указаны изменяемый original code и конкретная зависимость. Поэтому запрет «любой frozen/cold/serving без нового Train — OUT» в защищённом пакете **слишком широк**. Замороженное состояние допустимо для LEARNED_OUTPUT; оно должно иметь реальное происхождение, идентичность и достигнутый reader. Такие карточки идут после разблокирования настоящего обучения и новых учебных изменений, а не перед ними.

Обозначения в таблицах:

- **COND** — содержательный малый опыт есть; требуются указанные конкретные поля и native host. Это техническая готовность, а не новый запрос разрешения.
- **FIX_DESIGN** — постановку нужно исправить до интерпретируемого запуска.
- **RECLASSIFY** — blanket exclusion неверен при подтверждённом LEARNED_OUTPUT/TRAIN_INPUT пути.
- **OPEN** — настоящий recipient/caller/input contract ещё не установлен; не запускать похожий proxy.
- **N/A / FIXED / ARCHIVE** — соответственно неприменимо к данному пути, уже исправлено, историческое свидетельство.
- **ACQ** — acquisition/no-update контроль, отдельно от repair, где обучаются оба плеча.
- **DIAG** — аналитическое/компонентное наблюдение; не самостоятельный learning run без связи.

Любой фактически измеренный полезный выигрыш фиксируется как SUCCESS(metric, domain). Если одновременно хуже другая метрика, это одновременно SUCCESS первой и REGRESSION второй; не общий FAIL, скрывающий полезный результат. Неприменимость, неизвестные данные, отсутствие contrast, недостигнутая ветвь и нулевой измеренный эффект — разные состояния.

## 2. Приоритетные результаты аудита

### EA-01. Последняя N-KU-01 математически превращает оба KNN в константы

[R23:75–101][R23] задаёт четыре TRAIN rows и k=3:

- A: K1/K2/K4 = ADD_LOOP, K3 = ADD_METHOD.
- B: K1/K2/K3 = ADD_METHOD, K4 = ADD_LOOP.

Текущий [FileActionKnn.Predict:128–141][FileAction] берёт три ближайших и голосует по количеству. Среди **любых** трёх записей A есть минимум два ADD_LOOP; среди любых трёх B — минимум два ADD_METHOD. Поэтому после обучения A всегда выдаёт ADD_LOOP, B всегда ADD_METHOD независимо от cosine-вектора. Это строгий вывод из состава карточки и алгоритма, не выполненный эксперимент.

На EXAM карточки три завершённых обхода и один отсутствующий обход. Аналитически постобучающие ответы обязаны дать A1/4 и B3/4 по её узкому gold, тогда как balanced accuracy обеих констант = 1/2. Снижение false ADD_LOOP на завершённых обходах полезно по данной метрике; потеря recall отсутствующего обхода неизбежна. Но такой результат **не доказывает**, что таблица различает do/while либо вообще использует структуру запроса.

Минимальное исправление при сохранении production k3: шесть TRAIN rows — два do, два обычных завершённых обхода, два действительно отсутствующих обхода. Тогда в каждом плече не менее двух представителей каждого класса, и две константы уже не следуют из арифметики k. В обоих плечах тот же dataset, одно изменение DoStatement в Label, те же четыре EXAM; 2 facade Train, 12 source presentations, 16 facade queries. Не обещать эффект до настоящего extraction/Train/Predict. Альтернатива k1 в обеих ветвях — допустимый отдельный research profile, но это не буквальный production k3.

Приоритет: исправить постановку до исполнения N-KU-01. Novelty: общая проблема class imbalance E14 уже описана в planning 12-MATRIX-KNN-TRANSFER-PROVENANCE-AND-EVALUATION.md:21; новое здесь — доказанная константность **конкретной новой N60 панели**, а не новая общая идея majority baseline. Поиск performed только по доступному на момент проверки planning snapshot; полноту глобальной novelty определяет parent join.

В W/P pair-score является native outcome, даже если text decoder неизвестен; отсутствие Generate не превращать в нулевую accuracy.

## 7. Компактные исправленные карточки и исполнительские правила

### EA-KU-01-v2 — ссылка на единственную согласованную шестистрочную карточку

Окончательные TRAIN/EXAM, один DoStatement-фактор, native facade, бюджет и полный prompt находятся в [LF-01 / N-KU-01-R](01-new-findings-and-small-experiments.md). Это один рецепт; отдельный набор с тем же ID здесь не дублируется. Исходные 4/k=3 допустимы для узкого эффекта смены постоянного класса, но не доказывают структурное различение. В f5dd это ограничение уже явно признано.

### EA-LO-v1 — единое правило для загрузки и чтения обученного результата

**В каждую карточку и каждый prompt добавлять один и тот же смысл:**

«Назови класс вмешательства: TRAIN_UPDATE, TRAIN_INPUT, LEARNED_OUTPUT или UNRELATED/OPEN_LINK. Для TRAIN_UPDATE/TRAIN_INPUT покажи конкретные source data → native update → изменяемое state → reader. Для LEARNED_OUTPUT покажи реальное происхождение обученного state, immutable identity, loader/reader и точное место, где вмешательство меняет доступность или смысл результата. Новые учебные вызовы для frozen readout не обязательны. Они не должны добавляться декоративно; reader effect не переименовывается в улучшение optimizer или приобретение знания. Если dependency неизвестна, укажи точный missing caller, не запускай proxy. Любое измеренное улучшение полезной метрики — успех этой метрики и домена; рост accuracy не обязателен, ухудшения остальных показателей показываются рядом. Неизмеренное качество — NOT_MEASURED, не 0 и не unchanged. Обязательное масштабирование, тест-count gates и повторы до успеха не применяются. Работа с действительными training blockers и updates идёт раньше reader-only/общих проверок».

**Минимальная learned-output карточка на конкретном owner:** GDC-MULTI. Исходный state — реально полученный GDC-CAT checkpoint с positive contrast/overflow preferences, hash и training receipt. A — current BuildLocalImprovementPlan top1; B — все положительные совместимые правила только для этой пары дефектов. Четыре HTML/CSS GDC-CAT, 8 настоящих Improver.ExecuteAsync, 0 updates. Measure own code repairs/false edits/cost; source-only defects одинаковы, weights одинаковы. Исправление читателя обученных предпочтений законно по пользовательскому п.4; улучшенное обучение весов этим не заявляется. Если реальный checkpoint не существует, OPEN_STATE; не изготовлять его веса вручную.
