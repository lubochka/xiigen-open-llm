# Малые эксперименты: порядок, ресурсы и готовое задание исполнителю

**В этом пакете эксперименты спроектированы; новые native training/инференс не выполнены.** Выполнены только три семейства Python probes операций из исходников, с явными ограничениями в [evidence](evidence/README.md). Цель следующего шага — проверить один механизм на одном предмете обучения и обычном потребителе. Пакет не требует последовательного выполнения всех каталогов прежде первого полезного опыта.

## 1. Сначала восстановление, затем дополнительные гипотезы

P0–P5 ниже обозначают **ID опытов**, а не шесть уровней приоритета. Их полный протокол, источники и ограничения — [первая глава](00-EXTERNAL-DOMAINS-RECOVERY-FIRST.md). Начать с P0 в нужном домене; выбрать одну следующую строку по фактически обнаруженному разрыву.

| Опыт | Первый ограниченный объём | Что должно измениться | Чего такой объём не доказывает |
|---|---|---|---|
| P0: state → ordinary consumer → новый процесс | 8 запросов × 2 плеча × 2 состояния процесса = **32 обращения; 0 updates** | Прочитано нужное сохранённое знание, сохранён смысл ответа после cold load | Универсальную способность к новым задачам |
| P1: structural C# KNN | **32 TRAIN occurrences, 16 EXAM; 2 Train, 32 direct predictions** | Полезный выбор класса на общей панели и затем обычный consumer | Качество перевода, DPO или масштабирование |
| P2.1: learned POS order | E25 **128 TRAIN / 32 EXAM**, два 32-кейсных сравнения; отдельно 8 raw фраз | Классификация порядка, затем её реальное применение | Raw-text translation quality из одного gold-POS результата |
| P2.2: применение порядка | 7 E27 fixtures × 2 = **14 вызовов; 0 updates**; отдельно 8 raw фраз | Роли и порядок сохраняются | Что правильный императив обязан быть SVO |
| P3: contextual dictionary | 15 E26 fixtures × 2 = **30 вызовов; 0 DPO updates**; затем 8 новых контекстов | Правильное значение слова используется в ответе | Что заранее наполненный словарь научился из DPO |
| P4: место neural адаптации | 2 урока × 2 плеча = **4 updates**; 4 EXAM до/после по двум плечам = 16 ответов | Один target-set contrast меняет полезность свободного ответа | Что новый target set подходит всем базам/доменам |
| P5: полный resume | Один одинаковый следующий update в двух процессных плечах; **8 одинаковых запросов на каждое** | Непрерывное и восстановленное состояние имеют согласованное поведение | Что любой прежний FAIL E48 означал отсутствие ранней пользы |

Дополнительные native measurements, cold checks и расширения панелей в главе считаются отдельно. До их запуска исполнитель записывает конкретное число обращений и предельный бюджет; приведённые цифры — размеры первой стадии, а не выдуманные наблюдённые расходы PC. P4 начинает с одного полного policy state: существующие adapters остаются в forward обоих плеч, а различается trainable target set. Состояние оптимизатора по вновь разрешённым параметрам B задаётся явно; его нельзя молча объявить исторически восстановленным.

## 2. Быстрые проверки шести конкретных механизмов

| ID | Самая дешёвая стадия | Доменная стадия | Основной falsifier |
|---|---|---|---|
| [KU-01](02A-NEW-SEGMENT-AGGREGATION-GAP.md) | Native compiler + counting authority + aggregate; 2 составных и соответствующие одиночные prompts, 0 обучения | Один frozen trained authority; по 6 новых задач документации/кода, разные targets и same-target multi-segment отдельно | Actual producer не сегментирует либо selected host не подключает learned seam |
| [KU-02](02B-NEW-CANDIDATE-ELIGIBILITY-GAP.md) | Тот же edge с/без чужого registry target; снять raw scores и calls до inference | По 6 задач документации/кода/оркестрации, один checkpoint, 0 updates между вариантами registry | Global crossing не возникает либо сохранившийся кандидат не даёт правильного результата |
| [PT-01](03-NEW-PROMPT-PATTERN-GAPS.md) | Один accepted semantic duplicate, 4 запроса × 2 плеча × 2 процесса = 16 Translate, 0 updates | Сохранение реальных требований/запретов задания в API, одна предметная панель | Admission исключает повтор или matched A/B дают одинаковое корректное задание |
| [PT-02](03-NEW-PROMPT-PATTERN-GAPS.md) | 10 native fixtures × 2 = 20 Decide, 0 updates; 6 исходных + 4 дополнительных контроля | 4 новых запроса одного домена × 2 = 8 API обращений | Принятая память не использует признак или B теряет полезный смысл/recall |
| [AUT-WEIGHT-01](04-AUTONOMOUS-LEARNING-CONDITIONAL-GAPS.md) | 5 строк одного Domain; лог Weight на provider/PrepareBatch/executor и controls | 8 уроков × 2 плеча = 16 supervised предъявлений, replay одинаково отключён; 8 EXAM | Реальные weights≤1 либо update/output не отличается |
| [AUT-REPLAY-02](04-AUTONOMOUS-LEARNING-CONDITIONAL-GAPS.md) | Два цикла по 5 строк; artifact success, quality reject, затем membership2 | На панель: 2 плеча, одинаковые5 новых+2 replay во втором цикле; отдельные bad-lesson и good-undertrained панели | Отсутствует живой consumer/buffer либо promotion-gated B мешает полезным правильным урокам |

Для KU дополнительные учебные пары нужны **только если нет подходящего реально обученного authority**; это отдельная подготовка по карточке, не обязательное повторное обучение существующего checkpoint. Counting mock проверяет вызовы и сборку, не качество обучения. AUT-путь прежде всего должен быть найден в выбранном запуске: current source сообщает, что non-test composition root отсутствует. Не запускать его как «исправление RP01», пока такой причинной связи нет.

Для replay бюджет первой стадии обучения cohort и подготовки начальной старой памяти записывается отдельно от следующих семи предъявлений. В каждой семантической панели одинаковы число updates и позиции replay; фактические tokens и выбранные IDs раскрываются. Отрицательный материал диагностического контроля не становится автоматически одобренным положительным учебным corpus.

## 3. Контракт сравнения и критерий полезности

Зафиксировать до опыта commit, exact input/lesson IDs и bytes, subject/domain/direction, state hashes, feature/tokenizer/schema version, frozen reference, trainable target set, ordered curriculum/replay IDs, decoder и рубрику. Где поле неприменимо — записать `NOT_APPLICABLE`, а не добавлять фиктивный neural optimizer к dictionary/KNN проверке.

Главное измерение — **собственный ответ обычного потребителя по новому source-disjoint случаю**: правильность доменного закона, сохранение требований/ролей/отрицания, отсутствие критического нарушения. Для памяти отдельно считать exact seen, новый вариант известного закона и новый закон; `!ExactSourceHit` ещё не означает обобщения. Старый навык проверяется отдельными retention случаями.

У механического probe свой исход: изменился weight, shortlist, margin или source association. У доменной проверки свой исход: `IMPROVE`, `NO_GAIN`, `REGRESS`, `INCONCLUSIVE`, `INVALID_EVIDENCE`. Малый положительный сигнал выбирает следующий узкий опыт; он не удостоверяет восстановление всего обучения. Если реальный consumer отсутствует — `UNREACHABLE_IN_SELECTED_RUN`; это полезный результат маршрутизации исследования, не quality FAIL модели.

Минимальный отчёт содержит before/after ответы по каждому case, вмешательство, actual selected consumer, источник ответа, state delta, cold parity, win/loss/critical counts, teacher/judge/student calls и фактическое время/ресурсы. CPU/GPU peak и сумма пиков разных процессов — разные величины. Новые broad tests/CI, большие dataset sweeps и повторное обучение всей истории не нужны для source-only исследования.

## 4. Готовый текст следующего задания

Ниже текст для одной исследовательской реализации, а не выполненный run. Выбор урока и проверка пары соответствуют [RP01](../../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/README.md) и [replanning AGENTS](../../AGENTS.md). Фактическую версию модели и роли исполнитель пишет в receipt, не подменяя их названием из промпта.

> Выбери первый применимый recovery-опыт P0, затем одну из P1–P5 или один конкретный новый EXP из указанной карточки. Сначала прочитай её pinned source и установи реальный producer→learner/state→consumer в выбранном домене. Используй существующий сохранённый компетентный state; если его байтов нет, явно отдели поиск/реконструкцию от restore. Реализуй только указанное вмешательство B в изолированном исследовательском пути, сохраняя guards, provenance, доступные targets и полный исходный policy state. До первого update зафиксируй пары, split, порядок, параметры и оценочную рубрику. В новых DPO-парах CODEX с требуемой проектом Astra 6 ultracode выполняет отбор урока; допущенная внешняя открытая китайская модель создаёт обе стороны; отдельная оценка CODEX проверяет точную неизменённую пару. TIE/BOTH_BAD/UNJUDGEABLE не превращай в forced preference. Генератор не назначается автоматически судьёй. Исполни самый маленький контроль из карточки и измерь обычный ответ, retention и cold consumption. Сохрани все успехи, неудачи и фактические вызовы. Закончи конкретным вердиктом с per-case evidence и одним следующим действием. Не объявляй source proxy native обучением, переименование пары новым уроком, а hash/loss/count доказательством пользы.

Исполнитель не обязан восстанавливать смысл задания из десятков старых промптов: карточка, эта общая рамка и её прямые источники составляют ограниченный рабочий пакет. Правки core, обучение и promotion в текущем исследовательском commit не выполняются и не выдаются за завершённые действия.
