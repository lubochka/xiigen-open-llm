**Ветвление:** в `DesignToCode@8f20ce` непосредственно найден `27.TranslationDomain/TranslationTrainedUnits.cs` с `ExecutorUnit.TrainOnExample → _knnStore.AddPair` и E26 словарём; более ранняя `language_translate@f6032a` **не содержит** каталога `27.TranslationDomain` в проверенном дереве, но содержит сами эксперименты E25/E26/E35/E36/E40. Следовательно, говорить «в language_translate была та же готовая TranslationMachine» — неточность. Сравнивать программу нужно по branch+path+SHA, не только названиям.

### Самый короткий следующий маршрут экспериментов

**E-00: source/recipient identity, прежде чем менять код.** Для трёх настоящих следов (один успешный E25/E26 hybrid, один C# RP01, один ENRU RP01) зафиксировать `training material SHA → train API → trainable state key → checkpoint SHA → fresh reopened actual consumer → heldout answer`. Артефакт — три call-graph trace, с границами, где связь не доказана. Ноль новых model updates.

**E-01: отдельный bounded семантический пилот с зафиксированным законом.** Выполнить [MICRO-N26 Verifier polarity](26-MICRO-LEARNED-VERIFIER-POLARITY-EXPERIMENT-2026-10-16.md): 4 seed Unit rows, 16 frozen candidate texts, actual Verifier, wrongAccepted/correctAccepted. Это способ выяснить, реально ли learned law поменяет **качество принятого ответа** за одно короткое исполнение. Не подменять им доказательство влияния на RP01 TextGenerator.

**E-02: один RP01 consumer bridge без retraining** (только если E-00 обнаружил отсутствующий recipient). На заранее замороженных одних и тех же 8–16 semantic questions сравнить: `TextGenerator` как сейчас; legacy learned Unit непосредственно; фактический product consumer с законным retrieval/Unit маршрутом, если такой вообще предусмотрен дизайном. Зафиксировать идентичность source law, запрет gold/oracle answer leakage, собственно generated answer, independent judge и coverage. Не смешивать результаты: improvement of retrieval access ≠ improvement of neural weights. Если в ProductHost такого законного маршрута нет, verdict `ARCHITECTURAL_GAP` без имитации через вставку oracle текста в prompt.

**E-03: только затем один learning-factor ablation** по самой сильной подтверждённой деградации (например, baseline random B0 vs lawful pretrained base, либо visible-source prompt vs truncated-source prompt) с неизменными 8–16 blind tasks и frozen settings. Не менять одновременно warm base + LoRA rank + tokenizer + retrieval. Stop после одного различающего фактора; никаких повторных 500-pair Windows full-gates для выяснения научной причины.

### Чего нельзя заявлять

1. `passed:true` в E25/E26/E40V2 не доказывает обученный универсальный LLM: только точную метрику и данные соответствующего эксперимента.
2. `passed:false` в E13/E36 не перечёркивает поздние learned functions; tracing приоритетнее булевого вердикта.
3. Хорошая проверка весов LoRA и optimizer restore не доказывает семантически правильный свободный ответ.
4. `QualityVerifier` или `TranslationMachine` дефект **не** является автоматически причиной C#0/3/ENRU0/4, пока RP01 не вызывает этот recipient.
5. Данные разных веток, размеров валидации, доменов и decoder settings нельзя объединять одним процентом улучшения.
6. **Этот документ — сбор источников и приоритетов, не результаты нового native .NET запуска**; источник `llm_mvp_core/docs/plans/replanning-possible-diffs` оставлен полностью read-only.
