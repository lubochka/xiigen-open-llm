## Ответ на исходную проблему

У системы исторически были **разные виды обучения**. В одних опытах обучалась модель токенов и предпочтений, в других — lookup-память исправлений, KNN ближайших AST/семантических примеров, маршрутизаторы, словари фраз, верификаторы и граф зависимостей. **RP01 не воспроизводил весь гибрид**: его сохранённая кампания изменила q/v-LoRA у randomly initialized B0 (vocab629, hidden512, четыре слоя), но обычный свободный смысловой ответ не улучшился на маленьком опубликованном экзамене. Причины могут одновременно лежать в Student competence, objective, pair quality, feature representation и подключении обученной памяти к output consumer.

Источник текущего negative baseline: [RP01 recovery source audit](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md) и [Scientific DIAG](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-CAUSAL-LEARNING-DIAGNOSTIC-PACK.md). C#500 — 500 DPO records из 25 шаблонных families, 50 optimizer updates, 16 LoRA изменились, 39 base frozen, free correctness **0/3→0/3**. EN→RU500 continuation — ещё 50 updates по 500 записям 20 categories, free **0/4→0/4**. Изменение весов и likelihood margin не равно приобретению языкового умения.

## Дополнительное новое в этом проходе: E30 condition identity (NEW-26)

[NEW-26 source proof](26-NEW-E30-PREDICATE-CACHE-STATE-ALIAS-AND-MISREAD-2026-10-16.md) обнаружил **точный новый кандидат-урок**, не тот же generic KNN top1/metadata bug:
1. **NEW26.01** у всех transition одного C# файла одинаковый 22D whole-file predicate-frequency vec, но Next может зависеть от Current — условная информация уничтожена при обучении и inference.
2. **NEW26.02** PredicateCache.Lookup выбирает *первую* сохранённую метку при равном cosine; позднее исправление без более богатого адреса не побеждает.
3. **NEW26.03** E30V2 изменяет предмет и validation panel: вместо следующего AST-предиката классифицирует 8 NL classes. Его отдельный FAIL не опровергает возможный источник полезного KNN на исходном target.
4. **NEW26.04** whole-file frequency теряет порядок AST переходов — частный случай прежнего DIF-13, а не независимое открытие.

[Архив E30](https://github.com/lubochka/llm_mvp_core/blob/8c7d41611aecba98d3d1bbdbf30d69bd784949ae/35.ExperimentsV2/results/E30-PREDICATE-CACHE/results/run-2026-05-01-001.json): kNN cacheAcc **2.3%**, hit 46.4%, overall enhanced 16.67% при bigram baseline 32.25%. Исторический measured FAIL реальный; конкретный вклад потери Current **ещё не измерен**. Содержимое трёх E30 файлов проверено также на language_translate/DesignToCode/external_domains/orchestrator-extensions/main: тела методов эквивалентны после отброса license header. Это не доказывает, что другие ветки не содержат отдельной успешной реализации похожей функции.

**Быстрый опыт:** [MICRO-26 protocol](26-MICRO-E30-CONDITIONED-KNN-CAUSAL-EXPERIMENT-2026-10-16.md), [Python proxy](26-MICRO-E30-CONTEXT-IDENTITY-PROXY.py), [executed JSON](26-MICRO-E30-CONTEXT-IDENTITY-PROXY-RESULT.json). 12 синтетических heldout transitions: прежний first-hit 6/12, conditioned memory 12/12, label-corruption control 6/12; **не продуктовая точность и не .NET кодовый тест**. ## Какие эксперименты запускать первыми, чтобы вернуть реальное обучение

**Параллельные научные треки без общей ложной метрики:**

1. **Student viability:** [RP01 REC02/REC03](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/README.md): tiny 8–32 exact examples, проверка gradient, SFT warm-up + DPO vs DPO-only, matching tokens/time/cold reload, free semantic correctness. STOP before another 500 until Student learns even controlled baseline.
2. **Hybrid learning path:** [EXP01 Unit memory vs Student](11-EXP01-UNIT-MEMORY-IMPACT.md), [MICRO-25 POS memory](25-MICRO-E26-POS-CONTEXT-CAUSAL-EXPERIMENT-2026-10-16.md): тот же урок → trained Unit → new-family ordinary TranslationRoutingFlow; необходимо real changed answer.
3. **NEW-26 KNN context:** [MICRO-26](26-MICRO-E30-CONDITIONED-KNN-CAUSAL-EXPERIMENT-2026-10-16.md): пока отдельный E30 native experiment, **не** пытаться внедрить в RP01 DPO.
4. **Correct scoring/adoption:** [24 Tatoeba evaluator pilot](24-MICRO-TATOEBA-QUALITY-GATE-EXPERIMENT.md): перед promotion проверять смысл, а не совпадение подстрок.

Не менять одновременно learner, teacher, data, tokenizer, kNN features и scorer: тогда не будет причинной информации. Для победителя нужны **paired semantic correctness на blind источниках, precision плюс coverage, no regression на старых валидных ответах, cold-reload и actual consumer proof**, а не только saved weights/number of PASS.

## Роли, владелец, подтверждения

**Human selector / арбитр выбора: CODEX с GPT-6 Astra 6 UltraCode.** Он выбирает задачу, law, адрес learner, accepted goals, границы train/test. **Teacher DPO: внешняя лицензированная открытая китайская модель**, она создаёт обе стороны chosen/rejected и записывает фактические version/provider/license/source IDs. **Независимая оценка качества DPO: отдельный CODEX с GPT-6 Astra 6 UltraCode** проверяет смысл и отсутствие запрещённых/обратных меток каждой пары перед admission. **Blinded trained-output evaluator:** CODEX/Astra 6 UltraCode отдельно проверяет ordinary Student/Unit on new families, с неизменными тайными answers. Не выдавать ручной Python proxy или другие синтетические имитации за actual Chinese teacher или CODEX judge.

**Применённые Skills:** [архитектурный аудит](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/human-readable-architecture-audit-SKILL.md), [планирование](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/phase-planning-SKILL.md), [review плана](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/plan-review-SKILL.md), [code review](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/code-examination-SKILL.md), [промпты](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/prompt-patch-authoring-SKILL.md), [human communication](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/conversation-intent-and-self-reflection-SKILL.md), [verification](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/skills/claim-verification-SKILL.md). ## Independent plan-review / stop conditions

- **Overclaim forbidden:** архивные E09/E14/E25/E40/Units не объявлять эквивалентными trained B0-LoRA без shared consumer, same-panel and same target. Часть historical positive papers имеют ограниченные split/denominators.
- **No fake novel claim:** NEW26 — конкретный source-specific E30 механизм, но не «единственный ранее никем не замеченный дефект» без exhaustive text search, не точный пользовательский migration commit matrix→KNN.
- **No hidden deterministic authority:** first wins или static fallback не может считаться обученным арбитром, даже если увеличил «количество попаданий»; сохранить видимость собственных weights/neighbours/reason.
- **No quality win from toy:** 6/12→12/12 показывает только алгебраическую неидентифицируемость на одинаковых обучающих переходах; семейства повторяются и сама proxy не вызывает .NET.
- **No wrong edit boundary:** ни один файл защищённого core/docs/plans/replanning-possible-diffs не разрешён к записи и не изменён этой серией.
- **Real next implementation slice:** если native E30 B−A на blind families не положителен, STOP/INCONCLUSIVE; если положителен, trace existing consumption before one specific RP02 kNN feature patch, independent reviewer, narrow native replay, then ordinary consumer evaluation.

**Итог:** узкая новая находка source-backed и cheap proxy воспроизводима; **причины полного ухудшения RP01 и восстановление качества не подтверждены**. У проекта есть проверяемая программа малых A/B, которая разделяет learning signals по их настоящим получателям.
