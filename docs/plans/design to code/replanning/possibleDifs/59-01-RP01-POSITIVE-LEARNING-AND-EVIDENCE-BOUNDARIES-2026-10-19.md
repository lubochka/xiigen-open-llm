# N59 — RP01: доказательства положительного обучения и границы причинных выводов
**Дата:** 2026-10-19. **Статус:** независимый source/receipt audit; новые learning runs = 0; причина нулевого улучшения RP01 = NOT_PROVEN. **Назначение:** `xiigen-planning/.../possibleDifs`. `llm_mvp_core/docs/plans/replanning-possible-diffs/**` — READ ONLY. Коммиты/файлы protected не менялись.

## 1. Результат для человека
Вопрос не сводится к «DPO работает/не работает». Существуют **успешное обучение памяти**, **исторические полезные kNN-алгоритмы** и отдельный **неуспешный в предметном поведении LoRA/DPO RP01**. Нельзя использовать случайный B0/неполный DPO в качестве опровержения успешного memory-learning; нельзя объявлять рост margin успехом перевода. Следующая проверка должна сравнивать *изменяемое учебное состояние и ответы обычного потребителя* по конкретной теме, а не чисто тестировать формулу retrieval.

Принятые ответы **12/24→22/24**, correct/accepted **11/12→19/22**, **wrong accepted 1→3**; 5 edge-cases не стали верными, включая отрицание и вопрос. Рост полезен **по качеству комбинации и доле отвеченных**, но обнаружена цена по wrong accepted, а одиночное измерение latency/RAM не подтверждает стабильного ускорения. Это **learning memory**, не обучение нейронного `DpoTrainer`.
2. **RP01 не восстановил semantic free-generation** — [RP01 recovery/code audit](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/design%20to%20code%20session/replanning/Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md): C# preferences 16/25→16/25, own answers 0/3→0/3; EN→RU preferences 12/20→12/20, own 0/4→0/4. ## 4. Не переписывать историю
- Считать полезным **любой реально измеренный рост полезного показателя по предметной теме**: качество, coverage, скорость, RAM/VRAM, учебные примеры до навыка, труд, latency, полнота сохранённой памяти. Accuracy увеличиваться не обязана. Рядом — *все* изменившиеся и ухудшившиеся оси. Статистическую неопределённость и доменные границы отражать, но не ставить произвольную квоту прироста.
- Как «эксперимент влияния на обучение» принимать только A/B, где named `Student/Unit/Flow/memory` действительно обучается на сопоставимом материале, выбранное отличие достигает его состояния или правила обновления, а затем измеряется **его собственное** поведение до/после (при необходимости cold restore). Проверка лишь логики скоринга, теста, отчётной метрики, симуляции или oracle — полезный debug **не эксперимент улучшения обучения**.
- При fixed retrieval policy без нового урока назвать это «эффект inference/selection на использование ранее обученной памяти», а не «более качественное обучение». Если учебные материалы не доходят до рассматриваемого получателя — `INVALID_FOR_LEARNING_CLAIM`, никаких новых дорогих прогонов.
- Не удалять/не подстраивать false accepts 18.10, неполные результаты, frozen E22/E40V2 или отрицательный RP01.
