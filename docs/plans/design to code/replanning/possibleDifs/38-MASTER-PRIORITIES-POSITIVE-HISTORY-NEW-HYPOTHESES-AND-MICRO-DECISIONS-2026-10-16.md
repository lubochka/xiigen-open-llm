## 1. Какой факт должен изменить план

Сохранённая [диагностика RP01](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md): случайный 4-layer Student/B0 с vocab 629, hidden 512 и q/v LoRA rank8 прошёл C#500 за 50 шагов, затем EN→RU500 за ещё 50; весовые файлы/LoRA изменились, но свободная генерация **C# 0/3→0/3, EN→RU 0/4→0/4**. Увеличение DPO margin не доказало способность отвечать на законные незнакомые вопросы. **Утверждение «сам KNN плох, раз RP01 не отвечает» неверно**, поскольку RP01 Student и обучаемые Unit/KNN — разные владельцы состояния и разные пути выдачи текста.

И обратное тоже неверно: архивные PASSED на узких структурных/lookup-пробах не доказывают качество нейронного Student. Следующая работа должна диагностировать, **что реально обучилось, куда попало и кто выдаёт ответ**, а не прогонять чужие Windows CI, затем подгонять test cases под схему.

## 4. Где применимы KNN-признаки, а где ими можно ухудшить ответ

| Признак / метод | C# / AST / code-action | EN↔RU | HE↔EN | SQL / DSL |
|---|---|---|---|---|
| Точное дерево: SyntaxKind, parent, sibling, scope, operator order | **Сильный кандидат**, если Roslyn AST доступен и семантический law сопоставим | **Не Roslyn**, нужен linguistic parser/tagger | Не переносить C# tree | Только SQL AST, другой парсер и функции |
| Порядок слов, отрицание, субъект, tense, POS left/right | Важны operator/order/type; natural POS недостаточно | **Сильный кандидат**, особенно «не», глагольная форма, субъект | **Сильный кандидат** при морфологии и направленности | Boolean operators/NULL semantics как typed syntax |
| Bag-of-words / hashed token IDs / generic cosine | Хороший дешёвый candidate generator, **не** финальный арбитр закона | Может удалить отрицание/субъект, требовать guard | Нужен script/language separation | Может слить =/!= и AND/OR |
| Latest feedback, typed source version, negative memory, confidence calibration | Существенны для correction/code law | Существенны, обязательна языковая направленность | Существенны | Существенны, не принимать опасную неверную команду |
| Только neural DPO free generation | Требует language/code base; не заменяет compiler oracle | Требует обученную language base и quality judge | Нет доказательства RP01-тренировки | Нет доказательства RP01-тренировки |

Это **матрица задач**, не заявление, что AST или POS всегда эффективны. У каждого «сильного кандидата» требуется одной осью проверить прирост на **замороженной**, *другой* family panel и отсутствие law regressions.

## 5. Порядок самых дешёвых решений — без git/windows-run loops

1. **R0 / теперь:** [MICRO-38-A](38-MICRO-COUNTERFACTUAL-CONDITIONING-EXPERIMENT-2026-10-16.md) только B0/C50, 6 frozen diagnostic C# contrasts и одной source-disjoint panel. **Ноль новых optimizer steps**; отделяет «нет conditional ability» от «декодер не извлекает learned ability».
2. **R1:** one-pair native gradient/LoRA probe и tiny SFT vs DPO warm-start **лишь если** R0 не показал способность; без долгой подготовки тестовой инфраструктуры.
3. **R2:** воспроизвести [N78 restored memory](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/78-translation-restored-memory-positive-receipt.md) с before/after **нового** safe-002 и контрастом предметного закона; восстановить соответствующее Unit state, затем обычный adapter. Отдельно сохранить source language и объяснить, что оригинальный probe использовал English source при RU_EN label.
4. **R3:** на действительно сохранившихся E09/E14/branch artifacts сначала выполнить [N38-B split audit](38-NEW-E09-WITHIN-FILE-HOLDOUT-LEAKAGE-2026-10-16.md), затем matched E09 baseline/knn panel и old/new semantic label codec. Не повторять 45.33% как уже обоснованный quality gain.
5. **R4:** доменные one-factor проверки POS, negation, AST, retrieval order и verifier на фиксированных learned histories. Каждая должна возвращать **law-correct normal output**, не лишь попадание neighbor в top-k.
6. **R5:** только для гипотез, изменивших independent heldout correctness, расширять corpus/steps/domains; обычный local smoke для ошибок ввода, формата, сохранения. CI/windows integration gates — после полезного обучения, не как его замена.

**Stop/Go:** GREEN для нейронного научного milestone = хотя бы один правильный новый full-answer от истинно обученного Student, подтверждённый paired pre/post + независимым oracle, затем воспроизведён после cold restore. GREEN для Unit/KNN = правильный новый, не exact-source law case + сохранение старого закона, independent gold и нормальный consumer после restore. **GREEN тестового runner без этого — НЕ acceptance.**
