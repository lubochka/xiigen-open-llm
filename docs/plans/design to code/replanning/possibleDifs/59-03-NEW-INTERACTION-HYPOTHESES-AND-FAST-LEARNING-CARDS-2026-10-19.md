## Общее правило для КАЖДОЙ карточки и КАЖДОГО промпта
**Любое фактически измеренное улучшение полезного показателя считается успехом по этому показателю и предметной теме. Рост accuracy необязателен. Отчёт обязан рядом показать ухудшения и изменения остальных измеренных показателей.** Успех в скорости, памяти, шагах, количестве учебных примеров, покрытии, correct/answered и пр. локален. Изменение названия метрики не становится улучшением. Если измерение не участвует в настоящем учебном состоянии/caller/обычном consumer, это **НЕВАЛИДНЫЙ ЭКСПЕРИМЕНТ ПО УЛУЧШЕНИЮ ОБУЧЕНИЯ, НА НЕГО ЗАПРЕЩЕНО ТРАТИТЬ ТОКЕНЫ**. Результаты code-only diagnostics и frozen inference должны иметь отдельную метку и не запускаться вместо user task.

### Карточка N59-L01 — Короткий второй учебный шаг после успешного EN→RU 8-lesson composition (VALID design)
**Тема:** перевод; профиль EN→RU (RU→EN — отдельный future profile при собственном owner). **Получатель:** существующий `TranslationMachine.TrainStructuredBatchAsync` → `ExecutorUnit.TrainOnExample` (`word/phrase/exact/kNN` memory) → `GetOrchestratorAsync().RunAsync`, *не* Student DPO/LoRA. **Source:** [18-Oct raw results](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/results/2026-10-18/translation-memory-ingress-01/report.md); [TrainOnExample](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/27.TranslationDomain/TranslationTrainedUnits.cs#L403-L456); P125/P55/P54. **Гипотеза:** новое обучение операторам может сохранить 8 recombinations и уменьшить critical wrong-accepted; альтернативно снизит coverage или исказит старое знание. **Важный контрпример 18.10:** `do not delete the file` был принят как `удали файл`; `did you delete the file` — как императив. Эти exact тестовые фразы **НЕ включать в TRAIN**.

**Начальное state B0:** cold fresh machine, одинаковый approved 8-lesson training corpus/mapper, checkpoint hash, одна общая frozen оценочная панель. **A0=B0:** без уроков; **A1=B1:** после 8 одинаковых уроков. Следующий равный учебный бюджет 2 дополнительных урока:
- **A2 control:** две дополнительные безопасные утвердительные пары того же размера (контроль эффекта «ещё 2 урока»), с проверенным допустимым `chosen` и валидными phrase mappings.
- **B2 intervention:** две допустимые *другие* пары, обучающие отношения `do not + verb` (запрет) и `did you + verb` (прошедший вопрос), с explicit teacher-approved phrase mappings, не совпадающие целиком с EXAM. В обоих плечах один `TrainStructuredBatchAsync`, одинаковое число examples/phase, same owner, *никакого hardcoded verifier/guard/routing change*. Это contrast учебного **содержания**, а не «исправления внешнего кода».
- **EXAM** до запуска фиксировать: старые 8 exact+8 recombinations; критический not-delete с новым object, did-you-validate с новым object, нейтральные вопросы/отрицания, completely unknown verb, content-fragment conjunction. Каждый semantic source-family disjoint с EXTRA TRAIN; никаких gold labels в `ExecutorOutput`/selector для EXAM. Пусть правка слова не даёт 100% — отсутствие переноса тоже результат.
- **Контроли:** frozen state без EXTRA, separately shuffled targets/phrases в изолированной копии если допустимо, `do not`/positive и `did you`/imperative pairs, направление/TopicDomain фиксированы, стабильный independent semantic judge. Для unknown допускается корректный abstain вместо ложного уверенного ответа.
- **Наблюдение:** real unit state delta (exact/phrase/word/index entries), selected adapter/reason/evidence, actual Flow output до/после A0/A1/A2 и B0/B1/B2, cold-import spot check; считать gained/lost correct, operator-preservation, correct/all, correct/accepted, coverage, wrong-accepted, training sec/2 lessons, per-query latency, RAM, checkpoint/index bytes; число trainable neural layers = 0, число фактических Unit/Flow и исполненных уровней отдельно. Отдельно стоимость **ручной подготовки mappings** — это teacher supervision, её нельзя выдать за автономно выведенные alignment laws.
- **Возможный вывод:** B2 уменьшил wrong accepted с 3 до 1 без роста total accuracy → **успех safety/polarity**; если A2 быстрее/меньше RAM → **локальный успех этих осей**, даже при худшем semantic score, оба эффекта показать. **Не записывать придуманные числа как измеренные**. Прежние 8/8 positive combinations — отдельная retention bucket.

**Промпт исполнителю N59-L01 (future, не разрешение на запуск):**
> Перед любыми действиями получить отдельное явное разрешение на точную версию опыта. Найди current owner и provenance этих 8 уроков в P125/report. Реально обучи две одинаковые из B0 памяти существующим `TrainStructuredBatchAsync`, затем вторым A/B пакетом по 2 разным *учебным* lessons; frozen EXAM и normal `RunAsync` без подставленных expected. Запиши raw states/answers A0,A1,A2,B0,B1,B2, gained/lost, false accepted, latency/RAM/bytes, manual alignment work. Не смешивай Code/Verifier policy changes с уроками. **Любое измеренное улучшение полезной метрики — успех этой оси и темы, accuracy не обязана расти; прочие оси и ухудшения показывай рядом.** Если второй lesson не изменил названную memory или ordinary consumer обошёл получателя — эксперимент invalid for learning; stop, не трать токены.

**Статус:** native NOT_RUN. **Приёмка:** same source/input hashes, independent train/exam, actual memory mutation, real output; no win quota, exact controller trace.

### Карточка N59-L02 — Accepted→feedback→replay poisoning, только после обнаружения РЕАЛЬНОГО consumer (CONDITIONAL / BLOCKED)
**Тема:** перевод; профиль EN→RU; **потенциальный** получатель — durable feedback TrainingExample/DPo pair → реальный downstream memory/DPO trainer → ordinary consumer. **Верифицированный source-scope:** [`FeedbackRouter.RouteAccepted`](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/14.ContinuousLearning/Feedback/FeedbackRouter.cs) получает `FeedbackSignal.Accepted` и сохраняет положительный TrainingExample из `ModelResponse`; EDITED имеет другой механизм. **НЕ найдено свидетельств**, что `TranslationRoutingFlow` сам посылает такой `FeedbackSignal` или что эти examples автоматически доходят до same translation `ExecutorUnit`. **Следовательно запуск запрещён, пока нет source trace этих связей.**

**Гипотеза:** выросшая доля accepted после полезного обучения (12→22/24) вместе с wrong accepted (1→3) **может** увеличить вред от ошибочной будущей обратной связи, **если** отдельное приложение принимает каждый accepted answer за позитивный user signal. Это не утверждение о нынешнем продукте. Важнейшее отличие: машинный `confidence/accepted` **≠** пользовательское `FeedbackSignal.Accepted`; не симулировать связь по сходству названий.

**План только ПОСЛЕ consumer evidence:** подготовить две одинаковые уже-обученные 8-lesson памяти. A: human-verified true feedback на один нового материала; B: в действительном user feedback/trainer route допущен один ошибочный accepted output из observable false acceptance, только в разрешённой изоляции, зафиксирована настоящая provenance. Второй шаг настоящего `Train*`/DPO с реальной admission в обоих плечах, raw state/cold, один heldout с сохранением negation и старого навыка. Сравнить lost/gained, число учебных событий до полезного навыка, bytes, RAM, latency, accepted errors. Contamination не должна идти на production/user resources. Без real dispatcher и trainer owner **INVALID_LEARNING**, не тратить токены.

**Промпт исполнителю N59-L02:** 
> Сначала source-only найдите **конкретный** путь `TranslationFlow output → explicit user FeedbackEvent → FeedbackRouter → persisted accepted TrainingExample → actual training consumer of SAME state → ordinary Flow`. Если любого ребра нет, отчёт `BLOCKED_NOT_APPLICABLE` с точными файлами; обучение/прокси не запускайте. Только после отдельного разрешения сравните реальные A/B учебные обновления и собственные ответы, не синтезируйте user acceptance. **Любой полезный измеренный gain — успех по этой оси и теме, accuracy не обязательна, все ухудшения рядом.** Нет настоящего обучения — опыт невалиден; не тратьте токены.

### Карточка N59-L03 — Scheduler `DidRun` vs actual learning-state receipt (SOURCE CONFIRMATION, NO RUN)
**Тема:** может относиться к нескольким предметным темам, конкретная **не установлена**; **потенциальный** получатель — реальный scheduled `IncrementalTrainer`/`ExecutorUnit` по определённому domain. `LearningEventScheduler.DrainIfIdle` [L44–53](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/21.AgentInfrastructure/Loop/LearningEventScheduler.cs#L44-L53) возвращает `DidRun=true` после **очистки очереди и выдачи событий**, не после optimizer/Train step. **Это прямой source fact.** Caller, ошибочно учитывающий это как `LearningCompleted`, **не подтверждён**. Риск — `did release events` перепутан с `did train` и переданные события без update зря улучшают отчёт.

**Никакого бессмысленного Pseudo-A/B на `DidRun`!** Сначала source-only найти `DrainIfIdle` call site → actual trainer → stored update identity; если прямой цепи нет, `NOT_APPLICABLE` для RP01 и stop. При установленной цепи future A/B — один одинаковый batch + idle/on/off при **одинаковых дошедших и допущенных уроках**, снять real trainer receipt/optimizer delta/own output, а не просто boolean `DidRun`. Если никакое обучение не меняется, этот опыт — observability bug, а **не** learning-quality A/B.

**Промпт исполнителю N59-L03:**
> Только source trace до настоящего recipient; `DidRun` из очереди не является measured training gain. Не запускайте tests/simulators/training, пока отсутствует достижимый callback. Реальные улучшения полезных показателей учитывать даже без роста accuracy, со всеми ухудшениями рядом; изменение надписи «DidRun» само по себе не считается улучшением обучающейся системы.

### Карточка N59-L04 — Проверка узкого AST-aware kNN *внутри* обучаемой памяти, не универсальный фильтр (CONDITIONAL)
**Тема:** программирование/SQL, профили C# структурные правила и SQL; отдельные translation profiles только для word-order/role, **не C# AST**. **Получатель:** existing `KnnLogicalUnit.Train`/named learned index + ordinary `ExecuteAsync`, если caller структурной задачи реально использует именно его. [Generic KnnLogicalUnit source](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/21.AgentInfrastructure/Logical/KnnLogicalUnit.cs), related [P16](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/cards/P16-semantic-order-roles.md), [P26](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/cards/P26-structural-features.md), [P113](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/cards/P113-feature-energy.md). **Not new discovery:** hashed bag features lose order; **new proposed joint contrast:** one learned memory supports a domain-specific structural channel with negative-controls in nonstructural translation, instead of selecting universal feature weights.

**A0/B0:** empty memory, same 8 source/gold examples. **A1:** train ordinary hashed content+pseudo predicates. **B1:** train same 8 labeled examples with an **explicit domain-qualified** token-order/AST feature channel, query+index schema same version; change only representation, no oracle from TEST. EXAM: C# `if (x==null) return` vs `if (x!=null) return`, SQL `WHERE a>=10` vs `WHERE a>10`; roles/null/ordering, label-shuffled and entity-renamed controls; translation data only negative control to show AST channel does not apply. **Must prove actual AST owner/projection and ordinary product caller first**; otherwise blocked, no synthetic kNN replacing current code. Real same memory before/after and normal output plus latency, memory, learning examples, gains/losses; conditional cold.
**Промпт исполнителю N59-L04:** 
> Прежде подтвердите native Unit recipient и что оба embeddings/indexes реально строятся из тех же учебных examples. Контроль AST parsed из TRAIN/входа, не из EXAM labels. Сравните A0/A1/B0/B1 на реальном `ExecuteAsync` с честным train/exam split и domain scope; не распространяйте C# AST policy на перевод без доказательств. **Любое полезное улучшение метрики считается успехом для выбранной предметной темы без обязательного роста accuracy; все tradeoffs рядом.** Если нет реального обучаемого состояния/consumer, stop: невалидный learning experiment.
