# MICRO-N39 — два BPE одного V, один DPO pair: self-validity vs identity загруженной модели

**16.10.2026 · TEST DESIGN, NO NATIVE EXECUTION / NO PRODUCT MUTATION.** Только `xiigen-planning/llm_plan3/.../possibleDifs`. Protected core research остаётся только для чтения. Этот micro не исправляет случайную базовую B0, EOS, KNN, teacher или LoRA — проверяется **одна** модельно-токенизаторная идентичность exact DPO.

## Tier 0: воспроизводимый native .NET invariant test без разрешения на обучение

Прочитать source [DpoExactPairMaterial:CreateBatch/Validate](https://github.com/lubochka/llm_mvp_core/blob/d1862939bfe24c3bbeb12a49af917c7ca569a10f/11.DPO/Models/DpoExactPairMaterial.cs#L64-L145), [DpoTrainer.CaptureBatch](https://github.com/lubochka/llm_mvp_core/blob/d1862939bfe24c3bbeb12a49af917c7ca569a10f/11.DPO/DpoTrainer.cs#L991-L1000), [BpeTokenizer.Train/ComputeStateSha256](https://github.com/lubochka/llm_mvp_core/blob/d1862939bfe24c3bbeb12a49af917c7ca569a10f/01.Tokenizer/BpeTokenizer.cs#L34-L130).

Test-only in-memory objects (no file write into product docs, no optimizer, no model mutation):

1. `A = new BpeTokenizer(); A.Train("abababab abababab", vocabSize:258)`; `B = new BpeTokenizer(); B.Train("xyxyxyxy xyxyxyxy", vocabSize:258)`. Проверить exact actual `A.VocabSize == B.VocabSize` (если не равно 258, скорректировать *только корпус fixture* до двух merges и задокументировать это), `shaA != shaB`. Принципиально: V совпадает, артефакты — нет.
2. Проверить 3+ строки (`"abab"`, `"xyxy"`, `"abxy"`). Assert: `DecodeA(EncodeA(s)) == s` и `DecodeB(EncodeB(s)) == s`; хотя бы для одной s token-ID sequences различаются. Зафиксировать выбранную строку ДО просмотра качества.
3. Создать одну **легально типизированную** admitted pair `prompt="Write a short rule about abab"`, `chosen="abab correct"`, `rejected="abab wrong"` через существующий тестовый trusted producer. Выбор `chosen/rejected` в этом **механическом fixture** не является созданием нового real learning DPO и не должен маркироваться model-author Chinese. В реальном эксперименте новый DPO создаёт внешняя открытая китайская модель.
4. Создать `materialB = DpoExactPairMaterial.CreateBatch(B, prompt, chosen, rejected, admission)` — из in-repo friend-test assembly либо через существующий trusted test builder. Зафиксировать `materialB.ExactMaterial.TokenizerSha256 == shaB`, токены и self-digest.
5. Негативный контракт: `CaptureAndValidate(materialB, A.VocabSize, 128)` **ожидаемо не откажет из-за tokenizer mismatch**, если sequence/context сами валидны. Тот же вызов с именованным `expectedTokenizerSha256: shaA` должен отказать с `DPO_EXACT_MATERIAL_INVALID`. Контроль `expectedTokenizerSha256: shaB` должен пройти.
6. Отдельно проверить `DpoExecutionProfile.Capture / Matches`: при одинаковых material/framing/objective/allowed parameter map профиль не хранит SHA A/B и сам этот различающий случай не выявляет. Не смешивать с отдельной admission legality: legitimate issuer, valid pair side authors и mutation permit по-прежнему требуются.
7. Вывести точную таблицу `vocabSize, shaA, shaB, source s, idsA, idsB, selfRoundtripA/B, noExpectedShaStatus, expectedAStatus, expectedBStatus`. Если недоступен friend-test путь, фиксировать `NATIVE_NOT_RUN`, не подменять парсером source-only proxy.

**Pass механизма:** same-V different-SHA реальны, валидный exact batchB принят без expected SHA, отвергнут при ожидании shaA. **Falsifier:** production path предоставляет проверенный другой invariant, который делает этот случай фактически недостижимым; тогда `DEFENSE_IN_DEPTH_ONLY`. Проверка exception в искусственном юнит-тесте сама по себе не доказательство ухудшения RP01.

## Tier 2: tiny causal semantic A/B — только если найден настоящий допустимый caller

Только в disposable разрешённом контуре:
- **A:** Student/tokenizerA + legal chosen/rejected generated by A; **B:** те же слова, модель StudentA, но IDs generated by B через разрешённый exact producer. Контраст подменяет **одну** независимую переменную: BPE identity; optimizer state, dataset, semantics, seed, config и свободный decoding tokenizer A frozen. Для реального DPO сначала CODEX/Astra 6 UltraCode как человек выбирает case; **внешняя открытая китайская модель** генерирует обе actual DPO стороны; **отдельный CODEX/Astra 6 UltraCode** проверяет их качество; нельзя использовать эти toy `abab` в качестве доказательства domain learning.
- Не запускать если модель или test training authority не поддерживает illegal mismatched pair в isolated test; не обходить security grants. Можно вместо тренировки измерить `next-token target ids` и log-probs для обеих кодировок на одном StudentA, это mechanism evidence без живого quality effect.
- При законном tiny A/B (≤8–12 независимых C#/ENRU задач, никаких RP01 500 повторов) замерить `initial target id agreement; logprob margins; chosen-law correct complete answer; incorrect/critical cases` на слепой панели и после cold restore.
- Если А и B равны по downstream или B недостижим — `NO_CAUSAL_RP01_EVIDENCE`; если B хуже на реальном обычном consumer при единственной замене tokenizer и source proof валиден — `SMALL_PANEL_GAIN_FROM_IDENTITY_GUARD`; если явный mismatch уже блокируется у producer — `NOT_REACHABLE`.
