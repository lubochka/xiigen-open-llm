## 1. N37-A — новый структурный тег может ВЫКЛЮЧИТЬ проверку похожести исходной фразы

**Смысл:** больше структурной информации не обязательно означает более строгий retrieval. Если в full signature добавлен непохожий на имя POS структурный компонент, `IsLowInformationSignature` переключает требуемую source-overlap с 0.35 на 0.0, то есть **более богато размеченная подпись допускает чужую фразу, отвергнутую прежней подписью**.

Прямое звено: [TranslationUnitContracts.cs L246–265](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationUnitContracts.cs#L246-L265) выбирает для full signature threshold 0.35 только если `IsLowInformationSignature(fullSignature)`, иначе 0.0. [L295–306](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationUnitContracts.cs#L295-L306) называет low-information любую подпись с не более чем двумя компонентами или с компонентами после первого, все из `TranslationPos`. Обычный `RULE_SYNTAX` в этой части не является POS. [L268–293](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationUnitContracts.cs#L268-L293) вообще не вызывает `SourceSimilarity`, если minimumSourceSimilarity=0.0, оставляя узкую проверку `TranslationMemorySourceLaw`. Последняя распознаёт только изолированную английскую связку `the box is (not) empty` и аналоги: [TranslationMemorySourceLaw.cs L11–47](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationMemorySourceLaw.cs#L11-L47).

**Точный source-only контрпример:** запрос «blue widget», память «green vehicle», source lexical overlap=0. Запрос/память с идентичным ключом `TYPE|NOUN|VERB` → порог 0.35 → запись не принимается. При *одинаковом* `TYPE|NOUN|VERB|RULE_SYNTAX` на обеих сторонах → порог 0.0 → чужая запись может пройти. `SourceLaw` здесь Unknown, не Contradiction. Это не означает, что реальный семантический токенизатор произвёл такие ключи; нужно отдельно подтвердить пути производства tag и runtime совпадение full key.

**Важное подтверждение потенциальной достижимости настоящим токенизатором:** [TranslationSemanticTokenizer.Tokenize L124–150](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationSemanticTokenizer.cs#L124-L150) действительно включает `ruleTags` в обычные `Signature` и `PrefixSignature`, а [L153–195](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationSemanticTokenizer.cs#L153-L195) строит RU subject/tense/gender/agreement tags. У обычной фразы **без известных концептов** без тегов full signature может состоять из одного Pattern (порог .35); при **двух и более** RU-тегах получится более двух компонентов, не являющихся POS, и порог станет 0.0. Это уже реальный путь построения ключа, **но не доказательство**, что две такие фразы встречались в одном training bucket, не имели source overlap и породили wrong answer. Потребуется выполнить native Tokenize обеих строк и показать actual full key equality; использовать искусственный `TYPE|NOUN|VERB` только как L0-проверку чистой функции.

**Почему новизна узкая:** N14/N16/N28/N30 ранее находили scope, неверный tokenizer, FIFO и late target check. Здесь отдельный **немонотонный переход security/quality threshold из 0.35 в 0.0 при добавлении feature**, который не исправляется простым увеличением k. Если токенизатор реально всегда выдаёт POS-only ключи, статус `NOT_REACHABLE` и гипотеза снимается.

**Быстрая проверка A37:** одна пара query/source и одна память; native тест `FindNearestCascade` на POS-only подписи и той же подписи с добавленным rule tag, frozen source/target. Ожидаемые L0 counts: 0 затем 1. L1 только при реальном key production: C# documentation AST tags, SQL operators, EN→RU grammatical tags, по 4 source-disjoint query и 4 негативных opposite-law; проверить accepted-wrong/abstain с обычным Executor/Flow. Дополнительный вариант «оставить source guard 0.35 независимо от tag» менять только внутри экспериментального adapter. Не считать ухудшение coverage без проверки настоящих правильных ответов улучшением.

## 2. N37-B — похожесть несимметрична и принимает кандидата с чужими обязательными оговорками

[SourceTokens L308–314 и SourceSimilarity L316–323](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationUnitContracts.cs#L308-L323): оценка = `|tokens(query) ∩ tokens(candidate)| / |tokens(query)|`. Это **query containment**, не симметричная similarity. Значение 1.0 возможно, когда память содержит десять добавочных оговорок, отсутствующих во входе.

**Контрпример на формуле:** query «delete records», сохранённый source «delete records after backup is verified by administrator». После фильтра low-info слов 2 query-токена и 6 candidate-токенов; текущая мера = 2/2 = **1.0**, Jaccard для тех же множеств = 2/6 = **0.3333**. При пороге .35 первая мера примет кандидата, вторая — отвергнет. Дополнительные слова «after backup ...» меняют условия выполнения операции и не являются шумом. SourceLaw для этих фраз возвращает Unknown. При этом Jaccard **не объявляется правильным универсальным алгоритмом**: полезный paraphrase/retrieval может сознательно использовать query containment. Следует проверять опасные *квалификаторы*, а не механически ужесточать все домены.

**Быстрая проверка B37:** 3 source query, каждая с (i) корректным paraphrase; (ii) кандидатом-супермножеством с иной обязанностью/условием; (iii) оригинальным learned sentence. Frozen signatures/labels, одинаковый exact/phrase/word-map state. A=current overlap/query; B=symmetric coverage or qualified-clause veto после распознавания модальности и условий. Метрики: wrong accepted, lawful recall, retention, abstain. Домены с высокой ценой ошибок: C# permission/null contracts, SQL WHERE/transaction conditions, EN→RU temporal/negative clauses. Для простой терминологии дополнительный контекст может быть безопасен, поэтому фиксировать per-domain результат, а не global rollout.

## 3. N37-C — первый непустой tier останавливает поиск, хотя его переводы отвергнуты позднее

**Два реально раздельных уровня в коде:**
1. [FindNearestCascade L246–265](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationUnitContracts.cs#L246-L265) возвращает первый **непустой по source** bucket в порядке full → prefix → structure. Он не знает целевого языка и не проверяет target текст.
2. [ExecutorUnit.TrySelectKnnCandidate L333–363](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationTrainedUnits.cs#L333-L363) получает **только этот один tier**, затем отвергает target по `IsTargetCompatibleForDirection` и/или дополнительному similarity. Если отвергнуты все, метод возвращает false, **не пытаясь следующий tier**. [EN_RU target script check L924–939](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationTrainedUnits.cs#L924-L939) требует кириллицу и запрещает латиницу. Shared memory [TranslationMachine L714–744](https://github.com/lubochka/llm_mvp_core/blob/793d7b755b23aac90445da3ac6661b1bff7e6672/27.TranslationDomain/TranslationMachine.cs#L714-L744) делает cross-direction конкуренцию возможной.

**Логическая комбинация:** EN→RU query; в full bucket один source-compatible английский target «Return status», в prefix bucket один source-compatible кириллический target «Вернуть статус». Класс source-law Unknown не отвергает full. Cascade отдаёт full и останавливается. Executor отвергает английский target. До prefix правильный кандидат не доходит. Условие **не требует >k записей** и поэтому отличается от уже опубликованного [N16 target filtering after k](16-INDEPENDENT-NEW-GAPS-KNN-CORRECTIONS-AND-UNIT-TRUTH-2026-10-16.md) и [N30 shared direction store](30-NOVEL-DIRECTION-GATED-KNN-AND-SHARED-CROSS-LANGUAGE-CANDIDATES-2026-10-16.md). В обычном Flow exact/phrase/word routes могут сделать KNN недостижимым — требуется явный route trace.

**Быстрая проверка C37:** напрямую построить Store(full wrong-target, prefix correct-target), вызвать cascade и затем Executor-filter, проверить метки `FULL_ONLY→REJECTED` и `PREFIX_PRESENT_NOT_VISITED`. A=current; B=только в shadow adapter — применять target-law фильтр на каждом tier до решения «tier viable», затем переходить к следующему; C=negative control prefix с законно неверным переводом (не разрешать без independent rubric). На 12 EN→RU и 12 EN→HE/EN→ES source-disjoint cases сравнить ordinary correct, wrong accepted, abstain, latency и hit provenance. B должна улучшить хотя бы один заранее замороженный новый source без прироста чужоязычных/противозаконных ответов. Если все реальные вызовы перехвачены exact/phrase/word, `ROUTE_NOT_REACHED`, не объявлять улучшения.
