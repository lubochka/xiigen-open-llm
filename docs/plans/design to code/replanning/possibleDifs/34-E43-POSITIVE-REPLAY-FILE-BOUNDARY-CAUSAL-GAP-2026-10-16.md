## 1. Зачем это важно

До того как считать старую реализацию реплея «доказавшей, что модель не забывает», нужно установить, чему именно её учили. В E43 каждая исходная запись — отдельный файл, но метод сначала объединяет **все** извлечённые предикаты файлов в один массив и лишь потом связывает соседей. Получаются пары вида «последний предикат файла A → первый предикат файла B». Это не последовательность внутри документа и не проверенное правило домена.

Такой механизм может одновременно (а) учить искусственным переходам и (б) оценивать их как будто это полезный навык. Отсюда новая адресная гипотеза **N34-H1**: *часть исторически положительного E43 gain могла зависеть от порядка файлов, искусственных соседств и необособленного holdout, а не только от сохранения переносимых знаний*. Это не отменяет реальный зафиксированный положительный опыт; требует изолировать его механизм.

**Механическое следствие:** при `F` непустых файлах внутри одного набора из одной или более последовательностей предикатов, конкатенация добавляет до `F−1` несуществующих переходов через границы. Если извлечение какого-то файла пустое, точное число рассчитывается по непустым файлам. ## 3. Вторая гипотеза N34-H2: «обобщение» было повторным предъявлением того же перехода

`oldVal` отбирается как хвост **того же упорядоченного списка** `oldPairs`, а в `replayBuffer` попадают пары из `oldTrain`. Несмотря на разные позиции oldTrain/oldVal, совпадающие значения биграмм `(first,next)` могут оказаться по обе стороны, и алгоритм на частотах ответит на `oldVal` за счёт точного повтора перехода. **Это возможная оценочная утечка по признаку перехода, не доказанное наличие конкретных повторов в Tier 2 run.** Нужна отдельная статистика train/val duplicate *pair keys* и переходов по source families.

Для E43 по коду также нельзя приписать gain именно доле 30%: `BuildBigram` не использует trainable transformer; непосредственное возвращение старых примеров в частотную таблицу само по себе повышает вероятность старого top1. Сравнить 0/10/30% и old-only при неизменном validation следует как отдельную *диагностику*, не подбирая ratio по закрытому gold.

## 4. Быстрый отличающий эксперимент: E43-FILE-BOUNDARY-01

**Граница:** только Code/LogicExtractor-биграммы и архив E43; **НЕ** EN→RU, не DPO reference, не C# LoRA. Дизайн запуска оформлен в [34-MICRO-E43-REPLAY-CAUSAL-PROTOCOL](34-MICRO-E43-REPLAY-CAUSAL-PROTOCOL-2026-10-16.md).

- **Контроль A (current):** прежняя конкатенация `Zip`, прежняя 30% replay.
- **Контроль B (one factor):** `Zip` отдельно *внутри каждого файла*, без межфайловых переходов; сами предикаты/законные пары и ratio сохраняются.
- **Фиксированный набор:** исходные old/new files с pinned SHA, не использовать случайное перемещение файлов между old/new. Для каждого варианта одинаковая **внутрифайловая source-family-disjoint** validation panel с заранее замороженными ID. Отдельно замерять `file_boundary_pairs` и `same_pair_seen_in_train`.
- **Взаимодействие:** для A и B повторить 0% / 30% replay. `Δ_R(A)` и `Δ_R(B)` сравнить на **одном** holdout. `Δ_R(B)>0` при отсутствии совпадений и разных file orders поддержит переносимый replay; исчезновение gain на B/closed panel подтвердит риск исторического завышения, не «полное отсутствие обучения».
- **Негативный контроль:** shuffled file order **внутри** old/new train для A, без изменения val и без изменения набора файлов. B должен сохранять сами пары; A может создать другие boundary pairs.
- **Нельзя** интерпретировать `0.3978−0.3226` как исправляемые 7.52 п.п. в RP01: это разные модели, получатели и eval.

## 5. Возможный ремонт — только после проверки

Если B лучше A на одном frozen family-disjoint panel и даёт воспроизводимую точность, переносить guard `fileId` в формирование bigram evidence, хранить `source_file_id` вместе с pair, и затем отдельно проверять, что нужный механизм вообще вызван реальным trainable Unit/Consumer. **Не** переписывать DPO или HNSW на основании результата E43. Если эффект нулевой, оставить E43 историческим domain-specific наблюдением и закрыть N34-H1 как `NOT_SUPPORTED_ON_MATCHED_PANEL`.
