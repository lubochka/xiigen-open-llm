Нельзя объединять «существует текст эксперимента» и «эксперимент валиден по сегодняшнему запросу». Примеры из ПОКАЗАННОГО protected кода:

Их можно использовать как уже существующий source evidence или подготовительный контроль внутри разрешённого native обучающего A/B, если дополнительный запуск реально нужен и разрешён.

## 4. Успех измерения и опровержения — единое правило для каждой будущей карточки

Действующие [P125 card](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/cards/P125-executor-memory-learning.md), [method 01](https://github.com/lubochka/llm_mvp_core/blob/codex/dpo-implementation/docs/plans/replanning-possible-diffs/experimets/2026-10-19-small-learning-probes/01-method-and-report.md) содержат правило: ANY measured useful metric improvement = local success for that metric/domain (не accuracy-gate); all other deltas and harms adjacent. Для нового N60 это перенесено в КАЖДУЮ [карточку и исполнительский prompt](60-02-REAL-LEARNING-MICROEXPERIMENTS-2026-10-19.md). Нельзя отменять положительный результат из-за прежнего arbitrary 5% threshold, нельзя игнорировать 3 wrong accepted.

Minimum evidence bundle for any approved run:
- core SHA and code method/line addresses, donor exact SHA / sample label; source license; data family IDs; active model/unit and version.
- Named training caller AND persisted memory/LoRA update, unit count/hash; changed lesson IDs; actual trained after and actual ordinary Flow outputs. A0/B0 and A1/B1; equal prior state and dataset inputs except ONE selected factor.
- Per-domain actual gold with independent judge, output JSON/CSV each raw case and denominator; train/exam family disjoint; no mixing of C#/SQL AST features as «translation-domain law».
- Full metric vector, explicit tradeoffs, measurement units and scope. CPU counter must measure CPU, not TickCount64 wall. Report training work count, no fake claims when train==0.
- Human approval of exact proposed experiment and independent review PASS bound to reviewed SHA; no implicit approval from older card.

## 5. Что осталось открытым и что нельзя объявлять завершённым

- Полный semantic readback всех P01–P125 и ~470 подслучаев на текущем HEAD НЕ выполнен в этой сессии, поэтому «все детали уже отражены и корректно измеряют обучение» **не доказано**.
- Исторические 360 SHA registry references и новые 19-Oct planning documents НЕ имеют полного нового source→card→case→status map. Нужно добавлять read-only shadow delta index в planning, не перезаписывать core.
- EXP-N60-A/B — разработанные короткие паспорта и исполнительский промпт, не выполненный native A/B. Отсутствие причинного learning gain не превращать в успех из-за математического threshold примерa.
- Дополнительные branches main/DesignToCode/DesignToCode-clean/PrepareToGPL/language_translate имеют отличные экспериментальные representations. Установить old matrix run→new kNN commit lineage пока не удалось; не подменять доказательство источниками других Tier.
- Никаких действий по изменению исходного кода или запуска обучения не разрешено этой научной документацией. Следующая легитимная операция — индивидуальный human review **точного** короткого опыта на названном обучаемом recipient, если пользователь даст отдельное разрешение.
