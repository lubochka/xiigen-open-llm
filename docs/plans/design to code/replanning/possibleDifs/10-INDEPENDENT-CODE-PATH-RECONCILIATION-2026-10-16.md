## 2. Кто реально создавал DPO, кто отвечает за качество и чему обучали

**Непересматриваемая ответственность целевого teacher контура:**
1. **CODEX с моделью GPT-6 Astra 6 UltraCode** исполняет человеческую функцию: выбирает конкретную учебную слабость, учебный case и требуемый предметный закон.
2. **Внешняя открытая китайская модель**, разрешённая по лицензии и условиям использования, генерирует **ОБЕ окончательные стороны**: chosen и rejected для одного точного prompt/context. Слабый Student output допустим как диагностика, но не обязан стать rejected.
3. **CODEX с моделью GPT-6 Astra 6 UltraCode** отдельно оценивает **точную пару** после создания: насколько chosen действительно лучше, какую конкретную ошибку содержит rejected, корректность доменных ограничений и источников, TIE/BOTH_BAD/UNJUDGEABLE. Он не выдаёт собственные правки за авторство китайской модели.
4. Student через существующий DPO/LoRA trainer учится на допущенном материале. **Независимая** оценка после обновления проверяет реальные ответы на новых семьях задач через целевого consumer, а не тренировочный margin.

Первичный действующий контракт: [WorkLeft teacher roles 6–16](https://github.com/lubochka/xiigen-planning/blob/bfcc610bbaf3cffa54b921b2f435dc616955e2cb/llm%20mvp/design%20to%20code%20session/09.09.26WorkLeft-02-teaching-chinese-model.md#L6-L16); [RP01 offline source boundary 13–19](https://github.com/lubochka/xiigen-planning/blob/bfcc610bbaf3cffa54b921b2f435dc616955e2cb/llm%20mvp/design%20to%20code%20session/replanning/Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-OFFLINE-TEACHER-BATCH500.md#L13-L19).

**Но фактические C#500 и EN→RU500 не были выполнением этого teacher-контура:** в [CodeDocumentationSimulationDpoExperiment 41–70,113–118](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/14.ContinuousLearning/Training/CodeDocumentationSimulationDpoExperiment.cs#L41-L70) provenance точно обозначен **simulation**, а **обе стороны** размечены DeterministicGenerator. Никакого external-Chinese inference/judge receipt в этом маршруте нет. **Статус: CODE + CONTRACT_DIFF, а не доказательство плохого качества всех 1000 пар.** Нужно отличать структурно правильные JSON-тройки от CODEX semantic assessment и от independently measured Student gain. Для новой кампании нельзя переименовать simulation в Chinese/Astra.

### Исторические результаты, которые нельзя автоматически переносить

## 4. Порядок проверки: сначала дешёвое причинное доказательство, не новая очередь Windows CI

| Порядок | Изолируемый механизм | Контроль и минимальный результат | Если провал |
|---|---|---|---|
| **T0** | Верный recipient / actual exact-v2 / gradient | На **новой** небольшой разрешённой паре: exact material fingerprint, target masks, finite difference или directional gradient, adapter on/off, frozen reference, no-update; без нового Main500 | STOP большой DPO, исправить **первый** потерянный data/gradient seam |
| **T1** | Может ли B0 научиться хоть одной закономерности? | Малый train-only chosen CE overfit, new-family heldout отдельно; fixed tokenizer, same Student and decode; back-to-back DPO-only и warm→DPO | Если train-only не учится — искать вычислительный defect/capacity до новой pair factory |
| **T2** | Адекватность DPO content и prompting | Chinese-written chosen/rejected, exact CODEX Astra 6 UltraCode judge, один domain law и semantic near-miss; true actor receipts, различие survives exact tokens; фиксированный бюджет | TIE/BOTH_BAD/UNJUDGEABLE quarantine, не фальсифицировать preference |
| **T3** | Вектор, kNN и Unit connections | Freeze solver; old vector vs law-aware representation; exact vs ANN отдельно; при fixed hits top1 vs learned rank; new unseen law families | Не приписывать отсутствие gain DPO-модели, если consumer не подключён |
| **T4** | Restore/ordinary inference | exact checkpoint pre-save→post-save→fresh load→ordinary app; same input framing and decoded tokens; token distribution/logits; no stale cache | Локализовать конкретный missing adapter/manifest/preload seam, не строить trainer заново |
| **T5** | Cross-domain effect | Когда появился **ненулевой** useful baseline, измерить новые domain transfer/retention/worst-domain quality, cost including all branches | 0/3→0/3 на исходно непригодном C# не использовать как доказательство retained skill |

**Внешнее качество =** paired semantic correctness по новым предметным семействам, law violations, partial/correct/critical/abstain, retention и PC time/RAM, а не optimizer step, loss, число файлов, test count или рост similarity. Зафиксировать rubric **до** очередного тренировочного шага; frozen RP01 examinations менять нельзя. Не выполнять 500 новых пар, пока T0/T1 не прояснили работоспособность минимального learning path.
