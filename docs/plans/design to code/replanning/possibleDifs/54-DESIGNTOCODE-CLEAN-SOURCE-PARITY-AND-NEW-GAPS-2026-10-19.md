## 2. P0 — наиболее непосредственный механизм потери тренировочной информации

**Точная цепь:**

**Смысл:** исходная оценка `chosen/rejected` известна в `record.Chosen.Verdict.Score` / `record.Rejected.Verdict.Score`, но новый **token-facing** DPO-представитель намеренно ограничивается `html/css`; локальная кодовая ветка, ожидающая прежнюю структуру score, осталась. В fallback у неё `margin=1.0` при любых различающихся строках. Это делает **локальный rewardMargin нечувствительным к инверсии оценок**; если downstream weights зависят от margin, возникнет искажение величины/знака. Прямо по коду локальный `AddDelta` для `source_kind`, `internal_vector:mean/dimension` получает числовые contributions, а сам `preferenceMargin` сохраняется в AverageRewardMargin. **Не утверждаем**, что все веса используют margin или что весь neural gradient становится нулевым: это проверяется A0 отдельно.

## 3. Новое поведение: обучение одного правила может подавить другое

[Source `DesignConversionTrainedUnits.cs:L298–353`](https://github.com/lubochka/llm_mvp_core/blob/358af351e22a92a3f7938d1f9221d5aeb7ddb053/44.DesignConversionDomain/DesignConversionTrainedUnits.cs#L298-L353) создаёт `availableRules` из всех дефектов. Если найден хотя бы один положительный `DesignConversionLearnedCorrectionPreference`, возвращает `SelectedRules: [ranked[0].Rule]` даже когда есть ещё обязательные независимые дефекты. Взаимодействие **обученная память ↔ жёстко заданный детерминистический исправитель**; проблема не эквивалентна "алгоритм скрыто детерминистический". Здесь оба механизма работают, но обучение может **сузить** используемое действие.

Контрпример без клика по браузеру:
- запрос с двумя видимыми дефектами `contrast` и `overflow`; без weights selected=`[contrast, overflow]`;
- один положительный `correction_category:contrast`; selected=`[contrast]`, `overflow` не исправлен;
- два положительных, `contrast=0.8`, `overflow=0.9`; selected=`[overflow]`, `contrast` пропущен;
- веса `0/-0.3` и case с единственным дефектом — отрицательные контроли.

Проверка недостаточности требует реального законного learned Unit state. Замена правила `top-1` на сохранение всех *критических* rule IDs — гипотеза ремонта, но до acceptance надлежит проверить конфликты CSS/DOM, где применение двух правил может быть неверно. Ограничение домена: **только Design-to-Code визуальные дефекты; не переносить в C# AST или перевод.**

## 4. Что исправлять, что сохранять

| Решение | Причина |
|---|---|
| **Repair candidate:** separated trusted labels for local feature weights, не вставляя `visual_score` в tokenizer input | Сохраняет реальный `html/css` token-target и устраняет логическую зависимость от исчезнувшего поля |
| **Repair candidate:** explicit correction-role source properties in authorised derived signal | Current Machine проверяет категории, но канонический материал их не несёт |
| **Research only:** preserve safe DOM relationship type/order, no raw `parentRef` | Не возвращать приватные идентификаторы и output leakage |
| **Research only:** selective vector dimensions or dimension-aware embeddings with explicit schema/version | Prefix16 мог срезать полезное; избегать обучения на source IDs и тайных label-derived признаках |
| **Keep:** current output HTML/CSS, legal teacher authority, source-disjoint admission, model/reference identity and q/v backward | Это существенные современные исправления; полный revert gold не разрешён |
| **Keep separate:** domain-specific kNN POS, AST, replay buffers и semantic verification | `DesignConversion` приём не есть универсальное объяснение RP01 0/4 |
