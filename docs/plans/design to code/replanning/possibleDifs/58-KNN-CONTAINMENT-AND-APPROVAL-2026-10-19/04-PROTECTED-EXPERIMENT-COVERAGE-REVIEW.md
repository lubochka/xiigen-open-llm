### Проблема корректности экспериментов, непосредственно видная в документах

Protected [P07](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/docs/plans/replanning-possible-diffs/experimets/cards/P07-materialized-token-contrast.md) и [P81](https://github.com/lubochka/llm_mvp_core/blob/eb05219c27663835ce927c7bf97cf1274c07cddb/docs/plans/replanning-possible-diffs/experimets/cards/P81-input-conditioning.md) в `Прямые источники` содержат ссылки вида `C:/Users/lubao/Documents/xiigen/...:line`. Такой путь **не является переносимой привязкой** для независимого CODEX на GitHub без локального дерева и удостоверенного commit SHA. Оригинальные объяснения могут оставаться верными; проблема — **воспроизводимость source proof на другом executor**. Каждый исполняемый паспорт должен вместо абсолютного пути иметь SHA blob + permalink + реальный filename/range и содержимое, нужное для offline audit. Не следует редактировать защищённые карточки; покрытие/недочёт фиксировать здесь, в planning.

**Отдельный deficit personal-review gate:** часть исторических P-card имеет общий короткий будущий промпт и относительные refs, но НЕ полноценный в каждой карточке паспорт модели/initial checkpoint/seed/полного текста task; mini01 его требует. Значит `P-card exists` ≠ `approved executable protocol`. Новые N58 паспорта содержат конкретные TRAIN/EXAM, модель learner, условный executor ID, skills, initial state policy и expected conditional output. Если exact SHA initial checkpoint неизвестен до разрешения, явно написать PENDING вместо выдумки.

**Не заявлено:** глобальная полнота всех найденных деталей в неизменяемом core защищённом каталоге; независимая научная корректность всех 470 подслучаев; успешная реставрация donor model; native прирост N58 K1/K2. У уже выявленного [N57 argument role/verifier](../57-ARGUMENT-AND-VERIFIER-LEARNING-GAPS-2026-10-19/README.md) есть локальные плановые новые карточки, которые **не добавлены** в core protected P01–P125 — по прямому запрету их нельзя туда дописать. Приоритет после review: обобщить working copy crosswalk в planning, просить явного права синхронизации отдельно, не перезаписывать.
