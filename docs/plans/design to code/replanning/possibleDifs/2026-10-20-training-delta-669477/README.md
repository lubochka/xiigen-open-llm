## Что означает успех

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и предметной теме; рост точности не обязателен.** В той же строке отчёта остаются изменения остальных показателей, включая ухудшения. Успех отдельной оси делает результат кандидатом для решения пользователя; он не означает автоматический перенос в основной код.

Различаются: изменение обучаемого состояния; улучшение учебного NLL или предпочтения; правильность свободного ответа; стоимость настоящего Train; сохранение старых навыков. Наличие метода, число тестов, исправный JSON и совпадение имён файлов сами по себе не измеряют обучение. Загрузка данных, восстановление и чтение выученного результата допустимы, когда указан точный путь зависимости результата обучения.

Малый эксперимент меняет только свою изолированную копию. Не запускает общий CI, не чинит продуктовые тесты, не заменяет реальный learner на формулу и не пишет в защищённую папку. Для будущих заданий модель исполнителя — default текущей сессии; язык отчёта — русский; навыки, место и команды заданы прямо.

**STOP/NEXT действует немедленно.** После «заканчивай и переходи» не дописывать прошлый отчёт, не проверять Git, hashes, публикацию и не выполнять ещё один review или run. Перейти к уже назначенному следующему заданию. После «остановить всё» прекратить всю работу; допустимо только необходимое прекращение собственного ещё работающего процесса. Старые опыты и результаты сохраняются.

## Граница полноты

Полностью получены и проверены по Git blob SHA **832 исходных Markdown `possibleDifs`: 799 базовых и 33 добавленных параллельно**; по ним выполнен поиск совпадающих механизмов и разобраны найденные близкие работы. Проверены правила всех **154 карточек core669**, отдельно извлечены **133 встроенных промпта**. Прочитаны конкретные родительские RAG-первоисточники, нынешние учебные цепочки, исторические исходники и первичные сохранённые результаты. На core827 отдельно проверены инвентаризация **157 карточек**, изменённые постановки и шестой результат; на core6e — 27 изменённых карточек, LF-03 и EOPT erratum. Девять относящихся к гипотезам production subtrees не менялись от 669 к 827, а все 45 production project trees не менялись от 827 к 6e. Это **не утверждение о построчном смысловом аудите всех файлов репозитория, всех веток или всех 470 подслучаев**.

Новые VT/RMS-карточки находятся только здесь, в `possibleDifs`. В защищённом core-каталоге их пока нет; это явно отмеченный разрыв покрытия, устранённый отдельными проектами опытов без нарушения запрета на изменение той папки. Исполнение и включение измеренного кандидата в основной код остаются разными последующими действиями.
