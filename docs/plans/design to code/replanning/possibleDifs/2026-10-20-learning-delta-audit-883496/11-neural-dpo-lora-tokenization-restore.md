## Главный результат

Не обнаружено оснований заново объявить текущий DPO «не обучающимся», формулу LoRA неправильной или Embedding/fractional-mask исторические дефекты всё ещё отсутствующими исправлениями. В текущем code path присутствуют actual forward → backward → AdamW → разрешённые LoRA параметры. Это подтверждение механизма, не доказательство полезного владения C#, переводом или иным доменом.

Один новый **изолированный исследовательский фактор внутри известного BPE-семейства**: выбор merge по числу исполнимых неперекрывающихся замен. SKNN — неактивный вариантAST; единая очередь в05. Сам факт overlapping/nonoverlapping уже описан как сохраняемая семантика в старой cost-карточке; новизна не приписывается этому факту. Новое — самостоятельное A/B **другой цели обучения BPE**, без weighted chunks/no-match оптимизаций. В фиксированном fixture заранее ожидается выигрыш lambda-компрессии и ухудшение комментариев/общей EXAM-компрессии. Это аналитический прогноз, не measured success и не установленная причина неудачи RP01.

## 3. N62-R1: measured ресурсный успех сохранить, формулировки ограничить

Свежий [report N62-R1-01](https://github.com/lubochka/llm_mvp_core/blob/883496bca18113bf37e0afe683c75b05a0075048/docs/plans/replanning-possible-diffs/experimets/results/2026-10-20/N62-R1-01/report.md) относится к двум actual DPO steps на плечо. Изменение frozen-base comparison находится непосредственно внутри ApplyOptimizer через `RequireValid`, значит оно входит в обучение. Локальное уменьшение allocations и времени observed phase — полезный измеренный результат; accuracy gain для кандидатуры не требуется.

Выявлены интерпретационные границы, переданные агенту проверки отчётов и root для одного additive erratum:

1. Сравнение одноимённых фаз **не устраняет** смешение фиксированным порядком A→B. Факт фазовых timers не доказывает причинную независимость от JIT/нагрева.
2. Утверждение «ухудшений ни на одной измеренной оси» неверно: по raw sibling проверил GC collections A=[188,12,9], B=[189,13,10]; ухудшены все три счётчика. Сам я прочёл report и code chain; raw окончательно сверил experiment_review.
3. Изменение16 adapter tensors подтверждает факт обновления, не улучшение полезного ответа. Два successive losses относятся к различным D-T1/D-T2 и не составляют before/after на одной панели.
4. Равные final hashes/losses/moments показывают равенство этой двухшаговой траектории. Они не доказывают математическую эквивалентность во всех shapes/seeds/domains.
5. Причина общего ускорения именно JIT/разогрев — гипотеза, не измеренный causal факт.

Повтор этого завершённого эксперимента не нужен. Полное добавочное уточнение: [03-N62-R1-measurement-erratum.md](03-N62-R1-measurement-erratum.md). Нельзя дублировать поправку конкурирующими перезапусками/правкой protected report.

Exact/semantic terms: CountPairs, realized/realisable merges, self-pair, «фактическое сокращение/слияние», «исполнимые слияния», overlap/non-overlap. Близкие документы прочитаны содержательно: BPE-WEIGHTED-CHUNKS прямо требует сохранять overlapping counts и называет non-overlap counting **другим алгоритмом**; BPE-NO-MATCH сохраняет те же pairs/merges и меняет allocation. Проверены также пакеты learning-signal-and-cost-audit, learning-results-and-new-gaps и learning-audit-additions. Отдельный готовый causal A/B этого objective-factor не найден.
