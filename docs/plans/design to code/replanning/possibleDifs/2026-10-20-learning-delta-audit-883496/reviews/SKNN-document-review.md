## Roslyn identity: граница статического вывода

Исходник использует `List<SyntaxNode>.IndexOf`; по [официальному контракту List.IndexOf](https://learn.microsoft.com/en-us/dotnet/api/system.collections.generic.list-1.indexof?view=net-9.0) это default equality comparer и первый найденный индекс. B не заменяет identity на Span/текст или структурную эквивалентность. Cache хранит реальные node references и использует TryAdd, сохраняя first occurrence; fallback0 и saturating byte semantics совпадают.

Рецепт проверяет equality contract загруженного SyntaxNode до Train и фиксирует Microsoft.CodeAnalysis.CSharp4.12.0 — ту же package version, что [native csproj](https://github.com/lubochka/llm_mvp_core/blob/883496bca18113bf37e0afe683c75b05a0075048/12.SemanticCompiler/SemanticCompiler.csproj). Общий API [SyntaxNode](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.syntaxnode) различает ChildNodes/Parent и структурную EquivalentToCore; это не повод использовать equality по одинаковому тексту. Статикой **не аттестовано**, что все node references конкретного runtime будут совпадать в каждом обходе. Поэтому actual ordered-state/prediction parity — обязательный результат самого назначенного A/B, а не отдельный предварительный learner run. При несовпадении эксперимент сохраняет результат и не маскирует его новой подгонкой cache.

- Не проверены установленный Windows checkout, SDK/package access, компиляция, текущая Roslyn assembly identity, длительность и фактические allocations. У карточки правильный статус NOT_RUN.

- Resume относится только к завершённой подготовке без начатых arms. При живом/неизвестном процессе исполнитель наблюдает тот же процесс; отсутствие stdout само по себе не разрешает новую execution chain.
- Эта новая гипотеза проверяет узкую стоимость подготовки C# AST перед настоящим kNN Train. Она не объясняет сама по себе падение качества нейронного RP01 и пока не является успешным измеренным кандидатом.
