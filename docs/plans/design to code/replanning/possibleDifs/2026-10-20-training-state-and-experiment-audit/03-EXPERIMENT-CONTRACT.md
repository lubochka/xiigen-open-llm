## Решение о запуске не подменяется решением о внедрении

Поручение этого аудита — собрать расхождения и проверить постановки. Здесь подготовлены документы и isolated source-copy заготовки; новое обучение не запускалось. Будущий исполнитель получает отдельное поручение выполнить выбранный опыт. После результата он показывает raw outputs и точный кандидат переноса; автоматического product fix, CI, merge или массового запуска всех карточек нет.

Действующая [policy от 20 октября][policy] уже отменяет общий PENDING и повторные личные разрешения для обычной подготовки. Это не основание снова просить пользователя назвать host или путь. Неизвестность разрешается доступным source inspection, а реальная отсутствующая зависимость явно называется. В этом пакете `.NET SDK unavailable` ограничивает фактическую компиляцию, а не отменяет выводы из кода.

## Одинаковая причина — одинаковый материал и измеритель

Для сравнения процесса приобретения знания нужны A0/A1/B0/B1: состояние A до/после и состояние B до/после. Начальные состояния функционально одинаковы на общей схеме; TRAIN/EXAM и их порядок фиксированы; между A и B меняется один заявленный механизм. Метрики считают как изменения внутри плеч, так и различие изменений. При новой taxonomy число координат намеренно различается: равны первые 15 координат, две добавленные нулевые; требовать равенства полных hashes было бы ошибкой.

Нельзя назвать «до» одним scorer, а «после» другим; нельзя менять denominator, удерживать успешные случаи и выкидывать неудачные. Например, у E09 historical Take(500) требует явного ограничения вывода. При зависимой проверке restore/reader допустим один доказанно обученный artifact и одинаковый EXAM до/после точечного ремонта, без искусственного дополнительного Train. Тогда вывод — сохранность/использование приобретённого, не новое усвоение.

Для стоимости реального обучения дополнительный Generate не обязателен. Проверяются те же updates, состояние/градиенты/предусмотренные invariants, wall/CPU/allocations и retained memory. Качество свободных ответов, если оно не измерено, помечается `NOT_MEASURED`, а не `0%`. Таймеры build, startup, source copying, learning и evaluation отдельно; cache fill входит в опыт, скрытый warmup не добавляется. Из одного измерения можно описать наблюдаемый выигрыш с его ограничением; нельзя выдумывать статистическую устойчивость.

**Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности не обязателен. В отчёте рядом показываются изменения остальных показателей, включая ухудшения.** Отсутствие полезного изменения при достигнутом механизме — честный нулевой результат. Недостигнутый writer, непрочитанный state или различный экзамен не становятся отрицательным ответом на причинную гипотезу.

## Что входит в готовую карточку

Нужны: вопрос; источник/версии; domain; baseline и candidate; exact repair target; learner/state/reader; frozen TRAIN/EXAM; входное состояние/seed/model shape; точный счёт операций; команды; пути outputs; правило конфликта; raw schema; метрики; статус build/run; граница переноса. Если какого-то элемента нет, указывается конкретный незавершённый контракт. Слово PREPARABLE не доказывает, что host уже существует.

В новых isolated scaffolds привычная адресация `35.ExperimentsV2/Experiments/Rp01Micro/<ID>/` и `experiments-v2/RP01-MICRO/<ID>/` находится внутри добавочного planning packet. Native code читается по pinned SHA и копируется в этот scaffold. Это исключает правки protected и основной реализации даже на этапе подготовки.

Команда опыта не выбирает новый ID сама, если output уже существует: существующий результат сохраняется, запуск этого фиксированного задания останавливается с указанием конфликта. Новую репликацию можно явно назначить отдельно. SDK/source SHA mismatch — точная подготовительная ошибка, не повод автоматически fetch другой branch, переписать tests или обойти admission.

## Ресурсные опыты тоже обязаны касаться обучения

- Frozen transpose: тот же native Transformer/LoRA/Trainer, одинаковые targets и updates. Кэш только для неизменной base weight; no cache trainable A/B. Если база меняется, опыт не имеет права держать устаревший transpose. Первое заполнение и цена удержания массива измеряются.
- BPE copy: сравнивается само обучение vocabulary/merges на фиксированном corpus, участвующее в `KnnLogicalUnit.Train`. Encode equality — контроль функции после Train, не самостоятельный serving benchmark. Не заявлять улучшение KNN accuracy без собственного соответствующего измерения.
- Reference reuse из предыдущего пакета: повторяются те же model-visible pairs в настоящем DPO; reference действительно frozen; первая miss и cache memory включены. Это отдельная уже найденная гипотеза, а не вариант нового Linear cache.

## Общий проверочный промпт для ревью конкретной карточки

> Проверь только указанную карточку и её source-copy. Сопоставь заявленный фактор с actual writer/state/reader; проверь, что frozen материал достигает ветви и не меняет одновременно второй механизм. Проверь exact paths/commands/inputs/counts и отсутствие записи в production или protected. Сравни исходные native blocks и список намеренных diff. Не запускай обучение, CI, test suite или второй домен без отдельного поручения на этот запуск.
>
> Любое измеренное улучшение полезного показателя считается успехом по этому показателю и домену; рост точности не обязателен. Рядом должны быть остальные измеренные изменения, включая ухудшения. Статус NOT_RUN нельзя превращать в measured gain, source hash — в learned quality, а correct argmax на нулевых весах — в приобретённое умение. Верни конкретные замечания с файлами/строками и минимальной поправкой. Не объявляй всю карточку невалидной только из-за deterministic kNN или отсутствия нового Train в доказанной restore-зависимости.
