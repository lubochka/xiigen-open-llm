**B — исторический реально обучавшийся DPO, ДРУГАЯ архитектура:** [DesignToCode `8f20ceb` runner](https://github.com/lubochka/llm_mvp_core/blob/8f20ceb8a9bfbadab2ad309226c47dd76e714548/experiments-v2/INTERNAL-TRAIN-READY-V191/runner/InternalTrainReadyDpoRunner/Program.cs#L44-L98) обучал `LlmModel` и сохранял веса/checkpoint. **C — выученные дискретные Translation Units:** [TranslationMachine](https://github.com/lubochka/llm_mvp_core/blob/216a1f3d6af3f40ceef081dc168b07e4ce3934f9/27.TranslationDomain/TranslationMachine.cs) владеет `SemanticTokenizerUnit`, `ExecutorUnit`, `QualityVerifierUnit`, shared [TranslationKnnStore](https://github.com/lubochka/llm_mvp_core/blob/216a1f3d6af3f40ceef081dc168b07e4ce3934f9/27.TranslationDomain/TranslationTrainedUnits.cs). **D — исторические эксперименты KNN, matrix, ranking, replay:** [E09/E34/E43 evidence](02-HISTORICAL-EXPERIMENTS.md) и [matrix→KNN исправления интерпретации](12-MATRIX-TO-KNN-EXPERIMENT-MISREADS.md). E43 replay `.3226→.3978` относился к bigram retention, не q/v LoRA. `FAIL` исторической матрицы **не отвергает** ту же функцию в KNN — требуется новый recipient-specific test.

Ранее подробно разобраны [C#500 и ENRU500](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-LEARNING-RECOVERY-AND-CODE-AUDIT.md): C# `500 pairs (25×20 templates), 50 optimizer steps, LoRA changed, free 0/3→0/3, margin +.0012275314`; EN→RU `500, +50 steps, free 0/4→0/4, margin +.0001100063`. `0/n` на столь маленькой панели не доказывает глобальной бесполезности DPO, но **нет наблюдаемого улучшения на этих опубликованных free cases**. Random B0 `vocab=629, hidden=512, layers=4`, q/v rank8 LoRA, greedy decode — крайне важные отличия от компетентного языкового базиса.

## 3. Матрица доменов: НЕ всякий KNN feature нужен всем

| Domain / output law | Релевантные механизмы | Anti-leakage / negative contrast |
| --- | --- | --- |
| **EN↔RU** | морфология, согласование рода/числа/лица, POS, word order, phrase mapping, directional KNN, negation, verb tense, open vocab | `I/you/he/she`, `not/never`, novel names, RU→EN vs EN→RU, 12–24 source-disjoint |
| **Task orchestration** | typed plan/step state, dependencies, graph closure, conditions, warnings, rule conflict | шаг A зависит от B, B failing, false success/timeout, source of action; verify actual execution not JSON only |
| **Figma→HTML+CSS** | tree/parent-child, containment, positions, alignment, CSS cascade, responsive constraints | перемещение узла, sibling reorder, conflicting CSS selectors, independent screenshot/DOM measure (не токеновый BLEU) |
| **C# code docs** | Roslyn AST, nullable operators `?.`, `??`, `!`, overloads, control flow, exceptions, type inference | минимальные пары `?.` vs `.`, `??` vs `||`, null vs throw, method return types, preserve identifiers |
| **Angular docs** | TS template AST, lifecycle, inputs/outputs, RxJS subscriptions, version-specific syntax | standalone vs module, signal vs observable, async, teardown, pinned Angular version |
| **SQL docs** | query parse AST, joins, `NOT EXISTS`, `IS NOT NULL`, null three-valued logic, CTE scope, operator order | `LEFT JOIN` vs `INNER`, swapped predicate, `NOT IN` with NULL, dialect/version pinned |
| **DPO construction itself** | source/target pair polarity, law groundedness, chosen/rejected author, CODEX selection & double grading, no-op detection, counterfactual diversity | TIE/BOTH_BAD, same-model-visible pair, invalid provenance, family-disjoint blind Student improvement |

**Правило выбора:** AST/positional feature полезен там, где имеет проверяемый закон (C#/SQL, semantic sentence order, Figma DOM), а для широкого semantic retrieval может быть лишним. Сравнивать отдельно `bag-only`, `order`, `AST`, `domain-hybrid` на **одинаковых** записях, без навешивания AST во всех доменах по умолчанию.

## 4. Приоритетная последовательность шести быстрых причинных опытов (не повторить ещё 500 неясных DPO)

1. **P0 recipient + tiny learnability**, 8–32 cases: trained Unit/KNN vs random B0 DPO vs short SFT→DPO; exact own saved candidate + cold readback; сравнить free-response на отдельных 12 blind cases (см. [RP01 DIAG pack](../Kiro-Xiigen-RP01-Learning-First-Slice-Pack/RP01-2026-10-16-CAUSAL-LEARNING-DIAGNOSTIC-PACK.md)).
2. **P0 model-visible DPO and gradient**: 4 same-prompt law pairs; RAW vs exact-v2 vs legacy bridge, assert actual chosen/rejected token ID divergence and response mask; one finite-diff gradient; provenance и изменённый learned recipient прежде всей кампании ([N16 visible pair](16-TRANSLATION-DPO-MODEL-VISIBLE-PAIR-COLLAPSE.md)).
3. **P1 AST/ordering vs generic kNN**: 12 or 24 paired source-disjoint C#/SQL/ENRU problems, fixed retrieval corpus, score semantic correctness/retrieval coverage per domain; negatives from operator/polarity minimal contrasts ([E09](12-MATRIX-TO-KNN-EXPERIMENT-MISREADS.md)).
4. **P1 learned state/restore**: 8 lessons / 12 requests, current vs fresh reopen, compare Unit/LoRA/vector index and true consumer, not metadata export; compare one-lesson additive effect and replay retention.
5. **P1 NEW N35 product chain**: 12 ENRU cases + 2×2 negator retention/confidence ablation and 3 affirmative controls; compare *correct-and-returned*, wrong-high-confidence, abstention, cold-restore parity ([MICRO-N35](35-MICRO-NEGATION-WORDMAP-CONFIDENCE-FACTORIAL-2026-10-16.md)).

6. **P1 NEW N36 unknown-domain gate**, 12 train/dev class labels + 24 source-family-disjoint cases: historical vector-score vs current post-verifier scalar, false-known, correctness + abstain + real-domain trade-off ([N36](36-NEW-E46-SYNTHETIC-FAIL-MISREAD-AND-POST-VERIFIER-NOVELTY-SIGNAL-ERASURE-2026-10-16.md)). Исторический `passed=false` в synthetic без gain не считать доказательством бесполезности способа для KNN.

**Stop logic:** не масштабировать обучение по 500 пока 8–32 exact tiny train-only случаев не способны поднять train target utility; не переписывать scorer/historical receipts; нельзя лечить KNN, если он не в active RP01 consumer; нельзя объявлять эксперимент успешным по `PASS` unit tests без independent semantic evaluation.

## 5. Реальные ветки: evidence ≠ наличие имени

Проверены существование и heads: `DesignToCode@8f20ceb8` (есть исходники и реальные V191/V210 receipts); `DesignToCode-clean@e346b88a`; `language_translate@f6032aff`; `external_domains@3036a01a`; `orchestrator-extensions@b293045b`; `main@f84c6741`; `codex/dpo-implementation-s04@f84c6741`. **Наличие ветки и наличие одного старого результата НЕ подтверждают, что весь родственный обучающий path мигрировал в действующий `codex/dpo-implementation`.** `language_translate` в просмотренном историческом ref не содержит тот же `27.TranslationDomain/TranslationTrainedUnits.cs` на том же пути; это повод искать исходные source owners, а не говорить «ветка не имела обучения». Для любой положительной исторической метрики нужны commit SHA, dataset split hash, true learner, checkpoint format, post-restore consumer, paired evaluation IDs и caveats.

Критически: `DesignToCode` использовал другой hash-based encoder и включал `Chosen:`/`Rejected:` маркеры внутрь token stream. Это реальный **методологический shortcut risk** старых тренингов и не модель того, как должен работать новый точный DPO. См. [real historical training](11-CROSS-BRANCH-REAL-LEARNING-RESULTS.md).

**Неподменяемые роли:** CODEX с моделью **Astra 6 UltraCode выполняет человеческую роль выбора/утверждения случая**, затем **тот же класс CODEX/Astra независимо проверяет точную пару**, и **отдельная независимая CODEX/Astra оценка** судит final Student/Unit responses. **Разрешённая внешняя открытая китайская модель создаёт обе стороны настоящей DPO: `chosen` И `rejected`.** CODEX не выдаёт synthetic proxy за китайского автора. Указание `Astra-synthetic-dev` допустимо только при честном фактическом авторстве/разметке, не как замена `open Chinese teacher`.

**Не выполнено:** нативные .NET причинные тесты, самостоятельный вызов CODEX Astra 6 UltraCode, генерация реальных китайских DPO, независимый blind judge, полный checkout/сопоставление всех веток, полный индексированный full-text просмотр всех 262 файлов и всех RAG. Поэтому итог здесь — приоритизированная **карта гипотез с source доказательствами и экспериментами**, а НЕ доказанная двадцать одна причина деградации и НЕ acceptance ремонта. Публикация — только `xiigen-planning/.../replanning/possibleDifs`; protected core каталог остаётся READ_ONLY.
