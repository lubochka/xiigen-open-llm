# 47. Восстановление language_translate: внутренние различия и новые гипотезы

**Дата: 19 октября 2026. Сначала — восстановительные опыты R00–R04 по `language_translate`; затем — шесть новых конкретных гипотез LT-N01–LT-N06.** Пакет сопоставляет исходники, реальные сохранённые положительные результаты, неудачу RP01 и прежние каталоги различий. Для каждого нового механизма заданы короткий опыт, предметная область, наблюдаемый результат и условие опровержения.

**Главный вывод:** успехи исторической ветки относятся к разным получателям — контекстному словарю, структурной KNN-памяти, счётчикам переходов и action-классификатору. Несколько этих реализаций сохранились в current практически без изменения. Проверять нужно, какие признаки и уроки дошли до них, какое обученное состояние восстановлено и вызывает ли его обычный потребитель. Нынешний нейронный RP01 действительно обновляет подключённые q/v-LoRA; это не доказывает переноса в них способности другого исторического learner. Подробные source traces: [01](01-LANGUAGE-TRANSLATE-RESTORATION-FIRST.md), [02](02-NEURAL-AND-UNIT-INTERNALS.md), [04](04-STATE-AND-RESTORE.md).

## Первыми выполнить именно восстановительные опыты

| Приоритет | Опыт и историческое основание | Что сравнить в короткой проверке | Применимость |
|---|---|---|---|
| **R00** | Точный `language_translate` donor → состояние → обычный ответ | Donor с его checkpoint/corpus/tokenizer; current штатный путь; один целевой перенос. После ответа — fresh-process restore. Диагностическая строка о направлении не считается переводом | Выбранная способность и её реальный Unit/Flow; обязательный первый шаг |
| **R01** | Контекстный выбор значения, E26: **0.40→1.00** на 15 исторических случаях | При одинаковом материале выключить/включить вклад левого и правого контекста в ranking значений; проверить полный перевод неоднозначной фразы | Прежде всего RU→EN технический перевод; EN→RU отдельно. Исторически fixed dictionary/manual tags, без neural updates |
| **R02** | Структурный KNN, E09: **0.2413→0.3507** в сохранённом run | Один semantic target codec, один split и candidate pool; изменить только вклад AST-контекста в distance и проверить выбранное обычное действие | C# next-action/continuation, с отдельными if/loop/try/async случаями |
| **R03** | Сохранение старого материала, E43: **0.3226→0.3978** | Одна neural policy и новые уроки; serving memory с новым материалом против той же памяти с разрешёнными старыми примерами; old/new ответы и restore | C# продолжение или перевод, раздельные панели; исторический E43 — счётный bigram learner |
| **R04** | Action KNN, E14: **0.75→1.00** на малой панели; также есть **0.8393→0.8750** и отрицательный run **0.8824→0.8676** | Сохранить положительный неконфликтный контроль; проверить конкретный typed-feature repair из LT-N01 при тех же labels/k/corpus | C# action prediction; пригодность самих action labels оценивается отдельно |

Источники каждой цифры — закреплённые donor JSON и соответствующий runner в [главе 01](01-LANGUAGE-TRANSLATE-RESTORATION-FIRST.md). Это **архивные наблюдения с разными метриками и ограничениями**, а не выполненные здесь A/B или обещанный размер улучшения. Например, у E09 панели baseline/KNN различаются; E26 задаёт словарь и context tags кодом; E43 заново строит bigram counts. Положительный эффект сохранён вместе с точным объектом, в котором он наблюдался.

История «неудачный matrix опыт стал успешным после переноса той же функции в KNN» остаётся существенным направлением проверки. Для рассмотренных архивов тождество задачи, features, assets и метрики такой пары опытов полностью не установлено. Поэтому R02 проверяет вклад конкретного сигнала в KNN на одинаковой панели; старое `FAIL` не принимается как запрет использовать сигнал в другой функции или домене.

## Шесть новых конкретных гипотез

«Новая» здесь означает, что именно эта причинная цепочка/различающий опыт не найдены при адресной сверке двух каталогов. Это не шесть доказанных причин неудачи RP01.

| ID | Что обнаружено в коде | Что быстро проверить | Статус и область |
|---|---|---|---|
| **LT-N01** | `List<int>` и `Task<int>` дают одинаковые 30 AST-kind frequencies, но `ActionLabelGenerator` требует разных labels | Native extraction для 8 контрастов и controls; те же labels/k, один typed feature; fidelity к label и полезность действия отдельно | Новый конкретный унаследованный риск C#. [Карточка](03-NEW-KNN-HYPOTHESES.md) |
| **LT-N02** | `MethodKnn` создаёт next-method pairs через границу независимых классов одного файла | Те же methods/features, запрет только cross-class pairs; перестановка независимых классов и одна class-local панель | Унаследованный риск для дополнения класса. Для порядка всего файла может быть намеренной политикой. [Карточка](03-NEW-KNN-HYPOTHESES.md) |
| **LT-N03** | `Compile` добавляет source в учебный корпус до prediction; повторный анализ снова увеличивает частотный вес | Отдельно frozen evaluation; отдельно 1 против 10 Compile одинаковых bytes с document-id replacement control | Унаследованный C# grammar/frequency механизм; intentional online adaptation оценивается отдельно. [Карточка](03-NEW-KNN-HYPOTHESES.md) |
| **LT-N04** | Повторный export в прежний каталог меняет файлы A до проверки старого index при publish B; CLI load не использует тот же guard | Тот же checkpoint: без export / прежний каталог / новый каталог; hashes, publish, фактически загруженные bytes, 24 ответа | Текущий translation asset lifecycle; не доказанная gradient-регрессия RP01. [Карточка](04-STATE-AND-RESTORE.md) |
| **LT-N05** | Рост постороннего морфологического семейства меняет global maximum и расстояния между старыми словами, даже после полного rebuild | Фиксированные embeddings/candidates/own families; только другой denominator policy. Отдельно контроль нормы base vectors | Условный риск переноса donor morphology; ordinary caller и learning gain appender не установлены. Формульный rank flip воспроизведён. [Карточка](05-ADDITIONAL-MECHANISM-HYPOTHESES.md) |
| **LT-N06** | Тот же cosine scheduler после TotalSteps снова повышает LR; supervised caller способен продолжать | Девять updates на плечо при horizon=4, с/без clamp; actual LR, update norms и paired ответы | Условный incremental/SFT риск. Обычный RP01 DPO использует другой LR path. Формульный рост воспроизведён. [Карточка](05-ADDITIONAL-MECHANISM-HYPOTHESES.md) |

LT-N01–03 присутствуют и в `language_translate`, и в current: функциональные diff соответствующих трёх файлов ограничены добавлением лицензии. Они могут проявиться на другой панели и объяснить ограничения переносимого learner, но не доказывают появление ошибки при межветочном переносе. LT-N04 — поздний asset workflow; LT-N05 — проверка перед восстановлением опциональной функции; LT-N06 требует actual steps сверх horizon.

## Актуальность: уже выполненные исправления не ставятся заново в очередь

В архиве 18 октября есть два разных рода результатов, которые нужно сохранить одновременно:

- **Память переводчика действительно учится.** P125 ordinary Flow дал 0/24→19/24 после 8 уроков. Выделенное исправление доставки `phrase_mappings` дало **11/24→19/24**, mappings **0→16**, новые сочетания **0/8→8/8**. Холодное восстановление сохранило **все 24 наблюдаемых ответа и 19 правильных**, без новых уроков. Это discrete memory, не neural LoRA. В 19/24 по-прежнему не входят две явные смысловые ошибки и неоднозначный strict-fail случай; accepted-but-wrong нельзя скрывать ростом coverage. [Источники и ограничения](04-STATE-AND-RESTORE.md).
- **Исправление gradient пока не дало показанного смыслового прироста на короткой панели.** Embedding scatter-add, Linear bias backward и fractional legacy DPO mask уже исправлялись; сохранённые восьмишаговые проверки качества остались **0/24→0/24**. Embedding опыт был full-model SFT с 55 trainable tensors, а не штатный q/v-DPO. [Внутренние механизмы и отчёты](02-NEURAL-AND-UNIT-INTERNALS.md).

Текущий код уже содержит реальные attached LoRA, frozen reference, DPO optimizer/RNG continuation и чтение `phrase_mappings` в указанном ingress. Для этих путей нельзя оставлять старые общие формулировки «не подключено», «всегда забывается», «поле нигде не читается». В другом producer/consumer тот же вопрос проверяется своей трассой, без переноса чужого PASS.
