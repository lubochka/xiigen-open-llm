## 6.6. Короткий исполнимый порядок: от восстановления к новым причинам

Предлагаемые новые native-эксперименты имеют статус **PLAN / NOT_RUN**. Порядок не требует сначала реализовать все 125 семейств или выполнять большой общий test suite.

| Очерёдность | Минимальная работа и неизменяемые условия | Какой результат решает следующий шаг |
|---|---|---|
| **1. R00 и положительный контроль** | Найти точный `language_translate` owner/asset/task и ordinary consumer; сопоставить donor-native, current-native и целевой перенос. Отдельно воспроизвести нынешний 8-lesson/24-case memory контроль, если используется project 27. | Нужная способность реально воспроизводится, использован ожидаемый state, старые правильные ответы известны. | **2. R01–R04 из главы 01, по домену** | RU→EN: левый/правый контекст при одинаковой памяти и query schema. C#: AST-distance либо typed feature при одинаковых labels/k/split. Retention: старый corpus в serving memory при одинаковой neural policy. Один контраст за запуск. | Обычный ответ сохраняет смысл и приобретает нужное контекстное различие; old-law retention не ухудшается. Исторические E26/E09/E43/E14 выбирают механизм и контроль, их цифры не назначаются ожидаемым gain. |

Для C# scorer проверяет именно требуемое поведение/действие и область определения; для перевода — полный смысл, а не token overlap. Агрегирование разных доменов одним accuracy скроет область полезности сигнала.

### Минимальная запись одного опыта

| Поле | Что сохранить |
|---|---|
| Контракт и область | `experiment_id`, исходная гипотеза, domain, profile, owner/recipient, actual consumer, ожидаемый эффект и заранее записанное опровержение |
| Исходное состояние | Source/native commit, runtime/config, tokenizer/vector schema и SHA, checkpoint/adapter/corpus/index identity; optimizer/RNG/counters для нейронного пути |
| Учебный материал | Exact prompt/chosen/rejected, pair/source family IDs, роли автор/отбор/судья и фактические receipts; неизменный train/heldout split |
| Вмешательство | Одно изменённое свойство; что фиксировано; отдельные no-update/negative/irrelevant-domain controls; actual steps и schedule horizon |
| Реальное действие | Trace от material/feature до изменившегося state и обычного output; IDs соседей, route, loaded bytes, timestamps; число model blocks отдельно от числа trainable tensors |
| Результат | Raw before/after/restore answers, verdict и rationale на каждый случай; correct, wrong accepted, abstention, coverage, retention; wall time и RAM раздельно от teacher cost |
| Вывод | `IMPROVE`, `REGRESS`, `INCONCLUSIVE` либо `INVALID_EVIDENCE`, плюс native/source/formula evidence class и граница применимости |

### Роли и уровень доказательств

Для **новых DPO** CODEX с назначенной ролью `astra6ultracode` выбирает случаи; разрешённая внешняя открытая китайская модель создаёт **обе** exact стороны; отдельное CODEX-назначение независимо оценивает качество пары и затем обычные ответы Student. В протоколе фиксируется фактическая модель/версия и receipt, а не только желаемое имя. `BOTH_BAD`, `TIE` и `UNJUDGEABLE` сохраняются как такие результаты. Старые fixed fixtures и deterministic source-level counterexamples остаются контролями своего происхождения; им не приписывается новое teacher authorship. Storage/formula этапам без новых DPO не требуется искусственно добавлять генерацию пар.

| Что есть в этом пакете | Что этим установлено | Что не выполнено |
|---|---|---|
| Ссылки на закреплённые исходники и source trace | Условия, представление, update/load/call order, предполагаемый механизм | Новый native вызов соответствующих функций и новая оценка domain quality |
| Прочитанные архивные native JSON/reports | Указанный автором эксперимент с его HEAD, material, метрикой и ограничениями | Независимый rerun этого аудита на `a392…` |
| Python binary64 source-formula probes для LT-N05/06 | Для указанной модели формулы: nonlocal rank flip и повторный рост cosine LR; результаты и скрипт сохранены рядом | C# float/SIMD parity, native training, model/teacher calls и semantic quality measurement |
| Протоколы новых опытов | Воспроизводимое однофакторное вмешательство и критерий, позволяющий отказаться от гипотезы | Новые actual model runs, optimizer updates или принятие repair без результата |

Поэтому результаты Python имеют узкий статус **механистическая проверка формулы**. Они достаточны, чтобы обосновать следующий короткий native опыт; они не устанавливают историческую причину падения обучения. Работа считается восстановлением способности, когда конкретный consumer использует нужное обученное состояние, предметный эффект воспроизводится на объявленной панели и сохраняется после предусмотренного restore/продолжения.
