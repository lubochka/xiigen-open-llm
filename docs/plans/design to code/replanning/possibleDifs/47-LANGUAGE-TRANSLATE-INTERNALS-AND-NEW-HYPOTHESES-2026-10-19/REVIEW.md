## Поправки, внесённые по результатам проверки

1. **SFT/DPO сравнение:** SFT начинает с отдельной копии B0 и имеет явный бюджет. У существующего supervised Trainer отличаются targets, clipping и LR scheduler; такой опыт помечен как диагностика совокупности отличий пути. Для loss-only вывода нужен отдельно контролируемый response-only NLL. Восемь неудачных updates не доказывают недостаточную ёмкость.
2. **Embedding:** эффект 54/55→55/55 и 38 400 координат подписан как full-model SFT C50, 39 base+16 LoRA. Его не приписывают обычному frozen-base q/v-DPO.
3. **Качество пар:** проверка пригодности DPO материала сама по себе не получает причинный verdict о downstream quality без A/B обучения.
4. **Publication/load:** отказ old-index validation не означает, что существующий непроверяющий CLI loader обязательно откажет. Может загружаться переписанный asset с иной идентичностью.
5. **Scheduler:** до A/B фиксируется одинаковое RNG/dropout state. Повторный рост начинается при pre-call step > TotalSteps; DPO-only path исключён, смешанный DPO+supervised workflow рассматривается по стадиям.
6. **Домены:** граница класса меняет профиль задачи, не домен C#. AST и POS-context не назначены универсальными признаками перевода/кода.
7. **Дедуп и свежесть:** исправлены промежуточные счётчики корпуса и неоднозначные номера прежних документов. Все native result ссылки используют настоящий `docs/plans/replanning-possible-diffs/experimets/...`.
