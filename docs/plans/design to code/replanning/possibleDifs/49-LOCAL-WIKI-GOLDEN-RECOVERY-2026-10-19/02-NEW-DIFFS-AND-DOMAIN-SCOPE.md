**Дополнительный consumer gap:** в [`ProjectWikiTrainingOrchestrator` L7–53](https://github.com/lubochka/llm_mvp_core/blob/4945b8e85c17b5f150eb5b840d16bbdc4b506242/42.ProjectWikiDomain/ProjectWikiTrainingOrchestrator.cs#L7-L53) поле `_router` имеет тип **`ProjectWikiRequestRouterUnit` (статический)**, в [L205](https://github.com/lubochka/llm_mvp_core/blob/4945b8e85c17b5f150eb5b840d16bbdc4b506242/42.ProjectWikiDomain/ProjectWikiTrainingOrchestrator.cs#L205-L205) `_router.Route(prompt)`; оно НЕ использует `ProjectWikiRequestRoutingTrainableModel` напрямую. Старый gold orchestrator/общее поведение здесь могут иметь похожий deterministic seam; требуется отдельный trace, чтобы не объявлять регрессию без пары.

**Важная safety caveat:** `semanticQualityClaimed=false` может быть сознательной защёлкой без настоящей семантической проверки; **не поднимать до true и не убирать gate** ради метрики. Добавить независимый semantic evaluator, подтвердить `PublishedPolicyId→LoadedPolicyId→SelectedRoute`, разрешить безопасный fallback, а затем A/B на same held-out. **Домен:** документация/маршрутизация/оркестрация; не прямая причина EN→RU LoRA-качества без зависимости.

## G-W06 · P1 · Невозможный confidence rejection после clamp (математический факт в исходнике)

Текущая [`CalibratedConfidence` L330–348](https://github.com/lubochka/llm_mvp_core/blob/4945b8e85c17b5f150eb5b840d16bbdc4b506242/42.ProjectWikiDomain/ProjectWikiRequestRoutingTrainableModel.cs#L330-L348) возвращает `Math.Clamp(0.70+..., MinimumSelectionConfidence, 0.99)`. [`DecideOrDefer` L194–203](https://github.com/lubochka/llm_mvp_core/blob/4945b8e85c17b5f150eb5b840d16bbdc4b506242/42.ProjectWikiDomain/ProjectWikiRequestRoutingTrainableModel.cs#L194-L203) затем проверяет `confidence < MinimumSelectionConfidence`. После верхней формулы это условие **никогда не истинно для конечных корректных inputs**, поскольку результат зажат **снизу тем же порогом**. Это не снимает ранее выполнявшегося `topTwoMargin` или heldout gate; заявлять полный bypass неправильно.

**Почему важно:** score может пройти margin/gate, а calibrated-confidence threshold **не отбракует** неопределённую маршрутизацию — метрики «прошёл confidence» могут быть тавтологией. **Домен:** классификация / маршрутизация задач / wiki. **Проверить:** контролируемый margin чуть выше порога с нераспознанными токенами и новыми paraphrases; отдельно raw confidence / returned confidence / abstentions; wrong-route cost. Не менять смысл уже проверенных ответов ради немедленного PASS.

## G-W08 · P1 · Не возвращать старый substring classifier без контекстных отрицаний (новая гипотеза на исходниках)

Gold [`ContainsClientServerSignal`](https://github.com/lubochka/llm_mvp_core/blob/219d7ba89dc3ef43e03e17f1461ad96154d3dd7a/42.ProjectWikiDomain/ProjectWikiQueryPlanningFlow.cs#L550-L589) отмечает `client` по любому включению `frontend`, `ui`, `angular` и т. п.; отмечает `server` по `service`, `api`, `.net`, `controller`, затем возвращает `client && server`. Фраза **«Trace call flow inside this single C# service, without a frontend.»** содержит `service` и **`frontend` под отрицанием**. Согласно читаемым условиям старый классификатор склонен ошибочно считать её `ClientServerBusinessFlow`, current попадает в `WorkflowTrace` (не native evidence). Значит возврат gold алгоритма **вслепую** восстановит и ошибку.

**Новая гипотеза:** нужен *polarity-aware scope detection*, различающий наличия двух подсистем от их отрицаний, включая `without frontend`, `server only`, `no API`, «только бекенд»; но без агрессивного отбрасывания реальных client-server сценариев. **Домен:** запросы по архитектуре/коду, не универсальное правило перевода. **Малый опыт:** 4 настоящих full-stack prompts + 4 "без frontend" prompts + 4 double-negation/quoted code prompts; сравнить gold/current/C (потерянный route, но проверка negation context). Blind specificity/recall, правильная обработка кавычек. **Falsifier:** оригинальный `ContainsAny` уже где-то учитывает отрицание или конкретный native gold `DetectIntent` в таком вопросе не выбирает ClientServer — тогда исправить гипотезу; до исполнения только `SOURCE_PREDICTION`. [Negative control N01](05-CROSS-STACK-FIXTURE.json).
