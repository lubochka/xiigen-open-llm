## НЕОБХОДИМОЕ ПРАВИЛО — в каждой карточке и промпте

**Любое ФАКТИЧЕСКИ измеренное улучшение полезного показателя считается успехом именно по этому показателю и теме обучения. Accuracy увеличиваться НЕ обязана. Все остальные изменения, включая любые ухудшения, сообщаются рядом: quality/semantic law, correct/all, correct/answered, coverage, wrong accepted/all, forgotten laws, lessons/updates, time per unit of completed learning work and total wall time, peak RAM/VRAM, CPU time by real process counter, size of learned state, number of Unit/Flow/layers. Скорость training 0 updates — N/A, а не ускорение. Минимальный эффект с числами и корректными единицами — локальный успех, не «провал из-за порога 5%».**

**Любое измерение, не меняющее или не потребляющее что-либо на РЕАЛЬНОМ пути обучения, — НЕВАЛИДНЫЙ УЧЕБНЫЙ ЭКСПЕРИМЕНТ.** Никакого отдельного frozen decoding/scorer/report-only/cold restore без approved combined training A/B. Не добавлять фиктивные TrainBatchAsync (legacy +.01) ради прохождения gate. Если метрика меняется, но от неё НЕ зависит состав следующего lesson batch, весовой/памятный update или его readback в реальном обучении, ветка OUT_OF_LEARNING_SCOPE. Созданные ниже карточки не разрешены к исполнению; для каждой сначала личное письменное одобрение полной точной версии пользователя.

**Общий паспорт до кода:** pinned core SHA + donor SHA, выбранная тема обучения и задача, named recipient, настоящий TRAIN source и licenses, origin каждой DPO chosen/rejected стороны, независимый DEV/EXAM по source-family/file/time как подходит теме, one-factor A/B, запрет test-gold в learned state, input/output schema, accepted training rows, predeclared evaluator, A0/B0 checkpoint id+hash и проверка equivalence, A1/B1 updated state id+hash, реальные calls до/после через ОДНОГО ordinary consumer, выученные Unit/Flow IDs, мини-бюджет, все tradeoffs и reviewer. Если любой шаг отсутствует, статус NO-VALID-EXPERIMENT.

## EXP-N60-A — historical maximum vs latest *verified feedback* в переводческой учебной политике

- **Тема:** перевод. **Профиль первой проверки:** EN→RU, отдельная повторяемость RU→EN (не считать второй домен); topic_domain фиксирован.
- **Проверяемый фактор:** ONLY источник числового score для PromotionThresholdsFromMaxAccuracy: A = исторический best текущего Tatoeba loop; B = последняя разрешённая DEV/online feedback accuracy того же scorer. Формула 1-score/score, поисковая/структурная политика, модель, heuristic admission, golden rubric одинаковы; scoring policy НЕ менять (это иная гипотеза P58.4).
- **Настоящий получатель:** [TatoebaPilotLoopRunner admission→TrainRowsAsync](https://github.com/lubochka/llm_mvp_core/blob/f50b710a5eaa6a8f0468b07d5b2510342a1de7ba/27.TranslationDomain/TatoebaPilotLoopRunner.cs#L403-L454) → [BuildGeneralBatch→TrainStructuredBatchAsync](https://github.com/lubochka/llm_mvp_core/blob/f50b710a5eaa6a8f0468b07d5b2510342a1de7ba/27.TranslationDomain/TatoebaPilotLoopRunner.cs#L747-L770) → SemanticTokenizer/Executor/Verifier state (report each) → ordinary GetOrchestratorAsync().RunAsync. Не объявлять LoRA участником.
- **Предусловие (фальсификатор):** на ПРОВЕРЕННОМ DEV действительно last score < stored historical best. Нужна запись реальных scores, а не искусственно подставленные .9/.5. Если нет divergence в конкретных native историях — NOT_APPLICABLE, не тратить на A/B с одинаковыми decisions.
- **A0/B0:** побайтово равные копии одного законного machine checkpoint (включая 6 Executors, semantic tokenizer, source law version), одинаковая последовательность lesson candidates, одинаковый stored best, latest observed DEV score и исходные ordinary outputs на 4–8 замороженных EXAM запросах (не доступны policy).
- **Train:** согласованный минимум 2 последующих пакета по 2 TRAIN-row, с теми же источниками, порядком, batch size и lexicon generation; A и B вправе отобрать РАЗНЫЕ будущие уроки по policy, это и есть *измеряемое следствие фактора*. Обязательная запись всех предложенных/принятых/отклонённых lesson IDs и причин, действительно применённых updates, recipient UnitIds; ни один EXAM row в обучение не попадает.
- **A1/B1:** сохранить настоящие обновлённые memory hashes и counters; ordinary output через соответствующий Flow на тех же 4–8 EXAM, дополнительно 4 retention cases и 2 high-risk negation/actor cases. Score как внутренний proof readback не заменяет результат перевода.
- **Успех:** отдельно любой положительный полезный delta (quality, coverage при сохранении laws, меньше wrong accept, latency, RAM, training cost per accepted legal lesson); остальное рядом и даже если accuracy хуже, например меньше CPU_ms при одинаковой работе — локальный cost success. В отчёте абсолютные числители/знаменатели, no "relative improvement" при нулевом baseline.
- **Контроли:** (i) текущий score = best → одинаковая policy (должно быть no-effect), (ii) score-order frozen, (iii) скрипт/направление валидны, (iv) коррекция wrong lessons не попадает в защищённую EXAM. Если A/B выбирают одинаковые IDs либо нет реальных Unit-state writes — эффект learning НЕ доказан, никакой «симуляции правильных ответов».
- **Бюджет:** 1 маленький native harness, минимум 2+2 lesson batches и 8+4+2 EXAM probes, не Windows CI матрица. Если набор невозможно прогнать существующим Tatoeba API без продакшен-patch, допустимо описать минимальную test seam и оставить CONDITIONAL вместо выдуманного результата.

## EXP-N60-B — доступность feedback в текущем цикле vs предыдущем (независимо от max)

- **Тема:** перевод EN→RU на первом проходе; другой direction отдельно. **Фактор:** момент использования *допустимой DEV/online feedback* для curriculum admission (pre-decision vs post-feedback). Формулу best-vs-current фиксировать ОДИНАКОВО в A/B; нельзя сочетать с EXP-N60-A.
- **Источник:** [ShouldPromote вызван ДО RunCycleAsync](https://github.com/lubochka/llm_mvp_core/blob/f50b710a5eaa6a8f0468b07d5b2510342a1de7ba/27.TranslationDomain/TatoebaPilotLoopRunner.cs#L403-L417), затем [реальный TrainRowsAsync](https://github.com/lubochka/llm_mvp_core/blob/f50b710a5eaa6a8f0468b07d5b2510342a1de7ba/27.TranslationDomain/TatoebaPilotLoopRunner.cs#L444-L454). Если feedback в реальности является SEALED exam, B использует forbidden leakage: **NOT_ELIGIBLE**; не запускать.
- **A0/B0:** одинаковый исходный обученный checkpoint, frozen предыдущие scores и candidate dataset. До обновления показать ряд ordinary DEV feedback, но EXAM gold остаётся недоступен selection.
- **TRAIN intervention:** A применяет текущую временную политику, B — заранее утверждённую feedback policy без exam leak; получить accepted lesson IDs, применить каждый реально TrainRowsAsync → learner state, 2 минимальных online cycles, одинаковые пределы source families и total candidate work. Если B требует доступ к TEST gold до формального train admission, запретить, описать только source gap.
- **A1/B1 EXAM:** 4+ независимые ненаблюдавшиеся предложения, 2 исправления отрицания/актора; вывод до/после, learning reads/writes, counts, CPU/RAM/time and negative tradeoffs. Reject enhancement, если он улучшает только latency frozen scorer или использует EXAM labels.
- **Предельная трактовка:** одно улучшение любой полезной оси — успех для EN→RU данной панели; публикация в production требует отдельного решения, выбранные policy не должны учиться на тестовых answers.

## EXP-N60-DPO — проверить реальную LoRA vs легитимный memory baseline, но НЕ считать их одним обучением

- **Домен/профили:** документация C# (документирование ветвей метода), отдельно перевод EN→RU; по 2–4 качественные DPO пары и 4 heldout задачи на profile.
- **Реальный получатель нейронного A/B:** один и тот же подходящий pre-trained base и tokenizer, идентичные q/v LoRA init/reference/AdamW moments, одинаковый budget и source-disjoint EXAM. A pairs содержат только стилистические поверхностные contrast, B содержат source-confirmed semantic law contrast. Оба действительно train через DpoTrainer и возвращают обновлённые LoRA tensors. Chosen/rejected обе получены разрешённым источником, с независимым quality/admission; не генерировать source-id leakage.
- **Проверка:** A0/B0 full free-generation outputs, A1/B1 full outputs на тех же EXAM + teaching margin, negative laws, GPU/CPU/RAM, tokens/sec, time/update and actual count; 16 LoRA changed не объявлять ответом на задачу. Пользовательский score учитывает каждый измеренный полезный gain, все компромиссы записаны.
- **Memory comparison:** отдельно historical P125 ordinary Flow — как ориентир, НО не как плечо того же one-factor neural экспериментa. Нельзя назвать смешанное LoRA+memory улучшение доказательством LoRA.
- **Нельзя запускать**, если текущий Student до DPO не способен представить target-language bytes, checkpoint несовместим с tokenizer или нарушена независимость EXAM. Сначала восстановить warm base из исторического донорского source, иначе сравнивать формальную оптимизацию бессмысленно.
