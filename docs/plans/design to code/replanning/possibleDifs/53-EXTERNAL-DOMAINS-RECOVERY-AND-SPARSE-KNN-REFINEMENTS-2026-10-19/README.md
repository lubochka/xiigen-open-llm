# Сначала восстановить `external_domains`, затем проверять новые условия

**19 октября 2026 · Исследование с доказательствами и малыми опытами.**

Главный маршрут — [00: восстановление успешных механизмов `external_domains`](00-EXTERNAL-DOMAINS-RECOVERY-FIRST.md). Он поставлен перед новыми гипотезами, как потребовал пользователь. В нём шесть шагов R0–R5: найти реальное состояние и consumer; восстановить память POS-порядка E25; двусторонний контекст E26; структурный KNN E09 с корректным сравнением E07; обучаемую память E40V2; удержание через E43 с явным контрактом replay.

Сохранённые успехи повторно подтверждены raw receipts, включая E40V2 **66.67% → 100%**, тогда как соседний E40-v1 имел **0% → 0%**. Отрицательная версия не отменяет успешную; новые независимые source families всё ещё нужны. E26 заранее заполнен, E43 перестраивает счётчики, E25/E40V2 обучают память — эти результаты не объединены в одно утверждение об успешном neural DPO. [Первичные результаты и пределы](00-EXTERNAL-DOMAINS-RECOVERY-FIRST.md).
