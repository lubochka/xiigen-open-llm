Поэтому исходные метрики остаются, но точные уровни **Tier2 = малый позитивный**, **Tier3 = большой отрицательный**; прежнее Tier1/Tier2 является документарной ошибкой, не истинным изменением результатов. Вывод по обоим уровням остаётся *inconclusive for scalable generalization*. Обязательное сравнение использует same-file, same-label, same-denominator, same preprocessing; multi-seed/source-family split.

Проверить на одних файлах глобальный mapper и matched prediction set. Пока не утверждаем, что 45.33% — выдумка или что нарушилась каждая prediction; только о несопоставимости опубликованных чисел.

## 4. Чёткое разграничение двух смыслов «матрица»

1. **Линейная алгебра (`33.MatrixAlgorithms`, E12):** разреженное умножение, SIMD/SVD и low-rank compression — оптимизация представления/численной стоимости. Переход в kNN сам по себе не учит семантике; полезная матричная операция могла остаться внутри encoder/scorer. Требуется exact commit diff и algorithm lineage.
2. **Обучаемый ILearningUnit как domain/vector/many→many mapping** из [исходного задания, строки 12–23](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/design%20to%20code%20session/original%20task.md#L12-L23): «упрощённая матрица» в концептуальном смысле. Если её классификатор/память оказались полезнее как KNN retrieval, это **перемена архитектурного получателя/места использования**. Нельзя объявлять такое поведение «детерминированным злом» без замера query-specific policy.

**Статус связи matrix-failed → KNN-succeeded: `USER-REPORTED, SOURCE-LINEAGE-NOT_YET_PROVEN`.** В источниках найдены разные Tier одной KNN-функции и конкретные successful KNN runs; точного commit с old matrix-only learner → refactored KNN learner в просмотренных ветках/результатах **не установлено**. Это обязательная дальнейшая задача, а не опровержение свидетельства пользователя.

## 5. План доказательства переноса без переписывания реализации

1. `HIST-LINEAGE`: для каждого заявленного «неудачного» matrix variant отыскать commit SHA, старый `RunId`, входные данные, features, metric, threshold, raw JSON и точку переноса (PR/file rename/diff). Построить table `mechanism_key, old_path@SHA, new_path@SHA, method, input-schema, learner-state, owner, consumer, run-id, common eval-family`.
2. `HIST-SAME-PANEL`: построить file/family-level split; на одном и том же validation set сравнить old matrix, old KNN, latest KNN exact-index, latest HNSW и lexical-fusion, не смешивая artifacts с разной семантикой. Каждая модель получает одинаковый admissible pool, corpus и признаки; когда нельзя — явно указывать разницу условий.
3. `AB1 REPRESENTATION`: Roslyn structural vs hashed BPE vs transformer embeddings, все при одном exact kNN scorer. Показатели: Recall@k, top1, semantic law pass, collision rate, negation/number/stack/dialect sensitivity.
4. `AB2 SCORING`: E34 tuned alpha vs latest fixed .45/.35/.20 vs lexical-only vs vector-only, при одинаковом frozen candidate pool; веса обучать/подбирать на development, итог считать на sealed exam.
5. `AB3 NEIGHBOR CONSUMPTION`: frozen ranked candidates; первый hit против top-k evidence fusion и lawful arbiter с positive/negative/warning. Правила authority, veto, return abstain и provenance проверяются **после** сохранения top-k; не объявлять итог «учит модель» без обновляемого scorer/state.
6. `AB4 INDEX`: exact scan (`06.VectorSearch/BruteForceIndex.cs`) vs HNSW на одной метрике/координатах; отдельный тест encoder truncation, reindex после изменения обучаемой projection, recall, latency и saved-index cold load.

Условия результата: paired **per-task** показатели и ошибки, небольшое доверительное/неопределённое поле по family, затраты wall/RSS/VRAM/index memory; без post-hoc смены порога и без Windows Actions как primary score. Выход `IMPROVE / REGRESS / INCONCLUSIVE / INVALID_COMPARISON`. Плохой сценарий: увеличить k с 3 до 30, не изменив first-hit consumer, и записать рост neighbors как улучшение качества.

## 6. Provenance-lock для всех последующих отчётов

`old_ref SHA → old_method → old_artifact.run_id → original metric/denominator → new_ref SHA → new_method → shared feature contract → ranker/arbiter consumer → same-panel result → domain-law check`. Любой пропущенный компонент — не `PROVEN_PORT`, а `UNVERIFIED_HYPOTHESIS`. Сохранить и положительные, и отрицательные Tier; не восстанавливать «матрица проиграла» по непарному сравнению.
