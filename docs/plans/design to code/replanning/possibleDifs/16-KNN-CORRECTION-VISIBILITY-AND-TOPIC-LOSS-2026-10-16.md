## Короткий ответ человеку
У KNN-памяти раннего переводческого продукта могут теряться **не сами записи**, а **право более позднего успешного исправления влиять на ответ**. Программа действительно запоминает новые пары, но при выдаче кандидатов сначала берёт старые. Второй, независимый пробел: контекст предметной области передаётся в `ExecutorUnit.Execute(..., topicDomain)`, но не участвует ни в выборе выученного перевода, ни в ключах сохранения. Эти риски не равны доказанной проблеме LoRA и **не объясняют автоматически RP01 Student free 0/4**: для этого нужен actual caller trace.

## N16-KNN-01 · P0 conditional: поздняя правильная DPO/Unit correction невидима из-за FIFO при `k`
**Исходный контракт и конкретный код:**
- [TranslationUnitContracts.cs L183–214](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationUnitContracts.cs#L183-L214): `TranslationKnnStore.AddPair` делает `bucket.Add((sourceText,targetText))`, а собственный комментарий обещает, что «later pairs have higher DPO preference signal».
- [TranslationUnitContracts.cs L216–245](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationUnitContracts.cs#L216-L245): `FindNearest` при точном signature делает `exact.Take(k)` (берёт *первые*, а не новые записи).
- [TranslationUnitContracts.cs L247–298](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationUnitContracts.cs#L247-L298): боевой `FindNearestCascade → FindExactWithSourceGuard` сначала фильтрует по источнику, но затем вновь `admissible.Take(k)`. Здесь нет recency/quality/feedback rerank или supersession.
- [TranslationTrainedUnits.cs L333–365](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L333-L365): `ExecutorUnit.TrySelectKnnCandidate` запрашивает `k:5` и возвращает **первый** target, прошедший некоторые проверки направления и source similarity.
- [TranslationTrainedUnits.cs L404–436](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L404-L436): `TrainOnExample` действительно добавляет новые preferred outputs в эту KNN-store; rejected сам по себе не является новым supervision для scorer.

**Механический контрпример (вывод из метода, НЕ выполненный C# run):** при одной signature и одном совместимом source записать 5 прежних targets A1…A5 и затем правильное исправление B. `FindNearestCascade(..., k:5)` возвращает A1…A5 и **никогда B**. Если старые A совместимы с валидаторами, `ExecutorUnit` берёт A1. Новый `TrainOnExample(B)` увеличил счётчик обучения, но не изменил ответ.

**Уточнения / ложноположительные выводы:** прежде чем назвать конкретный production answer ошибочным, проверить, что (1) `ExecutorUnit` дошёл именно до KNN, а не `_exactSourceMap`/phrase/word map; (2) law guard не исключил прежние A; (3) B не попал в другой более приоритетный signature bucket; (4) старые цели действительно неверны согласно независимой разметке. `FindNearest` не назначает DPO-веса, хотя комментарий заявляет preference signal. Не путать с [MICRO-KNN-ORDER-01](11A-MICRO-KNN-ORDER-CAUSAL-PILOT.md): там сравнивался **порядок слов в векторе**, здесь — **порядок обучающих исправлений во времени**.

**Мини-фальсификатор:** direct `TranslationKnnStore` с 6 условно одинаковыми admissible source/signature pairs, затем query `k=5`; reverse train order без изменения содержания; проверить list of target IDs. При равенстве результата или если B присутствует в top5, пересмотреть источник/вызовы. Влияние на полезный перевод — отдельный L1 опыт по [16 microprotocol](16-MICRO-KNN-CORRECTION-AND-DPO-NOOP-PROTOCOL.md).

## N16-UNIT-02 · P1 conditional: контекст предметной области теряется до принятия решения
- [TranslationTrainedUnits.cs L242–264](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L242-L264): direction-specific `ExecutorUnit`, словари `_wordMap`, `_phraseMap`, `_exactSourceMap` содержат **source/lemma/concept**, без TopicDomain.
- [TranslationTrainedUnits.cs L264–333](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L264-L333): `Execute(SemanticTokenSequence tokens, string topicDomain)` принимает домен, но **не читает `topicDomain`** при exact→phrase→word→KNN→fallback.
- [TranslationTrainedUnits.cs L404–459](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L404-L459): `TrainOnExample` десериализует `ExecutorInput.TopicDomain`, но exact map записывает `_exactSourceMap[NormalizeMapKey(input.SourceText)] = chosen.Text`; обучение другого топика с тем же source перезаписывает прежний правильный перевод.
- [TranslationDirectionAdapters.cs L117–139](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationDirectionAdapters.cs#L117-L139): обычный adapter действительно передаёт `request.TopicDomain`, затем проверяет кандидата через Verifier.
- [TranslationTrainedUnits.cs L486–534](https://github.com/lubochka/llm_mvp_core/blob/83590a462b2f8aedc9d3ab4cb775193eb9c25ce5/27.TranslationDomain/TranslationTrainedUnits.cs#L486-L534): checkpoint exact/phrase/word maps сохраняет ключи **без TopicDomain**, поэтому обычный restore уже не сможет восстановить различение топиков, которое не было записано.

**Непосредственный синтетический сценарий:** EN→RU, source `bank`, `TopicDomain=finance` → `банк`, `TopicDomain=geography` → `берег`. После двух `TrainOnExample` в любом порядке обе обычные `Execute` с одним source получают один и тот же exact-target **последней** пары. Из двух разных законных смыслов минимум один неверен. Это механизм last-write-wins, **не доказательство generalization**.

**Фальсификатор:** two-domain same-source sequence в обоих порядках, затем exact `ExecutorUnit.Execute` и ordinary `TrainedTranslationAdapter`, раздельные статусы. Качественный intervention — scoped memory key `(direction,topicDomain,source)` с явным `general/unknown` fallback, **не** подмена SQL/medical/etc текстов ручными if-else. Сравнить correct/2, false acceptance, abstain/coverage, save→load parity. Следить, чтобы новое scope не потеряло допустимый междоменный общий перевод.
