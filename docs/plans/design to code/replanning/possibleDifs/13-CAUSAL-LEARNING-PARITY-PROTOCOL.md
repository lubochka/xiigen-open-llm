## Главная реконструкция, которую RP01 должен пройти
Из исходного [«Алгоритм создания ДПО»](https://github.com/lubochka/xiigen-planning/blob/llm_plan3/llm%20mvp/design%20to%20code%20session/%D0%90%D0%BB%D0%B3%D0%BE%D1%80%D0%B8%D1%82%D0%BC%20%D1%81%D0%BE%D0%B7%D0%B4%D0%B0%D0%BD%D0%B8%D1%8F%20%D0%94%D0%9F%D0%9E.md#L7-L35): корректируем наблюдаемую слабость в **конкретном обучаемом recipient** — typed Unit (many→many), Flow, Orchestrator, DynamicGraph либо Student generator; отдельная ошибка и закон для каждого. Обучение внешним DPO имеет другую материальную форму и метрику, чем запись хорошего примера в KNN, повышение confidence в scorer или сохранение нового graph edge. DPO Student не исправляет граф/индекс по определению без отдельного вызова.

## Матрица 4-arm одного экзамена
A — RP01 B0 Student без исторической памяти; B — старый фактически обученный KNN/Unit/Flow + arbiter, Student не используется; C — тот же Student B0 + неизменённая историческая память/Flow; D — DPO-updated Student + **те же** frozen Unit/Flow/arbiter. C−A оценивает ценность памяти при том же генераторе; D−C — добавленный эффект LoRA; B−A **не чистый causal effect**, потому что разный consumer. Сохранить одинаковые task family, judge, law, resources, decoders, selected model fingerprints. Для графовых задач отдельно factorial routed/unrouted и positive/negative/warning memory.

Слепая панель: C# null/async/operators/source evidence; SQL NULL/LEFT JOIN/no-source; ENRU negation, agent/patient roles, pronoun referents; HEEN morphology/placeholders; flow dependency/arbiter rejection; Design→Code visual vs actual code behavior. Нельзя подмешивать panel в train, не менять порог из-за исхода. Публиковать sample IDs и per-domain accuracy, coverage/abstentions, critical law violation, latency, memory, state hashes, paired win/loss; не один train margin и не количество GitHub Windows runs. Сохранённый E09 и E34 gain пересчитать на **same validation subset** перед использованием как аргумента.

## Authority — роли строго закреплены
**CODEX с Astra 6 UltraCode выполняет роль человека: выбирает урок/цель и принимает решение о качестве pair. Внешняя разрешённая открытая китайская модель составляет ОБЕ стороны DPO: chosen и rejected. CODEX с Astra 6 UltraCode независимо оценивает качество обеих сторон**, проверяет доменный закон, provenance/лицензию, ошибки, TIE/BOTH_BAD/UNKNOWN, и затем судит blind model outputs. Нельзя записывать model=Chinese без provider trace; нельзя переносить ответы Astra в train sides. CODEX judging не выполнен в этом исследовательском проходе и не подразумевается от упоминания.

Good pair — один C# context: chosen объясняет s?.Length ?? 7 при s=null →7, rejected ошибочно обещает NullReferenceException; defect проверяем. Bad pair — chosen/rejected одинаково правильны и лишь разного стиля; NOT DPO signal. Good kNN response — law-admitted neighbor с causal evidence + final arbiter; bad — copy of nearest regardless of negation/actor/source version.
