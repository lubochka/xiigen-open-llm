# RP15 — scientific examination and cost protocol

**Scientific question:** Does a real, law-aware compatibility/migration mechanism preserve or improve future ordinary solutions when a lawful domain version changes, within a bounded PC budget, without causing regressions or falsely attributing code/index repair to DPO?

## Preregistered arms and causal attribution

- **O (historical diagnostic):** prior defective or old code, if present. Compare O→N ONLY as a code/implementation gain, never as Student learning.
- **N (corrected no-update):** identical corrected code and evaluator, old safely compatible state or explicit safe abstention; no migration update, no DPO.
- **M (migration):** same corrected code as N + one scoped approved semantic-state migration/reindex/typed invalidation; Student weights unchanged. Gain M−N is migration/compatibility, not DPO.
- **U (optional DPO):** exactly the M code/state pipeline plus at most one authorized, unique Chinese-authored exact chosen/rejected Student lesson and actual optimizer update. Gain U−M is **candidate** learning evidence, only if affected learnable state and recipient changed and independent exam agrees.
- **D/L/H (optional hybrid ablation):** deterministic-only legal route, lawful learned route and hybrid with common hard guards, same lawful candidate set/rights, same budget; cannot give L illegal shortcut.

If M unsafe, do not run U. If training rights/profiles/consent absent, report U=NOT_RUN. If K no equivalent consumer, report NOT_MEASURED rather than fabricate outcomes.

## Frozen data and examiner

Required splits TRAIN, OP_DEV and SEALED_CERT by original **source-family/pattern** and time/version; never just shuffle near-duplicate rows. Domain law passports from 01A with authentic authority; label positives/negatives/warnings separately. For TIE do not force a DPO preference. Examiner is independent of Teacher, CODEX exact-pair judge and code author where feasible; evaluator uses externally grounded law, not model self-scores. Seal CERT until comparison preregistration is final, keep audit receipt without leaking answers to lesson selection.

Per-domain rubric: law-valid answer accuracy with sample denominator + uncertainty, critical violation count, predicted-domain mapping and OOD abstention, semantic coordinate preservation, lawful retrieved candidate recall/precision & observed multi-hit aggregation, feasible selected path regret against enumerated known legal alternatives, unit/flow many→many correctness, Graph order-2/3 generalization, Student held-out learning delta, old-domain retention, invalid cases.

Timing: real wall clock/phase latency, full CPU and peak/sustained RAM/VRAM, on-disk tokenizer/index/weights/checkpoints, retries/failed branches/reindex time and any external/teacher cost. Compare equivalent caps, batch/source order and snapshots. Report per-bulk deltas on same common frozen evaluation panel; fresh panels are separate trend, never hidden replacements.

## Acceptance and stop logic

1. Truthfully show SOURCE_TRACED and actual method→ordinary consumer at K SHA.
2. Show one law delta with discriminating semantically meaningful good/bad/edge case and no hard-law invalid migration.
3. Show a real compatibility decision consumed, not only a JSON or in-memory test.
4. Optional MIGRATION_STATE_CHANGED requires tracked before/after state and safely cold-switched pointer. Optional STUDENT_STATE_CHANGED requires actual optimizer/LoRA parameter evidence on declared Student, not index rebuild.
5. SCIENTIFIC_GAIN only on independent family/domain task quality and lawful path/time/cost, with uncertainty and retained old skill. REGRESS/INCONCLUSIVE/NO_CHANGE are accepted honest findings, not success claims.
6. ORDINARY_ADOPTION uses cold normal request and state reopening; IDE/native release stays RP06 if unavailable.
7. Independent CODEX GPT-6 Astra UltraCode source+science exact-final-SHA review only with actual separate invocation receipt; otherwise NOT_PERFORMED.

**Falsifiers:** source leakage; invalid rights; changed legal candidate pool; first-hit-only aggregation mislabeled adaptive kNN; reward gaming; changed teacher/judge pair bytes; optimization run missing; no cold adapter read; apparent speedup hides rebuild/failed-branch cost; Student gain measured against broken O not corrected M.

**Minimum first experiment:** C# nullable or EN↔RU negation, one actual old→new source/version change, frozen good/bad/tie/OOD and old-law retention, N vs M with exact same Student and code, measured ordinary local consumer latency + total disk/index. No GPU, Teacher or Windows CI necessary for this experiment. Independent Astra can then decide whether the selected mechanism is justified.
