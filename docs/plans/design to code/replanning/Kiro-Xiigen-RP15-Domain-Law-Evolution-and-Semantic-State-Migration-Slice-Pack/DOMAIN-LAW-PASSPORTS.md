# RP15 — domain law evolution passports, examples and examination obligations

Every passport records {domain axes, source/law authority, effective version/date, hard/soft constraint, semantic coordinates, authorized positive/warning/negative memory, targeted typed/graph/Student consumer, legal delta class, falsifier, old/new family IDs, privacy/rights}. The examples below are **design probes, NOT measured Student cases or DPO final material**; 01A must replace them with real authority/source family evidence and freeze controls.

| Domain | Stable hard law | Meaningful evolved-law scenario | Good vs bad and edge |
|---|---|---|---|
| EN↔RU | Preserve negation, quantities, names and modality | New industry style guide changes allowed terminology, but negation must survive | GOOD: “не требуется” vs English “not required”; BAD: “требуется”; EDGE: two faithful stylistic variants = TIE |
| Orchestration | DAG legality, dependencies, permission, cancellation, full branch cost | Cancellation policy/version changes allowable ordering | GOOD: compensate then cancel when required; BAD: race ahead and count failed illegal branch as zero cost; EDGE: no lawful path → abstain |
| Figma→HTML/CSS | Responsive layout, RTL, focus/accessibility and asset integrity | Design specification changes RTL/component constraints | GOOD: correct RTL and responsive focus; BAD: only screenshot at one width; EDGE: asset rights revoked |
| C# CodeDocumentation | Nullable/reference/operator semantics and language version | Nullable/operator interpretation changes with project language version | GOOD: distinguish a?.Length from a?.Length ?? 0; BAD: treat both identical; EDGE: old project still uses old semantics |
| Angular CodeDocumentation | Binding, lifecycle, runtime/framework version | Framework major migration changes template/lifecycle legal conventions | GOOD: version-pinned binding explanation; BAD: old lifecycle advice presented as new API; EDGE: project mixed versions |
| SQL CodeDocumentation | Dialect, transaction isolation, null/3-valued semantics | Dialect/isolation change modifies legal query/result expectation | GOOD: law/version-specific behavior; BAD: query judged across different dialect; EDGE: multiple defensible plans |
| DPO Builder | Legal model authorization, strict teacher authorship and separate CODEX human/judge | Teacher provider/profile or rights change | GOOD: CODEX selects lesson, approved Chinese authors both exact outputs, CODEX separately judges; BAD: Student answer masquerades as Chinese rejected; EDGE: TIE/BOTH_BAD/UNJUDGEABLE; no pair |

**Subject vs domain dimensions:** canonical F/D04 CODE_Q/BUG/PLAN/ARCH/REFACTOR are legacy classification labels, not replacements for subject law/version axes; do not silently collapse translation, SQL and C# onto those five labels. Preserve StackDetector-before-normalization and F/DECISIONS-LOCKED D-07/08/09 where applicable. Historical numeric performance claims are not newly measured.

**Three panels:** old-law retention, genuine changed-law transfer and unaffected-domain negative controls, each split TRAIN/OP_DEV/sealed CERT by **source family**; include GOOD/BAD/TIE/OOD/UNKNOWN and legal rights. Path-quality claim requires best among actually enumerated lawful candidates under equal budget; do not invent omniscient global optimality for intractable search.

**Token/vector/LoRA tests by function, not coverage:**
- Can raw→IR→token/vector still distinguish the law after version change?
- Is domain mapper predicted label accurate or abstaining on OOD, independently of oracle-domain diagnostic?
- Does actual kNN consumer use multiple legally eligible neighbors, not just the first hit? Compare exact/ANN index omission, fixed/dynamic k separately.
- Does typed Unit/Flow/Graph route produce the most useful **lawful** result under fixed resources?
- Does Student actually improve on held-out unfamiliar families after one valid new pair, **beyond** no-update/migration effect and without old-domain forgetting? A changed LoRA adapter hash alone fails this.
- Is all this delivered by ordinary cold PC consumer with trustworthy resource and rollback receipts?

If a law is not grounded in an authoritative source, return UNVERIFIED_LAW/NO_AUTOMATED_MIGRATION. Do not turn illustrative probes into training examples or a sealed exam without independent curators.
