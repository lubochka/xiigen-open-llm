## Зачем нужен одиннадцатый replanning slice

В XIIGEN уже определены алгоритмы разных природ: закон домена и детерминированный arbiter, domain/intent mapping, semantic token/vector, BM25+kNN, typed many→many LearningUnit, correction LearningFlow, async LearningOrchestrator, higher-order LearningDynamicGraph, Student + LoRA/DPO и Builder. **Уникальный продуктовый результат RP11**: реальный ordinary consumer порождает provenance по допустимым альтернативам; контрфактический оценщик сравнивает законные маршруты при честном бюджете; небольшой versioned online credit model учится предсказывать полезность компонентов/маршрутов по домену, ограничениям и цене; существующий RP04 controller получает объяснимое ранжирование только среди допустимых маршрутов; отдельная feedback-система передаёт сигнал **CODEX GPT-6 Astra UltraCode**, который выбирает разрешённое учебное задание. Ни credit scorer, ни эвристика не назначают DPO-пару и не обходят CODEX.

**RP11 — это не исследовательский R11** (минимальный first-lesson DAG), **не исторический S11**, не RP04 policy rewrite, не новый trainer, не повтор RP09 benchmark runner и не ещё один круг общего planning. Его единственные новые owned code seams — minimal provenance/credit contract, bounded paired-credit estimator, low-memory online credit state и разрешённый integration adapter к существующему policy consumer. Перед записью обязан доказать, что тот же seam не существует уже в текущем K: при доказанном эквиваленте — REUSE_NO_CHANGE.
