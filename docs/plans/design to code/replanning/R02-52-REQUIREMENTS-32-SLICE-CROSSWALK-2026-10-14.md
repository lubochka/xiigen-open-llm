## Additional functionality that a DPO-only interpretation would drop

**Eight task types vs seven domains — R02-025/026.** Domain (EN↔RU, async orchestration, Figma→HTML/CSS, C#/Angular/SQL documentation, Builder) is not equal to a user task class (also server/client code generation and stored procedures). RP06/S21 must preserve and source-trace task types and consumer outputs without inventing eight complete models. **R02-027 Hebrew→English** is extra language direction: keep owner/trigger and an independent law/meaning-preserving translation panel; no assumption that current tokenizer correctly supports it.

**Actual Design-to-Code product behavior — R02-029..038.** RP06 owns input package (Figma/Canva original tree, assets and screenshots), actual server→ILearningMachine caller, correct responsive output at multiple viewports, tier-dependent Free/Paid/Pro budget, iterative improvement with stopping, stored result data, a traced target in DPO, usefulness visible to user, permitted accepted-weight publication and named consumer repos (xiigen-platform-dot-net-angular, xiigen-flows-dot-net-angular, FigmaToCode-design-gen, CanvaToCode). S24/25 prove accepted-state adoption/provenance only, **not** a replacement for this full product behavior. A good-looking screenshot alone is not implementation or DPO gain.
