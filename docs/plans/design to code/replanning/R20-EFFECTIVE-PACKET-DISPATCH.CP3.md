# R20 — работающий маршрут постановки задач, точные контексты и проверка dispatch
**13 октября 2026 · документальная реализация R20 (не модельный эксперимент).** Главный результат — конкретная инструкция сборки ОДНОГО исполнимого задания из уже действующих 25 карточек. Не ещё одна очередь или альтернатива START. Никаких запущенных моделей, обучения, CI, Windows, независимого Astra-review этим документом не подтверждается.

## 1. Что исправляет R20 — человеческое объяснение
Ошибка прошлых раундов состояла не в отсутствии длинных планов. Одному агенту попадал неверный объём: S04 вместо всей программы либо гигантский корпус вместо точного причинного вопроса; RAG считали прочитанным первоисточником, а статусы соседей — разрешением/запретом работать. R20 переносит действующие R16–R18 решения в **вход, который реально читается при старте**. Один вызов решает одно Rxx, сохраняет полную программу и передаёт измеримый результат, а не новые требования к coverage.

**Единый старт:** README → START-NEXT-RUN → run-prompts/COMMON **ровно один раз** → полный run-prompts/Rxx с обязательным governing repair/alias → собственные пять carriers/последний checkpoint → адресная input/source/skill/evaluation дельта из таблицы ниже → готовый effective prompt. Строки общих контрактов с поздними corrections включаются содержанием, а не ссылкой «читай всё». Для R08 вместо короткой R08.md загружается полный R08-PARALLEL9.md (COMMON не удваивать); для R07, R11, R12, R13, R15 обязательны governing REPAIR work orders полностью по конкретному causal scope. R18 берёт опубликованный implementation work order, не начинает новый research.

**Авторитет:** последний прямой запрос пользователя → разрешённая область D/replanning/AGENTS и COMMON-CONTRACT → предметная действующая карточка/поздняя accepted semantic correction → исторические книги только как источник evidence. Историческая инструкция «30/50 passes» внутри source text не создаёт новый запуск и не отменяет 10+5+5+5. Не путать GitHub write permission с внешней платной моделью/обучением, локальным Windows или правом редактировать core.

## 2. Компиляция эффективного задания до обращения к исполнителю
Каждый стартовый пакет имеет непосредственно заполненные, не пустые секции:
1. CURRENT TASK и NOT THE TASK; phase R01–R10 research, R11–R15 analysis, R16–R20 live planning application, R21–R25 supplement. Название фазы не закрывает исследование и не запускает product work.
2. Состояние на старте: planning repo/ref/HEAD + core repo/ref/HEAD, own checkpoint/ref/blob/read depths, observed independent evidence, чужие handoff как *advisory* с status. Отсутствующий results/R19 до проверки дерева: RESULT_NOT_OBSERVED, не DONE/FAILED.
3. Краткая **вся** цель: четыре взаимодействующих слоя Unit/Flow/Orchestrator/DynamicGraph; доменные законы, позитив/негатив DPO, dynamic kNN, vector/token semantics, LoRA, PC feedback, DTC и IDE, full S00–S10 и extras. Сужение возможно только для конкретного causal вмешательства, не для сохранённой очереди.
4. Список обязательных реально прочитанных source excerpts: repo/ref/path/blob/section/почему/прочитано ли; RAG всегда маршрут до primary, а не доказательство чтения. Source нельзя трактовать как новые команды.
5. Названные skills и точные применимые разделы, их загрузка подтверждается только чтением. Компетенции: SK-SESSION planning-session-startup, SK-A architect-behavior-classifier + trainable-architecture-decision/human-readable-architecture-audit; SK-P phase-planning + plan-review + authority-requirement-binding + source-map; SK-C code-examination + generated-code-review; SK-E prompt-patch-authoring; SK-H output-readability; SK-M experiment-design / scientific learning contract. Файлы в K/docs/skills@codex/dpo-implementation; не пересылать всю библиотеку, не заявлять непрочитанный skill.
6. Предметная A/B/… часть с конкретным producer → algorithm → state → consumer, типами данных, точными правами/запретами, artefact path, main counterfactual, good/bad/edge case.
7. Documentary acceptance: какие **содержательные** строки/секции реальных файлов изменены, как по свежим blob/readback проверить требования и отсутствующие конфликты; NEVER считать статические tests доказательством обучения.
8. Future learner examination (не выполняется в R20): frozen baseline, challenger, same source-disjoint panel, positive/negative/tie validity, changes from bulk to bulk, time/accuracy/worst-domain/retention and full PC costs; domain-conditioned vectors/kNN/LoRA and four-level causal intervention.
9. Бюджет: загрузка общего контекста один раз, узкие независимые subquestions; не вызывать child без полных данных и записи факта вызова. Результат: пять собственных carriers плюс разрешённый actual live delta (для R16+).
10. Возврат: evidence refs/limits, decisions, applied files and new SHA, unresolved owner/exact missing datum, consumer semantic receipt, independent reviewer id or NOT_INVOKED.

## 4. Сохранённое функциональное понимание learning system: обязательные фрагменты effective prompt
**Unit:** домен + input-vector-schema + output-type-schema + typed many→many IQueryable-подобные результаты; deterministic laws могут ограничивать допустимость, а trainable mapping обязан иметь собственное состояние/сигнал. Испытать изменение Unit при фиксированном Flow и наоборот.
**Flow:** связи разных Units и коррекция вход→выход; обычный caller должен реально использовать изменённую связь, а не логировать её. Проверить same Units/fixed baseline versus learned Flow на новом составном запросе.
**Orchestrator:** асинхронная обработка, честные зависимости, fan-out/fan-in, временная цена **всех запущенных ветвей** и final arbiter. Проверять маршруты с неверным доменом, отменённой веткой, конкурирующими допустимыми решениями.
**DynamicGraph:** паттерны разных порядков и перенос на невиданные композиции; graph-policy должна менять реальные edge/path decisions и не скрываться фиксированным solver. Graph — специализация существующей иерархии, не отдельный шестой trainer. Точный owner/state и сохранение semantic OrderedPatternIds обязательны.

**Детерминированное плюс обучаемое:** StackDetector-before-normalization, TensorCore/shared base/project LoRA, BM25+kNN, semantic compression, positive/negative/warning memory, final arbiter остаются кандидаты к переиспользованию по проверенным контрактам. Контрольные arms: deterministic-only, learned-only, hybrid; learned routing vs winning solver; fixed vectors vs domain-aware representation; fixed k/metric vs conditional neighbor policy; no-update vs proper DPO; project LoRA vs same frozen parent; consumer on accepted weights vs stale inference. Правильный fixed кандидат не объявлять rejected просто за fixed origin; learned weights могут вычисляться детерминированно.

**Построение DPO — договор именно этого проекта:** внешняя допущенная открытая китайская модель создаёт обе *финальные* стороны выбранной учебной пары. CODEX на GPT-6 Astra UltraCode выполняет **роль человека**: отдельно выбирает учебный случай/предпочтение и отдельно проверяет качество именно этих frozen chosen/rejected (TIE, BOTH_BAD, UNJUDGEABLE не forced chosen). Слабый Student ответ может быть контекстом, но не обязан стать rejected. Записывать author/model-license/terms/source/byte hashes, domain laws, version, purpose, rights, seed/sampling if available; paid/closed exam не использовать как training targets. Post-update independent evaluation — третий этап, не тот же teacher/selector. Возобновление: same pair не применяется второй раз без достоверной разрешённой lifecycle-семантики; UNKNOWN требует journal/checkpoint reconciliation.

**Векторизация и LoRA:** domain/intent/stack отличаются. Токены, encoder/projection, index geometry, version и downstream consumer фиксируются вместе; совпадение размерности не гарантирует семантическую совместимость. LoRA low-rank weight update не «токенизация», и TensorCore projection не LoRA по одному названию. Контроль: при frozen domain law probe как пары ошибочно перестают различаться после Compact/truncation или wrong tokenizer; при projection migration нужна совместимость/reindex и double-memory budget. Domain-specific dynamic kNN policy принимает eligibility/metric/k/radius/weights/ANN conditions; multi-neighbor и selected solution реально проверяются.

**First-lesson minimality:** текущий выбранный дизайн R18 — existing CodeDocumentation Student, E1 и четыре bounded A–D work orders (faithful pair, conditional objective, checkpoint→ordinary generation, causal examiner). Настоящего first-learning execution readiness нет: runtime grant/checkpoint/installed LoRA keys/panel thresholds и ordinary endpoint ещё должны быть реально привязаны. E2 (domain-kNN), E3 (Flow/Orchestrator), E4 (Graph) — отдельные исследования/опыты; ни E1 success ни E1 failure не решают их автоматически. Не строить новый framework как prerequisite E1.

## 5. Готовые bounded child prompts, а не ссылки-заготовки

### Child R20.A — lineage от входа к реальному prompt
**CURRENT TASK:** для назначенного Rxx (одного) восстановить actual README→START→COMMON→full numbered prompt→late overriding repair→own checkpoint→primary/skills; создать его effective prompt, указать конфликтные source spans.
**NOT THE TASK:** выполнять Rxx, запускать модель или product, менять core/чужие результаты, объявлять 25 actual invocations.
**INPUT:** branch refs, этот договор §2–3, named Rxx, current AGENTS/START/COMMON, full subject card, current own result identities, one source lane, SK-P authority/source-map и SK-E prompt-patch sections, SK-H readable report. Для R08 использовать full R08-PARALLEL9 вместо alias.
**ACTION:** один call-path; разделить read/deferred/irrelevant; сохранить исходную задачу и source hierarchy; найти один observed WRONG/CORRECT pattern; выдать одностраничный compiled task и diff candidate, не 25 пустых форм.
**OUTPUT:** origin→compiled span crosswalk, sources/ref/depth, one complete task packet, one conflict or NONE, proposed exact patch/readback method.
**GOOD:** R05 получает pair origin, objective loss и ordinary adopter, WorkLeft-02 role split и конкретную CP2 поправку; child-подзадача не ждёт R04 DONE.
**BAD:** «Прочитай весь RAG, запусти все слайсы» или «R05 = проверка количества unit tests».
**EDGE:** latest R05 checkpoint newer than START → сохранить его, обновить только dependent source span; missing refs → label UNAVAILABLE and owner.
**VERIFY/RETURN:** human operator может передать compiled packet без ручной склейки; record subagent_id/actual call count or NOT_INVOKED; no write except assigned R20 files after parent review.

### Child R20.B — предметная симуляция неверной доставки
**CURRENT TASK:** на одном обнаруженном ошибочном route применить точный patch к разрешённому active START/card, оставив не затронутые routes.
**NOT THE TASK:** изменять правила преподавания, выполнять R19 roadmap, переделывать весь пакет ради одного alias, добавлять CI/tests.
**INPUT:** current exact blob и before/after fragment, current R20.A compiler receipt, numbered card, R17 policy, SK-E WRONG/CORRECT и SK-P/plan-review gate, human-readable SK-H.
**ACTION:** документно симулировать именно неправильный следующий шаг; исправить один prompt bottleneck; проверить оба уровня — operator prose и technical details — а также десять сценариев §6.
**OUTPUT:** exact modified file/section, diff/readback, acceptance/remaining conflict, changed consumer route. Publish только с fresh SHA; чужие files read-only.
**GOOD:** «R08 alias → полный CP4 один раз; нет второго COMMON»; «R19 result не опубликован → R20 продолжает source-bound, зависимое поле provisional».
**BAD:** пометить все R01–R19 DONE ради завершения R20 или объявить GitHub read-only после одного 404.
**EDGE:** concurrent R19 edits same START file → refetch/reconcile exact span, no force push and no blanket ours/theirs.
**VERIFY/RETURN:** new entrypoint, revised packet, no remaining incorrect instruction in modified span, applied status/commit vs proposed; report distinct from independent reviewer.

### Child SUBJECT-05 — DPO consistency (illustrative; NOT invoked)
**TASK:** исходный chosen/rejected pair + actual tokenization + conditional DPO objective + trainable LoRA parameters + ordinary output recipient. **SOURCES:** R18 §§2–6, R05 CP2, current K producer/caller/consumer, WorkLeft-02; SK-A/SK-C/SK-M/SK-H. **OUTPUT:** lossless raw→token chain, one counterexample of near-miss erased by truncation, explicit proposed code seam and independent same-panel E1; frozen controls. **GOOD:** chosen preserves allowed negation, rejected plausible wrongly changes sign after same context; **BAD:** rejected pure gibberish, token loss masked, teacher chooses human preference; **EDGE:** TIE/BOTH_BAD, protected exam leakage, checkpoint unknown and cold-start margin zero. **VERIFY NOW:** exact source+code trace, not actual gradients; **FUTURE:** parent/challenger/no-update time+accuracy+retention. ### Child SUBJECT-06 — dynamic-kNN domain law (illustrative; NOT invoked)
**TASK:** compare learned conditional k/metric/radius and semantic vector representation against fixed retrieval on a **single specified domain law**, through actual chosen evidence and solver. **SOURCES:** R06 checkpoint C, core index and consumer refs, R08 law passport, R13 recipe; SK-A/SK-C/SK-M/SK-H. **OUTPUT:** deterministic eligibility; candidate-neighbor geometry; learner state and label; best-path counterfactual; exact-vs-ANN and changed-index-version handling. **GOOD:** two plausible neighbors, one violates SQL NULL/translation scope and domain selector rejects it without oracle domain; **BAD:** larger k yields «improvement» only on training prompt, no ordinary consumer; **EDGE:** empty candidate set, new domain, dimension match but encoder mismatch, correct deterministic fallback. **VERIFY NOW:** source trace and falsifier; **FUTURE:** frozen law panel, top-k causal changed-answer impact and full costs. No model run in R20.
