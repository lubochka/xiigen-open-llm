**First two broad contrast families:** D4 C# and D1 EN→RU from independent projects; D3 ordinary DTC where allowed. This order is information gain, not a blocking dependency for source-only D2/D5/D6/D7 panels. HE↔EN, HE↔RU, distinct code generation, stored procedures, language learning, local wiki, native VS, all original S00–S10 extras remain inventoried with **owner+trigger**, not silently removed.

**Domain mapper axes:** subject, user intent, stack, language, project+version, law scope. `CODE_Q` alone is development intent, not C# / Angular / SQL / DTC subject. Return calibrated UNKNOWN/MIXED and lawful multi-label possibilities; do not let an LLM guess subject from source that is missing. A hard negative should be close in representation but materially wrong in law; a random irrelevant negative is not enough. Use source-family disjoint CERT, same matched output rubric and actual typed many→many associations.

**Transfer matrix**: D4→D1 negation/quantity meaning, D1→D3 layout ordered relations (do NOT project untranslated slots directly), D2→D3 asynchronous lawful revision path, D5→D3 template/viewport structure, D6→D4 NULL/nullable contrast, D7→all case selection. Cross-domain transfer is **hypothesis only** until a before/after same-family, same-budget, no-update-controlled exam rules out merely a shared keyword or a changed deterministic parser. The smallest permitted study can report only one contrast, with other rows `NOT_MEASURED`.
