# RP05 V2 — Пять коротких проходов к новому законному уроку B1

**Статус:** план исполнения; 2026-10-14. Этот документ не подтверждает ни запуска Student, ни вызова CODEX/китайской модели, ни измерений на PC, ни независимой экспертизы Astra UltraCode.

## Цель и граница
RP05 отвечает за новый обратный сигнал от обычного пользователя, проверку источника и доменного закона, выбор *нового* урока, законную DPO-пару, безопасное продолжение состояния Student, новый B1, независимый экзамен и реальное использование принятого состояния после холодного запуска. RP01 отвечает за первый реальный принятый B0; наличие B0 — предпосылка **изменения весов B1**, но не чтения исходников, подготовки экзаменов или анализа новых доменов. RP02 отвечает за domain mapping / vector-token semantics / law-conditioned adaptive kNN; RP03 — типизированные many-to-many Unit и коррекции Flow; RP04 — bounded asynchronous Orchestrator и higher-order DynamicGraph. Их исследования и кодовые слайсы независимы от успеха первого RP05 B1.

Не начинать повторно R01–R25, не проходить все WorkLeft и 32 слайса до каждого локального шага. Выбрать одну область риска, перейти от WorkLeft/RAG к актуальному primary source, реальному коду, вызывающему методу и обычному потребителю. Для каждого явного отсутствующего доказательства записать OPEN — не подменять утверждение предположением.

## Наука вместо подгонки ожидаемых значений
Экзамен утвердить *до изменения* по независимым **семьям источников** (репозиторий/дизайн/синтаксическая семья), три непересекающиеся группы train/development/sealed. Определить доменный закон, hard-law veto, законность отказа и rubric, judge blindness, minimum meaningful improvement и allowable retention loss до результатов. Публичные GOOD/BAD ниже — учебные примеры, а не sealed set.

P = предыдущий принятый model, C0 = тот же исправленный pipeline без обновления trainable state, T = такой же pipeline после **одного** разрешённого обновления. P→C0 показывает engineering-эффект, C0→T — learning-эффект. При прочих равных держать одинаковыми источник, prompt, decoder, tool rights, available candidates и PC budget. Измерять N **независимых** family, законно правильные ответы, critical law errors, abstain, domain mapping confusion, worst-domain, forgetting, wall/p50 и p95 только когда N это допускает, CPU, simultaneous peak RAM/VRAM, disk с rollback и index, failed branches, китайского автора, двух ролей CODEX, независимого outcome evaluator и cost per newly correct family. Изменённый hash, loss или зеленый CI не доказывают причинного прироста.

**Два типа проверок:** 0 новых product tests для READ/PLAN/NO_CHANGE/SCIENCE; для действительно изменяемого правового, mask, journal, undo, typed edge, async side-effect инварианта — минимальные существующие проверки, плюс новые только при непокрытом риске. Реальные обязательные release/security/native проверки нельзя удалять, но нельзя делать blanket Windows Actions или coverage %-gate перед sandbox learning.

**Протокол остановки:** нет B0 → handoff RP01, без фиктивного родителя; нет consent/license/valid pair → HOLD; ambiguous optimizer effect → UNKNOWN_STATE, не повторять; PC no headroom → NO_HEADROOM; trial law-regress → retain parent; endpoint stale selected digest → ADOPTION_GAP; нет отдельного Astra UltraCode reviewer receipt → INDEPENDENT_REVIEW_NOT_PERFORMED. Каждая остановка локальна к соответствующему опасному эффекту.
