# RP12 — causal credit assignment for hybrid learning

Existing architectural roles are distinct. ILearningUnit ≈ ILogicalUnit (L2) proposes typed many-to-many input/output associations. ILearningFlow ≈ ILogicalFlow (L3) corrects associations via typed OutputRefs, fan-in/fan-out. ILearningOrchestrator ≈ ILogicalOrchestrator (L4) handles lawful asynchronous dependencies, cancellation and cost. ILearningDynamicGraph is graph-domain learning under ILearningMachine<DynamicGraphDomain> (L5), not a new sixth inference trainer. Train is owned by LearningMachine, not methods added to Unit/Flow. Higher-order graph motifs do not establish a trained state unless an actual weight/state owner and consumer are traced.

Ordinary request → domain × intent × language × stack/dialect × version × rights → lawful semantic tokenizer/IR/vector codebook → positive/negative/warning memory → rank/k/radius/real multi-neighbor kNN → typed Unit → Flow → Orchestrator async alternatives → higher-order Graph → deterministic rights/laws/final arbiter → actual ordinary answer → RP09 blinded domain-law examination → RP12 attribution → existing owner intervention proposal.

The minimal causal selector observes an actual failure and explores mutually competing hypotheses: H1 domain mapping; H2 lost negation/operator/unit/RTL semantic coordinate; H3 first-hit or wrong multi-neighbor/rank/k/index; H4 Unit vs Flow typed association; H5 Orchestrator or higher-order Graph path; H6 Student DPO/response-only LoRA; H7 state/adopter mismatch; H8 insufficient/poisoned user evidence. It never conflates LoRA tensors with a semantic token codec, HNSW retrieval mutation with DPO learning, or policy preloading with a learned graph.

PROPOSED data contract, not existing K API: FailureEvidence(case/source-family/rights/tenant/domain law/input+consumer+state fingerprint/observed answer/quality/negative control/time/full PC); InterventionCandidate(hypothesis/one changed factor/frozen factors/current owner/legal candidate set/cost/no-change/rollback/falsifier); CausalDecision(preregistered comparison/source-depth/uncertainty/eligible next task, never an unconditional mutation).

One controlled intervention changes ONE factor with same lawful candidate pool, static safety guard and arbiter in every arm. Separately test mapping vs oracle-domain offline, generic vs law-aware tokenization, top1 vs actually fused multi-neighbor, fixed vs per-domain k or rerank, frozen Units vs Flow correction, frozen Flow vs learned lawful Orchestrator, known vs novel order-2/3 Graph motif, N parent vs C0 corrected no-update vs T one admitted DPO update, and evaluator-only vs cold ordinary accepted-state consumer. Do not run an uncontrolled global factorial or ascribe a multi-factor gain to one algorithm.

For each lawful intervention predeclare domain accuracy, critical law violations, candidate path regret among enumerated feasible paths, time, full actual PC RAM/VRAM/disk+failed branch+remote cost, old-domain retention, confidence, consent, rollback and no-change. A correct deterministic path is a positive outcome; do not force a learned alternative to win. If the cause is not identifiable, ABSTAIN/INCONCLUSIVE is correct. RP12 cannot build a new trainer, domain mapper, Graph, evaluation runner, IDE host or Builder.

All task paths are proposed until current code and actual callers are inspected. Any K source edit, model invocation, paid budget or learned state change needs a separate live effect grant.
