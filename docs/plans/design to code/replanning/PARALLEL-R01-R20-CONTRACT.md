## 3. Кто пишет и как не потерять параллельную работу

R01–R15: только свои пять carriers в `results/Rxx`: SOURCES.csv, FINDINGS.md, DECISIONS.md, CHANGE-MAP.csv, RUN-LOG.md. R16–R20: свои carriers плюс assigned planning artifacts. Child return-only. Чужие результаты, runtime code, tests, workflows, datasets, weights и core skills не изменять.

Владение: R16 — source-bound requirements; R17 — evidence/acceptance policy; R18 — implementation work orders; R19 — START/AGENTS/PLAN/COMMON/JOIN/navigation; R20 — model-packet content и context assembly. Один файл с пересекающимися edits имеет одного интегратора: владелец файла принимает section-bound proposals других workers. Для общих dispatcher/card связей интегратор R19; содержимое Rxx остаётся ответственностью Rxx. Это правило владения, не заявление, что распределённый lock уже реализован.

Перед записью: current blob, base section, proposed replacement, source/decision receipt. При конфликте перечитать актуальный файл, сохранить независимые добавления, разрешить пересечение по смыслу; не force-push и не blanket ours/theirs. После записи — remote readback и commit/blob. Публикация чужого RUN-LOG не сбрасывает собственный snapshot; перечитываются только изменённые semantic dependencies. При одновременном назначении двух writers одному Rxx сначала передать ownership, а не писать поверх друг друга.

## 4. Что не теряется при ускорении

Сохраняются все source roots, original/task/goal prompts, WorkLeft/LeftToWork, RAG→primary, S00–S10/extras, DPO/DynamicGraph, DTC и IDE; R01 discovery не заменяет смыслового чтения. Полные R07/R11/R12/R13/R14 repair scopes, R08 CP4 exception и existing findings остаются адресными inputs. Не создавать снова уже заполненные domain passports и DAG.

Unit — typed many→many с identity/associations; Flow — отношения и corrections; Orchestrator — async dependencies/choice/budget; Graph — higher-order patterns. Actual training owner остаётся ILearningMachine; не четыре новых trainers. Deterministic admissibility и learned state/authority различаются. Exact DPO pair должна сохранять смысл до objective, изменять правильные параметры и влиять на ordinary consumer. LoRA не подменяет tokenizer/projection; k>1 не доказывает использование нескольких соседей.

Chinese open author обеих final sides, Astra/Codex selection и отдельная exact-pair assessment, frozen reference, separate outcome evaluator сохраняются по current S04 authority. TIE/BOTH_BAD/UNJUDGEABLE не forced DPO. One-pair/no-repeat и full-state accept/rollback сохраняются; bulk — окно новых уроков. Оценка — domain mapping, laws, path quality, accuracy/utility, время, полный PC footprint, перенос/забывание и controls. Coverage, green Windows, lower loss и hash не доказательства обучения. Existing checks не отключать.

## 5. Передача и граница доказательств

Dispatcher встраивает содержанием общий contract один раз, полный назначенный prompt, только его адресную repair delta, actual source/skill excerpts и собственный checkpoint. R08 сохраняет свой full CP4 packet без повторного COMMON. Ни короткая таблица, ни список ссылок не заменяют model-ready prompt.

Receipt: `origin run/local ID + source repo/ref/blob/span + exact meaning/limits → affected requirement/consumer → accepted/contested/deferred + reason + next owner/action`. DISTINCT: prompt repair, content/code read, design decision, runtime bound, empirical result. NOT_MEASURED/NOT_PERFORMED остаются честными статусами. Цель — самый ранний достаточный разрешённый учебный маршрут, а не ожидание 25 формальных DONE и не закрытие всего проекта одним уроком.
