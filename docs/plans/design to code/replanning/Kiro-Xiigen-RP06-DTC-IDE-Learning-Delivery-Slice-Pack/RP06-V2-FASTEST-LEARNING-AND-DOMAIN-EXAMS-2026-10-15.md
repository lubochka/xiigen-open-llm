## Декомпозиция алгоритмов — реальные конкурирующие причинные гипотезы
1. **Детерминированный слой:** domain/intent classification uncertainty, права, лицензии, типы и версии, язык/синтаксис/AST, грамматический род/согласование, SQL dialect/NULL, DOM semantics, breakpoints, accessible CTA, arbiter reject/abstain. Эти законы не должны становиться «штрафом, который можно выучить обойти».
2. **Semantic tokenization/projection:** domain passport описывает смысл полей, размеры, типы, отношения/синтаксические роли, provenance и version; tokenizer → encoder → domain projection → vector index → actual consumer. LoRA A/B изменяет параметры модели, **не создаёт новую токенизацию автоматически**. Изменение системы координат требует replay/reindex/compatibility и честного измерения RAM/диска.
3. **Adaptive law-conditioned kNN:** сначала допустимый pool по домену/правам/типу/версии, затем несколько реальных кандидатов, логические признаки, agreement/conflict/uncertainty, кортеж score + lawful rationale. k(q)=f(domain, density, ambiguity, margin, conflict, latency budget); измерять exact top1 → multi-hit typed fusion → adaptive law-conditioned k/rerank → ANN. Просто Search(query,k) затем hits[0] не является RP02 успехом.
4. **ILearningUnit:** домен+схема вектора+схема выхода, many→many stable InputRef↔OutputRef, возможный learned scorer; без подмены ассоциаций позиционным zip.
5. **ILearningFlow:** исправляет typed связи между результатами Unit; learned relation delta измеряется с frozen Unit. Не путать static wiring с обучением.
6. **ILearningOrchestrator:** async/fan-out/join/cancel/rights/side effects+budget, learned route/stop/order лишь среди lawful paths. Считать ВСЕ branches; сравнение сожаления только с перечисленными исполнимыми альтернативами.
7. **ILearningDynamicGraph:** versioned motifs и связи высших порядков; frozen нижние уровни + unseen compound tasks; больше узлов ≠ улучшение.
8. **ILearningMachine/Student:** единственный проверенный optimizer/mutable checkpoint. DPO response objective, ranker/Flow preference objective и graph route objective не взаимозаменяемы. Назвать ответственный параметр и вызов обычного читателя.

## Как мерить обучение — не «test coverage»
Per P/C0/T and B0→B1→B2: n independent source families, exact input/context/seed/host/browser + code/model/encoder/index/adapter version; lawful correctness, domain-law violations, ranker/typed output, route correctness and path regret, DTC multi-viewport semantics, IDE source-grounded edits/answers, retention, abstention/calibration, p50/p95 **если достаточно наблюдений**, wall and CPU ms, all-branch work, peak concurrent RAM/VRAM, SSD/checkpoint+optimizer+rollback+reindex size, local CPU/GPU vs external cost and cold normal-user readback. Cost per correct new family; stratify domain and hard negative. Show raw rows, uncertainty/confidence intervals or clearly INCONCLUSIVE. Pre-register thresholds with independent examiner; no invented 95% or arbitrary threshold. 
Accept: measurable C0→T improvement with no material law/retention/PC regression and real cold consumer; otherwise REGRESS, INCONCLUSIVE, INVALID_EVIDENCE or NOT_MEASURED. Never conflate optimizer changed, score changed, correctness improved, published app and independent Astra PASS.
