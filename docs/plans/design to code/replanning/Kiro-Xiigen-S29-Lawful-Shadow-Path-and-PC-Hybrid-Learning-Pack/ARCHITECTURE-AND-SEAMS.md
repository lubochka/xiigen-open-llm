## Unique gap and decision
Before writing K, ask:
(1) Is there already an ordinary live caller? (2) Does an existing RP04 non-publishing execution mode exist? (3) Can a second legal route run read-only and within PC budget? (4) Does an existing trace consumer bind request+law+state+output+full cost? (5) Is the S28 preference consumer live? If yes to all, **REUSE_NO_CHANGE** and run a real H0 exam. If exactly one adapter is absent, request narrowly scoped K code effect grant and implement ONLY at the named owner. If no lawful second route, **NO_SHADOW** and do useful P/C0; no duplicate graph/executor.

## Three distinct facts
A *second candidate listed* ≠ *second path really executed*; a *path genuinely compared* ≠ *new learned policy step*; a *trained state changed* ≠ *generalized better cold ordinary answer*. A deterministic C0 may beat both no-gradient shadow and policy learning. Shadow itself must never write user's state, repeat external calls without consent or bypass D-15. Cost includes non-winning/cancelled branches, judge and restore reserve.

No type/semantic mismatch may be paid off by a higher score. Owners RP02 and RP18 retain all native algorithms.

## Shadow isolation
A route is shadow eligible ONLY when law/type/rights/tenant/source state/side effects/expense are approved; any business write, unapproved external provider, unrepeatable action or unknown cost invalidates live shadow. Read-only snapshot/dry-run is acceptable only if proven by existing current method. No blind clone or 'undo' of live user action. Public selected output is unchanged by private H0. Runtime callback can reserve and account full resource and cancellation; exact typed trace flows to S28 **without automatic optimizer**.
