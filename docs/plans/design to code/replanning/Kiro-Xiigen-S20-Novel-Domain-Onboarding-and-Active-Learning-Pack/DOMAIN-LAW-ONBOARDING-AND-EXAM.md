# S20 — new-domain passport, independently sourced exam, examples

## Eligibility to call a domain NEW
A subject must be **absent from the current active ordinary PC installation's compatible domain registry**, not merely absent from this prompt, hidden in a fixture, renamed, a dialect version of an active subject or unavailable because endpoint is broken. Freeze the active catalog, response samples, a genuine ordinary route and source-family lineage BEFORE choosing the target domain. Suggested candidate: SQL documentation **only if SQL subject is actually unregistered** in this installation; otherwise select another real-world authorized subject not already active (for example a distinctly scoped public specification supported by actual user need). C# documentation and EN↔RU serve as old-domain sentinels only when actually reachable. Do not pretend a new domain was onboarded because a static rule table gained a label.

All unknowns explicit; an unverified user statement is not binding law.

## Examiner design, not a fabricated run
Freeze before T1: TRAIN lawfully teachable source families; OP_DEV separately tagged diagnostics; SEALED_CERT independent issuer/source-family lineages never shown to teacher/Builder/patching/threshold choice. For first pilot propose new domain: at least 6 real source families × 2 variants (12) and two old-domain sentinels with ≥4 families × 2 variants each (16), total **proposal 28** cases if legitimately obtainable. Include 1–2 OOD/unknown/mixed strata per subject **without** quietly counting reused source text as independent families; actual N must be reported. Proposal sizes are not power guarantees; owner pre-registers minimum meaningful delta, uncertainty scheme, 95%-long-term objective versus pilot-only evidence, and PC limit. If sources unavailable -> smaller honest exploratory panel, certification remains NOT_CLAIMED.
