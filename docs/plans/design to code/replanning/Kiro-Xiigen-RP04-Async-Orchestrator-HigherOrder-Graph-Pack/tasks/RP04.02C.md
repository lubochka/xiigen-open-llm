## 1. CURRENT TASK, NOT THE TASK и условие передачи

**CURRENT TASK:** На одном готовом законном случае проверить `cold theta_motif → допустимая направленная композиция order-2/3 → реально исполненный graph selected target → decoded PathOrderRef → materialized typed OutputRefs → final D-15 arbiter → requested TOutput`. При достаточном совместимом receipt из 02B — REUSE_NO_CHANGE вместо повторной демонстрации.

**NOT THE TASK:** Новый E4/E3 update, изменение Student/RP02/RP03, построение нового публичного trainer, общий перепланировочный цикл, Windows coverage gate, многодоменный экзамен или все structural ablations до первого ordinary use.

**Минимальный выход:** одна корректная cold C0/U пара одного runnable domain с реальным reader и typed output даёт ADOPTION_OBSERVED_SINGLE_DOMAIN и позволяет начать 03B, даже если E3 не закончен. Не требовать дополнительно исторический P-run, второй домен, static-order-1 baseline или перебор stale/cycle cases, если соответствующие deterministic границы не менялись. Эти проверки не удаляются: научные сравнения принадлежат 03B, изменённый риск — его локальному owner.

Параметры изменены ≠ прочитаны ≠ выбор изменился ≠ пользовательский ответ улучшился. OUTPUT_UNCHANGED после действительного reader допустим как наблюдение, но не gain. Accepted P сохраняется, trial U не продвигается автоматически.

**Права:** отдельно действующие PRODUCT_CODE/OBSERVE/EVALUATE; без implicit TRAIN, внешних моделей, private-data export или production effects. Planning write grant не расширяет эти права; действующее разрешение повторно не спрашивать.

## 3. Prompt — точная последовательность

1. **Не переобучать.** Открыть journal 02B и проверить C0/U/accepted-parent compatibility. Если update уже applied/pending, продолжать его observation/ownership recovery, не менять signal ID и не начинать новый optimizer step. Перезапуск процесса не отменяет одноразовость сигнала.
2. **Выбрать один runnable typed structural case.** В нём должны действительно существовать направленные order-2/3 motifs, а не только AxisSweep flag profiles. Зафиксировать ports/direction/dependencies/law, actual topology и допустимый pool. Пример: чистое построение C# patch proposal с точно заданными required-nullability условиями. Второй домен пока не обязателен.
3. **Загрузить C0/U в одинаковый штатный consumer.** Отдельные cold processes либо доказанно изолированные snapshots, одинаковые code/entry/config/flags/non-target weights и budget. Для каждого `(case,condition,repeat,attempt)` новый invocation wrapper. One-shot `RunAsync` после первой, даже cancelled, попытки возвращает ALREADY_STARTED; не переиспользовать wrapper, не ослаблять guard. При fresh factory сохранить нужное theta_motif и совместимый runtime scope; проверить mutable dependencies, чтобы C0 не увидел U через общий объект.
4. **Зафиксировать реально выполненный маршрут.** Сохранить prepared_scenario, invocation_id, runtime_scope, actual E4 reader method/hash и route_class. Legacy pre-route/fallback не означает TARGET_USED. Target selection ещё не terminal target execution. Проверить default nonlearning bootstrap и actual selected-target reader, а не его наличие в исходниках.
5. **Проследить ordered payload до ответа.** Theta_motif → legal ordered motif → actual graph execution → действительно decoded PathOrderRef → typed OutputRefs → final arbiter → returned TOutput. Order-free upstream set, sorted refs или рост числа edges не доказывают исполнения order-3. Для inherited async path доказать CombinationId lineage после flattening и stable-ID→dispatch ordinal. Inner LegalStatus/Status, tenant/consent и effect guard проверяются отдельно от clean batch. Не объявлять отсутствие локального guard vulnerability, пока не прочитан downstream enforcement.
6. **Передать измеримое наблюдение.** Вернуть C0/U typed output, motif/reader/state signatures, selected-vs-executed evidence и branch-inclusive available cost. Это позволяет 03B измерять generalization, context-dependence, static-vs-learned ablations, вторые домены и bulk. Сохранить narrow status, не требовать положительного gain от этой карточки.

## 4. Примеры, ошибки и восстановление

| Случай | GOOD и причина | BAD и причина | EDGE / действие |
|---|---|---|---|
| Ordered execution | Typed dependencies реально задают допустимый order-3, final target возвращает patch, reader читает U. | PathOrderRef напечатан, но не decoded; selected node не исполнен. | NO_ADOPTION с конкретным resolver/invoker gap; не обучать ещё раз. |

| Invocation lifecycle | Два fresh wrappers сохраняют нужные C0/U states. | Один wrapper на весь bulk либо fresh machine без обученных weights. | ALREADY_STARTED — infrastructure failure, не rejected semantic answer. |
| Law | Non-null-required precondition соблюдён перед защищённой операцией; nullable SQL parameter preparation отдельно допустима. | Любое Bind-before-NullGuard объявлено незаконным. | Сначала выяснить semantics/schema; LAW_UNRESOLVED, не ложная DPO pair. |
| Coreference handoff | EN→RU carrier сохраняет роль и referent; мужская форма может относиться к новому мужскому субъекту. | Запретить мужские формы после любого женского существительного. | Ambiguous reference → допустимые альтернативы/clarification; владелец representation RP02. |
| Отказ | Stale coordinate/ref, удалённый Unit, цикл или revoked right дают безопасный отказ/совместимый parent. | Большой learned score обходит типы/consent либо partial batch выдаётся как normal output. | Сохранить trace и нужный changed-risk owner, не отключать safeguards. |

Все примеры — конструкции для задания, не реально сгенерированные Chinese DPO и не результаты эксперимента. «Лучший граф» без известного законного comparator — неподтверждённое утверждение.
