## 1. Задание, границы, ближайший результат

**CURRENT TASK:** На ОДНОМ готовом законном предметном случае показать полную цепочку `cold C0/U → реально прочитанная theta E3 → выбранный разрешённый вариант → фактическое исполнение → разрешённый типизированный TOutput → окончательный arbiter → ответ пользователю`. Сначала переиспользовать достаточное совместимое доказательство из 01B. Не создавать вторую демонстрацию ради номера карточки.

**NOT THE TASK:** Новый optimizer step; RP01 response DPO; RP02 tokenizer/vector/kNN; RP03 Unit/Flow; E4; общий Windows-run; расширение покрытия; повтор R01–R25; полный многодоменный экзамен. Исторический P как третий запускаемый comparator, второй домен и новая cancel/retry-кампания НЕ являются обязательными условиями первого ADOPTION_OBSERVED. Они принадлежат 03B или конкретному изменённому deterministic-risk.

**Готовность передачи:** один фактический cold C0/U trace одного домена, совместимые state identities и реальный typed output позволяют передать в 03B статус ADOPTION_OBSERVED_SINGLE_DOMAIN. Это не CAUSAL_GAIN, не широкая domain-adaptive способность и не production promotion. Если state загружен, но не прочитан — STATE_LOADED_NOT_USED; если прочитан, но результат тот же — ORDINARY_USED_OUTPUT_UNCHANGED, а не выдуманное улучшение.

Права PRODUCT_CODE/OBSERVE/EVALUATE применять только в уже разрешённом объёме; grant на planning Git не даёт TRAIN/PROVIDER/EXPORT/PRODUCTION_EFFECT. Не запрашивать заново действующее разрешение. Подготовленный trial не заменяет принятый production parent без отдельного решения.

## 3. Prompt исполнителю — выполнить по порядку

1. **Восстановить состояние, не повторять урок.** Проверить journal и совместимые receipts 01B. Applied/pending update не повторять с новым signal ID. Для C0/U использовать их реальную immutable snapshot lineage; accepted P сохранять для rollback. Исторический запуск P выполнять только если он нужен для отдельного явно названного вопроса.
2. **Выбрать один готовый случай.** Например, read-only C# patch proposal с явной nullable-precondition либо другой уже runnable domain. Не ждать языка/SQL/ID одновременно. Записать вход, ожидаемый тип, law mask, разрешённые candidate IDs и фактическую классификацию вмешательства: CONFIG_PREF, RESULT_RANK, DISPATCH_ORDER, DISPATCH_SUBSET, реальный learned stop. Flags-only != structural path.
3. **Сделать cold-loading и fresh invocations правильно.** Для C0 и U использовать отдельные cold processes либо подтверждённо изолированные loaded snapshots на одном штатном entry с одинаковым кодом/flags/config/non-target state. Для каждого `(case,condition,repeat,attempt)` получить НОВЫЙ invocation wrapper штатной factory. `DynamicGraphCandidateInvocationOrchestrator.RunAsync` расходует wrapper уже при первой попытке, в том числе cancelled. Не ослаблять `_started`; не превращать новую factory в сброс theta. Проверить scope mutable runtime/dependencies: fresh wrapper сам по себе не исключает shared-state contamination.
4. **Доказать настоящий reader и маршрут.** Сохранить prepared_scenario, invocation_id, runtime_scope, loaded_state_hash, actual_reader_method, reader_state_hash, route_class, stable CombinationId и dispatch ordinal. Legacy pre-route может дать правильный ответ, минуя candidate runner: это LEGACY_PRE_ROUTE, не TARGET_USED. Default Compose/nonlearning flags проверить по реально вызванной factory. Один ScenarioId, файл checkpoint или хороший ответ не доказывает применения theta.
5. **Проследить ответ до конца.** `theta → law-admitted plan → actual selected target invocation → typed OutputRefs → D-15 arbiter → returned TOutput`. Выбор target не равен исполнению. После flattening сохранить CombinationId lineage; array position не identity. Complete clean batch не заменяет inner LegalStatus/Status, tenant/consent и final effect guard. PARTIAL_FAILURE/foreign/stale batch не выдавать за успешный ordinary result. Если downstream guard неизвестен, GUARD_UNPROVEN, без выдуманной security vulnerability.
6. **Сохранить краткий результат и передать в 03B.** Вернуть оба raw typed outputs, состояние/решение, все доступные branch statuses и затраты. Rank changed, output changed, output better — разные утверждения. На этой карточке достаточно первого корректно наблюдённого использования состояния; многодоменная независимая оценка, context-reversal, исторические/structural ablations и bulk принадлежат 03B.

## 4. GOOD / BAD / EDGE — конкретные различители

| Случай | GOOD и почему | BAD и почему | Восстановление |
|---|---|---|---|
| Два условия | C0/U имеют разные invocation IDs, одинаковую конфигурацию и разные нужные state hashes. | Второй RunAsync того же wrapper получает ALREADY_STARTED и объявляется ошибкой learner. | Fresh wrapper; прежние попытки остаются в журнале/стоимости. Не повторять optimizer. |
| Cold reload | Новый процесс действительно читает U, затем штатный target возвращает типизированный patch. | Scorer использует U, но обычный host читает P или идёт ProjectWiki bypass. | STATE_ONLY/TARGET_NOT_USED; назвать отсутствующий reader, не расширять инфраструктуру без причины. |
| C# / SQL | Для non-null-required операции guard перед защищённым dereference/execute. Для nullable schema допустима подготовка DBNull parameter. | Универсально объявить Bind-before-NullGuard нарушением независимо от семантики операции. | LAW_UNRESOLVED до проверки precondition/schema; не изготовлять ложный negative. |
| Отмена/эффект | Реальный owner завершает/отменяет child; consent проверяется перед одним разрешённым effect. | Возврат по timeout считается остановкой child либо новая attempt повторяет effect. | Сверить исходный journal/ownership и terminal receipt; не запускать зависающий in-process child. |
| Выход | OutputRefs разрешены в requested TOutput, final arbiter подтверждён. | Возвращён только ID, IQueryable refs или частичный batch. | ADOPTION_NOT_VERIFIED; один точный resolver/consumer gap. |

Удалённый Unit/OutputRef, неизвестный dialect, несовместимые coordinate/law versions или revoked consent → безопасный отказ либо совместимый accepted parent. Не выполнять реальный эффект ради отрицательного примера. При native SAC blocker использовать только уже подтверждённый supported CORE_ONLY путь с IDE_NOT_VERIFIED; не крутить Windows Actions.
