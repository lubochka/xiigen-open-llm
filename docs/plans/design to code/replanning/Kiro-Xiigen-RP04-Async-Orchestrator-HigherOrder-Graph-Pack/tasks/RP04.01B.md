## 3. Prompt — исполнение

1. **State-first и настоящее вмешательство.** Открыть journal/checkpoint и classify new/not_applied/applied/awaiting_evaluation/unknown. Unknown reconcile у существующего owner. Выбрать одно: CONFIG_PREF, RESULT_RANK, DISPATCH_ORDER, DISPATCH_SUBSET или доказанный learned stop. Назвать method, читающий theta, и конкретное решение. Текущий bounded runner обычно исполняет все supplied plans; post-result ranking не экономит уже выполненную работу. Null CandidateStream не early exit.
2. **Проверить сигнал.** Оба same-x/same-pool outcome FULL_CLEAN_OBSERVED, lawful, independently comparable и привязаны к CombinationId→materialized TOutput. UNOBSERVED/CANCELLED/PARTIAL_FAILURE/DENIED не observed negative. Forbidden plan не исполнять ради обучения. TIE/both-bad/unknown attribution/zero feature difference → NO_UPDATE. Source-observed route feedback не обязан ждать response-DPO author; response-pair-derived signal требует реальных 03A role/provenance receipts и явного recipient/objective.
3. **Зафиксировать deterministic/learned границу.** RP02 law eligibility, domain/role/vector tokens, dynamic kNN metric/k/index, LoRA projection, RP03 Unit/Flow, E4/Student, pool/law version, decoder/judge/config/budget — frozen. Hard-law mask и final arbiter не заменять штрафом в score. Domain laws определяют допустимость; learned score выбирает среди допустимых альтернатив. Все признаки доступны в момент решения; future answer/judge label/неизмеренная duration unexecuted plan запрещены для pre-dispatch policy.
4. **Сделать контекст действующим, а не декоративным.** Если используется linear score и `phi(x,p)=[c(x),a(p)]`, context term сокращается в pair difference: `score(x,p+)-score(x,p-)=w_a·(a(p+)-a(p-))`. Это глобальный ranking, не достаточная contextual model. Для DOMAIN_ADAPTIVE claim source-trace joint features `psi(x,p)` либо nonlinear joint scorer. Минимальный пример — sparse context×action interactions или существующий compact bilinear `c(x)^T W a(p)`. Не требовать полного tensor product, новой embeddings модели или второго RP02 tokenizer. Явно назвать content/role/dependency×plan взаимодействия и их versioned координаты. Если пока доступен только глобальный/config ranking, честно выполнить его первый разрешённый урок и назвать narrow capability; broad context claim оставить UNVERIFIED, не блокировать весь lane.
5. **Один численный update.** Reuse approved source-confirmed pairwise owner. Для linear preference: `d=phi_plus-phi_minus; m=theta·d; L=softplus(-m)+lambda*||theta||²; grad=-sigmoid(-m)*d+2*lambda*theta`. Для bilinear использовать его реальный gradient над joint features, не подставлять additive formula без соответствия. Actual approved optimizer/step settings, finite checks, numeric old/new и data-gradient отдельно от regularization. Shrinkage alone не учит preference. Consumed-once journal и atomic state owner обязательны; interrupted attempt не получает новое ID для повторного update. Это E3 pairwise objective, НЕ standard response DPO.
6. **Сохранить identity на decision seam.** При reordered dispatch `plan.Index` должен совпадать с list position, а CombinationId и canonical semantic tuple остаются прежними: `[A(index0),B(index1)]→[B(index0),A(index1)]`. Хранить stable ID→ordinal→output→feedback→update. Не regenerating ID из новой позиции. Равные scores используют declared tie-break, не fabricated preference. Для RESULT_RANK без reorder — index change NOT_APPLICABLE.
7. **Persist/cold use без второй тренировки.** Accepted parent recoverable; C0 — тот же pre-update state на исправленном software без ЭТОГО update, не обнуление прежних навыков; U — один attributable update. Для paired ordinary observation один и тот же поддержанный entry/config, но fresh one-shot invocation wrapper для каждого condition/attempt. ## 4. GOOD / BAD / EDGE

**Численный пример направления, не hyperparameter recommendation:** `phi+=(1,0), phi-=(0,1), theta=(0,0), lambda=0, illustrative eta=.1` дают `grad=(-.5,.5), theta_new=(.05,-.05), margin=.1`. Actual execution обязан сохранить свои approved values. При `d=0` regularization не доказывает preference learning.

**GOOD RESULT_RANK:** оба lawful plans реально выполнены; U reader выбирает независимо лучший typed answer; stable IDs сохранены; стоимость всех вариантов опубликована. **BAD:** названо снижение total work только по winning score/latency. Исправление — scope claim, не выдуманный speedup.

**GOOD CONTEXT:** одинаковые A/B допустимы для x1 и x2, rubric предпочитает A в x1 и B в x2; scorer имеет decision-time joint interactions. C# pure strategies для маленького/большого входа или SQL equivalent read-only algorithms для разных распределений — возможные controlled examples, но preference требует наблюдаемой quality/cost цели. **BAD:** выбор меняет лишь law mask; это guard, не learned contextual ranking. EN→RU два допустимых регистра можно различать по явно запрошенному стилю; agreement/coreference law отдельно обязательно.

**BAD STRUCTURE:** четыре flag profiles одного узла названы четырьмя multi-step routes. Narrow CONFIG_PREF оставить полезным результатом, structural claim снять. **BAD CAUSAL:** вместе с theta поменять RP02 kNN/tokenization, скрыть timeout как negative или обучаться по array position.

**EDGE:** nonfinite gradient/features → no mutation; missing writer → exact 00B seam; consumed signal → resume receipt; stale schema/law → compatibility decision; conflicting grades → adjudicate без переписывания judged bytes; no cold reader → STATE_CHANGED_ONLY/01C gap. Только один eligible plan или отсутствует genuine opposite preference → NO_VALID_CONTEXT_REVERSAL, а не искусственный loser. P сохранить; не ослаблять rubric и не rerun-until-green.
