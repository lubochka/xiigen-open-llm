## 6. Raw ledger и метрики

Отдельно считать:

- **Общий пользовательский результат:** lawful correct / ALL assigned applicable requests. Failed/missing/ALREADY_STARTED остаются видимыми в общем знаменателе. Отдельно justified abstention и unjustified refusal.
- **Применение learner:** TARGET_USED / ALL assigned cases, отдельно legacy/fallback/unknown. Gain на target-used subset допустим лишь с явным N и unconditional user score; нельзя убрать bypass failures ради красивого эффекта.
- **Domain mapping:** correct domain/compatible set, confusion и unknown handling. В A/D RP02 frozen; новая mapping claim принадлежит B и RP02 owner.
- **Reach vs rank:** correct lawful target emitted / oracle-known cases; selected correct / oracle-in-pool; unconditional success. Не прятать starvation за conditional score.
- **Paired change:** `(gains-losses)/same paired N`, uncertainty на independent source-family level. Пример арифметики: 3 gains и 1 loss из 24 — +2/24, не +3/24. Repeats одной family не новые independent items.
- **Контекст:** reversed preference success только на independently established reversal families; law mask одинаково допускает A/B. На mixed/unknown не требовать искусственного winner.
- **Стоимость:** ordinary start→valid output/end; proposal/admission/execution/cancellation-drain; ALL branches/retries; actual CPU/GPU work, peak RAM/VRAM, index/graph/tokenizer/adapter/optimizer/checkpoint/journal bytes, cold start/reindex, teacher/judge cost. Concurrent wall durations не складываются в request latency. Отдельно time-to-first-actual-update, training time и exam time, без вывода human work из CI timestamps. Отсутствующее измерение NA, не 0.

Timeout/cancel request не доказывает child completion или resource release. В inspected runner proposal work предшествует timeout/stopwatch, cancellation drain отдельный; нужны actual caller/termination ownership receipts. Не запускать специально hanging in-process job.

## 7. Bulk, гибрид и compact PC

После isolated comparison B0→B1→B2 — реальные authorized successive bulks уникальных новых lessons; один old pair/signal не переименовывать для replay. Для каждого bulk отдельно new-family capability, retention прежних families, cross-domain interference, marginal training/evaluation time и полные bytes/resources. Записать exam exposure; увиденные evaluator corrections не возвращать в sealed T как независимые.

Hybrid comparison — после первого useful lesson: deterministic baseline D, learned L только при сохранённых rights/security constraints, lawful hard-mask+learner H с matched resource budget. Не отключать consent ради L. E3×E4 interaction — только после доступности обоих, не блокировка первого lane. RP02 владеет domain/token/vector/dynamic-kNN сравнением; RP03 many→many и Flow correction; RP18 в существующем crosswalk — actual LoRA→semantic projection reader; RP01 — Student response DPO. Не смешивать recipients в одном causal claim.

LoRA является low-rank parameter adaptation, поэтому сам факт LoRA не доказывает tokenizer/semantic projection: нужен именно project-specific transform→versioned vector→real consumer receipt. Response-DPO отличается от route/motif pairwise objective. Primary methodological references: [DPO](https://arxiv.org/abs/2305.18290), [LoRA](https://arxiv.org/abs/2106.09685). SQL example qualification: [Microsoft SqlParameter.IsNullable](https://learn.microsoft.com/en-us/dotnet/api/microsoft.data.sqlclient.sqlparameter.isnullable) не валидирует parameter value; business nullability определяется задачей/schema, не property name.

Компактность доказывается quality/work/state tradeoff и retention на действительном PC budget. Маленький checkpoint при худшем поведении либо быстрый winner при выполнении всех losers не доказывает compact efficient learning. Не обещать выполнение на любом PC без указанного hardware и измерений.
