### Feature/algorithm constraints
- For E3 admit before rank. Utility candidate: observed lawful final success − pre-registered resource penalty; estimates may rank, but **unknown branch outcome stays UNKNOWN**. Prefer a tiny contextual linear/pairwise scorer or verified existing edge-ranker. A stochastic preference objective is NOT automatically full language-model DPO loss.
- For E4 pattern token = directed ordered ports + typed input/output + actor/referent/negation + logical dependency + domain-law applicability + time/version/provenance + embedding schema. Learn preference for novel order-2/3 paths, not edge-count.
- RP02 owns domain mapper, role-specific vector tokenization, dynamic lawful kNN selection and scorer; **not plain top-k neighborhood**. For EN→RU, next token depends on part of speech, syntax slot, grammatical gender/number/case and referent continuity **with speaker/referent-switch exceptions**. kNN distances are only evidence after domain-law masks and coordinate compatibility.
- LoRA weights/generation targets, projection to semantic tokens and domain-sensitive embedding coordinates are different mechanisms. Never assume changed LoRA implies automatically updated kNN space. Freeze them when measuring E3 or E4; handoff needed changes to RP02/RP18.
- DPO is not a replacement for every learned objective; if an E3/E4 ranker consumes preferences, define its own exact \`pairwise/logistic\` or credit objective and data admission. Only claim standard Student DPO after verifying response-only mask and policy/reference log-probability objective in the actual trainer.
