## Точный ход

1. Переоткрой существующий intent/checkpoint до повторного применения события. Идентифицируй parent, Wtrial, feedback_id, domain/law/port/feature-order/coordinate/index schema, rights/tenant и trial identity. Отдельно snapshot live accepted descriptor/pointer или NONE. Не предполагай accepted W0.
2. Переиспользуй existing transactional state owner, если он обеспечивает coherent state. Если нет, минимальный выбранный дизайн для single-writer trial: immutable versioned checkpoint payload {numeric W, compatible schemas, consumed event ledger, parent ref}, checksum; temp write+durable flush+atomic pointer replacement на поддерживаемом filesystem. Все guarantees привязать к реальной платформе. Единственный writer/expected-version CAS не допускает stale overwrite. Не строить distributed store ради одного урока.
3. Публикация commit boundary должна связать W и consumed feedback ledger: недопустимы новая W без ledger или ledger без W. Не отдавать partially committed state reader. При неизвестном исходе после crash сначала reconcile имеющийся intent/pointer; только затем решать о восстановлении, без нового event ID.
4. Заверши PID1; запусти PID2 через реальный **isolated experiment entry** с тем же scorer/serializer implementation. Из bytes загрузи Wtrial, snapshot/version и applied ledger. Запиши PID, executable/command, file digest, actual reader version и scores на зафиксированном lawful x. Не использовать object/static dictionary из PID1.
5. Cold scores/state должны удовлетворять тому же declared inference contract. Rank flip относительно W0 НЕ требуется; stochastic generated text не обязан быть побайтно одинаковым. Replay того же event не меняет W/ledger. В trial восстанови parent W+schema+ledger+pointer и проверь совместимый reader; parent restore не удаляет audit происхождения уже attempted event.
6. Убедись, что обычный accepted live tuple не менялся во время trial/cold/rollback. Если trial rejected, старый serving продолжает работать. Нет live parent — NONE/NOT_ADOPTED, не fake Trusted.
7. Передай 03B `TRIAL_COLD_CONSUMED` и 02C технический publisher contract. **Только после отдельного scoped admission** 02C может использовать machinery для согласованной публикации accepted W+registry tuple. При её отказе откатить и W, и served pointer; один saved hash не является quality acceptance.

## Примеры, края, ошибки

**GOOD:** PID2 загрузил Wtrial из persisted bytes через shared reader, scores соответствуют checkpoint; replay оставил digest; parent restore восстановил trial; live accepted descriptor не изменён. Это cold learning-state evidence, не ordinary adoption.

**BAD:** cold требует fake IsLearned/Trusted; вставить новый Candidate под accepted exact-ID и ждать fallback; restore только W при оставшемся rejected registry tuple; запустить второй object в том же PID; повторить feedback из-за потерянного stdout. Почему: false serving, shadowing, incoherent state, warm-cache или duplicate update.

**EDGE:** torn write, corrupt checksum, incompatible law/coordinates, concurrent writer, revoked rights, OOM/native DLL refusal. Quarantine candidate и загрузить валидный parent либо fail closed. При native block сохранить точную команду/ошибку и BLOCKED_COLD; не отключать App Control и не запускать blanket GitHub Windows suite как замену.

**Recovery:** определить первую повреждённую пару payload/pointer/ledger, восстановить последний совместимый immutable parent. Если writer не атомарен — исправить только этот owner. **Falsifier:** новый PID не прочитал bytes; replay даёт второй delta; live tuple изменён без admission; восстановлена W без совместимой schema/ledger.
