## GOOD / BAD / EDGE

**GOOD:** fresh PID читает accepted W, обычный endpoint выдаёт source-correct typed result, actual next Unit вызван; N/latency/footprint и новый consented event записаны. Scope ordinary показан прямо.

**BAD:** warm isolated scorer benchmark назван PC adoption; запись весов без Host reader; скрыта память base model/index; trial W0 искусственно admitted; guard отключён ради скорости. Почему: подмена продукта, неполный бюджет или security bypass.

**EDGE:** offline, OOM, native DLL/App Control refusal, revoked feedback consent, stale coordinate, corruption. Fail closed/rollback approved parent, exact error/command; не переносить этот blocker назад на уже завершённое isolated learning. Для N=1 distribution выводы ограничены; не выдумывать надёжный p95.

**Recovery:** первая missing consumer/publisher boundary получает narrow owner repair. Если cold Host недоступен — BLOCKED_LOCAL_PC с actual failure, upstream receipts сохраняются. **Falsifier:** loaded W/approved tuple не совпадают, actual target/Host отсутствует, несопоставимые comparator scopes или скрытые расходы.
