## 3. Hybrid architecture and domain-law distinction

**L2 ILearningUnit:** configured domain, requested typed input/output, vector tokenization/semantic coordinates from RP02. For multiple request IDs, each may produce 0/1/N associated candidate outputs. Required per-request explicit `SourceInputIds` to candidate→actual authorized `OutputRef`→actual materialized TOutput; shared result `o2` may be associated with BOTH q1 and q2. Do not zip arrays by index, stringify IDs as output or use corpus evidence `SourceIds` as request provenance. Preserve present ILogicalUnit ABI with smallest compatible adapter/sidecar.

**L3 ILearningFlow:** F0 enforces genuinely deterministic hard constraints (typed ports/nullability, known domain-law invariants, rights/tenant/consent, schema/embedding versions, TTL, cancellation, cycles, effects, budgets and final arbiter). Then F1 scores **only eligible legal** target transformations (identity, typed projection, lawful fan-out/fan-in, bounded ReturnLoop) with a versioned learned L2 relation policy. 0 legal options=ABSTAIN; 1=deterministic route/no update; 2+=learn only on a real independently observed preference among **two F0-lawful alternatives for SAME input**. A forbidden action may be retained as warning/negative retrieval example but never executable F1 loser.

**Domain laws:** LAW_HARD only if objectively enforceable from explicit schema/contract or authoritative arbiter (e.g. C# nullable declaration, fixed SQL tenant predicate, unambiguous negation, rights). LAW_CONDITIONAL depends on actual parser/POS/semantic entity resolution, dialect or source context. LAW_SOFT includes uncertainty and empirical quality/style choice. Russian gender/coreference with ambiguous antecedent cannot be hardcoded as absolute F0 law; abstain/calibrate or route to independent judgment. KNN proximity is evidence memory, NOT law authority.

**RP02 interface, read-only in first Flow experiment:** DomainPassport = domain_id + law_version + requested input/output shape + tokenizer/codebook id + vector_space_id/coordinate_version + semantic feature schema + domain-law neighbor eligibility and arbiter warnings + distance/reranker id + adaptive_k/radius policy + index hash + uncertainty. Law-conditioning and dynamic k matter, not simply taking more nearest neighbours. Freeze RP02 policy in C0/T; later test it separately. RP18 LoRA→semantic-vector conversion only through a real separately trained, versioned projector and measured alignment; LoRA weights are not tokens/vectors.
