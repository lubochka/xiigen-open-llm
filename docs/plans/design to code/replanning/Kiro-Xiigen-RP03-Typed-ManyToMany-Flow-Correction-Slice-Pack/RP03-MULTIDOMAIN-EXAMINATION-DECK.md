## C# / CodeDocumentation — law is language/runtime semantics, not preferred wording
**CS-1 nullable N:M:** input Q-CS1: "Document method static int? ParseOrNull(string s)"; input Q-CS2: "Document method static int ParseOrThrow(string s)". Unit may emit [signature, nullability note, exception note] with OutputIds tagged by SourceInputIds; order intentionally shuffled. GOOD Q-CS1 says Nullable<int> permits null; Q-CS2 cannot silently return null. BAD swaps nullable and non-null semantics or uses sorted result position; why bad = false source association and hard C# contract violation. EDGE = identical surface text but different signatures/overloads, expired OutputRef or two methods sharing a lawful documentation snippet. Grade source association F1 + typed value and correctness.
**CS-2 nullable law choice:** one candidate PortTransform A preserves "int?" to "Nullable<int>" at next Unit, another B strips "?" to int. For a nullable input B is DETERMISTICALLY MASKED, even with learned score 0.999. GOOD Flow chooses A or ABSTAIN, BAD learned score overrides typing. This case checks safety, NOT semantic learning (only one lawful action).
**CS-3 legitimate learning choice:** two transformations both preserve type but differ in cost/clarity of overload resolution under a pinned C# language version. Independent graded end-task utility may prefer lower-cost route; F1 may learn preference among both legal routes. BAD: model changes C# language version or input code between P and T; invalid attribution.
**CS-4 negative/edge:** Task<Result<T>> vs Task<T>, CancellationToken cancellation-before-side-effect, unknown generic constraint. Independent compiler or language expert adjudicates hard law; missing project references ⇒ abstain rather than fabricate a compile pass.

## EN→RU translation — law is preserved meaning, negation, quantifiers and entities
**TR-1 negation:** input "You must not delete user data without consent." GOOD: "Нельзя удалять пользовательские данные без согласия." ALSO valid with other grammatical constructions. BAD: "Вы должны удалить пользовательские данные без согласия." Why bad = reversed prohibition. Compare semantic rubric, not exact Russian string.
**TR-2 quantifier & association:** Q-TR1 "At least three copies"; Q-TR2 "At most three copies" produce correlated typed translation candidates; shuffled candidate order must not swap >=3 and <=3 meaning. GOOD preserves bound and SourceInputIds; BAD sorted hash or positional Zip. EDGE: numerals written in words, inflections and multiple lawful RU phrasings.
**TR-3 entity & units:** "Do not exceed 5 mg per kg." GOOD retains prohibition, 5 mg/kg and target entity; BAD drops "not" or changes mg to g. A very fluent mistranslation is still a hard negative.
**TR-4 ambiguity:** "They filed the charge." Legal translations depend on legal/electrical context; UNKNOWN/MIXED must ask for context or return alternatives/uncertainty, not give arbitrary fake high-confidence correctness.

## SQL — third structurally distinct domain; pin engine/version/dialect
**SQL-1 three-valued logic:** for standard SQL "WHERE deleted_at = NULL" does not select NULLs. GOOD suggests "IS NULL" when the intended condition is null testing; BAD treats "=" as equivalent; why bad = UNKNOWN in three-valued logic. Check dialect and query intent first.
**SQL-2 NOT IN subquery containing NULL:** one source variant has NULL, another explicitly filters NULL out; lawfully different results. GOOD preserves source association and discusses UNKNOWN; BAD identical generic answer to both. EDGE engine-specific semantics; if oracle absent, UNKNOWN not forced PASS.
**SQL-3 fan-in join:** two result sources for the same tenant with independently typed columns can be joined only on explicit keys; GOOD deterministic type/tenant mask plus learned ordering of eligible plans, BAD merges solely on output order or crosses tenants. Learning must not bypass hard SQL integrity.
**SQL-4 performance-only choice:** two equivalent query plans under same DB stats/dataset and permission; measure actual wall/CPU/memory, not merely pretty SQL output. Differences caused by changed dataset invalidate the ablation.
