## Подробный prompt

**A — разделить решения.** Trace request → subject/domain/intent/stack → допустимый pool → features/vector → retrieval → использование соседей → learned selector → execution → final arbiter. Назови owner, schema/version, state и ordinary consumer каждого шага. Объясни, что меняется обучением, что лишь пополняется в памяти, что вычисляется детерминированно над learned parameters. Unknown/mixed domains, права, типы и законы предмета не маскировать forced label. Warning с ответом не abstention.

**B — функция поиска по домену.** Для каждого релевантного domain family предложи проверяемую форму, например `score_d(q,n)=Σ w_j(d,q;θ) φ_j(q,n)`, отдельно `k_d(q;η)`/radius/confidence/budget, допустимые признаки, диапазоны и обновляемые параметры. Это гипотеза, не объявленный лучший metric. Не утверждай metric properties для query-dependent score без доказательства. Установи, подходит ли kNN предмету вообще; явно сравни вариант без него. Выдели BM25, exact retrieval, ANN, reranking, aggregation и final authority как разные компоненты. Проверь actual index API: custom score не автоматически поддерживается cosine backend. Representation migration требует совместимых index/checkpoint versions и учёта reindex.

**C — реальный consumer и граф.** В текущем коде проверь finding «первый hit даёт Output, остальные только evidence IDs». Если так, увеличение k не значит объединение результатов. Проследи learned edge authority, L2 decision, L3 execution, preload/adoption и typed associations; existing inactive path не отсутствие всего runtime. Раздели solver улучшение и selector обучение; кредит назначается actual recipient, а не победителю по имени. Сохрани positive/negative/warning memory, semantic order и final arbiter. Отдельно укажи, нужен ли L3 выбранному первому documentation lesson.

## Outputs / examination

Пять собственных carriers: mechanism/authority map; domain-specific candidate-function passports; exact/ANN/neighbor-consumer constraints; current→candidate deltas; R07/R08/R12/R13 receipts. Documentary acceptance: на одном single-domain и одном mixed-domain запросе можно проследить каждое решение и назвать обучаемое состояние. «Найдены kNN классы» недостаточно.

Future experiments: oracle-domain vs predicted-domain при одинаковом solver; fixed pool/representation vs changed selector; fixed neighbors vs changed aggregation; exact vs ANN при одинаковой функции; same memory/no-update vs learner; OOD, duplicate families, sparse corpus. Измерять mapping precision/recall или task-appropriate set metric, retrieval relevance, path validity, downstream quality, latency, index bytes/rebuild и retention. Пороги выбрать до наблюдений в R13/R22. Никаких product tests здесь.

**Good:** при одинаковом pool learned reranker выбирает законный путь лучше fixed policy; цена всех вариантов учтена. **Bad:** повысили k с 5 до 20 и объявили обучение, хотя используется первый hit. **Edge:** ноль допустимых соседей; разные версии codebook; численно близкие, но законно несовместимые записи; более релевантный результат стоит больше бюджета; неизвестный domain; ошибочный confidence.
