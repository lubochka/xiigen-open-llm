## Подробный prompt

**A — бюджет целой системы.** Перечисли одновременно резидентные base/runtime/encoder/codebook/adapters/activations/optimizer/index/graph/cache/snapshots и transient copy/reindex/load buffers. Отдельно disk growth и CPU/GPU boundary, teacher/assessor/evaluator placement/стоимость/передаваемые данные. Numeric budget привязать к declared hardware/config/dtype/context/batch/concurrency, не историческому предположению. Ширина async fan-out — ресурсная политика; девять research tasks не девять GPU training jobs. Считать worst observed peak и p50/p95/total, не только current-thread allocations.

**B — state machine.** Trace accepted state→request inference→weakness/feedback→validated novel lesson→pair admission→snapshot→one allowed update→awaiting examination→accept or full rollback→ordinary reload. Каждому переходу: durable identity, mutable data/owner, разрешённый side effect, recoverability и version compatibility. Учесть weights, LoRA, optimizer/scheduler/RNG/counters, applied/pending pair identities, encoder/index/graph manifests. Unknown outcome никогда не повторяет optimizer вслепую; publication failure не означает разрешённый второй урок. Local S04 и remote S05 разделены.

**C — feedback не truth.** Разделить пользовательскую preference, factual correction, изменившееся требование и malicious/erroneous input. Валидировать rights, scope/domain, novelty, conflict, evidence, cross-tenant/project isolation и нужную human/model authority. Сначала ordinary ответ текущей моделью; feedback не меняет веса синхронно в неподтверждённом request. Принятая новая task family учит нужного recipient, а не весь shared base без политики. Отрицательный/неясный опыт сохраняется как evidence, не forced promotion.

**D — controlled growth и retention.** Определить admission при capacity pressure, очередь/ограничение обучения, caching vs learned state, compact/reindex trigger, совместимую миграцию и архивирование по действующим правилам. Не удалять данные/weights этой задачей. Retention panel охватывает ранее изученные domains без скрытого training replay. Track total bytes/latency/time/quality по bulk и бюджету, а не только gain новой domain family. Стоимость snapshot/evaluation может доминировать update — измерять отдельно.

**Good:** latency и peak включают reload/reindex/snapshot и evaluator; ambiguous update восстановлен по журналу без повторения pair. **Bad:** «адаптер 2 MB, значит работает на ПК», thumbs-up = ground truth, S04 требует remote push до первого local inference, отчёт скрывает rejected updates. **Edge:** GPU OOM, disk full, stale index, power loss after update before verdict, schema migration, incompatible adapter, teacher unavailable, conflicting multi-user feedback, irreversible external action.
