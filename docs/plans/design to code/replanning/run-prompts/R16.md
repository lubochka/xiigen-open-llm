## A — восстановить источники и отличить READY от предложения

**Prompt:** Для каждого меняемого requirement ID прочитай origin → current active owner → latest R12/R13/R15 disposition → actual consumer. Заполни (source path/ref/exact span, expectation before, resolved owner decision, new observable behavior, deterministic law, learnable owner/state/signal/update, ordinary consumer, future experiment, current status, full-project dependent tasks). Не заполняй неизвестное догадкой. Historical 70/30 replay пометь конфликтом с текущим one-new-pair/no-repeat; не объявляй миграцию принятой. R12/R13 repair prompt опубликован ≠ repair исполнен. R15 findings доступны ≠ независимое Astra одобрение.

**Good:** R15 O5 требует E2 multi-neighbor consumer, поэтому dynamic-kNN — provisional learned policy с обязательной проверкой реального consumer, а не готовый алгоритм. **Bad:** R12 намеревается выполнить A–F, значит все четыре learned roles уже реализованы. **Edge:** два разных S04 snapshots, новая ветка core, PRIMARY не открыт, earlier PASS для иного SHA, R13 RUN-LOG конфликтует с DECISIONS. В любом случае сохранить limitation.

**Проверка A:** traceable ID/semantic source для каждого решения, текущие R12/R13/R15 статусы доступны и никакой R15-only suggestion не становится unreviewed product authority.

## B — точное исправление активных требований

**Prompt:** Вноси source-bound, минимальные и читаемые изменения по семействам:
- DPO: CODEX/Astra 6 UltraCode human case selection; внешняя китайская модель обе финальные стороны; отдельный CODEX/Astra exact-pair judgment (TIE/BOTH_BAD/UNJUDGEABLE не forced); Student trainer + независимый evaluator; frozen prompt/context/chosen/rejected identities, optimizer eligibility, rollback и ordinary product caller.
- ILearningUnit: domain+vector/input/output schema и typed many→many; hard types и law filters; state/signal/consumer/falsifier. ILearningFlow: correction/relations между Units. ILearningOrchestrator: асинхронное route/branch/budget selection. ILearningDynamicGraph: higher-order pattern relation/transfer. Каждое качество измерять самостоятельно. ILearningMachine actual trainer owner не заменять четырьмя trainers.
- E1 DPO; E2 domain mapping, law-sensitive tokenization/vector+index, fixed/exact baseline против learned kNN state/aggregation; E3 Flow/Orchestrator path; E4 Graph unseen compositions. LoRA ≠ tokenizer/преобразование смысла без source/target/trainable group/compatibility. Полный PC lifetime cost, feedback rights/novelty and cross-bulk retention.
- Проверка обучения: до исхода назначить frozen domain source-families/panel, same context no-update, baseline/challenger, delta threshold, allowable regressions, full resource metrics и ветки IMPROVE/REGRESS/INCONCLUSIVE/INVALID_EVIDENCE/NOT_MEASURED. Не подменять метрику coverage/Windows; не отключать реальные native/deterministic delivery safeguards.
- Документировать выбранное для actual product stage отдельно от contingent R12-F/R13 first-card/R15 CODEX independent review. Не удалять original requirement; если опыт отрицательный и валидный, работа над экспериментом завершена, но продуктовый прирост не доказан.

**Good:** «У E2 сохранены детерминированные фильтры, а learned reranker использует несколько законных соседей; oracle-domain и predicted-domain проверяются раздельно». **Bad:** «увеличим k до 8 и объявим dynamic learning»; «неудачный Chinese rejected перепишет CODEX и останется Chinese-authored»; «запуск Windows зелёный → Student стал лучше». **Edge:** пользовательский feedback содержит закрытый ответ; сменён индексный encoder без reindex; ambiguity/TIE; orphan state; reviewer недоступен; отрицательный опыт.

**Проверка B:** эти требования есть в **действующих** WorkLeft-02/INTEGRATION-01/00/RESEARCH-03, а не только в replanning отчёте/историческом DPO. Сохранены S04 local/S05 remote/S06 new lessons и 95% owner domain rubric.
