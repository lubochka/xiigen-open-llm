## 4. Неизменные роли и архитектурный смысл

**Роль человека в выборе урока выполняет CODEX с Astra 6 ultracode. Допущенная внешняя открытая китайская модель создаёт ОБЕ окончательные стороны chosen/rejected. CODEX с той же Astra 6 ultracode отдельно оценивает качество точной пары в точном разрешённом контексте.** Native `GPT-6-Astra` + `ultra` — уже разрешённый alias, не новая проблема выбора модели. Отдельный Student weak response допустим как context автора, не автоматически final rejected. Reviewer не переписывает пару под Chinese provenance. Изменённый текст/context не наследует старую assessment. Requested/actual invocation, судья пары, DPO reference и независимая оценка Student различаются. Здесь эти model calls не выполняются.

Учебная пара должна иметь одинаковую задачу/разрешённый контекст обеих сторон, корректный полезный chosen, действительно хуже решающий ту же задачу rejected и объяснимый контраст. Правильный deterministic ответ не rejected по происхождению. TIE/BOTH_BAD/UNJUDGEABLE, недостаточный контекст и сомнительные права — не вынужденный выбор. Restricted/closed exam ответы нельзя отмывать через китайского автора. Hash/schema, semantic acceptance, optimizer eligibility, update, selected publication и utility — разные факты.

| Блок | Сохраняемая deterministic часть | Что может обучаться; различающее вмешательство |
|---|---|---|
| Unit | Domain/input/output schemas, допустимые операции и законы предмета, typed many→many associations | Представление или response/action preference конкретного recipient. Зафиксировать связи/память и сравнить отсутствие адаптации с разрешённой адаптацией. |
| Flow | Совместимость портов/версий и допустимость переходов | Отношения и коррекция результата одного Unit во вход другого. Заморозить Units, изменить только relation/correction policy; затем обратное вмешательство при отдельном основании. |
| Orchestrator | Lifecycle, cancellation, границы ресурсов и полномочий | Полезная асинхронная комбинация и следующий шаг. Зафиксировать Units/candidate universe, сравнить решение и цену всех веток; fastest branch не автоматически лучший ответ. |
| DynamicGraph | Типы, identity, допустимая структура и meaningful order | Отношения паттернов разных порядков. При тех же primitives оценить новые композиции; связь не учится от одного прироста числа edges. |

## 7. Часть B1 — faithful objective и два разных вопроса о margin

**Skills:** code-examination, trainable-architecture-decision, prompt-patch-authoring, plan-review. **Контекст:** CP2 FINDINGS §5 и DECISIONS §2 A/B; K/18.CapabilityTraining/LlmIngredientLogicalUnits.cs BuildBatch/Compact/ToMask; K/11.DPO/DpoTrainer.cs StepVector/ComputeLogProbs/BackwardLogProbs; plan-07 §3.2a; R02 margin locator; WorkLeft P4-1 §5B/§6 и R06-F13. **Выход:** уточнение существующего R18 work order и точные unresolved decisions R12, не новый trainer.

> Сохрани уже найденные F10/F11. Для standard probabilistic DPO запиши actual x/y, candidate unit, serializer, response boundaries, masks, aggregation, reference snapshot и trainable parameters:
> `m = beta * [(log pi_theta(y+|x)-log pi_ref(y+|x)) - (log pi_theta(y-|x)-log pi_ref(y-|x))]`, `L = -log sigmoid(m)`.
> Для autoregressive full-response цели likelihood суммируется по response tokens при данном context. Проверь actual boundary в совместной BPE serialization, одинаковую логику forward/backward и не измени незаметно публичный average inference scorer. Arbitrary similarity/vector distance или CODEX judge score не является такой likelihood; другой pairwise objective должен быть назван и обоснован отдельно.
>
> В части faithful preparation сохраняй semantic content обеих сторон и input laws; raw passport не оправдывает Compact. Реальный tokenizer/model limit проверяется до mutation. Overflow означает существующий bounded refusal, не тихую обрезку, увеличение 480 до другой константы или ручное сочинение нового rejected. Сокращённая/изменённая пара требует своей разрешённой авторизации и exact assessment, не наследует старую. Смысловая компрессия может исследоваться отдельно только при доказанной сохранности нужных различий.
>
> Раздели ТРИ вещи: (1) PE1.2p5/LOW_CONTRAST pre-update admission clause; (2) WorkLeft P4-1 правило обновления GraphNodePreferenceState по reward-margin; (3) actual DpoTrainer logistic gradient. При одинаковом scoring distribution pi_theta=pi_ref даёт m=0, L=log(2), dL/dm=-1/2; это не доказывает плохую пару и не гарантирует ненулевой gradient каждого параметра. Но отдельный node updater вида delta_state=f(margin) может действительно не менять своё состояние при m=0. Открой actual updater/caller и назначение state прежде вывода. R06-F13 — точный locator и вопрос, не готовый verdict о дефекте DpoTrainer или всех node updates. Проверь также, не блокирует ли отдельное zero-margin правило cold start всей связки. Не удаляй оба правила одним исправлением и не заявляй глобального отсутствия gate по поиску нескольких методов.

**Хорошо:** логистический gradient и reward-fed graph state явно разведены; изменяется только противоречащее своему objective требование после установления consumer. **Плохо:** «m=0 — всегда запрещено обучение» либо «dL/dm≠0 — любые node weights обязаны меняться»; zero margin объявлен эмпирическим наблюдением по равным весам при разных dropout modes. **Края:** разные длины ответов; общий prefix >480; значимые пробелы/literals; идентичные tokens; zero Jacobian; frozen params; разные policy/reference tokenizers; неизвестный state updater; обе стороны имеют ошибки.

**Приёмка сейчас:** таблица clause → actual consumer → equation/state → counterexample → disposition (SOURCE_ONLY / CODE_TRACED / NOT_TRACED / PROPOSED_CHANGE). Математика не выдаётся за execution. Источники формулы и LoRA: Rafailov et al., https://arxiv.org/abs/2305.18290 ; Hu et al., https://arxiv.org/abs/2106.09685 ; они не доказывают runtime XIIGEN. **Return:** сохранённый пакет lossless A → objective B; точные права/файлы/конфликты для R12/R16/R17/R18; один bounded resolver для неизвестного updater, не повтор всех WorkLeft.
