**A — authority reconciliation.** Прямо сверить original четырёхролевая цель, current DPO author/selector/judge policy, no-repeat, replay70/30 historical conflict, helpers/learned arbiter, local S04/remote S05 и S06 campaign. **B — решённые causal contracts.** Для Unit, Flow, Orchestrator, Graph задай input/output/type/multiplicity/association, deterministic admissibility, learned state/authority, signal/objective, update owner, ordinary caller, fallback, version и falsifier. Dependency order и cancellation не покупаются score.

**C — DPO.** Реши precise pair task/context/positive/negative/abstain contract и semantic recipient. Для **стандартного DPO** objective выражается как `-log σ(β[(log πθ(y+|x)-log πref(y+|x))-(log πθ(y-|x)-log πref(y-|x))])`; определить conditional probabilities, response masks, padding/EOS, sequence reduction/length policy, frozen reference и parameter group. Если текущий learner иной, назвать его точно и обосновать objective вместо ярлыка DPO. Both final sides Chinese-authored; CODEX/Astra selects lesson and separately assesses immutable pair; evaluator после update отдельный. No silent compact/truncation, no invalid receipt inheritance, full-state rollback и ordinary adoption. Не менять public inference scorer неявно.

**D — domain/vector/kNN.** Выбери **семейство** domain-specific representations и функций, не одинаковый универсальный vector. На translation/code/SQL/layout/orchestration примерах реши law-sensitive features, forbidden normalization, schema/codebook versions, learned weighting/reranking/aggregation, dynamic k/radius bounds, legal pool, exact reference и ANN assumptions. Dynamic score может не быть метрикой; index choice/reindex/cost должны соответствовать. Измеримые hypotheses вместо магического «лучшего k». OOD/mixed/unknown и typed mapping определены до реализации.

**E — LoRA/projector/PC.** Укажи source и target representation, trainable matrix/parameter group, frozen base, objective и actual downstream consumer. Low-rank adaptation может параметризовать projection, но не равна tokenization. Реши compatible checkpoint/index/adapters, snapshot/recovery, full model+optimizer+index+memory/snapshot footprint и bounded feedback lifecycle. Проектный PC profile проверить; численное fit/ускорение оставить hypothesis до измерений.

**F — связи и первая реализация.** На трёх walkthrough (single-domain, mixed-domain, unseen composition) покажи перенос смысла и правильный credit. Сравни альтернативы по causal bottleneck, information gain/effort и риску, не только цене патча. Выбери первый конкретный existing seam и последующий structurally different domain. Привяжи все решения к R13 examination, R16 requirement edits, R18 implementation work order, R21/R22 breadth. Full graph/laws/LoRA обязательства остаются в плане даже если первый опыт проще.
