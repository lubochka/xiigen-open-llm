## 5. Функциональная examination вместо coverage

Это проектирование опытов, а не создание unit/coverage suites. Проверка документа сейчас: source→functional expectation→mechanism/gap→контрпример→конкретный будущий опыт→owner. Проверка обучения позже: frozen parent/challenger, независимые task families, неизменная рубрика, одинаковые сведения и бюджет, обычный consumer, uncertainty и полная цена. Existing deterministic state/provenance/type constraints не объявлять лишними, но они не доказывают learned utility.

Сравнивать до/после **внутри каждого bulk на одной panel**; изменение состава следующих bulk отдельно учитывать. Development/operational panel, используемая для выбора улучшений, не untouched final exam. Семейство исходных задач — единица независимости; вариации одного примера не N независимых наблюдений. Порог практически значимого эффекта, допустимую регрессию, точность оценки и stop/budget выбрать до просмотра challenger. Нет универсальных выдуманных 95%/20×/2MB порогов; действующий noise-aware критерий не откатывать к старому голому проценту. Новое FINDINGS-REPAIR §7 содержит заполненный метод, но actual numeric/runtime bindings честно отделены; конкретный packet не READY с пустыми полями.

Обязательные независимые оси: domain/multidomain/OOD assignment; сохранение предметного смысла representation; neighbor relevance; valid path/associations; actual state update; DPO utility; adapter adoption; retention; latency/total time; RAM/VRAM/storage. Warning с возвращённым ответом не abstention. Best path означает лучший среди рассмотренных допустимых путей при заданном budget, не доказанный глобальный optimum.

Для причинности: no-update с сопоставимой памятью; oracle-domain против predicted-domain; fixed representation + changed neighbor function; fixed pool + changed selector; frozen Units + changed Flow; frozen Flow + changed Orchestrator; flat primitives + higher-order graph; accepted state в evaluator против того же state в обычном caller. Полный factorial до первого урока не нужен. Повторное обучение той же пары ради ablation не разрешено автоматически; сначала выбрать совместимый с no-repeat дизайн/отдельно разрешённые состояния.

Domain-specific kNN разделяет eligibility, features/scales, metric/score, k/radius, index, neighbor use и final authority. Query-dependent weights могут нарушать предположения индекса: нужен сопоставимый exact/reference путь и цена retrieval/reindex. «Больше k» не улучшение fusion, если consumer использует только первый hit. Geometry/code semantics/negation/SQL NULL/dependency order не стирать общей нормализацией. Ranking loss не именовать DPO без conditional policy/reference; одна solver victory не обучает selector.

PC считать целиком: base/reference/runtime/encoder/codebook/adapters/gradients/activations/optimizer/index/graph/cache/snapshots, storage growth, rollback/reindex/reload, teacher/assessor/evaluator, все ветви и неуспешные попытки. Семнадцать начатых research/analysis sessions не семнадцать конкурирующих GPU jobs. Hardware profile и scheduling фиксируются до measurements. Независимые component peaks не суммировать как измеренный simultaneous peak. Feedback: сначала ответ текущей версией, затем validation/rights/novelty/conflict, разрешённый новый урок, update, retention; user feedback не автоматически истина.

Вердикты будущего опыта: IMPROVE / REGRESS / INCONCLUSIVE / INVALID_EVIDENCE; без опыта NOT_MEASURED. Утверждение «компактнее и эффективнее» требует совместного quality/cost сравнения, не одной меньшей матрицы. Astra examination содержит независимое суждение, контраргументы и ссылки на output; не заменяет measurement и не гарантирует истинность.

## 6. Evidence, продолжение и приёмка

Любая передача: origin run/local ID/checkpoint/ref/span → точный вывод → limits → принимающий Rxx → изменённая строка/решение либо непринятый остаток. Namespaces R04:E01/E02, HANDOFF:E1–E4, AE6:E0–E6, HYBRID:Hxx, SRC-Rxx и FS-xx/FS-Dxx не смешивать.

Опора на 13.10.2026: R07 прежний bounded result не закрывает полный механизм; действует R07-REPAIR-WORK-ORDER. R08 прежние CP2/CP3 statuses исторические, current own checkpoint проверять на запуске; CP4 repaired packet сам не доказывает source-complete result. R09 — ограниченное сообщение о existing runs с невосстановленным raw sample; sum job elapsed, workflow elapsed, scheduler delay, runner usage, человеко-часы и invoice различать. Новые R11 и последующие results продолжать от их фактических carriers, не объявлять несуществующими по старому snapshot. Адресные completion/findings corrections §0 не выполняют чужие раунды.

Каждый результат: человеческий вывод; что прочитано непосредственно/атрибутировано; mechanism map; hypotheses и falsifiers; intended edits; good/bad/edge walkthrough; documentary acceptance; future experiment и consumer; остаток/размер; actual calls/model/ref; self-check versus independent review. Published DRAFT не accepted design. R15/R25 — реальные отдельные reviewer invocations, когда выполнены; без них NOT_PERFORMED, не вымышленный Astra PASS.

Child packet до вызова содержит конкретные CURRENT TASK/NOT THE TASK, роль/skills, source/ref/spans и load depth, input/output/association contract, current→target algorithm, bounded action, allowed/forbidden paths/commands, evidence-only границы, good/bad/edge и мысленный walkthrough, outputs/claim-evidence scope, documentary acceptance, future examination отдельно, finite budget/stop и return schema. Child не решает недостающую архитектуру под видом «добавить тесты» и не пишет shared files.

Научные первоисточники для адресной проверки, не свидетельства эффективности XIIGEN: Rafailov et al., DPO §4/Eq.7, https://arxiv.org/html/2305.18290v3 ; Hu et al., LoRA §4, https://arxiv.org/html/2106.09685v2 . Предложенные здесь causal contrasts и workload boundaries — план экспериментов, не опубликованные измерения.
