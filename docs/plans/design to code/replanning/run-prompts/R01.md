## Подробный prompt

**R01-A — расположение и authority.** Сопоставь tree entries с исходными продуктами DPO/DynamicGraph, DTC и IDE. Для каждого семейства запиши repo/ref/root, роль источника, preimage/blob, размер, current/history/unknown и обнаруженные преемники. Начни с реальных roots; Windows-адрес не является доступным checkout. Открой хотя бы вводную цель каждого root, который назначаешь; не называй это полным чтением. Найденные циклы RAG отдай R03 с visited identity.

**R01-B — предметная нагрузка.** Назначь владельца каждому активному source family и **отдельным смысловым spans** больших смешанных файлов. R02 requirements; R03 lineage; R04 representation; R05 DPO/update; R06 retrieval/authority; R07 whole-mechanism consistency; R08 domain laws/data; R09 process/resources. Размер файла не равен сложности: учитывай число контрактов, версий и переходов. R07/R10 не резерв всего непрочитанного. Для неизвестного семейства назначь вопрос/owner/consumer, не вычёркивай его.

**R01-C — проверка карты.** Сравни source families с каждым найденным slice и каждой original-prompt capability. Проведи обратный проход: выбери одну способность вне S04 и покажи путь от требования через RAG до primary/code owner. Найди обязательства, отсутствующие в slice queue. Обнови свой visited/coverage остаток; существующие source IDs не перенумеровывай.

Для незавершённого содержательного чтения статус NOT_READ, не COMPLETE. Это не доказательство, что весь repo прочитан или система обучается.

Future functional examination не выполняется R01: карта должна позволять R13/R21 выбрать домен и найти input→learner→ordinary output без угадывания владельца. Consumer R10 принимает по точным routes, не по количеству файлов.

Сохранить namespace/unknown; проверить только зависимую дельту.
