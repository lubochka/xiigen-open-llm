## Содержание пяти частей

**A — первичные обязательства и существующие исследования.** RAG→primary→successor; WorkLeft RESEARCH-01 и REVIEW-20 с честной глубиной чтения, семь предметов и original-only extras, все три направления и S00–S10. Двадцать прежних reviews не становятся двадцатью новыми.

**B — семь предметных паспортов.** Перевод и дополнительные языки, orchestration, Figma→HTML/CSS, C#, Angular, SQL, DPO Builder. В каждом нужны реальные scope/source, существенные features/tokens, good/hard-negative/valid alternative/unknown, source-family правило, kNN hypothesis, metric и consumer либо точный gap. Примеры внутри prompt — DOCUMENT_EXAMPLE / NOT_FOR_TRAINING, не admitted corpus.

**C — причинная связь с алгоритмами.** Отдельно Unit many→many, Flow correction, asynchronous Orchestrator и higher-order Graph; для каждого deterministic law, learned signal/state, actual consumer и различающий опыт. Domain mapping, representation и dynamic kNN разделены на измеримые факторы; число k и evidence IDs не доказывают полезное learned решение.

**D — DPO, LoRA и данные.** Exact pair→tokens/masks→objective→правильный recipient→ordinary consumer; пять диагностических verdict и запрет тихой перестановки/переписывания сторон. CODEX/Astra выбирает урок и отдельно оценивает пару, Chinese author пишет обе стороны, post-update evaluator отдельный. Loss-visible смысл, LoRA/projector bridge и source-family independence проверяются отдельно. Actual Compact/480-character seam и mean-score риск включены как bounded code evidence, не измеренный эффект.

**E — первый информативный опыт без обязательного E1-first.** Сравнить реальные кандидаты E1 DPO, E2 domain/representation/kNN, E3 Flow/Orchestrator, E4 DynamicGraph по вопросу, предпосылкам и полной цене. Existing CodeDocumentation Student сохраняется для его E1-урока; этот урок не блокирует независимый готовый E2/E3/E4. R08 сам заполняет предметный контраст, metric и family criterion; exact design/data/runtime fields связываются с R12/R13/R18. Далее — same-panel parent/challenger, новые уроки от bulk к bulk, time/accuracy/whole-PC cost/retention и continued feedback.

R08 пишет только свои пять `../results/R08/{SOURCES.csv,FINDINGS.md,DECISIONS.md,CHANGE-MAP.csv,RUN-LOG.md}`; children return-only. R10/R12/R13/R14/R17/R18/R21/R22 получают versioned subsets с конкретным источником, вопросом, ограничением и владельцем. Не вводить ALL_R01_R16_DONE и не менять чужие результаты.

Каждая часть полного поручения содержит роль, контекст, skills, подробный prompt, direct references/RAG, outputs, good/bad/edge, документную проверку сейчас, будущую функциональную проверку обучения и return. При делении child получает эти поля содержанием, а не один список ссылок.

Никаких product tests/coverage/Windows/Actions/build/training/model calls этим документным нарядом; existing safeguards не отключать. Prompt repair, research completeness, runtime mechanism, learning gain и independent review — отдельные статусы. Авторский self-check не independent Astra examination.
