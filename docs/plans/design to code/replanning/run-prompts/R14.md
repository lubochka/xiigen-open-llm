## Подробный prompt

**A — старое→новое без потерь.** Для каждого current task/slice/extra ID укажи исходную capability, actual code/evidence, dependency, стоимость/unknown, решение KEEP/REUSE/MERGE/DEFER/REPLACE и новый milestone/owner/trigger. Не создавать новые IDs, скрывающие потерю старых. Уже существующий equivalent implementation переиспользовать, но не принимать README как evidence. Большой mixed task делить по callable capability/experiment, не по числу строк документа.

**B — новая последовательность.** Размести сначала smallest validated learner seam и independent local examination, затем structurally different domain, затем нужные domain mapping/vector/kNN/Flow/Orchestrator/Graph interventions. PC/feedback integrity учитываются с первого loop, полный scale расширяется позже. DTC API/render/DB/remote publication/user-tier budgets и IDE indexing/task/execution/weakness/adoption не исчезают, а имеют cause-based milestones. Remote S05 и native qualification не универсальные первые gates.

**C — нагрузка.** R01–R09 остаются девятью независимыми research starts; R10 join может принимать checkpoint, но не fake DONE. R11–R15 анализируют достаточные relevant inputs; R16–R20 меняют resolved clauses; R21–R25 дополняют. Research parallelism отдельно от single-PC resource queue. В каждом milestone ограничить active hypothesis/intervention, data/evaluation budget, actual owner и resumption checkpoint. Не вводить отдельные 30/50-pass readiness loops из skills.

**D — проверка расписания.** Документно пройди позитивный first lesson, отсутствие gain, неготовый teacher, необходимость native consumer, следующий domain и higher-order graph transfer. Проверь отсутствие cycles и обязательств без consumer. Назови independent reviewer checkpoints R15/R25; их отсутствие не подменять self-PASS. Full delivery и narrow experiment имеют разные readiness.
