## 2. Общая архитектура и роли, которые передаются каждой подзадаче

Unit принимает domain, структуру входных векторов и выходную схему; возвращает **typed many→many** с сохранёнными associations. Flow учит/применяет отношения между units для коррекции input→output. Orchestrator асинхронно рассматривает комбинации. DynamicGraph моделирует отношения паттернов разных порядков. Это функциональные роли, не требование четырёх новых API: сопоставляй с actual ILogical*/ILearningMachine по поведению. `Train` остаётся у Machine; Graph — L5 specialization. Generic collection или `IQueryable` в сигнатуре не доказывает смысл, ленивость, streaming либо настоящий payload consumer.

Сохраняются TensorCore/shared base/project adapters, StackDetector-before-normalization, semantic compression, BM25+kNN, positive/negative/warning memory, final arbiter и learned authority. Для каждого алгоритма нужны deterministic contribution, изменяемое состояние/parameter group, signal/objective, владелец, producer, ordinary consumer и различающее вмешательство. Транспонирование A/B и равная размерность не доказывают семантическое выравнивание. При обновлении encoder/codebook отдельно определяются compatibility/index rebuild и rollback целого комплекта. No-update control имеет сопоставимые memory/context/compute; иначе эффект памяти не приписывать весам. Успех компактности формулируй как сохранение/улучшение полезности при меньшей полной цене, а не просто меньший adapter».

**Выход:** role→state→controlled intervention→semantic outcome→cost, exact unused/NOT_TRACED поля; один E02 или E01 recipe candidate. **Хорошо:** learned Flow улучшил новые relation families при неизменных Unit outputs; отдельно проверена retention. **Плохо:** изменены encoder/k/LoRA/graph сразу, хороший итог объявлен доказательством каждого блока. **Края:** async early wrong winner, cancellation cost, no-op gradient, новый adapter не загружен ordinary consumer, full index rebuild съел экономию, одинаковая ширина несовместимых embeddings. **Приёмка сейчас:** роли не потеряны, один effect не засчитан четырежды. **Будущая examination:** semantic quality, task completion/path quality, full latency, peak process RAM/VRAM, local/external cost, update/reindex cost, old-domain retention. **Стоп/передача:** R13 selects recipe; R18 one seam; R23 PC profile. Аппаратные лимиты не выдумывать и не требовать полной PC qualification для завершения исследования.

## 5. Предметные паспорта: не один пилот за всю программу

Каждая строка — expectation→representation→различающий случай→examination owner, не готовый корпус и не новая фиксированная онтология. Domain, intent, language/stack/project, schema, роль и slice — разные оси. Для закона нужны actual source/version/scope; веса/лицензии/данные не считаются допущенными по историческому названию.

| Предмет | Смысл, который нельзя потерять | Сравнение для будущего экзамена | Следующий владелец |
|---|---|---|---|
| EN↔RU, extra HE↔EN | Script/direction, negation, entities, quantities, referents | Lawful paraphrase против почти совпавшего ответа с перевёрнутым отрицанием; оценка смысла отдельно от character score | R08/R13/R21 |
| Orchestration | Port types, prerequisite edges, semantic order, allowed domain/skills | Те же units при иной зависимости; правильный путь против короткого пути с пропущенным prerequisite | R06/R07/R13 |
| Figma→HTML/CSS | Hierarchy, units, constraints, assets, responsive context | Похожий screenshot на одном разрешении против сохраняющего структуру решения на нескольких | R08/R21/R24 |
| C# documentation | Symbol binding, scope, type/nullability, version | Rename сохраняет binding; другой scope/nullable contract меняет смысл | R08/R21 |

| Builder для шести | Same task/context, genuine preference, recipient, semantic order, provenance | Правдоподобный rejected с существенной ошибкой против мусорного negative; TIE/BOTH_BAD/UNJUDGEABLE | R05/R08/R22 |

**Не путать два типа пар.** В representation diagnostic два входа x/x′ могут отличаться отрицанием или domain. В DPO обе стороны y+/y− отвечают **одному и тому же замороженному x**. Пример DPO: один запрос требует сначала проверить dependency, затем выполнить действие; chosen соблюдает этот порядок, rejected правдоподобно пропускает dependency. Два разных запроса не становятся DPO-парой. Примеры здесь объясняют рубрику, не являются новым admitted training dataset.

## 6. Приёмка исследования и будущая learning examination

**Сейчас:** source/authority→сохранённое функциональное ожидание→actual mechanism/gap→контрпример→конкретное наблюдение/owner. Различать DISCOVERED, SOURCE_READ, CODE_TRACE, SIBLING_EVIDENCE, HYPOTHESIS, EMPIRICAL_OBSERVATION. Чтение не принятие, accepted pair не accepted weights. Нет фактического независимого модельного вызова — `independent_review=NOT_PERFORMED`; нет опыта — `efficacy=NOT_MEASURED`.

**Перед будущим опытом R13 фиксирует:** actual code/state/consumer, lawful source-family IDs и split, tokenizer/schema/index versions, one-factor contrast, frozen reference/solver/knowledge, actual hardware/thread/cache conditions, budget, semantic rubric, useful-change/noise rule и stopping/confirmation checkpoint. Unknown input обозначается честно; не заполняется удобными числами. Training/development/operational/closed-confirmation разделены; парафразы и N−1 negatives одной source family не независимые samples. Closed answers не раскрываются selector/Chinese author.

**Сравниваем от bulk к bulk:** per-domain и macro quality; mapping confusion и качество solver при oracle-domain; eligible coverage/false accepts/real abstentions; lawful neighbor/path quality; accepted/restored/no-op lesson counts; время encoding/search/generation/update/evaluation и full wall time; peak process RAM/VRAM, model/adapters/optimizer/index/graph/cache/snapshots; failed/cancelled branches и rebuild; old-domain retention. GC current-thread allocation не peak RAM. При нуле полезных updates вернуть ноль и полные расходы, не делить на ноль. “Лучший путь” означает лучший среди определённого допустимого pool при указанном бюджете, не доказанный global optimum.

User feedback сначала наблюдается на текущем accepted состоянии, потом проверяются источник/полномочия/предметный смысл, затем допускается новый урок. Mutable training и ordinary inference читают согласованные версии. При неизвестном исходе update — recovery, не ещё один gradient. Отмена update не возвращает уже потраченные деньги или раскрытые данные.

**Вердикты опыта:** IMPROVE / REGRESS / INCONCLUSIVE / INVALID_EVIDENCE. Высокий cosine, shape, hash, loss, code coverage или зелёный Windows run сами по себе ни один из этих смысловых выводов не подтверждают. Сохранить отрицательный результат; не ослаблять экзамен после ответа и не назначать автоматические дополнительные серии до победы. Цель 95% сохраняется с определёнными population/rubric, но не подменяется confidence или универсальными Q30 числами.
