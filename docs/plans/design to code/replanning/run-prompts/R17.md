## 4. Подробный prompt A–F

### A — восстановить область и точные старые gates

**Роль:** планировщик + reviewer. **Skills:** phase-planning, plan-review, code-examination для спорного runtime claim. **Контекст:** §3 primary, R01/R02/R03 source/requirement receipts, R09 cost findings, R11 two DAG, current R16 sections.

Прочитай реальные acceptance paragraphs, а не только заголовки или S04. Создай source→old gate→protected property→new evidence→owner/trigger map. Отдельно учти S00–S10/extras, original-only obligations, DPO/DynamicGraph, DTC, IDE и найденные WorkLeft/RAG ветки. У каждого семейства статус CONTENT_READ/ATTRIBUTED/NOT_OBSERVED/NO_AFFECTED_CLAUSE_WITH_REASON; ни одно не исчезает молча. Непрочитанный участок имеет source owner и конкретный вопрос, не автоматически блокирует все остальные clauses.

Классы: документ; deterministic integrity; допустимый урок; действительное обновление; learned utility; PC efficiency; host/native/remote delivery. Сохрани rights/provenance/no-repeat/state recovery/laws/native obligations. Test count, coverage, loss, hash и Windows green не достаточны для learned utility. Подозрение test-fitting фиксируй как supported/refuted/inconclusive по цепочке исходное требование→код→изменение ожидания, не как установленное обвинение.

**Выход:** заполненная таблица target paragraphs в CHANGE-MAP; источник и old text для каждой замены. **Приёмка:** ни удаления без owner/trigger, ни ALL_READ по listing. **Good:** убрать Windows-first у non-native опыта, сохранить native release owner. **Bad:** удалить S05 вместе с S04 gate. **Edge:** старый архивный gate, новая R16 редакция того же paragraph, недоступная RAG-цель. **Не задача:** новый полный inventory вместо R01/R03.

### B — DPO: от содержательной пары до правильного изменяемого состояния

**Роль:** архитектурный/code reviewer. **Skills:** trainable-architecture-decision, code-examination, prompt-patch-authoring. **Контекст:** current WorkLeft-02; original DPO algorithm; current S04 RUN §§2.1–2.3; R05 CP2 и поздние corrections; R12/R13 доступные contracts. Actual paths/methods брать из code evidence, не придумывать.

Напиши acceptance clauses для всей цепочки: разрешённая weakness/lesson selection → Chinese author ОБЕИХ final sides → отдельный CODEX/Astra exact-pair assessment → фактическая serialization/tokenization → conditional objective/reference → разрешённые параметры Student → isolated candidate → ordinary consumer → независимое качество. Student weakness answer не автоматически final rejected; reference policy не judge.

Проверка пары различает `preferred_side` и `pair_usable`. Оба законных хороших ответа могут быть TIE; оба плохих — BOTH_BAD; неразрешимое сравнение — UNJUDGEABLE. Rejected хуже по domain meaning при том же допустимом условии, не потому, что его написал deterministic solver. При material изменении bytes/context снова оценить пару. Не переносить авторство и старую assessment на новые bytes.

Для стандартного DPO требуется действительная conditional log-probability обеих response sequences под policy и frozen reference; prompt conditioning сохраняется, objective contribution от response/mask/EOS/reduction явно определены. Проверить сохранение различающего фрагмента после фактического транспортного пути. Silent truncation и arbitrary cosine-as-DPO недопустимы. Для selector/ranker без такой probability model назвать настоящий preference/ranking objective, owner и gradient/state path, не переименовывать его в стандартный DPO.

**Выход:** pair/admission/objective/recipient/consumer clauses и trace gaps с owner. **Приёмка:** changed checkpoint или optimizer entry не объявлены полезным обучением; identical weights/zero cold-start margin не превращены в выдуманную мутацию. **Good:** различие null/0 сохраняется до response objective и оценивается на других семействах методов. **Bad:** обе стороны обрезаны до общего префикса, но pair JSON принят. **Edge:** valid pair не помещается; TIE; stale reference; update outcome UNKNOWN. **Не задача:** генерация реальных training pairs или второй trainer.

### C — домены, представления, dynamic kNN и LoRA

**Роль:** domain/representation reviewer. **Skills:** trainable-architecture-decision, code-examination, human-readable-architecture-audit. **Контекст:** R04/R06/R08, DOMAINS passports, WorkLeft MECH/RESEARCH-03 и соответствующие actual encoder/index/projection/consumer traces.

Потреби существующие семь паспортов, не создавай их заново. Для каждого выдели действительные законы, domain/intent/schema, существенные token distinctions, target vector semantics, unknown/mixed handling и независимые source families. Domain mapping измерять отдельно от solver: oracle domain vs predicted domain, ошибки маршрутизации/abstention и end-to-end utility. Shape/version equality не семантическая совместимость.

Dynamic kNN разобрать как `eligible candidates → features/score → k/radius → index/retrieval → neighbor use → arbiter`. Для функции назвать то, что фиксировано законом, query-dependent и действительно обновляется от feedback; назвать владельца state и реальный consumer нескольких соседей. Сравнить fixed policy и обученную policy при сопоставимых candidate pool/representation/budget. Для query-dependent/asymmetric score проверить применимость index; approximate recall сравнивать с допустимым exact reference. Увеличение k при возврате одного bestExample.Output не доказывает aggregation learning.

LoRA рассматривать как способ изменения конкретного weight map, не tokenizer. Для заявленного source→target vector преобразования нужны значение координат, actual projection/adapter owner, target signal, совместимость token/codebook/index и downstream semantic result. Изменённый adapter не доказывает правильную векторизацию. Записать нужный reindex/rollback, а не скрывать его цену.

**Выход:** заполненные строки §5 для mapping/representation/kNN/LoRA и доменные illustration clauses. **Приёмка:** нет одного универсального k/metric/token vocabulary, объявленного лучшим без сравнения; неизвестные bindings явно названы. **Good:** SQL NULL/дубликаты/порядок различаются, retrieval и downstream ответ оцениваются отдельно. **Bad:** cosine вырос — SQL стал правильнее. **Edge:** mixed domain, unseen schema, same shape/different meanings, no eligible neighbors, contradictory memory. **Не задача:** полный новый encoder перед первым уроком.

Если C не помещается, раздели C1 (laws/mapping/representation) и C2 (kNN/LoRA consumers). C1 возвращает versioned schema/meaning receipt; C2 читает primary самостоятельно и не ждёт C1 DONE для независимой части. Каждый child получает полный prefix §7 и соответствующий полный текст C, свой named subset, выход и примеры; без нового общего inventory.

### D — четыре роли и полезность их соединения

**Роль:** архитектор + causal reviewer. **Skills:** trainable-architecture-decision, code-examination, plan-review. **Контекст:** original task; R07 A–I/R12 A–F, ALGORITHMS four-role contracts, R13 compiler, R14 full-delivery DAG; actual call/association/credit paths.

Сохранить поведение, не создавать API из опечаток: **ILearningUnit** принимает domain/input-vector/output schemas и даёт typed many→many associations; **ILearningFlow** учит отношения/коррекции между Units; **ILearningOrchestrator** асинхронно выбирает допустимые комбинации input→output; **ILearningDynamicGraph** учит отношения паттернов разных порядков и перенос композиций. Actual ILogical*/ILearningMachine сопоставить по коду; Train у существующего ILearningMachine, не четыре новых trainer.

Для каждой роли написать law/admissibility, learned state/recipient, signal/objective, changed edge/association, actual consumer и опровергающий опыт. Победа Unit не закрывает остальные роли. При исследовании Flow фиксировать Units; при Orchestrator — solver/candidates/budget; при Graph — lower-role mechanisms и различать unseen combination от нового названия старого пути. Считать цену всех branches/cancellation/retries, не только победителя. Best among observed feasible candidates не global optimum.

Однофакторные ablations нужны для локализации, **но недостаточны для claim о полезности соединения**. Для выбранной причинной пары механизмов R13/R22 составляют ограниченный 2×2 контраст compatible frozen component states: old/old, new/old, old/new, new/new, на одной panel. Если crossing несовместим по representations/state, не выдумывать его: определить допустимый matched contrast и указать, что interaction пока не идентифицирован. Эти контроли не разрешают повторно обучить ту же pair в четырёх ветках.

Сравнивать fixed-rule baseline D, learned choice L и hybrid H при одинаковых hard safety/domain constraints; L не означает отключить безопасность. H-frozen/no-update отличает benefit памяти/контекста от обновления. Совместный выигрыш и взаимодействие — разные claims; супер-аддитивность не обязательное свойство хорошего hybrid. Выбор основывать на domain utility/retention/whole cost, не требовать победы каждой сложной архитектуры.

**Выход:** четыре role clauses + один конкретный interaction packet для выбранного стыка, остальные назначены R22 по trigger. **Приёмка:** deterministic и learned части, получатель credit и ordinary use названы. **Good:** два допустимых пути одинакового качества, hybrid использует меньше операций/памяти при фиксированном бюджете сравнения. **Bad:** Graph обучен, потому что Unit loss снизился. **Edge:** lawful alternative path, async race, contradictory graph pattern, cancellation, incompatible crossed states. **Не задача:** все комбинации всех алгоритмов до E1.

### E — bulk protocol, остановка и PC/feedback

**Роль:** reviewer экспериментального протокола. **Skills:** phase-planning, plan-review, human-readable-architecture-audit. **Контекст:** R13 actual recipe, R08 families, R09 cost limits, R23 lifecycle, current one-pair/no-repeat rules.

Для каждого выбранного опыта до эффекта зафиксировать metric/unit, practically meaningful effect, retention tolerances по обязательным strata, uncertainty method на уровне независимых families, число новых уроков/наблюдений, allowed calls/attempts и конечный time/compute/memory budget. Существующее owner decision использовать; без него дать явное DESIGN_PROPOSAL и требуемый binding, не подставлять 95%, 0 или увиденный результат. Document clause можно применить, но конкретный незаполненный опыт остаётся DESIGN_BINDING_REQUIRED.

Bulk — окно последовательных НОВЫХ уроков, не разрешение replay или batch promotion. В каждом bulk сравнивать parent/challenger на одной versioned panel; для longitudinal learning curve сохранять отдельный стабильный anchor или явно учитывать смену сложности/cohort. Улучшение на более лёгком следующем bulk не gain. Operational development panel не untouched final exam; final exam не teacher context и не инструмент многократного tuning. Family/template/source leakage, evaluator disagreement и многократный выбор лучшего checkpoint учитываются в выводе, не скрываются.

Измерять per-domain/worst-domain utility, domain/path correctness, retention/transfer, wall time/time-to-quality и whole PC footprint: base/reference/adapter/optimizer/activations/encoder/index/graph/cache/snapshots/reindex, persistent growth, teacher/judge/evaluator, failed branches. Отдельно local runtime и external teaching cost. PC configuration измерить перед runtime; старое описание железа не считать доступностью сегодня. Меньший adapter не означает меньшую полную систему.

User feedback сначала права/смысл/новизна/противоречия/допуск, затем новый урок. Snapshot rollback возвращает применимое model/optimizer/RNG/representation/index/graph состояние, **но не стирает durable факт уже использованной пары и её disposition**. UNKNOWN mutation → quarantine/reconcile до любого нового update; rejected/rolled-back pair не становится новой после переименования run_id.

**Выход:** protocol binding table и stop/promotion/recovery clauses. **Приёмка:** IMPROVE/REGRESS/INCONCLUSIVE/INVALID_EVIDENCE/NOT_MEASURED раздельны; отрицательный опыт завершён, но requirement gain не закрыт; нет repeat-until-improve. **Good:** быстрее при заранее допустимой non-inferiority качества и полном учёте цены. **Bad:** trial weights выбраны на final exam, а он назван независимым. **Edge:** underpowered families, identical weights, counter reset, budget exhausted, mixed-domain regression. **Не задача:** runtime execution или придуманные numeric results.

R18 получает разрешённые clauses конкретного first-learning seam; R19/R20 — effective packet changes; R21 — domain expectations; R22 — interaction/causal requirements; R23 — full cost/feedback/no-repeat; R25 — exact candidate и отдельное reviewer assignment. Полученные receipts не выдумывать: SENT/ACKNOWLEDGED/APPLIED различаются.

**Приёмка:** live instructions не требуют all R01–R16 DONE или всего curriculum перед независимым clause; first lesson не объявлен готовым без собственных binding/permission; все прежние safety/delivery obligations сохранены с owner/trigger; чужие статусы/результаты не изменены. **Good:** конкретная замена принята R18 с exact clause ID. **Bad:** новый appendix нигде не загружается; автор подписал self-check как Astra PASS. **Edge:** concurrent edit/409, stale blob, новый R13 receipt после commit. **Не задача:** массовая переорганизация документов.

## 5. Обязательная матрица functional expectations

Каждая строка становится criterion ID R17-AC01…AC12, с источником/owner/trigger и actual evidence status. Это требования к предметному изучению, не новые unit-test suites. На отдельном bulk включаются только причинно затронутые строки и необходимые integrity/retention controls; полный набор распределён по программе.

| ID | Что нужно доказать | Различающее наблюдение и недопустимый вывод |
|---|---|---|
| AC01 | Правильный domain/intent/schema | Oracle vs predicted mapping, unknown/mixed/abstention и downstream effect; solver accuracy не заменяет mapping. |
| AC02 | Семантика tokens/vectors | Law-sensitive contrasts переживают transformation; различать lexical tokens, semantic schema, embeddings, codebook/index. Short vector не proof semantic compactness. |
| AC03 | Полезный dynamic kNN | Eligibility/metric/k/radius/consumer/state; fixed vs learned, exact vs approximate where applicable; neighborhood IDs без use не improvement. |
| AC04 | Содержательная и допустимая DPO | Same lawful prompt/context, real authorship, meaningful preference, usable отдельно от preferred, exact payload до objective. |
| AC05 | Настоящий objective/recipient | Actual conditional probability или честно названный иной preference objective; разрешённые parameter groups и state lineage; gradient/hash не utility. |
| AC06 | LoRA/semantic projection | Actual changed map, source/target meaning, compatible consumer, downstream utility/retention; LoRA не tokenizer по названию. |
| AC07 | Unit many→many | Корректные associations, input/output types и domain meaning на новых families; число outputs не quality. |
| AC08 | Flow corrections | Fixed Units, changed relation/correction state, association preservation и downstream difference. |
| AC09 | Orchestrator path | Lawful async candidate selection при фиксированных alternatives/budget; quality/time/branch cost, не обещание global optimum. |
| AC10 | DynamicGraph transfer | Higher-order unseen compositions familiar primitives, отдельный graph state/consumer и lower-role controls. |
| AC11 | Hybrid compactness/efficiency | D/L/H/H-frozen и ограниченный interaction contrast where causal; качество–стоимость/Pareto, whole footprint, не adapter bytes. |
| AC12 | Continual user learning | Новые допущенные уроки, full recovery/no-repeat, честные bulk curves, retention/transfer/growth и ordinary accepted-state use. |

**Семь baseline subjects — illustrative examination, НЕ готовые training pairs:** EN↔RU: отрицание/числа/единицы и смысл, не exact string; orchestration: lawful dependency/order/cancellation и цена путей; Figma→HTML/CSS: hierarchy/layout semantics и новый viewport, не pixel identity; C# docs: null/0, cancellation, exceptions и реальное поведение; Angular docs: observable lifetime/unsubscribe и event semantics; SQL docs: NULL/duplicates/ordering/transaction semantics; Builder: допустимость произведённого lesson/curriculum и полезность для другого Student, не только valid JSON. Исходные HE↔EN/прочие languages/intents/extras сохраняются через source map с owner/trigger. Локальные domain laws не универсализировать на неизвестную schema/версию.

## 6. Статусы и первый урок

Разделять `STARTED`, `DRAFT_PATCH`, `APPLIED_DOCUMENT_CHANGE` и `MEASURED_PRODUCT_RESULT`. Внутри runtime отдельно: `EXPERIMENT_ADMISSIBLE(scope)` → факты `PAIR_ADMITTED`/`OPTIMIZER_ENTERED`/`UPDATE_OBSERVED` → `UTILITY_VERDICT` → `PROMOTION_DECISION` → `DELIVERY_ADMISSIBLE(scope)`. Ни одна стрелка не означает автоматическое повышение следующего статуса.

Документный ремонт применим без claim LEARNING_READY. Первый existing CodeDocumentation урок не ждёт нового универсального encoder, полного Graph, всех доменов/ablations или unrelated Windows. Он всё равно требует собственных valid data/owner/objective/state/ordinary consumer/criteria/permission и applicable separate review. Global R12/R13/R15 status не substitute для списка конкретных зависимостей; R17 не отменяет unresolved prerequisite и не подписывает review за другого.

Нулевой/отрицательный/неясный valid experiment может завершить процедуру, не доказав прирост. NO_TRAINING_NEEDED сохраняет достаточный parent без teacher/update. Final release и remote S05 имеют свои реальные rights/host/status requirements. После rollback запрещено повторять уже применённый урок.

## 7. Полный контракт bounded child и результаты R17

По умолчанию выполнять A–F последовательно как checkpoints R17. Делегирование — только при действительной пользе. Перед child call parent составляет **один полный prompt**: CURRENT TASK из назначенного A/B/C1/C2/D/E/F; NOT THE TASK; роль и относящиеся skill excerpts; exact current sources/target clause/ref/blob и relevant origin receipt; protected expectation; подробные действия; названные outputs; good/bad/edge; allowed/forbidden actions; documentary acceptance и future experiment отдельно; finite reading/response budget; return schema. Содержимое выбранной части и общие §1–2/6 ограничения встраиваются, а не передаются только ссылками. Незаполненные поля или «изучи весь репозиторий и исправь» не допускаются. Missing runtime identity передаётся как named unresolved fact, не выдуманный ID.

**Child authority:** read assigned source/code; return proposal only. No shared/sibling writes, no product effects, no nested autonomous queue. Если source не найден после exact route/alias check, вернуть exact gap/impact и продолжить независимую часть. Бюджет исчерпан — checkpoint с прочитанным остатком, не потеря scope и не автоматический новый раунд.

**Child return:** source/ref/span → actual/proposed mechanism → affected original expectation → exact old/new clause → preserved law/state/rights → causal example/control/falsifier → remaining binding → consumer → evidence limits + skill_load_status + actual call identity (или честное отсутствие отдельного вызова). Parent проверяет semantic receipt, затем сериализует запись.

**R17 carriers сохраняют существующие schemas/IDs:** SOURCES.csv — refs/read depth/limits; FINDINGS.md — реальные дефекты и сохранённые сильные решения; DECISIONS.md — принятые clauses и scoped status; CHANGE-MAP.csv — exact before/after/owner/trigger/receipt; RUN-LOG.md — фактический checkpoint, commit/readback и остаток. Не создавать пять новых файлов для каждой части. При ремонте только поручения допустим отдельный audit memo, но он не заменяет live edits и не переписывает чужие выполненные результаты.

**Финальный отчёт Лубе:** какие действующие документы исправлены и где опубликованы; как теперь экзаменуются домены, DPO, hybrid connections и PC learning; какой exact next seam остаётся до первого урока; что не выполнялось. Независимая экспертиза требует отдельного фактического запуска на exact candidate с actual reviewer/model identity. Запрошенный Astra Ultra — назначение, не доказательство, что он был вызван.
