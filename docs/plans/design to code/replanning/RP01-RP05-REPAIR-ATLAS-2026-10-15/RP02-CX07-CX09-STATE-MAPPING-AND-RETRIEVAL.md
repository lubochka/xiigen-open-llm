## 6. CX09 · Geometric recall and law-scored candidate recall are different

### Evidence and constructive counterexample

The fully read HnswIndex search helpers use cosine similarity. Previous 02C blob `5988c0628035fa9352b10cf2eb9c534a0f60bbb7` correctly required same metric/pool and rare-law recall, but left the two possible reference sets implicit. A downstream candidate-conditioned law score can order the same vectors differently.

PUBLIC illustration, not observed data: lawful A has cosine 0.95/domain score 0.20; lawful B has cosine 0.70/domain score 0.90. Exact cosine top-1=A and ANN top-1=A yield geometric Recall@1=1, yet B never reaches the law scorer. Increasing ef cannot be assumed to cure this metric mismatch. The domain score is inference-computable, not copied from a hidden answer. Prohibited candidates stay outside the pool.

### Explicit protocol already integrated into 02C/C05

Define on the same authorized finite corpus/query:

1. `G_m`: exact top-m under the actual index metric, same vector version/eligibility/type/role contract and declared tie policy.
2. `L_r`: top-r under the same frozen inference-computable domain-law scorer across that finite lawful corpus. This is a SCORER reference, not independent semantic truth. Final C#/EN→RU/SQL examination still judges meaning. Warning/negative roles have separately declared allowed influence; they cannot become accepted final solutions by being highly ranked.
3. `C`: actual candidate IDs reaching the scorer after retrieval/expansion/filtering, before final consumed-k reduction. Record requested m, actual |C|, consumed k and search effort separately.

Report geometric recall `|C ∩ G_m| / |G_m|` and law-scorer candidate recall `|C ∩ L_r| / |L_r|` only with nonempty identified references. Compare matched budgets and disclose actual cardinalities; retrieving more is not free. Empty references → NOT_APPLICABLE. Unavailable whole-pool reference → NOT_IDENTIFIED outside explicitly bounded support. Define tie tolerance/equivalence beforehand, not after observing winners.

Optional scorer regret `max_pool s_theta(q,z) − max_C s_theta(q,z)` applies only to nonempty lawful sets and one fixed score. It is not solution accuracy, calibrated correctness or global path optimality. A bounded candidate set only supports a bounded conclusion.

Locate the FIRST lost useful option: missing corpus evidence; domain exclusion; proposal/index-metric mismatch; ANN approximation; reranker; typed reduction; final solver/arbiter. Do not train a reranker to recover a candidate never offered. Route the measured bottleneck to the actual existing 01A/01B/01D/02B2/02C owner rather than always changing ef or rebuilding ANN.

GOOD: a SQL ON/WHERE candidate is missed by both exact cosine and ANN but ranks highly under law features; diagnose representation/proposal budget before ANN tuning. The equivalent C# case concerns null/operator behavior, and EN→RU concerns negation/referent relations rather than lexical overlap. BAD: perfect cosine recall is called perfect domain reasoning. BAD: an expensive offline exhaustive scan silently supplies online features or its serving cost is hidden.

EDGE: zero candidates, ties, all candidates semantically wrong, role-negative memory, stale coordinate version, non-index-compatible contextual score or resource-limited reference. Keep support and validity explicit; never force ANN superiority. Diagnostic whole-pool work is recorded separately as examination overhead; a product fallback/scan belongs in end-to-end PC cost. Tune on TRAIN/OP_DEV, never SEALED.

Recovery: NO_CHANGE when adequate; otherwise one measured proposal/fallback/effort fix or exact owner handoff. Existing C05/E uses zero new tests; only an actually changed index/access invariant keeps its nearest narrow check. No new C09 experiment, benchmark platform, mandatory ANN replacement or first-lesson blocker.
