## 47. Separate adaptive teaching selection from evaluation sampling

**C · P1-CLAIM · proposed detail.** Repair 43 makes denominators visible; it does not by itself make two adaptively selected bulks comparable.

**What/why:** CODEX may deliberately select the weakest cases for teaching. That changes the case mixture. Improving or worsening average scores on successive selected bulks can reflect mixture or feedback availability rather than a changed learner. Silence from a user is not a positive label.

**Assignment text:** For ONE domain/mechanism, state the target workload and whether the question is first-lesson gain, retention, worst-domain performance or deployment performance. Record the teaching selection reason/policy separately from the evaluation sampling rule. Compare C0/T on the same enrolled panel with declared domain/family weights; show per-stratum outcomes as well as the declared total. Record offered, selected, labeled, unlabeled and unavailable-family counts. If evaluation consists only of selected weak cases, limit the conclusion to those cases. Do not invent sampling probabilities or a population correction when they were not recorded.

**GOOD:** CODEX chooses hard C# lessons while an independently chosen matched C#/RU panel measures both checkpoints. **BAD:** only users who corrected an answer are evaluated, and the result is called overall user accuracy. **EDGE:** a domain has no labels; report missing evidence and workload coverage, not perfect correctness or a fabricated zero solver score.

**Public arithmetic:** unchanged easy/hard accuracies 90%/50% produce 82% with an 80/20 case mixture and 58% with 20/80. No learning change is needed for that difference.

**Return/falsifier/recovery:** selection/evaluation policy, target and sampling unit, raw stratum counts, matched comparison and explicitly limited claim. A score change that disappears under the same declared workload falsifies the claimed bulk learning effect. Reanalyze compatible observations; obtain a bounded new panel only when necessary. No old-pair retraining. **Sources/skills:** U, A/C, B/28/43, W; ARCH, REVIEW, HUMAN.

## Application order and stopping boundary

Do not schedule 47–58 in numerical sequence. For a saved-but-unjudged pair, 57 identifies the next actor effect; for an actual DPO loss question, select 50; for a bulk claim, select the relevant 47/48/49/54 distinction. A single first-domain pilot need not wait for every later domain, LoRA transfer, graph lifecycle, UI, all-factor ablation or PC certification. Those obligations retain their real owners and triggers.

For source/design/no-change work: **zero new product tests**. For a later real deterministic safety/integrity change: reuse the smallest relevant check and add one only when a demonstrated changed risk is otherwise uncovered. Learned behavior uses a source-grounded domain examination, matched relevant factors, measured time/resources, retention and an independent authorized reviewer—not a required percentage of test coverage.

Document publication, exact readback, author review, product implementation, state change, domain gain, ordinary adoption and independent CODEX/Astra review remain separate statuses. The [publication receipt](12-LEARNING-FIRST-EXTENSION-RECEIPT.md) records the actual edited paths and readback. This document alone is not proof that its suggested repairs have been implemented in all slice cards or product code.
