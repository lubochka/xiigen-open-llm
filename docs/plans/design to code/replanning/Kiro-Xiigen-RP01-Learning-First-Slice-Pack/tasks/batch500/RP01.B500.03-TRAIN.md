## Что именно исследовать в DPO и LoRA

[Первичная работа DPO](https://arxiv.org/abs/2305.18290) задаёт предпочтение двух ответов на общий input относительно reference. Для стандартной последовательностной постановки:

```text
delta = (log pi_theta(chosen|x) - log pi_theta(rejected|x))
      - (log pi_ref(chosen|x) - log pi_ref(rejected|x))
loss = -log sigmoid(beta * delta)
```

В source trace показать actual objective и aggregation. Sequence log-probability — сумма response-token log-probabilities; средняя на токен и сумма не взаимозаменяемы. **Frozen margin scorer текущего опыта использует token average**: не называть его доказательством тождественности training objective. Не менять уже запущенный алгоритм задним числом. Обнаруженное существенное расхождение — явная ограниченная гипотеза следующего опыта, либо INVALID binding, а не автоматический rewrite всего trainer.

Student receives exact x/y+/y−, response-only shifted targets; prompt/padding не должны обучаться как ответы, различающий токен не теряется. Reference frozen и отдельно от mutable policy. Допустим cache reference likelihood по exact input/mask/tokenizer/reference/numerical version; policy likelihood после update не брать из stale cache. Standard DPO не требует autoregressive generation на каждую обучающую пару; не подмешивать сотни generation/evaluator calls в optimizer loop.

[LoRA](https://arxiv.org/abs/2106.09685) здесь — named trainable matrices при frozen base, не tokenizer и не semantic projection. При изменённом механизме проверить actual allowed parameter delta, finite values и неизменность base/reference ближайшим имеющимся наблюдением. Не запускать новый общий suite для повторного доказательства неизменённого published runner.

## GOOD / BAD / отказ → действие

GOOD:500 distinct pairs прошли50 committed minibatch updates с непрерывным состоянием, и фактический результат описан независимо от gain. BAD:500 раз вызвать one-pair lifecycle с новым B0; такой счётчик не показывает500-парное накопительное обучение. GOOD: state changed, preference shifted, free answer unchanged — честно три разных вывода. BAD: новый LoRA hash объявлен освоением C#.

NaN/Inf → сохранить owner journal, прекратить конфликтующий эффект и назвать последний подтверждённый snapshot; не продолжать вслепую. OOM → не менять main batch посреди замороженного опыта без признания новой версии; адресное восстановление у owner. Timeout/unknown → не считать failed-before-effect. Save/readback mismatch → кандидат не принимается как рабочий, parent/артефакты сохраняются. Loss drops but behavior does not →04PREFERENCE_ONLY/NO_GAIN, затем одна hypothesis о данных/representation/base/objective, не бессмысленные повторы exam. Missing timings → UNKNOWN, не приписывать часы Qwen или optimizer.

Allowed: existing trusted offline owner по реальному поручению; isolated state; конкретная будущая training/persistence правка и nearest affected invariant. Forbidden: Windows matrix, .issued cleanup, duplicate writer, новый trainer, canonical serving mutation, closed gold in TRAIN. Вернуть общий packet; actual state effect отдельно от measured learning и publication. Никакой «выполнено» по одному этому документу.
