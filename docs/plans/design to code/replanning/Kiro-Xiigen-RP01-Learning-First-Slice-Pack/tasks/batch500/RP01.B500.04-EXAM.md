## Точный текущий критерий и границы вывода

Primary текущего frozen protocol:

```text
m_i = mean response-token logp(chosen|x) - mean response-token logp(rejected|x)
delta = average_25(m_i Trial) - average_25(m_i C0)
positive: delta > 1e-6; negative: delta < -1e-6; tie: |delta| <= 1e-6
```

Сохранить неокруглённые значения, per-case deltas и response target counts. Это **narrow near-transfer preference signal**, не доказательство свободного объяснения и не вероятность успеха на всём домене. Исходный tolerance не объявлять статистически обоснованным confidence threshold. Missing/nonfinite/mismatched case не удалять молча из25: complete primary result не получен.

Для free3 исходный positive signal: хотя бы один C0-incorrect→Trial-correct и положительное net изменение correct count. Все потери, critical/law errors и неполные ответы показываются отдельно. Более мелкие качественные улучшения — descriptive, а не изменение этой уже frozen рубрики.3 — подмножество25, не28 independent families. Broad retention/domain transfer этим опытом не измерены.

Outcome записать раздельно: state update; preference positive/negative/tie; free behavior improved/unchanged/regressed; validity; adoption. PREFERENCE_ONLY_SIGNAL полезен как ранняя диагностика, но не превращается в FUNCTIONAL_GAIN. Нулевой/отрицательный опыт не требует бесконечных пересдач и не закрывает возможность следующего500-парного исследования. Production selection отдельно.

## Следующий опыт: разрешён маленький смысловой прогресс

До новой кампании допустимо выбрать Q_law: доля заранее обязательных правильных semantic clauses внутри case, далее среднее по case и независимым families. Critical contradiction даёт заранее установленный penalty/flag; отсутствие некритической детали не переименовывать в критическое после результата. Небольшой положительный paired shift с конкретным исправлением можно назвать **OBSERVED_SMALL_GAIN**, без обещания significance. +1 fully-correct — пример, не универсальный минимальный прирост. Не требовать+2/12 или95% перед продолжением исследования.

Показывать correct counts/n01/n10 и regressions, неопределённость/малоеN. Варианты bootstrap/exact paired analysis применяются по реальным independent units;25 шаблонов или500 instances не объявлять автоматически независимыми. При недостаточных данных uncertainty UNRELIABLE/NOT_ESTIMATED. Выбор лучшего checkpoint по многократно открываемому final panel запрещён; после раскрытия он diagnostic/retention, для нового confirmatory вывода нужны неиспользованные families. ## Примеры и разбор отказов

GOOD future partial rubric: null fallback объяснён, empty string пропущена; при двух заранее выбранных равных clauses —0.5. BAD: после результата добавить лёгкие clauses для gain. GOOD: верное отрицание/действующее лицо важнее красивого перевода. BAD: fluent ответ теряет not. GOOD: несколько корректных переводов допускаются frozen rubric. BAD: exact string gold отвергает синоним без смысловой ошибки.

Изменились code/representation/memory между плечами → перечислить конфаундер; повтор нового сравнения только как новый binding, не скрытый reuse. Identical outputs → reuse адресной оценки,03R diagnostic по необходимости; не пять повторов. В outputs обнаружен TRAIN/gold leakage → INVALID_EVIDENCE в затронутой области, отделить незатронутые observed facts. Failed evaluation → сохранить actual issued/completed counts, не назначать score отсутствующему ответу. Новая ошибка после обучения → показать её, не усреднять из отчёта.
