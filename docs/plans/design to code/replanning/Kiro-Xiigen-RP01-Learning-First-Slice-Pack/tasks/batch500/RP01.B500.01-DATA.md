## 01A — полный промпт отдельному автору обеих сторон

> Ты симулируешь РОЛЬ внешнего открытого китайского DPO-автора в development, а не факт вызова Qwen. На каждый exact prompt/context создай chosen и rejected. Chosen должен решать эту задачу; rejected — правдоподобно нарушать один объяснимый предметный аспект. Нельзя использовать мусорный ответ, потерять отрицание при нормализации или сделать длину/стиль надёжной подсказкой label. Причину ошибки вынеси в sidecar, не в обучаемый ответ с маркером WRONG. Для прямого Astra generation — честный ASTRA_SYNTHETIC_DEV; для программной материализации — действительное описание материала и генератора, не ложное model authorship. Не выдумывай parser enum или разрешение. Если обе стороны допустимы, верни AMBIGUOUS. Не обращайся к Student и закрытому экзамену.

Не требуется500 строк в одном model context. Разбитый ответ не импортируется частично. Исправленная существенная строка получает новую версию; прежние bytes сохраняются. Данные симуляции не объявляются статистически эквивалентными Chinese output distribution.

## Примеры и объяснение ошибок

**Хороший C# contrast.** `static int Size(string? s) => s?.Length ?? 7;` Вопрос: объяснить null и пустую строку. Chosen: «Для null вернётся7; для пустой строки0». Rejected: «В обоих случаях0, потому что null — строка нулевой длины». Ошибка — потеря null semantics, не стиль. Плохой rejected «банан999» слишком лёгок. Два корректных перефразирования не создают обязательного preference.

**Хороший ENRU contrast.** `The engineer did not approve the change.` Chosen сохраняет «не одобрил»; rejected теряет отрицание. `Эта новая книга оказалась полезной` vs `оказался полезным` демонстрирует согласование связанного объекта. **Плохой закон:** запрещать любое masculine после feminine. В «Книга лежала на столе. Он был деревянным» местоимение может относиться к столу. «Анна подошла к Марии. Она улыбнулась» без контекста допускает неоднозначность; её нельзя искусственно оценивать как единственный referent.

Это публичные иллюстрации, не будущие скрытые exam cases. Новизна требует новых структур/контекстов, не только переменных в этих примерах.
