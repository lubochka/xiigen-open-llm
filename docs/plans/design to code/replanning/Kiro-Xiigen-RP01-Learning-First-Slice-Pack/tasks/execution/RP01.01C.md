## Промпт

Найдите и минимально исправьте причину, по которой ordinary consumer не может использовать **уже принятый** Student checkpoint. Code trace, научная acceptance, canonical publication и actual cold adoption — разные evidence. Если модель ещё не принята/не опубликована, не выдавайте это за loader defect и не переключайте normal service на private Trial.

## Действия

1. Прочитать ordinary endpoint→server config/DI→canonical model selection→actual generator. Записать method и state identity на каждом ребре. Ошибка auth/неразрешённый Trial/отсутствие publication — не автоматически ошибка loader.
2. Установить точный invariant: accepted manifest selects matching weights+tokenizer+adapter; no caller filesystem checkpoint path; parent/trial/domain/config не alias в cache; missing/corrupt/incompatible accepted state не создаёт fresh random model молча.
3. Проверить существующий generation façade/service и переиспользовать его. Новый helper/adapter допустим **только** если actual gap доказан и он меньше прямого исправления existing owner; нельзя вводить 14→26 cycle или параллельный generator. Обосновать путь до/после, не заявлять класс по памяти как existing API.
4. Исправить один smallest reached seam. Не менять training objective, kNN/representation, научную rubric, canonical publisher или данные. Если API/DTO действительно меняется, поправить ближайшего producer+consumer version binding вместе; иначе DTO не расширять ради отчётности.
5. Предусмотреть честный result: output text отдельно от route metadata; actual served checkpoint identity; cancellation/stop/EOS policy из config; корректные error/fallback indicators. Не заполнять timing/token counts догадками.
6. Передать T3.C конкретный verification entry после **реальной T2/T3.P acceptance/publication**. Source-only review может завершиться CODE_PATH_VERIFIED, но actual adoption без normal new-process invocation остаётся NOT_VERIFIED.

## GOOD / BAD / EDGE

GOOD: discovered cache key не различает model SHA; минимальная правка ключа сохраняет существующий generator и проверяется на двух разных accepted identities. Почему: устранён причинный разрыв без нового serving framework.

BAD: «на всякий случай сделать shared façade» без defect; или заменить ordinary call прямым evaluator/trial handle. Почему: лишняя разработка/другая trust boundary. Remedy: reuse existing owner и один конкретный missing edge.

BAD: Step1 NoUpdate output назван trained adoption. Почему: это допустимый control, но не доказательство урока. Remedy: отдельно accepted Trial identity и actual publication receipt.

EDGE: positive science без publication→T3.P, не loader patch; stale parent после publication→resolver/cache edge; несовместимый tokenizer→typed refusal; genuine cold-start permission→только existing B0, не silent reset; cancellation mid-generation→не training replay; native/rights error→точный owner, не security bypass; одинаковый текст parent/Trial не опровергает adoption, если actual loaded identity подтверждена.

## Проверка результата

Без изменений→0 новых tests. Изменённый loader/cache invariant→ближайшая focused valid-identity и relevant invalid/mismatch/fallback проверка; не mandatory suite для всего inference. Actual cold ordinary response проверяется отдельно T3.C, не fixture. Windows matrix/coverage не критерий learning; applicable real security/native/release protections остаются.

Return P/K SHA, exact reached defect/NO_CHANGE, producer→loader→generator consumer map, allowed diff, preserved boundaries, risk-specific evidence or 0, actual publication/adoption statuses раздельно, failure/recovery, next=T3.C/T3.P/precise owner. STOP без model promotion или Student update.
