# RP01.03B — новые feedback-уроки и сравнение от пакета к пакету

**Не prerequisite первого E1.** Начать с одного нового разрешённого feedback и одного bounded next-lesson handoff. Полный continual механизм/многодоменный campaign — у RP05/RP09 владельцев, не скрытая реализация всех слайсов внутри RP01. [Dispatcher](../../RP01-EXECUTE-NOW.md).

## Промпт

Используйте результат первого опыта, даже если он отрицательный, чтобы подготовить **следующий новый** урок и заранее определить, как измерить его пользу/стоимость/retention. Не переиспользуйте old pair как новый урок и не считайте user correction автоматически истиной. Не запускать модели/optimizer в режиме READ_ONLY_HANDOFF; EXECUTE_NEXT_BULK допустим только по отдельному actual grant, уже поддерживаемому descendant lifecycle и конкретному RP05 work order.

**Критически важно:** текущий first-RP01 scientific route проверяет parentless Step1/root и one-step policy. Он **не является универсальной командой для второго/третьего bulk**. Не вызывать тот же first `train-and-hold` на descendants и не удалять root-only guard. Найти существующий разрешённый continuation owner; если его нет, передать конкретный минимальный versioned continuation gap RP05, без задержки первого E1 и без fake EXECUTED.

**Inputs:** actual initial/previous accepted checkpoints, T1/T2 outcome и failure classes, новый consented feedback, source/retention policy, pair/application lineage, domain/consumer capability map, prospective resource envelope. **Sources:** K/14.ContinuousLearning/Feedback/FeedbackRouter.cs, Training/DpoTrainingExecution.cs; K/26.TrainableRouter/Training/CodeDocumentationRepositoryOwnedDpoTrainingPublicationCoordinator.cs и scientific lifecycle CurrentScienceIntent; canonical journals; D/R23-PC-STATE-FEEDBACK-LIFECYCLE.md, WorkLeft-02 R16/R17; G/active-codex-execution-guide-05-auto-dpo-loop.md через relevant RAG primary. **Skills:** client-adaptive-learning-loop-SKILL.md, learning-loop-closure-SKILL.md, experiment-design-SKILL.md, improvement-measurement-SKILL.md, code-examination-SKILL.md из K/docs/skills — persistent state, evidence before update, chronological evaluation.

## Один bounded проход

1. Связать feedback с actual request/domain/context/version и consent; определить correction claim, supporting source и uncertainty. Contradictory/poisoned/private-unsupported feedback→quarantine, не silent training.
2. CODEX Astra 6 UltraCode выбирает отдельный admissible TRAIN case. Chinese model по настоящему grant создаёт **обе** final DPO стороны; отдельный CODEX Astra 6 UltraCode J оценивает exact pair. User answer или failed Student output не переименовывается в Chinese output.
3. Проверить novelty по source/semantic family и applied journal, не только UUID/raw hash. Старые weights/optimizer/RNG/scheduler/version должны продолжаться от настоящего принятого parent; rejected Trial не становится parent без acceptance. Unknown effect→recovery.
4. Подготовить запись prospective bulk: scope/time window, unique new pair IDs, source-family counts, actual continuation method, max attempts/steps/resources, immutable parent and experiment protocol. Числа не выдумывать: reuse owner budget либо пометить обязательный unresolved parameter до исполнения. В READ_ONLY никаких вызовов.
5. Описать сравнение accepted A_previous и candidate C_bulk **в одинаковом code/domain-policy/decoder/budget**, плюс untouched retention families. Если одновременно изменяется kNN/representation — отдельный factorial/ablation, не общий DPO claim. Новые C#/SQL/RU cases используют свои actual consumers; first raw C#12 CLI не принимает SQL только от смены domain label.
6. Передать **один** next-lesson/bulk packet и механизмный gap владельцу RP05/RP09. Тот исполняет свои отдельные state/data/exam карточки. No training needed/исчерпан budget — честная остановка следующего effect, не бесконечный Teacher loop.

## Что записывать по каждому реальному bulk

`bulk_id; chronological window; parent/candidate/accepted hashes; domain/consumer; attempted/valid/admitted/applied/published/retained counts; distinct source families; duplicate/quarantine/failure counts; Q_before/Q_after per domain and worst domain; critical-law errors; justified abstention and answered fraction; old-domain retention; all-stage wall/CPU/RAM/VRAM/disk and external cost; actual steps; acceptance/keep-parent and reason`.

Gain сравнивать не только с первым A0, но и с A_previous. Time per **действительно решённое допустимое задание** и cost per new admissible pair/полезный прирост требуют явных denominators; при нуле gain не писать красивое конечное cost-per-gain. Repeated tuning на одном final sealed exam запрещено: development feedback panel отдельно, untouched confirmation families отдельно. Все failed/reverted attempts включаются в затраты.

## GOOD / BAD / EDGE

GOOD: после C# урока новый feedback подтверждает другую ошибку, создаётся новая Chinese/J пара, descendant state продолжается supported route, old-family performance и затраты сравниваются. Почему: измеряется continual improvement, не повтор старого урока.

BAD: десять запусков одной пары названы десятью bulks; новый UUID обходит lineage; от user EDITED сразу обновлены веса. Почему: нарушены novelty/авторство/правда feedback. Remedy: quarantine/recovery и настоящий S/A/J.

EDGE: scientific first-root route не поддерживает child→RP05 конкретный continuation gap; новый domain consumer отсутствует→NOT_RUNNABLE; native failure→affected lane only; bias/poisoning→independent law check; memory растёт с index/journal→retention/compaction budget измерить, не скрыть; old-domain regression→KEEP_PARENT/следующая гипотеза, не уменьшить denominator; feedback с private data→purpose-specific consent, не публичный upload.

READ_ONLY/unchanged code→0 новых product tests. Actual new deterministic state/privacy invariant→только nearest focused check у implementer. Полезность→independent domain/bulk experiment, не coverage.

Return prospective packet или genuine executed-bulk evidence, строго различая mode; actual sources/skills/P/K SHA; continuation support; role/grant/lineage; dataset/metric/budget bindings; next owner/precise missing contract. Не утверждать Student/PC/multidomain gain без реальных результатов. STOP.
