## Архитектурная граница, которую нельзя потерять

User names ILearningUnit/ILearningFlow описывают требуемые роли. Прочитанный current `ILogicalUnit<TInput,TOutput>.ExecuteAsync` возвращает `Task<OperationResult<LogicalUnitResult<TOutput>>>`; это не объявленный IQueryable API. `LearningMachineContracts.cs` закрепляет Train на ILearningMachine, не на ILogicalUnit/Flow. Найдите реальный bridge для many→many/queryable result contract; если отсутствует, **назовите gap**, не утверждайте, что он реализован вызовом `AsQueryable()` над IDs. Requested IQueryable semantics, query lifetime и actual payload/resolver должны быть сохранены либо явно согласованно отображены на существующий контракт. Новое имя интерфейса само по себе не решение.

## Один bounded проход

1. Выберите Unit-результат **или** Flow-коррекцию как primary seam. Проследите domain/schema/input → actual unit invocation → typed payload/association IDs/OutputRef → downstream consumer. Запишите existing vs proposed отдельно.
2. Для many→many контракт должен явно содержать input identity, result identity, принадлежность результата одному/нескольким inputs, output type/schema/version, provenance и статус. Не требовать равного числа inputs/outputs. Определите zero results, partial, reordered, duplicate identities, errors и cancellation. Payload может быть коллекцией в существующем envelope, но это необходимо доказать consumer-ом, не предположить.
3. Для IQueryable/queryable bridge определить provider/execution boundary, supported operations, materialization/ownership/lifetime, request scope и cancellation. Нельзя повторным перечислением незаметно запускать новые model/effect calls или возвращать ссылки, уже потерявшие scope. Для будущего async bridge сохранить required typed semantics, а не тихо заменить контракт удобным типом.
4. Flow correction: назвать входной/целевой semantic schema, какие связи/параметры обучаются, signal/labels/preferences, state owner, update через existing learning owner, checkpoint/version и actual next-Unit input. Fixed mapping полезен как baseline, но не выдаётся за обученный. Learned parameters могут исполняться детерминированно; отсутствие случайности не опровергает обучение.
5. Правила типов, domain laws, source/effect permissions и associations остаются deterministic guards. Learned correction может выбрать/преобразовать только допустимый input; не менять координаты/единицы измерения без codec/schema binding. DPO для предпочтения остаётся actual CODEX selection → Chinese BOTH → separate CODEX Astra 6 UltraCode J; механические fixed examples не переименовываются в Chinese DPO.
6. Передать RP03 **один** исполнимый proposal: exact changed owner/files, input/output/state contract, минимальный implementation seam и эксперимент. При двух независимых seams — отдельные Unit и Flow карточки с этими же обязательными полями, конкретными examples/failure/stop, не общая инструкция «сделай many-to-many».

## Проверка способности

Unit experiment: одинаковые inputs/representation/Flow, vary only Unit state; измерять typed result correctness, completeness и точность связей, не количество outputs. Flow experiment: Unit/retrieval fixed, deterministic/no-update correction vs learned correction; измерять следующий фактический Unit input и итоговый law-correct solution, association errors, latency/resource use. Независимые source families; несколько lawful outputs допустимы. C#/SQL/RU проверяются через свои реальные consumers, не переназванием одного C# source.

## GOOD / BAD / EDGE

GOOD: inputs A/B дали A1,A2,B1,B2 в перемешанном порядке; association IDs сохранились, Flow исправил typed argument B1, downstream решение улучшилось при fixed Unit. Почему: доказаны и связи, и влияние correction.

BAD: `Zip(inputIds,resultIds)` присваивает ответы по позиции; IQueryable содержит только IDs без payload/resolver; одновременно изменены Unit и Flow, а gain приписан Flow. Remedy: explicit relation identity/typed consumer и causal contrast, не новый coverage percentage.

EDGE: output связан с двумя inputs→явное отношение, не дублирующая ложная ownership; stale OutputRef→typed unresolved, не подстановка чужого result; смешанные schema/domain→compatible explicit codec либо refusal; cancel после частичного результата→сохранить status/identity; повторное query enumeration→не повторять effect; zero valid output→lawful abstain/fallback, не fabricated candidate.
