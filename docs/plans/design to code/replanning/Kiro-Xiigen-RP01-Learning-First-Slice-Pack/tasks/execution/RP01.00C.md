# RP01.00C — независимая проверка конкретного изменения

**CONDITIONAL READ_ONLY.** Только когда proposed 01A/B/C/B0 или scientific-boundary изменение действительно требует отдельной проверки. Не очередной gate перед неизменённым работающим маршрутом. 0 новых product tests/model-training effects. [Dispatcher](../../RP01-EXECUTE-NOW.md).

## Промпт reviewer

Проверьте **один exact candidate/diff** против исходного требования и реально затронутого риска. Не пересматривайте всю архитектуру RP01/R01–R25 и не требуйте уже успешного обучения, чтобы оценить план узкой code correction. Если нужен independent CODEX Astra 6 UltraCode, укажите actual invocation/model/session; собственный повторный просмотр автора не переименовывается в независимую Astra-проверку.

**Inputs:** task/requirement ID, exact P/K candidate SHA и changed files, before/after diff, 00B defect/consumer evidence, исходный invariant, предложенные разрешённые effects, ближайшее existing focused evidence. **Sources:** полные changed files + ближайшие caller/consumer/interfaces; relevant WorkLeft-02/R18 subsection; actual scientific lifecycle только если изменение касается hold/publish/replay. **Skills:** K/docs/skills/plan-review-SKILL.md (candidate-bound PASS), generated-code-review-SKILL.md/code-examination-SKILL.md (source before tests), trainable-architecture-decision-SKILL.md (state/authority при затронутом learner), prompt-patch-authoring-SKILL.md (конкретная correction).

## Порядок

1. Подтвердить exact candidate и scope. Если уже есть genuine matching review тех же semantic blobs/dependencies, reuse его допустим в указанном scope; чужой/старый SHA не автоматически PASS нынешнего HEAD.
2. Самостоятельно прочитать change, original requirement и nearest callers/consumers. Выбрать проверки **по изменению**: raw/mask→exact bytes/causal targets; objective→формула/derivatives/state recipient; B0/journal→NoUpdate/one-use/recovery; loader→accepted identity/unsafe fallback; hold→intent before effects/exact publication. Не исполнять все ветки для документационного исправления одной ссылки.
3. Провести source-level walkthrough одного valid и одного существенного adverse/edge path. Установить, что исправлен root cause, а не weakened guard/fixture. Concrete missing proof назвать отдельно от code defect.
4. Только если затронут scientific protocol: проверить prospective criteria, независимые source families, same-code C0/Trial, отсутствие утечки и смешения kNN/LoRA effects. Runtime score, PC budget execution и real model roles не выдумывать.
5. Вернуть BOUNDED_PASS/NEEDS_FIX/UNVERIFIABLE со списком exact findings: source location, нарушенное требование, минимальный repair owner, как проверить устранение. Review author не делает скрытых product edits или запусков T1.

## Примеры и края

GOOD: исправление mask принято по actual consumer и focused invariant; одновременно указано Student gain=NOT_MEASURED. Почему: source correctness не притворяется научным результатом.

BAD: все 16 заданий PASS, потому что файлы существуют; или любая code correction BLOCKED до удачного post-update экзамена. Почему: смешаны полнота документов, исправность механизма и learning evidence.

EDGE: candidate изменился→STALE_REVIEW только зависимой семантики; other-slice commit не меняет reviewed blob→record unaffected, не полный review заново; missing actual independent invocation→NOT_PERFORMED; proposal меняет чужие shared files→указать ownership conflict; current code уже repaired→REUSE_NO_CHANGE вместо повторного патча; critical privacy/no-replay risk→block affected effect, не весь параллельный проект.

## Приёмка

Return `reviewed_task/requirement, exact_candidate_and_blobs, actual_reviewer_identity/receipt_or_NONE, independent_or_author_selfcheck, scope, source_walkthrough, risk_specific_existing_evidence, findings/fixes, verdict, runtime/science_NOT_MEASURED, next_owner`.

Никаких новых test-count/coverage/Windows/30–50-pass quotas. Actual mandatory safeguards не отменяются. PASS связан с candidate и проверенным риском, не blanket product readiness. STOP после передачи finding/receipt.
