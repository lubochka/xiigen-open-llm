## Совместный опыт Student × domain-policy

После появления обоих реальных механизмов четыре плеча: Q00=parent+old policy, Q10=Trial+old policy, Q01=parent+new policy, Q11=Trial+new policy. Domain-law/permissions/final arbiter guards неизменны во всех плечах. Q10−Q00 — Student effect при old policy; Q01−Q00 — policy effect при parent; I=(Q11−Q01)−(Q10−Q00) — interaction на заранее выбранной шкале качества. Это арифметическое разложение, не автоматическая statistical significance. Q11−Q00 нельзя целиком приписать каждому компоненту.

Если old policy не имела данного semantic feature, зафиксировать это как baseline design; не отключать hard laws и не выдавать deliberately unsafe arm за допустимый продукт. Отдельный deterministic lawful fast path сохраняется как comparator и fallback. Если он лучше, это результат, а не ошибка экзамена.

## Порядок подготовки

1. Выбрать вопрос и actual methods/state owners; назвать исходную гипотезу и альтернативу, которая её опровергнет. Например: reranker улучшает lawful path ranking на прежнем eligible pool; альтернатива — выигрыш объясняется более дорогим retrieval, а не state update.
2. Заморозить independent source families, domain/law/version, ambiguous-case/abstention правила, scorer и критерии до воздействия. TRAIN/DEV/operational feedback/untouched confirmation раздельны. Повторы внутри семьи — noise observations, не новые независимые семьи.
3. Записать prospective denominator, repeats/sample plan, практически значимый эффект, uncertainty method и budget из разрешённого протокола. Не выдумывать численные лимиты машины. Existing first-C# 12×5/+2/critical=0 не переносить автоматически в другие домены.
4. Указать actual execution commands/API **из текущего consumer**, раздельные authorities и output refs. Измерительные raw данные закрыты по purpose. Эта READ_ONLY карточка не вызывает runtime; receiving owner получает один complete work order, не «запусти benchmark».
5. Предусмотреть порядок/cache/seeds: сравнимые cold/warm strata, fixed decoding/settings, межплечевой порядок до результатов. Не требовать равных фактически потраченных ресурсов — использовать одинаковые допустимые envelopes и измерять реальное потребление/качество; quality-at-budget и cost-at-quality — разные вопросы.
6. Count end-task correctness, critical law errors, lawful abstention и answered fraction, правильность выбранного пути/ассоциаций, per-domain и worst-domain retention, latency N/p50/p95, total elapsed/CPU/peak RAM/VRAM и disk. Scope машины включает одновременно живущие base/reference/LoRA/optimizer/index/cache/processes; не суммировать независимые process peaks как якобы одновременный peak.
7. Teacher/CODEX selection/J/science, failed/reverted attempts, indexing/reindex, reload/recovery, external cost и user feedback processing входят в end-to-end cost. Remote serving/authoring помощь отмечается отдельно: local Student training не равно полностью автономная offline система.
8. Задать outcome IMPROVE/REGRESS/INCONCLUSIVE/INVALID_EVIDENCE, domain/resource limits и следующий owner. Если качество и затраты имеют tradeoff — показать обе стороны, не сворачивать их в произвольный score задним числом.

## GOOD / BAD / EDGE

GOOD: при тех же allowed PC limits новый hybrid решает больше независимых lawful задач; reported latency/resource и old-domain retention не скрывают failures. Почему: measured tradeoff относится к настоящему consumer.

BAD: «adapter 2 MB⇒всё обучение помещается на PC»; один C# trial⇒SQL/RU generalization; warm Trial сравнен с cold parent; отсутствующие поля заполнены нулями. Remedy: complete resource boundary, distinct domain consumers, comparable strata, NOT_MEASURED.

EDGE: OOM до/после state mutation→effect-aware recovery и failure cost; прирост нулевой→cost-per-gain не определён, не красивое конечное число; маленький N→pilot/uncertainty, без universal claim; repeated final exam tuning→contamination invalidates confirmation; изменённый dtype/tokenizer/index→явная новая версия experiment; среднее улучшилось, critical worst domain ухудшился→не скрывать aggregate.
