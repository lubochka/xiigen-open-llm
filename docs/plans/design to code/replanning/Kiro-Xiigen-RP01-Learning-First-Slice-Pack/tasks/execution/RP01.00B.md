## Порядок

1. Read-only проверить разрешённый previous handoff и актуальность его run/parent/pair/policy/held/publication refs у существующих owners. Ошибка доступа не доказывает отсутствия. Если ничего наблюдать нельзя — STATE_UNKNOWN с точным отсутствующим наблюдением; не строить surrogate JSON.
2. Разделить parent PRESENT/ABSENT/CORRUPT/UNKNOWN, pair ABSENT/ELIGIBLE/QUARANTINED/UNKNOWN, intent и canonical attempt, held/verdict/published. Intent и canonical attempt — разные этапы. Проверить stage только по разрешённой metadata/journal, не читать private answers ради статуса.
3. Выбрать ближайшую ветку по таблице. Затем открыть соответствующий command/endpoint/owner и нужную source delta. Разделять inspect, author, reopen, fresh train-and-hold, explicit resume-baseline-and-hold, publish-held, protected OneLesson и ordinary Generate. Отказ одного endpoint не означает отказ всех.
4. Переиспользовать актуальную карту `exact pair → material/response mask → policy/reference objective → permitted LoRA/optimizer/journal → Trial → hold → publisher → ordinary consumer`. Дочитать только реально отсутствующее или изменившееся ребро; указать path:method, caller, state owner и evidence. Если полной карты нет, не выдавать частичную за ROUTE_VERIFIED, но передать обоснованное ближайшее действие и конкретного владельца оставшегося source debt.
5. Для raw/mask, objective/state и consumer вернуть REUSE_NO_CHANGE, PROVEN_DEFECT или UNKNOWN. Только PROVEN_DEFECT с нарушенным инвариантом назначает 01A/B/C. Missing grant не defect objective; cached prevalidation, уже вызванный до calibration, не надо реализовывать повторно.

## GOOD / BAD / EDGE и восстановление

GOOD: exact held-trial уже есть; проверены его metadata и путь T2, previous source map переиспользована. Почему: не повторены optimizer, sampling и полный audit.

GOOD: сохранены пять raw C0 до canonical attempt; owner admission подтверждена, next=T1 explicit recovery. Почему: сохранившаяся работа не выброшена; actual command требует отдельного effect grant.

GOOD: parent действительно отсутствует при eligible dataset; B0 помечен InitialBaselineNoUpdate, а не обучением.

BAD: «OneLesson вернул 503 — переписать trainer». Почему: другой protected input и missing grant не доказывают алгоритмический дефект. Remedy: actual route и exact refusal.

BAD: «intent открыть не удалось — урок не запускался». Почему: access error может скрыть эффект. Remedy: UNKNOWN → custody/recovery owner без записи.

BAD: изучить весь optimizer/publisher до того, как прочитан существующий complete-held handoff. Почему: не влияет на ближайший T2 и повторяет source work. Remedy: state-first, нужная delta и scoped unresolved owner.

EDGE: core HEAD изменился → перечитать относящиеся blobs, не считать весь HEAD автоматически equivalent; неполный post-update state → не baseline recovery; raw train-existing → scientific route, не снятие guard; SAC/native failure → точная текущая ошибка, не изменение security/full CI; несколько run IDs одной pair → existing lineage/sibling check, не «свободный» ID.

## Выход и проверка

Один state-handoff: P/K SHA; прочитанные и переиспользованные source/RAG spans отдельно; source→method→state owner→consumer, известная и неизвестная часть; A/B/C decisions; B0 need; run/pair/parent/policy/intent/canonical-attempt/held/verdict/published refs; eligibility owner/UNKNOWN; observed_state; next_task/branch; exact_blocker; new_product_tests=0; model_effects=NONE.

Другой исполнитель должен выбрать ту же ветку без полного reread проекта. Нет named optimizer recipient/ordinary consumer → не писать ROUTE_VERIFIED для всего пути. Runtime не наблюдался → CODE_TRACE_ONLY/STATE_UNKNOWN. Проверить мысленно свежий запуск, допустимый C0 recovery, post-attempt, held и inaccessible state; они не должны схлопываться в один запуск. Это проверка инструкции, не выполненный runtime эксперимент. STOP после read-only handoff.
