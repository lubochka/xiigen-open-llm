## Что именно проверить

1. Для выбранного standard response-sum DPO `ell_theta(y|x)` — сумма causal log-probabilities только response targets; conditioning/frame/mask идентичны policy/reference. Определить
   `m = beta * ((ell_theta(y+) - ell_ref(y+)) - (ell_theta(y-) - ell_ref(y-)))`,
   `L = w * softplus(-m)`, `dL/dm = w*(sigmoid(m)-1)`.
   Для standard positive-weight case beta>0, finite w≥0. Repo-specific VectorSignal/weight semantics прочитать отдельно: отрицательный множитель меняет направление предпочтения, поэтому его нельзя молча считать допустимым standard weighting. Любая намеренная alternative objective/length normalization должна иметь отдельный явно выбранный contract, не скрытую смену под старым именем.
2. Проверить logits→target shift, masked sum, numeric stability finite inputs и derivative signs. Для scalar иллюстрации m=0,w=1: L=log(2), derivative=-0.5. Это локальная математическая проверка, не proof gain после произвольного optimizer step.
3. Найти **реально установленные** project LoRA A/B, RequiresGrad, optimizer membership, checkpoint serialization/loading и reference storage. Флаг LoRA в config, название класса или новый weights hash сами по себе не доказывают обучаемого получателя. Base/reference не должны обновляться данным project step; shared storage alias требует проверки.
4. Не требовать изменения **каждого** A/B тензора на каждом шаге: zero gradients/initialization/zero weight возможны. Отчёт различает optimizer invoked, committed step, allowed tensor delta и useful learning. Не фабриковать mutation ради PASS.
5. Проверить полный parent/Trial optimizer moments/step, RNG/dropout/training mode, journal и recovery. InitialBaselineNoUpdate Step1 использует DPO identity как provenance, не consumed lesson; реальные applied descendants/legacy history запрещают обход повторного применения новым UUID.
6. Текущий scientific lifecycle удерживает один Trial: partial intent→existing recovery; complete held→T2; publish-held не вызывает optimizer. Дефект recovery после неизвестного effect ремонтируется у state owner, а не удалением intent/истории.

## Примеры, отказ и минимальная проверка

GOOD: source-backed sign defect исправлен в reached consumer; scalar derivative и allowed-key observation совпадают с contract; code ready возвращается T0, gain=NOT_MEASURED.

BAD: mean по prompt+PAD выдаётся за standard response-sum DPO; reference обновляется вместе с policy; словарь kNN или меньший LoRA file объявлен Student learning. Почему: неверная цель/получатель/claim. Remedy: исправить actual owner, не metric label.

EDGE: m≈0, zero VectorSignal, long unequal responses, overflow, gradient clipping, reference alias, incompatible optimizer resume, last target omitted, два writers, cancel после commit. Для каждого определить математический invariant/state boundary; не делать повтор optimizer для выяснения unknown outcome.
