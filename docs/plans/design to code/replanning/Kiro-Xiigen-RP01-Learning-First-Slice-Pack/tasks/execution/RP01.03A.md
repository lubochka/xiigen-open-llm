## Этапы и полномочия

**B0 — только при действительно отсутствующем parent.** [B0 child](../children/RP01.03A-B0-BOOTSTRAP.md), отдельный настоящий grant. Совместимый parent переиспользовать. Step1/InitialBaselineNoUpdate не является optimizer step. CORRUPT/UNKNOWN parent не равен чистому отсутствию.

**T0 — read-only freeze/revalidation.** [T0 child](../children/RP01.03A-T0-CONTROLS.md). Проверить parent, pair/J, rights, один step, reference/decoder/kNN/arbiter/representation/budget и policy. Для нового опыта intent должен отсутствовать; для pre-executor recovery неизменённые исходные policy/intent/settings проверяются повторно без новой preregistration. Согласованную evidence переиспользовать. Связать 12 независимых C# families ×5 repeats, scorer/retention, run/parent/dataset/pair. Не запускать отдельный C0: existing lifecycle владеет baseline и Trial capture. Если сравнимой предыдущей модели нет: P=NO_PRIOR_COMPARABLE_MODEL. T0 не имеет model effects.

**T1 — fresh или explicit pre-executor recovery, не два запуска подряд.** [Полная T1 карточка](../children/RP01.03A-T1-UPDATE.md) задаёт точные команды и разрешения:

- отсутствующий intent + готовые inputs/grant → один `train-and-hold`;
- тот же intent + допустимый неполный/полный C0 ДО canonical attempt, подтверждённый journal owner и повторной server admission → один `resume-baseline-and-hold`;
- canonical attempt/claim/journal/Trial, drift, orphan, sibling conflict или UNKNOWN → не baseline-resume, existing recovery owner;
- complete held → сразу T2, без T1.

Baseline-resume может завершить C0 и дойти до ПЕРВОГО optimizer, поэтому не называется read-only. Он не даёт права повторить update. Existing coordinator проверяет весь retained C0 до новых calls, переиспользует допустимые raw/results, затем при допуске делает один DPO step и сохраняет Trial/raw evidence. Native/baseline guards могут отказать; наличие команды не гарантирует update. Зафиксировать actual LoRA tensor delta, optimizer/journal и неизменность base/reference. HELD_FOR_SCIENCE не publication receipt. Native negative сохранить. Cancel/partial write → повторное определение stage у owner, без автоматического replay/смены run ID.

**T2 — отдельный независимый CODEX с `astra 6 ultracode`.** [T2 child](../children/RP01.03A-T2-EXAM.md). Использовать existing complete held и private raw C0/Trial answers. Никакого нового Teacher/Student generation/optimizer. Blind frozen-rubric assessment, настоящий runtime model ID/receipt, binary family decisions, critical errors, все ordered repeat hashes. Пять повторов одной семьи и разные run IDs не означают независимые семьи или разные Student seeds. Сохранить owner-only scientific-verdict установленной схемы; публично только разрешённая сводка. Negative/inconclusive сохраняются; policy не подгоняется.

**T3 — publish-held, затем cold adoption.** Только genuine independent verdict, positive native gate и совпадающие bindings позволяют owner настроить existing startup policy/held/verdict hashes и publish-held. Публикуются те же saved Trial weights, без optimizer/calibration/evaluation. Затем новый процесс ordinary Generate подтверждает загрузку этих весов. Retained-training readiness, root startup authority и ordinary-serving результат различаются. Нельзя напрямую публиковать private Trial или передавать verdict=true клиентским request.

## Проверка результатов без coverage

Код не менялся → новых продуктовых тестов 0. Реально изменённый journal/mask/loader/rights инвариант → ближайшая targeted проверка существенного риска/отказа, reuse exact-candidate evidence. Нет Windows matrix и процентного gate.

Текущий first-science policy: 12 families ×5 repeats; operational acceptance: correct-family gain≥2, trialCritical=0, newCritical=0 и native positive. Это существующий ограниченный критерий первого опыта, не универсальный научный закон/statistical significance. Различать STATE_CHANGED, HELD, SCIENTIFIC_IMPROVE/REGRESS/INCONCLUSIVE/INVALID_EVIDENCE, PUBLISHED, COLD_ADOPTED. Loss/hash не заменяет эти доказательства. Headroom и paired acquired/lost families считать по frozen verdict, не вводя нового gate задним числом.

В C0→Trial меняется только разрешённое Student state. Domain map, tokenizer, kNN, arbiter, decoder, reference и budget фиксированы. SQL/EN→RU и Student×law-policy interaction — отдельные параллельные опыты RP02/04E, не автоматически результат первого C# урока. Domain laws нельзя заменить простым голосованием соседей.

**Стоимость:** fresh C0 требует 60 логических наблюдений до optimizer; полный C0/Trial — 120. При reuse это не обязательно 120 новых native evaluator calls. Отдельно показать new/reused/logical/historical-UNKNOWN, Student generations, native evaluator, CODEX S/J/T2, failed costs и time-to-first-update/held/accepted. Не делать новые вызовы ради отчёта. Метрики без actual evidence остаются NOT_MEASURED.

## GOOD / BAD / EDGE с причинами

GOOD: сохранился пригодный C0 до canonical attempt; тот же run явно восстановлен, raw не генерируются повторно, первый update выполняется только в пределах actual grant. Почему: не теряется работа и не дублируется обучение.

GOOD: T1 состоялся, gain отсутствует; Trial/raw сохранены, parent active, 03B получает гипотезу нового разрешённого урока. Почему: отрицательное наблюдение не подменено green.

GOOD: complete held уже есть; выполняется только T2, затем при настоящем допуске publish-only без второго optimizer.

BAD: C0 со старым kNN, Trial с новым, gain назван DPO. Причина: два вмешательства. Remedy: INVALID_EVIDENCE, отдельный prospective опыт, не переписывание старых labels.

BAD: оборвавшийся T1 повторён после удаления intent; или baseline-resume назван просмотром без эффекта. Причина: неверная модель жизненного цикла. Remedy: distinction pre-executor/post-attempt и реальные grants; unknown → owner recovery.

EDGE: scorer unavailable → held сохраняется, T2 BLOCKED_EXACT; parent drift → не продвигать устаревший Trial; scientific positive/native negative → не обходить publisher; positive verdict/cold load failure → 01C, не retraining; OOM → сохранить stage/effect-known boundary, не менять settings незаметно внутри опыта.
