## Алгоритм

1. S выбирает один допустимый case по реальному диагностическому сигналу либо domain-law analysis, если Student parent ещё нет. Не выдумывать Student score и не ждать B0: B0 нуждается в eligible DPO. Зафиксировать raw owner input/source/question и неизменяемый selection handoff.
2. A проверяет actual source/effect grants, model edition/license/output-use, manifest/layer/profile ID+SHA, loopback endpoint и полный native-token budget. Existing raw intake имеет maximumAuthorCalls=1 и maximumDpoSteps=1; не добавлять обязательный smoke inference перед исправным authoring.
3. A через существующего владельца передаёт frozen task и получает JSON chosen/rejected от **одной действительной Chinese model invocation**. Сохранить exact decoded strings без Trim/newline/Unicode/punctuation rewrite и без `[WRONG:]` добавки. Weak Student answer может быть разрешённым контекстом, но не автоматически final rejected.
4. J получает неизменяемую пару и source, проверяет законы/версию, содержательное chosen>rejected, авторство обеих сторон, права, disjointness receipt и novelty/lineage. TIE/BOTH_BAD/UNJUDGEABLE/REVERSED/BYTES_CHANGED/SOURCE_INVALID → quarantine, не forced ranking.
5. J не редактирует ответы и не создаёт фиктивный Native receipt/optimizer grant. Настоящий результат exact-pair assessment передаётся existing admission owner, который сохраняет фактический eligible state по действующим правилам. Отдельный grant на T1 остаётся необходим.
6. Parent отсутствует → условный B0; parent имеется → T0. Если pair уже applied/исход неизвестен → reconciliation, не новый UUID ради replay. Дефект material/mask только при source evidence →01A, а не обязательное «проверить всё».

## Иллюстрации, не реальные учебные данные

GOOD: один source `Count(string? s) => s?.Length ?? 7`, один вопрос про s=null; Chinese действительно пишет объяснение fallback 7 и правдоподобное ошибочное объяснение результата 0; отдельный J подтверждает семантическое различие по точным bytes. Почему: учебный сигнал относится к закону, не стилю.

BAD: rejected — мусор или тот же правильный ответ короче. Почему: не даёт требуемого содержательного предпочтения; J возвращает TIE/PAIR_NOT_USEFUL, не fake VALID.

BAD: CODEX исправил отрицательный ответ и сохранил authorship=Chinese. Почему: false provenance. Remedy: новую final authoring revision создаёт разрешённый Chinese owner, затем новый exact J, без silent replacement.

EDGE: полный rendered prompt >1536 native input tokens в текущем CPU profile→новая согласованная версия TRAIN selection, не truncate; model/rights/profile drift→BLOCKED_EXACT; partial response/cancel→прочитать retained outcome, не autoretry; both correct/both bad→quarantine; source real-repository вместо ORIGINAL synthetic→проверить допустимый route, не подделать sourceKind.
