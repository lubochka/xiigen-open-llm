## Новый процесс после публикации: не переносить root grant в serving по инерции

**Source-bound условие на K025c42c, не наблюдавшийся runtime failure:** `BindCheckpointForStartup` при включённом initial-training выборе загружает latest compatible manifest и допускает только exact pinned parentless Step1 с InitialBaselineNoUpdate. После успешной публикации latest может стать trained descendant. Сохранённые INITIAL_TRAINING selectors тогда не превращаются автоматически в разрешение загрузить его как initial B0.

Если этот activator включён в выбранном host и bind отказывает, `ContinuousLearningRetainedObjectHostedActivator.StartAsync` отмечает inactive composition failed и закрывает retained policy gateway. **Из этого нельзя автоматически заключить, что `/api/code-documentation/generate` недоступен:** endpoint разрешает собственный CodeDocumentationGenerationService, а тот использует `PrepareStart` для обычной serving-only загрузки. Полный endpoint outcome определяется фактическим запросом, а не training-ready флагом. И наоборот, HTTP success сам по себе не доказывает правильный served checkpoint.

Host owner для serving-only процесса должен выбрать предусмотренный ordinary generation configuration с actual accepted identity, запрещённым скрытым cold-start и без случайно унаследованного first-root optimizer выбора. На прочитанном source отключённая ветка initial selector требует `_mode` отсутствует/пуст и **`_reason == null`, `_parentHash == null`**. Надёжное явное выражение отсутствия — не передавать в **новый serving-only процесс** все три:

`XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_MODE`, `XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_REASON`, `XIIGEN_CODE_DOCUMENTATION_INITIAL_TRAINING_PARENT_SHA256`.

Это указание будущему уполномоченному host owner, не изменение среды этой документной публикацией. Не очищать чужую shell/session, user/machine-wide environment или действующий training host. Не сбрасывать accepted weights, topology, tokenizer, journal, source/privacy protections или generation configuration. Частичное удаление только MODE при оставшихся REASON/PARENT не является тем же disabled state. Для mixed-purpose host с необходимым training lifecycle требуется собственный поддерживаемый contract, а не обход root guard или молчаливое применение этих serving-only настроек.

**Минимальный достаточный результат:** записать purpose нового процесса, наличие/отсутствие selector trio без секретов, actual retained readiness отдельно, actual Generate result и served SHA. Не добавлять ещё один C0/optimizer, новую suite или обязательный эксперимент для всех других слайсов.

## GOOD / BAD / EDGE

BAD: positive T2, но publication не состоялась; verifier вручную прописал Trial path. Почему: обойдён canonical publisher. Remedy: T3.P, без forced load.
