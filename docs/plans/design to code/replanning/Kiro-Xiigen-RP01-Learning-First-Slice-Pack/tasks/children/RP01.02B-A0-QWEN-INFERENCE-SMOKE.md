# RP01.02B.A0 — не более одного диагностического вызова, не учебная пара

**INCIDENT_ONLY.** A0 нужен только когда конкретный нерешённый вопрос — может ли фактический provider завершить inference. При пригодном свежем evidence или готовом разрешённом authoring пути — SKIPPED/REUSED; сам authoring может дать нужное наблюдение без дополнительного smoke. [Dispatcher](../../RP01-EXECUTE-NOW.md), [Q0](RP01.00B-Q0-503-AND-MANIFEST-TRIAGE.md), [единственный автор A](RP01.02B-A-AUTHOR.md).

## Промпт оператору

Проверьте одну способность локального provider ответить на безобидный синтетический запрос. Разрешён **максимум один generation request**, без встроенного повторного запроса, автоматического reconnect/retry или дополнительного авторства DPO. Результат не становится TRAIN-строкой, J verdict или доказательством исправности production binding. Никаких Student/model-weight/configuration изменений.

**Вход:** incident_id и точный unanswered question, actual host/base URI/model/version/digest, разрешённая diagnostic profile и budget/cancellation policy, genuine разрешение на этот эффект, prior observations. Q0 — возможный источник evidence, **не обязательный отдельный предшественник**. Отсутствие разрешения/реального локального исполнителя → NOT_PERFORMED. Не выдумывать установку, адрес или alias.

**Источники:** actual K/tools/Rp01RawDpoLesson/README.md, достигнутый provider client и LocalQwenOllamaInferenceProfileAuthority, официальный [Ollama generate API](https://docs.ollama.com/api/generate) и [model inventory](https://docs.ollama.com/api/tags). Применять документацию к реально установленной версии. Skills K/docs/skills/code-examination-SKILL.md, diagnostic-escalation-SKILL.md, prompt-patch-authoring-SKILL.md — слоям наблюдения и одному вмешательству; generic test-count/Tier-escalation правила не импортируются.

## Действия

1. Проверьте существующий observation. Если inference уже подтверждён для нужных host/model/settings и вопрос закрыт — не вызывать снова. Для непроверенного/чужого процесса на порту никакой prompt не отправлять.
2. Запишите выбранный diagnostic request **до** вызова: `POST <actual-base-uri>/api/generate`, model — точный подтверждённый ID, `stream=false`, prompt: `Describe a red ball in one short sentence. No code or private data.` Runtime options/limits — только actual permitted diagnostic profile. Не добавляйте unsupported think/format значения; строка model из примера документации не заменяет actual identity.
3. Различайте два режима. Если проверяется production client/profile, использовать его реальный command/adapter и **его** native-token preflight/caller-cancellation contract; не подставлять `num_predict=128`, timeout=600 или другой profile из старого smoke. Если это разрешённый прямой provider-only запрос, записать его actual options и явно `PRODUCTION_PROFILE_NOT_EXAMINED`. Прямой API success не доказывает работу XIIGEN adapter. Нет подходящего разрешённого исполнителя — BLOCKED_EXACT_EXECUTOR, не писать новый harness ради одного smoke.
4. Выполните один запрос через поддерживаемый local runner с данным cancellation policy и без auto-retry. Продуктовые ManualCpuAuthoring/ManualEvaluation профили не получают новый HTTP deadline из этой карточки. Диагностическая отмена/ошибка не означает, что сервер уже освободил model resources; не запускать второй запрос поверх неизвестного первого.
5. Зафиксируйте actual status, returned model, `done`, `done_reason`, наличие непустого **final response**, wall time и доступные counters. `thinking` отдельно и не заменяет final response. Длительности API приводить к явным единицам по installed API; stdout не содержит secrets/private logs. Не требовать точную фразу или JSON, если request этого не задавал.
6. Вернуть INFERENCE_OBSERVED, FINAL_RESPONSE_NOT_OBSERVED, CANCELLED_OR_UNKNOWN, PROVIDER_ERROR или NOT_PERFORMED. Даже успешный smoke не означает что обе DPO стороны созданы, objective корректна, модель обучилась или PC budget достаточен для полного lifecycle.

## GOOD / BAD / EDGE

GOOD: один запрос даёт final текст с actual model/host/settings; next=A или конкретный binding owner по unresolved question, а не автоматический A1. WHY: получен именно недостающий факт.

BAD: «один запрос» плюс «один допустимый retry», произвольная смена модели или ручной второй запрос до завершения первого. WHY: превышение предписанного эффекта и скрытый расход. Remedy: сохранить отказ; иной experiment возможен только как отдельно назначенное обоснованное действие, не повторять до удачного ответа.

BAD: thinking-only, tags success или green mock назван DPO_SUCCESS. Remedy: исправить статус и сохранить original response; не придумывать missing final answer.

EDGE: model load slow/OOM/length stop → reported diagnostic limitation, не automatic pull/GPU switch; direct API работает, adapter нет → A1, не ещё один smoke; Windows и WSL различаются → host-specific evidence; cancelled request продолжает занимать ресурс → existing process/status observation, не force-kill без полномочий.

## Приёмка и output

`incident_id; P/K SHA; actual source/skill sections; host/model/profile/options/grant; direct-provider or production-client mode; prior evidence reused; generation_request_count (0 or 1); timestamp/status/done/final flags; raw-safe response ref; durations/cost or NOT_MEASURED; exact limitation; next owner`. New product tests=0, DPO_pairs=0, Student_updates=0, CODEX_selection_and_J=NOT_PERFORMED. STOP после этого observation.
