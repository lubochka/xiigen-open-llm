## GOOD / BAD / EDGE и восстановление

**GOOD:** пять exact C0 raw переиспользованы; missing slots досняты; существующий executor дал один update; Trial held, parent active, next=T2. Почему: достигнуто обучение без повторной работы и необоснованного принятия.

**GOOD:** cached verdict в позднем слоте не проходит profile/parser; общий prevalidation отказал до новых calls. Почему: механизм уже защищает границу. Сохранить evidence и передать точный refusal owner; не писать новый validator без PROVEN_DEFECT.

**BAD:** назвать `resume-baseline-and-hold` безопасным read-only просмотром. Почему: после C0 возможен optimizer. Remedy: получить/проверить существующий actual effect grant; для одного осмотра использовать 00B, не запускать эту команду.

**BAD:** cancel объявлен zero-effect, intent удалён, та же pair обучена с новым run ID. Почему: потеря single-use/effect history. Remedy: сохранить историю и выбрать owner-supported recovery по journal.

**BAD:** C0 использует прежний kNN, Trial новый, прирост приписан DPO; либо training loss объявлен IMPROVE. Remedy: ограничить claim/INVALID_EVIDENCE, не менять frozen rubric.

**EDGE:** complete C0 без canonical attempt может быть кандидатом для того же explicit recovery; canonical attempt без held — уже НЕ эта ветка. Native negative — held, не publish. Pair уже применена в lineage — не новый урок. Source/parent/settings drift — refusal, не новый expected hash. OOM/cancel/partial write — записать последнюю известную stage, не считать эффект отсутствующим. Отсутствующий поддерживаемый механизм — bounded 01B issue с method/caller/consumer, не permission удалить артефакты.

Не добавлять timeout/autoretry. Используются caller lifetime и host stopping token. Actual native failure блокирует достигнутую операцию, не независимые SQL/EN→RU работы. Если host уже проверен, ritual smoke не нужен; при необходимости build только запускаемого project/affected dependencies. Windows security и всю Actions matrix не менять.
