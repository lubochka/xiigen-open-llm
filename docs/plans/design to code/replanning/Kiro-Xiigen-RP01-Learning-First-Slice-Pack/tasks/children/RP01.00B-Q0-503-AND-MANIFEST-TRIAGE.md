# RP01.00B.Q0 — один наблюдаемый сбой, без обязательной серии диагностики

**INCIDENT_ONLY / READ_ONLY.** Нет конкретного инцидента или нужный факт уже подтверждён текущим receipt → SKIPPED/REUSED. Q0 не является воротами перед A, T1 или 02A. Единственный [dispatcher](../../RP01-EXECUTE-NOW.md); [правила](../../GOVERNANCE-AND-REVIEW.md). Старый local recovery protocol — исторический источник, не обязательный список команд.

## Промпт исполнителю

Определите, на каком реально достигнутом участке произошёл переданный сбой. Не диагностируйте Qwen по одному слову 503 и не считайте найденный model manifest доказательством inference. Верните один source-backed ответ или точно ограниченную неизвестность. Не запускайте модели, не создавайте пары, не меняйте настройки/права/Windows security и не запускайте тестовую матрицу.

**Вход:** конкретный incident_id, timestamp, фактический command/tool, доступный URL/HTTP code/error body без secrets, last confirmed stage, host identity (Windows/WSL/container/remote), существующие relevant observations и границы разрешённого read access. Отсутствие shell на PC → LOCAL_OBSERVATION_NOT_PERFORMED, не отсутствие модели.

**Источники:** актуальный K/tools/Rp01RawDpoLesson/README.md и достигнутый command/provider caller; 25.ModelServer endpoint/config только если сбой действительно от него; current provider configuration, не придуманный localhost. D/09.09.26WorkLeft-02-teaching-chinese-model.md R16 для разграничения ролей. Skills K/docs/skills/code-examination-SKILL.md, diagnostic-escalation-SKILL.md, prompt-patch-authoring-SKILL.md: прочитать относящиеся разделы наблюдения/слоя/минимального исправления. Старые test-count triggers и правило «первая догадка — root cause» здесь не применяются: сервис, доступ, память и transport требуют собственных фактов.

## Шаги

1. Pin P/K SHA и повторно используйте immutable relevant receipts. Установите origin: connector/context transport; локальный provider; XIIGEN protected endpoint; scientific hold/recovery. Client 503 без target/payload не определяет origin. Существующий HELD_FOR_SCIENCE — не сбой Teacher.
2. Выберите **одно минимальное недостающее наблюдение**, а не выполните весь диагностический список. Model registration unknown → read actual provider inventory. Provider reachability unknown → read API inventory/status на действительно настроенном endpoint. Ошибка current scientific request → read saved intent/status через owner, не запускать заново. Log already resolves question → не делать network call.
3. Для подтверждённого Ollama read-only inventory — `GET <actual-verified-base-uri>/api/tags`; сравнить точный model/digest. Дополнительные `ollama list/show/ps`, process/port или manifest paths нужны только если они различат оставшиеся гипотезы. Не открывать private prompt/logs/secrets и не делать pull/restart/generate. Port 11434/Windows home — не универсальные defaults.
4. Windows localhost не доказывает доступность того же сервиса из WSL/container. Записать, **откуда** получен observation. Проверка из другой среды не устраняет исходный сбой. Не менять закреплённый endpoint на LAN URL и не переписывать hash-bound inputs.
5. Вернуть primary classification + остаточные гипотезы: TRANSPORT_FAILURE, PROVIDER_UNREACHABLE, MODEL_NOT_REGISTERED, PROVIDER_INVENTORY_REACHABLE, XIIGEN_TYPED_REFUSAL, HELD_AWAITING_SCIENCE, UNKNOWN_EFFECT или UNATTRIBUTED. API inventory reachable не равно model-inference-ready или training-ready.

## Следующий владелец

Не существует обязательной цепи Q0→A0→A1→A. Если готовы authorised authoring inputs и нет существенной неопределённости, вернуться A. Если действительно неизвестна способность сервиса закончить запрос — предложить incident-only A0 с отдельным реальным разрешением на один диагностический вызов. Binding mismatch → read-only A1. Complete held → T2; unknown effect → существующий recovery owner. Неразрешимый по имеющимся наблюдениям source вопрос может получить X, но отсутствие X не блокирует независимые работы.

## GOOD / BAD / EDGE

GOOD: trace показывает отказ connector до обращения к provider; Q0 сообщает transport failure и не переустанавливает Qwen. WHY: чинится наблюдавшийся слой.

BAD: tags содержит модель → объявить оба DPO ответа созданными; или добавить A0 как обязательное подтверждение любого inventory. WHY: разные эффекты/лишний расход. Remedy: вернуть только доказанный факт и state-aware next action.

EDGE: порт занят другим процессом → не отправлять материал; API доступен с Windows, WSL не проверен → HOST_SPECIFIC_UNKNOWN; missing file и access denied различать; client cancel после training start → UNKNOWN_EFFECT независимо от доступности Ollama. Несколько возможных причин допускаются; не назначать root cause по первому совпадению имени.

## Приёмка и выход

`incident_id; P/K SHA; sources/skills actually read; actual execution host; prior evidence reused; one observation or NONE; redacted origin/status; facts versus hypotheses; classification; unresolved question; next owner`. New product tests=0, inference=0, optimizer=0, configuration writes=0. Гипотеза опровергнута, если direct evidence указывает другой слой; исправить классификацию, не историю наблюдений. STOP после bounded handoff.
