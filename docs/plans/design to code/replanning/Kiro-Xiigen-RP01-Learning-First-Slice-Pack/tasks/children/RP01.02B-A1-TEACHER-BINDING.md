## Проверка

1. Найдите фактический путь `selected source → intake/config hashes → resolver → teacher factory/client → decoded chosen/rejected → J handoff`. Если dataset уже переоткрывается без factory, истёкший authoring grant не требует нового Teacher call; actual training/source use оцениваются своим owner отдельно.
2. Сопоставьте model edition и registry digest, native vocabulary/template, endpoint/host, full rendered input, request/response schema, final text extraction, raw byte preservation и cancellation. Не доказывать production binding прямым provider-only smoke с другими settings.
3. Текущий raw route требует **ManualCpuAuthoring и ManualEvaluation** ID/SHA из actual authority. Старые `qwen35-local-authoring-cpu-bounded-v1`, скопированный digest и finite deadline не являются универсальными актуальными параметрами. На K source anchor `025c42c74b1d30ffa4660f9824a52cf8fcaf7c88` tools README требует ctx2048/reserve512/native input≤1536, CPU2/batch16/GPU0 и caller-lifetime без нового таймера. Проверять identity вместе с реальным descriptor/consumer; readback README не считается actual model call.
4. Различайте чистое отсутствие, mismatch, malformed response, source-authority refusal, transport failure и unknown persistence. Один источник может быть readable SealedRepositorySource и не давать права mutate pair store. Не заменять настоящий read-only source пустой writable папкой.
5. Если binding корректен — REUSE_NO_CHANGE и возврат **A без повторного smoke/authoring в A1**. Если пара уже authored — J; complete held — T2; unknown effect — recovery по dispatcher. Если дефект доказан, вернуть exact file/method, нарушенный contract, smallest change и nearest risk check. Отдельно назначенный code owner делает patch; A1 не создаёт новый trainer/client и не снимает 503/safety guard.

## Примеры и исправления

GOOD: direct provider вернул final response, но adapter извлекает неверное JSON поле; A1 связывает конкретный caller/DTO defect и передаёт code owner, не вызывает второй Teacher. WHY: исправление и авторство разделены.

BAD: success A0 → обязательный A1 → ещё одна pair generation → A снова пишет пару. WHY: дублирование model effects и неоднозначное авторство. Remedy: одна A с resolver-first reuse, остальные stages только diagnosis.

BAD: менять config SHA на произвольное observed значение или выдать старый profile за current. WHY: digest связывает реальные входы, не заменяет authority. Remedy: настоящая versioned config у владельца, не silent rewrite.

EDGE: one ID without SHA → exact input gap; API reachable from Windows only → host-specific UNKNOWN; две semantic-equivalent стороны → J/TIE, не provider patch; malformed/partial output → сохранённый отказ; known raw-v2/legacy mismatch → конкретный reader/version owner, не Unicode normalization; отсутствующий trained parent не blocker authoring законного original TRAIN case.
