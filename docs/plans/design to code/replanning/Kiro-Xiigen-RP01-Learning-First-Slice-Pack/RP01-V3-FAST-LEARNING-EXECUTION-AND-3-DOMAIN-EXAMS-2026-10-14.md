## 3. Three concrete real-world law families — DOCUMENT_EXAMPLES, NOT sealed data

**C# / CodeDocumentation.** User asks: what does string? s=null; int? n=s?.Length produce? GOOD: null; explain conditional access and nullable result. BAD: zero due to imaginary default; WHY: confuses ?. with ??, incorrect language law. EDGE: getter with side effects, invalid version or unknown target types → version-specific clarification/abstention. Candidate DPO negative must be a plausible *semantic* error, not a random malformed answer. Holdout must use different source-origin/AST families and be frozen before Teacher case selection.

**SQL / actual SQL consumer.** Query with WHERE amount = NULL. GOOD: SQL three-valued logic requires IS NULL for missing values (dialect qualified). BAD: equality with NULL is TRUE; WHY: loses unknown/null law. EDGE: LEFT JOIN filter on right-hand fields can drop unmatched left rows; schema or dialect unknown → no invented valid SQL. Compare routing with wrong-domain trap and k=1/fixed-k/dynamic-k with actual multi-neighbour fusion; record which neighbour evidence truly influences final query.

**EN→RU / actual translation consumer.** "Do not delete it unless approved." GOOD: preserves prohibition and approval condition, e.g. "Не удаляйте его без разрешения." BAD: "Удалите, если разрешения нет"; WHY: reverses the safety law. EDGE: ambiguous approval owner, mixed RU→EN direction, protected paths/numerals; ask for context or abstain, never silently flip polarity. Compare raw BPE-only against domain-aware semantic features with same source/budget; LoRA weights do not equal semantic-token codebook.

These are model teaching instructions. DO NOT put them verbatim in the sealed holdout or call published examples blinded.

## 4. Focused verification: which tests are actually necessary?

- READ_ONLY audit, hypothesis, RAG traversal, exam precommit, review, handoff: **zero new product tests**. Output source ledger, decision and falsifier, not percent of coverage.
- Existing correct code: **REUSE_NO_CHANGE**, zero new tests; an existing relevant runnable probe may be reused to substantiate the assertion if needed.
- Change to exact pair/material: check assessed raw UTF-8 side hashes == trainer-consumed sides; response mask excludes prompt/pad and includes last answer token; invalid/overflow stops BEFORE mutation. One compact targeted probe can exercise multiple invariants if observable. No synthetic 146-assertion campaign.
- Change to objective/LoRA: check sign, active key allowlist, frozen reference/base and one genuine project-LoRA delta; refusal must not mutate. If existing code already proves correctness, do not rebuild.
- Change to rights/replay/rollback: focused denial, consumed-pair journal unknown-state reconciliation and cold checkpoint readback. No retry when optimizer effect outcome unknown.
- Learned ability: paired actual user-like cases from frozen source-disjoint families. Record grading by independent domain expert/rubric, practical effect and uncertainty; do not turn varied answer wording into deterministic expected-string assertions.
- Required runtime/release/branch/provenance protections remain in scope only when the associated operation happens; a missing permission is a STOP/BLOCKED_AUTHORITY, not something to fabricate or bypass.

**Non-negotiable C0:** If code was repaired, evaluate corrected pipeline WITHOUT training. Only C0→T estimates the effect of the DPO update. Do not call P→T (software fix+training confounded) a learning gain.
