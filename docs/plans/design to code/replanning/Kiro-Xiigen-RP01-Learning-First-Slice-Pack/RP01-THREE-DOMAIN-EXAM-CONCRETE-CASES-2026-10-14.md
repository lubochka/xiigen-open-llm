# RP01 — executable law-grounded cases across C#, SQL and EN→RU

**2026-10-14 · SCIENTIFIC DESIGN EXAMPLES, NOT TRAINING OR ACTUAL EXAM RESULTS.** Use with [five executable work orders](RP01-FIVE-EXECUTOR-WORK-ORDERS-2026-10-14.md), existing [full domain passports](RP01-MULTIDOMAIN-EXAM-CARDS-2026-10-14.md), [learning examination](LEARNING-EXAMINATION.md) and R13/R21/R22. Examples below teach the examiner the required case structure. **Never copy these published examples into the sealed holdout and then claim it was blind.** Actual train/dev/sealed records must be newly sourced, source-family-disjoint, lawful and held in an authorized evidence store.

## 1. Two types of evidence, not a test-coverage campaign

**Deterministic mechanism smoke** is justified ONLY when its relevant code changes: (a) exact x/y byte and response-mask identity, (b) DPO sign and trainable LoRA allowlist, (c) grants/replay/checkpoint recoverability. Read-only / NO_CHANGE means zero new tests. Native deployment security/release rules remain binding where truly applicable.

**Non-deterministic learning examination** runs real tasks by family, with independent adjudication and paired actual outputs. One selected judged DPO pair or optimizer loss decrease proves neither learning nor generalization. Each real exam record needs domain-law/version, source provenance/right, independent family identity, actual end-user intent, available legal paths, chosen path and its cost, expected meaning/constraints, severity for errors, legitimate uncertainty, real ordinary consumer, P/C0/T outcome and matched PC cost. If actual consumer does not exist, use NOT_SUPPORTED rather than a simulated answer called product improvement.

**First-milestone order:** C# full precommit + one Student lesson; SQL and EN→RU **parallel nonblocking shadow** passports. RP02 then validates the domain mapper/semantic tokens/adaptive kNN on actual consumers. Neither all seven domain certifications nor RP03/04 graph training blocks the first Student DPO update. Broader bulk-by-bulk trials must follow the first valid measurement, not delay it.

## 2. Concrete exam case cards (published SEMANTIC EXAMPLES ONLY)

| Domain/law family | User-like request or input | GOOD answer / valid path | BAD answer and WHY | Edge / examiner action |
|---|---|---|---|---|

| Mixed C#/SQL | 'Explain SQL NULL and then give the Russian instruction' | Detect two domains, preserve both sets of laws or explicitly hand off | Force single C# tokenizer and label the whole task C# | Test domain routing separately from actual DPO Student skill |
| Novel/unclassified | Domain not in manifest or legality unknown | UNSUPPORTED/ABSTAIN with explanation and required context | Confident wrong-domain generation | Include unsupported in numerator/denominator by preregistered policy |

## 4. Algorithm ownership and falsification — deterministic + learned must interact

| Component | Deterministic side / constraints | Learned mutable state & real consumer | Causal arms and what would disprove benefit |
|---|---|---|---|
| Student DPO (RP01) | versioned exact source admission, response mask, frozen ref, one-use journal, lawful lesson | **actual existing project-LoRA** in ordinary CodeDocumentation generation | P original; C0 corrected no update; T corrected one update. No changed eligible adapter or no measured C0→T improvement => no claimed learning |
| Domain mapper (RP02) | domain manifest/version, allowed types, known unknowns | learned domain classification consumed by real router | oracle domain vs predicted vs wrong-domain decoys; score lawful downstream solution, not label accuracy alone |
| Vector tokenization (RP02/RP18) | raw text BPE ≠ typed AST features ≠ embedding/vector token ≠ LoRA weights; preserve reversibility/version/provenance | domain codebook / projection / learned feature weighting with typed consumers | raw vs domain-aware features at equal budget, reindex/version held constant; semantic collision or incompatible decoder falsifies benefit |
| Dynamic kNN (RP02) | source/license partition, candidate legality, exact index and hard-law veto; never infer k from coverage | domain- and query-dependent k, metric, weighting/reranking and **real multi-neighbour aggregation** | fixed k=1 vs fixed k>1 vs dynamic k at equal source/cost; first-hit-only consumer disproves multi-neighbour claim; ANN measured separately |
| ILearningUnit many→many (RP03) | typed input schema and output result collection; law-constrained shapes | unit mapping weights / result ranker | frozen deterministic baseline vs unit update on lawful outputs, consumer of **many** results |
| ILearningFlow correction (RP03) | typed legal links between units and preserving input/output contracts | mutable correction/relation policy | freeze Unit, vary Flow; if only Unit changes, no Flow gain attribution |
| ILearningOrchestrator (RP04) | async budget, cancellation, rights, no hidden side effects | learned path and scheduling policy | same eligible paths deterministic vs learned under equal PC budget; count all attempted branches |
| ILearningDynamicGraph (RP04) | typed higher-order combination, valid dependencies and constraints | learned higher-order patterns | unseen combinations vs frozen lower-order graph; graph size alone not learning |
| Hybrid PC efficiency (RP05+) | enforce hard laws regardless of model, legal fallback and irreversible-effects rules | choose compact trainable memory/policy only where useful | deterministic-only vs learned-only lawful vs hybrid; accuracy, worst-law violations, whole-PC RAM/VRAM/storage/latency including index+adapter+optimizer |

A trained LoRA is NOT automatically a domain semantic token. A vector index hit is NOT DPO learning. A k>1 API whose caller consumes hit[0] is NOT multi-neighbour fusion. An async path returning output without learning policy-state change is NOT demonstrated learning. RP01 records these requirements and hands them to existing owners; it **does not implement** E2–E4 before E1.

## 5. Bulk-to-bulk and cost evaluation (after first observed E1)

Pre-register R13 minimum evidence, useful effect, critical-law veto, worst-domain retention and PC budget. For each *new* bulk, log: unique proposed/admitted/applied/accepted/reverted DPO pairs, actual model+LoRA/checkpoint identities, source-family overlap, domain-route confusion, P/C0/T paired correctness on independent families, critical-error count, path regret to lawful oracle, abstention precision, worst previously learned domain, full time per useful correction, RAM/VRAM (whole process peak, do not sum asynchronous peaks), disk model+LoRA+optimizer+index+cache+journal, all paid/failed calls, cold-start/restore time. Confidence interval and p95 only with statistically meaningful N; otherwise mark exploratory, never invent significance. One new lesson applied once is a first learning *experiment*, not statistically proven cross-domain improvement.

**Verdicts:** IMPROVE only on precommitted lawful end-task gain with acceptable regression/resources; REGRESS; INCONCLUSIVE; INVALID_EVIDENCE (leak/confound/wrong consumer); NO_TRAINING_NEEDED; NOT_MEASURED. If invalid/negative retain old accepted parent; plan next bounded lesson or code seam. Sufficient fixed deterministic solution is a valid win: do not force stochastic learning when it wastes PC resources.

**Формулы:** `lawful_accuracy = lawful_correct / eligible`; `critical_wrong_law_rate = critical_wrong_law / eligible`; `DPO_pair_effect = accuracy(T)-accuracy(C0)`; `full_PC_efficiency = lawful_correct / all_wall_seconds` со стоимостью failed calls, training/index memory and persistence reported independently. Статистическая неопределённость — по независимым origin families; маленькое N даёт PILOT/INCONCLUSIVE, не выдуманные 95%.

**Bulk после реального E1:** B0 → B1 → B2, в каждом уникальная admitted x/y+/y− пара и separate optimizer receipt, evaluate **new** unseen families + fixed old-family retention on actual consumers; compare improvements per bulk with cost growth, replay/poisoning and cross-domain interference. Запрет: training на SEALED, duplicate pair via new UUID, auto-promote on one loss number, assume external model call happened just because README says so.

**GOOD + почему:** SQL mapper маркирует `IS NULL` и нужный dialect, C# mapper отдельно маркирует `?.`, mixed request разделяется по законным путям; adaptive k реально объединяет 3 lawful hits and improves consumer answer under matched cost. Это проверяет правильное применение domain laws и реальный механизм.

**BAD + почему:** «k=3» в config, но `hits[0]` — единственный использованный neighbour; четыре зеленых unit-теста при ухудшении holdout объявлены успешным обучением. Это проверяет только fixture и параметр, не изменённую способность.

**EDGE / resolution:** unknown SQL dialect => clarify/abstain; EN→RU direction ambiguity => explicit direction; duplicate ANN id => repair identity ledger before measuring; domain-law version drift => quarantine old embedding/rebind version; teacher receives sealed prompt => `INVALID_EVIDENCE`, regenerate a disjoint panel; cold process picks old checkpoint => `NOT_ADOPTED` with exact caller; OOM/budget-confounded arm => `INCONCLUSIVE` and preserve parent.
