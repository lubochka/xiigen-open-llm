| 3 | Д-02, Д-03: старый hashed/truncated whole-sequence objective сменился exact BPE и суммой response likelihood | Подтверждено; нынешняя версия лучше сохраняет материал. Старые и новые margin/accuracy несопоставимы без восстановления их определений. Влияние длины на полезность — проверяемая гипотеза. |
| 4 | Д-01: отличаются модель, reference и область разрешённых параметров | В [25](25-historical-neural-learning-donor.md) найден реальный исторический head-only update; нынешний RP01 обновляет q/v-LoRA при frozen head. Причинный вклад места адаптации ещё не отделён от базы, tokenizer и учебного сигнала. |
| 5 | И-01: v309 сообщал высокую accuracy, но четыре сохранённых checkpoint одинаковы | Подтверждено файлами и историческим отсутствием backward. Это узкий дефект конкретного старого прогона, а не отрицание всех исторических успешных обучений. |

Дополнительный поиск соседних веток дал три конкретные цепочки в [09](09-domain-functions-and-sibling-branches.md): неперенесённый морфологический канал; сохранённую доменную память E13B, которая правильно завершает знакомые формулы и отказывается от неизвестных; изменение восстановления памяти с истории домена на corpus, привязанный к манифесту. Это разные домены и consumers. E13B не потерян в коде, но его вызов из RP01 не найден. Для morphology положительный runtime-результат пока не найден; для restore не найден парный quality-run.

Следующий первичный участок [10](10-historical-function-transfer-and-learning.md) нашёл ещё два конкретных разрыва. В E40V2 учебная память семи признаков дала сохранённые 21/21 validation, но первый production TrustScorer заменил её фиксированной суммой. В E38 план требовал ScoreForKnn при выборе кандидатов; функция создана, однако найденный orchestration path пишет только metadata после выбора flow. E35, напротив, имеет реального перенесённого consumer, ограниченного flag/route evidence. Эти результаты относятся к доверию источникам, выбору скилов и порядку веток; их влияние на RP01 generation ещё не доказано.

У нынешнего RP01 подтверждено изменение всех 16 разрешённых LoRA-тензоров, неизменность базы и восстановление состояния. Однако на прочитанных маленьких панелях полезный свободный ответ не появился: C# 0/3 → 0/3, EN→RU 0/4 → 0/4. Это сохранённые исторические результаты, не новый запуск. Небольшое движение likelihood не заменяет смысловую правильность ответа.

Новые первичные цепочки уточнили, где именно искать отличие:

- **Учебный сигнал:** все 500 C# пар имеют одинаковое начало обеих сторон. В суммарной DPO-цели общий token-prefix при одинаковом conditioning сокращается; прямое обучение выбора хорошего продолжения не равно обучению начать связный ответ. Это гипотеза недостаточного сигнала, а не доказанный нулевой gradient — [14](14-data-quality-and-evaluation-alignment.md).
- **Потеря памяти при переходе между процессами:** E18 реально обучается и публикуется. Но прочитанный session loader не восстанавливает его classifier из descriptor; отдельная память используется при следующем Train. Это конкретный разрыв для domain routing, не ошибка восстановления Student — [20](20-domain-routing-positive-mechanism.md).
- **Замена признаков:** полезный старый E26 использовал соседний POS-контекст; нынешняя память слова адресуется по word/concept и запасному surface key. Наличие имени E26 в комментарии не означает перенос той же функции — [17](17-positive-pos-knn-versus-production-rules.md), [23](23-language-context-and-learned-rule-scope.md).
- **Неверная интерпретация старого отрицательного опыта:** E29 не сравнивал хорошие и плохие текстовые ответы DPO; V2 обучал переходы между перемешанными predicates. Его нулевой прирост не отвергает нынешнюю DPO-гипотезу — [24](24-e29-pair-value-and-probe-objective.md).
- **Смысл обучающего вектора не доходит до optimizer отдельными координатами:** текущий RP01 сводит его к числу активных значений и весу пары. AdamW дополнительно ограничивает эффект общего масштаба; относительные веса нескольких пар всё ещё могут менять направление обучения — [30](30-teaching-vector-adamw-and-current-recipient.md).
- **Неверно определённый объект памяти:** E30 сохранял один вектор файла для разных переходов, не включая текущий предикат. Это подтверждает конкретную потерю условия; отрицательный результат этого cache нельзя переносить на любой kNN — [32](32-e30-lost-transition-context-and-historical-comparison.md).

Уточнение Любы о переносе ошибочно оценённого механизма «из матрицы в функцию kNN» принято как главный исторический вопрос. Найдены связанные первичные документы, интеграционные commits и реальные функции. Точный experiment ID и полная цепочка именно этого воспоминания пока не установлены; выдавать найденный E34 или перенос проекта 21 → 18 за окончательный ответ было бы подменой.

## Следующий исследовательский шаг

В `language_translate`/`external_domains` адресно просмотрены morphology, E13B и restore; затем по первичному integration plan прослежены E35/E38V2/E40V2 до результатов, git и consumers — 09/10. Открытый главный вопрос — точный матричный механизм, ставший полезной функцией kNN. Ни E40-аппроксимация, ни E38 score-gap, ни E23 без прямой исторической связи не объявлены тем самым donor. Участок12 сузил подозрения по актуальному Student: простого обхода LoRA/первого response-target/legacy EOS в этом пути не найдено. Пакеты14,20,25 получены от `/root/rp01_diff_investigation_astra`; родитель прочитал их. В25 найдены реальные изменения neural head и узкий preference-сигнал. Продолживший поиск единственный `/root/rp01_code_trace_astra` вернул28 и36; теперь ему поручен архив19 мая. Родитель проверяет выводы и обновляет общие документы. Промежуточные пакеты не завершают исследование. Проекты опытов не исполняются.

Для проверки более сильного предположения «раньше работало именно полезное нейронное обучение» нужен конкретный сохранённый донор: исходный checkpoint, обновлённый checkpoint, одна и та же evaluation-панель и реально вызванный consumer. v309 с одинаковыми сохранёнными весами не подходит на роль такого донора. Другие исторические успехи этим не исключены.

Полного аудита всех веток, всех корпусов и всех доменных функций здесь нет. Отсутствие функции в прочитанном маршруте RP01 не означает отсутствие в репозитории. Условные минимальные исправления описаны рядом с находками; код по ним не менялся.
