Главная точка входа — [`00-START-HERE.md`](<C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/00-START-HERE.md>), текущая очередь — [`execution-queue.json`](<C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/execution-queue.json>). В ней 162 потока; пакет описывает 119 карточек и 728 активных публичных эталонов. Номер в исторической очереди не назначает следующий запуск. Первый назначенный поток — `TR07-OMISSION`, профиль `ru-en`, партия 10 строк.

Роли закреплены в [`10-CODEX-AND-CHINESE-ROLES.md`](<C:/Users/lubao/Documents/xiigen/llm mvp/learning-sets/preparation/10-CODEX-AND-CHINESE-ROLES.md>):

1. CODEX выбирает одну тему, профиль, objective, источники и семейства. Это отдельное решение, связанное с конкретным `request.json`; обзор данной папки его не заменяет.
2. Kiro использует фактически выбранную пользователем китайскую модель для создания кандидатов. Её реальное имя сохраняется; имя модели оценщика нельзя подставлять в `generator_model`.
3. CODEX независимо решает задания из слепого A/B-пакета. Ему не передают ключ предпочтения и авторское объяснение правильной стороны. Профиль проверяющего, указанный в пакете как `astra 6 ultracode`, подтверждается доступной конфигурацией, а не вымышленным названием или квитанцией от генератора.
4. Содержательная оценка и необходимые языковые/исполняемые доказательства предшествуют `validate → audit → merge → compose → export`.
5. Экспорт остаётся обменным форматом. Он не доказывает совместимость с native learner, обучение Student или улучшение модели. Это отдельный последующий этап.

`prepare` только собирает запрос, prompt и шаблоны. Он не вызывает китайскую модель или CODEX. Сохранённые квитанции и хеши обеспечивают связь артефактов; пакет прямо признаёт, что это не аутентификация личности модели со стороны провайдера.

## По чему проверять первую фактическую партию Kiro

Это критерии будущего чтения результатов, не поручение запускать дополнительные модели или обучение в этой сессии.

| Проверка | Достаточное свидетельство | Что не считается достаточным |
|---|---|---|
| Выполнено нужное задание | `request.json`, выбранный objective/profile, назначенные семейства и исходный prompt; связанное решение выбора материала | Заголовок темы без точного задания; успешный запуск `prepare` |
| Генерация действительно состоялась | Сохранённый ответ выбранной китайской модели, фактическое имя и связь с запросом | Авторские reference, переименованные в generated; заполнение шаблона `PENDING` догадками |
| Предпочтение осмысленно | Все необходимые условия видны в prompt; `chosen` удовлетворяет им; у `rejected` конкретный существенный дефект; независимый A/B-review с причиной | JSON без синтаксических ошибок; перестановка сторон; ответ, верный только благодаря скрытой metadata |
| Набор измеряет нужный навык | Один objective и профиль, назначенные положительные/отрицательные классы и противоположные контекстные случаи там, где это требует карточка | Постоянный ответ «уточнить» или «ждать»; одноклассовый набор вместо назначенных контролей; незаметная смена задачи |
| Выборки независимы | Происхождение сценария и его производных сохранено; переводы, опечатки и переформулировки одного сценария остаются в одном split; публичные эталоны не выданы за закрытый EXAM | Только новые `pair_id` или разные строки текста; ошибочное объединение всех независимых сцен с общей лексемой |
| Доказательство подходит домену | Для переводов — фактический языковой разбор пары; для `code.*` — требуемая проверка обоих кандидатов на одинаковых входах и версии; для `docs.*` — подходящее доказательство факта по действующему контракту | `passed=true` без связанного подтверждения; source citation вместо необходимой проверки поведения кода |
| Сохранена действительная история | Связанные raw/draft/review/release, исправления с происхождением, отчёт о принятых и отклонённых строках | Замена ошибочного исходника успешной версией без истории; объявление всей партии хорошей по одному примеру |

Для первой партии из 10 строк содержательный разбор должен охватить каждую пару. Это не даёт права назвать качественными будущие тысячи строк: контроль применяется к очередной фактической партии и её артефактам. Качество данных и наличие измеренного учебного эффекта остаются разными выводами.

Ожидание работы Kiro также проверяется по фактам: существующий handle и состояние конкретного процесса, затем завершение и фактические результаты. Early yield не равен отказу; обещание будущего уведомления не равно завершению. Дублирующий запуск, бесконечное чтение пустого файла и посторонняя работа «пока ждём» не заменяют ожидание.
