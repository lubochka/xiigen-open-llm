# E30: память теряла условие перехода; V2 проверяла уже другую задачу

Дата: 2026-10-16. READ_ONLY_RESEARCH. Первичная сверка новых helper-отчётов N26 по core `259c61769c3c`. Никакие алгоритмы E30, proxy или эксперименты здесь не исполнялись.

## Подтверждённая ошибка постановки учебного объекта

В [E30PredicateCache.cs](../../../35.ExperimentsV2/Experiments/E30PredicateCache.cs), строки 91–102, из каждого исходного C# файла извлекается последовательность предикатов. Для **всего файла** строится один вектор; затем он прикрепляется к каждому переходу `(Current, Next)`.

При заполнении памяти (`:43–45`) сохраняются только `(Vec, Next)`. При попадании в кэш (`:50–56`) текущий предикат не используется. Он учитывается лишь в запасной bigram-модели при отсутствии подходящего соседства (`:60–61`).

Это конкретный случай, когда система обучается ответу, потеряв необходимую часть вопроса. Для условной последовательности A→B→C два перехода получают одинаковый адрес V, но разные ожидаемые ответы B и C. Выбор по V не может различить эти две ситуации. Пример следует из построения данных; его runtime-воспроизведение не выполнялось, частота таких конфликтов в старом корпусе не подсчитана.

В [PredicateCache.cs](../../../35.ExperimentsV2/Infrastructure/PredicateCache.cs), строки 33–41, вектор содержит частоты 22 предикатов; позиции перехода и текущего предиката в нём нет. `Lookup :21–30` меняет выбранный ответ только при строго большем cosine. При точном равенстве остаётся первая запись. Значит, добавление корректирующей записи не гарантирует её использования.

Этот fallback тоже влияет на смысл итоговой accuracy.

Дополнительная поправка к чтению source: комментарий V2 `:26–28` обещает нулевые векторы для всех natural-language строк и отсутствие попаданий. **Сохранённый отчёт содержит шесть baseline hits.** Поэтому комментарий нельзя выдавать за факт старого запуска. Исходники и артефакт не содержат здесь полной аттестации исполнявшегося бинарника; противоречие нужно сохранить, а не устранить придуманным объяснением.

## Связь с нынешним продуктом

Адресный `git grep` по tracked C# нашёл `new PredicateCache` только в самом E30. Это не доказывает отсутствие любого альтернативного consumer, но не даёт связи с нынешним RP01. Проверка помощниками других веток здесь не объявляется нашим повторным полным сравнением этих веток.

Вывод применим как архитектурная гипотеза: для предсказания перехода адрес памяти должен сохранять условие перехода, а не только похожесть целого документа. Из него не следует запрет kNN, доказанная полезность word-Jaccard или необходимость заменить всё нейронной сетью.

## Небольшой будущий эксперимент

Для одной фиксированной C# панели сравнить прежний адрес `FileVector` и адрес с дополнительным `Current`, сохранив тот же корпус, threshold, tie-policy и fallback. Отдельным опытом исследовать порядок конфликтующих записей. Считать правильность следующего предиката, качество только среди попаданий, долю отказов и случаи, где cache испортил правильный bigram-ответ. Не менять одновременно task на английскую классификацию.

Сначала можно искать сохранённую пару таких runs. Если её нет, будущий запуск требует отдельного пользовательского поручения. Сейчас выполнена только source/raw сверка. Точный исторический случай «неудачная матрица → успешная функция kNN» по-прежнему не локализован; E30 им не объявляется.
