## 4. Почему SFT H16 нельзя просто выдать за native DPO parent

[RepositoryOwnedModelCheckpointManifest.cs:34](C:/Projects/llm_mvp_core/14.ContinuousLearning/Training/RepositoryOwnedModelCheckpointManifest.cs:34) определяет DPO identity как manifest набора, поставившего preference rows. Публичный publisher не может переключить обученный SFT state в initial baseline.

`ValidateRequest :823–846` требует корректные lineage/runtime/provenance и настоящий sealed DPO dataset. `:997–1029`: недостаточно JSON с совпавшим hash; native DPO reader повторно проверяет каждый pair-файл и соответствие domain/design/version. Сфабрикованный manifest, test placeholder hashes или произвольный неиспользованный DPO набор не дают честного происхождения H16 SFT.

H16 не запрещён самим размером. [StartService:354](C:/Projects/llm_mvp_core/26.TrainableRouter/Training/CodeDocumentationRepositoryOwnedModelCheckpointStartService.cs:354) проверяет supported domain/pattern, конструктивный ModelConfig, совместимость и cold-start policy, а не требует H512. `LoadIntoFreshModel :421–474` валидирует payload с точным config и LoRA. Значит ограничение — **отсутствующий truthful SFT→native lineage contract/provenance bundle**, а не доказанная невозможность H16-тензоров в native loader.

Изоляция предусмотрена native layout: [RepositoryOwnedTrainingArtifactLayout.cs:1328](C:/Projects/llm_mvp_core/14.ContinuousLearning/Training/RepositoryOwnedTrainingArtifactLayout.cs:1328) требует абсолютный существующий normal root без reparse traversal; `:1366–1379` — sentinels `LlmFromScratch.sln`, `14.ContinuousLearning/`, `11.DPO/`. В будущем это должно быть реальное частное repo-shaped дерево A/B, не canonical `C:/Projects/llm_mvp_core/training-artifacts/models`. [Loader:129](C:/Projects/llm_mvp_core/14.ContinuousLearning/Training/RepositoryOwnedModelCheckpointLoader.cs:129) вызывает clone custody preparer: native START не следует считать безусловно read-only операцией. Сейчас его не вызывали даже для проверки совместимости.

**Точный gap карточки `PARENT-CONTINUATION-01` (не runnable recipe):** автору требуется выбрать и определить одно из двух разных исследований: (а) native DPO candidate с настоящими sealed dataset, parent/trial/optimizer/RNG/baseline/quality/lease доказательствами; (б) отдельный truthful SFT adoption schema/adapter, который native reader и writer действительно поддерживают. Последний не найден в рассмотренных model checkpoint owner API. Existing H16 SFT файл не назначается DPO candidate; обратное утверждение требовало бы новой реализации и её отдельной авторизации. Недостающие входы нельзя поручать искать runtime исполнителю.

Для полной будущей карточки ещё нужны author-assigned private root/host/source closure/entry command; точный model/tokenizer snapshot и шесть настоящих fingerprints; genuine training provenance; lawful caller/capability; исходный native parent и допустимый source attempt bundle; конкретные acceptance/readout/call budgets. В этом evidence **нет выдуманной CLI и нет обещания, что host существует**. Не требуется новое обучение ради формального пункта: после появления честно допущенного trained candidate можно отдельно сравнивать native parent selection на одинаковых данных и learned state, но это иной готовый протокол.

Поэтому report `:35`, `:53`, `:61` завышает доказательство, когда близость соседних loss объявляет побайтной проверкой моментов.
