**Не смешивать попытки и факторы.** У attempt2 исправленные weighted A/B дали12/16 и совпали actual в16/16. У attempt3 сравниваются native equal-weight arm и отдельно названный repeated-row mechanism control: оба дали12/16, но actual отличаются в6/16. Это три разных утверждения: равный score, равный actual и совпадающий фактор. Их хранить отдельными полями. `assigned_arm_b_executed_here=false` остаётся явным; repeated-row контроль не становится реализацией gradient weight10. В таблицу каждого вывода включить attempt ID, фактор, источник learner, model-visible input, знаменатель и набор row IDs.

**Сохранить выполненное исправление конечности.** Current `DecideComparison` проверяет обе руки и связывает численную пригодность с hypothesis,exit,problems. Старую запись об открытом finite gate не переносить в новый список неисправностей без source-diff. Независимый пересчёт сохранённого attempt3 даёт constant ceiling6/16 и input-only ceiling12/16. По каждому равному score показывать retained/gained/lost rows, чтобы изменения внутри конфликтующих input classes не исчезали.

**Завершение набора проверок удостоверяет внешний запуск.** `report.md`, написанный из первого Fact, не удостоверяет завершение остальных Facts или внешний exit. Удалить из нового generated report литеральное «пройдено2из2, код0» как утверждение о всём test run; вместо него писать `test_suite_terminal=NOT_OBSERVED_BY_THIS_FACT`. Завершивший тот же запуск внешний collector добавляет discovery IDs, фактические passed/failed/skipped и process exit, связанные с source/assembly/run identity. Не записывать число найденных методов как число исполненных. Ранний failure после записи частичного report не должен оставлять suite-success.

**Различающий контроль приёмки.** Сохранить healthy finite positive и отдельную порчу одного блока любого плеча. Дополнительно принудительно оборвать последующий Fact либо финальный acceptance после report: итоговый внешний документ обязан сообщить failed/incomplete, сохранив частичные числа.
