# P49 — виденный вход, новая цель и реальная цена. Дополнение 11.11.2026

Связано с `P49-probe-warm-start.md`, верхним уточнением09.11 и проверками `P49-OVERLAP-AND-RETENTION`, `P49-WARM-COST-AND-GRADIENT-GATE`. Core `009bf226174441fa0fbf0336e74ad2f2b7174d92`. Исторический attempt2 не переписывается; source closure и сохранённое наблюдение различаются.

**Current closure.** Упомянутый в верхнем уточнении finite gate attempt2 уже реализован в attempt3 через `FinitenessGovernedVerdict.DecideFinitenessGoverned`: любая неfinite рука лишает всё сравнение пригодности. Новый аудит подтвердил эту связь по коду и сохранённым NaN-controls, но свежего native PASS не получал.

**Три категории вместо одного overlap.** Каждая EXAM строка классифицируется относительно фактической обучающей истории конкретного плеча: (1) seen input и seen exact input-target pair; (2) seen input, но target pair новая; (3) unseen input. Категории взаимоисключающие и в сумме дают всю EXAM. Сравнение pair equality не используется для вывода input novelty. На сохранённой панели cold имеет2+1+1: e-t1(0→1) предъявляет знакомый0 с новой целью, e-t2(2→3) — единственный невиденный input. Warm имеет4+0+0. Формулировка «остальные два — настоящий незнакомый вход» исправляется датированной поправкой к report, без изменения raw.

**Ожидаемый negative берётся из входов.** Существующий sensitivity пример1→5 не является unseen: warm TRAIN содержит1→0. Он остаётся полезным контролем «знакомый вход, новая цель». Отдельный unseen пример обязан иметь input, отсутствующий во всех реально предъявленных TRAIN этого плеча. Перестановка только gold при неизменном input не меняет счёт input novelty. Empty panel не проходит как100% exact replay.

**Цена и польза.** Сохраняются new-material6/8→7/8 и warm retention6/6→3/6. Cold получил60 updates, warm600+60; total720. Основные64 readouts и32 negative-control readouts показаны раздельно. Один конечный score не измеряет скорость обучения, совпавший warm hash не отменяет стоимость подготовки. Кривую dose-response и новый независимый EXAM назначать отдельным будущим рецептом; для исправления сегодняшнего overlap достаточно read-only пересчёта.

**Приёмка.** На сохранённых row-level данных независимый evaluator получает input overlap3/4 и exact-pair2/4 у cold,4/4 и4/4 у warm; generated prose выводится из трёх счётчиков. Native проверка helper отдельно ловит ошибочное слово unseen для known-input/new-target, не проверяет только наличие строки «незнакомые входы». Writer, JSON и человекочитаемый отчёт сохраняют один смысл величин.
