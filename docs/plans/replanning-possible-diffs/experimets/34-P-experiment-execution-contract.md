## Обучение, эталон и сравнение

Модель исполнителя — текущая настроенная по умолчанию, без самостоятельного override. Обучаемая модель — **конкретный native learner карточки**, не внешний языковой сервис и не выдуманный checkpoint. Для дискретной памяти сохранённое S0 — сама обученная таблица/индекс с tokenizer/config; это не LoRA и не нейронный optimizer. Для neural continuation нужны именно назначенные weights, optimizer и RNG; weights-only загрузку нельзя назвать полноценным продолжением.

Каждый паспорт содержит буквальные TRAIN/EXAM либо конкретный существующий fixture, A/B, независимый gold и finite calls. Общие компактные наборы: [35](35-P-fixture-packs.md); состав набора не меняется исполнителем. Перед вмешательством в уже приобретённый навык проверить его на назначенном learned panel. Один квалифицированный S0 может быть восстановлен независимо в A/B; повторная подготовка ради нового hash запрещена. Если нужны разные shapes, согласование функций и подготовку задаёт соответствующий паспорт, а не этот общий текст.

Измерять предсказания до обучения, после реального обучения и после фактора отдельно. **0→0 без выученного навыка не подтверждает полезность обучения**, даже если поменялся loss или размер файла. Уточнение Любы27октября отменяет исключение reader-only: **каждая новая PRIMARY-программа включает реальный Train/update**, связанный с диагностируемым механизмом. S0 — старт ограниченного продолжения, не замена этому участку. Точные рецепты десяти прежде нулевых паспортов —[36](36-diagnostic-learning-programmes.md); произвольный один шаг ради галочки запрещён. Механическая проверка без этой цепочки не является завершённым PRIMARY. KNN memory/BPE fit — настоящее обучение соответствующего learner, даже если neural updates=0. Нулевая контрольная рука admission допустима при реально обучающейся другой руке, а нулевая вся программа — нет. Остальные правила[30](30-failure-recovery-and-learning-validity.md) обязательны.

Если API не создаёт пустую модель, cold до Train — явное отсутствие обученного экземпляра (`NO_TRAINED_UNIT`) в экспериментальном H. Это наблюдение инфраструктуры, не предсказание модели, не ошибка обучения и не выдуманный вызов пустого learner. Например, `KnnLogicalUnit.Train(empty)` возвращает `TRAINING_EXAMPLES_REQUIRED`. В бюджетах отдельно считать cold observations, реальные native queries и updates; общий лимит наблюдений не повышать. После Train обязательно измерить actual output. Если native API допускает cold instance, использовать именно её реальный ответ. Не обходить private constructor и не создавать stub, возвращающий gold.

Любое измеренное улучшение полезной оси — успех этой оси и данного домена. Показывать gained/lost cases, качество старого навыка, ложные принятия/отказы, bytes/allocations/time отдельно; не скрывать регрессию средним. Constant-label контроль нужен для классификаторов; разные классы одной задачи допустимы, разные предметные темы в TRAIN не смешиваются. Эталон не извлекать из actual ответа проверяемой модели.

Отчёт R/report.md на русском: один абзац гипотезы, фактические before/A/B и контроль, таблица всех полезных показателей и ухудшений, ограничения по домену, ссылки на raw, точные original file/method и кандидат исправления. Отдельные execution_status, learning_validity, hypothesis_status. Удачный валидный эффект зарегистрировать в required-changes.md при обычном завершении; никаких автоматических product changes, CI, коммитов или пуша из факта успеха опыта. Навыки: `docs/skills/experiment-design-SKILL.md`, `architect-behavior-classifier-SKILL.md`, `plan-review-SKILL.md`, `prompt-patch-authoring-SKILL.md`, `output-readability-gate-SKILL.md`. Сначала применимый контракт, затем эксперимент; это не требование перелистывать все skills на каждом шаге.

## Проверка рецепта перед первым model call

Проверить в указанных исходниках доступность API, точную сигнатуру DTO и реальное поведение A. Private/internal API не становится публичным от упоминания в карточке; применять назначенный experimental adapter, не менять доступность продукта. Искусственно сломанное A обозначать абляцией, а не текущим native поведением. Штатный fallback исполнять и записывать как настоящий fallback, не переименовывать в no-hit.

Проследить все побочные записи learner: например, один Translation TrainOnExample пишет full/prefix/structure ключи. Fixture обязан сохранять назначенный контраст после этих записей. Controlled keys, injected faults и новые bridge явно помечать; их результат не распространять на ordinary Flow без отдельного предусмотренного readout. Учитывать стоимость подготовки S0 и его восстановления; кэш или immutable state не заменять незаявленным повторным Train. Если source опровергает рецепт, зафиксировать точное несовпадение, не придумывать новый опыт для получения PASS.
