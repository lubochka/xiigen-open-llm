## Обязательные правила для карточки и любого её промпта

**Найти tool и дождаться своей операции — обязанность исполнителя.** До выдачи команды прочитать [контракт31](../31-tool-discovery-and-wait.md) и указанные там реальные skills/references; по каталогу текущей среды найти launch и wait/resume/status, прочитать их схему и сохранить provider, handle, start time, H/R и deadline. Не выдумывать Kiro API по Codex-примеру, не просить пользователя выбирать инструмент или запускать команду вместо исполнителя.

**Ожидание не равно бесполезному polling.** Одна выдача entry; затем штатный bounded wait/resume того же session/cell/process ID до terminal exit или исходного experiment deadline. Нормальный wait можно повторять при silent/running. Два быстрых неблокирующих чтения без прогресса требуют перейти в wait; если он неисправен/ответы противоречат — независимое чтение H/R/claim/exit и своего PID+start. Не вводить Start-Sleep в занятый терминал. Предел одного ожидания≤60с — не предел эксперимента; yield/RPC timeout не доказывает exit/kill/нулевой расход. После диагностики живой процесс продолжают ждать. Отсутствие log не доказывает, что запуска не было. Не выдавать entry заново «синхронно на25минут», не подбирать results-NN, не удалять claim/partial, не сокращать TRAIN/steps до двух минут ради tool. При UNKNOWN сохранять неизвестный расход и разбирать существующий запуск. STOP/NEXT Любы немедленны.

**Без действительного обучения задача не выполнена.** До исполнения в рецепте должны быть точные original файл/метод, learner→изменённое состояние→consumer, TRAIN/EXAM, назначенный before и конечный бюджет достаточного учебного набора. Для retention/restore требовать показанный навык до вмешательства; для acquisition допустим cold start с проверкой приобретённого поведения. Updates, loss, hash и случайный верный токен сами по себе не доказывают навык; частичное token learning не объявлять целым ответом/правилом. Unit/BPE обязаны действительно обучать память/правила и читать полученное состояние. Restore/consumer допускает доказанно обученный артефакт без повторного обучения ради счётчика.

**0 → 0, отсутствие обучения или неполное A/B — не завершение эксперимента.** Раздельно записать execution_status, learning_validity и hypothesis_status; при невалидности учебная цель OPEN. Сохранить сырые свидетельства и продолжить разрешённое исправление постановки, а не только написать «невалидно» и отчитаться об успехе. Не искать другой checkpoint/модель/host, не менять seed/фактор, не увеличивать steps до PASS: точный исправленный рецепт назначает автор карточки до новой попытки. Старые опыты не удалять. Поздняя ошибка сохранения не обнуляет состоявшиеся updates; неизвестное число — null, невыполненное плечо — «не измерено».

Любое полезное измеренное улучшение в **валидном учебном сравнении** — успех своей метрики/домена; рост accuracy необязателен, регрессии рядом. Диагностика невалидной постановки не закрывает учебную цель. Default-модель исполнителя без override; точные H/R/entry ниже. Отчёт — русский R/report.md. Текущая правка документов не разрешает runtime. Прямые STOP/NEXT Любы немедленны и при открытой цели.

Полный конечный порядок диагностики и критерии: [контракт30](../30-failure-recovery-and-learning-validity.md). При конфликте со старым текстом ниже действует этот блок.

**Порядок выполнения — только [единый индекс экспериментов](../cards/00-execution-index.md).** Там указаны номер, приоритет, конкретная карточка и следующий шаг. «Второй» означает строку №02, а не выдуманный N-KU-02. Этот README и следующие разделы объясняют материал, не предлагают исполнителю самостоятельно выбирать очередной опыт.

**Обновление 20.10: [N60 — маленькие изменения обучения](23-additions-n60-small-learning.md).** В одном документе собраны проверки SFT-маски, состояния AdamW, вычисления пустого хвоста DPO и порядка DPO/SFT; отдельно — учебная метка C# do-цикла, выбор следующих уроков перевода и запись правил Verifier. Для каждого указаны данные, один изменяемый механизм, получатель, бюджет и ещё не выполненная подготовка. Это планы, а не результаты запусков.

**Исполнитель сам готовит опыт.** Люба не обязана называть ID, путь, SHA или лично заполнять паспорт. При прямом разрешении ограниченной программы исполнитель открывает карточку по следующему номеру единого индекса, наследует разрешение и готовит обычные входы. `NEEDS_INPUT` / `OPEN` означает незавершённую подготовку с названным следующим действием, а не доказанное препятствие и не просьбу к Любе предоставить команду. `BLOCKED` требует конкретной неудачной попытки получить необходимый недоступный ресурс. Существенный выход за поручение требует уточнения. Документный запрос сам по себе запусков не разрешает: **этот проход ограничен чтением и Markdown**.

**Последнее уточнение Любы: учебная цепь включает действия до и после Train.** Если результат обучения зависит от загрузки данных/checkpoint или использования обученного состояния, такая проверка допустима. В карточке нужны provenance состояния, конкретный файл и метод неисправного звена, точечное изменение и одинаковый материал до/после. Restore или consumer-проверка уже обученного состояния не обязана повторно учить модель; она проверяет сохранность или использование приобретённого умения. Новое обучение заявляется только при настоящей операции обучения. Исключаются лишь проверки, подтверждённо не связанные с обучением ни до, ни после него. Пока связь не исследована, это задача подготовки trace, а не основание исключения; декоративные Train не добавляются. Старые широкие исключения serving/cold/report подлежат этой адресной проверке, а не считаются окончательным запретом всего класса.

**Любое фактически измеренное полезное улучшение — успех по показателю и предметной теме:** время, CPU, RAM/VRAM, усилия, число уроков/обновлений, размер состояния, слои модели, Unit/Flow, точность и другие полезные величины. Рост точности не обязателен. Остальные изменения и ухудшения показываются рядом; неизмеренная ось не приравнивается к нулю. Для сравнения нужны сопоставимая работа и измеритель; изменения объёма работы из-за выбранного фактора фиксируются отдельно. Исправление измерителя — успех достоверности, но смена подписи сама по себе не ускоряет вычисление. Нулевой эффект действительно достигнутой операции обучения допустим.

Паспорта сохраняют исходный запрос, модель исполнителя и Student, навыки, данные, ожидаемые наблюдения и расходы. Отсутствие повторного личного согласования версии не является самостоятельным препятствием. Неизвестные поля заполняет исполнитель в пределах разрешённой программы; они не превращаются в установленные факты от одного заполнения таблицы.
