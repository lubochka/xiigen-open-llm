## 1. Вопрос, receiver и единственный фактор

Вопрос: сохраняет ли cap256 полноту выбора непересекающихся выученных spans на восьми словах; исправляет ли полный ограниченный обход потерю первого слова?

Тема обучения — перевод, профиль EN_RU/general. Настоящий learner — `TranslationMachine.TrainStructuredBatchAsync → ExecutorUnit.TrainOnExample`; обучается дискретная phrase/exact/KNN память, без нейронных весов. ## 2. Почему число путей проверяемо

Продуктовый [AddPhraseMapping:756–760](../../../../../27.TranslationDomain/TranslationTrainedUnits.cs) пишет одно значение по нормализованному source key. [Native Train:404–456](../../../../../27.TranslationDomain/TranslationTrainedUnits.cs) при WordMappings=null не создаёт word/surface mappings. Однословные PhraseMappings допустимы: это phrase edges, а не дополнительная независимая word option.

[TranslationSemanticTokenizer.Tokenize:98–110](../../../../../27.TranslationDomain/TranslationSemanticTokenizer.cs) сохраняет отдельный token для каждого слова, split по пробелу. [NormalizeMapKey:1008–1022](../../../../../27.TranslationDomain/TranslationTrainedUnits.cs) для выбранных ASCII words только приводит case/пробелы к canonical виду; ни одно слово не исчезает и разные span keys не сливаются. Эти свойства всё равно проверяются подготовительным guard на текущем коде, не предполагаются после будущих изменений.

При одном target на каждый возможный span и отсутствии других ветвящихся вариантов:

`F(0)=1; F(n)=F(n-1)+Σ(F(n-l), l=1..n)`.

Skip и singleton phrase — **две разные ветви**, уже учтённые в формуле. Значения F(0..8):1,2,5,13,34,89,233,610,1597. Это верхняя граница для данного класса графа при n≤8, не универсальная оценка для любых языковых вариантов/словарей. Cap2048 достаточен только после проверки однозначности normalized span и отсутствия дополнительных alternatives.

На длинной панели ниже из позиции0 доступны только skip и phrase[0..1]. Суффикс positions1..7 содержит все28 contiguous spans. Поэтому **полный обход имеет точно F(7)+F(6)=610+233=843 листа**. A сначала целиком пытается `Walk(1)` и достигает cap256 внутри этого суффикса; ни один сохранённый путь A не включает phrase[0..1]. B способен покрыть8/8, выбрав этот prefix и phrase[2..7]. На коротком положительном контроле полных путей F(2)+F(1)=5+2=7.

843/7 и правильные ответы B — **аналитические ожидания, ещё не измеренные результаты**. Если runtime shape отличается, опыт возвращает INVALID_GRAPH_SHAPE; не менять слова, нормализацию, cap или oracle для получения желаемого числа.
