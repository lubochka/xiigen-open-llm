## 1. Что проверяем

Дополнительный конструктор обучаемой модели получает уже обученное состояние и `array of function principles` для слоя KNN. Каждая функция оценивает пригодность **выученного кандидата**, например по синтаксическим предшественникам или смысловому времени. Ответ по-прежнему берётся из обученной памяти. Проверяем функции отдельно и совместно, а затем сохраняем/восстанавливаем ту же модель с теми же функциями.

Три предметные темы: C#/.NET, продолжение текста на естественном языке, оркестрация. Пять начальных профилей: `CS`, `EN`, `RU`, `HE`, `OR`. EN/RU/HE — профили языковой темы, не утверждение о трёх независимых архитектурных доменах. Контракт позволяет добавить иной профиль с собственным массивом и собственным набором; данный бюджет покрывает только эти пять.

## 3. Контракт дополнительного конструктора

Следующий C# — **проект API**, этих типов пока нет:

```csharp
DomainKnnLearningModel(LearnedDomainState state); // прежнее ранжирование
DomainKnnLearningModel(
    LearnedDomainState state,
    IReadOnlyList<IKnnPrinciple> principles); // принимает и IKnnPrinciple[]

interface IKnnPrinciple {
    PrincipleDescriptor Descriptor { get; } // id, version, profile, scope, weight
    PrincipleScore Evaluate(QueryContext query, LearnedCandidate candidate,
                            ReadOnlyPrincipleState learnedState);
}
// PrincipleScore: Applicable + Value [-1,+1] + краткие наблюдаемые основания.
```

1. Конструктор копирует массив; элементы — неизменяемые функции с отдельным read-only state. Повтор ID, NaN, отрицательный вес или чужой профиль — ошибка до получения ответа/обучения. Неприменимость — Value=0 с `Applicable=false`, а не успех проверки. Отсутствие AST/временного условия не является отрицательным gold.
2. Функция видит только пользовательский запрос, доступный префикс, кандидата из TRAIN и назначенное обученное состояние. Запрещены EXAM expected, номер строки, скрытый будущий токен, rationale проверяющего, системное время и внешняя сеть. Функция не пишет ответ и не добавляет кандидата. Детерминированный разбор допустим; его вклад называется предметным prior, а не выученным знанием.
3. `S(q,c)=S_native(q,c)+0.20*sum(w_i*f_i(q,c))`. Веса в данном опыте равные `1/m`, m — число назначенных функций плеча. Неприменимые функции остаются нулевыми, веса остальных не перенормируются. Пустой массив вызывает исходное ранжирование без нового округления. При равенстве — исходный Ordinal ExampleId; порядок массива не должен менять ответ. Это выбранная постановка, не уже доказанные оптимальные коэффициенты.
4. В одиночном плече функция получает весь дополнительный бюджет .20; в совместном он делится. Поэтому сравнение «совместно против одиночной» не доказывает синергию. Для синергии нужна отдельная карточка с одинаковыми индивидуальными весами. В текущей карточке цель — полезность назначенного массива.
5. В S0/S1 сохраняются веса frozen encoder, tokenizer, примеры и их порядок, векторы, конфигурация индекса, состояние функций, ID/версии/профиль/веса. Делегаты не сериализуются: ограниченный каталог `id+version -> implementation` восстанавливает функции. Unknown version даёт явную ошибку; тихая подмена пустым массивом запрещена. Constructor не вызывает Train и не переинициализирует загруженные веса.
6. `Learn(lesson)` явно меняет память и TRAIN-статистики; неизменяемые вычислительные функции остаются прежними. Это проверка обучения памяти Unit. LoRA/DPO-обучение весов, изменение архитектуры нейросети и генерация полного кода здесь не заявляются.

Математическая граница выбранного смешивания: при `sum(w)=1` и `f∈[−1,1]` добавка кандидату лежит в `[−.20,+.20]`; разность двух добавок — в `[−.40,+.40]`. Поэтому исходный отрыв строго больше .40 эта настройка перевернуть не может. Это вывод из формулы, **не доказательство улучшения**. Сумма предметных score не обязана быть метрикой с неравенством треугольника: она применяется после неизменённого поиска, а не тайно заменяет расстояние HNSW. Итоговый score и прежний confidence не являются калиброванной вероятностью.

Для структурного сходства использовать `Value=2*similarity-1` при наличии признаков с обеих сторон; пустые/неполные признаки дают неприменимость. **Точный causal AST recipe:** cursor — UTF-16 длина исходного code-prefix. Разобрать `prefix + "\n__KDP_CURSOR__();"` без дописывания правильного токена/ответа и без ручного закрытия скобок. Найти identifier marker по его span; для ancestor-path взять первые три ancestor kinds, у которых `SpanStart < cursor`, исключив созданные marker InvocationExpression/ExpressionStatement и recovery nodes без реальных prefix tokens. Отсутствующие закрывающие tokens имеют zero width и не являются признаками. If/Else роль определяется предком позиции, не ожидаемым ответом. Для обоих ordered признаков `similarity=LCS(a,b)/max(length(a),length(b))`. Для predecessors сначала собрать prefix tokens со `Span.End<=cursor`, исключая только **вложенные** local-function/lambda bodies, не содержащие позицию marker; активное method/local-function body с cursor сохраняется. Это важно: snippet без class-wrapper может быть top-level local function, его тело нельзя целиком исключать. Взять последние4 оставшихся tokens. Отдельно последние2 завершённых sibling statement kinds текущего блока, без вложенных local/lambda declarations. Сходство predecessors — среднее двух доступных LCS-отношений; если доступна лишь одна часть, берётся она и coverage фиксируется. Ни parser diagnostics, ни искусственный marker не превращаются в label. Тот же recipe применяется к TRAIN input кандидата, без его Output.

**Время и токенизация фраз:** sentence для time-frame — последнее предложение prefix, содержащее курсор, после последнего `.`, `?` или `!`; предложения до него не голосуют за время. Phrase lookup: Unicode NFC, invariant lowercase, слова как последовательности Unicode letters с combining marks; внешняя пунктуация разделяет слова, отрицания/служебные слова не удаляются. Истинные тексты и Output сохраняются исходными. EN construction хранит контексты, оканчивающиеся `look forward to` / `would like to`; связь с формой продолжения получается только из TRAIN. Несколько конфликтующих temporal cues в текущем предложении дают неприменимость, а не выбор первого.

**Явная связь с событием — ограниченное исключение к предыдущему предложению:** recognize `[the|that] <event> [ended|finished] before now.` и `During that <event> <subject>` в текущем prefix, где event — `shift` или `job`. Только при совпадении event и отсутствии отрицания переносится отношение `target_action during event; event ended before now` → past interval. Это вывод из видимых отношений времени, не наличие слова yesterday. Сопоставление с past-кандидатом даёт +1, с habitual −1; без явной связи прошлое предложение игнорируется. T02 и E02 EN назначены именно на этот контраст. Данная функция не читает ожидаемую глагольную форму; расширение beyond этих конструкций требует другого набора.

«Популярная фраза» в этом маленьком опыте означает **частую в зафиксированном TRAIN**. Не утверждать популярность во всём языке. Проверка настоящего частотного корпуса потребует отдельно назначенного корпуса и другого бюджета. Редкая подходящая фраза не объявляется ошибочной лишь из-за малой частоты.

## 5. Данные и обученный старт

Точный минимальный набор находится в [KDP01-fixtures](KNN-DOMAIN-PRINCIPLES-01-fixtures.md). Он не заменяет большие learning-sets и не даёт их смысловой приёмки. Каждый профиль имеет S0:4 урока, T+:4 урока и EXAM:8 запросов. TRAIN одной темы не смешивается с другой. Внутри темы сохранены конкурирующие ответы и контроли.

Будущий отдельный producer один раз создаёт S0 и S1 каждого профиля. Frozen encoder: Vocab512, Context64, Hidden16, Layers1, Heads4, KvHeads2, FF32, стандартные Rope/RMS. Размер соответствует маленькому существующему [тестовому получателю](C:/Projects/llm_mvp_core/tests/DpcDomainClassifierLogicalUnitTests.cs:182); этот тест здесь не запускался. Tokenizer.Train получает только восемь S0+T+ **входов** данного профиля, vocab320; это заранее известный TRAIN vocabulary, не EXAM. Веса encoder создаются один раз и сохраняются до чтения EXAM; во всех плечах загружаются те же bytes. Их нейронная обученность не заявляется: обученная часть этого опыта — KNN-память, состояния функций и, во втором опыте, router.

Последовательность: EMPTY → вставить S01…S04 через native Train/Add → S0 → вставить T01…T04 в том же порядке → S1. При подготовке новой памяти можно использовать Train(S0) и Train(S0+T+) как native batch replacement, но счёт distinct lessons остаётся4/8, а физический повтор embedding/reindex входит в стоимость. При наличии совместимого сохранённого bundle producer не запускается вновь. `Restore`/reindex не выдаётся за новое обучение.

До первого Train wrapper допускает явное EMPTY-state и возвращает `NO_LEARNED_EXAMPLES`; native Train с пустым списком сейчас отказывает, поэтому его успешный вызов на EMPTY не выдумывать. EMPTY — отрицательный контроль, не обученная модель. В обычных S0/S1 используется штатная непустая native memory.

Обязательная квалификация: на EMPTY ответы отсутствуют; S0 правильно воспроизводит все четыре своих **различных** урока. S1 воспроизводит T+; приобретение хотя бы одного нового точного ответа на T+ против S0 фиксируется отдельно. Если этого нет, нет доказанного нового учебного выигрыша данной дозы; нельзя заменять его margin в тысячных. Нулевой результат на основной панели до и после не закрывает цель. Нет автоматического подбора другого набора, LR, скрытого pretrain или дополнительных уроков.

Exact recall — квалификация записи, не EXAM обобщение. Все 8 EXAM запросов назначены до запуска; IDs/expected и признаки evaluator не входят в model input. Разделение по здесь заданным шаблонам слабое: это ограниченный механический пилот с перефразировками, не оценка новых реальных семейств или языковой компетентности.

## 6. Плечи, причинность и бюджет

Для CS/RU/HE/OR: `A=[]`, `B1=[f1]`, `B2=[f2]`, `B12=[f1,f2]`. Для EN: `A=[]`, `B1=[time]`, `B2=[construction]`, `B3=[prefix]`, `B123=[time,construction,prefix]`. Всего21 плечо; порядок фиксирован A, B1, B2, B3 если есть, All. Нет автоматического перебора других весов/порядков/моделей.

Каждое плечо читает копии одного S0/S1 своего профиля и отвечает на те же8 EXAM. Для каждой строки показать `A0,A1,B0,B1`, итоговый эффект `B1−A1`, собственный учебный сдвиг `B1−B0` и взаимодействие `(B1−B0)−(A1−A0)`. Эффект уже в S0 при нулевом дополнительном учебном сдвиге — польза чтения обученной памяти, а не ускоренное усвоение T+.

`ScoreCandidates` получает **один и тот же сохранённый список кандидатов и базовых score для всех плеч одного запроса/состояния**. Native `_index.Search(topK=exampleCount)` не гарантирует полноту графового поиска. Сохранить список фактически найденных IDs и проверять наличие конкурентов. Функция не может вернуть исключённого кандидата. Exhaustive поиск нельзя включить только в B; если нужен отдельный полный поиск, это новая одинаковая A/B-постановка, не молчаливый ремонт текущей.

В обычном Embed уже действует ограничение первых64 токенов: [EmbeddingModel:79](C:/Projects/llm_mvp_core/05.Embeddings/EmbeddingModel.cs:79). На фактически выполненной токенизации записать total token count, реальные видимые IDs/декодированный prefix и факт наличия cursor-контекста; не делать дополнительный Forward ради trace. Функции могут читать полный видимый пользователю input — тогда выигрыш при обрезанном encoder input так и назвать. Он не доказывает восстановление знаний в нейронных весах. Лимит embedding не менять только для B.

Основной лимит: 21×8×2=336 сравнительных ответов; дополнительно 5×4 EMPTY, 5×4 S0 recall, **5×4 ответов S0 на будущие T+ до update**, 5×4 S1 recall тех же T+. Последние две панели позволяют проверить приобретение ответа на новом уроке, а не сопоставлять разные строки. Для отделения оболочки от native — исходный конструктор на 5×8 запросах S0: должен совпасть с A уже измеренной панели. Для восстановления — 5×8 повторных ответов All/S1 после fresh load; совпадают с ранее сохранёнными. Итого до496 логических ответов, 40 distinct memory lessons. Embedding может быть общим для одинакового query/state, но полную цену общего вычисления не вычитать из эксплуатационного времени B.

Функциональные проверки API (пустой массив, перестановка массива, чужой профиль, неизвестная версия) используют уже полученные score/state без новых model calls. Проверка удаления памяти: 5 EMPTY-панелей уже выше; функции не могут выдавать код/перевод/подэтап сами. Данные/статистики частот по EXAM не обновляются.

Будущий wall cap: подготовка и сборка≤10мин, producer≤10мин, измерения≤10мин, отчёт≤5мин, общий35мин. Это лимит постановки, не измеренный прогноз. Нельзя уменьшать TRAIN/EXAM ради короткого timeout. При исчерпании сохранить partial и известный расход; не делать rerun под другим result-ID.

## 7. Что считать успехом

Любое измеренное улучшение полезного показателя — успех **этого показателя и профиля**; рост accuracy не обязателен. Показывать рядом ухудшения: exact целого ответа, семантическое время, полярность, естественность продолжения по заданному reference, нарушение prerequisites, ошибки на редких конструкциях, latency/CPU/allocations/размер состояния. Снижение loss/margin без приобретённого ненулевого полезного ответа не заменяет учебную цель.

Для переноса в общий default этой микропанели назначен строгий контроль: ни одной новой смысловой ошибки в E05–E08; не ухудшать правильные ответы основного профиля. При нарушении полезный локальный эффект сохраняется в отчёте, но universal/default перенос не предлагается. Ресурсную цену показывать числом, не объявлять любое увеличение CPU запретом. Ускорение по единичному cold run — наблюдение, не доказанная устойчивая экономия.

Ошибки отличать: gold неоднозначен; нужного кандидата нет в памяти; кандидат исключён index; функция неприменима; функция предпочла неправильного кандидата; неверный restore. Исполнитель не «чинит» EXAM после просмотра B и не удаляет неудачный профиль из отчёта.
