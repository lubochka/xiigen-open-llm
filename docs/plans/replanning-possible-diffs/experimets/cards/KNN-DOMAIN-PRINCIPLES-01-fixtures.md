## Правила материализации

* Идентификатор `<profile>/<row>`. Порядок S01,S02,S03,S04,T01,T02,T03,T04; EXAM по номеру. Никакого shuffle/генерации исполнителем. Таблицы назначают Text и Output; назначенные служебные поля ниже добавляются одинаково для всех плеч. Метка столбца Output не входит в Text.
* Input для языка: строка `Задание: <задача>. Префикс: <prefix>`; продолжить только суффикс, без повторения prefix. Выбирается один из четырёх известных суффиксов профиля; это ограниченная retrieval-задача, не свободная генерация. Не заявлять, что выбранная фраза единственная возможная во всём языке. `QueryContext` отделяет instruction от prefix, сохраняя отрицания/регистр/знаки в prefix. Частотная функция работает с prefix, а не с русской инструкцией.
* Семейства: CS-return/throw, CS-async, CS-iterator; language-tense, language-construction по языку; OR-server, OR-test. В таблице S/T/E могут быть родственные шаблоны — вывод только о данном контролируемом переносе. Для дальнейшего внешнего EXAM требуются новые семейства; эта карточка их не выдумывает.
* Query/task metadata содержит только факты, явно видимые в Text. Разметка expected, is_control, split и row-id доступна evaluator, не функциям. Функция не получает ручную метку правильного времени/AST ответа вместо извлечения из prefix.
* Ни одна строка большой кампании learning-sets не копируется и не считается принятой этим пилотом. Примеры ниже — авторские контроли малого опыта; они не входят в её квоту.

## CS: следующий лексический keyword в C#-префиксе

Text=`Контракт: <контракт>\nC# prefix: <код>`. Курсор сразу после последнего символа code; ответ — **keyword/keyword sequence**, не `%200` AST ID. Классы S0: return, throw, await, yield return по1; S1 по2. `yield return` считается одним ответом из двух токенов. Префиксы могут быть синтаксически незавершёнными; суффикс с правильным ответом нельзя добавлять перед извлечением AST.

| ID | Контракт | Код до курсора | Output |
|---|---|---|---|
| S01 | Ветка ok немедленно возвращает число1; остальные ветки не рассматриваем. | `int F(bool ok) { if (ok) {` | `return` |
| S02 | Ветка bad немедленно бросает исключение; остальные ветки не рассматриваем. | `int F(bool bad) { if (bad) {` | `throw` |
| S03 | Асинхронный метод должен дождаться операции; продолжение после ключевого слова будет WorkAsync(); | `async Task F() {` | `await` |
| S04 | Итератор должен выдать следующий элемент без завершения перечисления; продолжение будет 1; | `IEnumerable<int> F() {` | `yield return` |
| T01 | Ветка else немедленно возвращает число2; if уже обработан. | `int G(bool bad) { if (bad) { throw new Exception(); } else {` | `return` |
| T02 | Ветка else немедленно бросает исключение; if уже обработан. | `int G(bool ok) { if (ok) { return 1; } else {` | `throw` |
| T03 | После локальной функции внешний async-метод должен дождаться операции WorkAsync(); локальная функция не вызывается. | `async Task G() { int Local() { return 2; }` | `await` |
| T04 | После local-функции внешний итератор должен выдать элемент2; local не вызывается. | `IEnumerable<int> G() { int Local() { return 2; }` | `yield return` |
| E01 | Ветка else немедленно возвращает число3; if уже обработан. | `int H(bool bad) { if (bad) { throw new Exception(); } else {` | `return` |
| E02 | Ветка else немедленно бросает исключение; if уже обработан. | `int H(bool ok) { if (ok) { return 3; } else {` | `throw` |
| E03 | Внешний async-метод ждёт WorkAsync(); local не вызывается. | `async Task H() { int Local() { return 3; }` | `await` |
| E04 | Внешний итератор выдаёт элемент3; local не вызывается. | `IEnumerable<int> H() { int Local() { return 3; }` | `yield return` |
| E05 | Ветка ok немедленно возвращает число4, а не бросает исключение. | `int J(bool ok) { if (ok) {` | `return` |
| E06 | Ветка bad немедленно бросает исключение, а не возвращает число. | `int J(bool bad) { if (bad) {` | `throw` |
| E07 | Async-метод уже закончил ожидание; сейчас должен немедленно завершиться без значения. | `async Task J() { await WorkAsync();` | `return` |
| E08 | Итератор уже выдал элемент; сейчас обязан бросить исключение. | `IEnumerable<int> J() { yield return 1;` | `throw` |

E07/E08 проверяют, что частый шаблон «async→await / iterator→yield» не превращён в ответ независимо от контракта. Семантический контракт оставлен базовому native retrieval; AST-функция не читает Output. Снижение качества на этих строках — существенная доменная регрессия.

## EN: форма по времени, конструкция и продолжение фразы

Задачи `work`: «Продолжи предложением с глаголом work в simple tense и точкой»; `hear`: «Продолжи с hear from you и точкой, согласуя форму с префиксом». Допустимые ответы: `works.`, `worked.`, `hear from you.`, `hearing from you.`. Для названных субъектов время/конструкция выбирает нужный из этих вариантов; другие глаголы не являются альтернативными gold.

Простое bag-of-cues по всему тексту не считается правильной реализацией этой функции. E05 сохраняет отрицание в исходном prefix; это проверка устойчивости выбора суффикса, не доказательство способности переводить отрицания.

Здесь разрешено читать предыдущее предложение **по явной ссылке на тот же event**, как задано в карточке. В E07/E08 такой ссылки нет. Это не претензия на универсальное понимание времён/аспекта английского.
