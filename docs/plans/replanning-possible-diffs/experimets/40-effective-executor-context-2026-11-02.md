## 3. Оценщик должен проверять то, что обещано

Калибровочные примеры и фактические ответы проходят через один callable с теми же options. Сравнение заранее записанных boolean не проверяет рабочую функцию. Для P102 `Trim()==gold` в калибровке и `StartsWith(gold)` в результате оказались разными правилами.

| Пример для gold «20; y получает старое x» | Ожидаемый результат |
|---|---|
| Канонический верный ответ | Exact=true; semantic=true |
| Верный пересказ «It prints 20 because y receives the value of x before x is incremented.» | Exact=false; semantic=true в объявленной поддерживаемой рубрике |
| Верный gold + «It actually writes 21 and y gets the new value.» | Semantic=false: противоречие обязательно проверяется |
| 120 вместо20; либо20 с объяснением new value | Semantic=false; совпадение подстроки не помогает |
| Пустой, оборванный или неподдерживаемый текст | Отдельные EMPTY/TRUNCATED/UNJUDGEABLE; не скрывать из знаменателя |

Для небольшой панели допустим детерминированный разбор заранее объявленных смысловых признаков/формулировок. Не выдавать его за универсальную оценку произвольного языка. Независимый человек может дать рубрику сохранённым ответам, но это отдельный метод, не исполнение исправленного C# scorer. Exact text, семантика и полнота остаются разными полями.

До модели проверить вместимость назначенной canonical последовательности в decoder budget с действующим tokenizer. Если gold47 при cap46, полный canonical gate не откалиброван. Это не доказывает невозможность иной более короткой токенизации. Изменение cap после результата требует отдельного ограниченного задания; старые условия и raw сохраняются. | Update уже выдан или S1 сохранён, упал report | Восстановить чтение/отчёт от точного S1; additional Train=0 | Начать PRIMARY сначала ради зелёного exit |
| Контроль ловит ошибку A, но не B | Принять чувствительность только для этого пути; проверить обычного потребителя | Подменить native path копией без явной границы |
| Научная гипотеза не подтвердилась | Записать отрицательный результат и приобретённые/потерянные строки | Ослабить gold, убрать неудачную строку, добавить уроки до PASS |
| Неработающий scorer, недостижимая ветвь, недопустимые входы | INVALID_MEASUREMENT / NOT_REACHED в нужной части, ремонт именно причины | Объявить отрицательный научный результат или обученную способность |
| Неизвестная стоимость/момент/состояние | Null/UNKNOWN с причиной и планом наблюдения | Записать0 или N/A без доказательства отсутствия |

Логическая попытка имеет одного владельца. Claim создаётся атомарно для exact ID, фиксирует process identity и стадии PRE_MODEL → MODEL_STARTED → UPDATE_ISSUED → STATE_SAVED → READOUT → TERMINAL. Ненулевой exit сам по себе не доказывает PRE_MODEL. После UPDATE_ISSUED неизвестность запрещает автоматический Train; восстановление требует свидетельства стадии. Номер суффикса не разрешает повтор. Build timeout должен управлять конкретным child и подтверждать его завершение; timeout инструмента не равен остановке процесса.

## 5. Что входит в доказательство переноса

Набор прочитанных файлов до сборки не равен потреблённым входам. Для native build сохранять evaluated project instances с effective properties, Compile items, csproj/imports/props/targets и digest фактически прочитанных bytes. Один путь при разных properties — разные instances. Исполнение copied assembly и отдельного Roslyn oracle описывается своим уровнем, без переименования в ordinary native acceptance.

Отдельно фиксировать optimizer calls, effective updates, Forward/Backward, KNN/BPE fits, readouts, retries, builds, wall/CPU, allocated и peak. Счёт по source допустим, если так назван; это не независимый runtime hook. Суммировать можно только совместимые единицы и непересекающиеся окна. Отсутствующие попытки не считать нулевыми.

Изменённые weights не доказывают ненулевой data gradient: AdamW decay способен двигать координату отдельно. Два целевых ответа DPO не исключают градиента остальных logits через softmax. Шаг optimizer не равен fingerprint его моментов. Из этих различий следует предел вывода, а не требование нового обучения ради отчёта.

## 6. Выход исполнителя

Вернуть readable summary, exact source/state hashes, полный список попыток, actual outputs и поимённые gained/lost, определения метрик, результат callable calibration, ordinary consumer evidence и remaining gaps. Для переноса указать source_implemented, component_verified, native_acceptance раздельно. Для исторического исправления — parent attempt, что пересчитано по saved evidence, какие поля не восстановимы. Перед публикацией сверить конкурентные изменения и readback опубликованных bytes. Число файлов и перечисление навыков не являются приёмкой результата.
