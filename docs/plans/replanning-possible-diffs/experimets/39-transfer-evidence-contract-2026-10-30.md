## 1. Утверждение должно иметь потребителя

| Уровень утверждения | Необходимое свидетельство | Чего ещё нельзя заявлять |
|---|---|---|
| Документ/коммит существует | Exact SHA и diff | Исполнение, правильность и польза |
| Native метод исправлен | Положительный и отрицательный контроли на его actual API | Любой другой overload/facade тоже исправлен |
| Обычный путь потребляет механизм | Public request → features → actual member/state → downstream output; controlled intervention | Обобщение вне проверенной панели |
| Есть полезный эффект | Назначенная метрика, независимый gold, контроли, регрессии и цена рядом | Скорость обучения по одной точке; общесистемная accuracy по4 примерам |
| Состояние восстановимо | Полные actual bytes, reader с новым PID и Train0 | Exact continuation без проверки следующего шага |
| Exact continuation | Совпадающий следующий шаг по всем реально потребляемым состояниям | Битовая одинаковость на непроверенных runtime/platform |

Одна строка PASS не поднимает доказательство на следующий уровень. `execution_status`, `learning_validity`, `hypothesis_status`, `consumer_reachability` и `state_recoverability` читаются раздельно из observations. Negative/NO_CONTRAST — допустимый итог исполнения; открытая гипотеза не закрывается переименованием статуса.

## 2. NAMED_CHECK: публичный API, владение и отказ партии

Проверить фактический default overload и каждый wrapper, через который распространяется обещание. Caller-owned features, labels, nested answer collections и returned payload не должны менять принятую память, если контракт объявляет ownership. При отказе новой партии старая модель остаётся доступна. Сначала validate/copy в локальную таблицу, затем publish; valid Train остаётся объявленным replace/append, одно не превращается в другое случайно.

**WRONG:** тестировать `KnownImmutable<MutableDto>()` с явной policy и считать, что старый overload без policy тоже отказывает.

**CORRECT:** вызвать именно старый overload; после successful admission изменить исходный/выданный объект и прочитать ещё раз. Если default требует policy, получить конкретный отказ до construction. Immutable positive control и корректный typed copy должны работать.

**Контроль чувствительности:** временно отключённая копия или публикация до validation заставляет соответствующий negative fixture нарушить инвариант. Такой контроль выполняется локально на fixture, не исправляет production ответ на время теста.

## 3. NAMED_CHECK: одно физическое исполнение и все реальные entry points

Существующий claim не означает умерший процесс. До первого model call каждый entry point использует атомарный admission/consumed-launch с run identity и owner identity. Живой/неизвестный owner сохраняет право на R; второй invocation не удаляет его claim и не пишет scientific outputs. Completed terminal не разрешает полный повтор через файл с удобным именем.

**WRONG:** `status.json` ещё нет → удалить claim → снова Train; либо `run-01/status.json` есть → «continue» с полным повтором.

**CORRECT:** определить фактическую стадию/owner; ждать тот же handle или продолжить только разрешённый недостающий postprocessing из сохранённого state. Новый физический запуск получает собственную lineage и все расходы, если он действительно назначен.

**Приёмка:** concurrent invocations; live/no-status; terminal; unknown owner; corrupted receipt. Только одна сторона достигает learner, другая не меняет чужие bytes. Тест нужен для P50/P52 собственных scripts и других actual callers, а не только shared helper.

Writer output root, launch args, manifest path и terminal указывают на одну попытку. Фактически прочитанные inputs обязательны. Prelaunch сверяет учтённые dependency DLL/deps и evaluated imports; generic helper не исправляет неверно настроенного caller. Native child exit имеет приоритет перед вторичной discovery ошибкой.

## 4. NAMED_CHECK: actual state и свежий reader

Для каждого learner заранее указать тип state и настоящего владельца сериализации. KNN хранит trained tokenizer/encoder, index/table, own outputs, schema/config. Translation сохраняет полный checkpoint, а не hash этого объекта. Neural continuation включает weights, optimizer, RNG, scheduler/data cursor и остальные реально используемые mutable fields. Значение «не применяется» объясняется типом learner; фиктивный AdamW для таблицы не создаётся.

**WRONG:** сохранить lessons+counts+SHA отдельно обученного witness и написать «после сбоя можно продолжить из обученной памяти».

**CORRECT:** writer сохраняет actual bytes до report; завершает процесс; reader с новым PID, без TRAIN sources и с trap на Train загружает state и повторяет панель. Для exact continuation выполняется тот же следующий шаг в обеих ветвях.

**Приёмка:** unchanged bundle проходит; отсутствующая часть/неверная schema/невалидная topology отклоняются до публикации. Different JSON shapes/timing не используются как доказательство model delta. Отсутствующий historical state получает `restorable_state_missing`; рецепт реконструкции не выдаётся за сохранение.

## 5. NAMED_CHECK: правильная производная и неизменённые targets

Все зависимые градиенты используют одно pre-step состояние. Для ProbeNN проверяются embedding, W1 и W2, затем полный one-step vector. Исправление W2 не закрывает dEmbedding, если W1 уже изменён. Sample-weight multiplier проверяется как множитель исходного градиента, а не как произвольное число повторных updates.

**WRONG:** исправить один цикл; поменять заодно targets/LR/order; приписать улучшение исходному фактору.

**CORRECT:** сохранить transition/target identity, сначала проверить derivatives конечными разностями, затем выполнить отдельно назначенное сравнение фактора. Историческое target-confounding остаётся ограничением причины.

NaN — отдельный наблюдаемый исход. Для утверждения о скорости разрушения нужен first-nonfinite-step, а не только число неконечных весов в финале. Корректный градиент и конечные веса ещё не доказывают полезного обучения.

## 6. NAMED_CHECK: независимость по входу самого learner

Сначала зафиксировать schema после всех преобразований. Раздельно посчитать source/file/project overlap, model-input overlap, `(model-input,target)` overlap и family overlap. Source metadata, не переданная модели, не делает вход независимым.

**WRONG:** `f1:0→1` и `t1:0→1`, модель видит0; объявить t1 новой задачей по имени файла.

**CORRECT:** назвать это удержанием известного отображения; для generalization назначить отдельную панель с различимыми model-visible inputs без передачи gold. Если одинаковому входу назначены разные targets, посчитать ceiling по группам: `sum_x max_y count(x,y) / N` для соответствующего readout.

При одинаковом весе обеих конфликтующих сторон оптимальный ответ может не меняться. Перед новым Train показать, что назначенный фактор способен изменить измеряемый выход хотя бы на одном заранее выбранном примере; не выбирать этот пример постфактум по понравившемуся ответу. Constant, rule и given-family baselines сохраняются, когда они объясняют задачу.

Каждый физический process/stage имеет receipt. Суммы `attempt_total` и `parent_total` включают первый проход, повтор и probes. Единицы не смешиваются: fits, lesson presentations, optimizer updates, queries, graphs/node calls, witness fits, время/память. Неизвестное — null/unknown с причиной.

```text
Данные: <что реально видит learner, TRAIN/EXAM/CONTROL, overlap, independent gold>.
Вмешательство: <ровно изменяемая часть>; остальное связано source/fixture hashes.
Состояние: <typed actual bytes, loader, new-process/Train0 или явная неприменимость>.
Расход: <число fits/lessons/updates/queries и границы времени, без смешения единиц>.
Исполнение: <единственный entry, run identity, owner handle, R, terminal policy>.
Приёмка: <positive + negative + public-consumer evidence; фактический test owner>.
Результат: observations → effective evaluator → допустимый claim;
negative/NO_CONTRAST сохраняется, старый Train не повторяется ради отчёта.
```

Незаполненное поле, от которого зависит correctness, требует завершить постановку до запуска. Для обычной правки отчёта/документа неприменимые учебные поля не создают выдуманный барьер. Прямое поручение пользователя и уже выданная авторизация учитываются; этот текст не создаёт повторного запроса разрешения на уже назначенную работу.


## 10. Дополнение 01.11.2026: контроль действительно должен сработать

Основание: [107](../fixes-based-on-experiments/107-transfer-and-experiment-audit-2026-11-01.md), адресная приёмка89 cards в109. Исторический результат не переисполняется только потому, что уточнился проверяющий.

Каждый контроль несёт observed_count, violation_count и status.0 наблюдений означает UNEXERCISED;0 denominator означает UNMEASURED/null. Пустой список нарушений без положительного support не является PASS. Научная назначенная панель, чистый synthetic unit control и reconstructed readings сохраняют разные provenance. Новый контроль измерителя не становится задним числом строкой старой scientific panel.

**Различимость:** постоянная ничья не crossing; одинаковые alpha A/B не treatment; branch с0 hits не improved consumer. Различать наличие доступного runtime context и внесение gold/next во вход. Prompt-only equivalence classes считать после encoding/truncation отдельно от target/mask; уникальность combined pair не доказывает уникальность входа.

**Память и отказ:** valid JSON не равен typed payload. Проверять поздний train/eval/publication failure immediately before repair-fit. Key disambiguation между topics не решает correction authority внутри одного key. Default guards, wrappers и соседние owners учитываются по actual member, а не по общему слову KNN/router.

**Честная формулировка:** sign каждой preference пары, cross-prompt contrast, full-vocabulary answer и acquisition relative to same-row baseline — разные оси. Coverage proxy не обещает retention laws; label0 не кодирует отсутствие ответа; run failure не honest abstention. Любой действительный узкий gain сохраняется с границей и издержками.

## 11. Дополнение после P88 — фактический бюджет, вход и чувствительность

Основание: [аудит113](../fixes-based-on-experiments/113-post88-transfer-and-experiment-audit-2026-11-01.md), [план114](../fixes-based-on-experiments/114-post88-addressed-repair-plan-2026-11-01.md), [53 адресные карточки115](../fixes-based-on-experiments/115-post88-card-hardening-and-coverage-2026-11-01.md). Эти требования уточняют оценку и следующую назначенную работу; старые raw неизменяемы, бюджеты и NEXT сами не увеличиваются.

### 11.1. Каждый настоящий вызов стоит в общем счётчике

P85 объявил1 Train, но copy-faithfulness и production panels довели его до5. Перед первым вызовом host регистрирует все плановые операции и один общий pre-call recorder: main, cold setup, parity, warmup, diagnostics, k/seed/order, restore. Поле `purpose` объясняет расход, но не вычитает его. Различать native Train calls, fits, logical arms, lessons, updates, Predict, Forward, Backward и report-only arithmetic.

Отчёт имеет planned total, actual total по всем attempts и trace операций. При неизвестном значении — null+reason, не0. Tiny fake learner фиксирует6-й вызов сверх лимита5 как отказ до делегирования; report-only reducer не обращается к learner. Дополнительная панель после результата получает ссылку на конкретное изменение задания. Отсутствие ссылки в Git не доказывает отсутствие внешнего разрешения, но не позволяет аттестовать predeclared budget.

### 11.2. Подпись связывает evaluated instance, а не только файл проекта

Замыкание сборки должно учитывать путь проекта вместе с effective global properties, TargetFramework/RuntimeIdentifier и metadata ProjectReference. Один файл с двумя наборами свойств — два экземпляра вычисления. Conditional source/import входит в binding именно там, где его потребляет настоящая сборка. Контроль: Parent с AdditionalProperties включает Conditional.cs, который отсутствует при самостоятельной оценке Child; подпись обязана видеть различие. Unsupported graph даёт явный отказ, а не пустую успешную подпись.

Архив completed terminal сохраняет прошлую попытку, но не разрешает новую учебную. Continuation называет стадию; report repair имеет learner limit0. Существование нового run ID, отсутствие современного claim или старый формат terminal не обнуляют оплаченную работу.

### 11.3. Сохраняется фактически прочитанное представление

Для вывода об обобщении/отсутствии утечки сохранить actual TRAIN/EXAM model-visible vectors или обратимо восстанавливаемые bytes с конкретным codec identity. Метаданные файла, имени класса и позиции не заменяют представление, потребляемое learner. Current и next стороны transition имеют отдельные file/position IDs; target/gold хранится отдельно от query features. Overlap считается после реального усечения/нормировки/кодирования и сопровождается conflicting targets/ceiling.

Если поле не записано, status NOT_RECORDED. Pure reconstruction из неизменённых fixtures допускается с отдельным provenance и0 Train/Predict; она не становится наблюдением старого процесса. P82 показывает missing evidence; P83 —4/4 exact feature overlap при новых именах. Эти два исхода нельзя смешивать.

### 11.4. Тип модели и идентичность её состояния различны

Для KNN/BPE сохранить полный native Manifest, actual corpus/config, детерминированные vocab/merges или поддерживаемую state identity и фактический размер. `BpeTokenizer` — имя класса; оно не устанавливает конкретный обученный словарь. Если штатного exporter нет, поле отмечается unavailable и в плане назначается минимальный exporter; выдуманный hash имени типа запрещён. Новые fits для реконструкции старого missing state не допускаются автоматически.

Cold restore требуется только тому claim, который его обещает: новый PID, actual payload, Train0. Текущий PRIMARY может ограничиваться in-process prototype; отсутствие лишнего restore не является его нарушением. LFS OID доказывает ожидаемый объект, а не доступность и правильность скачанных bytes.

### 11.5. Равенство проверяет только чувствительное семейство

Каждая сохранённая семья state имеет собственные bytes, owner и positive sensitivity control. RNG fingerprint не включает номер optimizer step как будто это случайность; reference не считается чувствительной, если по построению immutable и никогда не затрагивается вмешательством. Статусы: SENSITIVE, VACUOUS, UNMEASURED; denominator содержит только проверенные чувствительные семьи. P87 доказал4, а не6; его ошибочный machine5 исправляется отдельным digest-bound receipt.

Первая достигнутая фаза отказа обязательна. Profile/material refusal до permit доказывает early admission; он не доказывает rollback после partial update. Для late failure нужен отдельный named boundary без отключения действующего guard ради искусственной достижимости.

### 11.6. Согласованность внутренних связей и конечного потребителя

При Load проверять не только диапазоны полей, но и отношения: graph edge на level L ведёт к node, имеющему L; MaxLevel равен реальной максимальной глубине. При retrieval пригодность и logical lesson identity согласованы с ranking/cap. При составном output scalar label и obligation set имеют одну объявленную политику происхождения; consumer исполняет все обязательства, а не первый элемент.

Trace runtime input→actual received digest→selected state/UnitId→output нужен там, где возможна canonical substitution. Наличие trained instance не гарантирует потребления контекста: P88 даёт постоянный ответ при подменённом входе. Prototype Flow, product-source snapshot, linked native component и обычный product endpoint имеют отдельные значения `execution_scope`.

### 11.7. Машинная поправка и работа с файлами

Correction schema содержит target path, original digest, corrected fields, основание и границу. Reader применяет её только к совпавшему target; старые raw остаются историей. Нельзя делить все correct outcomes, включая отказы, на число answered: numerator и denominator принадлежат одной выборке.

Любая пакетная запись выбирает явный перечень путей. Нормализация по маске/рекурсии/признаку «свой» запрещена; binary states никогда не считаются текстом. Для затронутого pinned input проверяются actual bytes/OID до исполнения и публикации. Это не требует добавлять в Git все случайные файлы рабочей области; публикационный diff содержит назначенную работу.

### 11.8. Короткий проверяемый промпт исполнителю

Промпт не задаёт ожидаемые ответы в признаках learner, не разрешает рост дозы ради положительного эффекта и не подменяет пользовательское разрешение новым формальным барьером.

Перед исполнением сохранить machine-readable declared_vs_actual: размер/active_count teaching vector, Signal, objective version, optimizer origin, moments imported, step, RNG и reference owner. ## 12. После P89: исполнение, входы и предел приёмки

Основание — [116](../fixes-based-on-experiments/116-post89-execution-boundary-audit-2026-11-01.md), core c4d05a2. Требования применяются к своему owner и не добавляют neural-проверки там, где достаточно чтения файлов.

1. **Реестр читает свидетельства exact ID.** При публикации terminal/result согласовать Q-строку, вход индекса,00-README и continuation prompt. Отдельно хранить execution, observed learning, hypothesis, source transfer и ordinary consumer. Отсутствие научного выигрыша не возвращает завершённый ID в NOT_RUN. Все failed/partial attempts входят в учёт. Старый alias не закрывает новый stableID.
2. **Начальный hash не гарантирует прочитанные bytes.** Снять весь consumed input inventory: required, optional с состоянием PRESENT/MISSING, extra sources и evaluated project instances. Перепроверить перед child; выбрать immutable snapshot/handle, если чтение позже допускает гонку. Optional означает допустимость начального отсутствия, а не разрешение скрытой подмены. Информационный неиспользуемый файл можно исключить только явным контрактом. Gold связан с evaluator и не становится входом generator.
3. **Эффективный паспорт снимается до первого mutation.** Записать actual vectors/signals, тип и исходный step optimizer, фактически импортированные moments, masks, параметры sampler/monitor, выбранный caller и ревизию, объясняющую отличия от проекта. Нельзя выводить DPOstep400 из metadata SFTдонора. Расхождение без разрешённой ревизии — named refusal до платной работы; старое фактическое измерение сохраняется с правильной границей.
4. **Оракул должен обнаруживать свой отказ.** Качество ответов не заменяет structural admission графа; ранний отказ не доказывает поздний rollback; тождество x=s*(x/s) не является независимой проверкой unscaled sum. Positive control и negative witness проверяют одну названную обязанность. Exit0 harness без проверки exact cases не закрывает приёмку.
5. **У вызова есть вложенная стоимость.** Compile/restore/validation могут обучать зависимость. Ledger содержит parent-child call graph, отдельные Fit/Train/Forward/Backward/Optimizer и реальные процессы/попытки. Сумма вложенных calls не называется числом независимых fits. Failed harness не исчезает; NOT_MEASURED не превращается в 0.
6. **Локальная заметка не удостоверяет remote publication.** Ссылка содержит repository, branch/commit, полный путь, blob digest и область. Совпавший номер документа с другим filename не заменяет отсутствующую цель. Проверка ссылки и сборка/ordinary consumer имеют разные статусы.

Образец будущего точного задания: «На `<source SHA>` исправь `<owner/границу>` по `<check ID>`; сохрани positive fixture и докажи отказ на `<negative witness>`; назови actual caller и observed state before/after, расходы и reached stage. Сначала прочитай сохранённые raw/attempts. Не повторяй PRIMARY ради report. Отчёт заверши отдельно по execution, learning, hypothesis, transfer и consumer, приложи hashes и конкретный незакрытый остаток». Шаблон сам не назначает новую программу или бюджет.
