## Дополнительный условный риск: старые shards в новом наборе

BuildAsync создаёт каталог и записывает `shard_0000.npy`, `shard_0001.npy` и далее; в прочитанном методе нет удаления прежних файлов или атомарной замены manifest. Если первый набор имел больше shards, а следующий записан в тот же каталог с меньшим числом, старшие старые имена могут сохраниться. [DataLoader:33](C:/Projects/llm_mvp_core/02.DatasetPipeline/DataLoader.cs:33) собирает все верхнеуровневые `.npy` и сортирует имена; оставшийся shard тогда становится кандидатом следующего обхода.

Это вывод из композиции методов **при условии повторного использования каталога**, а не наблюдённое загрязнение корпуса RP01. Может смешать домены, версии токенизатора или старый split, если внешний владелец не создаёт чистый каталог. Внешняя подготовка данных и полный существующий набор NPY здесь не исследованы. Для будущей проверки достаточно сопоставить ожидаемый список/хеши shards с реально переданным loader каталогом; воспроизводить обучение для обнаружения примеси необязательно.

## Как уточнить будущую причинную проверку

Предложение остаётся проектом, не разрешением запуска. Для одного домена взять один сохранённый corpus/tokenizer/model state и сначала выбрать **один** фактор, например stride. Отдельно сравнить одинаковое число optimizer updates и одинаковое покрытие исходных позиций: при одинаковых batch/seqLen оба бюджета обычно одновременно не совпадут. Не назвать эти два разных вопроса одним равным бюджетом.

Для границы документа не менять одновременно ID, attention reset и loss-mask без явного признания составного изменения. Для EN→RU измерять отрицание/роль/направление на новых источниках; для C# — различие операторов, условий и результата. Сохранять результаты по доменам: короткому корпусу overlap может помогать, другому — ограничивать охват.

Условие helper «нет градиента embedding — модель фактически не учится» слишком широко. [Исследование detached-путей](56-autograd-reachability-and-sft-caller-controls.md) отделяет недоступность конкретного параметра от обучения остальных слоёв. Будущий контроль должен подтвердить изменение параметров, необходимых именно его гипотезе; отсутствие одного градиента не обнуляет автоматически всё обучение. Старые инструкции helper о роли внешнего автора не меняют действующие указания пользователя о simulation и нынешней исследовательской фазе.

Открытый первичный след: какой инструмент фактически создал NPY для конкретного положительного pretraining, какой tokenizer и список shards были переданы runner. Без этого нельзя привязать найденные свойства к падению RP01 или объявить будущую замену stride исправлением качества.
