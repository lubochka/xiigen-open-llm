## Что стало понятнее после свежей проверки

1. **Полезное обучение в истории действительно есть, но успехи принадлежат разным механизмам.** В E48 на промежуточном бюджете N56 сохранён рост примерно 14% → 34%, хотя итоговая оценка помечена FAIL. В E43 сохранён рост точности на старых примерах 0,3226 → 0,3978. Первый пример — обучение небольшой сети с дополнительными исходными примерами, второй — новый частотный словарь с добавлением старых примеров. Ни один автоматически не доказывает качество нынешнего LoRA Student. [37](37-new-helper-findings-data-history-and-language.md), [36](36-helper27-state-replay-and-quality-review.md).

2. **Наличие перенесённого кода ещё не означает его использование.** E09 перенесён в production-класс, но включается флагом, который по умолчанию false. В пределах tracked C# поиск нашёл обучение, включение и чтение predictions только в Tests. Это конкретный путь возможной утраты полезного механизма; внешние/untracked callers данным поиском не исключены. [38](38-e09-transfer-labels-and-opt-in-consumer.md).

3. **Часть показателей измеряет не то, что обещает название.** Batch029 создаёт heldOutBatch, но UnitAccuracyAfter берёт из training result. Отдельная product-heldout проверка при этом существует и не аннулируется этим замечанием. Другой Unit scorer проверяет verifier на отрицательных примерах и использует новый base tokenizer с языком ru вместо trained tokenizer и языка обычного запроса. [36](36-helper27-state-replay-and-quality-review.md).

4. **Правила могут сохраняться в объекте и всё же не попадать в ключ поиска.** RuleTags остаются в sequence, но исчезают из двух lookup signatures, тогда как training формирует ключи иначе. Это уже более точная гипотеза, чем «грамматику удалили». Ранние exact/word/phrase пути могут скрывать эффект. [23](23-language-context-and-learned-rule-scope.md).

5. **Нужно проверять сами эталоны будущих опытов.** В polarity-fixture команда Start the process сопоставлена с Процесс запущен. Для обычного перевода это смена модальности, а не правильный ответ. Такая пара допустима только в отдельно определённой задаче подтверждения результата. Иначе опыт сможет наградить семантическую ошибку. [36](36-helper27-state-replay-and-quality-review.md), [37](37-new-helper-findings-data-history-and-language.md).

6. **Несколько сильных формулировок помощников пришлось сузить.** Cache alias требует живого retained cache, а не полного process crash. Readiness reset не стирает learned memory. Отличие replay DPO/KNN не доказывает forgetting: parent checkpoint выбирается отдельно. Повторяющиеся шаблоны внутри batch не доказывают нарушение frozen Main500: требование стратификации найдено в комментарии, тогда как сохранённое разрешение MAIN сохраняет порядок. [36](36-helper27-state-replay-and-quality-review.md), [37](37-new-helper-findings-data-history-and-language.md).

## Как читать покрытие

- **Код/история:** адресные участки первичного source, caller/consumer и, где есть, сохранённые результаты. Причинный эффект на качество остаётся будущей экспериментальной проверкой.
- **Проект опыта:** рассмотрены гипотеза, различающий фактор, результат и ограничения. Полная исполнимость каждой команды не аттестована; разрешения на запуск нет.
- **Fixture:** JSON прочитан, структура и предметные примеры рассмотрены. Все авторские gold labels не объявлены независимо правильными.
- **Чужой proxy-result / proxy-код:** сохранённый JSON и текст скрипта прочитаны. Скрипты не запускались; результат не приписывается native XIIGEN или нашему исполнению.
- **Сводка/индекс:** утверждения привязаны к отдельным разборам; повторная упаковка не считается независимым evidence.

Большие сводки проверялись адресно по утверждениям, таблицам и ссылкам. Это не построчная аттестация каждого абзаца всех 52 Markdown.
