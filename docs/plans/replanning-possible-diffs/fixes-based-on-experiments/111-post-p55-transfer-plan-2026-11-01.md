Все дополнительные warmup, retry, sensitivity и контрольные обучения сверх таблицы запрещены без пересмотра бюджета; не скрывать их в setup. Встроенные `MeasureAccuracy` учитывать отдельно как внутренние операции batch, не приписывать им независимый внешний EXAM.

Для полезного измеренного выигрыша показывать домен, абсолютные числитель/знаменатель и относительное изменение. Стандартный значительный выигрыш — **строго больше 5%**, без регрессии другой измеренной основной метрики больше 5%, кроме явно разрешённого CPU исключения. Если исходное значение ноль, относительный процент неопределён: писать изменение счётчика/процентных пунктов. Явное исправление правильности/сохранности допускается отдельным логическим основанием, но ресурсная цена остаётся в отчёте. CPU исключение не превращает рост allocations в допустимый CPU рост. Для ветки «cleanup/dynamic composition без доказанного gain» действует отдельное условие пользователя: **не ухудшить качество и скорость native обучения**; inference и setup не заменяют измерение Train.

На одинаковом оборудовании измерять отдельные окна native Train, обычного readout, component lookup, сериализации и загрузки: wall, process CPU, allocated bytes, peak/retained memory с указанием области, state bytes и число записей. Один парный запуск — ограниченное измерение, не статистическое доказательство стабильного ускорения; неизвестная величина остаётся `UNKNOWN`, не ноль. Порядок, cold/JIT и разные дозы обучения указывать. Недостаток данных даёт CONDITIONAL, а не автоматический дополнительный запуск.

Свежий reader — **другой процесс**, читает байты только назначенного checkpoint, сверяет hash, IDs, policy identity и learned state, не вызывает Train и не строит заново пары из gold. Если state дискретный и optimizer/RNG отсутствуют, писать N/A с причиной. Не выдавать `ExportAsync().CheckpointRef` за файл: текущий `TranslationMachine.cs:283–296` возвращает placeholder; использовать реальный checkpoint API владельца101. Старую память не переписывать и не мигрировать молча.
