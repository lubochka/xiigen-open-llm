### KHE: второе обучение действительно должно заменить содержимое

Файл: [Tests/MethodKnnAdmissionLearningTests.cs](../../../../Tests/MethodKnnAdmissionLearningTests.cs), тест повторного допустимого fit99–116 и refusal69–97.

Для формы `[B,S,H,D]` и перестановки1↔2 результат имеет форму `[B,H,S,D]`. При координатах `b,s,h,d`:
- source offset = `((b*S+s)*H+h)*D+d`;
- destination offset = `((b*H+h)*S+s)*D+d`.

Именно этот guard и прямые адреса перенести в отдельную ветвь. Симметричное указание осей2↔1 относится к тому же swap; normalization осей и ошибки ранга сохраняются по прежнему публичному контракту. За пределами guard оставить **старый fallback**, а не новую generic-версию, которой AT01 не измерял. Backward проверяется как обратная перестановка на несимметричных размерах и независимом неравномерном upstream gradient.

Численная математика не доказывает расход памяти. Сохранить локальные numerical tests, затем выполнить только назначенную восстановленную учебную программу владельца45/57 и измерить native ресурсную ось. Не объявлять generic allocation reduction доказательством direct-stride AT01. Если более широкий generic reuse сохраняется как отдельная идея, оформить отдельную гипотезу/опыт вне этой qualification; самовольно расширять R2 нельзя.

Если запланированный harness ещё отсутствует, сначала реализуется именно его ограниченный контракт; отсутствие не заполняется вымышленным PASS. Полная общая инфраструктура не нужна ради исправления двух assertions R1.

### Повторная квалификация после уже сделанного переноса

Старый рецепт «baselineCommit=HEAD перед правкой» применим только до первоначального изменения. Теперь:
- **Проверка текущего B** против независимого закреплённого gold законна для корректности; она не даёт свежего причинного процента экономии.
- **Historical-transfer pair:** `B=transfer commit` из64 и `A=B^` проверяют первоначальный перенос на его историческом окружении, только если обе версии имеют одинаковые необходимые seams. Отсутствующий test seam переносится одинаковым mechanical extraction overlay в A и B; overlay имеет отдельный diff/SHA и не меняет обучающий алгоритм. Для SVD/HCL это требование53/57 обязательно: raw parent не предоставляет новые fixed-panel API. Такой A уже не называется просто нетронутым B^.
- **Repaired-factor pair:** результат ремонта R2 ATS нельзя проверять старым generic transfer commit. Будущий заказ сначала фиксирует SHA исправленной direct-path реализации B; A имеет тот же source и harness, но именно исторический generic fallback без новой direct-path ветви. Разница A/B должна совпасть с измеряемым AT01 фактором. Ни один неизвестный будущий SHA здесь не объявлен готовым. При квалификации ремонта другого FIX аналогично перечислить его единственный меняемый фактор. Отдельный provenance у base revision, common seam overlay и factor patch.
- **Current-composition correctness:** совместная проверка текущего HEAD всех оптимизаций — отдельная стадия; её результат не смешивается с процентом historical-transfer или repaired-factor. Одинаковые harness/fixture/state обязательны внутри каждой причинной пары.
- **Не переключать и не очищать активную рабочую копию** с параллельными работами. Не создавать сейчас worktree/clone и не выдавать source-copy runner за native сборку. До будущего A/B исполнения должны быть конкретно назначены две разрешённые изолированные рабочие директории, идентичный harness revision и native assemblies; такой запуск не входит в данный аудит. Если их нет, выполнить в отдельно разрешённой реализации текущие correctness checks и явно оставить fresh resource effect непроверенным.
- Не менять ветку под идущим процессом. В receipt писать фактические source/assembly/harness/fixture/state SHA, phase, counts и terminal exit; одинаковые A и B отклоняются. Historical experiment report хранится отдельно.

Такое ограничение сохраняет результаты прошлых опытов и предотвращает ошибочное объявление уже изменённого HEAD исходным A. Оно не требует заново обучать все модели.

## 6. Усиление соседних карточек

Помимо владельцев найденных ошибок, в действующие карточки внесены конкретные проверки:15/16/17/21/25/28/32/34/37/40/41/42/54/55/59/62-supervised. Общий договор — [03§24](03-test-and-execution-contract.md#transfer-audit-20261027).

Особые случаи:
- сохранность после отказа/коллизии проверяется **до** repair-fit или restore здорового состояния;
- expected не генерируется проверяемым learner;
- state включает optimizer/RNG там, где это часть механизма;
- teacher-forced framing не выдаётся за авторегрессионное усвоение;
- exact factor и неизменные fallback перечисляются до кода;
- кэш проверяет владельца, изменившийся input и отрицательный путь; для не-кэша cache API не придумывается;
- реальный consumer защищён отдельно от helper; выбранный domain не означает, что верное body/state дошло до получателя.

Это адресное усиление применимых карточек по найденным классам ошибок, не утверждение, что каждый документ каталога прошёл полный семантический аудит.

## 7. Критерий закрытия будущего ремонта

Для каждой строки хранить отдельные подтверждения: source diff, исполнившиеся tests с final result, независимый oracle и его чувствительность к конкретной ошибке, before/after при ненулевом усвоении, полный нужный state, resource metric если она является основанием переноса, реальный consumer. Измеренный полезный эффект не отменяется из-за отсутствия роста accuracy; ухудшения показываются рядом и ограничивают профиль интеграции. Значимые регрессии не скрывать общим средним.

Сейчас закрыт документный этап: аудит, порядок ремонта и усиление карточек. Исправление production/tests, прохождение проверок и квалификация эффектов этим текстом **не заявляются**.
