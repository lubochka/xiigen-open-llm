# 96. Применимость усилений ко всем владельцам — 29 октября 2026

Основание — [94](audit-experiment-transfers-2026-10-29.md), адресное исполнение — [95](repair-plan-experiment-transfers-2026-10-29.md). Перечислены все 62stable ID и 56 уникальных файлов-владельцев нынешнего реестра. Это **карта применимости требований**, не 62fresh code audits и не 62native PASS. Общий контракт 03 делает перечисленные условия частью следующего разрешённого изменения соответствующего owner; новых одинаковых учебных запусков таблица не назначает.

## Правила и конкретные границы

### Восстановление и производное состояние

Тот же прогретый owner, допустимый restore, следующий обычный consumer. Сравнивать state/key/profile/typed RNG по контракту; новый объект не заменяет этот случай. Очистку назначать только по реальной зависимости cache.

### Границы владения

Отдельно caller→Train и Execute/result→caller; мутация копии после допуска не меняет learned state или второй ответ. Назвать массивы/ключи/реальные output types; не переносить универсальный deep clone на неизвестный T.

### Достижимость фактора

До новой оплаченной программы вывести условие срабатывания; измерять настоящую ветвь, не регистрации. При 0trigger сохранять положительное обучение отдельно, causal hypothesis не закрывать.

### Одна реальная цепь получателя

Из восстановленного выбранного состояния через действующий native путь получить actual output. Saved oracle/ожидаемый label/заготовленный payload не подставляется внутрь пути. Две половины в разных тестах не считаются одним e2e.

### Точная численная или дискретная граница

Задать предельное значение и соседние представимые/дискретные значения; независимый oracle и literal expected. Для тензоров сохранить masks/shapes/gradient; случайная сетка не доказательство всех границ.

### Окно ресурса и причинность

Отделить kernel/rebuild/полный Train/readout/serialization; allocations не heap/peak. A→B с прогревом не устойчивый speedup; равны total updates не означает равенство дозы нового материала. Сохранять все встречные метрики.

Для любого будущего runtime дополнительно source→build→run binding. Для запрещающего guard обязательно valid acceptance при том же включённом guard; положительный setup до включения не подходит. Для общего adapter явно записать отличие от native. Эти общие условия применимы по наличию соответствующего механизма, не означают наличия ошибки в каждом owner.

## Явно неприменимое

Sampler CDF не вызывается в чистых KNN-memory карточках: требование near-one draw им не назначается. DPO reference-cache clear не назначается immutable tokenizer/key caches без реального invalidate события. Равенство whole answer не заменяется rank/accuracy из другого домена. Изменение вывода P20/P22 не переводит остальные карточки в HOLD автоматически.

## Адресные будущие эксперименты

| Карточка | Конкретное усиление |
|---|---|
| P08 | Верхний остаток CDF, zero-mass exclusion и actual trained logits при переносе |
| P16 | Противоположные роли должны давать действительно заявленную A-коллизию; если её нет, это иной контраст |
| P18/P19/P21 | Различить length/schema, вход/выход arrays, malformed rejection и valid acceptance; перечислить sibling consumers |
| P20 | N≥2m+2 лишь necessary bound; нужны actual pruning/prevented removals и ordinary answers |
| P22 | Общий SplitMix adapter, native ownership/migration отдельно, stream/graph/answers отдельно |
| P23 | Discriminating token вне 64, одинаковый материал и named factory adapter для maxLen; выделить вклад vector/BM25/pattern |
| P24 | Выбранные replay IDs/material/dose реально различаются и доходят до DPO/retrieval consumer |
| P25 | Восстановленные output mappings читаются ordinary consumer; same-ID substituted payload должен быть замечен |

Новые требования не разрешают менять fixture, seed, лимит или criterion после результата. Исправленные historical записи связываются с raw через source hash. Следующий PRIMARY определяется только каноническим индексом.
