## 3. Новые дефекты происхождения материала

### F128-01, P2 — одинаковое содержание уничтожает различие законных строк

`CapabilityMaterialLineageGuard.ResolveSingleSourceRow` (`308–327`) группирует найденные строки по семье, затем возвращает `rows[0]`. В `178–184` claimed SourceRowId сравнивается именно с этой первой строкой. Договор допускает разные SourceRowId одной семьи с одинаковым Content; перед resolver запрещены только повторяющиеся IDs.

Два Train с одинаковым текстом, разными IDs одной семьи и независимый Test — разрешённый положительный случай. Вторая Train-строка отвергается `LINEAGE_CONTRADICTS_CONTENT`; при подаче только второй строки перестановка доверенного списка меняет отказ на успех. Это ошибка продукта даже без спорного пересечения Train/Test. Существующий `ExamContentAppearingInTrainUnderANewName_IsRejectedBeforeLearning` (`CapabilityMaterialLineageTests.cs:154–180`) по той же причине не доходит до ожидаемого `FORBIDDEN_CONTENT_OVERLAP`.

**Исправление:** после независимого пересчёта содержимого и проверки единственной семьи выбрать заявленный ID среди реально совпавших доверенных строк. Family/role брать у этой строки; неизвестный ID, другой текст и несколько разных семей по-прежнему отвергать. Нельзя устранить падение простой заменой expected на фактически полученный код: положительный разрешённый случай останется сломан. [Независимая проверка договора](../../../../experiments-v2/_audits/post128-2026-11-03/independent-lineage-review.md).

### F128-02, P2 — отдельные политики Dev/Test превращены в общий запрет

Публичный `CapabilityMaterialIntersectionPolicy` задаёт четыре независимых флага. Guard объединяет Dev и Test, а затем использует OR двух запретов (`198–244`). Пример, не зависящий от предыдущего дефекта: Train и Dev одной семьи имеют **разные** тексты, Test другой семьи; запрещено только Train/Test-family. Договор допускает вход, код запрещает его по Train/Dev. Нормализованный блок (`219–232`) дополнительно не учитывает content-флаги вообще.

Это чрезмерный отказ в selective policy, не обнаруженная утечка. Две встроенные политики со всеми флагами true не меняются. Ремонт хранит ролевые множества отдельно и применяет каждый запрет к своей паре; отдельную более строгую защиту фактически потребляемых held-out bytes в `Admit`/`RefuseHeldOutContentInConsumedMaterial` не ослаблять. Нужна матрица четырёх комбинаций TrainTest/TrainDev для family, exact и normalized.

## 4. Новые дефекты приёмки опытов

### E128-1, P1 — полное состояние записано, но не сравнивается

В `P12801/Program.cs:554–586` после загрузки реально проверяются ключи/цели фраз, их количество, число KNN и отсутствие чужой темы. Это полезный comparer. Но он не сравнивает полную TopicSourceMap, KNN targets, lineage, порядок фраз или SHA/размеры bundle. Полный `StableState` вычисляется (`1110–1129,1263–1277`) и записывается в обеих сторонах, но его равенство не входит в приёмку.

Статическое воспроизведение **именно этих предикатов** принимает оригинал и отвергает замену phrase target; при этом пропускает пустую TopicSourceMap, замену KNN target при прежнем count, замену source lineage, перестановку phrase enumeration и ложный SHA bundle. [Семь случаев](../../../../experiments-v2/_audits/post128-2026-11-03/p128-static-counterexamples.json) не являются нативным Load: будущий тест обязан построить допустимое состояние и дойти через реальный loader до того же comparer.

Положительное свидетельство сохранено: checkpoint **28 167 байт**, SHA256 **`a541d5cd7368b858eaf1a606b54fa959a38f586546857787198afd106be532be`**, размер и hash совпали с bundle; writer/child StableState равен **`3347399707582fe13abe5d20ff0f35d750bc0c459d4335f362247f0c596e9643`**. Фактическая потеря памяти в этой попытке не обнаружена. Найден недостаточный заслон для будущего расхождения.

### E128-2, P1 — потребительские результаты не влияют на обязательный итог

Потомок записывает 29 ответов удержания, два экзаменационных ответа и четыре вызова сборщика (`592–612`), но их равенство ожидаемому поведению не добавляет ошибок в `Problems`, от которого зависит exit (`628`). Три чувствительных вмешательства (`365–368,695–746`) также измерены, но их ожидаемый эффект не обязателен для итогового решения.

При успешном API неверный ответ может остаться честным `ExactCorrect=false` в JSON и не изменить итог. Ремонт связывает полноту набора IDs, состояние, ordinary output и эффект контролей с общим finalizer. Научно отрицательный A/B-результат при исправной процедуре остаётся валидным отрицательным результатом: нельзя требовать выигрыша B как условия «опыт исполнен». Процедурная пригодность, гипотеза и разрешение переноса — три отдельных вывода.

### E128-3, P1 — внешняя оболочка не возвращает отказ процессов

`P12801/Run-Experiment.ps1:95–118` сохраняет оба exit и при неуспехе только вызывает `Say`. Явного `exit` или исключения нет. При нормальном завершении `pwsh -File` возвращает 0 ([официальная семантика Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pwsh?view=powershell-7.6#-file---f)). Красный JSON или предупреждение не заменяет отрицательного внешнего exit. Нужны четыре сочетания producer/child: 0/0, 9/0, 0/9, 9/9; только первое завершает оболочку успехом. Это проверяется малыми процессами с заданным кодом, без повторения обучения.

### E126-1, P1 — отказ квалификации и пропуск restore превращаются в DONE

`P12601/Pnl0407L2Bridge.cs:184–200` пишет `START_QUALIFICATION_FAILED` и возвращается из void. `Program.cs:97–114` затем возвращает 0. Оболочка проверяет только exit, отсутствие обязательной точки пропускает через `continue` (`Run-Experiment.ps1:105,108`) и печатает назначенные arms/updates (`128–136`). Контрпример — ноль квалифицированных уроков, ноль updates, нет checkpoint, но внешнее DONE всё ещё достижимо.

Во всех 16 сохранённых arm-result квалификация пройдена, есть `ARM_COMPLETED` и изменение состояния. Отрицательный путь — дефект программы приёмки, а не опровержение этих записанных обновлений. Ремонт возвращает типизированный итог, считает исполненное и делает пропуск обязательного restore отрицательным общим результатом.
