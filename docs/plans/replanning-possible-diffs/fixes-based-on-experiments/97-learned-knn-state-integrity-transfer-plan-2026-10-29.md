## R31-QD — запрос должен принадлежать размерности обученной памяти

Примеры другого owner не добавляют проверки или Train к этому разделу.

**Связь с обучением.** В [KnnLogicalUnit.cs](../../../../21.AgentInfrastructure/Logical/KnnLogicalUnit.cs) `Train` обучает BPE и индекс (строки 150–174), `Execute` строит запрос и читает этот индекс (243–244). В [HnswIndex.cs](../../../../06.VectorSearch/HnswIndex.cs) `Search` (99–110) начинает обход без проверки длины; косинус проходит по длине запроса. Короткий запрос тем самым меняет пространство сравнения и может быть принят как полноценный. Штатный `Vectorize` создаёт 64 координаты; опыт не доказывает, что штатный текстовый вход сам создаёт 63.

**Математическое основание.** Косинус определён для двух векторов одного пространства R^d. Сумма по 63 координатам и нормировка в этом срезе не являются обещанным сравнением в R^64, даже если отброшенная координата случайно нулевая. Равенство длин необходимо, но недостаточно для равенства версии токенизатора/схемы признаков.

**Точная правка.** В `HnswIndex.Search(float[] query, int topK)` до первого вычисления расстояния проверять `query.Length` против размерности выученного индекса. Для непустого индекса источником служит размерность принятого обучающего вектора; согласовать этот источник с предмутационной проверкой `Add` из 95, раздел 7. Не создавать два разных определения размерности. Несовпадение — `ArgumentException` с `ParamName=query`, ожидаемой и фактической длиной. Не молча обрезать, дополнять нулями или возвращать уверенный ответ. Существующий результат пустого индекса `[]` сохраняется; его изменение этим опытом не обосновано. Null/nonfinite, равная длина при другой схеме и повреждённый файл — отдельные контракты, не объявлять их проверенными P18.

**Новый тест:** `Tests/KnnLearnedStateIntegrityTests.cs`, метод `TrainedIndex_RejectsWrongQueryDimension_AndRetainsAnswers`. Проект — `Tests/LlmFromScratch.Tests.csproj`. Его нельзя цитировать как повторное подтверждение всё ещё открытой мутации метаданных или как проверку mutable `TOutput`. Основание R31-OO остаётся P19 плюс приведённый текущий код.

**Математическое основание.** Для обучения M = Train(D) последующий внешней стороной выполненный `D[i].Output.Steps[0]=...` не является оператором обновления M. Если результат `Answer(M,q)` меняется, состояние M не отделено от владельца D. Та же ссылка, утёкшая из `Answer`, создаёт обратный канал записи. Копия только `record` или только верхнего массива не отделяет вложенные изменяемые объекты.

**Сверка 30.10.2026: один действующий контракт.** Единственный владелец механизма — R2 [плана102](102-late-transfer-repair-plan-2026-10-29.md) и уже существующий `21.AgentInfrastructure/Logical/IKnnAnswerSnapshot.cs`: `IKnnAnswerSnapshot<TOutput>`, `ForStorage`, `ForRead`. R31-OO сохраняет учебные контроли P19 и миграцию реальных mutable-потребителей. Прежнее предложение `IOutputSnapshotPolicy`, `Capture`, `TrainOwned` заменено этим решением; второй интерфейс не создавать.

Использовать существующую перегрузку `KnnLogicalUnit.Train(..., IKnnAnswerSnapshot<TOutput>, ...)`. Текущий код вызывает `ForStorage` при записи и `ForRead` при выдаче. Проверить отдельно каждую границу и вложенные изменяемые поля: копия верхнего record недостаточна. Совместимая перегрузка для неизвестного mutable-типа выбирает `DeclaredShared`, поэтому наличие нового API не доказывает изоляцию всех вызовов. Не вводить универсальное JSON-клонирование, рефлексию всех `TOutput` или сериализацию делегата. Идентичность/версия политики для сохранения относится к конкретному носителю по плану74, а не к новому параллельному API.

3. Во втором тесте независимо обучить единицу, получить 12/12; сохранить DTO, реально выданный для `u1`, изменить и его `Route`, и вложенный `Steps[0]`, повторить панель. Требование: 12/12. Повторная выдача не разделяет с предыдущей изменяемый список. Это **новая проверка переноса**, не измеренный вывод P19.
4. Отдельно сохранить существующий строковый пример: два урока и один запрос, без изменения ожидаемой строки. Не считать этот контроль доказательством универсальной глубокой копии.

Бюджет двух основных тестов: 2 BPE fit, 16 уроков/добавлений, 48 `Execute/Search`, 64 `Vectorize`. Строковый контроль отдельно добавляет 1 fit, 2 урока, 1 запрос. Итого 3 fit, 18 уроков, 49 запросов, если выполнены все три. Не прятать дополнительное обучение в «подготовке». Удаление входного `Capture` обязано ломать первый тест, удаление выходного — второй; такие контрольные запуски, если проводятся, учитывать отдельно, каждый повторяет учебную дозу своего теста.

Падающие проверки, ожидавшие тождество ссылок, менять лишь для owned-контракта. Проверки содержания, типов и порядка шагов сохраняются. Не подменять ответ `ToString()`, не сериализовать его в строку ради зелёного теста. Разрешены новые тестовые DTO и их явная политика, но не правка исходных результатов P19.

**Сохранение/восстановление и доменный конструктор.** P19 не показал roundtrip изменяемого ответа с сохранённой политикой. У общего класса нельзя выдумывать уже существующий `Save/Restore`. При подключении к персистентному доменному конструктору владелец [74](74-knn-domain-constructor-transfer.md) должен хранить идентификатор/версию политики и схему выходного типа вместе с идентичностью модели/токенизатора/домена; код политики разрешается установленным каталогом. Неизвестная/чужая политика — отказ до публикации модели. Существующие строковые KNN-опыты не доказывают этот mutable roundtrip. In-process исправление допускается отдельно; сохранение mutable-модели остаётся открытым до конкретного носителя и учебной проверки после восстановления.
