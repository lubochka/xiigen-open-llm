## 3. Новые ошибки и точный предел воспроизведения

### A01 — подпись видит путь проекта, но теряет его фактические свойства

**Владелец:** `experiments-v2/_runners/run-binding/New-RunBinding.ps1::Get-RunBindingSourceClosure`, `Get-RunBindingProjectEvaluation`, `Get-RunBindingImportClosure`.

Синтетический Parent ссылается на Child с `AdditionalProperties="AuditSwitch=enabled"`. У Child import `enabled.targets` подключает `Conditional.cs` только при этом значении. Настоящая сборка Parent успешна, её ответ42; явное MSBuild evaluation Child с этим свойством возвращает Anchor.cs и Conditional.cs. Настоящий SourceClosure возвращает только Program.cs и Anchor.cs, failures пусты. В очереди и visited хранится путь без набора global properties; metadata ссылки не передаётся.

**Следствие:** closure не соответствует реально собранному экземпляру дочернего проекта. Ремонт всех путей imports сам по себе этого не закрывает. **Не доказано:** успешное полное Invoke-BoundRun с неподписанной подменой. На используемом Linux текущий parser preprocess не распознаёт Unix paths и даёт IMPORT_GRAPH_EMPTY; он закрывает запуск, а не молча пропускает его. Переносимость и полнота экземпляра сборки — разные вопросы.

**Закрытие:** RF02 по114 — identity=(path, effective global properties, target framework/runtime), перенос metadata ссылки, все действительные instances; negative change conditional file/import должен менять подпись или отказать до child. Не навязывать самодельную имитацию MSBuild там, где нужен evaluated graph.

### A02 — номера соседей проверены, принадлежность уровню нет

**Владелец:** `06.VectorSearch/HnswIndex.cs::Load`.

На копии настоящего восьмиузлового S0 P2101 Load принимает: (1) ребро entry point на уровне1 к существующему узлу, у которого есть только уровень0; (2) не-entry узел, глубина которого выше объявленного MaxLevel. Все номера в допустимых пределах, а entry point согласован со своим MaxLevel — потому новые локальные проверки проходят.

**Следствие:** пригодный экземпляр выдаётся с противоречивой навигацией. Аудит не добавлял в него новые узлы и не заявляет измеренную аварию Add или частоту неверного ответа. Достаточно доказанного нарушения admission contract. Приёмка RF09 должна проверять cross-node level existence и максимум по всему graph. Симметрия каждого edge не требуется: pruning допускает directed links.

### A03 — P85: общий бюджет обучения записан как бюджет основной панели

`P8501/Program.cs` делает2 Train в CheckFaithful(k1/k5),1 основной Train и2 Train в production panels(k1/k5). Их сохранённые выходы подтверждают исполнение; `budget.actual.trainCalls` и его writer всё равно содержат1. Проверенный итог5=1+2+2 восстановлен из control flow и receipts, а не из нового instrumented run. Основные предметные числа остаются верными. В [effective corrections](../../../../experiments-v2/_audits/2026-11-01-post88-transfer-audit/effective-corrections.json) записано исправление с hashes исходных файлов.

### A04 — P82: обещанная независимость после codec не проверяема по raw

В каждом arm54 экзаменационных строк без current vector; TRAIN95/70 vectors сохранены. Карточка уже требовала эти данные. Значение overlap — NOT_RECORDED. Файловая непохожесть и другие имена методов не устраняют совпадения на уровне признаков, как непосредственно показал P83. Возможная pure reconstruction будет иметь отдельное происхождение, а не подменять отсутствовавшее наблюдение исходного процесса.

### A05 — P88: class name вместо identity обученного tokenizer

after.json содержит `01.Tokenizer:BpeTokenizer`, но не bytes/hash/actual vocab size. Сериализована только часть Manifest; UnitId/UnitRole/DomainTag не сохранены в нём. Требование карточки не выполнено. Это пробел идентичности состояния; cold restore в PRIMARY не требовался и его отсутствие не считается нарушением. Результат прототипа3/6→6/6 остаётся воспроизводимым по строкам.

### Уже известные остатки и снятые ограничения

- **P87:** metrics5 sensitive families против4 в уже исправленном report. RNG envelope включает step; его изменение не равно сдвигу случайности. Correction обязана быть машинной и связанной с исходным digest. `ModelForwardCalls=-1` остаётся неизвестным, не0.
- **RF02 legacy terminal:** фактическая Request-RunBindingLaunchAdmission отклоняет fixture без флага и допускает тот же completed fixture с ContinuationAuthorized при отсутствии claim. Это подтверждение старого остатка; child не запускался. Совпадение archive bytes не доказывает право заново исполнить обучение.
- **P64 denominator:** значение correctOverAnswered=2 уже разобрано в111. Корректны4/4 outcomes,2/2 answers,2/2 refusals; новая находка ему не приписывается.
- **P88 unpublished sources:** старый blocker снят: все6 original SHA256 preflight совпадают с опубликованным dbf4c99, включая KnnLogicalUnit и IKnnAnswerSnapshot. Не требовать повторной публикации уже доступных bytes.
- **Инцидент нормализации:** причина и восстановление starts уже описаны авторами. Этот аудит не редактировал start/binary/raw. Сверка Git LFS pointer не подтверждает доступность его payload; полный размер исторического ущерба здесь не переаттестован.
