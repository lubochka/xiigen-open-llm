Прогон тестов в этой сессии выполнить нельзя: сборка и прогон тестов запрещены

и не моя ошибка в команде — это действующий запрет в настройках репозитория.

## Откуда запрет

Файл `.claude/settings.local.json`, раздел запретов (`permissions.deny`), 11 записей.
Из них по сборке и прогону:

```text
Bash(dotnet build *)

Bash(dotnet run *)
PowerShell(dotnet build *)

```

В разделе разрешений (`permissions.allow`, 21 запись) из команд `dotnet` есть только
`dotnet new` и `dotnet sln`. То есть ни одна оболочка не может ни собрать проект,
ни прогнать тесты.

## Что это доказывает и чего не доказывает

Доказывает: в текущей сессии прогон «до правки» физически недоступен обеими
разрешёнными оболочками, и обход этого запрета другим инструментом был бы
нарушением настроек владельца, а не решением задачи.

НЕ доказывает: что новые проверки красные. Это пока не проверено. Утверждать
«они упали бы» по чтению кода — это вывод, а не прогон, и выдавать его за прогон
нельзя.

## Почему миграция НЕ применена

Закон владельца: каждый тест обязан быть красным на прежней логике, и вывод
прогона до правки и после правки сохраняется в файлы. Если применить миграцию
сейчас, прежней логики не останется, и прогон «до» будет невозможен уже
принципиально, а не только из-за запрета. Поэтому код продукта оставлен прежним:
сохраняется сама возможность получить требуемое доказательство.

Единственное исключение — два изменения, которые поведения не меняют и прежнюю
логику сохраняют:

1. новое поле происхождения урока и номер версии формы ключа в записи учебной
   строки (`27.TranslationDomain/TranslationUnitContracts.cs`), оба
   необязательные, со значениями по умолчанию;
2. новый чистый вычислитель канонического ключа
   (`27.TranslationDomain/TranslationSemanticKey.cs`), который НИКЕМ пока не
   вызывается.

Ни одна строка продуктовой логики записи или чтения ключа не изменена. Поиск
`TranslationSemanticKey` по папке `27.TranslationDomain` даёт только объявление
и ни одного вызова из продуктового пути.

## Что нужно, чтобы снять блокировку

Любой один из двух путей:

1. владелец разрешает `dotnet test` (точечный прогон по фильтру достаточен), и
   тогда прогон «до», миграция и прогон «после» выполняются в этом же слайсе;
2. владелец сама выполняет два прогона и отдаёт их вывод: первый — сейчас, на
   прежней логике; второй — после миграции.
