## Уточнение после P107 — 2 ноября 2026

**Snapshot tokenizer должен быть фактически прочитан новым владельцем.** Сохранение vocab/merges и повторный вызов живого объекта — отдельное наблюдение; приёмка восстановления создаёт новый tokenizer/model, загружает точные bytes и выполняет обычные Encode/Decode/генерацию в исходном назначении. LFS pointer не считается прочитанным binary checkpoint.

Наблюдать tokenizer identity/version, learned merges, encoded input, actual chosen output IDs и reencoded decoded text раздельно. Для результата с unknown ID посередине совпавший текст не скрывает потерю токена. Валидная русская буква из нескольких tokens проходит; неполный UTF-8 suffix получает явный статус. Нельзя чинить проверку глобальным ASCII-only ограничением.

Порча одного сохранённого merge/ID должна обнаруживаться тем же loader/consumer и не оставлять частично опубликованную модель. Freeze reference подтверждать её фактическими fingerprints, а не равным количеством словарных записей. Для перепроверки сохранённого readout не повторять BPETrain или DPO update.

Основание: [аудит 123](codex-123-post107-transfer-and-experiment-audit-2026-11-02.md), [план 124](codex-124-post107-addressed-repair-plan-2026-11-02.md), [контекст 41](../experimets/codex-41-post107-executor-checks-2026-11-02.md). Это уточнение приёмки будущего переноса; прежние результаты и назначенная доза сохраняются.

### `18.CapabilityTraining/LlmIngredientLogicalUnits.cs`

Внутри `PrepareExecution`, перед циклом, объявить **локальную** nullable snapshot reference. Это объявление не делает capture. Передавать её по ref в BuildBatch. Все исходные preference-count, UTF-8 bounds, authorship, finite teaching-vector и aggregate guards остаются в прежнем порядке.

Если observer активен, очистить invocation snapshot и использовать сохранённый per-pair overload. Если observer отсутствует — использовать ref overload. Legacy branch не использует snapshot и сохраняет прежние Compact/Encode/masks.

Snapshot живёт ровно один вызов PrepareExecution. Он не хранится в поле, AsyncLocal, service singleton или cache; между вызовами не переносится. Обычный caller владеет неизменяемым tokenizer на время подготовки; изменение оригинала **после** завершения проверяется отдельным guard. Эквивалентность при внешнем concurrent mutation **внутри** Prepare не доказана, новый lock/epoch/глобальный cache этой карточкой не вводится.

### Count-only diagnostic seam

В том же файле DpoExactPairMaterial добавить nested internal `DpoTokenizerCaptureCountScope` для тестов: Begin/Dispose, readonly Captures, AsyncLocal только для текущего **счётчика**, восстановление предыдущего scope в finally/Dispose. Нет Action/Func callback, setter, доступа к BPE, возможности заменить snapshot/batch или влияния на решение learner. Это позволяет проверять настоящий публичный Prepare без включения старого tokenization observer, который сам активирует fallback. AsyncLocal не содержит tokenizer или trained state. В production без активного scope счётчик не создаёт нового snapshot/cache.

Не менять BPE Train, tokenizer serialization, DPO objective, masks, padding, optimizer/reference policy, LoRA topology, admission/lease/publication. Для этих решений уже существуют отдельные планы.

## 5. Четыре точных ingress/state guard-теста

Они непосредственно охраняют материал, который принимает learner; это не отдельные эксперименты и не доказательство качества `0→0`. Каждый использует новый tokenizer, загруженный из назначенного donor JSON; модели H512 не создаёт. Исходные две строки/typed authors те же. Все observer scopes восстанавливаются в finally, count scopes Dispose возвращает прежнее значение.

| Новый Fact | Точные операции и ожидаемая граница |
|---|---|
| `SnapshotCapture_IsLazyAfterGuards` | Три separate exact Prepare по одной плохой строке: first-row undefined author; malformed UTF-16 `Chosen="\uD800"`; Chosen==Rejected. Три native refusal, 0 successful captures, 0 DPO. Ошибка остаётся штатной по соответствующему guard, tokenizer-derived state не создаётся |
| `Snapshot_IsLocalToOnePreparation` | Prepare двух valid rows: 1 capture. Сохранить batches/bits/hash. Один `callerTokenizer.Train("abab abab abab abab",260)`. Старые batches неизменны; native `CaptureAndValidate(oldBatch,int.MaxValue,int.MaxValue,currentTokenizerSha)` отвергает старую привязку с InvalidErrorCode. Второй Prepare обеих строк: 1 новый capture и новый tokenizer SHA; snapshot между вызовами не переиспользован |
| `ActiveObserver_PreservesPerPairCaptureAndMutationOrder` | На свежем donor tokenizer один Prepare двух строк; observer только перед второй строкой делает один `Train("abab abab abab abab",260)`. Два captures; первая pair связана со старым SHA, вторая с новым. Это прежняя observer semantics, не допущение concurrent mutation. Scope убирается в finally |
| `FailedPreparation_DoesNotLeakSnapshot` | Prepare `[valid D-T1, D-T2 с Chosen==Rejected]` даёт fail после 1 capture. Отдельный Prepare одной D-T1 с observer, выбрасывающим `InvalidOperationException("TS01_EXPECTED_OBSERVER_FAILURE")` перед первым Encode, даёт штатный `PreferenceBoundsInvalidErrorCode` / 0 captures.
