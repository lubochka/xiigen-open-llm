## 2. Точный native участок и единственный фактор

На зафиксированном срезе [E05:93–123](https://github.com/lubochka/llm_mvp_core/blob/38c05f2e9a0fd5ec5da269ea078daf298b637d3b/34.Experiments/Experiments/E05HierarchicalPrediction.cs#L93-L123) строит модели, а [E05:125–147](https://github.com/lubochka/llm_mvp_core/blob/38c05f2e9a0fd5ec5da269ea078daf298b637d3b/34.Experiments/Experiments/E05HierarchicalPrediction.cs#L125-L147) читает `wb.Predict(curLocal)`. [BigramMarkov.Train/Predict](https://github.com/lubochka/llm_mvp_core/blob/38c05f2e9a0fd5ec5da269ea078daf298b637d3b/34.Experiments/Core/MarkovChain.cs) создаёт счётчики заново при каждом Train; Predict выбирает первый максимальный элемент строки. Это реальное чтение результата обучения, поэтому исправление адреса участвует в измеренном качестве.

### Общая механическая подготовка A/B

Для маленького native теста нужен **один заранее назначенный внутренний seam**, одинаковый в A/B. В common harness commit извлечь локальные Fit и reader E05 в новый **`34.Experiments/Experiments/E05LocalHierarchy.cs`** с internal типами `E05LocalHierarchy`, `E05HierarchyState`, `E05HierarchyReader`. Это будущие имена, сейчас API не существует. Назначение:

- `Fit(train, tokenToCluster, clusterMembers, k)` переносит native обучение93–123: ровно те же cluster sequence, фильтр по кластеру, локальные номера, порог `localSeq.Count>=2` и BigramMarkov.Train. Состав members после kMeans остаётся построенным E05, тест передаёт fixed members. Никакого второго learner в Tests.
- State держит native cluster/within instances и metadata. Reader получает state, имеет `Observe(int currentToken)`, `PredictNext()` и `Reset()`. A хранит текущий observed token и читает прежний `curLocal`; Observe не получает gold или весь будущий EXAM. Общий helper выдаёт предсказанный глобальный ID/неуспех, а внешний E05 по-прежнему считает правильные ответы и сохраняет прежний знаменатель.
- `E05HierarchicalPrediction.Run` после прежнего kMeans вызывает этот Fit, создаёт reader с пустой историей перед validation и в каждом прежнем шаге вызывает Observe текущего токена, затем PredictNext. Это общий A/B wiring, не новый режим fullE05. Train suffix или будущие validation токены в history не подставляются.
- При отсутствии friend-доступа добавить **только** `[assembly: InternalsVisibleTo("LlmFromScratch.Tests")]` в `34.Experiments/Properties/AssemblyInfo.cs`; если он уже есть, не дублировать. ## 3. Математическое основание приоритета

Это самостоятельный вывод из native счётной модели; измеренные6 дополнительных правильных ответов подтверждаются raw, не выводятся из формулы. Пусть `c(x)` — кластер глобального события, `l_c(x)` — его номер в списке членов **этого** кластера. После фильтрации TRAIN по кластеру c native счётчик имеет смысл

$$N_c(i,j)=\#\{t:z^{(c)}_t=i,\ z^{(c)}_{t+1}=j\},\qquad f_c(i)=\operatorname{argmax}_jN_c(i,j).$$

Вход строки — последнее событие подпоследовательности c. Число `l_s(x)` из другого кластера s не является состоянием c: одинаковый int не означает одинаковое событие. Корректный доступ при уже наблюдённом целевом состоянии — `f_c(l_c(x_last,c))`. Счётчики не меняются; меняется только адрес, по которому читается обученный закон перехода.

При перенумерации целевых локальных ID перестановкой π таблица становится `N'_c(π(i),π(j))=N_c(i,j)`. Для строки с **единственным максимумом** `f'_c(π(i))=π(f_c(i))`; последующее обратное декодирование даёт тот же глобальный ответ. B переносит и локальный адрес history, и декодирование согласованно. A передаёт число из независимого списка и этой эквивариантности не имеет. Доказательство относится к доступной history и уникальному максимуму: first-index tie breaking и fallback на первого member сами по себе общей инвариантностью не обладают.

Конкретный causal witness — canonical q02 после обучения: source `validate_input` имеет local0, целевой кластер persist. A читает row0 `[0,20,0]` и выдаёт `persist_schema`; B использует последнее наблюдённое `persist_policy`, local2, читает row2 `[19,0,0]` и выдаёт правильное `persist_input`. При перестановке persist members меняются ID и расположение строк, но нужная строка B остаётся адресованной тем же событием. Сохранение heartbeat4/4 отдельно показывает, что same-cluster чтение не сломано.

Предпосылка применима к последовательностям состояний с обучением на кластерных подпоследовательностях: orchestration events, потенциально отдельные синтаксические потоки. Она не доказывает пригодность тех же кластеров для естественного порядка слов, AST или всех доменов. Такие переносы требуют своего положительного опыта и сюда не включены.
