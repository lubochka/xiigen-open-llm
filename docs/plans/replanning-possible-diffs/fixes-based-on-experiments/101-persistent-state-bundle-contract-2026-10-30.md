## Тип состояния определяет комплект

Дополнение аудита104: правило «actual bytes + reader нового процесса» действует для всех learners; перечень neural weights/AdamW/RNG ниже относится к neural exact continuation.

| Тип | Что сохранять | Что доказывает приёмка |
|---|---|---|
| KNN / discrete memory | Actual trained tokenizer/encoder/schema, таблица/индекс/IDs, собственные answers/metadata и config | Новый PID, Train0, те же literal answers и counts |
| Translation checkpoint | Полный ExportCheckpoint, включая обученные таблицы и corrections; hash рядом | ImportCheckpoint в новом процессе; public ExportAsync/ImportAsync проверяется отдельно |
| Neural inference | Weights, topology/config, tokenizer | Inference restoration; exact training continuation этим не заявляется |
| Neural exact continuation | Все реально потребляемые model/optimizer/RNG/scheduler/data-order/cursor fields | Reader Train0 для загрузки; отдельно тот же следующий update, что в непрерывной ветви |

У KNN без optimizer не создаётся фиктивный AdamW. Если последующий ANN Add потребляет RNG, его состояние входит в continuation этого индекса. Hash, lessons, manifest и отдельно обученный tokenizer witness не заменяют actual state. Разные JSON формы/timing не доказывают model delta. Исторический P50/P52 state gap фиксируется явно; потерянные bytes не восстанавливаются из SHA и не требуют повторного Train ради отчётности. [Адресный ремонт C05](105-addressed-repair-plan-2026-10-30.md#c05-сохранить-настоящий-learner-и-проверить-новый-процесс).

## Зачем этот договор

Опыт сохраняет обученный старт и пишет в отчёт, что им можно продолжить обучение. Продолжить **точно** — значит получить в новом процессе ровно то же состояние, с которого ушли: те же числа, те же моменты оптимизатора, ту же позицию генератора случайных чисел, тот же разборщик текста, ту же настройку и тот же получатель. Если хоть одна часть не сохранена, продолжение будет **похожим**, но не тем же, и расхождение проявится не сразу.

Двадцать четвёртый опыт показал, как это ломается тихо. Он сохранил веса и моменты оптимизатора в два файла, а снимок генератора собрал **в переменную в памяти** и передал её сборщику плеч внутри того же процесса. Внутри процесса всё сошлось, сравнение плеч было настоящим. Вместе с процессом переменная исчезла. В расписках остался только односторонний отпечаток снимка, по которому байты не восстанавливаются. [Разбор комплекта](../../../../experiments-v2/RP01-MICRO/P2401/results/attempt-0001/persistent-state-bundle-audit-2026-10-30-src387013f5.md).

Этот договор обязателен для следующих опытов, которые публикуют обученный старт как пригодный к продолжению.

## Части neural exact-continuation комплекта

Таблица семи частей описывает нейронный bundle, в котором эти владельцы реально существуют. Для KNN/count/Translation memory состав выводится из её schema: tokenizer/index/maps/lesson identity/version; отсутствующие по механизму optimizer/moments/scheduler — N/A с причиной, не требование выдумать нейронные файлы. В настройках и расписании также сохраняются data-order/cursor и другие реально потребляемые mutable fields. Полнота определяется actual consumer; семь имён файлов сами по себе не доказывают её.

| Часть | Что в ней обязано быть | Чем проверяется |
|---|---|---|

| Генератор случайных чисел | Типизированные записи по каждому потоку, **позиция потребления** каждой записи и опознаватели устройства — отпечаток топологии и отпечаток настройки адаптеров | Файл существует; поля читаются; опознаватели совпадают с теми, под которыми состояние будет открываться |
| Разборщик текста | Словарь и правила склейки ровно того разборщика, которым считались входы | Отпечаток совпал; пробное разбиение даёт те же числа |
| Настройка | Численная рамка модели, учебная цель и карта получателя обучения | Поля читаются; получатель назван конкретной единицей, а не ролью |
| Состояние расписания | Назначенное состояние расписания скорости обучения | Поле существует; значение соответствует фактическому положению |
| Описание комплекта | Одно описание, перечисляющее все шесть частей с их отпечатками и размерами | Каждая строка описания разрешается в существующий файл с совпавшим отпечатком |

## Правило полноты

**Комплект считается полным только после того, как новый процесс откроет его и выполнит назначенное чтение без единого нового обновления.**

Не считается доказательством полноты:

- успешная запись файлов в том же процессе, который их создал;
- совпадение подписей состояния внутри одного процесса;
- наличие описания комплекта без самих файлов;
- успешная загрузка только весов, без остальных шести частей.

Вспомогательная запись состояния учебный бюджет опыта не меняет: сохранить снимок генератора — это запись файла, а не обновление весов, и в счётчики обучения она не попадает. Нехватка бюджета обучения никогда не является причиной не сохранить состояние.

## Четыре запрета, выведенные из двадцать четвёртого опыта

**Переменная в памяти состоянием не является.** Если снимок собран, но не записан, он исчезает вместе с процессом. Собрали — запишите рядом с весами, в том же каталоге, в том же проходе.

**Односторонний отпечаток состоянием не является.** Отпечаток SHA-256 годится, чтобы **проверить** уже имеющегося кандидата, и не годится, чтобы кандидата **получить**: исходные байты из него не вычисляются. Текстовое представление в журнале — тоже не состояние: из текста байты автоматически не восстанавливаются, и записывать его вместо снимка нельзя.

**Указатель на большой файл без содержимого состоянием не является.** Наличие указателя и наличие содержимого проверяются отдельно: совпали ли отпечаток и размер содержимого с теми, что обещаны указателем, и материализуется ли содержимое в свежей копии хранилища.

**Метаданные шага и RNG cursor проверяются отдельно.** В P24 `RandomStateStep` снимка задан константой0 при optimizer step401; это несогласованная метка snapshot. `ConsumedCursor` каждого RNG stream — другое поле: число потреблённых случайных значений не обязано равняться числу optimizer steps. Оба берутся из своих фактических владельцев, сравниваются по полям и не подменяются друг другом.

## Если точного состояния генератора в уже готовых артефактах нет

Порядок действий для всех прошлых опытов, у которых комплект оказался неполным.

1. Записать `persistent_bundle_incomplete: rng` и перечислить остальные недостающие части поимённо.
2. **Не** подставлять состояние генератора от исходного старта, **не** подставлять свежее зерно, **не** выдавать текстовое представление или отпечаток за состояние.
3. Сохранить действительное сравнение внутри процесса: оно было настоящим. Уточняется только его граница — годится внутри одного процесса, не годится как основа точного продолжения в новом.
4. Историческое обучение заново **не** запускать ради красивой отметки «полно».
5. Если будущая задача действительно потребует восстановления недостающих байтов, для неё сначала создаётся **отдельный ограниченный рецепт** со своей приёмкой: откуда берётся кандидат, какое доказательство личности его подтверждает, что считается отказом. Такой рецепт не назначается попутно внутри работы по осмотру.

## Приёмка договора у будущего создателя состояния

Создатель обученного старта отчитывается семью строками с явной применимостью/N/A «часть → есть/нет/неполно → чем доказано» и одной строкой про чтение новым процессом. Отчёт без строки про новый процесс полным не считается, даже если все семь частей на месте.

Если какая-то часть сознательно не сохраняется — например, разборщик текста строится заново и это безопасно, — это пишется прямо: какая часть, почему её отсутствие не мешает точному продолжению и чем это доказано. Молчаливый пропуск части — дефект публикации.

## Что этот договор не делает

Он не назначает повтор ни одного исполненного опыта, не меняет их учебные выводы и не переоткрывает очередь. Он не разрешает запуск обучения. Он задаёт только состав комплекта и правило, по которому комплект можно называть полным.
