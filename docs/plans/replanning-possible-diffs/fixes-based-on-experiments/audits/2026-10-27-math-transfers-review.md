## 3. M1 — FIX-ATS переносит другой фактор и расширяет область изменения

**Класс:** доказанное расхождение реализации с измеренным фактором и точным планом; численный defect не установлен. **Приоритет ремонта:** P2.

Доказательство: [AT01 report:14–17](../../../../../experiments-v2/RP01-MICRO/AT01/a001/results/report.md) и [one-factor.diff:38–62](../../../../../experiments-v2/RP01-MICRO/AT01/a001/results/one-factor.diff) ограничивают B условием `rank==4` и нормализованными осями 1↔2. [План 45:42–44](../45-attention-transpose-strides.md) задаёт ту же ветвь и сохранение общей ветви для других рангов/осей. В [реальном коде:868–900][ats-source] этого guard нет: один `int[rank]` выделяется на любую общую перестановку, затем каждый элемент снова разлагается по всем осям через `%`/`/` и `newShape.FlatIndex`.

Обе схемы могут давать одинаковую перестановку; текущие coordinate-oracle tests поддерживают именно правильность значений. Но они не могут доказать, что выполнен **измеренный** factor. Результаты AT01 нельзя приписать этому generic rewrite. Сокращение числа временных массивов следует из кода; размер выигрыша и цена более широкого изменения не измерены.

**Минимальный будущий ремонт:** в `TensorOps.Transpose` поставить узкую branch из плана 45 после существующих identity/last-two-axis ветвей; применять `j=((b*C+c)*A+a)*D+d` только к rank-4 1↔2. Для остальных форм вернуть прежний generic fallback. Не добавлять product feature switch. Сохранить существующие progress name, check до записи и inverse backward. Если broader generic factor нужен отдельно, это отдельная гипотеза с собственным назначением, а не молчаливое завершение AT01.

**Регрессия:** сохранить независимые coordinate и roundtrip cases; добавить уже назначенные планом 45 two-branch accumulation и rank-4 middle-axis cancellation на первом positive progress для `[2,17,19,23]`, с неизменными input bytes и отсутствием опубликованного результата. Existing `SimdMatMulTests.TensorOps_TransposeCancellationInterruptsLargeActiveKernel` уже существует; нельзя утверждать, что отмена вообще не тестировалась. Его axis 0↔2 не заменяет новый middle-axis case. Основное учебное подтверждение — M2; исторические −8,67% не жёсткий порог.

## 4. M2 — локальная алгебра ATS/MB/RRD/CS не заменяет перенос учебного подтверждения

**Класс:** доказанный пробел покрытия новых тестов; не доказанное падение кода. **Приоритет:** P2, после M1 для ATS.

В [ATS tests][ats-tests] проверяются mapping/roundtrip/gradient; [MB tests][mb-tests] — `u[row]/D`, другая ось и accumulation; [RRD tests][rrd-tests] — последовательная сумма и небольшой RMS-подобный граф; [CS tests][cs-tests] — visible-cell parity, masked context и gradients Q/K. Эти тесты полезны. Однако в них нет восстановления семейного learned S0, четырёх native SFT updates, контроля keyed AdamW и RNG, закреплённых TRAIN/EXAM readouts и записи resource costs. [План 45:99–120](../45-attention-transpose-strides.md), [план 44:65–116](../44-rms-row-reduce.md) и [план 41](../../fixes-based-on-experimentsperiments/41-neural-learning-resource-deltas.md) требуют именно эту следующую ступень. Не объявлять существующий unit suite пустым и не объявлять его выполненной квалификацией обучения.

Математика прочитанных ветвей согласована: при row-major последней оси `mean[r]=Σ_k x[rD+k]/D`, поэтому `grad[rD+k]=u[r]/D`; RRD сохраняет порядок слагаемых. Для CS после causal mask вес и upstream выше диагонали равны нулю при обычных конечных входах; значит пропуск соответствующих dot products допустим **в этой композиции**. `CausalScores` не является общим MatMul без маски. Сейчас настоящий [attention consumer][cs-consumer] соблюдает композицию и сохраняет отдельный WithPast path.

**Минимальный будущий ремонт:** дописать назначенные native learning fixtures, переиспользуя существующие unit contracts. На каждый ID — свой сохранённый donor и identity, не один общий «почти такой же» RNG. Восстановить weights, keyed AdamW step 400, оба moments и RNG; четыре updates T1,T2,T1,T2; step 404; before/after readout и frozen snapshots. Не повторять 400 подготовительных updates. Для MB не чинить в этой карточке известный `keepDims=false` backward: [тест:93–115][mb-tests] явно сохраняет legacy failure, [57:112](../57-native-transfer-contract-gaps.md) отделяет его от last-axis factor.

**Oracle и бюджет:** одинаковые starts/config/framing; реальное изменение trainable bytes; frozen bytes неизменны; одинаковые online losses, outputs, keyed final optimizer и RNG A/B на одном runtime; все ресурсные дельты, включая ухудшения. По каждой из четырёх карточек использовать её исходный конечный бюджет: по 4 updates на arm, без нового producer. Не складывать проценты разных опытов. Не сравнивать сегодняшний HEAD с самим собой как A/B: он уже содержит все четыре переноса. Перед будущим запуском назначить явно проверенный control, отличающийся только соответствующим фактором, без скрытого отката остальных переносов и без нового worktree без разрешения.

**Защитный контрпример:** вариант, который возвращает те же logits, но пропускает обновление AdamW или обнуляет moments при restore, может пройти tensor tests и accuracy-only checks; новый state oracle должен его отличить. Для CS нужен также consumer-level контроль, который отличит возврат основного attention к full MatMul от сохранённого standalone `CausalScores`: численная parity одна этого не различает.

## 5. M3 — FIX-LC: проверка только метрик не защищает память ученика и кэш после отказа

**Класс:** доказанный пробел state/lifecycle oracle. **Приоритет:** P1 для защиты state и fail-before-hit, без утверждения текущей порчи состояния.

[Тест RememberedReferenceScoresProduceTheSameStepAsRecomputingThem:37–53][lc-tests] вызывает по два StepVector на H8/C8 synthetic fixtures; [AssertSameMetrics:165–170][lc-tests] сравнивает только Loss, RewardMargin, ChosenReward, RejectedReward с шестью знаками. Все четыре показателя снимаются в ходе шага; они не доказывают равенство финальных параметров и optimizer. `Fixture`:179–235 создаёт свежие модели и маленькие пары `a/b/cc`, `d/ee/f`, не восстанавливает квалифицированные две строки N61. Остальные новые Facts проверяют counts, valid new pairs и FIFO, но не исполнение негативных сценариев из [плана 13:93–100](../13-dpo-reference-cache.md).

По source guards находятся на правильной стороне: `CaptureBatch` валидирует exact material ([1071–1079][lc-capture]); recipient проверяется до operation ([1312–1325][lc-rollback]); reference forward явно `training:false` ([1087–1091][lc-capture]); key включает digest/tokenizer/version/reference identity; Store выполняется только после обеих оценок ([951–962][lc-step]). `RestoreContinuationState` очищает cache ([684–693][lc-restore]); rollback очищает его после восстановления ([1330–1336][lc-rollback]). **Это чтение намерения и control flow, не проверенный runtime эффект.**

**Минимальный будущий ремонт:** расширить существующий тест сравнения, сохранив его tiny companion: до и после каждого из двух steps сравнить policy adapters, frozen base/reference bytes, keyed AdamW m/v/step и RNG. Показать ненулевое изменение trainable state. Для учебной квалификации взять исходный N61 weights-only S0, сохранить честное `new_dpo_epoch=true`, fresh AdamW step 0 и одинаково заданный новый DPO RNG; не выдумывать потерянные SFT moments/RNG. По два StepVector, две точные исторические пары, без повторной 1000-step подготовки.

**Конечные негативные cases, используя тот же native lifecycle:**

1. Прогреть пару; затем предъявить malformed exact material или несовместимый tokenizer/profile. Ожидать прежний конкретный отказ **до hit/forward/update/publication**, неизменные веса/optimizer/RNG/файлы. Новый корректный digest — иной case и не заменяет invalid-material case.
2. Прогреть cache; изменить frozen reference. Следующий step обязан получить `DPO_PROJECT_LORA_RECIPIENT_INVALID` до cache hit, а не вернуть сохранённые оценки. Идентичность эталона не назначать заново ради обхода отказа.
3. Прогреть cache, выполнить настоящий continuation restore; отдельно инъецировать late publication failure в допустимую существующую точку. После успешного rollback полное состояние равно pre-step; следующий законный retry пересчитывает обе reference стороны каждой пары. Ни ledger, ни `Clear()` в исходнике сами не являются PASS.
4. Mechanical atomicity: сохранение одной пары возможно только после обоих float; исключение второй стороны не оставляет resident half-entry. Выбрать тестовую точку вокруг реальной ветви вычисления/Store, а не изобретать отсутствующий `GetOrCompute` API. Legacy timing exception test с выключенным cache не доказывает этот контракт.
5. Сохранить уже правильный timing oracle: первый step ref4/policy4, второй ref0/policy4; null/zero-duration семантика соответствует отсутствию вызова. `EvaluateMany` и legacy не читают и не прогревают training cache.

**Защитный контрпример:** cached arm с пропущенным `ApplyOptimizerStep` на втором шаге имеет те же четыре возвращаемые метрики, если они вычислены до update; current four-metric assertion этого последнего отличия не наблюдает. Сравнение финального keyed state наблюдает его напрямую. Это аргумент о чувствительности oracle, не выполненная mutation-test демонстрация.

## 6. M4 — FIX-SVD: тесты проходят через дублированное ядро, основной consumer ими не защищён

**Класс:** доказанный integration/test-oracle gap и неполная переносимость исторической панели. **Приоритет:** P2.

[`FitFixedTraining`:31–61][svd-core] заново строит cooccurrence/rowSums/colSums/PPMI. [`Run`:78–129][svd-core] содержит второй такой же блок; Run не вызывает FitFixedTraining. Общим остаётся только TruncatedSvd. Все новые [SvdDirectedTargetReadingTests:27–105][svd-tests] обучают новый 600-token трёхсобытийный cycle и вызывают FitFixedTraining/EvaluateFixedPanel. Текущий Run действительно вызывает `ArgmaxDirected` на строке 138, но если **только эту строку** вернуть на symmetric reader, перечисленные новые тесты продолжат проверять другой вход. Это конкретный контрпример к заявлению «новые tests защищают next-token Run».

Математическая часть переноса правильна: `L=U√Σ`, `R=V√Σ`; directed score — `L[source]·R[candidate]`. `LLᵀ` симметрична, поэтому не представляет произвольную несимметричную transition matrix. Это не обещает exact low-rank reconstruction для любых матриц и не оправдывает замену similarity/cosine во всём проекте. Отдельный `ArgmaxSourceSimilarity` имеет прежний смысл и должен сохраниться.

**Минимальный будущий ремонт:** механически сделать counts→PPMI→factorization одним shared core, вызываемым и Run, и fixed-panel входом. Оставить ограничение BPE ID через `Math.Min(t, VocabSize - 1)` и train/validation split в Run с прежним контрактом; не отправлять raw BPE IDs в fixed-vocab core. Основной directed consumer также должен использовать общий явно именованный next-token reader. В regression проверить именно соединение Run с этим reader; isolated helper assertion не заменяет consumer-level assertion. Не назначать другой SVD из проекта 33 вместо E10.

**Учебный oracle:** перенести существующие SVD01 `train.json`/`exam.json`, five labels и независимый native Bigram reference; before 600 и after 2400 tokens — отдельные корпуса. Сохранить два self-controls, first-wins ties, одинаковые L A/B и PPMI/counts, directed 0/3→3/3, total after 2/5→5/5, измерить обе стороны reconstruction и retained payload +120000 B. Сравнения читают сохранённые matrices без дополнительных fits. Назначенный [57:128–130](../57-native-transfer-contract-gaps.md) бюджет — 4 SVD fits + 2 Bigram fits, 9000 token presentations, 30 predictions. Tiny cycle оставить algebra companion; не выдавать его за всю историческую панель.

## 7. M5 — FIX-HCL: адрес исправлен, полная семантическая панель не защищена новыми тестами

**Класс:** evidence/test coverage gap; новый algorithm defect не найден. **Приоритет:** P2.

[Run:101–112][hcl-consumer] использует настоящий `E05LocalHierarchy.Fit`, новый reader и `Observe(val[i])` до PredictNext. [Reader:116–174][hcl-reader] видит только наблюдённые события, хранит последнее local state для каждого кластера, очищает историю Reset и сохраняет прежний source-local fallback при отсутствии target history. Новые [tests:40–160][hcl-tests] содержательно проверяют wrong-row counterexample, target permutation, no-history и reset. Не назначать здесь ложный «ремонт» рабочего Reset или fallback.

Однако тестовый Train — новая 18-token последовательность **шести событий/двух кластеров** ([32–37][hcl-tests]); историческая проверка — **семь событий**, отдельный heartbeat cluster, before/after и **16 query histories**. Нынешние тесты не защищают сохранение 4/4 heartbeat controls, общие learned tables arms и исходные 12 cross-cluster запросов. Положительный результат HCL01 не заменяется одним примером PersistPolicy→ValidateInput→PersistInput.

**Минимальный будущий ремонт:** сохранить unit tests, добавить exact fixture `HCL01/train.json`, `exam.json` и canonical/permuted member order. Зафиксировать independent global gold; пропускать reader только по observed prefix, никогда по future answer. Снять before/after learned count tables и ответы; одинаковое обучение при смене reader, затем permutation invariant в decoded global labels. Reset между histories; no-history ветвь оставить compatibility case, не обещать по ней измеренного роста качества.

**Oracle и бюджет:** после обучения A10/B16 из16, cross6/12→12/12, heartbeat4/4 в обоих; semantic permutation A4/16/B16/16; одинаковые tables A/B при одном member order. Использовать матрицу из существующего плана: 8 условий, 24 native Train внутри неё, 128 queries; повторные assertions читают сохранённые tables/predictions. Не запускать kMeans/BPE/полный E05 Run ради micro-panel. Реальную проводку Run→shared Fit/reader проверять отдельно ограниченным integration assertion, не объявляя весь router подтверждённым.
