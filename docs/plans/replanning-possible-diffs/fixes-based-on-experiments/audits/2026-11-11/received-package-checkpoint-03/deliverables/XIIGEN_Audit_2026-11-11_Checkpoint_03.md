### 3. Обнаружен конфликт нового планировщика фраз с последующим допуском

Текущий планировщик выбирает максимум покрытых слов, затем минимум фраз. Вызывающий код допускает покрытие≥85% **либо** не менее двух фраз с покрытием≥50%. Независимый полный перебор на синтетических нормализованных входах показал два контрпримера внутри лимита8слов:

| Вход | Допустимый прежний план | Выбранный новый план | Следствие |
|---|---|---|---|
|8слов, фразы`a1 a2`,`a5 a6`,`a2 a3 a4 a5 a6 a7`|4/8,2фразы, допущен|6/8,1фраза, отказ|Больший охват потерял допустимый вариант|
|6слов, фразы`a1 a2`,`a3 a4`,`a2 a3 a4 a5`|4/6,2фразы, допущен|4/6,1фраза, отказ|Правило равенства предпочло недопустимый вариант|

Это подтверждение несовместимых критериев исходника, **не** нативный запуск tokenizer/trainer/facade и не измерение качества итогового fallback. Ремонт должен согласовать поиск с действующим допуском и сохранить альтернативы, а не снижать порог ради зелёного теста.

В поздней пометке benefit-filter уже есть оговорка об этой разнице; новые данные уточняют число для конкретной fixture. Скорость и полезность early-stop этим пересчётом не измерены.

- Карточка15: конкретное типизированное состояние активной редакции цели, последовательность A→B1→B2→save/load→B3, исключение исторической A из выбора текущего тела, честная миграция неоднозначных старых checkpoint и раскрытый бюджет5batches/25readouts.

- Общий договор улик: исключительное владение каталогом до Train, сохранение незакоммиченных/прерванных попыток, запрет overwrite, отдельный результат измерений и внешний окончательный результат runner.

Ремонт касается согласованности **отчётной функции потерь** с правильным градиентом. Обнулять градиент по границе clipping не следует.
