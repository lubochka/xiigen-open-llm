## 2. Что действительно реализовано

В [planner](https://github.com/lubochka/llm_mvp_core/blob/05caa77dc629d4801783f839f2011db06b1a92ac/27.TranslationDomain/TranslationPhraseCompositionPlanner.cs) строки195–305 добавляют `PlanAdmissible` рядом с прежним `Plan`. Таблица `best[position, spans]` сохраняет лучший suffix для **каждого точного числа фраз**. Нулевая строка разрешает только пропуски, добавление фразы использует suffix с `spans−1`; невозможные состояния остаются `null`. После построения predicate применяется к готовым кандидатам `best[0, spans]`, затем выбирается лучший по прежнему `IsBetter`: coverage по убыванию, span count по возрастанию, ordinal keys.

Для действующей проверки coverage/count это достаточная конструкция. При фиксированном числе фраз менее покрывающий suffix не может стать допустимым, когда лучший уже отвергнут; добавление фиксированного префикса сохраняет сравнение покрытия и ordinal порядка. Поэтому сохранение одного лучшего suffix на точное число фраз не теряет необходимую допустимую альтернативу. Это source-level аргумент, не новый native/exhaustive тест.

Автор явно зафиксировал ограничения полноты в строках172–194: predicate читает только coverage, count и непустоту и монотонен по coverage при фиксированном count. Условие на конкретные keys/targets или немонотонное ограничение покрытия этим доказательством не покрывается. Не нужно объявлять helper отсутствующим либо требовать замены на 0/1/≥2 только ради соответствия прежнему варианту плана. Трёхкатегорийный вариант может остаться отдельной оптимизацией с собственным доказательством.

В [caller](https://github.com/lubochka/llm_mvp_core/blob/05caa77dc629d4801783f839f2011db06b1a92ac/27.TranslationDomain/TranslationTrainedUnits.cs) строки1043–1063 всё ещё вызывают `Plan`; строки1095–1105 после этого применяют coverage/count и target-direction проверки. Форма тестового predicate в новом классе452–463 совпадает с coverage/count частью внутри разрешённой области, где отсутствуют принятые word mappings и оба счётчика покрытия равны. Доказательство helper не является доказательством всего target-direction/fallback контракта; эти проверки остаются у обычного владельца при wiring.
