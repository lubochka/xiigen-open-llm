## B09 — fallback по пустому результату не отличает отсутствие решения от его поломки

**Статус: подтверждено исходником; условный путь. Тег: WRITE-TIME в будущем адресном ремонте inventory.** Это не свидетельство, что текущий здоровый root `.sln` уже ушёл в fallback.

[TestSuiteBatchManifest.cs, 2007–2062](https://github.com/lubochka/llm_mvp_core/blob/55cfd9d00bbebdeae04da7c505b84d0b1cb9b747/Tests/TestSuiteBatchManifest.cs#L2007-L2062) вызывает recursive scan при `declaredProjects.Count == 0`. Такой ноль возникает не только при отсутствии `.sln`: существующий файл может не иметь распознанных `Project(` строк либо все его `.csproj` могут отсутствовать на диске. Комментарий «пустой список означает, что решения нет» шире кода. Тогда широкий обход снова видит вложенные проекты; ограничение штатного solution-пути не опровергнуто.

**Ремонт:** вернуть структурированный результат `solution absent / declared / invalid`, а не только список существующих проектов. Разрешать recursive discovery лишь при явно выбранном synthetic-root режиме без решения. Наличие, но непригодность solution — диагностируемая ошибка с исходным путём/строкой и missing target. Синтетические положительные случаи без solution сохранить. Минимальная проверка: здоровое решение с вложенной чужой копией, явный synthetic root без решения, существующее malformed solution, все объявленные targets отсутствуют, смешанный valid/missing target. Ни чужие копии, ни пропавшие declared projects не должны молча менять область описи.

Поэтому новый аудитор может независимо подтвердить состав и арифметику receipts, но не повторить по ним выполнение каждого hash comparison без исходных объектов и метода. Это не опровержение прежнего результата. Для отдельного будущего восстановления нужен неизменяемый method source/hash и отдельная per-pair запись pre oid, expected oid, фактически computed oid, sizes/bytes removed; после восстановления — собственная сверка final state. Нельзя вставлять CR перед каждым LF: исходная операция необратима без оригинала, и lone CR нужно сохранить.

Восстановление этим аудитом не делалось; факт отсутствия восстановления сейчас также не доказан. Исторический README говорит только, что его наряд восстановления не выполнял.
