## 2. R117-01 — проверяющий, которому нельзя навязать успешный ответ

**Исправляет:** F03/F04/F05, остатки 135/R03–R06/R08. **Файлы:** `P11501/src/BlindEvaluator.cs`, `P11501/Program.cs`, `P11701/Program.cs`, `P11401/Program.cs` и соответствующие текущие verifier. Пути от `experiments-v2/RP01-MICRO/`. Сначала локальные функции и их call sites; новая универсальная инфраструктура продукта для этого не нужна.

### Данные и алгоритм

1. Передать проверяющему **доверенное назначение** отдельно от кандидата receipt: expected experiment/attempt/source, версия данных, список обязательных check IDs, число и ID строк, схема, допустимые диапазоны и cap. Эти величины берутся из зафиксированной карточки/входа, не копируются из проверяемого ответа. Неподтверждённую revision не сертифицировать.
2. Для числа сначала проверить тип и конечность actual/expected/tolerance; tolerance конечный и неотрицательный, probability/accuracy в [0,1], counts целые и неотрицательные. Далее сравнение в заранее заданном допуске. Не полагаться на `abs(...) > tolerance` при NaN.
3. Для P115 сравнить точные множества document IDs/word IDs, длины и DF, corpus content identity и independently expected revision. В паритете A/B сравнить точные QueryId, количество/состав кандидатов, score/rank, selected ID, **полный output** и confidence. Не использовать общий префикс `Math.Min` как полный паритет.
4. Результат каждого контроля содержит `check_id, expected, observed, verdict, evidence_path`; незаписанное наблюдение = UNKNOWN. Предлагаемые поля — контракт будущей реализации, не уже существующий API. Для corrupt fixture `observed=false` может быть правильным отказом: контроль проходит при `observed == expected`, а не при «все raw bool true».
5. Финализатор сверяет точный набор required IDs. Любой missing/duplicate/unknown/failed mandatory check исключает `VALID` и успешный общий exit. Название гипотезы и ожидаемое плечо не доступны слепому предметному оценщику.
6. Статусы раздельны: исполнение, пригодность измерения, бюджет, исход гипотезы, продуктовая приёмка. Законный отрицательный научный результат сохраняется как результат; его не превращают в инфраструктурную ошибку и не повторяют ради PASS. Конкретное нарушение budget обозначается отдельно даже при полезной локальной метрике.

### Новый carrier c257523: полное владение без повторной реализации binding

Владелец CapabilityMaterialLineageGuard.AdmittedTrainingMaterial уже принимает actual строки. Сохранить эту связь и NOT_EVALUATED_NO_LINEAGE. Upstream SnapshotPreferences уже копирует vector, поэтому эти случаи укрепляют общий carrier API и не объявляются воспроизведённой атакой на нынешний trainer.

### Контракт публикации и восстановления

Каждый writer захватывает immutable base holder, строит свой candidate, проверяет отмену и публикует только `CompareExchange(expectedBase,next)`. Автоматического rebase/retrain/retry после конфликта нет. Проигравший кандидат **не** вносится в победившее состояние.

Перед возвратом позднего конфликта построить checkpoint именно из candidate holder и stagedRuntime существующим BuildCheckpoint(version,runtime) в TranslationMachine. Обычный SaveCheckpointAsync вызывает ExportCheckpoint, который читает CurrentVersion: после проигрыша CAS он сохранит победителя S1, поэтому для кандидата B этот путь непригоден. Вынести запись готового payload из SaveCheckpointAsync в общий атомарный writer и передать ему явно построенный candidate checkpoint. TrainingDataArtifactStore сохраняет учебные пары и не заменяет checkpoint runtime. Отдельный content-addressed artifact обязан содержать фактическое состояние, не ожидаемый журнал уроков. Артефакт содержит base identity/version, candidate identity/hash, фактический checkpoint/schema, lineage, расход, причину отказа и текущую победившую version. BuildCheckpoint включает ExportedAtUtc: hash неизменного artifact подтверждает сохранённые bytes, а restored-state parity сравнивает канонический state payload/identity без нового времени экспорта, чтобы новый timestamp не создавал ложный mismatch. Error/result возвращает проверяемый locator или handle. Переживание процесса — критерий сохранности; локальная переменная не подходит.

При ошибке хранения возвращается явный `CANDIDATE_PERSISTENCE_FAILED` (предлагаемый код), исходная машина остаётся целой; сообщение «сохранён» допустимо только после подтверждения записи. Нельзя молча сохранить только журнал уроков или вернуть обещание с несуществующим path. Повторное чтение артефакта не запускает обучение. Его возможное применение к иному base — самостоятельная операция с новым version admission.

Evaluate измеряет один захваченный holder. Если к моменту записи опубликован другой, результат остаётся измерением старой identity и не меняет Accuracy новой. Подпись через ILearningMachine и явно версионный вызов остаются совместимыми.
