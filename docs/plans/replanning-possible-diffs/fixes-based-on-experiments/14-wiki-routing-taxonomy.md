## 2. Конкретный перенос в код

В [ProjectWikiRequestRoutingTrainableModel.cs:25–42,58–92,200–220,295–299,384–388](https://github.com/lubochka/llm_mvp_core/blob/4f35cb71b3db482bfe7ebe611c652c78d89d5db1/42.ProjectWikiDomain/ProjectWikiRequestRoutingTrainableModel.cs#L25) сегодня нет двух меток; `LabelIndex` направляет неизвестное значение в последний индекс, а reader не имеет двух ветвей.

| Место | Запланированное изменение | Почему участвует в обучении |
|---|---|---|
| `Labels` | Сохранить первые 15 меток и их позиции; добавить `SystemBoundaryMapperTraining`, затем `CrossStackBusinessFlowGraphTraining` | Урок должен обновлять свою координату, а не отрицательный класс |
| `LabelIndex` | Для неизвестной метки находить **явный** индекс `NotProjectWiki`; не использовать `Labels.Length-1` | После расширения последняя координата больше не отрицательная |
| `DecideOrDefer` | Декодировать обе новые метки в `system-boundary-mapper-unit` и `cross-stack-business-flow-graph-unit` с теми required inputs, которые уже заданы соответствующим ветвям статического router | Обученная координата становится доступна потребителю |
| `FromSnapshot/NormalizeVector` | Проверять идентичность списка меток. Для точного старого списка из 15 имён — сохранить 15 координат, добавить две нулевые; для точного нового списка — принять 17. Неизвестный порядок, дубликаты, несовпадающие длины — явная ошибка загрузки | Иначе чтение переносит выученный смысл в другую координату |
| `ToSnapshot` | Писать фактический порядок имён и его версию совместимости; не улучшать оценку качества при миграции | Новый размер не является новым обучением |

Миграция — необходимая часть переноса WT, **не дополнительный экспериментальный выигрыш**. Выбрана политика сохранения **именованных координат**, а не обещание прежнего readout: добавление даже нулевых выходов может изменить argmax, top-2 и margin, если прежние scores отрицательны. Поэтому мигрированный 17-мерный snapshot получает `GatePassed=false`; старые gate-данные сохраняются только как историческое свидетельство, не как действующий допуск. Перед продуктовым `Route` требуется настоящая повторная оценка всех 17 классов по действующему контракту. Исходный 15-мерный файл не переписывается. Не вводить скрытую маску двух новых классов, которая изменила бы метод WT.

Изменение `Train` на margin-update сюда **не входит**: WM01 изменил иной фактор и пока равен постоянному ответу 2/4. Не объединять WT и WM в один «успешный патч».

## 6. Короткий контракт исполнителя

Исполнитель использует свою текущую default-модель без override; Student здесь — native линейный classifier, не модель ассистента. Скилы: `docs/skills/intent-to-plan-SKILL.md`, `phase-planning-SKILL.md`, `plan-review-SKILL.md`, `generated-code-review-SKILL.md`, `test-integrity-SKILL.md`, `human-communication-GLOSSARY.md`. Отчёт по-русски: причина → обучаемое состояние → поштучное до/после → выигрыш/регрессии → восстановление → решение кандидата. При создании новых DPO внешняя открытая китайская модель генерирует пары; CODEX с `astra 6 ultracode` выполняет роль выбора и оценки качества. В WT эти роли исторически не исполнялись — не приписывать их отчёту.

STOP/NEXT немедленно прекращает действия предыдущей карточки: нельзя дописывать её отчёт, тесты, commit или cleanup. Краткое сообщение о уже подтверждённом состоянии не разрешает новые действия над старой карточкой. При NEXT брать точный новый ID из реестра; при STOP больше ничего не запускать. Полные роли skills, ожидание и русский шаблон отчёта заданы в [общем контракте](03-test-and-execution-contract.md). Живой process handle ждут штатным wait в том же ходе до exit/deadline; отсутствие новых строк не равно завершению и не разрешает повтор. Старые эксперименты и результаты не удалять.
