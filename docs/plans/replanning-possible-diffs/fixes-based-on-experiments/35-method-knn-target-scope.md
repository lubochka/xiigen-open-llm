## 2. Математическое основание и пределы режима

Обозначим полное множество синтаксических признаков метода `F(m)`, а признаки внешнего тела без спуска во вложенные функции — `S(m)`. Для текущего метода `c_i` и следующего `n_i` прежняя память хранит `(F(c_i), F(n_i))`, новая — `(F(c_i), S(n_i))`. Выбор соседа остаётся:

`i* = argmin_i [1 − |F(q) ∩ F(c_i)| / |F(q) ∪ F(c_i)|]`.

Меняется только голос `CanonicalType(F(n_i)) → CanonicalType(S(n_i))`. Следовательно, при одинаковом порядке/признаках **все расстояния и выбранные соседи A/B должны совпасть**; различие ответа обязано возникать после выбора того же соседа. Это точный проверяемый причинный путь, а не замена обучения на заранее записанные ответы.

У Q1 полная цель содержит `If, Ret` из локальной функции, поэтому прежний rule даёт Guard; проекция оставляет `NumericLiteral, Ret` и даёт Mixed. У Q2 из полной цели удаляются вложенные `Try, Catch`; `Decl, NumericLiteral, Ret` дают Mixed. У внешних Q3/Q4 соответствующие If/Ret и Try/Catch сохраняются. Математика объясняет четыре результата при данном gold и **не доказывает**, что сама эвристика CanonicalType является полной семантикой программы. [Native Jaccard/CanonicalType:150–184](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/Prediction/MethodKnn.cs#L150-L184).

Граница `OuterBodySyntax/v1` означает **синтаксическую категорию внешнего тела**. Predicate Roslyn из опыта исключает все LocalFunctionStatementSyntax и AnonymousFunctionExpressionSyntax; он **не проверяет вызов**. Поэтому:

- Переносить явным scoped API для C#-профиля внешней структуры; существующий legacy API сохраняется.
- Не писать «автоматически исключены только невызванные функции»: опыт содержит невызванные функции, но алгоритм не имеет call-graph анализа.
- Вызываемые/escaping лямбды, async-effects, expression-bodied методы и межпроцедурный смысл не получают положительного вывода этого опыта.
- Не менять признаки запросов/Current, unordered Jaccard, соседство файлов, k или decoder. Это не исправление порядка токенов и не новый AST embedding.

### Почему результат нельзя перенести на default k=5

[Native facade:31–43](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/SemanticCompilerFacade.cs#L31-L43) создаёт `MethodKnnPredictor(k:5)`. При четырёх парах `Take(5)` берёт **все четыре**, независимо от запроса. A имеет голоса Guard×2 и ErrorHandling×2; ordinal tie-break выбирает ErrorHandling — аналитически 1/4. B имеет Mixed×2, Guard×1, ErrorHandling×1; получаются четыре Mixed — аналитически 2/4, с потерей различения controls. Это **не новый измеренный запуск**, а прямое следствие голосования и сохранённых пар.

Поэтому default k=5 и старые callers не переключаются. Измеренный профиль подключается явно через новый узкий параметр конструктора фасада, принимающий **настоящий** `MethodKnnPredictor(k:1)`; default остаётся k=5. Смена default k или объединение профилей требует отдельного основания. Не размножать строки TRAIN для искусственного большинства.

`MethodScopeMaterial` — новый training-only record: `Methods`, `TargetScopes`, `ProjectionVersion="outer-body-syntax/v1"`. Можно разместить рядом с PackedMethod в том же файле; отдельный subsystem не нужен. Map имеет readonly внешний интерфейс, а target-набор каждого принимаемого Next копируется при Train, чтобы поздняя мутация projection map не меняла обученную цель. Не утверждать полную immutable-память Current: старые Current-наборы уже передаются по ссылке, этот независимый контракт не расширяется.

Проекция: по `method.Body.DescendantNodes(descendIntoChildren: child => child is not LocalFunctionStatementSyntax && child is not AnonymousFunctionExpressionSyntax)`; сами два вида узлов пропускать; все остальные обрабатывать прежним `AbbreviateKind`, пропуская "?"; comparer ordinal. При Body=null возвращается пустой набор, как у прежнего extractor; улучшение expression-bodied методов не заявляется. [Экспериментальная правка](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/experiments-v2/RP01-MICRO/MKSC01/one-factor.diff).

До очистки/замены таблицы проверить версию, уникальность ключей методов и наличие ненулевого projection-набора по каждому ключу. Ошибка возвращает `OperationResult<int>.Fail` с точным кодом `UNSUPPORTED_TARGET_SCOPE_VERSION`, `DUPLICATE_METHOD_KEY` или `TARGET_SCOPE_MISSING_FOR_METHOD`, сохраняя старую память. Пустой HashSet допустим; null и пустое множество не одно и то же. Сначала собрать все новые пары во временный список, затем заменить таблицу. Тот же метод, являющийся Next одной пары и Current следующей, получает **новую запись только в роли Next**; нельзя мутировать его исходный record/set.

Фасад использует прежние границы fileId/short.MaxValue, исходный порядок и тот же predicate соседства. Новый scoped метод применяет KHE-порог четырёх пригодных пар перед destructive Train; при недостатке возвращает `INSUFFICIENT_ADJACENT_METHOD_PAIRS` и ничего не заменяет. Низкоуровневый scoped Train, как legacy Train, может принять 1–3 пары: порог reader относится к фасаду. Общий подсчёт можно вынести из уже принятого KHE guard в private helper **без изменения predicate**, чтобы не расходились два ingress. Неподходящие исходники обрабатываются как legacy Extract; в валидном fixture их нет. При конфликте ключей/версии нельзя fallback-ом запустить legacy Train и стереть модель.

Фактический consumer уже существует: [facade Compile:153–175](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/SemanticCompilerFacade.cs#L153-L175) → [PredictNextMethodType:314–324](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/SemanticCompilerFacade.cs#L314-L324) → native Predict → `CompilationResult.PredictedNextMethodType`. Этот reader выбирает последний извлечённый метод и требует UseMethodKnn, CSharp, TrainingSize≥4. Новый scoped producer должен дойти именно до этого поля.

Связь с внешним production domain registry для нового scoped ingress **не установлена**. Не придумывать зарегистрированный handler или существующий checkpoint API. Новый concrete facade ingress и constructor seam — предложенная ограниченная композиция; глобальная регистрация в assistant/API этим планом не назначена. `ISemanticCompiler` и HTTP DTO сейчас не расширяются.

Readonly reflection существующего `_pairs` по образцу [E13E14FeatureFlagTests](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/Tests/E13E14FeatureFlagTests.cs) допустим для снимка; не внедрять пары reflection и не формировать expected label через CanonicalType.

Чтобы не дублировать decoder в evaluator, соседство для этой exact-match панели проверяется независимой равностью query.KindBag и соответствующего сохранённого Current.KindBag плюс уникальностью точного совпадения, а не второй реализацией native Predict. Полное nearest-distance объяснение из raw остаётся historical evidence; измеренные live predictions берутся только из learner.

Compile вызывает `RememberCompiledSource → EnsureGrammarMaskFilter → GrammarMaskFilter.Train`: **восемь B Compile дают восемь побочных fit E05**, хотя MethodKnn обучается один раз. Они учитываются в расходе, не входят в timer MethodKnn ingress и не передают EXAM в его пары. Проверить состояние MethodKnn после каждого readout; качество E05 здесь не оценивается.

Новый тест выполняется после реализации B и одновременно читает pinned A. Это один native transfer-check, а не повтор исторического MKSC host. Если B не достиг4/4 или controls потеряны, сохранить actual failure; не подбирать k, не размножать уроки, не скрывать неприятный результат и не увеличивать бюджет. Тест не требует фиксированных исторических миллисекунд. В A/B замерить отдельно полный extract+fit ingress, direct readout, B Compile, allocations/CPU/wall/whole-process peak; временные интервалы должны быть названы, чтобы source-copy A и facade B не выдавались за одинаковый overhead.

## 6. Контракты, защищающие результат обучения

После успешной учебной проверки два Facts в новом `LlmFromScratch.Tests.ExperimentFixes.MethodTargetScopeContractTests` используют один contract fixture. Это прямые проверки записи/сохранности учебной памяти, не самостоятельные «успехи 0→0». Фиксированный дополнительный источник:

```csharp
class Chain {
    void Begin(){for(int i=0;i<2;i++){}}
    int Middle(){int Inner(int x){if(x<0)return 0;return x;}return 7;}
    void End(){try{}catch{}}
}
```

Producer: один native ExtractWithTargetScope, fileId=0; predictor k1; один успешный низкоуровневый TrainWithTargetScope, 3 метода/2 пары. Он допустим независимо от facade threshold4.

- `ProjectedTargetDoesNotRewriteTheSameMethodAsCurrent`: Middle как Next первой пары имеет внешний набор NumericLiteral/Ret; как Current второй сохраняет исходные LocalFunction/If и прочие raw kinds. Его PackedString/индексы прежние. После этого fixture меняет **принадлежащую caller копию** projection-набора Middle; записанный Next остаётся прежним, подтверждая защитное копирование.
- `RejectedScopeMaterialKeepsTheAlreadyTrainedPairs`: на том же обученном predictor вызвать scoped Train один раз с отсутствующим ключом Middle и один раз с повторным ключом одного метода. Оба typed failure по разделу3; число/содержимое старых двух пар совпадают. Это две отклонённые попытки, ноль успешных повторных fit и ноль Predict. Сначала сохранить raw state, потом assertions; нельзя считать возврат failure новым обучением.

Fixture выполняет эти действия ровно один раз, Facts читают результаты; порядок xUnit Facts не управляет мутациями. Эти controls проверяют два прямых риска переноса: alias Current/Next и очистка памяти до validation. Не добавлять неподтверждённый call-graph resolver, новую обучающую тему или большой corpus.

### Фиксированный resolver и владение запуском

Обе новые fixtures читают обязательные `XIIGEN_FBE_SOURCE_ROOT` и `XIIGEN_FBE_OUTPUT`; не используют cwd/bin, CopyToOutputDirectory или поиск по диску. Проверить их provenance/hashes и native DLL passport до первого BEFORE/fit. Learning fixture принимает только output `source_root/artifacts/fbe/FIX-KS/attempt-0001/learning`; contract fixture — только `source_root/artifacts/fbe/FIX-KS/attempt-0001/contracts`. Иная переменная/путь или отсутствующий файл даёт setup-failure с нулём учебных вызовов в TRX/stdout. Первое действие каждой fixture после этих проверок, до любого BEFORE/fit: атомарно создать `<output>/ownership.json` через `FileMode.CreateNew`, `FileAccess.Write`, `FileShare.None`, записать PID/runId/startUTC и stage. Уже существующий ownership или любой прежний учебный receipt/comparison/status запрещает новый fit; `tests/`, созданный logger, сам по себе не блокирует первую попытку. Только владелец marker создаёт `status.json=running`, а в finally атомарно обновляет **свой** status до terminal success/failure со стадией, exception и реально завершёнными counts. Это единственная разрешённая замена собственного status; входы, marker и учебные receipts пишутся CreateNew и не перезаписываются. Сначала сохранить фактически завершённые readouts/counts, затем пробросить assertion. Не записывать нули вместо not_reached.

При коллизии прочитать исходный handle/status; не удалять marker, не auto-suffix и не повторять завершённую руку. Аварийное завершение без finally проверяется по исходному tool handle/exit, отсутствие файла не доказывает отсутствие запуска. Эти же проверки существующего handle/TRX выполняются перед каждой командой legacy compatibility; её Tests-факты не получают скрытых повторов. Ownership и status отдельны для learning/contracts, оба этапа остаются в одном назначенном attempt-0001.

## 9. Связь с prompt → domain → реальный получатель

[FIX-E2E20](20-prompt-domain-e2e.md) уже планирует learned outer selector → FlowRef → registered domain → настоящий handler → actual answer → cold restore. Его три темы, fixed TRAIN/EXAM и шесть запросов до/после restart сохраняются. MKSC измерял **категорию следующего метода после обучения**; эта строка не является domain ID и не должна назначать route по Guard/Mixed.

К прежним receipts добавляется только сохранность области обучения: translation/orchestration/Wiki/unsupported запрос не вызывает ни legacy, ни новый `TrainMethodKnnWithTargetScope`, не заменяет method pairs и не меняет k/projection profile по prompt metadata. Наблюдение на уже используемой receiver/factory границе; **0 новых запросов, 0 fit, 0 новых topics и 0 donor loads**. Не создавать MethodKnn только ради проверки отсутствующего вызова.

Положительный consumer scopedk1 проверяется один раз здесь настоящим Compile с тем же обученным state. Его нельзя объявлять уже существующим HTTP prompt→C# route. Для MethodKnn native cold save/load не найден; E2E не обещает восстановление его таблицы и не запускает скрытый Train ради restart. Существующие восстановимые selector/recipient states документа20 по-прежнему обязательны. Новый C# topic, method-model persistence и product registry composition данным измерением не обоснованы и сюда не добавляются.
