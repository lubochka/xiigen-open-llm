### 1.1. Недостающая граница приёмки

Перенос `ff1f9fee2c4` ввёл snapshot; `61732d9981d` — framing; `854b6084da5` — раздельную цену обычной оценки. Их наличие проверено по `git log`, а не принято из отчёта за новый прогон.

Точные места текущего кода:

- [CorpusStatisticsSnapshot.cs](../../../../18.CapabilityTraining/CorpusStatisticsSnapshot.cs): `LexicalCorpusStatistics.DescribeOutput`, строки 174–176, возвращает `string.Empty` для `null`; `ComputeContentHash`, строки 333–335, получает уже преобразованный `OutputTextForm`.
- [LlmIngredientLogicalUnits.cs](../../../../18.CapabilityTraining/LlmIngredientLogicalUnits.cs): `TransformerEmbeddingKnnLogicalUnit<TOutput>.Train`, строки 159–199, не отвергает `Output=null` и передаёт его через `DescribeOutput`; `DescribeCorpus`, строки 484–488, повторяет преобразование; `WithCandidatePrinciples`, строки 242–245, использует это описание для `RequireBelongsTo`.
- [LexicalCorpusStatisticsTests.cs](../../../../Tests/ExperimentFixes/LexicalCorpusStatisticsTests.cs): `AbsentFieldAndEmptyField_WereOneMaterialForThePriorDigest_AndAreSeparatedNow` проверяет **Text** напрямую в `LexicalCorpusDocument`. Законный `Train` отвергает пустой Text; этот helper-тест полезен для encoding, но не проверяет достижимый `Output=null`.

Это вывод из кода, **не воспроизведённая подмена живого snapshot и не измеренная потеря точности**. Математическая причина: если producer `P(null)=P("")`, то для любого последующего framing `E` и hash `H` также `H(E(P(null)))=H(E(P("")))`. Более строгий encoder не восстановит потерянное до него различие. Риск относится к тождеству сохранённых учебных ответов и reuse, что входит в разрешённые пользователем логические исправления.

### 1.2. Конкретное дополнение к ремонту R117-04

Работать в тех же двух продуктовых файлах и `Tests/ExperimentFixes/LexicalCorpusStatisticsTests.cs`; владелец остаётся [139§5](codex-139-post117-addressed-repair-plan-2026-11-03.md). Сохранить действующую допустимость отсутствующего Output: передавать отсутствие как отдельное значение/tag через `DescribeOutput` и `OutputTextForm` в уже имеющийся writer. Не заменять это строкой `"null"` или запрещённым пользовательским разделителем. Не вводить новый публичный запрет null ради зелёного теста. Изменение nullability внутреннего DTO согласовать с обеими проекциями, не только с Build. Универсальное тождество произвольного `TOutput.ToString()` этим не обещается.

Будущая адресная приёмка:

1. **Различающий producer-тест, без модели:** одинаковые ID/Text и `Output=null` против `Output=""` проходят именно `DescribeOutput` → `LexicalCorpusDocument` → `Build`. Старый код даёт одинаковый content hash; исправленный — разный. Для честной копии каждого корпуса hash совпадает. `RequireBelongsTo` принимает свою копию и отвергает перекрёстную через существующий `ContentMismatchErrorCode`. Не подставлять nullable OutputTextForm вручную в обход producer.
2. **Обычный обученный путь:** расширить существующий `TrainedUnit` fixture с `SharedModel`/`SharedTokenizer`, без новой модели из сети. Две единицы, по одному уроку с одинаковым `StatusId/StatusText`: у одной null-output, у второй empty-output. Два вызова `Train`, два `WithCandidatePrinciples(CreateEmpty("documentation"))`; оба законных reuse проходят. Четыре ordinary `ExecuteAsync` (по одному до и после reuse каждой единицы) сохраняют исходные фактические значения null/empty, не выдумывают правильный текст. Это диагностика контракта, не опыт усвоения с 0→0.
3. **Положительный учебный контроль и actual identity обязательны:** существующий `AfterTrainingTheCorrectedLesson_TheOrdinaryReaderAnswersTheNewOutput` с `approved→cancelled` и старые parity/cost tests не удалять и не ослаблять. Обязательно сравнить фактические `CorpusContentHash` двух обученных единиц из пункта 2: они различаются и каждый сохраняется после собственного reuse. Если наблюдение сейчас недоступно, добавить узкий internal read-only diagnostic accessor к уже построенному snapshot; не собирать второй «ожидаемый» snapshot вместо наблюдения actual. Одного producer-теста недостаточно для этого пункта.
4. Пустой/отсутствующий **Text** по-прежнему отвергается `Train`; helper framing test остаётся отдельным. Unicode, разделители и прежний законный corpus/reuse сохраняются. Не менять BM25 score, данные P115, gold или перечень кандидатов ради identity-проверки.
5. Старое замечание в начале тестового файла «прогона не было / команды запрещены» — историческое сообщение автора, не ограничение назначенного ремонта. Исполнитель выполняет свежие сборку/discovery/прогоны по [46](../experimets/46-qa-execution-test-repair-and-fresh-results-2026-11-03.md). Падение разбирает по независимому контракту и чинит fixture/expected, если неверен тест; не оставляет UNRUN как приёмку.

Ожидаемые затронутые тесты: новый producer-контраст должен краснеть на прежнем коде; старый null-Text test остаётся зелёным и не является достаточным покрытием.
