## 2. Какой код пишет и читает выученное состояние

Native путь исходного опыта:

`C# source → SemanticCompiler.LogicExtractor.Extract → int[] active predicate IDs → PredicateDatasetRouter.AutoLabel(TRAIN source) → PredicateDatasetRouter.Train → PredicateDatasetRouter.Predict(EXAM predicate IDs) → bool[6]`.

Точные источники:

- [GlobalUsings.cs](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/35.ExperimentsV2/GlobalUsings.cs): E22 использует alias `SemanticCompiler.LogicExtractor` из project12. `SemanticCompiler29.LogicExtractor` — другой extractor, подмена запрещена.
- [LogicExtractor.cs](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/12.SemanticCompiler/Compression/LogicExtractor.cs): объединяет Level3 AST predicates и Level2 semantic ops; добавляет textual FAIL/NULL_GUARD. Это последовательность активных ID0–21, не координатный вектор ±1.
- [SemanticTokenizerPipeline.cs](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/12.SemanticCompiler/Compression/SemanticTokenizerPipeline.cs): при менее четырёх AST predicates Level3 заменяется Level2. Все тексты ниже имеют не менее четырёх AST predicates. Исполнитель не упрощает их до expression snippets.
- [PredicateDatasetRouter.cs](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/22.AgentAlgorithms/Context/PredicateDatasetRouter.cs): `Train` очищает таблицу и `AddRange` сохраняет ссылки на переданные массивы; `Predict` действительно читает таблицу. Пустая таблица возвращает все шесть true; k=3 берёт три ближайших Jaccard sets и выставляет бит при `votes > 3 / 2`, то есть минимум 2 голоса.
- [E22DatasetRouter.cs](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/35.ExperimentsV2/Experiments/E22DatasetRouter.cs): фактический baseline — top3freq, несмотря на старое описание all-datasets в заголовке. Timing не включает acquisition/extraction; это участки readout/scoring, а не время всего обучения.

`Train` — замена полного снимка учебной таблицы, не append и не обновление числовых весов. Здесь один fit всех шести строк на новом экземпляре. Массивы после передачи не меняются; derived labels/predicates и их digest фиксируются в квитанции. Второй `Train` ради каждого assertion запрещён.

Jaccard превращает последовательность в `HashSet<int>`: порядок и повторения теряются. Этот тест не доказывает поддержку порядка предложения/AST. Deterministic source labels и feature extraction сохраняются как действующая граница опыта; этот план не признаёт их универсальной архитектурой routing и не переносит правила `Contains` в новый runtime selector.

[Установленная граница corpus](../66-e22-corpus-lineage-and-positive-run-boundary.md): exact450 texts/order/hashes, per-file labels и trained table не восстановлены. Native router не имеет save/load API. Поэтому **restore невозможен по имеющимся артефактам/API**; назначается ровно один минимальный fit нового фиксированного fixture и reuse того же in-memory instance. Сериализация `_train`, reflection injection, «старый checkpoint» и обещание воспроизвести 0.5646 запрещены. Никакой новой модели, LoRA, DPO или внешнего LLM этот тест не выбирает.

## 7. Метрики и критерии будущего покрытия

Различать exact-row accuracy (все 6 bits правильны) и bit accuracy (правильные bits из 24). Для каждого из 6 buckets записать support/TP/FP/FN/precision/recall/F1. При нулевом знаменателе precision/recall=0; F1=0 при нулевой сумме precision+recall. Macro-F1 — среднее **по всем 6**, в том числе TypeScript/Tests с support 0. Эти два класса нельзя удалить из знаменателя ради более красивого результата. Также вывести false positives, false negatives, extra selected datasets, ошибки extraction/admission и строки, где любое значение ухудшилось. Отдельно снять `Stopwatch.GetTimestamp` и `GC.GetAllocatedBytesForCurrentThread` вокруг extraction, единственного Train и каждого readout участка на одном синхронном thread; без повторов ради тайминга. Малые wall/allocated deltas — наблюдаемые затраты этого run, не устойчивый benchmark.

Следующая таблица — **заданные expected gates**, аналитически выведенные из frozen corpus и native контрактов; ни одно значение не представляется новым измерением:

|---|---:|---:|---:|---:|
| Native empty before / all-true | 0/4 | 12/24 | 5/9 | 12 / 0 |
| Eval-only top3freq | 2/4 | 20/24 | 4/9 | 2 / 2 |

Обучение должно дать ненулевой правильный результат и содержательный прирост против собственного before **и** независимого top3freq. Constant all-true, constant majority mask или ответы длины 6 этот gate пройти не могут. All-true здесь не является OOD rejection. Expected per-bucket F1 после fit `[1,1,0,1,1,0]`, support `[4,4,0,2,2,0]`: новые положительные TypeScript/Tests не проверены. Timing для шести маленьких строк не становится доказательством performance на historical 450.

Если фактический запуск даст частичный полезный выигрыш и failed assertion, отдельно сообщить и выигрыш по конкретной метрике, и не выполненный gate; не прятать улучшение за словом FAIL, не переписывать oracle для PASS. Если after 0 правильных строк и нет содержательного полезного усвоения — это не успешное учебное покрытие; не дописывать margin/proxy-историю. Новая диагностика corpus/producer или новая гипотеза не запускается автоматически в этой карточке.

Historical raw, аналитические expected gates и новый измеренный run имеют разные явные подписи.

## 10. Граница с prompt→domain E2E

TEST-E22 принимает **C# source** и возвращает **mask datasets**. Вход здесь не пользовательский prompt; выход не ID домена и не результат доменного receiver. В [FIX-E2E](20-prompt-domain-e2e.md) остаётся отдельный план внешнего learned prompt selector, передачи payload правильному домену и проверки его результата. Положительный TEST-E22 не засчитывается как исполнение FIX-E2E.

В проверенном пути E22 consumer — сам `E22DatasetRouter.Run`; в новом regression test — native `Predict`. Обычный product prompt-routing consumer этим исследованием не установлен и не внедряется. [E24AttributedRouter](https://github.com/lubochka/llm_mvp_core/blob/7eab1172bb3787eed9c1d966931a856df95f4976/35.ExperimentsV2/Experiments/E24AttributedRouter.cs) действительно делает Train у PredicateDatasetRouter, но enhanced readout использует другой `AttributedSegmentRouter`. Поэтому E24 не служит evidence использования именно этого выученного состояния. Wiring/adapter/новая архитектурная роль не добавляются под видом test coverage.

## 12. Обязательное STOP/NEXT

**При прямом STOP/NEXT или назначении следующего ID немедленно прекратить прежнюю карточку. Запрещено продолжать её отчёт, исправлять её код/тесты, коммитить, повторять прогон или выполнять cleanup под предлогом завершения.** Сообщить только уже подтверждённое состояние; при STOP не делать новых действий, при NEXT перейти к точному ID реестра. Старые эксперименты и результаты не удалять. Ожидание живого разрешённого процесса без такого указания выполняется штатным wait до terminal/deadline в том же ходе; ожидание не заменяется финальным ответом, плохими запросами или бесконечным polling одного tool.
