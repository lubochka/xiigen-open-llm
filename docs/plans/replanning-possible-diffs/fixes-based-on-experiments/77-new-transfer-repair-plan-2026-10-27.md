**Файлы будущего изменения:** `18.CapabilityTraining/KnnCandidatePrinciples.cs`, `Tests/KnnDomainPrincipleLearningTests.cs`; связанные вызовы `LlmIngredientLogicalUnits.cs` менять только при необходимости передать неизменяемую запись. Владелец — FIX-KDP/74, зависимый потребитель — E2E-KDR. Обнаруженный обход допуска не требует нового исследования, чтобы признать логическую ошибку.

1. Create читает Descriptor один раз, проверяет его и сохраняет каноническую запись `(callback, admittedDescriptor)` с копией значимых полей. Rank использует **сохранённые** Id/Version/Profile/Scope/Weight, а не повторно запрашивает изменяемый Descriptor. Сортировка и сумма относятся к этой же записи.
2. Внешний `Principles` не выдаёт внутренний массив и не допускает замену его элементов через cast. Возвращать защищённую коллекцию/описания; внутренний массив оставить приватным. Копирование только входного списка не защищает массив, возвращённый наружу.
3. Встроенные функции копируют массивы языковых маркеров и иные изменяемые параметры при создании. Замена слова в массиве вызывающего кода после создания не меняет уже допущенную модель. Нельзя обещать абсолютную чистоту произвольного внешнего callback одним названием интерфейса: контракт callback, обработка отказа и устойчивость результата должны быть явными.
4. Проверять конечность FinalScore; отказ функции не может протащить Infinity/NaN через паспортный вес. Сохранить подтверждённую формулу: суммарная поправка ограничена ±0,20, разность поправок двух кандидатов — не более 0,40 при принятых весах. Пустой каталог сохраняет прежний native путь.

**Точные отрицательные контроли:** (a) попытаться привести выданную коллекцию к исходному массиву и заменить элемент — внутренний массив недоступен; (b) callback после Create возвращает новый Descriptor с чужим Profile и Weight=Infinity — Rank продолжает использовать захваченную допустимую запись; (c) изменить caller-owned `past/future/negations` array — сохранённые копии и результаты не меняются; (d) один callback возвращает NaN — сохраняется действующее правило нейтрального вклада 0, а non-finite конечный score получает явный отказ. Проверка ловит изменение после допуска, а не только ошибочный вход до Create. Повторное чтение изменяемого Descriptor в Rank запрещено; произвольные скрытые изменения внутри callback этим правилом не объявляются устранёнными.

**Положительные контроли:** тот же обученный native Unit и тот же EXAM, сохранённые правильные RU/HE/OR ответы, пустой каталог, stable tie по ExampleId и обычный consumer. Увеличение набора функций не должно давать новый скрытый бюджет. Исходные численные результаты KDP сохраняются отдельно от инженерных проверок владения данными.

**Бюджет:** проверки коллекции/descriptor/численного предела — unit-проверки без модели и Train, не новые учебные эксперименты. Для native regression использовать один уже предусмотренный producer обученного состояния из 74 в том же test process; не обучать его заново для каждого mutation assertion. Если нужен новый самостоятельный учебный прогон, он сохраняет полный назначенный учебный участок 74 и его общий лимит; этот документ не добавляет второй цикл поверх него. Нельзя переносить experiment-only обходы допуска в продукт.
