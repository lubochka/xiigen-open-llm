## 1. Что получилось в опыте и чего он не доказывает

## 3. Математическая связь и её пределы

Это вывод непосредственно из кода, не новая эмпирическая цифра. Пусть `N` — две замены в указанном порядке и lowercase; `K_u` — множество ключей, выученных маршрутом `u`. Без hints и prior действуют

\[
h_u(q)=\sum_{k\in K_u}\mathbf{1}\{k\subseteq q\},\qquad
s_u=h_u,\qquad
c_u=\min(0.99,\max(0.20,0.20+0.12h_u)).
\]

Знак `\subseteq` здесь означает **подстрочное вхождение**, как `.Contains`, а не множество токенов. Writer создал `K_code={csharp,dotnet}`. Для `q=C# .NET` исходное lowercase даёт `h_code=0`, новый `N(q)` — `h_code=2`; поэтому confidence меняется `0.20→0.44`, а gap — `0→2`. Это точно объясняет пересечение неизменённых порогов в raw. При уже канонической строке `N(q)=q`, поэтому этот контроль сохраняется. В области согласованных с writer написаний `N(N(q))=N(q)`; состояние не надо переучивать, чтобы восстановить доступ к его признакам.

Условие полезной инвариантности — обе записи должны обозначать ту же технологию в контексте текущего маршрута. Нормализация не доказывает сохранение смысла для произвольной строки. В частности:

- `.Contains` не проверяет границ слов. По коду строка `abc#xyz foo.network` превращается в `abcsharpxyz foodotnetwork` и получает оба ключа. Это **рассчитанный риск**, не измеренный экспериментальный результат. Его отдельный контроль ниже обязан сохранить фактический ложный выбор, если он возникает.
- `DomainHint` добавляет `20` к score соответствующего профиля. Подсказка `documentation` может перекрыть два hits `code`. Это существующий deterministic policy, не свойство обучения и не устранённая этой карточкой проблема.
- Две конкурирующие памяти с теми же ключами дают равенство score; отказ по gap должен сохраниться. Alias normalization не разрешает fallback на первый candidate.

Поэтому математическое обоснование повышает приоритет **согласования writer/reader**, но не обосновывает глобальную семантическую маршрутизацию. Обнаруженная collision/подсказочная регрессия ограничивает применимость. Автоматически заменять `.Contains` новым token matcher или добавлять новые Replace запрещено: это другие факторы без положительного результата данного опыта.

## 7. Связь с prompt → domain E2E и граница новизны

В source уже есть больший consumer: [DistributedModelOrchestratorFlow.OrchestrateAsync:25–64](https://github.com/lubochka/llm_mvp_core/blob/ebaf7760a36d43172bd88317ff469edfd09a615b/26.TrainableRouter/Training/DistributedModelOrchestratorFlow.cs#L25) передаёт Prompt в `RouteAndLocateAsync`. В ветке specialist он возвращает UnitId/DomainTag/endpoint и verdict, **не вызывает модель за ответом**. Поэтому local consumer test этой карточки называется `prompt→profile→manifest`, а не полным пользовательским E2E. Test locator использует настоящий `InMemoryRemoteUnitLocator` с двумя явными fixture manifests `code`/`docs`; счётчик-observer только регистрирует вызовы, не выбирает маршрут и не подставляет ответ.

Для consumer оба manifest заданы полностью по существующему [RemoteUnitManifest](https://github.com/lubochka/llm_mvp_core/blob/ebaf7760a36d43172bd88317ff469edfd09a615b/21.AgentInfrastructure/ModelServer/Remote/RemoteUnitManifest.cs): `UnitId=code/docs`, `UnitRole=executor`, `DomainTag=programming/documentation`, `Version=fixture-v1`, `ServerBaseUrl=https://fixture.invalid`, `UnitEndpoint=fixture://FIX-KR/code` или `fixture://FIX-KR/docs`, `TrainingBranch=fixture-only`, `TrainingRunId=historical-KR01-profiles`, `TokenizerPath=fixture://FIX-KR/not-used`, `RegisteredAtUtc=2026-10-23T00:00:00Z`. `SourceDatasetSha256` — SHA256 точных UTF-8 bytes `training.json`; `ManifestSha256` — SHA256 UTF-8 строки `FIX-KR/<UnitId>/fixture-v1`. `ModelConfig=new RemoteModelConfig(2048,96,64,2,4,4,128)` и `LoraConfig=new RemoteLoraConfig(2,4f,0.05f,["q_proj","v_proj"])` — обязательные, но не используемые в этом test placeholders; receipt содержит `runtime_model_not_invoked=true` и `model_layers_exercised=0`. Это test-only адреса без сети и конфигурация без весов, не обученная нейромодель/продуктовая публикация. [InMemoryRemoteUnitLocator.RegisterAsync](https://github.com/lubochka/llm_mvp_core/blob/ebaf7760a36d43172bd88317ff469edfd09a615b/21.AgentInfrastructure/ModelServer/Remote/InMemoryRemoteUnitLocator.cs#L39) принимает записи с непустыми UnitId/endpoint; lookup использует фактический `ChosenUnitId`. Его случайная identity — операционная identity registry, не RNG обучения и не источник правильного маршрута.

Полный путь HTTP→learned domain selector→FlowRef→реальный receiver→ответ→restart уже спланирован в [20](20-prompt-domain-e2e.md). Его TRAIN/EXAM, 6 запросов, fixture budgets и каталог не меняются. На прежних receipts 20 можно только показать provenance этой уже выбранной реализации, если фактический recipient её использует; это **0 новых Train/Route/HTTP**.
