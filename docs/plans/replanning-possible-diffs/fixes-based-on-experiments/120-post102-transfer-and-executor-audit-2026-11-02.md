## 3. Новые ошибки и границы доказательства

### F102-01. Проверяется другая функция правильности

[Bridge](../../../../experiments-v2/RP01-MICRO/P10201/src/P102TrainingStepBridgeCopy.cs), строки381–409: калибровка `actual.Trim()==gold`. Строки682–718: `SemanticAnswerCorrect` получает `receipt.Text.StartsWith(goldSentence)`. Первый критерий и второй не эквивалентны. Верный gold с противоречащим хвостом пройдёт рабочую проверку; верный пересказ не пройдёт. MutationProbe1112–1117 меняет/сравнивает bool, не проводит испорченный текст через рабочий оценщик.

Исправление: один общий callable, отдельные exact/число/закон/противоречие/усечение, калибровка и итог вызывают его одинаково. Неподдерживаемая формулировка получает UNJUDGEABLE, а не скрытый PASS или исключение из знаменателя. Четыре уже сохранённых текста можно переоценить без обучения; текущий вывод TRAIN1/1, EXAM0/1 останется. Исправляющая интерпретация добавлена в этот аудит; C# scorer пока не изменён.

### F102-02. Разные метрики и непроверенная вместимость

TF37 — все совпавшие позиции; own7 — непрерывный prefix после `Encode(receipt.Text)`. Полной actual generated ID trace нет: сохранён фактически первый token73, остальные ProducedTokenIds перекодированы из текста. Простое позиционное сравнение этих перекодированных массивов здесь случайно тоже даёт7, но «пятикратное качество» не следует из двух разных процедур.

MaxNewTokens46 против canonical EXAM47 не позволяет вместить назначенный полный gold в таком представлении. Все четыре stop reason — LENGTH_LIMIT. Без полного vocabulary не утверждается абсолютная невозможность иной сегментации ≤46. Первая ошибка числа возникает значительно раньше усечения, поэтому cap не оправдывает неверные10. Исторические cap/raw не переписываются. Полный trace и восстановленный readout могут стать только отдельным заранее ограниченным продолжением от S0/S1 с additional Train0.

### F102-03. Неуспешный exit разрешает повтор уже оплаченной работы

[Runner](../../../../experiments-v2/RP01-MICRO/P10201/Run-Experiment.ps1),9–20 запрещает только успешный exit. Bridge191–208 при существующей claim выбирает следующий суффикс. Проверки живого process/stage нет. Поэтому возможны второй процесс рядом с первым и полный повтор после позднего отказа после update. Указанный build timeout600s в runner72–76 не реализован таймером для `Start-Process -Wait`.

**В историческом P102 двойное обучение не обнаружено:** три предыдущих runtime отказа расположены в LoadModels до scoring/Train. Находка относится к допуску будущего повторного исполнения. Требуется одна логическая claim, terminal receipt для любой ошибки, сохранённая стадия и recovery от S1 вместо повторного Train. Проверка механизма возможна дешёвым child со счётчиком побочного эффекта, без модели.

### F102-04. Подпись исходников и цена относятся лишь к части исполнения

Шесть сборок заняли суммарно284.98s; было четыре runtime entry, из них три ранних отказа. Последний успешный процесс109.939367s; его192 Forward согласуются с source-derived счётом, 2 Backward и1update. Его allocated32188097352bytes — накопленные выделения, не peak987226112bytes. Суммарные CPU/allocations и полная duration всех попыток UNKNOWN: одно из ранних terminal времён отсутствует. Нарушение научного лимита192 не доказано; полная цена подготовки в успешном runtime не содержится.

Manifest6 содержит341 entry и правильные hashes пяти собственных файлов host, но пропускает явно подключённый `25.ModelServer/ContinuousLearning/CodeDocumentationGenerationConfiguration.cs`, а также closure определений ProjectReference/imports. Prebuild glob по13 каталогам не равен графу реально потреблённых build inputs. Это конкретное продолжение RF02, не доказательство подменённых входов. Нужны evaluated project instances и consumed bytes.

### F102-05. Причинное объяснение сильнее данных

В [DpoTrainer](../../../../11.DPO/DpoTrainer.cs),1240–1248 производная log probability по всему словарю содержит `oneHot(target)-softmax`. Два выбранных ответа не означают отсутствие градиента у остальных logits. Корректно: pair-relative objective не гарантирует конкретный третий ответ/greedy поведение. Единственная причина generalization error этим опытом не установлена.

53248 изменённых weights не равны53248 ненулевым data gradients: AdamW отдельно применяет decay. На первом шаге нормированная составляющая содержит `g/(abs(g)+epsilon)`, а не всегда ровно learningRate. Raw gradient census не сохранён; его нельзя восстановить из одного changed count.

«Неназванные» здесь определены относительно полного EXAM carrier, включая prompt/chosen/rejected. На10 позициях outsider выше gold. TRAIN/non-TRAIN partition4/6 относится к общим argmax этих позиций; для BestUnnamedId partition1/9. Оба числа воспроизводимы при своих определениях. EXAM-local outsider нельзя называть вообще не обучавшимся токеном.

### F102-06. Неизмеренное состояние названо неприменимым

После step1 fingerprint optimizer moments остаётся строкой «не применяется до первого шага», потому что передан null. Это отсутствие измерения этим observer, не доказательство отсутствия моментов: save path существует. Fresh restore и keyed payload hash остаются непроверенными. Аналогично сохранность восстановленных файлов до/после одной успешной попытки не устанавливает писателя их старого повреждения и не исключает условный сбой этого пути.
