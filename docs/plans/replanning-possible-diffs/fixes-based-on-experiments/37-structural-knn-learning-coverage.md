## 3. Математическое объяснение именно проверяемого свойства

[DistanceTo:28–37](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/Prediction/StructuralKnn.cs#L28-L37) складывает неотрицательные штрафы за различия категориальных признаков и глубин. Вклад различия роли равен4, позиции в родителе —0.3. FileId и SiblingCount в расстояние не входят. Это установленное текущее поведение, не доказанная оптимальность весов.

В назначенных ниже файлах контекст — `IdentifierName` переменной внутри `AddExpression` в инициализаторе локальной переменной. У левого операнда роль3/позиция0, у правого роль4/позиция1. Остальные используемые расстоянием признаки одинаковы: AstNodeType, три типа предков, ScopeDepth и DepthInMethod. Поэтому между такими контекстами расстояние4.3, внутри каждой семьи —0.

В TRAIN по три файла каждой семьи. У любого EXAM-контекста есть **три нулевых ближайших соседа с одним заранее заданным gold**; ни один другой учебный контекст с расстоянием0 не имеет иного successor. При k=5 эти три голоса дают большинство независимо от оставшихся двух соседей и их ничьей. На BEFORE facade пропускает predictor, поскольку таблица пуста; после одного fit ожидается правильный ответ обоих типов. Это аналитическое основание будущего критерия, не фактический результат нового обучения.

Если хранить лишь текущий `IdentifierName`, четыре выбранных входа неразличимы. При двух противоположных gold постоянный ответ и классификация только по AstNodeType дают максимум2/4. Проверка4/4 защищает использование приобретённого структурного контекста. Она **не выделяет причинный вклад отдельного веса4**: позиция тоже различает семьи; не доказывает оптимальность k, HNSW, LoRA или нового tokenizer.

Границы явно ограничены. EXAM отличается именами/числами, но эти значения extractor игнорирует, поэтому его векторы совпадают с учебными. Это перенос внутри фиксированного синтаксического шаблона / использование выученной памяти, не обобщение на новые AST-структуры. Проект12 использует усечённые categorical IDs `%200`; математическая схема не доказывает отсутствие коллизий во всех SyntaxKind. ## 4. Полностью заданный минимальный набор одной темы

Источник каждой строки — ровно одна строка C# по шаблону:

```csharp
public sealed class CLASS { public int M(int ARG) { var result = EXPR; return result; } }
```

Подстановки литеральные, без генератора случайных имён или поиска corpus. `sealed` нужен существующему [StackDetector.PredictByMarkers](https://github.com/lubochka/llm_mvp_core/blob/3acae42f7ef474e449737a57f0cf064921c4bbc7/12.SemanticCompiler/Routing/StackDetector.cs), чтобы вход действительно прошёл CSharp reader. Он не участвует в различении двух target-классов; одинаков в каждом файле. Порядок TRAIN строго как в таблице.

| Учебный ID / файл | CLASS | ARG | EXPR | Следующий kind за выбранным IdentifierName |
|---|---|---|---|---|
| T1 / `left-1.cs` | TrainLeft1 | x | `x + 1` | NumericLiteralExpression |
| T2 / `left-2.cs` | TrainLeft2 | value | `value + 2` | NumericLiteralExpression |
| T3 / `left-3.cs` | TrainLeft3 | item | `item + 3` | NumericLiteralExpression |
| T4 / `right-1.cs` | TrainRight1 | x | `1 + x` | ReturnStatement |
| T5 / `right-2.cs` | TrainRight2 | value | `2 + value` | ReturnStatement |
| T6 / `right-3.cs` | TrainRight3 | item | `3 + item` | ReturnStatement |

| Проверочный ID / файл | CLASS | ARG | EXPR | Независимый gold successor |
|---|---|---|---|---|
| Q1 / `exam-left-1.cs` | ExamLeft1 | probe | `probe + 7` | NumericLiteralExpression |
| Q2 / `exam-left-2.cs` | ExamLeft2 | input | `input + 9` | NumericLiteralExpression |
| Q3 / `exam-right-1.cs` | ExamRight1 | probe | `7 + probe` | ReturnStatement |
| Q4 / `exam-right-2.cs` | ExamRight2 | input | `9 + input` | ReturnStatement |

`T1–T6` — учебные идентификаторы, `Q1–Q4` — идентификаторы четырёх readout. Native Train получает полные шесть source strings, **не только шесть выбранных контекстов**. Его writer создаёт16 переходов для каждого17-node файла, всего96 пар; остальные next-kind labels принадлежат той же задаче. Выбранные контексты служат fixed evaluation panel, не переопределяют writer.

До любого Train helper разбирает ровно эти10 sources Roslyn-ом и проверяет: zero diagnostics severity Error, один `AddExpression`, единственный его операнд `IdentifierName` с именем ARG,17 `DescendantNodes`,16 внутренних пар. Узел выбирается по синтаксическому типу и ARG, не через expected label или предсказанный ответ. У левой семьи его ordinal13, у правой14; `PredictedNextTokens[index]` относится именно к этому узлу. Setup проверяет синтаксис, counts и index, не читает `panel-gold.json` и не проверяет правильность предсказаний. После сохранения всех outputs scorer сопоставляет независимый следующий Roslyn kind выбранного узла с авторским gold из таблицы. Не использовать `StructuralVectorExtractor.NodeTypeId` или actual output для вычисления expected: кодек evaluator — зафиксированное `(int)SyntaxKind.NumericLiteralExpression % 200` / `(int)SyntaxKind.ReturnStatement % 200`; scorer проверяет различие двух ненулевых IDs до подсчёта correctness.

Числа17/16/96 и позиции13/14 — предписанные статические критерии этой панели, **не измеренная подготовка**. Если pinned parser даёт другое дерево, сохранить setup-failure с0Train; не менять fixture/ordinal до зелёного и не продолжать с другим объёмом. EXAM нигде не передаётся в `TrainStructuralKnn`; авторский gold хранится отдельно и открывается scorer только после сохранения всех outputs. Roslyn-разбор/semantic metadata не становятся подсказкой для `Compile`.
