```csharp
private static bool IsNonNullableIntRelationalPattern(
    MethodDeclarationSyntax method, IsPatternExpressionSyntax pattern)
{
    if (pattern.Pattern is not RelationalPatternSyntax ||
        pattern.Expression is not IdentifierNameSyntax identifier)
        return false;
    return method.ParameterList.Parameters.Any(parameter =>
        parameter.Identifier.ValueText == identifier.Identifier.ValueText &&
        parameter.Type is PredefinedTypeSyntax predefined &&
        predefined.Keyword.RawKind == (int)SyntaxKind.IntKeyword);
}
```

## 3. Математическое объяснение и пределы применимости

Для T01 значение `n=1,x=null` удовлетворяет `n is >0`, но не делает `x.Length` безопасным. Поэтому импликация «такой int-pattern есть → nullable receiver защищён» неверна. Исключение этого признака из hasNullCondition устраняет конкретный ложный вывод учителя.

[Спецификация C#, §11.2.9](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/patterns#1129-relational-pattern) задаёт relational pattern как сравнение входного значения с константой; [справочник patterns](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/patterns#relational-patterns) поясняет, что null не соответствует relational pattern. Поэтому `int? x; x is >0` может защищать **сам x**; это контроль T10–T12/Q4, который B намеренно не исключает. Type pattern также нельзя выкинуть общим запретом IsPatternExpression.

При неизменных признаках и query набор ближайших трёх строк не меняется. kNN выбирает
`argmax_label Σ_{i∈N3(q)} 1[y_i=label]`
с прежним tie-break. В сохранённых raw вектор Q1 равен векторам T01–T03; исправление трёх их labels меняет голосование для этого семейства. Для Q2/Q3/Q4 сохранены соответствующие тройки и labels. Это ограниченное объяснение наблюдённого ответа; новые Predict или эксперимент в документной сессии не выполнялись.

Helper проверяет синтаксическое имя и написание типа, а не SemanticModel/receiver binding/dominance. Не расширять его на System.Int32 alias, локальные переменные/функции, затенение имён, составные `and/or/not` patterns, произвольные value types или межпроцедурный null-анализ. Контрпример подтверждает ошибку именно фиксированного семейства, а не soundness всей policy Label. Применимость — C# AST supervision этой единицы; на текст, переводы и Wiki вывод не переносится.

Приоритет FIX-NKU→FIX-NG поддерживают измеренное исправление учебных меток и ответа вместе с этим логическим объяснением. Теория не получает самостоятельного success-ID, не обещает LoRA-эффект и не разрешает уменьшить минимальный набор.

## 8. E2E, ожидание и немедленный переход

[Общий план20](20-prompt-domain-e2e.md) уже описывает learned selector, typed handoff, действительного recipient и restart. У FileActionKNN нет native persistence: saved test rows не подтверждают cold restore и не импортируются через reflection. Общий restart20 проверяет только назначенные поддержанные состояния; скрытый Train для «восстановления» NG запрещён. Default UseFileActionKnn=false сохраняется.

Для живого exec_command session_id — write_stdin того же ID; для functions.exec с `Script running with cell ID` — functions.wait того же cell. Сначала прочитать схему доступного инструмента; в иной среде использовать её документированный wait. Порции≤60секунд, содержательное промежуточное сообщение; не polling loop/второй waiter/дубликат запуска и не финал «жду» вместо ожидания. Отсутствующий пока файл не доказывает смерть процесса.

**STOP/NEXT немедленны в этой карточке и каждом её промпте.** При STOP прекратить новые действия; при прямом NEXT перейти к названному ID, не продолжать прежние code/tests/report/commit/cleanup/«ещё одну проверку».
