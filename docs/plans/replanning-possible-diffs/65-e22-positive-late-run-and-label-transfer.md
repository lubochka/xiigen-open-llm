## Чему учился этот механизм

[E22:27–47](C:/Projects/llm_mvp_core/35.ExperimentsV2/Experiments/E22DatasetRouter.cs:27) извлекает предикаты из исходных файлов, автоматически размечает шесть dataset buckets, берёт первые 80% строк для Train и последние 20% для проверки. В самом этом коде нет перемешивания, группировки семейств или проверки непересечения смысловых шаблонов. Порядок и состав старого входного корпуса из одного receipt восстановить нельзя.

[PredicateDatasetRouter:25–48](C:/Projects/llm_mvp_core/22.AgentAlgorithms/Context/PredicateDatasetRouter.cs:25) сохраняет учебные примеры и для запроса находит три ближайших множества предикатов по Jaccard, отдельно голосуя по каждому dataset bucket. Это настоящее использование сохранённой учебной памяти. Здесь не обновляются LoRA-веса и не генерируется новый текст Student.

Baseline [E22:49–76](C:/Projects/llm_mvp_core/35.ExperimentsV2/Experiments/E22DatasetRouter.cs:49) выбирает три самых частых dataset buckets по TRAIN. Оба варианта затем сравниваются с теми же автоматическими метками. Положительный результат показывает лучшее воспроизведение этой разметки по предикатам, но ещё не независимую человеческую правильность выбора домена.

Три нуля также не доказывают одинаковую причину: для отличия отсутствующих положительных примеров от ошибок нужен состав соответствующей контрольной части.

## При переносе изменили не только размещение класса

Commit `10364aef4016ceeb66877f0f62dac8cf6fecd43d` от 6 мая переключил E22 с экспериментального `DatasetRouter` на `AgentAlgorithms.PredicateDatasetRouter`. Прочитан его diff. Исходный predecessor: `d7b25cbd5b668c0935b51faeb1c20b90ab0da069`. **Уточнение lineage после пакета66:** этот SHA не ancestor receipt `88a880abf4`; в его ancestry находится `cb88fee44619ed00b59ebd6e4830676146e6bf4b`. Blobs E22 и router во всех трёх refs побайтно равны. Сравнение алгоритмов сохраняется, но прямую историческую цепочку следует обозначать через cb88; [подробности и смешанные SourceLink-снимки ZIP](66-e22-corpus-lineage-and-positive-run-boundary.md:26).

В этом predecessor `35.ExperimentsV2/Infrastructure/DatasetRouter.cs:65–69` определяет часть BugFix через `ActionLabelGenerator.Label`. Последний, `Infrastructure/ActionLabelGenerator.cs:19–36`, анализирует AST: member access в теле метода и отсутствие null/is-pattern в условии `if` данного метода. В нынешнем [NeedsNullCheck:76–81](C:/Projects/llm_mvp_core/22.AgentAlgorithms/Context/PredicateDatasetRouter.cs:76) осталась строковая проверка: в полном файле есть точка и нигде нет ` null`/`is null`.

Это разные смысловые контракты:

- `namespace A.B` даёт точку даже без разыменования внутри метода. Новый признак может сработать; старый AST-признак из этого не следует.
- Null guard в одном методе может подавить новый признак во всём файле, хотя другой метод содержит незащищённое обращение. Старый алгоритм рассматривает методы отдельно.
- Комментарии и строковые литералы видны строковому правилу; их положение в AST имеет значение для прежнего правила.

Это разбор условий по source, **не исполненные примеры**. Старый AST-эвристический oracle тоже не объявляется идеальным: наличие любого `IsPatternExpression` в условии не обязательно защищает нужный объект. Проверять следует корректность конкретного предметного случая, а не только совпадение со старой эвристикой.

Отдельный более ранний commit `8b3f4b2d6835a4dab44cead3fa681919d9d9fb98` уже менял baseline и его подсчёт: predict-all заменён на top3freq с per-bucket macro-F1. Комментарий «predict-all математически доминирует macro-F1 независимо от precision» не является верным общим свойством F1; совершенный классификатор с precision=recall=1 даст больше. Поздние результаты нельзя сравнивать с заголовочным 16,7% как с той же метрикой.

**Практический пробел:** при переносе сохранили имя эксперимента, но изменили label function. Даже положительный поздний результат нельзя трактовать как чистую проверку прежней задачи. При текущем corpus shift это ещё один изменённый фактор, а не доказанная причина прироста или падения.
