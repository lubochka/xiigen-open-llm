## Стыковка с уже назначенным E2E

Предметный TranslationMachine вызывается по typed handoff [старого 20](../fixes-based-on-experiments/20-prompt-domain-e2e.md). JO/IDX сохраняют его checkpoint schema и outputs, QVA имеет отдельный RU→EN verifier profile, HNQ — отдельный KnnLogicalUnit и не является автоматической заменой executor-en_ru. E2E использует именно совпадающего получателя/направление/fixture, не выбирает «любой успешный translation checkpoint». Доказывать actual call/result/state provenance, а не строку выбранного домена. Для formatter/restart использовать сохранённые states выше; новые методы восстановления или повторное обучение только ради сводки не назначены.
