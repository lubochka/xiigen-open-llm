# 256. Warm-start sweep: что показывает 8→5 и чего не доказывает отсутствие роста

## Вопрос

Достаточны ли четыре запуска Table 16.9 для вывода о единственном спектральном аттракторе архитектуры?

Table 16.9 описывает MNLI-50k, двухслойный Q/K-split блок, MLM warm start, bidirectional embedding с $\theta=0.40$, seed 42 и **level-one protection rule**. В четырёх конфигурациях принятых growth events нет; pruning встречается только при $K_{\mathrm{init}}=8$. Это конкретное ограниченное наблюдение. Следующие утверждения 16.51–16.53 автор правильно маркирует `[CONJ]`, а отдельный convergence argument откладывает. [Table 16.9](../source/0643-0646-ch16-level-two-pruning-and-stabilisation.md#table-16-9), [Conjectures 16.51–16.53](../source/0643-0646-ch16-level-two-pruning-and-stabilisation.md#conjecture-16-51).

## Числа и прямые выводы

| Начальные головы | Итоговые головы | Принятый рост | Pruning | Accuracy |
|---:|---:|---:|---:|---:|
| 1 | 1 | 0 | 0 | 0.4413 |
| 2 | 2 | 0 | 0 | 0.4561 |
| 4 | 4 | 0 | 0 | 0.4692 |
| 8 | 5 | 0 | 3 | 0.4585 |

Во всех строках выполняется арифметический баланс $K_{\mathrm{obs}}=K_{\mathrm{init}}+n_{\mathrm{growth}}-n_{\mathrm{pruning}}$. Строка $8\to5$ демонстрирует принятие трёх pruning events. Строки $1,2,4$ демонстрируют отсутствие принятых архитектурных изменений за соответствующие запуски. Лучшее из четырёх опубликованных accuracy — $0.4692$ при четырёх головах; оно выше результата $8\to5$ на $0.0107$, то есть на **1.07 процентного пункта**. Без повторов и неопределённости нельзя превращать эту разность в статистический вывод.

## Отсутствие принятого роста не устанавливает причину

Conjecture 16.51 связывает $n_{\mathrm{growth}}=0$ с тем, что $\Gamma_{\mathrm{res}}$ ни разу не превысил $\theta_w$. Сами итоговые счётчики не показывают историю trigger: рост мог быть отключён выбранным protection-only режимом, отвергнут проверкой стабильности или другими условиями приёма. Нужны временные значения residual, порогов, eligibility и причин отклонения. Нулевой счётчик accepted events слабее утверждения об отсутствии любых trigger candidates.

Аналогично, конечная точка $8\to5$ не доказывает ни сходимость при большом времени, ни устойчивость к другим seed/threshold/init, ни basin of attraction. Если механизм умеет только уменьшать число голов, состояния ниже целевого бюджета могут оставаться неподвижными. Поэтому равенство $K_{\mathrm{obs}}=K_{\mathrm{pred}}^*$ в Conjecture 16.53 нельзя читать как достижимость одной и той же точки из всех инициализаций. [Conjecture 16.53](../source/0643-0646-ch16-level-two-pruning-and-stabilisation.md#conjecture-16-53).

## Число 5.7 и статус спектрального объяснения

Подпись таблицы получает $K_{\mathrm{pred}}^*\approx5.7$ из empirical $\Gamma_0$ и **calibrated** $\kappa_A$. Значения $\Gamma_0$ в четырёх строках существенно различаются: $3628.31,2446.91,1788.60,1508.88$. Поэтому проверяемый прогноз должен указать, какая строка, какой $\kappa_A$, какой порог и какое округление использованы. Без этих данных нельзя воспроизвести значение 5.7 или трактовать его как единую независимо определённую целевую ширину. Число голов целое; «$5\approx5.7$» — сопоставление масштабов, а не равенство точке фиксированного оператора.

Прямой rank-one deflation аргумент гарантирует удаление заранее определённой спектральной компоненты при росте. Обратное удаление обученной головы с общими параметрами не является автоматически обратной операцией; для pruning нужен контроль изменения coverage и качества. Формулировка источника «deflation argument run in reverse» такого контроля не предоставляет. [Обсуждение на PDF 646](../source/0643-0646-ch16-level-two-pruning-and-stabilisation.md#pdf-0646).

Наконец, данные собраны при level-one rule. Они не проверяют score (16.79), его сходимость или интерпретацию целевых голов как signed pairs. Автор прямо оставляет сопоставленные per-head пары для Volume II. Для ресурса проекта важно хранить этот статус рядом с таблицей и не выводить из неё доказанную экономию обучения либо эффективность ещё не испытанного level-two controller.
