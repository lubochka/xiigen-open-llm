# 131. Relative emergence: почему одного положительного margin недостаточно

[Индекс](../README.md) · [Definition 12.1](../source/0417-0424-ch12-sharpness-mixed-regimes-and-hessian.md#definition-12-1) · [Theorem 12.2](../source/0417-0424-ch12-sharpness-mixed-regimes-and-hessian.md#theorem-12-2) · [Доказательство](../source/0417-0424-ch12-sharpness-mixed-regimes-and-hessian.md#pdf-0418)

## Какие две величины действительно нужно контролировать

Для заданной поддержки строки $C_i$ книга различает внешний зазор $\Delta_i$: насколько худший логит внутри поддержки выше лучшего снаружи, и внутренний разброс $\rho_i$: насколько различаются логиты внутри поддержки. Первый отвечает за уход вероятности из нежелательных столбцов. Второй отвечает за близость оставшейся вероятности к **равномерному** распределению на всей поддержке.

Определение (12.2) объединяет их в $\kappa_*=\min_{i\in I}\Delta_i/(1+\rho_*)$, где $\rho_*=\max_{i\in I}\rho_i$. Здесь $\kappa_*$ — константа emergence; исходный символ $\kappa$ также обозначает размер поддержки, и эти значения нельзя смешивать. Для положительности нужны строгие внешние зазоры. Отсутствие строго лучшего внешнего столбца допускает равенство и само по себе не даёт $\kappa_*>0$.

При масштабировании всех логитов на $a>0$:

$$
\kappa_*(aL)=\frac{a\Delta_*}{1+a\rho_*}.
$$

Поэтому фраза источника о неизменности при rescaling не следует из определения: добавленная единица нарушает однородность. При полном support $\kappa=n$ внешний максимум по пустому множеству требует отдельного соглашения; при пустом $I$ требуется отдельно определить минимум.

## Контрпример к Theorem 12.2

Теорема утверждает близость к каноническому gate **для всех достаточно больших** $\beta$. При фиксированном положительном внутреннем разбросе это неверно: увеличение $\beta$ одновременно подавляет внешние столбцы и усиливает предпочтение одного столбца внутри поддержки.

Редакторский пример, не эксперимент из книги: $n=d=3$, $X=I_3$, $d_k=1$ и

$$
L=M=\begin{pmatrix}2&1&0\\0&0&0\\0&0&0\end{pmatrix}.
$$

Активна только первая строка, её support — первые два столбца; остальные строки gate равномерны. Тогда $\Delta_1=1$, $\rho_1=1$, $\kappa_*=1/2$. При $\varepsilon=0.1$ напечатанная формула (12.3) даёт $\beta^*\approx15.24975$. Но при $\beta=20$:

$$
\lVert\operatorname{softmax}_{\mathrm{row}}(20L)-\operatorname{Gate}(p)\rVert_F
\approx0.70710678>0.1.
$$

При $\beta\to\infty$ первая строка стремится к $(1,0,0)$, а gate требует $(1/2,1/2,0)$; предельная ошибка равна $1/\sqrt2$. Неактивные строки в примере точно равномерны при любом $\beta$, поэтому ошибка не связана с ними.

## Где ломается доказательство и что можно использовать

Сам источник на PDF 418 получает одновременно **нижнее** ограничение на $\beta\Delta_i$ и **верхнее** ограничение на $\beta\rho_i$, (12.6)–(12.8). При $\rho_i>0$ это конечный допустимый интервал, который может быть пуст. Он не превращается в условие $\beta\ge\beta^*$.

Дальше доказательство меняет направления неравенств. Например, из $\Delta_i\ge\kappa_*(1+\rho_i)$ следует $\Delta_i-\kappa_*\ge\kappa_*\rho_i$, а на PDF 419 используется обратная оценка. Нижняя граница $\beta\Delta_i\ge T'$ также не даёт верхней границы экспоненты через $e^{T'}$. Отдельно сумма двух слагаемых, каждое $\le\varepsilon/\sqrt{2n}$, ограничена $\sqrt2\varepsilon/\sqrt n$, а не $\varepsilon/\sqrt n$.

Безопасный вариант использования исходной построчной оценки (12.5): выбрать бюджет ошибки $\delta=\varepsilon/\sqrt n$ и проверить **обе** достаточные границы

$$
2(n-\kappa)e^{-\beta\Delta_i}\le\delta/2,
\qquad
\frac{e^{\beta\rho_i}-1}{\sqrt\kappa}\le\delta/2.
$$

Неактивные строки проверяются отдельно. Для фиксированного $L$ их равномерный предел при $\beta\to\infty$ требует постоянных логитов по строке; «inactive» как имя в $p$ этого свойства не создаёт. При точно равных логитах внутри всех активных supports, положительных внешних margins и точно плоских неактивных строках препятствие исчезает, и экспоненциальная оценка через внешний margin действительно доступна.

## Значение для проекта

Margin и flatness следует сохранять раздельно. Нельзя делать из напечатанного $\beta^*$ автоматическое правило температуры, числа шагов обучения или достижения нужного gate. Сама статическая оценка не связывает изменение температуры с ходом оптимизатора. В этом пакете проверена формулировка; модель Xiigen по ней не обучалась.
