# 351. Related work: четыре оси сравнения и статус утверждения о новизне

## Вопрос

Что можно извлечь из Table 19.5, не превращая авторский обзор в доказанный приоритет?

**Таблица полезна как карта конструкции оператора; отсутствие всех четырёх признаков у перечисленных работ не доказывает отсутствие такого метода во всей литературе.** В этом проходе перенесён обзор рукописи, новый систематический поиск литературы не проводился. [Семь семейств](../source/0781-0784-ch19-growth-closure-variants-and-related-work.md#section-19-8), [Table 19.5](../source/0781-0784-ch19-growth-closure-variants-and-related-work.md#table-19-5).

## Четыре вопроса автора

1. Есть ли билинейное взаимодействие между токенами?
2. Выбираются ли партнёры через content-dependent token-to-token top-$k$?
3. Есть ли несколько heads?
4. Заменяет ли единый блок одновременно MHA и MLP?

Текст отдельно сопоставляет фиксированный spatial mixing в gMLP, gates внутри FFN, routing к экспертам и разреживание attention. Для использования в проекте полезно сохранять эти оси отдельно: слово “gating” само по себе не указывает ни объект маршрутизации, ни часть архитектуры, которую заменили.

## Внутренняя неоднозначность заголовков

Столбец “Bilinear cross-token” содержит для SwiGLU “yes (within token)”. Уточнение в скобках фактически исключает буквальный cross-token критерий. Поэтому эту ячейку нельзя превращать в Boolean “cross-token = true” без отдельного решения о схеме данных. Аналогично static spatial mixing и content-dependent выбор должны оставаться разными полями.

Список четырёх осей в прозе включает multi-head structure, тогда как четыре содержательных столбца Table 19.5 выделяют отдельно bilinear cross-token и cross-token data dependence, а отдельного multi-head столбца нет. Таблица не является механически идентичной формализацией вводного списка.

## Граница вывода

Фраза “To the best of our knowledge” ограничивает novelty claim знаниями автора; строки про UMoE и другие методы сохраняются как атрибуция рукописи. Таблица сама по себе не сравнивает качество обучения, память, throughput, причинность, hardware kernels или режим pretraining.

Утверждение подписи, что anchors разрешают остаточную permutation symmetry, должно читаться вместе с точными условиями аудита главы 19. Одновременное переименование heads и их anchors остаётся переименованием dictionary atoms; таблица не доказывает глобальную идентифицируемость всех параметров.
