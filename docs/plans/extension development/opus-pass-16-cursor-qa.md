## Ключевые факты

**Path B «live desktop» = headless extensionTests, не видимая сессия.** Единственный реальный запуск Cursor.exe (RUNTIME-03, 2026-06-18) в launch-summary имеет команду `Cursor.exe --extensionDevelopmentPath … --extensionTestsPath …runtime03-extensionHostQA.js --user-data-dir … --headless --new-window`. Это Extension **Test** Host в `--headless` — автоматический JS-прогон внутри extension host без видимого chat UI. `mirror.json` штампует `full_cursor_chat_ui_proven:false`, verdict `PASS_NARROW_CURSOR_EXTENSION_HOST_COMMAND_TARGET_LOCATOR_AND_ERROR_PATH_ONLY_PARENT_REVIEW_PENDING`. По всему репо `find *.png/*.jpg/*.mp4/*.gif` → 0. Значит требование dual-path Path B (локальный desktop с видимым маркером + скриншот/видео) не выполнено конструктивно: «десктоп»-доказательство — headless-харнес без рендера.

**Сильнейший «прошедший» Cursor host-QA исполнен в VS Code, не в Cursor.** `host-impl-cursor-01-summary.json` `successful_runner:"VS Code Extension Host dev-load path for Cursor extension repository"`, чек `code.cmd --extensionDevelopmentPath … --headless` = `PASS_BY_EXTENSION_HOST_REPORT`; прямой `Cursor.exe --extensionTestsPath … --headless` = `NO_REPORT_NOT_COUNTED_AS_PASS`. `claims_not_proven[0]="Full Cursor UI/chat participant invocation through a user-visible Cursor chat surface"`. То есть корректность Cursor-хоста доказана через VS Code-суррогат.

**Панель (единственная видимая UI-поверхность Cursor) ни разу не гонялась в реальном Cursor.** В RUNTIME-03 (реальный Cursor.exe) `extension-host-report.json` `panel_case:null`. Артефакты `xiigenSmartSkills.panel-*` есть ТОЛЬКО под `HOST-IMPL-CURSOR-01/vscode-extension-host/…` (то есть в VS Code). Так что поверхность, способная дать видимый desktop Path B (webview-панель), в настоящем Cursor не покрыта.

**«Phase 10 Cursor full extension live proof» никогда не исполнялась и гоняет test-only команду.** `test/phase10/phase10CursorFullExtensionProof.js:54` ассертит `entrypointName==="xiigenSmartSkills.runtimeProof.invoke"` — это команда с title «…Runtime Proof Harness (Test Only)» (P13 gap-4), а не пользовательские `xiigen.smartSkills.select`/`xiigenSmartSkills.panel`. Выходная папка `reports/PHASE-10-cursor-proof/` ОТСУТСТВУЕТ → харнес ни разу не прогнан. Даже если бы прогнали: `assertCommonResult` (`:51-138`) проверяет entrypointInvoked/имя/тип, `semanticQualityClaimed===false` (ожидаемо!), совпадение correlation id, redaction (sentinel не утёк), наличие файлов — но НИ РАЗУ не сверяет содержимое ответа с эталоном. JSON-verdict `PHASE_10_CURSOR_PROOF_READY_FOR_REVIEW`, `passed:true`; RU-отчёт «Итог runner: PASS_PENDING_REVIEW».

**Ни одного oracle корректности ответа во всей Cursor-QA.** grep по `test/` показывает: единственные ассерты о содержимом ответа — `assert.strictEqual(result.semanticQualityClaimed, false, …)` (HOST-08B:40, HOST-08D:48, HOST-08H:48, HOST-IMPL-CURSOR-01:90, FRDP-row12:123/183/187). То есть QA доказывает, что расширение НЕ заявляет ум, а не что ответ верный. checks-mirror RUNTIME-03 — 7 проверок: targeted extension host runtime, JSON.parse, JSONL.parse, UTF-8, `git diff --check`×2, process cleanup — всё плумбинг. Реальный видимый «ответ» в live-runtime (`…entrypoint-response…:concreteAnswer`) = редактированный дамп «Adaptive task+plan+skills ready. Semantic quality is not claimed.\r\nxiigen prompt-to-task :\r\ninput: {…}\r\noutput: {…"selectedSkills":[],"warnings":["…No available skills were provided by the host."]…}» — плумбинг-дамп, `selectedSkills:[]`, `NO_AVAILABLE_SKILLS_PROVIDED`, `runtimeExtensionClaimed:false`.

**Все Cursor-QA вердикты — PASS_PENDING_PARENT_REVIEW / PARENT_REVIEW_PENDING (не приняты).** HOST-08B `verdict:PASS_PENDING_PARENT_REVIEW`, HOST-08H `verdict:PASS_PENDING_PARENT_REVIEW`, RUNTIME-03 mirror `..._PARENT_REVIEW_PENDING`, phase10 `..._READY_FOR_REVIEW`. Ни один не имеет записанной приёмки родительским ревью; board (STATUS-BOARD:26 PARTIAL по фазе 6) опирается на непринятые pending-review проходы.

**QA-набор осиротевший (нельзя перезапустить как гейт).** `package.json` `scripts={install-smoke, verify-docs-final-coverage-nonhost}`, `dependencies:{}`, `devDependencies:{}`; `.github` отсутствует; нет `test`-скрипта и тест-раннера (node --test/vitest/jest/mocha). 10 QA-файлов запускаются только ad-hoc через host `--extensionTestsPath` или `node --check`. Контраст с Claude (P12: файлов не было вовсе) — здесь файлы есть, но нет упряжи/CI, чтобы гонять их как повторяемый гейт.

Замечание про негативное покрытие: у Cursor ЕСТЬ один controlled-error кейс (`CORE_ENDPOINT_MISSING`) в RUNTIME-03 и в HOST-IMPL — поэтому «нет негативных кейсов» (как у Claude P12) для Cursor НЕ заявляю; дыра точнее — негатив только транспортный, не семантический/degraded-answer.
