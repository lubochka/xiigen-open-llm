## Meaning of the columns

- "Автоматизированный контур / ядро / программный интерфейс приложения (Application Programming Interface, API)" means command-line or harness evidence that reaches `llm_mvp_core`, its core service, tests, or schema contracts.
- "Локальная реальная программа" means Claude, Cursor, or Codex installed/local host UI evidence for the actual scenario interaction. Opening JSON/log/result files, showing only a marker, screenshotting a debug artifact, proving only that the host opened, or reporting handler-level proof as UI proof is rejected.
- "Dual-Path Same-Scenario UI Proof" means the same scenario twice: Path A through the automated pre-host/core/adapter path and Path B through the real local host UI, using the same user prompt/task, expected behavior, selected skills/plan or response contract, and result comparison. The marker/correlation id is tracing only.
- "Host Session Auth Preflight and Browser Login Recovery" means the real host UI path cannot count until signed-in state is visible and verified. If Cursor opens anonymously, logged out, wrong-account, or session-lost, the next action is browser login recovery with no secrets captured, or human-assisted login when credentials are required.
- "No-Blind-Spot UI Scenario Script" means the scenario must describe scenario id, purpose, required qa/testing skills, exact launch/auth/actions/input/expected UI/evidence/status/branches, and forbidden substitutions before execution. agent judgment is not a scenario step.
- "50-Pass Scenario Clarity Review" means the scenario script must have 50 explicit checks or review passes before execution. Each check asks whether an agent could still make a judgment call not described by the scenario; any gap returns to planning repair.
- "Plan-Not-Ready Is Repair Loop, Not Stop" means plan not ready is not a stop. Do not execute an unready plan; return to architecture/planning repair loop with required skills/context and bounded subagents when required.
- "Joined status" means whether the automated/core/API evidence and local real-program UI evidence are accepted together for the same scenario under the Dual-Path Same-Scenario UI Proof rule.
- A status that is not a full joined pass is never terminal here; it always creates the next concrete work item.
