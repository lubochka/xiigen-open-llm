## Ключевые факты
- **Claude-host НЕ содержит ни одной команды/функции export/import/backup/share/continue-training.** `package.json` scripts = только `install-smoke`; `.claude-plugin/plugin.json` экспонирует только `hooks.SessionStart`; `src/claude-entrypoint.js` grep на `export|import|backup|restore|continueTrain|adaptive`-функции → только node-import’ы модулей. `contributes.commands` нет (это Claude-plugin, не VS Code).
- **Core two-leg lifecycle РЕАЛЬНО реализован, но вызывается ТОЛЬКО тестами.** `Phase08CommonUserTwoLegLifecycle.cs:505` пишет `personal-adaptive-checkpoint.json`, `:583/:588` читает `imported-adaptive-checkpoint.json` в `.xiigen/{sphere}/`, `:668` `ContinueTrainingFromCheckpoint(...)`. Вызыватели (`git grep`) = `Tests/Phase08CommonUserTwoLegLifecycleTests.cs`, `Tests/SkillSelectionPhase06TrainedSelectorEvidenceTests.cs`. Граница расширения `XiigenExtensionApiService.cs` ссылается на Phase08/ContinueTraining/export/import **0 раз**. То есть lifecycle — оттестированная библиотека без единого рантайм/host-вызывателя.
- **Метод `feedback` — единственный путь online-сигнала пользователя в адаптивную модель — объявлен, но не реализован.** Контракт: `XiigenExtensionApiContracts.cs:64` `FeedbackMethod="feedback"`, `:248-263` схема (`feedback_class`,`chosen_ref`,`rejected_ref`,`prompt_sha256`,`response_ref`,`correction_ref`), `:282` boundary-rule `feedback_routes_refs_only_to_user_local_adaptive_dpo_signal_creation`. Сервис `XiigenExtensionApiService.cs` — grep `feedback` = **0**; диспетчер `:962-974` для незнакомого метода даёт дефолт `"Method {method} produced task, plan, and skill evidence."` → для `feedback` вернётся task/plan/skills, а НЕ создание DPO-сигнала. Claude-hook без `-Method` (P10) ⇒ `feedback` из Claude никогда не вызывается. Итог: пользовательские правки/предпочтения не превращаются в adaptive DPO-сигнал — цикла обучения нет.
- **Рантайм-путь Claude — read-only, ноль мутации адаптивной модели по построению.** Даже при загруженном adaptive-state core печатает (`XiigenExtensionApiService.cs:822`) «user adaptive asset path may be loaded, but this response makes no learnability claim» и эмитит `USER_ADAPTIVE_SKILL_SELECTION_FALLBACK_NO_MODEL_MUTATION` (`:26-27`). Claude-отчёты подтверждают: `reports/CL-03-debug-display-evidence.json:144` «No user/adaptive learning mutation; debug flag only», `reports/CL-04-smoke-trace-report.json:134` «No adaptive/user learning mutation.» ⇒ «локальная модель учится» на Claude-рантайме недостижимо.
- **Claude-entrypoint конфликтует common-promotion staged root и per-user adaptive root.** `src/claude-entrypoint.js:239-243`: `userRoot = options.UserAdaptiveAssetRoot || env || raw?.activated_asset_root || raw?.UserAdaptiveAssetRoot`. Поставляемый локатор `qsg28-two-unit-test-locator.json` НЕ имеет поля `UserAdaptiveAssetRoot`, а имеет `activated_asset_root` (`:11`, это staged ОБЩИЙ two-unit target-root для promotion prompt-to-task+skill-selection) и `production_locator_update_done:false` (`:6`). Значит Claude-«adaptive/personal leg» либо пуст, либо указывает на общий тестовый target — реального per-user adaptive-состояния не подключено.
- **Claude-evidence сам объявляет adaptive lifecycle вне области расширения.** `phase40-claude-core-request.json:36` `adaptiveAssetRef:"claude-host:runtime-adaptive-ref-not-owned-by-extension"`, `:38` `adaptiveOwnedByHostOrProject:true`; `phase40-claude-install-smoke-report.json:57-58` `adaptive_state_root_ref:"claude-host:adaptive-state-runtime-root-outside-package"`, `project_local_state_ref:"project-local:adaptive-skill-state-outside-host-package"`. То есть расширение своей же декларацией снимает с себя владение adaptive/backup/export/import/continue-training — это противоречит R5 и Full Extension Definition.
- **Рантайм-загрузка checkpoint на Claude-пути ЛОМАЕТСЯ для 1 из 3 машин.** `reports/HOST-IMPL-01-probe/debug-on/xiigen-response.json:22` `orchestration_reasoning_load_error:"ORCHESTRATION_REASONING_MANIFEST_CHECKPOINT_REF_MISMATCH"`, `:40` «OrchestrationReasoning common asset load skipped/failed…» (то же в `debug-off/` и `install-smoke/phase40-claude-entrypoint-response-1.json:22`). Загрузка существующего checkpoint — предусловие continue-training — сломана для OrchestrationReasoning на Claude-рантайме.
