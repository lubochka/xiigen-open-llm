## Ключевые факты прохода
1. **У Codex ЕСТЬ настоящая плагин-система, но она marketplace-only, и XIIGen в ней НЕТ.** Реальный `codex-cli 0.136.0-alpha.2` (`CX-04R-host-runtime-path-report.json` `discovered_local_codex_cli.version`) имеет `codex plugin add/list/marketplace/remove` (decoded `local-codex-plugin-help.stdout.log`: «Install a plugin from a configured marketplace snapshot»). `codex plugin list` (decoded `local-codex-plugin-list.stdout.log`) перечисляет установленные плагины `documents/spreadsheets/presentations@openai-primary-runtime`, `browser@openai-bundled` + сотни `@openai-curated` — **`xiigen`/`codex-xiigen-smart-skills` отсутствует полностью** (grep xiigen → 0). `HOST-08F-codex-plugin-app-qa.json` сам фиксирует `plugin_runtime_discovery.codex_plugin_command_scope:"marketplace_management_only_from_help"`, `direct_local_plugin_app_invoke_path_found:false`. Значит: (а) команды «invoke локально-авторского плагина» в Codex нет — только управление marketplace; (б) `.codex-plugin/plugin.json` — НЕ тот формат, что Codex потребляет (Codex читает marketplace-snapshot `marketplace.json` под `~/.cache/codex-runtimes/.../.agents/plugins/`); (в) XIIGen-плагин никогда не был зарегистрирован/установлен в реальную систему. Собственный вердикт сессии: `CX-04R-host-runtime-path-report.json` `passed:false`, `verdict:"BLOCKED_OP13_NO_SAFE_NON_AI_CODEX_PLUGIN_HOST_INVOCATION_PATH"`, `true_codex_host_runtime_path_found:false`, `plugin_loaded_invoked:false`.

2. **`runCli` не выводит видимый ответ и debug-дисплей — печатает сырой (пустой) stdout PowerShell.** `src/codex-entrypoint.js:528-539` `runCli` вызывает `invokeXiigenCore(...)`, затем пишет только `result.stderr` (`:531`) и `result.stdout` (`:535`) — это сырой stdout дочернего `powershell.exe`. Он НИКОГДА не вызывает `createVisibleAnswerDisplay` (`:410-441`) или `createDebugTraceDisplay` (`:393-400`). Но `xiigen-extension-core-api.ps1` пишет ответ в ФАЙЛ `-ResponsePath`, а не в stdout ⇒ stdout процесса пуст. Отсюда прямое объяснение P08-наблюдения `phase40-codex-host-session-run{,-2,-3}.stdout.jsonl = 0 байт`: пользователь Codex не увидел бы ничего. Весь код построения видимого ответа/redacted-debug — экспортируемый мёртвый (только для тестов).

3. **Три расходящихся Codex-манифеста с противоречивым статусом.** `package.json` (Jun17, v0.1.1): `codexXiigenSmartSkills.packageShapeOnly:false`, `requestWiringImplemented:true`, `sourceEntrypoint:"src/codex-entrypoint.js"`, `powershellEntrypointAcceptedAsImplementation:false`. `.codex-plugin/plugin.json` (Jun16, v`0.1.0+codex.runtime04e-20260616-231500`): plugin-манифест со `skills:./skills/`, `interface.capabilities:[Interactive,Write]`, `defaultPrompt`. `.codex/xiigen-smart-skills.json` (Jun3, v`0.0.0-phase40-skeleton`): `phase40.implementation_status:"skeleton_only"`, `runtime_evidence:false`, `entrypoint_implemented:false`, `install_smoke_status:"not_run"`, а `entrypoint.implementation_file:"src/codex-entrypoint.ps1"` (тот PS1, который package.json объявляет `legacy_launcher_only` / НЕ принят как реализация). Три версии (0.1.1 / 0.1.0+ / 0.0.0-skeleton) и прямое противоречие «реализовано vs skeleton_only/not_run».

4. **`debug`-настройка `xiigenSmartSkills.debug` — только метаданные.** `package.json:56-63` debugSetting; `xiigen-extension-contract.json:53-62` debug_trace_contract; но `DebugEnabled` читается ИСКЛЮЧИТЕЛЬНО из CLI-флага `--debug-enabled` (`codex-entrypoint.js:504`); ни в `.codex-plugin/plugin.json`, ни в `.codex/xiigen-smart-skills.json` нет секции settings; Codex-командной поверхности, которая пробросила бы флаг, нет (см. факт 1). Плюс дисплей всё равно мёртв (факт 2). ⇒ redacted debug trace недостижим для пользователя Codex.

5. **Механизм «installed plugin» = LLM-агентский SKILL.md, который вручную шеллит `node .\src\codex-entrypoint.js`.** `skills/xiigen-smart-skills/SKILL.md` «Smoke Invocation» инструктирует Codex-агента запустить `node .\src\codex-entrypoint.js --method prompt-to-task ...` с явными evidence-путями; зависит от `C:\Projects\llm_mvp_core`. `.codex-plugin/plugin.json:14` `skills:./skills/`, `:21-24` `capabilities:[Interactive,Write]`, `:25-28` `defaultPrompt` — не потребляются ни одним доказанным Codex-host-путём (`HOST-08F` `full_plugin_ui_evidence:false`).

6. **Единственный непустой phase40 host-session run вызывает `codex-entrypoint.ps1` с несуществующими параметрами; 3 из 4 упали.** `phase40-codex-host-session-run-4.stdout.jsonl` (UTF-16) — Codex-CLI `command_execution` запускает `powershell.exe -Command powershell.exe -NoProfile ... -File .\src\codex-entrypoint.ps1 -ConcreteTask "..." -Prompt "..." -CoreRoot "..." -OutputPath "...\entrypoint-response.json" -TracePath "..."`. Но committed `src/codex-entrypoint.ps1` (param-блок `:2-26`) объявляет `-Method/-UserPromptOrTaskText/.../-RequestPath/-ResponsePath/-TracePath` — параметров `-ConcreteTask`, `-Prompt`, `-OutputPath` там НЕТ (при `[CmdletBinding()]` они были бы отклонены). Внутренний `command_execution` даёт `aggregated_output:""`, `exit_code:null`; `-4.last-message.txt`=«Shell exit code 0; XIIGEN_CODEX_HOST_SMOKE_DONE» (внешний echo). Runs 1/2/3: `phase40-codex-host-session-run{,-2,-3}.stderr.log` = `codex.exe : error: unexpected argument '-a' found` (malformed `codex exec`). Значит phase40-«host session» = double-powershell echo-smoke против РАСХОДЯЩЕГОСЯ параметр-контракта ps1, 3/4 прогонов — ошибка codex.exe.

7. **Два разных Codex-бинаря/версии; «runtime» гоняет node из installed-cache КОПИИ; model-backed путь Access denied.** `RUNTIME-04-codex-live-runtime-mirror.json`: `codex_executable:"C:\Program Files\WindowsApps\OpenAI.Codex_26.609.4994.0_x64__...\codex.exe"` — иной, чем discovery `C:\Users\lubao\AppData\Local\OpenAI\Codex\bin\...\codex.exe` v`0.136.0-alpha.2` (`CX-04R`); `installed_cache_root:"C:\Users\lubao\.codex\plugins\cache\xiigen-local\codex-xiigen-smart-skills\0.1.0+codex.runtime04e-20260616-231500"`, `cache_entrypoint:"...\src\codex-entrypoint.js"` (node из копии); `codex_cli_shell_scope:"Access denied; not used for model-backed send-message."`; `proof_scope:"narrow installed-cache/plugin-entrypoint runtime evidence only; full Codex chat UI unproven"`. То есть «инсталляция» = копия файлов репо в cache-каталог + ручной node, а НЕ загрузка/инвокация через Codex-хост.

8. **`createTargetLocator` выводит per-user adaptive-root строковым сканом ПЕРВОГО common target-ref.** `codex-entrypoint.js:279-284` userRoot fallback-цепочка `... ?? raw?.activated_asset_root ?? raw?.UserAdaptiveAssetRoot ?? ... ?? inferAssetRoot(targetRefs)`; `inferAssetRoot` (`:211-220`) берёт первый строковой ref, содержащий `/(prompt-to-task|orchestration-reasoning|skill-selection)/`, и режет путь до маркера. Итог: personal adaptive leg склеивается с common promotion target (`activated_asset_root`) и/или выводится из COMMON target-refs — настоящего пользовательского adaptive-состояния не подключено (Codex-инстанс дефекта, усиленный inferAssetRoot-эвристикой).
