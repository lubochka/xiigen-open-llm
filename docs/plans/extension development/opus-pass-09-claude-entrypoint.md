- **core-API путь реально доходит до компилированного .NET-ядра** — но тяжеловесно и непереносимо. `claude-entrypoint.js:495` `spawnSync("powershell.exe", … coreEndpoint)`, где `coreEndpoint = coreRoot/tools/xiigen-extension-core-api.ps1`. Этот PS-скрипт (`:112-187`) генерирует ВРЕМЕННЫЙ csproj `XiigenExtensionCoreApiInvoker.csproj`, пишет C#-Program `new XiigenExtensionApiService(coreRoot); service.ProcessHostExtensionRequest(request)` и делает `dotnet run --project … -- <req> <resp> <coreRoot>`, затем удаляет temp в `finally`. То есть каждый вызов = отдельная сборка+прогон .NET через дочерний PowerShell → требует .NET SDK + полный core-репозиторий на той же машине + Windows PowerShell. Реальная граница `XiigenExtensionApiService` вызывается, но не как поставляемый сервис-транспорт.
- **Claude-сторона НЕ делает никакого семантического решения** (это корректно по R6/thin-adapter): `buildRequest` только собирает `XiigenExtensionRequest` (`HostName:"Claude"`, `HostType:"claude-code"`, `Method:"prompt-to-task"`, HostFacts `host_semantic_ranking:false` и т.д.), пишет request-JSON, зовёт core, читает response-JSON, печатает `ChatDisplayText` в stdout. Ветвления по хосту нет (как и в ядре — см. P03).
