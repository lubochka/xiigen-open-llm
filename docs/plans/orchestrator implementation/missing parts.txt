The concept you are remembering is called Teaching-Runtime Symmetry, proved in E51B. The idea is this: the same compiler pipeline that processes a developer's prompt at runtime should also be used to process the training examples at teaching time. If teaching uses one representation and runtime uses a different one, the trained unit learns to recognise patterns it will never see again at inference time.
E51B proved this with SymmetryInspection: it takes a teaching record and a held-out runtime record, runs both through the same Compile function, and measures predicate overlap. If the overlap is high, the unit will generalise from training to runtime. If it is low, the unit learned from a different feature space than it will encounter in production.
The feature vector contract from E51B is concrete: 60 slots — 22 predicate counts, 5 domain slots, up to 32 normalised roots, and 1 decomposition-count slot. Both teaching examples and runtime prompts must produce vectors in this exact same space.
