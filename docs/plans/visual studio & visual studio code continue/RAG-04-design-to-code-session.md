### 7.Г Блок DPO (проходы 26-29) — САМАЯ ГЛУБОКАЯ находка

**Якорь базиса «11.DPO не referenced доменом» — ЗАКРЫТ:** мост `DesignConversionDpoPolicyCheckpointBridge`
реально вызывает настоящий `DpoTrainer.StepVector` с DPO-loss `-log σ(β·margin)`, sigmoid, ручным
backward, AdamW (`11.DPO/DpoTrainer.cs`). Формулы 11.DPO НАСТОЯЩИЕ. НО «обучение» на маршруте домена
**гарантированно пусто ЧЕТЫРЕЖДЫ независимо**:

- **Н26-1 (HIGH, математически мёртвый шаг):** `EncodeIds` берёт первые `PolicyContextLength=64` UTF-8
  байта строки `"{prompt} {chosen}"`, но prompt-префикс (`"design-conversion "`+unitId+64-hex sha) уже
  ≥95 байт → различающий суффикс (`chosen`/`rejected`) НИКОГДА не в окне → `ChosenIds ≡ RejectedIds`
  байт-в-байт → margin≡0 → градиенты сокращаются ТОЧНО в ноль. Единственное движение весов = weight
  decay AdamW (1−1e-7). Sha этого чекпойнта затем «сертифицирует» DPO-обучение.
- **Н27-3 (один шаг):** `StepVector(batches, 1)` вызывается ОДИН раз, lr=1e-5, policy НИКОГДА не
  warm-start-ится (cold-start от случайной инициализации). Почини усечение — тренировки всё равно нет.
- **Н27-2 (шумовой reference):** мост создаёт policy и reference как два НЕЗАВИСИМЫХ `new LlmModel` —

  ≠ копия policy; DPO-награды β(logπ_pol−logπ_ref) стартуют как межмодельный шум. Тест-хелперы ЗНАЮТ
  предусловие (`CopyWeights`), мост его пропускает.

  предпочитать REJECTED. ПРОТИВОРЕЧИЕ-ОРАКУЛ: тест репо `StepMany_...ImprovesRewardMargin` утверждает
  РОСТ — по выводу обязан падать; тест+код добавлены ОДНИМ коммитом `777ead8df` без свидетельств
