## Как проверять

Использованы только команды чтения (ничего не пишется на диск и не двигается на сервере):

- `git log` (история коммитов) — посмотреть, какие коммиты лежат на ветке и в каком порядке.
- `git ls-remote` (спросить сервер GitHub о вершинах веток, ничего не скачивая) — узнать реальную серверную вершину ветки без загрузки данных.
- `git merge-base` (общий предок двух веток) — найти точку, от которой две ветки разошлись.
- `git rev-list --count` (число коммитов между точками) — посчитать, на сколько коммитов одна точка опережает другую.
- `git merge-tree --write-tree` (проверка слияния «на бумаге», без касания файлов) — смоделировать слияние и увидеть конфликты, не трогая рабочую копию.
- `git status --porcelain` (список несохранённых изменений) — увидеть, что в рабочей копии не сохранено.
- `git worktree list` (список рабочих копий) — перечислить все привязанные к репозиторию рабочие копии.

Предупреждение: ветки `DesignToCode-clean` и `codex/dpo-implementation` двигаются ежедневно/почасово — перед любой сверкой сначала `git ls-remote`, а не локальный `git log` (локальная ссылка отстаёт без `git fetch`).
