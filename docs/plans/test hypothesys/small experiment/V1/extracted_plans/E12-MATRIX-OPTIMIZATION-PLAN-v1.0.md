# E12 — Оптимизация умножения матриц (разреженность + SIMD)
## Experiment Plan v1.0 · LlmFromScratch.sln

**Вопрос:** насколько специализированные алгоритмы умножения матриц
ускоряют N-граммные таблицы и зонд-нейросеть?

**Этот документ не касается XIIGen.**

---

## Где умножение матриц сейчас

В N-граммных экспериментах (E01-E07) матрицы не используются явно,
но неявно присутствуют:
- N-граммная таблица: `counts[prev][next]` — это разреженная матрица счётчиков
- `ArgmaxCount()` — поиск максимума в строке матрицы
- K-Means (E01): умножение матриц при вычислении расстояний до центроидов

В зонд-нейросети (E11): матричное умножение — главная операция:
- `W_embed × one_hot` → embedding lookup
- `W1 × input` → первый слой
- `W2 × hidden` → второй слой

## Три оптимизации

### Оптимизация 1: Разреженное хранение N-граммных таблиц

Сейчас N-граммная таблица хранится как плотный массив `int[][]`:
```csharp
// Текущий код (плотный):
var cooccur = new int[vocabSize][];
for (int i = 0; i < vocabSize; i++) cooccur[i] = new int[vocabSize];
// При vocab=512: 512×512 = 262 144 ячеек, большинство = 0
```

Заполненность типичной N-граммной таблицы: 2-5%
(на 410K токенов с vocab=512 реальных пар намного меньше чем 262K).

**CSR (Compressed Sparse Row) формат:**
```csharp
// SparseNgramTable.cs — хранит только ненулевые значения
public sealed class SparseNgramTable
{
    // Для каждой строки (prev token): только токены которые реально следовали
    // Dictionary вместо плотного массива
    private readonly Dictionary<int, Dictionary<int, int>> _data = new();

    // ArgmaxRow: найти следующий токен с максимальным count
    // Итерируем только по ненулевым — O(k) где k << vocab_size
    public int ArgmaxRow(int prev)
    {
        if (!_data.TryGetValue(prev, out var row)) return 0;
        return row.MaxBy(kv => kv.Value).Key;
    }

    // Память: O(actual_pairs) вместо O(vocab²)
    // Скорость поиска: O(k) вместо O(vocab)
    // где k = среднее число уникальных следующих токенов для данного предыдущего
}
```

**Ожидаемое ускорение:** 10-50× на ArgmaxRow при заполненности 2-5%.

### Оптимизация 2: SIMD для зонд-нейросети

Современные процессоры умеют обрабатывать 8-16 float за одну инструкцию
(AVX/AVX-512). .NET предоставляет это через `System.Numerics.Vector<T>`.

```csharp
// SimdMatMul.cs — умножение матрицы на вектор с SIMD
public static class SimdMatMul
{
    // Умножить матрицу rows×cols на вектор длиной cols
    // Результат: вектор длиной rows
    // Использует Vector<float> для обработки по 8 float за раз
    public static float[] MatVecMultiply(float[] matrix, float[] vector,
                                          int rows, int cols)
    {
        var result = new float[rows];
        int vectorSize = Vector<float>.Count;  // 8 на AVX, 16 на AVX-512

        for (int row = 0; row < rows; row++)
        {
            float sum = 0;
            int col = 0;

            // Обрабатываем vectorSize элементов за раз
            for (; col <= cols - vectorSize; col += vectorSize)
            {
                var matVec = new Vector<float>(matrix, row * cols + col);
                var inVec  = new Vector<float>(vector, col);
                sum += Vector.Dot(matVec, inVec);
            }

            // Остаток (если cols не кратен vectorSize)
            for (; col < cols; col++)
                sum += matrix[row * cols + col] * vector[col];

            result[row] = sum;
        }
        return result;
    }
}
```

**Ожидаемое ускорение:** 4-8× для матриц с размером ≥ 64×64.
Для маленьких матриц (< 32×32) overhead может съесть выигрыш.

### Оптимизация 3: Структурированная матрица для embedding-слоя

Если токены упорядочены по семантической близости (например,
все MethodDeclaration-типы стоят рядом), то embedding-матрица
становится приближённо Toeplitz (сдвиговая инвариантность).

Умножение Toeplitz-матрицы на вектор через FFT: `O(n log n)` вместо `O(n²)`.

```
Условие применимости:
  - Токены отсортированы по типу AST узла (все MethodDecl рядом)
  - vocab ≥ 256 (для FFT выгода ощутима)
  - Применимо только к embedding-слою, не ко всем слоям
```

Это экспериментальная оптимизация — тестировать последней.

## Структура эксперимента E12

Три под-эксперимента, каждый измеряет время:

```
E12a: SparseNgramTable vs PlainArray на N-грамм предсказании
  Метрика: время ArgmaxRow на 10K запросов
  Ожидание: 10-50× быстрее при vocab=512

E12b: SimdMatMul vs Plain на матрице 64×64 (зонд-нейросеть, hidden layer)
  Метрика: время 1000 операций матвекмул
  Ожидание: 4-8× быстрее

E12c: SimdMatMul vs Plain на матрице 512×64 (embedding lookup)
  Метрика: время 1000 операций
  Ожидание: 4-8× быстрее, но меньше чем E12b
```

**Важно:** точность предсказания не меняется — только скорость.
Это чистая инженерная оптимизация.

## Как интегрировать с другими экспериментами

После подтверждения E12:
1. Заменить `int[][]` на `SparseNgramTable` в E03, E04, E07, E09
2. Использовать `SimdMatMul` в E11 (зонд-нейросеть)
3. Сравнить `runner.Run("E11", scale: 2)` до и после — сколько сэкономили

Ожидаем что E11 с E12 будет:
```
Было: BPE время шага = 50ms
Стало: AST + SIMD = 50ms / 41 (меньше токенов) = 1.2ms на шаг
       (теоретически, реально 5-10×)
```
