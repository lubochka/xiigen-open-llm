# E08 — Структура предложения vs плоский текст (обычный язык)
## Experiment Plan v1.0 · LlmFromScratch.sln

**Вопрос:** работает ли принцип AST-токенов (E06) за пределами кода —
на обычном человеческом тексте?

**Этот документ не касается XIIGen.**

---

## Гипотеза

E06 показал 93.5% точности на коде потому что C# грамматика жёсткая:
после `public void` почти всегда идёт имя метода.
Грамматика человеческого языка мягче, но тоже существует:
после "я вчера" почти всегда идёт глагол, после "очень" — прилагательное.

Если заменить AST-дерево (синтаксис кода) на дерево разбора предложения
(подлежащее, сказуемое, дополнение) — преимущество структурного
представления должно сохраниться, но будет меньше чем на коде.

**Нижняя граница:** если улучшение < 5% на тексте — принцип работает
только благодаря жёсткости компиляторных грамматик, не универсально.

**Верхняя граница:** если улучшение > 15% — принцип фундаментальный
и применим ко всем последовательным данным с иерархической структурой.

## Что меняется (аналог E06 для текста)

| Параметр | Baseline | Enhanced |
|---|---|---|
| Токенизация | BPE по словам и подсловам | Синтаксические роли из дерева разбора |
| Единица токена | "вчера", "##ого", "пошёл" | `ADV`, `VERB`, `NOUN`, `SUBJ`, `OBJ` |
| Источник разбора | Нет | SpaCy (en_core_web_sm) или Stanza |
| Словарь | 500-2000 подслов | ~50 синтаксических меток (Universal Dependencies) |
| Метрика | N-граммная перплексия, top1 accuracy | То же |

Universal Dependencies (UD) — стандартный набор из ~40 ролей:
`NOUN`, `VERB`, `ADJ`, `ADV`, `PUNCT`, `DET`, `ADP`, `PRON`...
Плюс зависимостные отношения: `nsubj`, `dobj`, `amod`, `advmod`...

## Датасет

**Не использовать** Wikipedia или книги напрямую —
слишком большой объём, сложно контролировать качество.

**Использовать:** первые 500 предложений из каждого:
- Английский: `nltk.corpus.gutenberg` (классические книги, MIT)
- Опционально: научные аннотации из arXiv (structured English)

Почему именно эти: предсказуемая структура, достаточная длина предложений,
нет интернет-шума, легко загрузить.

**Тиры (аналогично E06):**
```
Tier 1: 100 предложений  ~2 000 слов    < 5 секунд
Tier 2: 1 000 предложений ~20 000 слов  < 60 секунд
Tier 3: 10 000 предложений ~200 000 слов < 10 минут
```

## Реализация (C#)

```csharp
// TextDependencyTokenizer.cs
// Вызывает SpaCy через subprocess (Python) или Stanza через HTTP.
// Возвращает последовательность синтаксических меток для предложения.
public sealed class TextDependencyTokenizer
{
    // Разобрать предложение и вернуть список меток UD.
    // Например: "The cat sat" → ["DET", "NOUN", "VERB"]
    // Или с зависимостями: "The/det cat/nsubj sat/ROOT"
    public OperationResult<IReadOnlyList<string>> Parse(string sentence);

    // Нормализовать метки в целые числа (аналог kindToIndex в E06).
    public OperationResult<IReadOnlyList<int>> ParseToIds(string sentence);
}
```

Два варианта реализации:
- **Вариант А (быстрый):** запускать Python-скрипт через `Process`,
  передавать текст через stdin, получать JSON с метками через stdout
- **Вариант Б (чистый):** HTTP-сервис на Python (FastAPI + SpaCy),
  C# делает запросы через `HttpClient`

Рекомендуется Вариант А для Scale 0-1 (меньше инфраструктуры).

```python
# spacy_server.py (для варианта А)
import sys, json, spacy
nlp = spacy.load("en_core_web_sm")
for line in sys.stdin:
    doc = nlp(line.strip())
    labels = [token.dep_ for token in doc]  # или token.pos_ для части речи
    print(json.dumps(labels))
    sys.stdout.flush()
```

## Метрики и критерий успеха

**Первичная метрика:** top1 accuracy (аналог E06 в 34.Experiments)

**Scaling signal:** `ud_saturation_ratio` — сколько новых UD-меток
появляется в validation vs training. Должен быстро насытиться
(в UD всего ~40 меток — меньше чем AST типов в C#).

**Критерий "прошёл":** улучшение ≥ 5% на Tier 1.

**Интерпретация результата:**

| Улучшение | Что означает |
|---|---|
| < 5% | Принцип работает только для жёстких грамматик (компиляторы). Гипотеза частично верна. |
| 5–15% | Принцип работает для иерархических структур любой природы. |
| > 15% | Синтаксическое представление фундаментально эффективнее плоских подслов. |

## Дополнительный тест: сравнение языков

После базового теста (английский) запустить тот же эксперимент на:
- Иврите — другой порядок слов, богатая морфология
- Русском — свободный порядок слов, падежи

Если улучшение сохраняется в разных языках — принцип языконезависим.
Это прямой аргумент для использования UD-представления в мультиязычных моделях.
