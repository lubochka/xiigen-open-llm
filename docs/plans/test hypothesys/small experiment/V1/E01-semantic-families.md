# E01 — Семантические семьи токенов vs плоский BPE
## K-Means кластеризация токенов вместо индивидуальных BPE id
**Проект:** llm-mvp-core · **Этот документ не касается XIIGen.**

---

## Гипотеза
Если заменить каждый BPE токен номером его семантического кластера (K-Means, K=50),
матрица переходов уменьшается с 2000×2000 до 50×50 — в 1600 раз.
Меньше состояний = каждый переход встречается чаще = точнее предсказание.

Аналогия: вместо того чтобы запоминать что "бежать", "мчаться", "нестись" предшествуют
"прочь" — запоминаем одно правило: "движение → направление".

---

## Нарастающие уровни нагрузки (Scale Ladder)

Каждый эксперимент проходит три уровня. Переход разрешён только если предыдущий дал ≥5% улучшения.

| Уровень | Название | Датасет | Время прогона | Инструмент |
|---|---|---|---|---|
| Scale 0 | Markov-micro | 1 файл (~1 000 токенов) | < 10 мс | Марковская цепь |
| Scale 1 | Markov-small | 1 подпроект (~9 000 токенов) | < 100 мс | Марковская цепь |
| Scale 2 | Markov-medium | 5 подпроектов (~45 000 токенов) | < 500 мс | Марковская цепь |
| Scale 3 | Probe-net | 1 подпроект + зонд-сеть 2L×64d | < 3 мин | Зонд-нейросеть |
| Scale 4 | Probe-medium | 5 подпроектов + зонд-сеть | < 15 мин | Зонд-нейросеть |
| Scale 5 | Full | Весь проект + трансформер | часы | Подпроекты 03+04 |

**Правило остановки:** если Scale N дал < 5% по всем метрикам — эксперимент помечается ABANDON.
Не запускаем следующий уровень зря.

```

Scale 1 (Markov-small):   01.Tokenizer/                     ~9 100 токенов
Scale 2 (Markov-medium):  01 + 02 + 05 + 07 + 09            ~30 000 токенов

Scale 5 (Full):           весь проект + трансформер          ~141 000 токенов
```

## Что меняется

**Baseline (оригинал):** Стандартный BPE. Каждый токен = целое число. Словарь ~2 000 уникальных токенов на один файл .cs. Матрица переходов 2000×2000.

**Enhanced (улучшение):** K-Means (K=50) кластеризует BPE токены в семантические семьи. Каждый токен заменяется id кластера (0–49). Матрица переходов 50×50.

**Использует подпроекты:** 01.Tokenizer, 14.MachineLearning (K-Means), 28.SemanticNlp

## Марковская реализация (Scale 0–2)

```csharp
// E01: заменить BPE id → cluster id перед построением матрицы Маркова
// Единственное изменение между baseline и enhanced — функция tokenize
static int[] TokensToClusterIds(int[] bpeTokens, Dictionary<int,int> tokenToCluster)
    => bpeTokens.Select(t => tokenToCluster.GetValueOrDefault(t, 0)).ToArray();

// baseline:  var tokens = BpeTokenizer.EncodeToInts(text);
// enhanced:  var tokens = TokensToClusterIds(BpeTokenizer.EncodeToInts(text), clusters);
```

## Примечания по каждому уровню

**Scale 0:** BpeTokenizer.cs (~1000 токенов): словарь ~150 BPE → ~50 кластеров. Матрица 150²=22500 → 50²=2500.

**Scale 1:** 01.Tokenizer (~9100 токенов): словарь ~400 BPE → ~50 кластеров. Матрица 160000 → 2500.

**Scale 2:** 5 подпроектов (~30K токенов): словарь ~800 → ~50. Проверяем стабильность выигрыша.

**Scale 3:** Зонд 2L×64d на 01.Tokenizer: K-Means embedding вместо одномерного lookup.

**Scale 4:** Зонд 5 подпроектов: подтверждаем что нейросеть тоже выигрывает.

**Scale 5:** Полный трансформер + весь проект. Финальное подтверждение.
