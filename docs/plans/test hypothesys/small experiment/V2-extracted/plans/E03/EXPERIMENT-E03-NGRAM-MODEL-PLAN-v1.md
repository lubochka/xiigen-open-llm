# E03 — N-граммная модель: какой N оптимален?
## Отдельный план эксперимента · LlmFromScratch.sln

**ID:** E03-NGRAM-MODEL  
**Подпроект-источник:** 35.CodeCompletion (Уровень 2Б — N-граммы)  
**Альтернативный подход учтён:** RESEARCH-04 (перплексия как единая метрика), EXPERIMENT-HARNESS-v2-MARKOV-PROXY (Марков = первый уровень валидации)

---

## Гипотеза

N-граммная модель обученная на самом проекте предсказывает следующий токен точнее случайного угадывания. При увеличении N (биграмм → триграмм → 4-граммы) точность растёт — но только если данных достаточно для надёжной статистики.

**Ключевое из RESEARCH-04:** перплексия N-граммы и перплексия нейросети измеряются одной метрикой. Если N-граммная перплексия снижается при переходе с bigrам на trigramm — то же произойдёт с нейросетью. N-граммы = быстрый прокси для поиска оптимальной "глубины памяти" модели.

**Уникальный угол масштабирования:** каждый тир добавляет один уровень N. Tier 1 → только биграмм. Tier 2 → биграмм + триграмм. Tier 3 → добавляем 4-граммы. И так далее.

---

## Что меняется

| N | Название | Что использует для предсказания | Минимум данных |
|---|---|---|---|
| 1 (unigram) | Случайно по частоте | Ничего из контекста | 100 токенов |
| 2 (bigram) | Биграммная модель | 1 предыдущий токен | ~500 токенов |
| 3 (trigram) | Триграммная модель | 2 предыдущих токена | ~2000 токенов |
| 4 | 4-граммы | 3 предыдущих | ~8000 токенов |
| 5 | 5-граммы | 4 предыдущих | ~32000 токенов |

Метрика сравнения — перплексия (из RESEARCH-04):
```
Перплексия = 2^(-среднее_log2(P(правильный_токен)))
Ниже = модель более уверена = лучше предсказывает

Baseline (unigram): ожидаем перплексию ~400–800 (словарь ~500 токенов)
Bigram:   ожидаем ~80–200
Trigram:  ожидаем ~20–60
4-gram:   ожидаем ~10–25 (только если данных достаточно)
```

---

## Уникальная ось масштабирования: оптимальный N для каждого объёма данных

Каждый тир тестирует максимальный N при котором у нас ещё есть надёжная статистика.

**Правило надёжности:** N-граммная таблица надёжна если среднее число наблюдений на одну запись ≥ 5.
```
Записей в bigramm таблице:   vocab_size²     = 500² = 250 000
Записей в trigram таблице:   vocab_size³     = 500³ = 125 000 000 (нужно очень много данных)

Реальных уникальных N-граммов намного меньше (код повторяется),
но зависимость та же: для большего N нужно больше данных.
```

## Лестница тиров

### Tier 1 — micro (< 5 секунд, < 50 МБ RAM)

**Датасет:** `01.Tokenizer` — ~2000 токенов  
**Тестируем:** unigram vs bigram  
**Ожидаемая перплексия bigram:** ~100–200 (снижение от ~500 baseline)  
**Оптимальный N на этом тире:** 2 (данных недостаточно для надёжных триграмм)

Переход: bigram перплексия < bigram_baseline × 0.6 → Tier 2

---

### Tier 2 — small (< 30 секунд, < 120 МБ RAM)

**Датасет:** 6 малых подпроектов — ~9 100 токенов  
**Тестируем:** bigram vs trigram  
**Ожидаемая перплексия trigram:** ~40–80 (ещё снижение)  
**Оптимальный N на этом тире:** 3  
**Специфичный тест:** сравнить bigram перплексию на Tier 1 vs Tier 2 — улучшилась ли за счёт большего датасета?

---

### Tier 3 — medium (< 2 минуты, < 250 МБ RAM)

**Датасет:** все подпроекты — ~141 000 токенов  
**Тестируем:** trigram vs 4-gram  
**Ожидаемая перплексия 4-gram:** ~15–35  
**Ключевой вопрос:** на каком N перплексия перестаёт значимо улучшаться? Это "оптимальная глубина памяти" для этого проекта.

---

### Tier 4 — external (< 10 минут)

**Датасет:** внешний C# проект  
**Тестируем:** 4-gram vs 5-gram  
**Ключевой вопрос:** переносится ли оптимальный N между проектами?  
**Гипотеза:** оптимальный N для C# кода ≈ 3–4, независимо от проекта (грамматика языка фиксирована)

---

### Tier 5 — full dataset (одноразово)

**Датасет:** CodeSearchNet C# или WikiText-103 техническая часть  
**Тестируем:** N-граммы vs нейросеть-зонд (2 слоя, 64 dim, 100 шагов)  
**Цель:** показать что N-граммная перплексия предсказывает нейросетевую перплексию (связь из RESEARCH-04)  
**Ожидание:** нейросеть лучше N-граммы, но разница в относительном улучшении между подходами остаётся той же
