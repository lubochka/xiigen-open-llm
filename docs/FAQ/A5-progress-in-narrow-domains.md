# A5 — Progress in narrow domains (AlphaGeometry / FunSearch / AlphaProof)

**Trend.** Systems such as AlphaGeometry, FunSearch, and AlphaProof show that narrow, well-specified domains can beat hand-written search and even reach competition-level results.

**How this project relates.** LlmFromScratch has several domain-specific pipelines, and their honesty status differs. `29.SemanticCompiler` is a deterministic pipeline (experiments E01-E27) that compiles input into predicates; `13.CodeOptimizer` runs deterministic Roslyn passes; `27.TranslationDomain` is a genuinely trained `ILearningMachine` with a real train / evaluate / export / import lifecycle. It declares four translation directions — RU->EN, EN->RU, HE->EN, EN->HE — in code; the training and held-out data shipped in the repository is for the Russian<->English pair, and the Hebrew<->English directions are declared and wired as adapters of the same machine.

**Where in the code.** `29.SemanticCompiler/Pipeline/SemanticCompilerPipeline.cs:18` — `SemanticCompilerPipeline : ISemanticCompiler29` (E01-E27 -> predicates). `13.CodeOptimizer/Pipeline/OptimizationPipeline.cs:34` — Roslyn AST + deterministic passes. `27.TranslationDomain/TranslationMachine.cs:12` — `TranslationMachine : ILearningMachine<TranslationDomain>` (real train / evaluate / export / import); the four directions are declared in `27.TranslationDomain/TranslationContracts.cs:20` (`enum TranslationDirection { RU_EN, EN_RU, HE_EN, EN_HE }`) and wired in `27.TranslationDomain/TranslationMachine.cs:559-601`. The shipped data folders hold Russian<->English pilots and held-out sets (`27.TranslationDomain/SourceData/sentence-index-ru-en-pilot-100.jsonl`, `27.TranslationDomain/TrainingData/tr-ho-ru-en-product-heldout-v1.jsonl`); there is no Hebrew training/held-out data file in the repository.

**Orchestration.** The semantic compiler is orchestrated as a fixed E01-E27 pipeline (`SemanticCompilerPipeline`); the translation machine exposes its runtime coordinator through the `ILearningMachine` contract (`GetOrchestratorAsync`), so it plugs into the same hierarchy as the rest of the stack.

**Honesty boundary.** Translation is a genuinely trained `ILearningMachine` (in the verified-trained list); the semantic compiler and the code optimizer are deterministic (not trained models). The machine declares four directions in code, but the training / held-out data shipped is for Russian<->English — the Hebrew<->English directions exist as declared, wired adapters rather than data-backed trained pairs in this repository. This is real narrow-domain engineering — a trained translation model plus deterministic domain pipelines — not superhuman theorem-proving, and it makes no AlphaProof-style claim.
