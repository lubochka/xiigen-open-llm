# A4 — New training methods (activation sparsity / credit assignment)

**Trend.** 2026 training research explores newer methods such as selective activation sparsity and prospective credit assignment to make training cheaper and more sample-efficient.

**How this project relates.** LlmFromScratch implements Direct Preference Optimization (DPO) and Low-Rank Adaptation (LoRA) from scratch, plus a classic supervised training loop; alongside these, a routing-profile builder assembles keyword profiles and DPO preference pairs for unit routing. DPO, LoRA and the supervised loop are real, working from-scratch training mechanisms (the established methods, not the specific 2026 techniques named in the trend); the routing profile is a deterministic scaffold rather than a gradient-trained model (see the honesty boundary).

**Where in the code.** `11.DPO/DpoTrainer.cs:16` — a real from-scratch DPO step (`Step` at line 38) computing `margin = chosenReward - rejectedReward` (line 51), `loss = -log sigmoid(margin)` (line 54), a manual backward pass (line 277), an AdamW optimizer step (line 61), and checkpoint save (lines 76/344). `10.LoRA/LoraApplicator.cs:17` — real from-scratch LoRA adapters over a frozen base. `26.TrainableRouter/Training/RoutingProfileTrainer.cs:10` — builds a per-unit keyword scoring profile from routing examples (deterministic keyword aggregation, no gradient/loss), and `26.TrainableRouter/Training/RoutingDpoPairBuilder.cs:10` constructs DPO preference pairs from routing decisions without running any gradient update. `04.TrainingLoop/Trainer.cs:24` — the base loop (forward -> cross-entropy -> backward -> clip -> optimizer step -> zero-grad, with gradient accumulation and checkpointing).

**Orchestration.** Training is driven per batch by `DpoTrainer.Step` (the DPO update) and by the supervised `Trainer` loop; the router's keyword profiles and DPO pairs are assembled by `RoutingProfileTrainer` / `RoutingDpoPairBuilder` as scaffolding, not applied through a gradient update.

**Honesty boundary.** The real, implemented from-scratch training mechanisms here are DPO (`DpoTrainer`), LoRA (`LoraApplicator`) and the classic supervised `Trainer` loop — the verified-trained list. The `26.TrainableRouter` routing profile is a training scaffold (keyword-profile building plus DPO-pair construction); it runs no gradient/loss step (a grep for `margin|loss|gradient|backward|AdamW` over `26.TrainableRouter` returns 0), so it is not a gradient-trained model and is not in the verified-trained list. And none of this implements the specific 2026 methods named in the trend (activation sparsity, prospective credit assignment) — those are the trend; what ships here is classic preference optimization and low-rank adaptation.
