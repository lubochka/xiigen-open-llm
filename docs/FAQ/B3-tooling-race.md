# How was LlmFromScratch built with agentic coding tools?

LlmFromScratch exposes a thin host-extension API boundary so an external editor or agent host (Claude Code, Copilot, Cursor) can send a concrete request to the core and get a concrete answer back. The three host extensions are separate EXTERNAL repositories, not part of `llm_mvp_core`; the core ships only the request/response boundary they call.

LlmFromScratch exposes a thin host-extension API boundary so an external editor or agent host can send a concrete request to the core and get a concrete answer back, keeping the core logic inside `llm_mvp_core` and the host integration outside it. `43.SmartSkillsDomain/XiigenExtensionApiContracts.cs:9` defines `record XiigenExtensionRequest` (with `HostName` / `HostType` / `Method`), and `43.SmartSkillsDomain/XiigenExtensionApiService.cs` is the service that serves that request: a host request enters through `XiigenExtensionApiService`, is dispatched by its `Method` into the core, and the answer is returned across the same boundary. This is the request/response boundary, not the host integration. The three host extensions (`claude-xiigen-smart-skills`, `codex-xiigen-smart-skills`, `cursor-xiigen-smart-skills`) are separate EXTERNAL repositories, NOT part of `llm_mvp_core`; the core ships only the API boundary they call, not the extensions themselves. There is no full Claude / Copilot / Cursor integration inside this repository, and the repository does not claim to have been generated by any of these tools — it exposes an integration point, nothing more.
