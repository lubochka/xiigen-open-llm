## Найденная точка обычной выдачи ответа

Точка **существует**. Это

`18.CapabilityTraining/DefaultLogicalCapabilityTrainer.cs`,
класс `GeneratedCapabilityFlow`, метод `ExecuteAsync` (строка 7599).

Что она делает сейчас по-человечески: берёт запрос пользователя, приводит его к
каноническому виду, обращается к выбранной обученной единице и возвращает её
ответ наружу обычным конвертом результата потока.

Чем она владеет в момент выдачи:

| Что нужно карточке | Что есть в точке выдачи сейчас |
| --- | --- |
| ссылка на выбранную единицу | поле `_unit` — фактический объект владельца |
| фактически показанный ответ | `unitResult.Value.Output` |
| опознание владельца | `unitResult.Value.UnitId` — **собственный** опознаватель владельца (проверено: блок ближайших соседей возвращает своё поле `_unitId`, а не опознаватель из запроса) |
| домен и роль владельца | `unitResult.Value.DomainTag`, `UnitRole` |
| запуск и опознание выдачи | `request.RunId`, `request.FlowId` |

Чего в точке выдачи нет: версии владельца, его порядкового номера регистрации и
опознания обученного состояния. Их даёт обычное чтение реестра единиц
(`InMemoryLogicalUnitRegistry.ResolveLatestById`) — тем же путём, которым их
читает сам координатор через свой справочник владельцев.

Чего в продукте нет вовсе, и это и есть разрыв Q12:

1. ничто не запоминает выдачу — ни выбранную единицу, ни показанный ответ;
2. у координатора адресного исправления **нет ни одного продуктового
   вызывающего**. Доказательство: во всём дереве на его имя ссылаются ровно два
   файла — он сам и один тест (`Tests/ExperimentFixes/KnnAddressedCorrectionTests.cs`);
3. продуктовое событие обратной связи (`14.ContinuousLearning/Core/Core.cs`,
   запись `FeedbackEvent`) несёт запрос, ответ модели, исправление и домен, но
   **не несёт, какая единица отвечала**. Поэтому исправление сегодня нельзя
   адресовать — ровно та болезнь, которую опыт P11101 измерил как «правильный
   адрес угадан в 1 случае из 2, одна чужая память изменена».

## Что будет сделано — минимальная правка

1. Новый файл `18.CapabilityTraining/KnnAnsweredDeliveryLedger.cs`: журнал
   состоявшихся выдач. Он запоминает пару «выбранная единица + показанный
   ответ» и при подтверждённом исправлении передаёт её вместе с выбранным
   получателем в **уже существующий** координатор. Своего обучения у журнала
   нет; обучает по-прежнему граница обучения за интерфейсом писателя.
2. Правка в точке выдачи (`GeneratedCapabilityFlow`): после успешного ответа,
   если журнал подключён, запомнить выдачу. Один необязательный параметр
   сборки, поэтому все существующие вызывающие остаются работоспособны.
3. Пропуск журнала через фабрику потока (`GeneratedCapabilityFlowFactory`)
   необязательным параметром.

Новых обучаемых блоков не заводится, уровень устройства не меняется, координатор
не переписывается.

## Ожидаемый наблюдаемый итог — один случай, два получателя

Основание: опыт P11101, случай `case-U2`
(`experiments-v2/RP01-MICRO/P11101/results/attempt-0001/arms.json`).

Заморожено до прогона:

| Шаг | Ожидание |
| --- | --- |
| до исправления, получатель U2 | ответ `archive` |
| до исправления, получатель U1 | ответ `review` |
| выбранный получатель, записанный точкой выдачи | `U2` |
| после исправления, получатель U2 | `archive then notify` — исходное действие дополнено действием `notify` |
| после исправления, получатель U1 | `review` — **без изменений** |
| путь выдачи | обычный: через `ExecuteAsync` потока, не прямым вызовом координатора |

Три вещи, которые проверка обязана показать отдельно:

1. **чужой получатель не изменился** — ответ U1 до и после совпадает дословно;
2. **урок фактически применён** — ответ U2 после исправления отличается от
   ответа до него и равен замороженному ожиданию;
3. **свой восстановленный ответ на месте** — исправленный владелец по-прежнему
   отвечает на тот же запрос, а не теряет память.

## Границы заявления — объявлены заранее

* Это **узкое** основание: один случай с двумя получателями. Общий допуск
  доменных функций ранжирования **не подтверждается** и не заявляется.
* Опознание обученного состояния только переносится и сверяется. Побайтовая
  сохранность состояния этим **не доказывается**.
* Кандидат в виде записи JSON **не является** контрольной точкой обучаемого
  блока. Отсутствие родного сохранения и загрузки у блока ближайших соседей
  нельзя прикрыть переобучением, и здесь оно не прикрывается.
* Русско-английский урок про молоко в холодильнике этому назначению не нужен и
  не добавляется.
