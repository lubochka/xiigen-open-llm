# Что именно считается «полным набором тестов проекта»

Чтобы «полный прогон» не оказался словом без содержания, я записываю состав
набора отдельно от его результата.

## 1. Тестовые проекты в решении

`LlmFromScratch.sln` содержит 79 проектов. Из них тестовых — **три**
(плюс один вспомогательный инструмент, не тестовый):

| Проект | Путь | Платформа | Файлов `.cs` | Роль |
|---|---|---|---|---|
| `LlmFromScratch.Tests` | `Tests\LlmFromScratch.Tests.csproj` | `net9.0` | 643 | **основной набор**; к нему относится объявленный уровень ≥ 1488 и в нём лежат оба теста аудита |
| `DesignConversion.ModelActivation.Tests` | `Tests\DesignConversion.ModelActivation.Tests\...csproj` | `net9.0` | 5 | отдельный малый набор по включению модели конверсии дизайна |
| `Tests.ApiDashboardWpf` | `Tests.ApiDashboardWpf\...csproj` | `net9.0-windows`, WPF | 1 | малый набор по панели |
| `RegistryLockHolder` | `Tests.Tools\RegistryLockHolder\...csproj` | — | — | **не тестовый**: вспомогательный исполняемый инструмент для проверок блокировки реестра |

### Деталь, которую стоит знать

`DesignConversion.ModelActivation.Tests` **включает по ссылке** два файла из
основного каталога проверок:

```
<Compile Include="..\DesignConversionLegalTeacherCapabilityTestFactory.cs" ... />
<Compile Include="..\DesignConversionModelActivationRegistryTests.cs" ... />
```

Значит тесты из `DesignConversionModelActivationRegistryTests.cs`
компилируются **в оба** проекта и могут быть исполнены дважды — по одному
разу в каждом наборе. При сложении чисел по проектам это даёт двойной учёт,
и я назову это в границах, а не замету.

## 2. Насколько объявленный уровень устарел

Объявленный правилами уровень — «≥ 1488 passed, 0 failed», дата объявления
**28 мая 2026**.

Независимый подсчёт по исходникам основного набора (разбор атрибутов xUnit,
только чтение):

| Атрибут | Найдено |
|---|---|
| `[Fact]` | 8 651 |
| `[Theory]` | 1 247 |
| `[InlineData]` | 5 669 |
| `[MemberData]` | 78 |

Грубая нижняя оценка числа случаев: `[Fact]` + `[InlineData]` = **14 320**
(случаи `[Theory]` раскрываются из `[InlineData]`/`[MemberData]`, причём
число случаев от `[MemberData]` по тексту не определить).

**Вывод:** набор вырос примерно **в десять раз** относительно даты
объявления уровня. Поэтому часть уровня «≥ 1488 зелёных» будет превышена
заведомо и сама по себе ничего не доказывает. Содержательная часть
объявленного уровня — **«0 красных»**, и именно её надо проверять строго.

Это, кстати, объясняет и почему прошлые прогоны смены (486, 544, 555
случаев) были узкими отборами, а не полным набором: полный набор на порядок
больше.

## 3. Что было запущено этим нарядом

Основное измерение — **основной набор** `Tests/LlmFromScratch.Tests.csproj`,
собранный в конфигурации Release и запущенный **без единого фильтра**.
Точная команда и исход — в `run-exit.txt`, журнал — в `full-run.log`,
файл результатов — `full-suite.trx` (всё в этом же каталоге улик).

Состояние по двум малым наборам и итоговые числа — в отчёте
`report.md` и в границах `claims-boundaries.md`.
