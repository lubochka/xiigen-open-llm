# Состояние рабочего дерева на момент прогона

Прогон измеряет **рабочее дерево**, а не вершину. Поэтому состояние дерева —
часть результата, и я записываю его точно.

## 1. Вершина

```
git rev-parse HEAD  ->  cd7268a17721afc7d3df6a3a388b3ff9d2533ee7
git rev-parse --abbrev-ref HEAD  ->  codex/dpo-implementation
git rev-parse --show-toplevel  ->  C:/Projects/llm_mvp_core
```

Корень и ветка — ровно те, что предписаны нарядом.

## 2. Изменённые (отслеживаемые) файлы

```
git status --porcelain
 M Tests/ExperimentFixes/TranslationPhraseCoverageLearningTests.cs

git diff --numstat
10	0	Tests/ExperimentFixes/TranslationPhraseCoverageLearningTests.cs
```

Ровно **один** изменённый файл: добавлено 10 строк, удалено 0.
Проиндексированных (staged) файлов — **ноль** (`git diff --cached --name-only`
пусто).

### Что именно в этой правке

Я прочитала правку (только чтение, `git diff`). Все 10 добавленных строк —
**комментарии** (`//`), объясняющие класс порога в проверке покрытия фразы:
что порог является предохранителем от катастрофы, а не охраной на уровне
существенности владельца в пять процентов, с конкретными числами и ссылкой
на ограничение в уликах другой работы.

**Исполняемого кода правка не добавляет и не меняет.** Это существенно для
честности измерения: правка комментариями **не может** изменить исход ни
одного теста. Поэтому по поведению измеряемое дерево равно вершине
`cd7268a1772`; формально же это всё-таки дерево, а не вершина, и я называю
результат именно так.

**Я этот файл не создавала, не изменяла и не трогала.** Это чужая
незакоммиченная работа по слайсу покрытия фразы.

## 3. Неотслеживаемые (untracked) файлы

Первый снимок (`git status --porcelain`, сделанный до того, как я создала
свои файлы) неотслеживаемых путей **не показал** — их было ноль.

Повторная проверка через `git ls-files --others --exclude-standard` уже в
ходе наряда показала четыре пути:

| `artifacts/fbe/FULL-SUITE-20261110/attempt-0001/expectation-before-run.md` | мой (улики этого наряда) |
| `artifacts/fbe/FULL-SUITE-20261110/attempt-0001/build-release.log` | мой (улики этого наряда) |
| `artifacts/fbe/FULL-SUITE-20261110/attempt-0001/build-exit.txt` | мой (улики этого наряда) |

### Находка, которую надо назвать прямо

Чужой файл `review-0004/independent-review-04.md` **появился после** моего
первого снимка дерева. То есть **дерево живое и меняется под измерением**:
рядом в том же рабочем корне работает проверяющий. Наряд это предполагал
(он прямо запретил трогать `artifacts/fbe/FIX-P54-PHRASE-COVERAGE`), и я его
не трогала.

Влияния на исход прогона этот файл не имеет: это документ улик (`.md`), он не
компилируется и не участвует в сборке. Но сам факт живого дерева я фиксирую:
повторный снимок `git status` после прогона может показать другой набор
неотслеживаемых путей, и это будет не моя правка.
