## Что я делаю, зачем, сколько сделано

**Что я делаю.** Чиню измеритель третьей попытки сорок восьмого опыта (файл проверок
`Tests/ExperimentFixes/P4801WeightingCurriculumCeilingTests.cs`): прежде он вычислял признак
«сравнение численно действительно», печатал его отдельным полем, а четыре поля вердикта рядом
— действительность обучения, состояние гипотезы, код возврата, список проблем — были написаны
руками. Испорченная будущая попытка записалась бы действительной с нулевым кодом возврата.
Кроме того, помощник считал бесконечные значения отдельно, а предикат их не использовал.

**Зачем.** Первая строка доски работ по внешнему аудиту (A02, находка F05): измеритель должен
уметь отвергнуть негодную попытку, а не только зафиксировать её.

**Сделано 5 из 5** пунктов наряда:
1. один валидатор определяет все четыре поля — сделано;
2. бесконечность включена в предикат — сделано (её там не было, подтверждено по живому коду);
3. три отрицательных контроля по блоку состояния (не-число, плюс бесконечность, минус
   бесконечность) — сделаны, проходят как испытания; добавлен четвёртый по потере;
4. положительный контроль — сделан;
5. обучение не добавлено — проверено по тексту.

**Осталось:** ничего в рамках наряда. Коммит и публикация — у родителя.

**Проблемы:** нет. Единственная неожиданность — вершина ветки сдвинулась на пять чужих
коммитов во время работы; они не затронули ни файл проверок, ни опубликованную попытку
(`git diff --stat` между вершинами по этим путям пуст).

## Как устроена починка (по живому коду после правки)

- **Запись численных улик руки** `ArmNumericEvidence` (имя руки, пять блоков состояния,
  конечность потери, номер первого нечислового шага) — строки 88–92. Основной прогон снимает
  её с итога плеча (`NumericEvidenceOf`, строки 108–109).
- **Вердикт** `ComparisonVerdict` с ровно четырьмя полями расписки плюс признак — строки 100–105.
- **Валидатор** `DecideComparison` — строки 118–157. Он обходит обе руки одним правилом, для
  каждого блока добавляет причину при нечислах (строка 130) и при бесконечностях (строка 135),
  для руки — причину при потере, переставшей быть числом (строка 140). Действительность — это
  пустой список причин (строка 146). Из одного решения выводятся четыре поля (строки 152–157):
  действительно → `VALID_FOR_NAMED_UNIT`, `NOT_SUPPORTED_IN_VALID_COMPARISON`, код 0, пусто;
  недействительно → `INVALID_NON_FINITE_STATE_OR_LOSS`, `OPEN_COMPARISON_NUMERICALLY_INVALID`,
  код 1, список причин вида «плечо «равные веса»: блок w1 содержит нечисел 1 из 1024».
- **Основной прогон** вызывает валидатор (строка 520), пишет четыре поля расписки из него
  (строки 646, 647, 663, 664), при отказе добавляет причины в сырой журнал (строки 531–532) и
  в шапку отчёта опыта (строки 688–700), а после записи всех улик роняет испытание, если
  сравнение недействительно (строка 677) — так внешний запуск завершается отказом, а расписка
  с ненулевым кодом и причинами остаётся на диске.
- **Контроли** — строки 1031–1171: готовые блоки состояния в формах продуктовой сети
  (704 + 1024 + 32 + 704 + 22 = 2486 чисел на руку, как у опубликованных рук), счёт тем же
  помощником `CountNumericHealth`, ни одного обучения.

## Дописано позже: сохранённая заплатка была искажена оболочкой и приведена к переводу строки

Отдельным нарядом выяснилось, что сохранённый файл заплатки (он лежал в каталоге `diff/` и с тех
пор удалён) хранил все строки с окончанием «возврат каретки плюс перевод строки». Сам `git diff`
печатает переводы строки — возвраты каретки добавил оператор перенаправления оболочки при захвате
вывода (журнал команд, строка 25). Из-за этого предкоммитный гейт пробелов печатал 374
предупреждения по одному этому файлу и блокировал публикацию всех улик починки. Файл был приведён
к переводу строки; отпечаток содержимого с вырезанными возвратами каретки до и после совпал
полностью (`4944d2cb…9ecf1f`), то есть изменились только окончания строк. Ни одно число этой
починки не менялось: проверки, сборки, прогоны и измеренные величины не затронуты. После починки
остались 13 предупреждений гейта — это подлинное содержимое вывода git (строки контекста для
пустых строк исходника и один заголовок куска), и править их нельзя.

**Чем это кончилось.** Решением владельца-архитектора файл заплатки больше не версионируется: он
удалён вместе с опустевшим каталогом `diff/`, потому что его содержимое избыточно — ровно тот же
диф воспроизводится из коммита, которым публикуется файл проверок, самим git и неизменяемо. Это
перенос доказательства на более надёжный носитель, а не стирание улики. Причины, числа удалённого
файла, готовая команда воспроизведения и граница «совпадение по содержанию, а не побайтово» — в
разделах «Почему заплатка больше не версионируется» и «Как воспроизвести тот же диф из хранилища»
файла `line-endings-repair.md` рядом с этим отчётом.
