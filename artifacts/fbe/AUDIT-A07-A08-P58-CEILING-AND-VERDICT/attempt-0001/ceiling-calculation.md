# Расчёт настоящего предела постоянного ответа, с числами

## Что такое предел постоянного ответа и чем он отличается от холодного счёта

Это две разные величины, и прежняя запись подставила одну на место другой.

**Наблюдённый холодный счёт** — сколько необученная модель ответила верно НА САМОМ ДЕЛЕ.
Получается прогоном панели через обычную цепочку «разборщик → исполнитель» на совсем
необученных единицах. Это наблюдение.

**Предел постоянного ответа** — сколько набрал бы наилучший ЕДИНСТВЕННЫЙ постоянный ответ,
который вход не читает вовсе. Получается расчётом: максимум по частотам ожидаемых ответов,
без единого вызова модели. Это расчёт.

Совпасть они могут только случайно. Зачем нужен именно предел: он отвечает на вопрос «а не
получено ли это число стратегией, в которой обучения нет вообще». Холодный счёт на этот
вопрос не отвечает, потому что необученная модель — это не наилучший постоянный ответчик.

## Данные расчёта

Панель экзамена этого опыта — метод `ExamRows()`, строки 83–93 целевого файла. Восемь строк.
Профиль проверки английский→русский, поэтому ожидаемые ответы русские.

| строка | запрос | ожидаемый ответ |
|---|---|---|
| e1 | Anna opened the window | Анна открыла окно |
| e2 | Anna closed the door | Анна закрыла дверь |
| e3 | Boris opened the door | Борис открыл дверь |
| e4 | Boris closed the window | Борис закрыл окно |
| e5 | Anna did not open the window | Анна не открыла окно |
| e6 | Anna did not close the door | Анна не закрыла дверь |
| e7 | Boris did not open the door | Борис не открыл дверь |
| e8 | Boris did not close the window | Борис не закрыл окно |

Различных ожидаемых ответов — **8 из 8**. Повторов нет ни одного.

## Какое правило сравнения использовано и почему именно это

Правило взято **то же**, которым опыт судит правильность ответа: полное совпадение текста без
учёта регистра. В исходном файле оно стояло двумя копиями — в оценке панели экзамена (строка
244) и в контроле обучения (строка 276):

```
Correct: string.Equals(candidate.Text, row.Gold, StringComparison.OrdinalIgnoreCase)
```

При починке правило **вынесено в одно место** — метод `AnswerIsCorrect(answer, gold)` — и
теперь им судится панель экзамена, контроль обучения и предел постоянного ответа. Это сильнее,
чем «использовать такое же правило»: отдельная копия внутри расчёта мерила бы предел другой
меркой, чем саму панель, и сравнение двух чисел перестало бы быть законным. Теперь расхождение
мерок стало невозможно по устройству, а не по дисциплине.

Эталон первого опыта (`experiments-v2/RP01-MICRO/P5201/Program.cs`, строка 1355) применял к
кандидату `.Trim()`. Здесь `.Trim()` **не** применён сознательно: правило самого опыта пробелы
не обрезает, а наряд требует судить предел тем же правилом, которым опыт судит правильность.
На этих данных результат одинаков (ни один ожидаемый ответ не имеет краевых пробелов), но
мерка обязана быть буквально той же, а не эквивалентной на текущих данных.

## Кандидаты

Образец из пятьдесят второго опыта: кандидатами берутся различные ожидаемые ответы панели
**плюс пустая строка**, чтобы стратегия «постоянно молчать» тоже считалась.

Кандидатов: 8 различных ожидаемых ответов + 1 пустая строка = **9**.

| кандидат | сколько строк панели угадал бы |
|---|---:|
| Анна открыла окно | 1 |
| Анна закрыла дверь | 1 |
| Борис открыл дверь | 1 |
| Борис закрыл окно | 1 |
| Анна не открыла окно | 1 |
| Анна не закрыла дверь | 1 |
| Борис не открыл дверь | 1 |
| Борис не закрыл окно | 1 |
| (пустая строка) | 0 |

## Результат

**Предел постоянного ответа = 1 из 8.**

- лучший постоянный ответ: «Анна открыла окно»;
- независимый знаменатель: 8 (размер панели);
- кандидатов рассмотрено: 9;
- кандидатов с тем же лучшим счётом: 8;
- вызовов модели: 0.

Почему именно 1: все восемь ожидаемых ответов различны, поэтому любой единственный постоянный
ответ совпадает ровно с одной строкой панели, а пустая строка — ни с одной.

Почему записанный лучший ответ воспроизводим: сравнение строгое (`correct > best.Correct`),
поэтому из восьми равных остаётся **первый по закреплённому порядку панели**, а порядок панели
заморожен. Поле «кандидатов с тем же лучшим счётом» записывается рядом именно для того, чтобы
читатель видел ничью и не принял «Анна открыла окно» за единственный достижимый максимум.

Это число совпало с ожиданием, записанным ДО правки в `expectation-before-run.md`. Ожидание
под поведение кода не подгонялось.

## Что стояло раньше и чем это было опасно

В опубликованной попытке:

```json
"контроль_постоянного_ответа": {
  "пояснение": "холодная панель — предел ответа без всякого обучения",
  "верных": 0
}
```

Ноль — это наблюдённый холодный счёт, а не предел. То же самое число рядом записано правильно
под своим именем (`холодная_панель.верных = 0`, строки 409 и 534). Одно число под двумя
именами, причём второе имя чужое.

**Чем это опасно, численно.** Плечи A и B дают на панели экзамена **1 верный из 8**. При
записанном «пределе» 0 выходило 1 > 0 — будто плечи обыграли постоянный ответ. При настоящем
пределе **1** плечи дают **ровно столько же**, сколько наилучший постоянный ответчик, который
вход не читает вовсе. То есть на панели экзамена плечи от постоянного ответа **неотличимы**.

Правило вывода взято дословно из второго эталона
(`experiments-v2/RP01-MICRO/P7101/Program.cs`, строки 497–509): «любое плечо с такой же долей
на этой панели не отличимо от постоянного ответа».

## Рушит ли это вывод опыта — нет, и вот почему

Вывод опыта по первой оси (содержание корректирующего урока) на панель экзамена **не
опирается**. Вторая ось в этом опыте объявлена вырожденной по устройству продукта — и это сам
результат опыта, а не его поломка.

Состоявшееся обучение доказано **другим** контролем, от панели экзамена независимым: контроль
обучения на САМИХ учебных строках даёт **0 из 8 до обучения и 8 из 8 после**
(`train-control.json` опубликованной попытки, перечитан при работе). Этот контроль и остаётся
доказательством обучения.

Поэтому исправление не меняет вывод опыта, а делает честной **границу** вывода: панель экзамена
доказательством состоявшегося обучения не является, и так теперь и записано — отдельным полем
`граница_панели_экзамена` в показателях и отдельным абзацем в отчёте.

Именно по этой причине условие «счёт панели не превысил предел» **не** сделано проблемой
расписки: это граница вывода, а не нарушение инварианта. Решение записано заранее, в
`expectation-before-run.md`, чтобы его нельзя было подогнать после прогона.
