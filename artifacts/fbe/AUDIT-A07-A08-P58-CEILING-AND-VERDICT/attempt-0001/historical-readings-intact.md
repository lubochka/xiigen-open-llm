`experiments-v2/RP01-MICRO/P5801/results/**`, 21 файл в двух попытках. Они не должны были

## Наблюдение: приёмник улик перенаправил запись сам

Общий приёмник доказательств решил вопрос до первой записи и сообщил об этом. Дословно из
файла-подсказки, который он оставил рядом с файлами прогона:

```
ПРОВЕРОЧНЫЙ ПРОГОН ОПЫТА: опубликованное наблюдение не перезаписывается.
Это проверка уже опубликованной попытки, а НЕ новая запись опыта.
Опубликованный каталог оставлен без изменений ни на байт: C:\Projects\llm_mvp_core\experiments-v2\RP01-MICRO\P5801\results\attempt-0002
Почему так решено: хранилище отслеживает внутри каталога файлов: 8
Файлы этого проверочного прогона пишутся сюда: C:\Projects\llm_mvp_core\Tests\TestResults\experiment-evidence\experiments-v2-RP01-MICRO-P5801-results-attempt-0002\run-20261110T083958155Z-0ad34c72
Этот каталог игнорируется хранилищем намеренно: проверка не публикуется как попытка опыта.
```

То есть приёмник **перенаправил**, а не отказал, и назвал причину числом отслеживаемых
файлов. Это и есть требуемое наблюдение: запись в опубликованный каталог не состоялась.

## Проверка, что перенаправление действительно никуда не публикует

Недостаточно поверить приёмнику на слово — проверено отдельно, причём по ТЕКСТУ победившего
правила игнорирования, а не по коду возврата:

```
git check-ignore -v --no-index <файл прогона>
-> .gitignore:24:**/TestResults/   Tests/TestResults/.../status.json
   код возврата 0
```

Победившее правило `**/TestResults/` — положительное (не начинается с `!`), поэтому вердикт:
путь **игнорируется**, и проверочный прогон не публикуется как попытка опыта. Подтверждено
вторым, независимым способом: `git status --porcelain=v1 -- Tests/TestResults` не предъявляет
ни одной строки.

Отмечу прямо: код возврата `check-ignore` сам по себе вердиктом не является — правило,
начинающееся с `!`, тоже даёт код 0, но означает обратное. Поэтому смотрел текст правила.

## Куда ушли файлы проверочных прогонов

В игнорируемое дерево `Tests/TestResults/experiment-evidence/experiments-v2-RP01-MICRO-P5801-results-attempt-0002/run-<время>-<метка>/`.
Каждый прогон получает свой каталог со своей отметкой времени, поэтому прогоны не затирают
даже друг друга.

Эти файлы новым наблюдением опыта **не являются** и в хранилище как попытка не подаются. Чтобы
записать новое наблюдение, надо назначить в карточке свободный номер попытки — это отдельная
работа и отдельное решение, и я его не принимал.
