# Четвёртый проход разбора: строки, не просмотренные тремя прежними проходами

**Что это.** Читающий разбор тех строк очереди переносов, которые не смотрел ни
один из трёх прежних проходов. Задача — узнать доказательством, осталось ли в
очереди хоть одно исполнимое улучшение продукта, или утверждение «переносить
нечего» верно уже не только для разобранной части, а для целого.

**Чего здесь нет.** Ни одной правки кода, ни одной сборки, ни одного прогона,
ни одной операции записи в хранилище. Запреты наряда соблюдены: общий каталог
сборки сейчас занят вторым исполнителем под его красную сторону.

## 3. Разбиение по природе работы, с причиной отказа одной фразой

**Переносом не являются 30 строк из 32.**

- **Приёмка уже перенесённого, 13 строк:** R02, R03, R04, R07, R11, R16, R23,
  R24, R25, R26, R29, R31, R37. Причина: колонка состояния сама говорит
  «механизм реализован», предписание — «закончить адресную приёмку»; переносить
  нечего.
- **Ремонт уже написанного, 4 строки:** R18, R28, R42, R47. Причина:
  предписание «делать названный или назначенный ремонт» либо «исправить потерю
  различия» при реализованном механизме; это починка, а не перенос измеренного
  улучшения.
- **Новая связка способности, а не оптимизация, 2 строки:** Q22, Q23. Причина:
  предписание «делать только узкий срез» — подключить обучение к потребителю;
  измеренного ресурсного выигрыша строка не несёт.
- **Сначала сверка сохранённого, 3 строки:** Q24, Q65, Q66. Причина:
  предписание «сверить сохранённое»; у строки Q24 реестр прямо говорит, что
  ошибка продуктового вызова ещё не доказана.
- **Покрытие проверками, а не правка продукта, 6 строк:** Q45, Q46, Q48, Q49,
  Q50, Q51. Причина: предмет строки — учебная проверка либо покрытие режима, то
  есть работа в проверках; продуктового улучшения она не переносит.
- **Иная природа, 2 строки:** 115 (узкий программный договор уже реализован,
  остаток — поведение сжатия) и 120 (совместное владение накладкой — договорная
  работа, не ресурсный перенос).

**Переносом являются ровно 2 строки:** Q40 и Q32. Обе разобраны ниже полностью.

### 4.1 Признак и метка урока используют один разбор (Q40, строка 232, работа FIX-KHC)

для вектора признаков, второй раз для метки. Правка разбирает один раз и
передаёт одно и то же дерево обоим.

**Карточка:** `docs/plans/replanning-possible-diffs/fixes-based-on-experiments/24-file-action-shared-parse.md`,

719: «Небольшое измеренное улучшение допустимо; не повышать приоритет за счёт
грубого одного тика CPU».

**Проходит ли критерий хозяйки: формально да, по сути нет.** Реестр допускает
строку во вторую очередь. Но весь выигрыш — по времени и процессорному времени,
а **выделения не изменились ни на байт**. Это ровно тот класс, который уже
дважды отклонялся: повторное использование экспоненты в сглаженном выпрямителе
(минус 9,96 процента времени при выделениях плюс 0,43 процента) и двойная
экспонента в учебной потере. Причём по времени эта строка слабее обеих: минус
2,64 процента при прямом признании реестра, что устойчивый процент не доказан.
Поэтому я ставлю её второй и не предлагаю к исполнению первой.

**Сверка по живому коду.** Подтверждено дословно. Привязка реестра (строка 952
по срезу `fd5a5a954121`) устарела по номеру — файл сдвинулся, в том числе моим
сегодняшним переносом; живая нормализация объявлена на строке 985 файла
`00.TensorCore/Core/TensorOps.cs` (отпечаток
`8cc01674db93a1fd7ca1682efd0f312a27f7f13a`, то есть опубликованное состояние
после моего переноса). Первым действием там идёт полный цикл копирования входа в
выходной массив, и только затем три цикла поиска максимума, возведения в
экспоненту и деления. Механизм описан верно и **не перенесён**.

**Продуктовый файл:** один, `00.TensorCore/Core/TensorOps.cs`, тело
нормализации. Карточка требует сохранить порядок вычислений с плавающей точкой,
владение выходным массивом, обратный проход, общий путь для остальных осей и
положения проверок отмены.

**Есть ли различающая проверка.** Назначенная карточкой — десять подслучаев,
включая совпадение входа и выхода по памяти, сохранность входа, не-последнюю ось,
не-число, плюс и минус бесконечность, недопустимую размерность и отмену до
начала, с независимым последовательным эталоном на показателях минус восемьдесят,
ноль и восемьдесят. В дереве её **нет**: поиск по отслеживаемым файлам не нашёл
ни одного упоминания назначенного имени. Существующие три проверки нормализации в
`Tests/TensorCoreTests.cs` (строки 164, 175, 188) сохраняются как есть, но
различающими не являются: правка обязана не менять числа.

**Риск столкновения.** Минимальный: файл ядра тензоров второй исполнитель не
правит, назначенные проверки лежат вне папки проверок опытов.

**Минимальный честный объём.** Одна правка продукта в квалифицированном пути;
новый договорный набор из десяти подслучаев; прогон трёх существующих проверок
нормализации; измерение, которое по самой карточке «малое наблюдение допускает
план, не обещает native-выигрыш».

## 5. Ответ на вопрос наряда

**Проходящих критерий строк не ноль — их одна.** Это признак и метка урока через
один разбор (Q40, работа FIX-KHC): выигрыш по выделениям минус 0,765 процента,
точность не изменилась, единственное ухудшение — процессорное время, которое
критерий ухудшением не считает. Вторая очередь по реестру.

**Второй по порядку** — нормализация без копирования (Q32, работа FIX-AC), но с
прямой оговоркой: её выигрыш только по времени, выделения не изменились, и это
тот же класс, который хозяйка уже отклоняла дважды. Предлагать её первой я не
буду.

**Остальные тридцать строк переносом не являются** по причинам, названным в
разделе 3 по одной фразе каждая.

Отсюда поправка к моему прошлому пакету: утверждение «чистых переносов не
осталось» было верно для разобранной области и неверно для целого. Один перенос
остался, и теперь это известно доказательством, а не умолчанием.

## 6. Девятого расхождения реестра с кодом не найдено

Оба кандидата сверены по живому коду у назначенного карточкой адреса: колонки
состояния подтвердились дословно, устарели только номера строк, и то по понятной
причине — файлы сдвинулись, в том числе моим же сегодняшним переносом. Это не
расхождение по сути, а сдвиг адреса, и я отмечаю его отдельно от восьми
настоящих расхождений.

**Навигационная особенность, не дефект, который мне позволено править.**
Девятнадцать строк реестра ссылаются на каталог
`docs/plans/replanning-possible-diffs/fixes-based-on-experimentsperiments/` —
имя с удвоенным куском слова. Каталог реально существует и содержит 11 файлов,
включая карточку кандидата Q32, то есть ссылки рабочие. Записываю как факт для
хозяйки: имя выглядит как давняя опечатка в названии каталога, но это её
решение, а не моё, и реестр я не правлю.

## 7. Чего я не устанавливал

- Состояний проверок: ни одной сборки и ни одного прогона — запрещено нарядом.
- Фактической закрытости коммитами для тринадцати строк приёмки и четырёх строк
  ремонта: я читал колонки и предписания, а не историю коммитов по каждой.
- Пользы и ухудшений для строк, которые переносом не являются: их замеры либо
  относятся к приёмке, либо не выражены в ресурсных числах.
- Соответствия четырёх строк третьего прохода списку 33: их названия в реестре
  отличаются от моих перефразировок, и сопоставлять по словам я отказался.
- Воспроизводимости чисел обоих кандидатов: оба замера реестр сам называет одним
  запуском, и устойчивый процент ни по одному из них не доказан.
