# Ожидание ресурса сборки и замеченное наложение снимка входов

## Что наблюдалось

На момент начала ступени 2 в системе работал чужой прогон тестов, который
собирает те же общие каталоги сборки (`bin`, `obj`) продукта.

| Что | Наблюдённое значение |
|---|---|
| Владелец ресурса | другой исполнитель, не я |
| Номер процесса (PID) | 19816 |
| Команда | `dotnet test Tests\LlmFromScratch.Tests.csproj -c Release --filter FullyQualifiedName~SupervisedDonorBoundaryReadoutTests --logger trx;LogFileName=chtenie-q06.tr...` |
| Время запуска | 2026-11-13T00:09:43.7647968+02:00 |
| Рабочие узлы сборки | 7 процессов `MSBuild.dll`, запуск 00:09:45 |
| Сервер компилятора | `VBCSCompiler.exe`, запуск 00:10:05 |
| Общие пути | `04.TrainingLoop/bin`, `04.TrainingLoop/obj`, выходы решения в Release |

Команда наблюдения: `Get-CimInstance Win32_Process` по именам `dotnet.exe`,
`MSBuild.exe`, `VBCSCompiler.exe`. Чужой процесс не остановлен и не тронут.

## Наложение снимка входов — предупреждение другому исполнителю

Моя правка продуктового файла `04.TrainingLoop/Trainer.cs` имеет время записи
**2026-11-13T00:09:40**, то есть на 3 секунды РАНЬШЕ запуска чужого прогона
тестов (00:09:43) и на 25 секунд раньше работы сервера компилятора (00:10:05).

Отсюда следует честный вывод: **чужой прогон тестов, скорее всего, собрал уже
изменённый мной исходник обратного прохода.** Его результат нельзя считать
снимком продукта без моей правки.

Я не могу доказать это изнутри своей задачи — у меня нет его журнала сборки и
его файла результатов прогона. Поэтому это не вердикт, а предупреждение:
архитектору нужно сверить его снимок входов с этим временем. Правило договора
проверки качества требует нового устойчивого снимка входов, если входы менялись
во время сборки.

Моего умысла здесь нет: наряд разрешил и предписал эту правку, а чужой прогон
запустился сразу после неё.

## Что я сделал по правилу ожидания ресурса

Последовательное окно: своя сборка не запускается, пока чужой прогон не
завершился. Чужой процесс не останавливается. Ожидание ограниченное, с
проверкой живости процесса по его номеру.
