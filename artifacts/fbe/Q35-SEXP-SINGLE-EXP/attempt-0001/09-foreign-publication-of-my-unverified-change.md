## Почему это дефект, а не просто неудобство

1. **Ложная приёмка.** Сообщение коммита заявляет приёмку другой строки работ —
   про чтение выученного ответа на восстановленных снимках. Моя строка переноса
   («использовать ту же экспоненту при вычислении градиента») **не принята**:
   её минимальная проверка не выполнилась ни разу, один шаг обучения не
   запускался, конечная потеря не получена, сдвиг шага оптимизатора не
   наблюдался. Сейчас опубликованная история утверждает приёмку над кодом,
   который никто не проверил в прогоне.
2. **Непроверенный продуктовый код в опубликованном состоянии.** Правка
   собирается без ошибок, но её поведение на прогоне не доказано. По стоячему
   правилу проекта публикация принятой работы требует независимой проверки и
   проверки на точной финальной вершине; здесь ни того, ни другого для моей
   строки не было.
3. **Чужая приёмка снята на дереве с моей правкой.** Это прямое продолжение
   того наложения снимка входов, о котором я уже доложил (файл
   `02-resource-wait-and-snapshot-conflict.md`): сначала чужой прогон тестов
   собрал мой изменённый исходник, теперь чужой коммит приёмки его же
   опубликовал. Достоверность приёмки другой строки тоже под вопросом, и
   решить это может только архитектор.
4. **Одно сообщение на две разные работы.** В коммите 13 файлов: часть — чужая
   работа по чтению ответа, часть — моя незакрытая работа по переносу. Границы
   коммита и строки работ разошлись.
