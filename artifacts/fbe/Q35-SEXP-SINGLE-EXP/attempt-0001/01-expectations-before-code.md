# Объявление ожиданий до касания кода

Это первый файл улик. Он написан ДО любой правки продукта, чтобы ожидаемое
нельзя было подогнать под наблюдённое.

## Что переносится

Перенос правки «использовать ту же экспоненту при вычислении градиента»
(раздел переноса «FIX-SEXP — Q35», якорь `q35-min`, строка 252 карточки
`docs/plans/replanning-possible-diffs/fixes-based-on-experimentsperiments/41-neural-learning-resource-deltas.md`).

Суть по-человечески: в обратном проходе функции потери обучающего цикла
показатель степени каждого элемента строки сейчас вычисляется дважды — один раз
при подсчёте знаменателя (суммы), второй раз при вычислении градиента. Перенос
требует посчитать его один раз на элемент, положить значения в один рабочий
массив на вызов и использовать этот же массив и для знаменателя, и для
градиента. Для следующей строки массив заполняется заново.

Точка правки: файл `04.TrainingLoop/Trainer.cs`, закрытый метод `BackwardLoss`
(строки 400–438 до правки). Больше в этом файле ничего не меняется.

## Что уже доказано исходным опытом и заново не измеряется

Из карточки: время снизилось на 31,19%; число вычислений показателя степени в
обратном проходе снизилось с 71 680 до 35 840; показатели точности сохранены;
в исходном опыте было 3 из 40 по панели чтения и 0 из 2 полных ответов.
Эти величины здесь не перепроверяются, побитовые сверки не выполняются, время
не измеряется как доказательство ускорения.

## Ожидания этого переноса (объявлены до правки)

1. **Сборка.** Затронутые проекты собираются без ошибок. Ожидание:
   `0 Error(s)`.
2. **Ровно один вызов показателя степени в методе.** После правки внутри метода
   обратного прохода остаётся ровно ОДИН текстовый вызов `MathF.Exp`
   (до правки их два, строки 422 и 428).
3. **Один шаг обучения с учителем проходит.** Один шаг на единственном уроке
   `// file: One.cs` с ответом `static int One()=>1;` выполняется без исключения
   и возвращает конечную (финитную) величину потери.
4. **Шаг оптимизатора сдвигается на единицу.** Родительский принятый комплект
   стоит на шаге 1000, значит после одного шага ожидается 1001.
5. **Прохождение именно по изменённому обратному проходу.** Цепочка вызова:
   оболочка проверки -> `Trainer.TrainSupervisedNextTokenStep` ->
   `Trainer.BackwardLoss` (изменённый метод) -> `Tensor.Backward`. Доказательство
   прохождения — ненулевое изменение весов, подтверждаемое сдвигом шага
   оптимизатора и полученной потерей; другого публичного пути к этому закрытому
   методу в продукте нет.
6. **Число верных токенов ответа до и после.** Записывается рядом как
   наблюдение. **Нового правильного полного ответа НЕ ожидается и требовать его
   нельзя** — исходный опыт давал 3 из 40 по панели и 0 из 2 полных ответов.
   Допустимый и ожидаемый исход: число верных токенов ответа до и после
   совпадает или меняется незначительно. Это не считается провалом переноса.

## Что считается провалом переноса

- сборка с ошибками;
- исключение на шаге обучения;
- нефинитная потеря;
- шаг оптимизатора не сдвинулся;
- в методе осталось два вызова показателя степени (правка не внесена);
- рабочий массив не перезаполняется для каждой строки (значения предыдущей
  строки попадают в градиент следующей).

При неверном градиенте карточка разрешает проверить ровно три вещи: повторную
запись рабочего массива для каждой строки, цель (target) и масштаб (scale).
Поиск не расширяется.
