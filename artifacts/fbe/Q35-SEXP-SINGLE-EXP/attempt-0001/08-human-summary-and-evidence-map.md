# Человеческий итог и карта доказательств

## Что сделано и что это даёт продукту

В обратном проходе функции потери обучающего цикла показатель степени каждого
элемента строки теперь считается один раз и используется и для знаменателя, и
для градиента. До правки он считался дважды: сначала при сборе суммы, потом
заново при вычислении доли. Для обучающего шага это ровно то же самое число,
просто посчитанное один раз вместо двух.

Пользователю это не добавляет нового поведения и не делает модель умнее. Это
удешевление обучающего шага: по исходному опыту число вычислений показателя
степени в обратном проходе упало с 71 680 до 35 840, время — на 31,19%,
показатели точности сохранены. Эти величины взяты из карточки как уже
доказанные и здесь заново не измерялись.

## Как работает алгоритм без кода

Обратный проход получает выходы модели (по строке на каждую предсказываемую
позицию), ожидаемый следующий токен для каждой позиции и масштаб. Для каждой
строки он: находит наибольшее значение строки; вычитает его из каждого элемента
и берёт показатель степени; складывает эти значения в сумму строки; затем делит
каждое значение на сумму, вычитает единицу у ожидаемого токена и прибавляет
результат, умноженный на масштаб, к накопленному градиенту. Изменилось одно:
значения показателя степени теперь запоминаются в одном рабочем массиве при
первом проходе по строке и во второй петле берутся из него. Для каждой
следующей строки все ячейки массива перезаписываются, поэтому остатка прошлой
строки в градиенте быть не может.

## Что проверено и что НЕ проверено — честная граница

Проверено наблюдением:
- правка внесена и совпадает с доказанным файлом единственного фактора;
- затронутые проекты собираются без ошибок на финальном исходнике;
- в методе остался ровно один вызов показателя степени;
- родительское состояние шага 1000 восстановлено и совпало с распиской по трём
  отпечаткам: веса, манифест, состояние модели;
- один шаг обучения с учителем прошёл по изменённому обратному проходу и дал
  конечную потерю 4,8934336;
- шаг оптимизатора сдвинулся на единицу: 1000 → 1001;
- число верных токенов ответа снято до и после: 2 из 20 и 2 из 20;
- градиент не сломан: обучающий цикл сам проверяет после шага, что ни один
  обучаемый параметр не стал нефинитным, и бросает исключение, если это так —
  исключения не было, шаг завершился кодом выхода 0.

**НЕ проверено, и я это не заявляю:**
- ускорение и снижение числа вычислений показателя степени — взяты из карточки
  как уже доказанные, заново **не измерялись**;
- побитовое совпадение весов или потери с исходным опытом — **не сверялось**,
  карточка этого прямо не требует;
- остальные пути обучения, кроме шага обучения с учителем, — **не проверялись**;
- полный набор тестов проекта — **не запускался** (наряд этого не поручал).

Нового правильного полного ответа не появилось, и его не требовалось: в исходном
опыте было 3 из 40 по панели и 0 из 2 полных ответов. Наблюдённое «2 из 20 до и
2 из 20 после» — ожидаемый исход, а не провал переноса.

## Что это НЕ путает с обучением

Один шаг обучения с учителем был настоящим: он изменил веса в памяти и сдвинул
шаг оптимизатора с 1000 на 1001. Но это **один шаг на одном уроке**, и он
ничего не доказывает про качество модели. Измерения качества не проводились,
отложенного набора не было, контрольная точка на диск не записывалась и ни один
опубликованный артефакт модели не менялся этим прогоном. Восстановление байт
веса родителя — это ремонт хранения, а не обучение.
