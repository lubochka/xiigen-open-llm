# Вопросы 3, 4, 5 — чувствительность, независимый оракул, тавтологии

## Вопрос 3. Вывод

Положительный случай покраснеет, если правило близости убрать из механизма. Это доказано структурно (ниже), подтверждено журналом мутации исполнителя (который я перепроверил, см. `04-evidence-integrity.md`) и не является круговой проверкой: ожидаемые метки выводятся без обращения к механизму голосования.

## Какая строка механизма решает исход

`12.SemanticCompiler/Prediction/MethodKnn.cs`, метод `Predict` (строки 329–365):

```text
340  var neighbours = _pairs
341      .Select(pair => (Pair: pair, Distance: JaccardDistance(query.KindBag, pair.Current.KindBag)))
346      .OrderBy(item => item.Distance)
347      .Take(_k)
351  return neighbours
352      .GroupBy(item => CanonicalType(item.Pair.Next.KindBag))
354      .OrderByDescending(group => group.Count())
358      .ThenBy(group => group.Min(item => item.Distance))      <-- правило близости
362      .ThenBy(group => group.Key, StringComparer.Ordinal)
363      .First().Key;
```

Доказательство: чтение файла, номера строк из вывода чтения; `grep -c 'ThenBy(group => group.Min(item => item.Distance))'` -> 1, `grep -n` -> 358.

## Что станет ответом без строки 358

На панели положительного случая (`TiedVotePanel`: `TrainGuardAsync`, `TrainLoop`, `TrainErrorHandling`, `TrainSimple`) обученных пар четыре, у каждой своя метка. Метки пар — `CanonicalType` набора ВТОРОГО метода каждого файла (строки 390–403):
- `GA.B`: содержит `If` и `Ret` -> `Guard` (проверка `Try/Catch` раньше — нет; проверка `If && Ret` раньше проверки `Await`);
- `LP.B`: `For` -> `Loop`;
- `EH.B`: `Try` -> `ErrorHandling`;
- `SP.B`: `{int b=2;}` -> набор `{Decl, NumericLiteral}`, не пуст, ни одно правило не сработало -> `Mixed`.

При пяти соседях и четырёх парах в голос входят ВСЕ четыре пары — четыре группы по одному голосу. `OrderByDescending(Count)` ничего не разделяет. Без строки 358 остаётся только `ThenBy(Key, Ordinal)`: `"ErrorHandling"` < `"Guard"` < `"Loop"` < `"Mixed"` -> для ЛЮБОГО запроса ответ `ErrorHandling`. Первый же запрос `guard-0` ожидает `Guard` -> `Assert.Equal("Guard", answer)` (строка 299 файла проверок) красный. Именно это наблюдал исполнитель под мутацией: `Expected: "Guard" / Actual: "ErrorHandling"` (`runs/mutation/m3-new-tests-under-mutation.log`, `mutant-new-tests.trx`: 1 упал, 2 прошли).

Со строкой 358: для `guard-0` группа `Guard` содержит соседа на расстоянии ноль (набор запроса `{If, LessThan, NumericLiteral, Ret}` совпадает с набором `GA.A`), остальные группы — на расстоянии больше нуля (`LP.A` `{For, LessThan, NumericLiteral, PostIncrement, Block}`: пересечение 2, объединение 7, расстояние 5/7; `EH.A` `{Try, Catch, Block}`: расстояние 1; `SP.A` `{Decl, NumericLiteral}`: пересечение 1, объединение 5, расстояние 4/5) -> `Guard`. Для `loop-0` симметрично -> `Loop`. Эти расстояния я ВЫВЕЛ по коду извлекателя и формуле Жаккара (строки 368–376), не запускал.

Ограничение: мой вывод наборов признаков опирается на имена видов узлов Roslyn (`LessThanExpression`, `PostIncrementExpression`, `Block` и т. п.) и правило `AbbreviateKind`; точный состав наборов я не наблюдал в исполнении. Для вердикта это не критично: решает лишь то, что расстояние до «своей» пары равно нулю (полное совпадение структуры), а до чужих — больше нуля, и это верно при любой разумной абревиации.

## Не подогнан ли ожидаемый результат под реализацию (круговая проверка)

Нет. Ожидаемые метки `Guard`, `Guard`, `Loop`, `Loop` можно назвать независимо от механизма голосования тремя способами:
1. Семантически: запрос `if(n<0)return;` структурно тождествен первому методу файла `GA`, чьё продолжение — `Guard`; запрос `for(...){}` тождествен первому методу `LP`, чьё продолжение — `Loop`. «Ближайшая пара» здесь — пара с расстоянием ноль, никакой другой кандидат на это место нет.
2. По замороженному источнику: обучающие тексты и четыре запроса дословно стоят в хозяине восемьдесят пятого опыта `experiments-v2/RP01-MICRO/P8501/Program.cs` (строки 61–71 и 458–464; я сверил текстами: `TrainGuardAsync`, `TrainLoop`, `TrainErrorHandling`, `TrainSimple`, `examSources` guard-0/guard-1/loop-0/loop-1 совпадают с константами файла проверок). Метки, по словам ранее принятого файла, — из сырых показаний опыта при одном соседе (`panel-production.json`); сам этот json я не открывал — ограничение.
3. По ранее принятому файлу `MethodKnnTieIsResolvedByDistanceTests.cs`, который принят до этого слайса и в этом слайсе не менялся (отпечаток `fad1b402…3ec3` до и после).

Ожидания в файле проверок — константы (`Gold` в `ExamQueries`, строки 103–121; `"Loop"` в строке 332; `"Guard"` в строке 326), а не значения, вычисленные через проверяемый код. Это и есть отсутствие круговости.

Дополнительно: отрицательный случай различает и «перебор» — если бы кто-то сделал расстояние ПЕРВЫМ правилом (раньше числа голосов), ответ на панели большинства сменился бы с `Loop` на `Guard`, и строка 332 покраснела бы. То есть набор из двух случаев чувствителен и к удалению правила, и к его неправильному возвышению.

## Вопрос 4. Независимый оракул с одним соседом

Что это: `NearestPairLabel` (строки 201–237 файла проверок) создаёт `new MethodKnnPredictor(k: 1)`, обучает его теми же парами (нумерация файлов — по позиции, как в `TrainMethodKnn` фасада, строки 186–187 фасада) и спрашивает последний метод запроса.

Тавтология ли это: частично общий код, но НЕ тавтология в отношении проверяемого правила. Обоснование:
- При `k = 1` после `Take(1)` группа ровно одна; `OrderByDescending`, обе `ThenBy` и `First()` ни на что не влияют. Строка 358 — проверяемое правило — в работе оракула НЕ участвует. Поэтому удаление/искажение правила близости оракула не меняет (под мутацией исполнителя контрольный случай и остался зелёным).
- Оракул разделяет с проверяемым кодом `JaccardDistance`, `CanonicalType` и извлекатель. Он НЕ независим от метрики расстояния. Но этот слайс метрику не проверяет (остаток — про разрешение ничьей), поэтому для цели слайса это допустимо.
- Оракул не единственный эталон: его ответ прибит к константе `Assert.Equal("Guard", nearestLabel)` (строка 326). Если бы оракул был сломан и вернул не `Guard`, случай покраснел бы на строке 326, а не прошёл бы «случайно».
- Оракул отвечает `Guard`, а фасад — `Loop` (строки 332, 336): ответы различаются, значит оракул не «эхо» проверяемого ответа.

Вердикт по оракулу: законен как проверка оснастки (что панель действительно даёт расхождение «ближайший ≠ большинство»), не законен как единственное доказательство — и он им не является.
