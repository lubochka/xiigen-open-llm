## ВЕРДИКТ: НУЖНА ПОЧИНКА — два дефекта, оба в УЛИКЕ автора

**Сама строка правила и блок пояснения в файле атрибутов — ПРИНЯТО, дефектов не
нашёл.** Все четыре утверждения пояснения проверены состоянием и верны.
Дефекты — в сопровождающей улике `gitattributes-diff-dump-rule.md`, и оба
относятся к классу «устаревший носитель состояния»: читатель получает из них
неверное текущее значение.

### Дефект 1. Разделы 3 и 4 предъявляют значение отменённой первой редакции как текущее

`gitattributes-diff-dump-rule.md`, раздел 3 «Состояние ПОСЛЕ правки» и раздел 4.

Раздел 3 даёт таблицу атрибутов трёх дампов со значением `cr-at-eol`. Раздел 4
ссылается на неё как на действительность: «атрибут пути выставлен (`cr-at-eol`,
см. раздел 3)» — и делает из этого вывод, что молчание гейта доказать нельзя.

Фактическое текущее значение, прибор `git check-attr whitespace text diff`:

| Файл | whitespace | text | diff |
|---|---|---|---|
| `source-drift-targeted.diff` | `-blank-at-eol,-blank-at-eof` | unset | set |
| `source-post-test.diff` | `-blank-at-eol,-blank-at-eof` | unset | set |
| `source-pre-build.diff` | `-blank-at-eol,-blank-at-eof` | unset | set |

Почему это дефект, а не придирка. Раздел 2, описывающий ту же отменённую первую
редакцию, помечен прямо: «ОПРОВЕРГНУТО, читать вместе с разделами 7 и 10», и в
теле сказано «весь этот раздел описывает первую редакцию». Раздел 9 тоже
корректно перекрыт разделом 10, который называет его по номеру. А разделы 3 и 4
такой пометки НЕ несут и вперёд не ссылаются, хотя содержат ровно то же
устаревшее содержимое. То есть один и тот же вид перекрытого материала помечен в
одном месте и не помечен в двух других. Следующий работник, открывший раздел 3
по заголовку «Состояние ПОСЛЕ правки», получит `cr-at-eol` — значение, которое
автор сам же опроверг измерением.

Что исправить: пометить разделы 3 и 4 как описание отменённой первой редакции и
дать вперёд ссылку на разделы 7 и 10, тем же способом, каким это уже сделано в
разделе 2. Содержимое не вычищать — на нём держится разбор ошибки.

### Дефект 2. Два разных числа строк файла атрибутов, и оба уже неверны

`gitattributes-diff-dump-rule.md`, раздел 6 и конец раздела 7.

- раздел 6: «Строк 1258, возвратов каретки 0, строк с хвостовым пробелом 0»;
- раздел 7: «Строк 1266, возвратов каретки 0, строк с хвостовым пробелом 0».

Фактическое текущее число, прибор `wc -l`: **1283**.

То есть в улике два взаимно несовпадающих числа, ни одно не помечено редакцией,
и **ни одно не совпадает с действительностью**: 1258 относится к первой
редакции, 1266 — к промежуточному состоянию блока пояснения, а блок затем был
расширен до 41 строки. Проверяющий, который сверит «Строк 1266» с файлом,
увидит расхождение и не сможет понять, какое из двух чисел действующее.

Числа про возвраты каретки и хвостовые пробелы при этом верны: проверено,
возвратов 0, хвостовых 0.

Что исправить: оставить одно число, привязанное к действующей редакции, и
пометить прежнее как историческое — либо убрать счёт строк вовсе, он не несёт
доказательной нагрузки.

| Утверждение пояснения | Проверка | Итог |
|---|---|---|
| отключено ДВА вида из трёх набора по умолчанию | `core.whitespace` в репозитории не задан, значит действует набор по умолчанию: `blank-at-eol`, `space-before-tab`, `blank-at-eof`; значение гасит первый и третий | верно |

### 4. Второй механизм назван верно — проверено моим прибором

Утверждение: у журналов и наблюдений другой механизм — файл становится
двоичным для сравнения и потому вне гейта вовсе.

Прибор `git check-attr whitespace text diff`:

| Путь | whitespace | text | diff |
|---|---|---|---|
| журнал прогона `.log` под каталогом улик | unspecified | unset | **unset** |
| наблюдение `.txt` под каталогом улик | unspecified | unset | **unset** |
| образец `.trx` | `cr-at-eol` | unset | set |
| три дампа `.diff` | минусы | unset | set |

`diff: unset` означает отключённое построчное сравнение, то есть Git считает
файл двоичным для сравнения, а гейт пробелов двоичные файлы не осматривает.
Утверждение верно, и вывод следующего работника будет правильным.
