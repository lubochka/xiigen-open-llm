# Правило атрибутов для сохранённых дампов разностей: что сделано и чем доказано

Дата: 12 ноября 2026 года. Задача: три файла улик параллельной сессии лежат вне
репозитория, потому что предкоммитный гейт пробелов даёт по ним ненулевой код:
в сохранённом дампе разности пустая строка контекста законно выглядит как строка
с одним пробелом. Срезать пробелы нельзя — это подделка чужого доказательства;
оставлять улику вне репозитория тоже нельзя.

Пути: `artifacts/fbe/CODEX-NOV12-RECHECK/attempt-0001/logs/source-drift-targeted.diff`,
`source-post-test.diff`, `source-pre-build.diff`.

## 2. Что было добавлено в ПЕРВОЙ редакции — ОПРОВЕРГНУТО, читать вместе с разделами 7 и 10

**Внимание: весь этот раздел описывает первую редакцию правила, которая не
работала.** Он оставлен целиком, а не вычищен, потому что на нём держится разбор
ошибки; действующее правило и его доказательство — в разделах 7 и 10.

Первая редакция, **отменена**:

```
/artifacts/fbe/**/*.diff -text diff whitespace=cr-at-eol
```

Два утверждения этого раздела **неверны**, и оба названы ниже прямо:

1. «Это уже устоявшийся образец… форма взята один в один» — **ложная
   равнозначность**. Образец, с которого бралась форма, исключением проверки
   пробелов не является (см. раздел 8 и исправленное пояснение в самом файле
   атрибутов).
2. «Значение атрибута заменяет набор правил для этого пути целиком» — **неверно
   по документированному поведению и опровергнуто измерением**: значение
   ДОПОЛНЯЕТ набор по умолчанию. Поэтому `cr-at-eol` ничего не гасило, и гейт по
   индексу давал на трёх дампах 163 замечания.

Исходный текст первой редакции, сохранён как есть для разбора ошибки:

> **Это не изобретение, а уже устоявшийся в этом файле образец для машинных
> улик.** Рядом тем же способом помечены файлы результатов проверок и показания
> опытов, например `/artifacts/fbe/**/*.trx -text diff whitespace=cr-at-eol` и
> `/artifacts/fbe/**/*.json -text diff whitespace=cr-at-eol`. Форма строки взята
> у них один в один, изменено только расширение.
>
> **Что правило делает.** Для дампов разностей под `artifacts/fbe` признаёт
> ошибкой пробелов **только** возврат каретки в конце строки: значение атрибута
> заменяет набор правил для этого пути целиком, а `cr-at-eol` не включает ни
> `blank-at-eol`, ни `blank-at-eof`.
>
> **Чего правило НЕ делает.** Не отключает проверку пробелов для исходников. Не
> делает файлы двоичными: построчное сравнение сохранено ключом `diff`.

**Действующее правило** (раздел 7, доказано наблюдением в разделе 10):

```
/artifacts/fbe/**/*.diff -text diff whitespace=-blank-at-eol,-blank-at-eof
```

Оно отключает **два вида из трёх** набора по умолчанию; третий —
`space-before-tab`, пробел перед табуляцией — **остаётся включённым**, и это
подтверждено контролем: файл под этим же правилом со строкой «пробел перед
табуляцией» гейт поймал.

## 4. Чего я не смог доказать наблюдением В ПЕРВОЙ РЕДАКЦИИ — ВЫВОД ОТМЕНЁН разделом 10

Раздел оставлен целиком: в нём разобран ложный контроль на файле результатов, и

**Прибор `git diff --no-index --check` после правки дал те же самые числа: код 3

добавлено» и выяснил причину.

Причина: **режим `--no-index` атрибуты пути не читает.** Доказательство прямое —
атрибут пути выставлен (`cr-at-eol`, см. раздел 3), а число замечаний того же

Отдельно отмечу ловушку, в которую сам чуть не попал: сначала я взял как
контрольный пример уже помеченный файл результатов проверок — прибор дал на нём
ноль замечаний, и это выглядело как доказательство, что атрибуты читаются.
Проверил содержимое: **в том файле строк с хвостовым пробелом ноль**, то есть
молчание прибора объяснялось содержимым, а не атрибутом. Как контроль он
непригоден, и я его не использую.

Ни одно написание `core.whitespace` молчания тоже не даёт: проверил
`cr-at-eol`, `-blank-at-eol`, `-trailing-space`, `-blank-at-eol,-blank-at-eof` и

замечания. Это согласуется с выводом: в этом режиме правила пути не применяются.

**Предкоммитный гейт, который атрибуты читает, работает по индексу, а постановка
в индекс — запись в Git, которая мне запрещена целиком.** Поэтому молчание гейта
я проверить не могу и **не выдаю за наблюдение**. Что доказано наблюдением:
замечания — это ровно `trailing whitespace` на строках из одного пробела, и
атрибут пути теперь объявляет для них набор правил `cr-at-eol`, в который
`blank-at-eol` не входит. Что остаётся выводом, а не наблюдением: что гейт по
индексу на этих путях замолчит. Проверить это может координатор при постановке в
индекс — у него гейт и так выполняется перед коммитом.

## 7. Исправление: прежнее значение атрибута было бессильно, опровергнуто прогоном гейта по индексу

Прежнее значение `whitespace=cr-at-eol` гейт **не** гасило. Это установлено не
мной: координатор поставил три дампа в индекс и запустил настоящий гейт
`git diff --cached --check` с конфигурацией по умолчанию — код возврата 2,
замечаний 163: тринадцать на целевом сносе и по семьдесят пять на двух
остальных, из них два вида — «trailing whitespace» и «new blank line at EOF»
(на последних строках 1158 и 1139). Живой контроль в том же запуске: файл с
одной строкой с хвостовым пробелом вне шаблона гейт поймал, то есть гейт не
слеп, а правило было бессильно. `git check-attr` при этом показывал ровно
`cr-at-eol`, то есть атрибут читался.

**Причина, документированная.** Значение атрибута `whitespace` **дополняет**
набор проверок по умолчанию, а не заменяет его: строковое значение задаётся в
том же формате, что настройка `core.whitespace`, где по умолчанию включены
`blank-at-eol`, `space-before-tab` и `blank-at-eof`, а отключение записывается
минусом перед именем. Поэтому `cr-at-eol` лишь ДОБАВЛЯЛО проверку возврата
каретки, а проверки хвостового пробела и пустой строки в конце файла оставались
включёнными.

### Выбранное значение и привязка каждого отключения к наблюдённому замечанию

```
/artifacts/fbe/**/*.diff -text diff whitespace=-blank-at-eol,-blank-at-eof
```

| Отключаемый вид | Какое наблюдённое замечание он гасит |
|---|---|
| `-blank-at-eol` | «trailing whitespace» — 161 замечание из 163: строки дампа, состоящие из одного пробела, то есть пустые строки контекста |
| `-blank-at-eof` | «new blank line at EOF» — 2 замечания, на последних строках 1158 и 1139 двух дампов |

Больше ничего не отключено.

### Что значение НЕ отключает, перечислением

- `space-before-tab` — остаётся включённым (входит в набор по умолчанию);
- `indent-with-non-tab` — остаётся в своём состоянии по умолчанию (выключен), и
  правило его не меняет;
- `tab-in-indent` — то же;
- `cr-at-eol` — **намеренно не добавляется**: в дословном дампе разности возврат
  каретки может быть законным содержимым проверяемого файла, и включение этой
  проверки вернуло бы ту же блокировку, только по другому байту. Это сознательное
  отступление от формы соседних строк, и оно названо здесь прямо;
- проверка пробелов для исходников и любых других расширений — не затронута;
- файлы двоичными не становятся: построчное сравнение сохранено ключом `diff`.

## 8. Находка про образец для файлов результатов и показаний опытов

**Строки вида `/artifacts/fbe/**/*.trx -text diff whitespace=cr-at-eol` и такая

Эти строки я не трогал: они на своём месте (1092 и 1141), и для своих файлов

заказавший правку по образцу, тоже: ложный контроль на файле результатов, где

Дополнительно: два уже отслеживаемых дампа под каталогом улик содержат по две

### Живой контроль в том же запуске: гейт не слеп

В том же вызове прибора по всему индексу код возврата был 2 и нашлись ровно два

`.ws-gate-control.txt:2: new blank line at EOF.`

Это сильнее простого «молчит»: один и тот же прибор в одном запуске **молчит на
путях под правилом и ловит путь вне правила**, причём ловит ровно те два вида
замечаний, которые моё значение отключает. Атрибут контрольной поверхности —
`whitespace: unspecified`, то есть правило её не касалось.

Контрольная поверхность к моменту следующей проверки уже снята и с индекса, и с
дерева, и гейт по всему индексу даёт 0 замечаний — то есть координатор убрал её в
том же ходе, как и обещал.

### Обоснование выбора маршрута

**Выбран Б.** Доводы, по порядку весомости:

1. **Он доказан наблюдением** настоящего гейта по индексу, а не выведен из
   документации: код возврата 0 при живом контроле, ловящем те же два вида.
2. **Отрицательные формы в значении атрибута действительно разбираются** — это и
   есть то, что доказал прогон: значение `-blank-at-eol,-blank-at-eof`
   сняло ровно эти две проверки из набора по умолчанию. Документированное
   поведение («значение задаётся в формате настройки `core.whitespace`, где
   отключение записывается минусом перед именем, а набор по умолчанию включает
   `blank-at-eol`, `space-before-tab`, `blank-at-eof`») подтвердилось
   измерением.
3. **Дамп улики остаётся читаемым построчным сравнением** — ключ `diff`
   сохранён. Маршрут А (`-text -diff`) делает файл двоичным для сравнения, и
   тогда увидеть, что именно изменилось в сохранённой разности, нельзя.
4. **Отключено ровно два вида**, оба наблюдённые; `space-before-tab` остаётся
   включённым, проверка возврата каретки намеренно не добавлена.

**Маршрут А остаётся рабочим откатом.** Его доказательство — поведение журналов
прогонов и наблюдений: у них правило `-text -diff`, `git check-attr` даёт
`diff: unset`, файл с отключённым построчным сравнением гейт пробелов не
осматривает вовсе, и поэтому возвраты каретки в 39 сырых журналах безвредны по
уже существующему правилу. Отсюда же закрыт мой прежний открытый вопрос: байты
сырых захватов остаются как есть, нормализация не нужна и была бы порчей улики.
Но раз Б измерен и работает, откатываться на А не нужно.
