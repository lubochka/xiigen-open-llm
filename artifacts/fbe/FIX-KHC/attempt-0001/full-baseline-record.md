# Полный прогон проекта проверок 12 ноября: измеренное состояние и ловушка счётчиков

Дата прогона: 12 ноября 2026 года, каталог взят в 17:30:13 при нулевой занятости,
итоговая строка в журнале — в 18:23. Прогон мой, в рамках работы по единому
разбору для признака и метки урока (идентификатор работы FIX-KHC), но ценность
его отдельная: это измерение состояния всего проекта проверок.

## Числа, посчитанные перечислением строк результата

| Показатель | Значение |
|---:|---|
| всего строк результата | **14 694** |
| прошло | **14 126** |
| упало | **473** |
| не исполнялось | **95** |
| длительность | **53 минуты 28 секунд** |

Сумма сходится ровно: 14 126 + 473 + 95 = 14 694. Вложенных строк (случаев
наборов данных) в файле ноль, то есть каждая строка — отдельный результат.
Элемент счётчиков заявляет те же числа, и с перечислением они согласны.

**Все проверки выполнились.** Прогон не оборвался на середине: он дошёл до
итоговой строки и напечатал её.

## Что было после итоговой строки, дословно

В журнале прогона, сразу перед итоговой строкой и после неё:

```
The active test run was aborted. Reason: Test host process crashed
Results File: ...\full-full-baseline-before-transfer.trx
Failed!  - Failed:   473, Passed: 14126, Skipped:    95, Total: 14694, Duration: 53 m 28 s
Test Run Aborted.
```

Процесс после этого висел около четырнадцати минут и был снят по точному
опознавателю **18172** при плоском процессорном времени: 6 765,6 → 6 765,7
секунды между двумя замерами. То есть работа не шла — висела разборка процесса, а
не какая-то проверка.

## ЛОВУШКА, которую обязательно запомнить

**Счётчики файла результатов убитого прогона внутренне не отличимы от
завершённого.** В этом самом файле сводка и счётчики выглядят так:

```
сводка результата: outcome = Failed
счётчики: total=14694 executed=14599 passed=14126 failed=473
          error=0 timeout=0 aborted=0 inconclusive=0 passedButRunAborted=0
          notRunnable=0 notExecuted=0 disconnected=0 warning=0
```

Обратите внимание: `aborted="0"`, `passedButRunAborted="0"`, `notExecuted="0"` —
то есть **в файле результатов нет ни одного признака прерывания**, хотя прогон
был прерван. Единственный честный признак прерывания лежит в ЖУРНАЛЕ прогона,
строкой «Test Run Aborted» и причиной «Test host process crashed».

Отдельная тонкость чисел: `notExecuted` в счётчиках равен нулю, а строк с
исходом «не исполнялось» — 95. То есть и это поле счётчиков не согласуется с
перечислением, хотя три главных поля согласуются.

**Правило, выведенное из этого случая.** Прогон считается состоявшимся по
**итоговой строке в журнале**, а не по появлению файла результатов и не по
завершению процесса. Если после итоговой строки процесс висит: снять два замера
процессорного времени, убедиться что оно плоское, назвать точный опознаватель,
снять процесс и записать, что файл результатов сброшен при снятии. Тогда прогон
остаётся доказанным, а прерывание — названным.

## Почему эта линия важна отдельно от моего переноса

Записанная в правилах проекта базовая линия «не менее 1488 прошло, 0 упало»
устарела: сегодняшнее измерение даёт 14 694 строки и 473 отказа. Числа от
10 ноября (всего 14 346, упало 501) взяты из такого же прерванного прогона,
поэтому их надо читать с той же оговоркой. Это второе независимое измерение
состояния проекта за три дня.

**Чинить эти 473 отказа не моя работа**, они к переносу отношения не имеют, и
зелёными я их не объявляю. Для гейта переноса эта линия как сторона «до» не
используется: мы с вторым исполнителем правим один тестовый проект одновременно,
и его починки попали бы в сверку как мои. Сторона «до» снимается отдельно по
конусу зависимостей правки.
