ГЕЙТ ПРОБЕЛОВ ВЕРНЫМ ПРИБОРОМ
команда: git -c core.whitespace=cr-at-eol diff --check -- <десять изменённых файлов>
почему именно так: обычный --check мисчитывает перенос строки Windows и слеп к файлам с отключённым сравнением
код возврата: 0
строк замечаний (обязано быть 0): 0

НОВЫЙ ФАЙЛ ОБЛАСТИ ПОПЫТКИ: он неотслеживаемый, поэтому проверен отдельным сравнением с пустотой
код возврата: 1
строк замечаний (обязано быть 0): 0

МАРКЕРОВ КОНФЛИКТА В ОДИННАДЦАТИ ФАЙЛАХ (обязано быть 0)
0

РАЗБОР ПРИБОРА, А НЕ ТОЛЬКО ЕГО КОДА ВОЗВРАТА
У сравнения с пустотой код возврата 1 означает «файлы различаются» — а они обязаны различаться,
потому что слева пустота, а справа новый файл. Признаком плохих пробелов служит НЕ код возврата,
а напечатанные замечания: их ноль. Поэтому вердикт по пробелам — чисто.
Проверено дополнительно побайтово ранее: метки порядка байтов нет, возвратов каретки 0,
хвостовых пробелов 0, файл кончается переводом строки.

ПОЛОЖИТЕЛЬНЫЙ КОНТРОЛЬ ПРИБОРА (без него «замечаний ноль» ничего не доказывает)
На заведомо плохом файле с хвостовым пробелом тот же прибор напечатал «trailing whitespace»
и дал код возврата 3. Значит прибор умеет ругаться, и ноль замечаний на моих файлах —
это настоящая чистота, а не молчание сломанного прибора.
