# P8A: ремонт читаемости и продвижение строк OrchestrationReasoning

## Вердикт

`PASS_CANDIDATE_REPAIRED_FOR_PARENT_REVIEW`.

P8A остается фазой продвижения строк. Checkpoint не формировался, обучение не запускалось, eval не запускался, runtime не вызывался.

## Схема ledger

В ledger используются поля `chosen_role` и `source_family_id`. Это задокументировано и проверено в self-check.

## Итоги по ролям

- `train_ready`: 3 строки.
- `eval_reserved`: 1 строка, обучение запрещено.
- `holdout_reserved`: 1 строка, обучение запрещено.
- `evidence_only`: 2 строки, обучение запрещено.
- `quarantine`: 0 строк.

## Строки для будущего обучения

`P5E-DPO-ORCH-001`: фазовый переход после проверки предпосылок, полномочий и ожидаемого результата.

`P5E-DPO-ORCH-002`: отделение ядра решения от внешней оболочки без проектных имен.

`P5E-DPO-ORCH-004`: зависимости между предпосылками, действиями и проверками.

## Защищенные строки

`P5E-DPO-ORCH-003`: `eval_reserved`, обучение запрещено.

`P5E-DPO-ORCH-005`: `holdout_reserved`, обучение запрещено.

`P4-ORCH-DPO-DRAFT-001`, `P4-ORCH-DPO-DRAFT-002`: `evidence_only`, не использовать для checkpoint без отдельного ремонта.

## Что это не доказывает

P8A не доказывает semantic quality, P8 pass, готовность API или готовность финальной модели. Она только готовит список строк для проверки архитектора.

## Следующее действие

Проверка архитектора P8A. Если принято, следующая отдельная фаза может сформировать кандидат checkpoint только из трех строк `train_ready`.
