# P5L: review повышения PromptToTask строк к split/dataset readiness

## Вердикт после ремонта semantics

Все шесть P5H строк проходят P5L ворота как split/dataset-ready кандидаты, но это не означает, что все шесть являются training rows. Только строки с ролью `train_candidate` могут быть входом обучения P6. Строки `eval_candidate` сохраняются для P7 evaluation, а строки `holdout_candidate` сохраняются для holdout evaluation; их нельзя тренировать в P6.

P5L не запускал обучение, eval, тесты, build, checkpoint/model export/import и не менял код. P5H история не переписана.

## Счетчики

- P6 training input rows: 2
- P7 eval candidate rows: 2
- Holdout candidate rows: 2
- Deferred/rejected rows: 0
- Semantic quality claimed: false
- Training allowed: false
- Eval allowed: false

## Что изменено смыслово

Файл `prompt-to-task-training-ready-candidates.jsonl` сохранен по требованию имени, но теперь каждая строка явно говорит, для чего она предназначена. `dataset_ready_for_p6_p7=true` означает, что строка прошла P5L gates как элемент будущего набора. `training_ready=true` разрешен только для `train_candidate`. Для `eval_candidate` и `holdout_candidate` значение `training_ready=false`, потому что эти строки должны оставаться вне обучения.
