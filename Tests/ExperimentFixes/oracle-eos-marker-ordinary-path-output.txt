Проверяемая программа: обычная ветвь генерации не выдумывает признак конца ответа.
Разборщик: 9.0.316; эталонные сборки: 9.0.18

Панель 1. Шесть сборок в порядке зависимостей, две версии проекта вывода.
  ок     собран тензорный слой — ожидалось True, получено True
  ок     собран семантический компилятор — ожидалось True, получено True
  ок     собрана основа — ожидалось True, получено True
  ок     собрана модель — ожидалось True, получено True
  ок     опубликованный генератор отличается от нынешнего — ожидалось True, получено True
  ок     опубликованный словарь отличается от нынешнего — ожидалось True, получено True
  ок     собран прежний словарь — ожидалось True, получено True
  ок     собран прежний проект вывода — ожидалось True, получено True

  Прежняя и нынешняя версии собираются как отдельные пары сборок, потому
  что словарь и генератор меняются вместе: вариант (Г) трогает словарь,
  вариант (В) — генератор.

  ок     собран нынешний словарь — ожидалось True, получено True
  ок     собран нынешний проект вывода — ожидалось True, получено True

Панель 2. Прежняя версия обрывает поток на последней записи словаря.
      прежний текст: знаков 3, байт 5
  ок     прежняя версия НЕ довела ответ до «CD» — ожидалось False, получено False
  ок     но начало ответа «AB» она выдала — ожидалось True, получено True
  Это и есть дефект: буквы после признака в ответ не попали вовсе, и
  вызывающий не получил ни причины, ни признака обрыва — обычные
  перегрузки возвращают только текст.

Панель 3. Нынешняя версия доходит до предела длины.
      нынешний текст: знаков 5, байт 7
  ок     нынешняя версия довела ответ до «CD» — ожидалось True, получено True
  ок     и начало ответа «AB» не изменилось — ожидалось True, получено True
  ок     ответы двух версий различаются — ожидалось True, получено True
  Различие прямое и поведенческое: на одном и том же потоке номеров
  прежняя версия теряет хвост ответа, нынешняя его отдаёт.

Панель 4. Законный случай: заданный вызывающим признак по-прежнему останавливает.
      прежняя: токенов 3, причина EOS
      нынешняя: токенов 3, причина EOS
  ок     прежняя остановилась на заданном признаке — ожидалось 3, получено 3
  ок     нынешняя остановилась там же — ожидалось 3, получено 3
  ок     прежняя назвала причину концом ответа — ожидалось EOS, получено EOS
  ок     нынешняя назвала ту же причину — ожидалось EOS, получено EOS
  Правка не отнимает раннего завершения: когда признак ЗАДАН и проверен,
  остановка по нему остаётся, и причина правдива.

  И подробная ветвь БЕЗ признака: обе версии доходят до предела.
  ок     прежняя без признака дошла до предела — ожидалось 5, получено 5
  ок     нынешняя без признака дошла до предела — ожидалось 5, получено 5
  ок     обе назвали причину пределом длины — ожидалось LENGTH_LIMIT, получено LENGTH_LIMIT
  Отсюда главное следствие: после правки обычная ветвь ведёт себя РОВНО
  как подробная без признака. Две ветви сходятся на честной, а не
  расходятся в разные стороны, поэтому «подробная неверна в другую
  сторону» перестаёт быть вторым дефектом.

Панель 5. Вариант (Г): словарь сообщает отсутствие признака, формат не задет.
      прежний словарь говорит: 255
      нынешний словарь говорит: ОТСУТСТВУЕТ
  ок     прежний словарь выдумывал номер последней записи — ожидалось 255, получено 255
  ок     нынешний словарь сообщает отсутствие — ожидалось ОТСУТСТВУЕТ, получено ОТСУТСТВУЕТ
  ок       недостижимый 300: отпечаток обученного состояния совпал — ожидалось 588d2f83695ff5901a9d440db33aa7d6bf1a16eae81b23782d48ba147694d259, получено 588d2f83695ff5901a9d440db33aa7d6bf1a16eae81b23782d48ba147694d259
  ок       ровно порог 256: отпечаток обученного состояния совпал — ожидалось 3bba3bc0d53fb07a5de4d28839f14c2b296b8034de37e5d561b123a9dcf95bf4, получено 3bba3bc0d53fb07a5de4d28839f14c2b296b8034de37e5d561b123a9dcf95bf4
  Признак конца в сериализацию не входит вовсе — сохраняются только
  таблица слияний и словарь, — поэтому ни один из 3210 сохранённых
  артефактов этой правкой не задет, и это измерено отпечатками.
  Число измерено по форме артефакта, а не по имени файла: файлов с
  именем tokenizer.json в дереве 3383, но 173 из них — описатель
  полей обходчика кода на 147 байт, а не словарь. Прежнее число
  3383 было завышением исполнителя. Состав цены: 3201 словарь в
  замороженных хозяевах опытов, 8 под .kiro, ровно один в config.

Панель 6. Чувствительность: порча правки обязана быть поймана.
  ок     подстановка порчи в словарь изменила текст — ожидалось True, получено True
  ок     подстановка порчи в генератор изменила текст — ожидалось True, получено True
  ок     порченая пара собирается (порча тихая) — ожидалось True, получено True
      порченый текст: знаков 3
  ок     порча поймана: ответ снова теряет «CD» — ожидалось False, получено False
  ок     и совпадает с прежним поведением — ожидалось AB�, получено AB�
  Порча собралась молча и вернула прежнее поведение, а сверка это

Панель 7. Сверка вторым способом на эталоне с заведомо известным ответом.
      эталон без признака: прежний «ABCDE», нынешний «ABCDE»
  ок       на потоке без признака версии совпадают — ожидалось ABCDE, получено ABCDE
  ок       и обе выдали все пять знаков — ожидалось ABCDE, получено ABCDE
  Это и есть проверка самой сверки: на потоке, где дефект не может
  проявиться, версии обязаны совпасть — и совпадают. Значит различие
  панели 3 вызвано именно номером признака, а не разницей сборок.
