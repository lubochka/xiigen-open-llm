## 1. Какой запрос решается (The Core Problem)

### Исходный запрос из `basic_prompt.txt`

Пользователь хочет **AI-платформу оркестрации потоков** (аналог n8n, но для сложных AI-пайплайнов), которая решает 10+ реальных бизнес-сценариев:

**Базовый сценарий (MVP):**
- Пользователь отдаёт дерево нод Figma (raw CSS/HTML).
- Система прогоняет его через **несколько AI-моделей** (Claude, GPT, Gemini, DeepSeek...).
- Учитывает предыдущие positive/negative feedback.
- Делает финальный review другой моделью.
- Возвращает результат клиенту.
- На каждом шаге сохраняет **промежуточные результаты + промпты** в Elasticsearch.
- Пользователь может поставить лайк/дизлайк + текст — это сразу попадает в RAG и улучшает будущие запуски.

**10 расширенных сценариев использования (из basic_prompt):**

1. **Figma → Полноценная система**  
   Пользователь выбирает технологии (клиент/сервер/БД). Система:
   - Анализирует все экраны и компоненты
   - Понимает архитектуру продукта
   - Генерирует архитектуру как набор flows внутри XIIGen
   - Для каждого экрана создаёт техдизайн взаимодействия с flows + собирает feedback

2. **Интеграция Figma в существующую систему**  
   Автоматическая генерация документации, skillset'ов, применение дизайн-системы, стилизация.

3. **Генерация системы с нуля по тексту**  
   Пользователь описывает идею → дизайн-тема → архитектура → skills → план реализации → генерация кода + возможность деплоя и отладки на платформе.

4. **Персональный AI-агент (WhatsApp Diet / Health)**  
   Регистрация → генерация плана питания несколькими AI-раундами → ежедневный сбор данных через WhatsApp → пересчёт калорий/нутриентов → корректировки + уведомления (push + WhatsApp).

5. **Полноценный Content Pipeline**  
   Голос/текст → STT → улучшение текста → план изображений/видео (3 сек) → генерация изображений + промптов → видео + музыка + аватар → субтитры → описание под платформы → автопостинг по расписанию.

6. **Библиотека Design Patterns**  
   Для каждого паттерна: когда использовать, как, примеры на 5 языках, распространённые комбинации.

7-10. Поддержка сложных UML (possible umls.drawio.xml), генерация систем по примерам типа "Small Business Networking App", динамический код из Genie skill library, поддержка любых GraphRAG-стратегий.

**Ключевые технические требования из запроса:**
- Generic интерфейсы (DB, Queue, AI, RAG, Secrets) — легко менять реализации.
- Динамические документы (никаких жёстких схем).
- Полноценный RAG + Graph на каждом шаге AI (AI сам планирует, что искать, и куда сохранять после feedback).
- Multi-language skills (основной .NET 9 + альтернативы: Node, Python, Rust, Java, PHP + клиенты React Native / Vue / Angular).
- Продвинутые "skills": MCP, тестирование всех уровней, DevOps (K8s), документация, безопасность, оптимизация.
- Полная наблюдаемость: визуализация flow, отладка каждой ноды (вход/промпт/выход), история.

## 2. Постепенное описание функционала (Progressive Functionality)

### Уровень 0 — Базовый AI Flow Engine (n8n для AI)
- Визуальный редактор DAG (React Flow).
- Запуск по traceId + input.
- Топологическая сортировка + последовательное/параллельное выполнение.
- Хранение состояния и результатов в Elasticsearch.
- Feedback loop (положительный/нейтральный/негативный + текст) → сразу влияет на следующие запуски через RAG.
