# 2. HOW TO SIMULATE A RUN

## The trace format

For each scenario, produce a STEP TABLE. Every row is one step the
engine must execute to complete the scenario.

```
| Step | What must happen | Handler | Input available? | Output expected | Actual result | Gap? |
|------|-----------------|---------|-------------------|-----------------|---------------|------|
```

### Column definitions

**Step:** Sequential number. Each step is one discrete action.

**What must happen:** Plain language. What the engine needs to do at
this point to make progress toward the scenario goal.

**Handler:** Which existing XIIGen handler or service would execute this.
Options:
  - ai-generate.handler (calls an AI model)
  - validate.handler (checks conditions)
  - route.handler (branches based on condition)
  - rag-retrieve.handler (retrieves from the retrieval system)
  - feedback.handler (stores results + emits events)
  - score.handler (evaluates quality)
  - [fabric interface].method (calls a fabric service)
  - HUMAN (requires human intervention)
  - NONE (no handler exists for this action)

**Input available?:** For each piece of data this step needs, mark:
  - ✅ exists and accessible
  - ⚠️ exists but not accessible to this handler
  - ❌ does not exist

**Output expected:** What this step should produce for the next step.

**Actual result:** One of:
  - WORKS — handler exists, input available, output produced correctly
  - PARTIAL — handler exists but input incomplete or output degraded
  - BREAKS — handler doesn't exist, or critical input missing
  - WRONG — handler exists and runs but produces incorrect output

**Gap?:** If BREAKS or WRONG: which gap class (A-L) and a one-line
description of what specifically is missing.

## Trace rules

1. **Start from what the engine receives.** Not from what a human
   would prepare. If the scenario requires an EngineContract and no
   EngineContract exists, Step 1 is "produce EngineContract" and it
   will break immediately.

2. **Follow the actual handler chain.** Don't skip steps. If the
   topology says rag-retrieve → ai-generate → validate → route →
   feedback, trace each one. The gap might be in retrieve, not generate.

3. **Check EVERY input.** For each step, list what data it needs.
   Mark each piece ✅/⚠️/❌. A step can break because ONE input
   is missing even if five others are present.

4. **Don't assume fixes.** If Step 3 breaks, don't assume "well if
   we fixed that, Step 4 would work." Trace Step 4 with the broken
   input from Step 3. The cascade reveals compound gaps.

5. **Trace the LEARNING path too.** After the main flow completes
   (or breaks), trace: what training data was produced? What should
   have been produced? This reveals learning gaps separately from
   execution gaps.
