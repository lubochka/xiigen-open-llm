# Раздельная сборка и запуск P108–P113

Шесть `Run-Experiment.ps1` вызывают один `ExperimentLauncher.psm1`.
Заявка с исключительным доступом удерживается от входа до итоговой записи.
Даже готовый успешный результат читается только после захвата заявки.
Сборка пишет отдельную квитанцию `experiment-build/v1`, исходные отпечатки
и идентичность артефакта. `BUILT_ONLY` не завершает опыт и не стирает его отказ.
Каждый вход/этап сохраняется в отдельном `invocations/<id>`.

`all`, `build`, `run` сохраняют назначение и прежние пределы владельцев.
P108: 600/900/1500 с; P110: 600/1200/1800 с. У P109/P112 этапы
600/1200 с, P111/P113 — 600/900 с; нулевой общий предел означает,
что отдельного общего лимита у прежнего владельца не было.
P108 `verify-saved` по-прежнему вызывает `--verify-saved` с отдельными
каталогами исходного результата и ремонта. Это не повтор PRIMARY.
Старый `selftest-launcher` требует нового явного QA-входа ниже: файл
исторического дочернего процесса и старые результаты ремонта не перезаписываются.
Нормализации Program.cs, проектов или других файлов при входе больше нет.

Терминальная квитанция `experiment-terminal/v1` проверяется по типам,
experiment/attempt/stage, обязательным исходам и непротиворечивости кода.
Ненулевой код ребёнка сохраняется отдельно и возвращается наружу.
Измерение FAIL при child0 возвращает21, бюджет FAIL —22, неизвестный исход —11,
конкурентный вход —12, срок этапа —124, общий срок —125,
неподтверждённая остановка дерева —126. Научный ноль не является ошибкой.
Старые P107 budget7/P108 budget8 не переименовываются.

Старые exit/run/status читаются по шести явным схемам из одного буфера на файл.
Известный согласованный failure7 остаётся7. У старых P108/P109 process0
не закрывает неизвестные обязательные outcomes: возвращается11 без нового
callback. P110–P113 могут вернуть0 только как согласованное сохранённое
свидетельство, без свежей научной переаттестации. История не переписывается.

## Изолированная QA без модели

`qa/Invoke-LauncherAcceptance.ps1 -OutputRoot <новый qa-results/q03-execution/...>`
вызывает реальные шесть wrappers в режиме `-Mode qa`. Явные QaStage,
QaAttemptId, QaOutputRoot и QaFixture меняют команду ребёнка и каталог,
а claim, deadlines, адаптеры, terminal validator и finalizer остаются общими.
Полный паспорт и независимые expected IDs находятся в каталоге конкретной QA.
Ни одна команда опыта/dotnet/Train/Forward/Generate в этом режиме не вызывается.

Declared identity fixture фиксируется до claim. Дочерний процесс сообщает
SHA/размер именно разобранного им буфера; общий finalizer сравнивает его с
сохранённой identity. Это проверка входа имитатора, не доказательство замыкания
реальных model inputs. Соседний `New-RunBinding.ps1` имеет собственный lifecycle
и синхронный dotnet API; его source-closure гарантии этому helper не приписываются.

Остановка дерева подтверждается для наблюдённых PID и времени старта.
Отсутствующее наблюдение или живой потомок не дают PASS. Отрицательный
контроль намеренно останавливает лишь корень; исходный FAIL фиксируется до
отдельной аварийной уборки. Такая уборка не меняет исход проверки остановки.
